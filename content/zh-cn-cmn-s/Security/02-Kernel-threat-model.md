## 简介

该威胁模型适用于 FreeRTOS 移植，支持硬件内存保护，例如 ARM 
Cortex-M 内存保护单元 (MPU)。该模型适用于使用 MPU 包装器 C 文件 
（FreeRTOS V10.6.0 中引入）的应用程序。在其设备中使用 FreeRTOS 的应用程序编写者 
负责保护设备以及设备上运行软件的安全。
请注意，协同程序已被弃用且缺乏 MPU 支持，因此超出了威胁模型的范围。


## 资产

1. FreeRTOS 内核 C 代码。
1. 应用程序代码 - 定义为内核 C 代码以外的所有代码。
1. FreeRTOS 内核内部数据。
1. 应用程序数据 - 定义为内核内部数据以外的所有数据。
1. 已保存的任务上下文 - 未处于运行状态的任务的上下文。
1. 任务堆栈 – 每个任务都有自己的堆栈。
1. [任务]系统调用堆栈 - 每个任务都有独立的系统调用堆栈来执行系统调用。
1. 系统堆栈 - 中断服务程序 (ISR) 使用的堆栈。
1. 特殊 CPU 寄存器，例如：
   + MPU 控制寄存器。
   + CPU 操作寄存器（例如执行模式）。
1. 通用 CPU 寄存器。


## 参与者

1. 非特权任务 – 具有有限特权的 FreeRTOS 任务。
1. 特权任务 – 具有全部特权的 FreeRTOS 任务。
1. 中断服务程序 (ISR)。
1. 具有内存访问权限的外围设备，例如直接内存访问 (DMA) 控制器和通信端口。


## 授权

下表列出了不同参与者针对各项资产所获授权的情况，在运行时明确获得 
额外授权的情况除外（例如，获得应用程序数据只读权限的 
非特权任务）：

| &nbsp; | 非特权任务 | 特权任务 | ISR 代码 | 外围设备 | 
|---|---|---|---|---| 
| 内核代码 | - | RW | RX | RW |
| 应用程序代码 | RX | RX | RX | RW |
| 内核数据 | - | RW | RW | RW |
| 应用程序数据 | - | RW | RW | RW |
| 任务上下文 | - | RW | RW | RW |
| 特殊寄存器 | - | RW | RW | RW* |
| 通用寄存器 | RW | RW | RW | - |

*R：读取；W：写入；X：执行；NA：不适用。不带任何字母的破折号表示“无权限”。*

*\*外围设备可以访问自身的特殊寄存器。*

总结上表。
1. 非特权任务具有
    + 应用程序代码的读取和执行权限。
    + 自身堆栈的读取和写入权限。
    + 通用寄存器的读取和写入权限。

2. 特权任务具有
    + 所有代码的读取和执行权限。
    + 所有数据的读取和写入权限。
    + 所有寄存器的读取和写入权限。

3. 中断服务程序具有
    + 所有代码的读取和执行权限。
    + 所有数据的读取和写入权限。
    + 所有寄存器的读取和写入权限。

4. 外围设备具有
    + 所有内存和自身寄存器的读取和写入权限。


## 入口点

系统调用 - FreeRTOS 系统调用将内核应用程序编程接口 (API) 函数与特定代码包装在一起， 
从而为非特权任务提供内核服务。此代码为调用内核 API 的非特权任务 
临时授予执行内核代码所需的特权。


## 信任边界

非特权任务实施系统调用以执行内核 API 函数 
是唯一一次跨越信任边界的情况。

## 不变量

FreeRTOS 调度器启动后，参与者无法访问其无权访问的任何资产。


## 内核缓解的威胁
FreeRTOS 内核可缓解以下威胁。 
在以下所有威胁中均假设攻击者以非特权方式运行。

1. 访问特权扰乱

    如果参与者成功访问（读取、写入或执行） 
    其无权访问的资产，则视为访问特权扰乱。

    缓解措施 - FreeRTOS 内核会在调度器启动时以及每次任务上下文切换时对 MPU 进行编程， 
    以便 MPU 执行“授权”部分表格中描述的授权。

2. 堆栈溢出

    堆栈指针增长超出堆栈内存时会发生堆栈溢出，导致内存损坏。

    缓解措施 – FreeRTOS 内核通过 MPU 区域向非特权任务授予访问其自身堆栈的 
    权限。MPU 区域的大小和起始地址与堆栈的大小和起始地址相匹配， 
    因此在堆栈外部写入会导致内存保护故障。

    应用程序编写者必须确保堆栈大小和对齐符合 
    MPU 硬件施加的各种限制，还必须确保同一任务无法访问 
    堆栈相邻的内存。

3. 堆栈操作攻击

    非特权任务具有自身堆栈的写入权限。攻击者可通过此功能利用 
    未能在使用之前初始化堆栈内存的内核函数。

    缓解措施 – 在仅特权代码可访问的独立堆栈上执行系统调用。

4. 利用以指针为参数的系统调用实现任意读取或写入

    攻击者可以将想要读取或写入的位置的地址作为参数 
    传递给取消引用该地址的系统调用，从而有效地允许攻击者读取或写入 
    内存。

    缓解措施 — 接受指针的系统调用必须拒绝调用任务 
    没有必要访问权限的地址。

5. 利用以函数指针为参数的系统调用实现任意代码执行

    攻击者可以通过将函数的地址传递给系统调用来提升其特权， 
    实现系统调用时会在特权上下文中执行提供的函数。

    缓解措施 — 查看所有系统调用，确保接受函数指针作为参数的系统调用 
    仅在调用任务的上下文中执行函数。

6. 假内核对象句柄

    攻击者可以将精心制作的内存块地址（而不是内核对象句柄）作为参数传递给系统调用， 
    从而诱使内核执行任意内存读取或写入操作。

    缓解措施 — 内核对象句柄是可间接验证的不透明整数，而非地址。

7. 使用攻击者控制的内存创建内核对象

    静态分配的内核对象使用应用程序编写者提供的内存。如果使用 
    攻击者提供的内存，则攻击者可能会操作内核。

    缓解措施 – 非特权任务无法访问静态分配内存中用于创建内核对象的系统调用 
    。可以使用特权任务中静态分配的内存创建对象， 
    也可以在启动调度器之前创建对象。

8. 覆盖内核 MPU 保护

    攻击者可以通过重叠 MPU 区域 
    （MPU 硬件支持的区域）来规避内核内存保护。

    缓解措施 – ARMv7-M MPU 是唯一支持重叠 MPU 区域的 MPU。在该架构上， 
    高编号 MPU 区域优先于低编号 MPU 区域， 
    因此内核使用最高区域编号（无法覆盖）来保护自己的代码和数据。

9. 换出后操作任务上下文

    任务的上下文既包括通用寄存器，也包括特殊寄存器。内核存储 
    所有未运行任务的上下文，以便将来可以再次运行任务。攻击者可以 
    通过操作已保存的上下文来劫持控制流或提升任务的特权。

    缓解措施 - 任务上下文存储在任务控制块 (TCB) 中，TCB 属于内核内部数据 
    结构，因此非特权代码无法访问。

10. 特权提升尝试

    攻击者可以执行系统调用用来提升特权的汇编指令。

    缓解措施 - 只有源自系统调用的特权提升才会得到授权。

11. 通过堆栈泄露信息

    系统调用存储在堆栈上的机密数据可以保留在堆栈上， 
    在系统调用返回后可由非特权任务访问。

    缓解措施 – 在仅特权代码可访问的独立堆栈上执行系统调用。


## 内核未缓解的威胁

1. 通过寄存器泄露信息

    系统调用存储在通用寄存器中的机密数据可以保留在寄存器中， 
    在系统调用返回后可由非特权任务访问。

    缓解措施 - 此威胁风险较低，由于内核系统调用不使用 
    在非特权任务读取时可能会出现问题的数据，因此无法缓解此威胁。应用程序编写者添加的使用机密数据的系统调用 
    必须采取适当措施，在调用返回前从寄存器中删除 
    此类数据。


## 应用程序需要缓解的威胁
应用程序需要缓解以下威胁：

1. 调度器启动之前执行不受信任的代码

    微控制器 (MCU) 启动，进入并保持特权模式，直至调度器启动。 
    调度器启动之前，内核无法针对不受信任的代码执行提供任何保护。

    缓解措施 - 应用程序编写者必须确保调度器启动之前不执行不受信任的代码。 
    强烈建议使用仅启动经过验证的签名映像的安全启动序列， 
    并且仅在非特权任务中执行不受信任的代码。

2. 在 ISR 中执行不受信任的代码

    MCU 在执行 ISR 之前会进入特权模式。在 
    进入 ISR 与 ISR 返回或降低其特权期间，内核无法针对不受信任的代码执行提供任何保护。

    缓解措施 - 应用程序编写者必须确保在所有 ISR 中都不执行不受信任的代码。强烈建议 
    使用仅启动经过验证的签名映像的安全启动序列，以尽可能缩短 ISR， 
    并将大多数中断处理推迟到非特权任务。为所有 ISR 
    安装单一入口点有助于管理特权级别。

3. 配置不正确

    应用程序可能无法正确导出以下链接器变量：

    - 内存的起始和终止包含以下代码：
        ```
        __FLASH_segment_start__
        __FLASH_segment_end__
        ```

    - 包含位于 privileged_functions 部分中的内核代码的内存开始和结束。
        ```
        __privileged_functions_start__
        __privileged_functions_end__
        ```

    - 包含位于 freertos_system_calls 部分中的 FreeRTOS 系统调用的内存开始和结束。
        ```
        __syscalls_flash_start__
        __syscalls_flash_end__
        ```

    - 包含位于 privileged_data 部分中的内核数据的内存开始和结束。
      ```
      __privileged_data_start__
      __privileged_data_end__
      ```


    应用程序编写者必须确保上述内存区域的大小和对齐符合 
    MPU 硬件施加的各种限制，还必须将 configENABLE_MPU 
    （针对 ARMv8-M 移植）定义为 1。

    缓解措施 - 应用程序编写者必须确保 FreeRTOS 配置正确。

4. 物理攻击

    终端产品可能遭受物理攻击，例如故障或旁路攻击。

    缓解措施 - MPU 保护无法抵御所有物理攻击。应用程序编写者必须 
    制定针对物理攻击的保护措施，或在有物理访问限制的环境中部署运行 FreeRTOS 的设备 
    （如需要）。

5. 源代码完整性

    应用程序编写者可以修改 FreeRTOS 源代码，这可能会引入漏洞。

    缓解措施 - 应用程序编写者不得修改 FreeRTOS 源代码。

6. 应用程序二进制完整性

    终端产品中运行的二进制文件被修改后可能引入漏洞。

    缓解措施 - 应用程序编写者必须使用硬件信任根、安全启动和 
    加密签名验证等机制来确保应用程序二进制完整性。

7. 非特权任务通过合法系统调用访问有效内核对象

    非特权任务可能通过合法系统调用访问本不该访问的 
    有效内核对象。

    缓解措施 - 应用程序编写者必须确保非特权任务无法 
    访问其不该访问的内核对象。

8. 回调中不受信任的代码执行
    以下回调在特权上下文中运行：
    - [Idle Hook Function](https://www.freertos.org/Documentation/02-Kernel/02-Kernel-features/12-Hook-functions#idle-hook-function)
    - [Tick Hook Function](https://www.freertos.org/Documentation/02-Kernel/02-Kernel-features/12-Hook-functions#tick-hook-function)
    - [Malloc Failed Hook Function](https://www.freertos.org/Documentation/02-Kernel/02-Kernel-features/12-Hook-functions#malloc-failed-hook-function)
    - [Stack Overflow Hook Function](https://www.freertos.org/Documentation/02-Kernel/02-Kernel-features/12-Hook-functions#stack-overflow-hook-function)
    - [Daemon Task Startup Hook](https://www.freertos.org/Documentation/02-Kernel/02-Kernel-features/12-Hook-functions#daemon-task-startup-hook)
    - [Software Timer Callback](https://www.freertos.org/Documentation/02-Kernel/02-Kernel-features/05-Software-timers/01-Software-timers)
 
    内核不提供任何针对上述回调中不受信任的代码执行的保护。
 
    缓解措施 - 应用程序编写者必须确保上述回调中不会执行不受信任的代码。一种选择是使用配置常量来禁用hooks。
