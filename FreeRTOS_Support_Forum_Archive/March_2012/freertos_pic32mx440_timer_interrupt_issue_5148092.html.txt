  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">pic32mx440 timer interrupt issue</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/liliot">liliot</a> on March 27, 2012</div><div class="thread-post-content">Hi All,<br />
&nbsp; I&#8217;m working with a simple self made board with a pic32mx440f512h.<br />
I started with a simple project defining 2 tasks &#40;working with gpios&#41;.  
Calling the vTaskStartScheduler, the second defined task runs just once, then the system hangs.<br />
I&#8217;ve observed that, on the timer interrupt, the code jumps to vector 0 instead of vector 4.  
Currently I&#8217;ve modified the xPortStartScheduler function &#40;port.c&#41; adding the following line at the very beginnig:  
&nbsp; INTCONSET = &#95;INTCON&#95;MVEC&#95;MASK; // Set MVEC  
to enable the multivector mode.  
Is that &#8220;fix&#8221; OK?  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">pic32mx440 timer interrupt issue</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on March 28, 2012</div><div class="thread-post-content">I&#8217;m not sure, without digging the manual out, but the official demo does it by making a call to the Microchip library as follows:  
INTEnableSystemMultiVectoredInt&#40;&#41;;  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">pic32mx440 timer interrupt issue</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/liliot">liliot</a> on March 28, 2012</div><div class="thread-post-content">You&#8217;re right, official demo uses the INTEnableSystemMultiVectoredInt&#40;&#41;.

Anyway I don&#8217;t understand &#40;I&#8217;m just a beginner&#41; why this interrupt controller configuration is left to the user whereas the OS functions define all the other stuffs &#40;like timer vector&#41;.
