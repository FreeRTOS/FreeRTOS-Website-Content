void vSetupTimerForRunTimeStats&#40; void &#41;;<br />
unsigned long ulGetRunTimeStatsCounterValue&#40; void &#41;;<br />

/&#42; T2 is 16-bits and generate an interrupt when it overflows.&nbsp; The<br />
number of overflows is stored in ulTMR2OverflowCount.&nbsp; This macro<br />
combines the current 16-bit counter value with the number of overflows<br />
to return a 32-bit timer value. &#42;/<br />
&#35;define portALT&#95;GET&#95;RUN&#95;TIME&#95;COUNTER&#95;VALUE&#40; ulCountValue &#41; <br />
&#123; <br />
extern volatile unsigned long ulTMR2OverflowCount; <br />

<br />

while its value is being used. &#42;/ <br />
T2CON&#95;VALUE = T2&#95;OFF; <br />
<br />
/&#42; The number of overflows is shifted into the most significant <br />
two bytes of the returned 32-bit value. &#42;/ <br />
ulCountValue = &#40; ulTMR2OverflowCount &lt;&lt; 16UL &#41;; <br />
<br />

</div></div><div class="thread-post"><h3 class="thread-post-title">Statistics implementation PIC32 Example 18</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on March 16, 2012</div><div class="thread-post-content">ulCountValue is defined &#8211; it is in the code you have posted as the parameter to the macro in the code you have posted&#33;&nbsp; You have then created another copy of it inside the macro, so I&#8217;m not sure what the pre-processor and subsequently the compiler will do at all.&nbsp; It sounds like you then have a third global variable of the same name defined before main&#40;&#41;, which will never get used anyway as the block scope one in the macro will shadow it.  
I would suggest starting by removing the two unnecessary variables that have the same name as the macro parameter and see what that does.&nbsp; If you get the same error then, it must be something inside the macro that is causing it as the macro is not supposed to return an unsigned long to the caller, but assign the unsigned long to the macro parameter.
