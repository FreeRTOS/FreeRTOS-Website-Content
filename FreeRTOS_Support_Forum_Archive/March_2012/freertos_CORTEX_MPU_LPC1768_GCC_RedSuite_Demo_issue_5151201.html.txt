  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">CORTEX_MPU_LPC1768_GCC_RedSuite Demo issue</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/*anonymous">*anonymous</a> on March 29, 2012</div><div class="thread-post-content">What version of gcc toolchain build this demo tested against ?<br />
I tried LPCXpresso v3.6.3&nbsp;&nbsp; &#40;should be very similar to RedSuite as stated in demo name&#41;.  
<pre><code>E:lpcxpresso_3.6.3_317Toolsbin&gt;arm-none-eabi-gcc.exe --version
arm-none-eabi-gcc.exe (Code Red/Red Suite/2009_01_C) 4.3.3
...
</code></pre>
Here is the fragment from RTOSDemo&#95;RDB1768.map:  
<pre><code>privileged_functions
        0x00001798  0x5d4 ./src/FreeRTOS/portable/GCC/ARM_CM3_MPU/port.o
        0x000018d8      xPortStartScheduler
        0x00001990      xPortSysTickHandler
        0x0000193c      xPortPendSVHandler
        0x00001930      vPortEndScheduler
        0x00001810      vPortSVCHandler
        0x00001798      pxPortInitialiseStack
        0x00001b8c      vPortStoreTaskMPUSettings
.text       0x00001d6c  0x51d6
        0x00004000      . = (__privileged_functions_start__ + _Privileged_Functions_Region_Size)
 *fill*     0x00001d6c  0x4000  00
 *(.text*)
 .text.Reset_Handler
        0x00005d6c  0x84 ./src/cr_startup_lpc17.o
        0x00005d6c      Reset_Handler
        0x00005d6c      ResetISR
</code></pre>
Look at .text section start address. It&#8217;s not 0x00004000, but shifted by 0x00004000 from end of privileged&#95;functions section end.<br />
Location counter assignments in linker script such as  
<pre><code>/* Non privileged code kept out of the first 16K or flash. */
. = __privileged_functions_start__ + _Privileged_Functions_Region_Size;
</code></pre>
doesn&#8217;t work as expected.<br />
The same results with Yagarto GNU toolchain &#40;arm-none-eabi-gcc.exe &#40;GCC&#41; 4.6.0&#41;.<br />
Although some tutorials doesn&#8217;t recommend location counter assignments, <a href="http://sourceware.org/binutils/docs/ld/Location-Counter.html">GNU ld manual</a> clearly describes this behavior and provides an example usage even.
</div></div><div class="thread-post"><h3 class="thread-post-title">CORTEX_MPU_LPC1768_GCC_RedSuite Demo issue</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/*anonymous">*anonymous</a> on March 29, 2012</div><div class="thread-post-content">Hmm. I read again ld manual and found that it&#8217;s correct behavior because location counter inside section block is relative. That line must be removed and line  
<pre><code>/* Non privileged code kept out of the first 16K or flash. */
. = __privileged_functions_end__;
</code></pre>
must be placed at end of privileged&#95;functions block.<br />
And it works as expected both in lpcexpresso and yagarto.  
</div></div><div class="thread-post"><h3 class="thread-post-title">CORTEX_MPU_LPC1768_GCC_RedSuite Demo issue</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/*anonymous">*anonymous</a> on March 29, 2012</div><div class="thread-post-content">I hurried again :&#41; Final correct line:  
<pre><code>/* Non privileged code kept out of the first 16K or flash. */
. = _Privileged_Functions_Region_Size;
</code></pre>
Please, do fixes I mentioned. Although demo works fine &#40;only because the LPC1768 flash luckily resides on 0x0, but this demo ported to STM32F2 with flash at 0x8000000 fails&#41;, these fixes must be done to get it linked correctly.
