  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">LPC178x Systick and interrupts</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/frankandersen">frankandersen</a> on March 1, 2012</div><div class="thread-post-content">I am trying to find out why my project ends up in vListInsert:  
/&#42; &#42;&#42;&#42; NOTE &#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;<br />
If you find your application is crashing here then likely causes are:<br />
1&#41; Stack overflow &#8211;<br />
&nbsp;&nbsp; see <a href="http://www.freertos.org/Stacks-and-stack-overflow-checking.html">http://www.freertos.org/Stacks-and-stack-overflow-checking.html</a><br />
2&#41; Incorrect interrupt priority assignment, especially on Cortex M3<br />
&nbsp;&nbsp; parts where numerically high priority values denote low actual<br />
&nbsp;&nbsp; interrupt priories, which can seem counter intuitive.&nbsp; See<br />
&nbsp;&nbsp; configMAX&#95;SYSCALL&#95;INTERRUPT&#95;PRIORITY on <a href="http://www.freertos.org/a00110.html">http://www.freertos.org/a00110.html</a><br />
3&#41; Calling an API function from within a critical section or when<br />
&nbsp;&nbsp; the scheduler is suspended.<br />
4&#41; Using a queue or semaphore before it has been initialised or<br />
&nbsp;&nbsp; before the scheduler has been started &#40;are interrupts firing<br />
&nbsp;&nbsp; before vTaskStartScheduler&#40;&#41; has been called?&#41;.<br />
See <a href="http://www.freertos.org/FAQHelp.html">http://www.freertos.org/FAQHelp.html</a> for more tips.<br />
&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;/  
for&#40; pxIterator = &#40; xListItem &#42; &#41; &amp;&#40; pxList-&gt;xListEnd &#41;; pxIterator-&gt;pxNext-&gt;xItemValue &lt;= xValueOfInsertion; pxIterator = pxIterator-&gt;pxNext &#41;<br />
&#123;<br />
/&#42; There is nothing to do here, we are just iterating to the<br />
wanted insertion position. &#42;/<br />
&#125;  
To me it looks like the Systick interrupts preempts the USB interrupt:  
In FreeRTOSConfig I have:  
/&#42; Use the system definition, if there is one &#42;/<br />
&#35;ifdef &#95;&#95;NVIC&#95;PRIO&#95;BITS<br />
&#35;define configPRIO&#95;BITS&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; &#95;&#95;NVIC&#95;PRIO&#95;BITS<br />
&#35;else<br />
&#35;define configPRIO&#95;BITS&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; 5&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; /&#42; 32 priority levels &#42;/<br />
&#35;endif  
/&#42; The lowest priority. &#42;/<br />
&#35;define configKERNEL&#95;INTERRUPT&#95;PRIORITY &#40; 31 &lt;&lt; &#40;8 &#8211; configPRIO&#95;BITS&#41; &#41;<br />
/&#42; Priority 5, or 160 as only the top three bits are implemented. &#42;/<br />
&#35;define configMAX&#95;SYSCALL&#95;INTERRUPT&#95;PRIORITY &#40; 5 &lt;&lt; &#40;8 &#8211; configPRIO&#95;BITS&#41; &#41;  
/&#42; Priorities passed to NVIC&#95;SetPriority&#40;&#41; do not require shifting as the<br />
function does the shifting itself.&nbsp; Note these priorities need to be equal to<br />
or lower than configMAX&#95;SYSCALL&#95;INTERRUPT&#95;PRIORITY &#8211; therefore the numeric<br />
value needs to be equal to or greater than 5 &#40;on the Cortex M3 the lower the<br />
numeric value the higher the interrupt priority&#41;. &#42;/<br />
&#35;define configDMA&#95;INTERRUPT&#95;PRIORITY 5<br />
&#35;define configUSB&#95;INTERRUPT&#95;PRIORITY 6<br />
&#35;define configTIM1&#95;INTERRUPT&#95;PRIORITY 7<br />
&#35;define configTIM3&#95;INTERRUPT&#95;PRIORITY 8  
&#35;define configLCD&#95;INTERRUPT&#95;PRIORITY 4<br />
&#35;define configGPIO&#95;INTERRUPT&#95;PRIORITY 10  
And in SHPR2 the value is 0xF8F80000, which I belive is the lowest priority?  
How is priority between the peripherals interrupts and system interrupts?  
I have a pin toggling in the TICK&#95;HOOK and a pin in the USB it handler, when the system crashes the USB interrupt is Active and then the TICK&#95;HOOK is called.  
Any Ideas?
