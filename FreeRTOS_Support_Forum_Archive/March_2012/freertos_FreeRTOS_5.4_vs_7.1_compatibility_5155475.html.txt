  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">FreeRTOS 5.4 vs 7.1 compatibility</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/alan_rouse">alan_rouse</a> on March 30, 2012</div><div class="thread-post-content">I have been running with FreeRTOS V5.4 for a long time now on projects using Eclipse and an STM32 ARM processor, and have no problems with it.&nbsp; However, I want to evaluate Precipio&#8217;s Trace add-on, which needs FreeRTOS V7.1.&nbsp; I tried updating to this latest version, but my project won&#8217;t run:  
My startup code is quite straightforward, creating a single task then starting the scheduler.&nbsp; That first task in turn creates further tasks.&nbsp; However, the problem occurs when the code reaches the vTaskStartScheduler&#40;&#41; command, at which point the debugger jumps to the default handler.&nbsp; On stepping through vTaskStartScheduler&#40;&#41; I have found that the error occurs when it calls   
<pre><code>void vPortStartFirstTask( void )
{
    __asm volatile(
                    " ldr r0, =0xE000ED08   n" /* Use the NVIC offset register to locate the stack. */
                    " ldr r0, [r0]          n"
                    " ldr r0, [r0]          n"
                    " msr msp, r0           n" /* Set the msp back to the start of the stack. */
                    " cpsie i               n" /* Globally enable interrupts. */
                    " svc 0                 n" /* System call to start first task. */
                    " nop                   n"
                );
}
</code></pre>
When the debugger reaches the svc 0 instruction it jumps the the Default Handler.  
FreeRTOS v5.4 has slightly different code, and this works.  
<pre><code>void vPortStartFirstTask( void )
{
    __asm volatile(
                    " ldr r0, =0xE000ED08   n" /* Use the NVIC offset register to locate the stack. */
                    " ldr r0, [r0]          n"
                    " ldr r0, [r0]          n"
                    " msr msp, r0           n" /* Set the msp back to the start of the stack. */
                    " svc 0                 n" /* System call to start first task. */
                );
}
</code></pre>
Can anyone suggest how I should modify my code to be compatible with FreeRTOS v7.1?
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS 5.4 vs 7.1 compatibility</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on March 30, 2012</div><div class="thread-post-content">The extra line of code &#40;cpsie&#41; should not effect you.&nbsp; It was added to prevent a hard fault being generated under certain conditions with certain libraries.&nbsp; If you are jumping to the default handler, rather than hard faulting, I would suggest that your interrupt vector table is not populated with the FreeRTOS interrupt handlers.  
If you are using CMSIS compliant vector table then you can add the following three lines to FreeRTOSConfig.h to allow the code to vector to FreeRTOS correctly:  
<blockquote>
  &#35;define vPortSVCHandler SVC&#95;Handler<br />
  &#35;define xPortPendSVHandler PendSV&#95;Handler<br />
  &#35;define xPortSysTickHandler SysTick&#95;Handler
</blockquote>
Otherwise you will have to populate the vector table manually, and can check your previous working project to see where these three functions fit into the table.  
Regards.
