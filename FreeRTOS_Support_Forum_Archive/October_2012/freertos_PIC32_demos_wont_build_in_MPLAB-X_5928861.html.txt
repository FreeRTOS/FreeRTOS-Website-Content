  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">PIC32 demos won&#8217;t build in MPLAB-X</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/moto95">moto95</a> on October 5, 2012</div><div class="thread-post-content">I am sure it must be something simple but I can&#8217;t get the PIC32 demo project to build. Having done a clean install of all the up-to-date Microchip tools, i.e. MPLAB-X and XC-32 compiler, then downloaded the latest version of FreeRTOS, this is the first error I get:  
../../../Source/portable/MPLAB/PIC32MX/port.c:72:22: fatal error: FreeRTOS.h: No such file or directory  
Adding the path to FreeRTOS.h fixes that and then produces:  
C:/Users/xxx/MPLABXProjects/FreeRTOSV7.2.0/FreeRTOS/Source/include/FreeRTOS.h:80:28: fatal error: FreeRTOSConfig.h: No such file or directory  
Adding the path to FreeRTOSConfig.h than produces:  
In file included from C:/Users/xxx/MPLABXProjects/FreeRTOSV7.2.0/FreeRTOS/Source/include/FreeRTOS.h:83:0,  
and  
from ../../../Source/portable/MPLAB/PIC32MX/port.c:72:  
and  
C:/Users/xxx/MPLABXProjects/FreeRTOSV7.2.0/FreeRTOS/Source/include/portable.h:320:25: fatal error: portmacro.h: No such file or directory  
Please educate me&#33;  
</div></div><div class="thread-post"><h3 class="thread-post-title">PIC32 demos won&#8217;t build in MPLAB-X</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on October 5, 2012</div><div class="thread-post-content">Many people have reported that the include paths are being deleted in the project.&nbsp; I haven&#8217;t worked out how/why/when this happens yet, but suspect it is something to do with different tool versions or tool installation directories.  
The easiest way to add them back in is as manual command line options.&nbsp; To do this, bring up the project properties dialogue box, then go to Configuration-&gt;XC32 &#40;Global Options&#41;-&gt;XC32-GCC category.&nbsp; You will see a &#8220;Additional Options text box on the right side.&nbsp; In this box add the following text:  
<pre><code>-I ../../../Source/include -I ../../../Source/portable/MPLAB/PIC32MX -I ../../Common/include -I ../
</code></pre>
Do the same for the XC32-as options.  
Let me know what happens.  
Regards.  
</div></div><div class="thread-post"><h3 class="thread-post-title">PIC32 demos won&#8217;t build in MPLAB-X</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/moto95">moto95</a> on October 5, 2012</div><div class="thread-post-content">Just tried that and it worked&#33; It now compiles without errors. Many thanks&#33;  
Next question is how hard will it be to get the demo to work on a Microstick II with a PIC32MX250F128B? Is there anything else required besides reconfiguring the project for a different target and development board? Will just have to try it…
</div></div><div class="thread-post"><h3 class="thread-post-title">PIC32 demos won&#8217;t build in MPLAB-X</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on October 6, 2012</div><div class="thread-post-content">The FreeRTOS port itself will run on any PIC32.&nbsp; I think there are configurations in the MPLAB project you are using for three different chips already, but not the one you are specifically wanting to use.&nbsp; Like you say, you will have to re-target for the specific chip by doing things like changing the linker script to match the chip, ensuring configTOTAL&#95;HEAP&#95;SIZE fits in the RAM available, etc.  
Regards.
