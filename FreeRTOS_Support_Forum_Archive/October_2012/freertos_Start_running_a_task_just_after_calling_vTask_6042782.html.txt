All tasks created before calling vTaskStartScheduler will be started immediately after the call &#40;and execute in priority order&#41;. I tend to create most of my tasks before calling vTaskStartScheduler. Most of these will enter the task infinite loop and then block on the queue/semaphore that they will be feeding from.

Just create the task before calling vTaskStartScheduler. It will automatically start running when the scheduler starts, because no tasks can run before that anyway.<br />
Unless instructed differently by your particular port, you should also make sure that interrupts are disabled throughout your init code. When the scheduler starts it will normally enable interrupts automatically anyway, and it&#8217;s usually not safe to have any interrupts get triggered before the scheduler is up and running.  
Link  
Richard Damon<br />
7 hours ago<br />
There is no problem with creating all your tasks, queue, etc before calling vTaskStartScheduler. In fact this gets around the problem of tasks/interrupts needing to check if the needed resource has already been created before using it.<br />
The only time I would think of doing otherwise would be in a very memory constrained application that needed to run different tasks in different conditions, but the work needed to prove that the setup was &#8220;stable&#8221; is high, as this almost by definition requires using dynamic allocations at run time, which is very hard to fully verify as it has a long &#8220;memory&#8221; in the state of the heap.
