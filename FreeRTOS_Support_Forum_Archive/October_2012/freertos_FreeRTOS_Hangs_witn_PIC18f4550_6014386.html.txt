  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">FreeRTOS Hangs witn PIC18f4550</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/*anonymous">*anonymous</a> on October 12, 2012</div><div class="thread-post-content">Hi there,<br />
kindly i need your help running my 1st FreeRTOS program, i used the rtosdemo1 in PIC18&#95;MPLAB demo folder.<br />
i just created my own task to toggle a LED on/off.  
after the scheduler starts, the debugger stuck at portRESTORE&#95;CONTEXT&#40;&#41;;&nbsp; in void vPortYield&#40; void &#41; i don&#8217;t know what is the reason.  
there is no error in compilation.  
while in the same function &#8220;void vPortYield&#40; void &#41;&#8221;, i gets the warning or error about &#8220;portSAVE&#95;CONTEXT&#40; portINTERRUPTS&#95;UNCHANGED &#41;;&#8221;<br />
the message says &#8220;unexpected token: &#95;asm&#8221;  
here is my configuration:<br />
1- MPLAB X IDE v1.41<br />
2- PICC18 Compiler v 3.43<br />
3- FreeRTOS v7.1.0  
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS Hangs witn PIC18f4550</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/edwards3">edwards3</a> on October 12, 2012</div><div class="thread-post-content">The FreeRTOS web site does warn that PIC18 is a bad target for an RTOS. Its architecture does not lend itself, and its compiler assumes single threading.  
I suspect your problem is more related to the PIC18 chip architecture not being identical to the base PIC18 chip the port was written on. Changed compiler versions will also give you problems no dount.
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS Hangs witn PIC18f4550</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/*anonymous">*anonymous</a> on October 12, 2012</div><div class="thread-post-content">would you please send me the link to that article?  
i wonder how there is a port for PIC18 in the downloadable source if the PIC18 is not a good target &#33;&#33;
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS Hangs witn PIC18f4550</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on October 13, 2012</div><div class="thread-post-content">Just because it is not a good target does not stop people from using it.&nbsp; Consider the hardware stack that has to be swapped in and out as part of a task context, the segmented memory that stacks can&#8217;t easily cross, and the fact that the compiler itself is not re-entrant, and you begin to see the problems.  
You will see on this page: <a href="http://www.freertos.org/RTOS_ports.html">http://www.freertos.org/RTOS_ports.html</a> that the PIC18 is listed, but only in brackets &#40;although it is not made clear on the page why, admittedly&#41;.  
The PIC18 section of this page: <a href="http://www.freertos.org/a00090.html#MICROCHIP">http://www.freertos.org/a00090.html#MICROCHIP</a> starts by saying it is &#8220;less than ideal&#8221;.
