Richard<br />
1 day ago<br />
As per the link posted in my first reply &#40;it wan&#8217;t me that made the Cortex interrupts so complex&#33;&#41;:<br />
The STM32 implements four priority bits, so the lowest priority is 15. The top four bits of 191 &#40;decimal&#41; are 1011 &#40;binary&#41;, which equals 11 &#40;decimal&#41;. Therefore, interrupts that use the FreeRTOS API must have a logical priority of 11 or lower. On the Cortex-M3, lower priority means higher numeric value, so if you are using the API from your USART, then it must have a priority between 11 and 15 inclusive.<br />
Conclusion &#8211; your configuration is not valid and you need to either change the priority of the USART interrupt or the value of configMAX&#95;SYSCALL&#95;INTERRUPT&#95;PRIORITY.<br />
Regards.
