</div></div><div class="thread-post"><h3 class="thread-post-title">Exception 07 in the FreeRTOS Kernel using ModBus</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on October 14, 2013</div><div class="thread-post-content">I&#8217;m not following all this, but some questions:
First &#8211; you have configMAX<em>SYSCALL</em>INTERRUPT_PRIORITY set to 3, but then set the priority of tasks that use system calls to 5.  This will *definitely* cause you a problem.  Please read the documentation page for the PIC32 port (link further down in this post).
In your calls to xTaskCreate() you are setting the stack size to:
&#8220;(configMINIMAL<em>STACK</em>SIZE)3&#8243;
I&#8217;m not sure what that will do.  configMINIMAL<em>STACK</em>SIZE is defined as ( 380 ), so the preprocessor will example the stack size parameter to &#8220;( ( 380 ) )3&#8221;.  Is that even valid C code?
Currently you have configCHECK<em>FOR</em>STACK<em>OVERFLOW set to 0.  Why is that?  Given the strange code used to allocate the stack size your problem could be a stack overflow.  What happens when you set configCHECK</em>FOR<em>STACK</em>OVERFLOW to 2 and define the stack overflow hook function?
I would recommend defining configASSERT(), it might highlight a problem for you.  http://www.freertos.org/a00110.html#configASSERT
The documentation page for the PIC32 tells you how to write interrupt service routines.  It does not look like you are following the guidelines.  See the &#8220;Interrupt Service Routines&#8221; section: http://www.freertos.org/port<em>PIC32</em>MIPS_MK4.html
Regards.
