  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">_impure_ptr not setup when entering first task</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/beginend1">beginend1</a> on October 4, 2013</div><div class="thread-post-content">Did I missed something or <em>impure</em>ptr  only is initialized in vTaskSwitchContext(). This makes (on my SMT32f4 uC) that before first context switch <em>REENT points at global impute</em>data variable instead of first task reent variable.
Second: I think, that you should  use <em>REENT macro instead of _impure</em>ptr directly.
FreeRTOS version 7.5.2
</div></div><div class="thread-post"><h3 class="thread-post-title">_impure_ptr not setup when entering first task</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on October 4, 2013</div><div class="thread-post-content"><blockquote>
  Did I missed something or <em>impure</em>ptr only is initialized in vTaskSwitchContext().
</blockquote>
Hopefully you missed something, but like I say in the comments, I don&#8217;t use the newlib stuff myself so I am reliant on the people who requested its existence to let me know if anything is wrong.
prvInitialiseTCBVariables() (in tasks.c) is called to initialise the task control block of a task when the task is created &#8211; not when the task is first switched in.  prvInitialiseTCBVariables() contains the following code which, I think, means each task has its own initialised impure_ptr.
<pre>
#if ( configUSE_NEWLIB_REENTRANT == 1 )
{
    /* Initialise this task's Newlib reent structure. */
    _REENT_INIT_PTR( ( &( pxTCB->xNewLib_reent ) ) );
}
#endif /* configUSE_NEWLIB_REENTRANT */
</pre>
<blockquote>
  Second: I think, that you should use <em>REENT macro instead of _impure</em>ptr directly
</blockquote>
So the line:
<em>impure</em>ptr = &amp;( pxCurrentTCB->xNewLib_reent );
should become?:
<em>REENT = &amp;( pxCurrentTCB->xNewLib</em>reent );
Is that right?  Will everything else still compile ok?
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">_impure_ptr not setup when entering first task</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/beginend1">beginend1</a> on October 4, 2013</div><div class="thread-post-content">I am no talking about allocation of <em>reent struct but initialization of _impure</em>ptr. Task switching properly changes <em>impure</em>ptr but first task doesn&#8217;t use the vTaskSwitchContext() but prvPortStartFirstTask() which is port specific, and this function does not touch <em>impure</em>ptr. I&#8217;ve looked at the code and there is no clean solution. The <em>impure</em>ptr can&#8217;t be initialized in prvPortStartFirstTask() becouse tskTCB is opaque there. The only solution came up is initialization of <em>impure</em>ptr just before call to prvPortStartFirstTask() and somehow in xTaskResumeAll() and/or in xTaskGenericCreate().
</div></div><div class="thread-post"><h3 class="thread-post-title">_impure_ptr not setup when entering first task</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on October 4, 2013</div><div class="thread-post-content">Ok, I understand now.  So it is just the first execution of the first task that the pointer is not configured, not the first execution of every task.
When xPortStartScheduler() is called pxCurrentTCB already points to the task that will be started first, so I think the following code added before xPortStartScheduler() should do what you want.
<pre>
#if ( configUSE_NEWLIB_REENTRANT == 1 )
{
    /* Switch Newlib's _impure_ptr variable to point to the _reent
    structure specific to the task that will run first. */
    _impure_ptr = &( pxCurrentTCB->xNewLib_reent );
}
#endif /* configUSE_NEWLIB_REENTRANT */
</pre>
Do you agree?
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">_impure_ptr not setup when entering first task</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/beginend1">beginend1</a> on October 4, 2013</div><div class="thread-post-content">Yes, this code is needed but NOT BEFORE calling xPortStartScheduler(). Some code may want to do something before creating tasks and starting scheduler. If you switch <em>impure</em>ptr there you can mess up a lot of things (eg. stdin/out/err will be different, different errno variable, etc.). This must be done inside xPortStartScheduler(). I don&#8217;t know FreeRTOS source so good to  tell you if xPortStartScheduler() is the only place where _REEN should be guarded. Generally speaking, all places where pxCurrentTCB is changed and task is switched should follow _REEN synchronization with new task. My doubts are also places where you create/delete tasks when scheduler is suspended, this is the reason why I pointed out xTaskResumeAll() and xTaskGenericCreate().
And at the end I think that
<em>REENT = &amp;( pxCurrentTCB->xNewLib</em>reent );
will be ok 😛
</div></div><div class="thread-post"><h3 class="thread-post-title">_impure_ptr not setup when entering first task</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on October 4, 2013</div><div class="thread-post-content">I understand your point, but I&#8217;m not sure I understand the danger of where I have placed the code.
The sequence is as follows:
1) Interrupts are disabled.
2) The pointer is set to be correct for the first task.
3) xPortStartScheduler() is called.
4) The first task starts to run
Interrupt are not enabled until the point that the first task start to run &#8211; and all the code executed in between steps 1 and 4 is FreeRTOS code.  There is no possibility of any application code running during this time, so no possibility of any inadvertent calls to newlib.
I would be grateful if you could elaborate using this scenario so I can get a better understanding.
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">_impure_ptr not setup when entering first task</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/beginend1">beginend1</a> on October 5, 2013</div><div class="thread-post-content">Ok, looked again and you are right. I was thinking about vTaskStartScheduler() instead of xPortStartScheduler(). Your solution should work.
