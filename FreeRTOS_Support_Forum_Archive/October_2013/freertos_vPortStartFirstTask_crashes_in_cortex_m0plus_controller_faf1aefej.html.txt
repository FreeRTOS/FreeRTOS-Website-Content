</div></div><div class="thread-post"><h3 class="thread-post-title">vPortStartFirstTask crashes in cortex m0plus controller</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on October 21, 2013</div><div class="thread-post-content">For the code you post it looks like you are using an out of date FreeRTOS version, although I don&#8217;t think that is related to your problem.
Try replacing the code in prvStartFirstTask() (vPortStartFirstTask() in your case) with the following.  It starts the scheduler without using the SVCHandler, so interrupts can remain disabled until the task context is ready:
<pre>
/* The MSP stack is not reset as, unlike on M3/4 parts, there is no vector
table offset register that can be used to locate the initial stack value.
Not all M0 parts have the application vector table at address 0. */
ldr r3, =pxCurrentTCB /* Obtain location of pxCurrentTCB. */
ldr r1, [r3]            
ldr r0, [r1] /* The first item in pxCurrentTCB is the task top of stack. */
adds r0, #32 /* Discard everything up to r0. */
msr psp, r0  /* This is now the new top of stack to use in the task. */
movs r0, #2  /* Switch to the psp stack. */
msr CONTROL, r0
pop {r0-r5}  /* Pop the registers that are saved automatically. */
mov lr, r5   /* lr is now in r5. */
cpsie i      /* The first task has its context and interrupts can be enabled.*/
pop {pc}     /* Finally, pop the PC to jump to the user defined task code. */
</pre>
Please let me know if this solves the problem.
Regards.
