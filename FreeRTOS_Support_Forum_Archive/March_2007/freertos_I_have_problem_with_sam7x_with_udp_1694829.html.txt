I have modified the web demo sample to use udp protocol I have 2 task that wait on queues. I have also 1 udp connection. I use also the usb to emulate a joystick.
up to now i been able to do all i want. the usb part is working, the udp also. 
BUT, some time, the os hangs. I don&#8217;t know exactly why it hangs. I can run my software for 5 10 minutes, and he hangs. I have used the debugger to know where the program is, and he is loked up in this function :
unsigned portLONG ulEMACInputLength&#40; void &#41;
in this part of the function:
&nbsp;&nbsp;&nbsp; /&#42; Walk through the descriptors until we find the last buffer for this 
&nbsp;&nbsp;&nbsp; frame.&nbsp; The last buffer will give us the length of the entire frame. &#42;/
&nbsp;&nbsp;&nbsp; while&#40; &#40; xRxDescriptors&#91; ulIndex &#93;.addr &amp; AT91C&#95;OWNERSHIP&#95;BIT &#41; &amp;&amp; &#33;ulLength &#41;
&nbsp;&nbsp;&nbsp; &#123;
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ulLength = xRxDescriptors&#91; ulIndex &#93;.U&#95;Status.status &amp; emacRX&#95;LENGTH&#95;FRAME;
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; /&#42; Increment to the next buffer, wrapping if necessary. &#42;/
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ulIndex++;
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; if&#40; ulIndex &gt;= NB&#95;RX&#95;BUFFERS &#41;
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; &#123;
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ulIndex = 0;
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; &#125;
&nbsp;&nbsp;&nbsp; &#125;
I never get out from there. I would like to know if somebody have already had this issue. 
btw i have test my software with lwip 1.1.0 and also with 1.2.0 and same thing happen.
regards
Jonathan
</div></div><div class="thread-post"><h3 class="thread-post-title">I have problem with sam7x with udp</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/embeddedc">embeddedc</a> on March 16, 2007</div><div class="thread-post-content">The descriptors are automatically filled by the processor DMA.&nbsp; Something is getting corrupt in the RAM utilized by the DMA.
A fix would be to include some code to ensure that you don&#8217;t loop more than once, and if you find yourself doing this resetting the descriptors to their default state.&nbsp; This would prevent your code hanging, but does not fix the cause of the problem, only the symptom.&nbsp; It would be better to find what is causes the corruption in the first place.&nbsp; Most likely thing would be a stack overflow &#40;before anybody else says it&#41;.
</div></div><div class="thread-post"><h3 class="thread-post-title">I have problem with sam7x with udp</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/dumarjo">dumarjo</a> on March 19, 2007</div><div class="thread-post-content">This is what i though. 
When this happen, i don&#8217;t received interrupt from the mac anymore. 
Right now i use only 1 udp connection but i use it in 2 task. I will try to protect the connection with semaphore to see what happen.
JOnathan
</div></div><div class="thread-post"><h3 class="thread-post-title">I have problem with sam7x with udp</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/dumarjo">dumarjo</a> on March 21, 2007</div><div class="thread-post-content">Ok i have found the problem 
Protected the connection between both task is correcting some part of the problem. 
The second is since we don&#8217;t use the tcp at all, after the refresh of the arp table, the computeur cannot communicate with the arm7 because in the lwip sample from freertos, the broadcast bit is not set. So iu have change to accept the broadcast and now everything is working well. 
I have also remove the caf bit to receive only the data that match our mac addr. 
So thank-you for your help on that one. 
Jonathan
