</div></div><div class="thread-post"><h3 class="thread-post-title">keil compiler warning</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on March 30, 2007</div><div class="thread-post-content">You have a C166 port?&nbsp; There was somebody asking about this recently.
You don&#8217;t say what the warning it, but I suspect it is that the code has no effect.
The code is only there to prevent another compiler warning &#8211; that the parameter is not used.&nbsp; This is the standard way of preventing such warnings.
Dave.
</div></div><div class="thread-post"><h3 class="thread-post-title">keil compiler warning</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on March 30, 2007</div><div class="thread-post-content">Yes, we are working on C167 porting. We are still in initial phase, but when we will have some more stable code, for sure we will share information with the community.
About warning, we think thas is more powerfull write
pvParameters = pvParameters;
this kill all the warnings. But maybe this technic could generate one more istruction.
What do you think about this?
</div></div><div class="thread-post"><h3 class="thread-post-title">keil compiler warning</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on March 30, 2007</div><div class="thread-post-content">Compiling the same code base with many different compilers is a pain.&nbsp; Code you add to prevent a warning on one compiler will cause a warning on another.&nbsp; Things such as using qualifiers on pointers &#91;&#40; volatile char &#42; &#41; for example&#93; will cause warnings that the qualifier has no meaning on some, while others will complain that the qualifier is missing if you leave it off.
In this case the usual method to prevent a warning is to &#40;void&#41; it, as when getting rid of the Lint warning that a function return type is ignored.
Setting the value to itself could perceivably cause a warning on some compilers &#40;I have not tried it will all of them&#41; that the line has no effect.
Can you selectively prevent the warning from being issued in the project configuration?
Regards.
