</div></div><div class="thread-post"><h3 class="thread-post-title">Stack-Problem on LPC2290</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on March 14, 2007</div><div class="thread-post-content">Does the CAN ISR use a lot of stack?
Has the CAN ISR been written using the required syntax &#40;naked attributes, portENTER&#95;SWITCHING&#95;ISR&#40;&#41;, only declaring variables ater the call to portENTER&#95;SWITCHING&#95;ISR&#40;&#41;, etc&#41;?
In the Data Abort handler, inspect the value of pxCurrentTCB to find out the location of the stack being used.&nbsp; If there are no 0xA5&#8217;s left in the stack then it has overflowed.
</div></div><div class="thread-post"><h3 class="thread-post-title">Stack-Problem on LPC2290</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/lucky-joe">lucky-joe</a> on March 14, 2007</div><div class="thread-post-content">I don&#8217;t want to switch in the CAN-Isr only proceed my CAN-driver
the ISR ist attributed with the follwoing statement: 
void&nbsp; &#95;&#95;attribute&#95;&#95;&#40;&#40;interrupt&#40;&quot;IRQ&quot;&#41;&#41;&#41; v&#95;lpc22xx&#95;CanIsrRxBus1 &#40;void&#41;
I think it seems to be OK &#33;
I also tried to use the Macros : portSAVE&#95;CONTEXT &amp; portRESTORE&#95;CONTEXT but that crashed immediately :-&#40;
Joe
</div></div><div class="thread-post"><h3 class="thread-post-title">Stack-Problem on LPC2290</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on March 14, 2007</div><div class="thread-post-content">&gt; I don&#8217;t want to switch in the CAN-Isr only proceed my CAN-driver 
Not sure what this is meaning.
portSAVE&#95;CONTEXT &amp; portRESTORE&#95;CONTEXT should not be used in an IRQ.
portENTER&#95;SWITCHING&#95;ISR&#40;&#41; portEXIT&#95;SWITCHING&#95;ISR&#40;&#41; can only be used in naked functions.
Does not help with your problem.&nbsp; Just clarification.
