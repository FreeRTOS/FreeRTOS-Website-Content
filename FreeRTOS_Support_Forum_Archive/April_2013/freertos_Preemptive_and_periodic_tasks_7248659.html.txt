</div></div><div class="thread-post"><h3 class="thread-post-title">Preemptive and periodic tasks</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on April 1, 2013</div><div class="thread-post-content">A task &#40;even the highest priority one&#41; &#8220;blocks&#8221; if it blocks in a call to a Delay operation,&nbsp; or waits on a semaphore or queue.  
Typically, most tasks will have some operation in their loop which blocks, while they wait for the next time they should do more work. The only exception will be lowest priority tasks which intend to use any remaining time doing something. &#40;They need to be lowest as any task lower won&#8217;t get time&#41;.

</div></div><div class="thread-post"><h3 class="thread-post-title">Preemptive and periodic tasks</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on April 1, 2013</div><div class="thread-post-content">That sounds like something has corrupted your system. Some likely causes:  
Stack overrun<br />
Interrupts using not FromISR APIs &#40;or non-interrupts using a FromISR API incorrectly&#41;<br />
Interrupts with wrong priorities  
Also, as a side note, using vTaskSuspend this way is a bit unusual, and I find I use vTaskSuspend only in very unusual cases. Normally a task is waiting for SOMETHING, either time &#40;so you use a vTaskDelay or vTaskDelayUntil&#41; or is waiting for some data &#40;so you get data from a Queue&#41; or it is waiting to be signaled via a semaphore. These tend to be more reliable than using Suspend and Resume,

</div></div><div class="thread-post"><h3 class="thread-post-title">Preemptive and periodic tasks</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on April 1, 2013</div><div class="thread-post-content">Where did you get your PIC24 project from?  
How did you put your PIC24 project together?  
Have you tried building and running the official demo application for the PIC24 that comes in the FreeRTOS zip file download?  
Do you have stack overflow detection turned on?  
Did you start with something very simple to get confidence that you had integrated the code correctly?&nbsp; I would suggest starting by turning <strong>pre-emption off</strong>, then creating two tasks that do nothing but yield to each other.&nbsp; For example you can start with <strong>just</strong> the following two tasks:  
volatile unsigned long ul1, ul2;  
<pre><code>void vTask1( void *pvParameters )
{
    for( ;; )
    {
        ul1++;
        taskYIELD();
    }
}
void vTask2( void *pvParameters )
{
    for( ;; )
    {
        ul2++;
        taskYIELD();
    }
}
</code></pre>
Create these two tasks using:  
<pre><code>portBASE_TYPE xTaskCreate( 
                            vTask1, 
                            "T1",
                            configMINIMAL_STACK_SIZE,
                            NULL, 
                            1, 
                            NULL;
                          );
portBASE_TYPE xTaskCreate( 
                            vTask2, 
                            "T2",
                            configMINIMAL_STACK_SIZE,
                            NULL, 
                            1, 
                            NULL;
                          );
</code></pre>
Start the scheduler, let it run for a while &#40;you may be able to do that in the MPLAB simulator&#41;, then pause the debugger.&nbsp; Now if you inspect the ul1 and ul2 variables they should have approximately the same value.&nbsp; Next if you inspect xTickCount &#40;defined in tasks.c&#41; you should find it has incremented.  
If that works, then it shows you can yield from one task to another, then you can turn preemption on and take out the calls to taskYIELD&#40;&#41; and try it again…..  
Regards.
