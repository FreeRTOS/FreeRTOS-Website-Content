  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">How to decide on the configTICK_RATE_HZ value</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/shashank2388">shashank2388</a> on April 16, 2013</div><div class="thread-post-content">Hello,  
I am developing an application based on PIC24 where am trying to interface ADC sensors, UART and some GPIOs. The problem is when I am going to implement each one of these in different tasks. I know that the scheduler does the task swap in and out process based on the priority of the tasks and the time for execution is based on configCPU&#95;CLOCK&#95;HZ value which in turn depends on the frequency at which the controller is running. I modified the sample code in which the default value of configTICK&#95;RATE&#95;HZ was set to 1000 i.e 100 ms. But 100 ms is too much value for my project.   
So what is the criteria to decide the value of configTICK&#95;RATE&#95;HZ for a particular application?  
Thanks in advance….
</div></div><div class="thread-post"><h3 class="thread-post-title">How to decide on the configTICK_RATE_HZ value</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on April 16, 2013</div><div class="thread-post-content">configTICK&#95;RATE&#95;HZ sets a couple of things:  
1&#41; The granularity of the timing.&nbsp; For example, if you want to block for 125ms then you can block for exactly 125ms if the tick is every 1ms, but only for either 120 or 130ms if the tick is every 10ms.  
2&#41; How long each time slice will be if you have more than one task running at the same priority.  
Generally you want the frequency to be as low as viable for your application so as not to waist time processing unnecessary tick interrupts.  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">How to decide on the configTICK_RATE_HZ value</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on April 17, 2013</div><div class="thread-post-content">What I use to set this is to look at the lowest tick rate that gives me acceptable resolution for timeouts &#40;which normally don&#8217;t need to be very good&#41;, and suitable activation for events that need to occur on a periodic basis that can not be based on some other interrupt.
