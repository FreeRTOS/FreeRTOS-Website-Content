For information, I work with:<br />
&#45; FreeRTOS V6.1.1<br />
&#45; EWARM&nbsp; 6.21.3<br />
&#45; Compiler optimisation for FreeRTOS set to High &#40;Speed&#41;

</div></div><div class="thread-post"><h3 class="thread-post-title">xTicksToWait within xQueueSendToBack</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on April 16, 2013</div><div class="thread-post-content">xQueueSendToBack maps to xQueueGenericSend so that is expected.&nbsp; At high optimisation you may see the variable as zero in the debugger because there is no direct relationship between the source code and the object code. </div></div><div class="thread-post"><h3 class="thread-post-title">xTicksToWait within xQueueSendToBack</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on April 18, 2013</div><div class="thread-post-content"><blockquote>
  Do you have any idea?
</blockquote>
Sorry no &#8211; this is just C code.&nbsp; If you pass a parameter into a C file I would expect the compiler to generate code that passed the parameter into the function.&nbsp; All I can suggest is that you step through the assembly code to see the parameter getting placed into a register outside of the function call, and then see the value getting read out of the register inside the function call.  
If the parameter is passed on the stack rather than in a register ensure the stack pointer is correctly aligned at that point in the code.  
If you suspect a context switch is occurring in between calling the function and entering the function and that somehow that is corrupting the register value then try entering a critical section before calling the function &#40;call taskENTER&#95;CRITICAL&#40;&#41;&#41; just as an experiment .  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">xTicksToWait within xQueueSendToBack</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/fabiensf">fabiensf</a> on April 18, 2013</div><div class="thread-post-content">Hi Richard  
I tried your suggestion to call taskENTER&#95;CRITICAL&#40;&#41; before to call xQueueSendToBack and it works fine.<br />

Adding&nbsp; taskENTER&#95;CRITICAL&#40;&#41; was just for debug purpose, so I removed it and I will look now to fix this issue in my software.
