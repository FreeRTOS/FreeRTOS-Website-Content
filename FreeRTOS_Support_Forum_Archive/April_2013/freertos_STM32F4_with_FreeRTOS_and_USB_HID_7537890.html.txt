&#123;<br />
&#95;&#95;IO uint32&#95;t count = 0;<br />

&nbsp; do<br />
&nbsp; &#123;<br />

&nbsp;&nbsp;&nbsp; &#123;<br />

&nbsp; &#125;<br />
&nbsp; while &#40;1&#41;;<br />
&#125;  
After a call to this delay function, the debugger can&#8217;t return to the previous level and seems to run continuously. When I pause the execution, the debugger seems to be in a function from task.c&nbsp; vTaskSwitchContext&#40; void &#41; and I can&#8217;t continue the debugging.  
I have to mention that I call the USB init function before the creation of tasks and the start of scheduler.  
Thank you.
</div></div><div class="thread-post"><h3 class="thread-post-title">STM32F4 with FreeRTOS and USB HID</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on April 12, 2013</div><div class="thread-post-content">That delay function is very crude. It does not seem to take into account the clock speed for a start so will presumably only give you microseconds at when the STM32 is running at one particular clock speed. It just a C function though and probably nothing to do with the problem you are seeing.  
<blockquote>
  I have to mention that I call the USB init function before the creation of tasks and the start of scheduler.
</blockquote>
Are you saying that this error occurs before the scheduler has started? In which case vTaskSwitchContext&#40;&#41; should never be running and I would guess that either vTaskSwitchContext&#40;&#41; is installed on the wrong interrupt vector, or that your USB driver is using the same vectors as FreeRTOS. FreeRTOS uses the SVC, SysTick and PendSV interrupts, is the driver using any of those?
</div></div><div class="thread-post"><h3 class="thread-post-title">STM32F4 with FreeRTOS and USB HID</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/vbordianu">vbordianu</a> on April 12, 2013</div><div class="thread-post-content">The delay function comes from an official example. It works very well in the project that not include FreeRTOS. Yes, this error occurs before the scheduler has started.&nbsp; I will check the vectors used by USB driver and the necessity of the code from SysTick&#95;Handler &#40;I think I&#8217;ve already remove it&#41;.  
I will come back with an answer asap.  
Thank you.
