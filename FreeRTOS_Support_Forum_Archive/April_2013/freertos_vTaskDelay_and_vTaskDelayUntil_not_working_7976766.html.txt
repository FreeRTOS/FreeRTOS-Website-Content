I have retargeted the LPC2106 GCC demo for my LPC2138 MCU based on the Rowley 2138 demo.<br />
Everything seems to work fine except for vTaskDelay and vTaskDelayUntil. It seems that whenever I call any of these it just stucks there forever. I have not disabled the interrupts. Unfortunately I don&#8217;t have access to a debugger, so I am only relying on LEDs for now. I enable a LED then call vTaskDelay or vTaskDelayUntil, then it will never reach the code part to disable the LED. Do you have any idea what can cause such behavior?<br />
By the way if I replace vTaskDelay with an own crappy delay function &#40;like counting to 0xFFFFF&#41; the code works as expected.

</div></div><div class="thread-post"><h3 class="thread-post-title">vTaskDelay and vTaskDelayUntil not working</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on April 29, 2013</div><div class="thread-post-content">Sorry &#8211; my mistake &#8211; you are correct that the page I directed you to is relevant only to microcontrollers with Cortex-M cores, whereas you are using an ARM7 core.  
The 2106 needs vPortYieldProcessor&#40;&#41; to be installed on the SWI interrupt vector to manage taskYIELD&#40;&#41; calls, and the IRQ vector to autovector to the correct interrupt for timer ticks.&nbsp; On the 2106 that is done using a vector table something like the following in the startup code &#40;assuming you have not changed the timer configuration in the 2106 port layer&#41;:  
<pre><code> b     _start        /* reset handler */
 ldr   pc, _undf     /* undefined handler */
 ldr   pc, _swi      /* SWI handler */
 ldr   pc, _pabt     /* program abort handler */
 ldr   pc, _dabt     /* data abort handler */
 nop                 /* reserved */
 ldr   pc, [pc,#-0xFF0] /* IRQ set to read VIC directly */
 ldr   pc, _fiq      /* FIQ handler */
_undf:  .word __undf /* undefined */
_swi:   .word vPortYieldProcessor /* FreeRTOS Yield. */
_pabt:  .word __pabt /* program abort */
_dabt:  .word __dabt /* data abort */
_fiq:   .word __fiq  /* FIQ */
</code></pre>
Ensure the tick and yield handler entry points are compiled to ARM instructions &#40;as opposed to THUMB instructions&#41;.  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">vTaskDelay and vTaskDelayUntil not working</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/mcufan">mcufan</a> on May 2, 2013</div><div class="thread-post-content">Thank you Richard. I think the problem was with the serialISR routines. When I rewrote it to use UART1 instead of UART0 I must have missed something and probably it kept the whole MCU blocked before the scheduler could even start.<br />
I started everything again from the LPC2106 example and everything works correctly now.
