</div></div><div class="thread-post"><h3 class="thread-post-title">LPC43xx Dual Core Application</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on April 2, 2013</div><div class="thread-post-content">To my knowledge, FreeRTOS is not set up specifically to handle a multi-core environment. You are going to have to handle a few issues:  
1&#41; The current code for a critical section just uses blocking off interrupts. For a multicore system, it must also block the other core from entering a critical section, otherwise it is possible for the two processors to be updating the same data at once, which will cause problems.  
2&#41; You may need to worry about cache coherency, just because one processor has written a value doesn&#8217;t mean the other processor will immediately see the change, depending on how the cache works, it is also possible that the order of writes may change.  
3&#41; It sounds like your system isn&#8217;t &#8220;symmetrical&#8221; so tasks need to organized so that they know which processor they can run in. If no tasks can run on either processor, the simplest would be to have two task lists &#40;and related structures&#41;, otherwise you need to add an affinity flag into the TCB.  
4&#41; Either of these changes will require other changes in the FreeRTOS kernel. Either the scheduler for a core needs to know how to pass over tasks that can&#8217;t run on that core, or other parts need to scan the multiple task list to activate tasks on all cores that are waiting for something. These pieces also need to find tasks on all cores for activation.

</div></div><div class="thread-post"><h3 class="thread-post-title">LPC43xx Dual Core Application</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/maszup">maszup</a> on April 26, 2013</div><div class="thread-post-content">the problem i had was solved by doing followning actions:  
1&#41; in lpcexpresso M0/M4 projects configure MCU settings to use different RAM memory regions. proviously M0/M4 were using the same ram and i got hard faults. that allowed me to run M0 from M4  
2&#41; change the way of debugging &#8211; by using debugger in lpcxpresso i thought i was running the code on M0 but in fact i did it on M4. in order to do it properly configure your Launch configuration for M0 so that it not Load the image to target &#8220;Load image&#8221; = FALSE @ Launch Configuration-&gt;Debugger-&gt;Script Values. Then i load both codes on M0/M4 with flasher and while running the code jump into M0 code with debugger &#8211; in this way M4 always runs M0 at startup  
3&#41; configure timer in M4 and just enable/disable its interrupt in M0. I was not able to configure timer at the M0 &#40;rit or timer0&#41;. I don&#8217;t know why yet but probably i forgot about something.  
4&#41; IPC example on queues did not work. it stopped after the second message recieved from M0. so i decided to simplify that and used IPC interrupts only and made my own communication structure which i located in shared memory space:
