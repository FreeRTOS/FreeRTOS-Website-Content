  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">FreeRTOS port for MPLAB/PIC18F452</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/joconnor37">joconnor37</a> on January 2, 2008</div><div class="thread-post-content">I have FreeRTOS demo project building successfully for 18F452 in MPLAB, programming successfully into an 18F452 development board from Forest Electronics Development&#40;FED&#41;, but getting &quot;little action&quot; on the board. The FreeRTOS demo project should flash LEDs on PORTD but doesn&#8217;t. In starting to dig deeper into the code, something immediately confuses me &#8211; partest.h defines:-
&#35;define partstDEFAULT&#95;PORT&#95;ADDRESS &#40; &#40; unsigned portSHORT &#41; 0x378 &#41;&nbsp;&nbsp; &#8211; I presume this is
PORTD, PORTD&lt;7:4&gt; drive the 4 LEDs on the FED development board. But the Microchip datasheets
give the address of PORTD as F83h. I cannot complete the reference chain between the &#35;define statement above, and actual PORTD &#8211; so maybe the demo project is not asking PORTD to do anything at present&#8230;.?
Has anyone else worked with this particular port of FreeRTOS? Any advice gratefully accepted as I am probably missing something simple here.
Regards,
John O&#8217;Connor
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS port for MPLAB/PIC18F452</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on January 2, 2008</div><div class="thread-post-content">The name partest.c is a left over from the original &quot;PARallel port TEST&quot;, and the 0x378 is the default address used to access the parallel port on a PC compatible system.&nbsp; I didn&#8217;t realise the definition was in the partest.h file, it should be moved to the FreeRTOS/Demo/PC/Partest/Partest.c file as this is the only file to which it is relevant, sorry for any confusion caused.&nbsp; It will not be used in the PIC code.
Look at the file FreeRTOS/Demo/PIC18&#95;MPLAB/Partest/partest.c to see how the LEDs are accessed on the FED hardware.
Its been quite I while since I fired up the FED board.&nbsp; My first suggestion would be to double check that all the fuse settings are correct.
Regards.
