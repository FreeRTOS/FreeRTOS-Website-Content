</div></div><div class="thread-post"><h3 class="thread-post-title">Recent changes that could affect behavior of vPortStartFirstTask</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/westmorelandeng">westmorelandeng</a> on May 11, 2016</div><div class="thread-post-content">Hello,
For the port I am running under IAR for the TI Hercules processor &#8211; I have made the following change in ./portable/ARM_Cortex-R4/port.c:
in StackType<em>t *pxPortInitialiseStack( StackType</em>t *pxTopOfStack, TaskFunction_t pxCode, void *pvParameters )
In order to get the first task to start properly:
<em>pxTopOfStack = ( StackType_t ) 0x00000000; /</em> R14 */
has been changed to:
<em>pxTopOfStack = ( StackType_t ) pxOriginalTOS &#8211; 64; /</em> R14 */
Here is my comment I have in my code:
    // *** this is a fix for the first task to start &#8211; otherwise it
    // *** is taking the contents of 0 (zero), adding 60 and taking
    // *** that as the address before subtracting 4 and loading
    // *** that to the PC; which is wrong.  It doesn&#8217;t hurt to do
    // *** this fix-up since R14 is the LR for this architecture.
    // *** &#8212; jcw
  Appears to be an innocuous fix to get the first task started.  
Regards,
John W.
