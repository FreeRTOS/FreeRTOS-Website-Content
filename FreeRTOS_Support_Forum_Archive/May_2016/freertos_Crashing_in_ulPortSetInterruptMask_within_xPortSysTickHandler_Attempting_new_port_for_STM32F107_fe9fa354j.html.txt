  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Crashing in ulPortSetInterruptMask within xPortSysTickHandler (Attempting new port for STM32F107)</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/dibosco">dibosco</a> on May 18, 2016</div><div class="thread-post-content">I&#8217;ve spent a lot of time fruitlessly trying to get USB going on the very old STM32F107 port for Rowley Crossworks that we&#8217;ve been using for a couple of years with uIP. Then we tried generating a FreeRTOS project from STM&#8217;s Cube to get the USB going, but although that kind of worked, if you plugged and unplugged, then replugged the USB cable it crashed. I spent some time on this and just couldn&#8217;t fathom it. 
So, finally today I decided to create a new FreeRTOS Project with Rowley Crossworks, use the latest STM libraries and import an run to complete project that works with USB as a CDC class just fine. 
Everything seemed to be going well, I got an LED flash task going and I was happy, until I tried sending what was coming in on the virtual com port to a queue rather than just echoing it back within the interrupt. I&#8217;m now chasing my tail trying to stop it getting hard fault handler errors all the time. 
I found that my two threads (USB thread to handle what was put in the CDC queue within the USB interrupt and an LED flash thread) were not getting called more than once. I then wondered whether the timer tick wasn&#8217;t set up properly, compared interrupt vectors in my old F107 project and realised that vectors were indeed not set up. I imported the startup.s file and modified the vectors to be the same as the old F107 FreeRTOS project, but now I am just getting crashes all the time, no matter what I try. I&#8217;ve had it crash at SVC<em>Handler and now after tinkering a bit more I&#8217;m just crashing all the time in xPortSysTickHandler() when it calls ulPortSetInterruptMask(). As soon as I step into the asm</em>volatile line that is in the ulPortSetInterruptMask function, I get a hard fault exception. 
I suspect this isn&#8217;t really enough to help me track this down, but thought it was worth a try. I&#8217;m running the project on the STM3210C-EVAL for what it&#8217;s worth. 
If anyone has any pointers or needs any more information to try to track this down I&#8217;d be most grateful.
Thanks!
Rob
</div></div><div class="thread-post"><h3 class="thread-post-title">Crashing in ulPortSetInterruptMask within xPortSysTickHandler (Attempting new port for STM32F107)</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/dibosco">dibosco</a> on May 18, 2016</div><div class="thread-post-content">For the moment, I&#8217;ve recreated from scratch the basic bare bones 
FreeRTOS with just the LED flash and it&#8217;s working. I&#8217;ve put it into 
Mercurial this time so can always roll back to here. I&#8217;ll add the USB 
and see whether I get back to this same stage.
I&#8217;d forgotten I&#8217;d added the three lines:
~~~
<h1>define vPortSVCHandler SVC_Handler</h1>
<h1>define xPortPendSVHandler PendSV_Handler</h1>
<h1>define xPortSysTickHandler SysTick_Handler</h1>
~~~
To FreeRTOSConfig.h and that it can&#8217;t have been a timer tick issue 
because the LED Flash thread was originally working fine.
I may be back for advice if I keep struggling when adding the queue in 
the USB code hinders me.
Thanks!
