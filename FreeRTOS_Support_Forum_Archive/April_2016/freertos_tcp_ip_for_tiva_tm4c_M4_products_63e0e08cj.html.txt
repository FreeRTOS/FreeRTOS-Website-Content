</div></div><div class="thread-post"><h3 class="thread-post-title">tcp/ip for tiva tm4c M4 products</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on April 18, 2016</div><div class="thread-post-content">I think there was somebody on the forum using a Tiva, but we don&#8217;t have any code ourselves.  If you have FreeRTOS working on the board, and you have a working network driver, then instructions on stitching in FreeRTOS+TCP can be found here: http://www.freertos.org/FreeRTOS-Plus/FreeRTOS<em>Plus</em>TCP/FreeRTOS<em>TCP</em>Porting.html
</div></div><div class="thread-post"><h3 class="thread-post-title">tcp/ip for tiva tm4c M4 products</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/frankthetank34">frankthetank34</a> on April 19, 2016</div><div class="thread-post-content">Within that link, it says that &#8220;Each MCU to which FreeRTOS+TCP is ported requires an Ethernet MAC driver. It is assumed this already exists and is known to work. &#8221; The ethernet MAC driver for the tiva products would be tivaware. However, I can&#8217;t find where this specifies what is required of the the ethernet MAC driver. Is that because the functions are only called from the &#8220;network interface port layer&#8221;? 
In the example network interface.c file for the STM32 parts, there are several other functions defined. Where are prvNetworkInterfaceInput, vMACBProbePhy and others documented? Should I follow the online guide and only provide the init, and interfaceoutput functions? While also sending data via the sendeventstructtoiptask?
Do I need a prvEthernetUpdateConfig() function?
Thanks!
</div></div><div class="thread-post"><h3 class="thread-post-title">tcp/ip for tiva tm4c M4 products</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on April 19, 2016</div><div class="thread-post-content">There are only two dependencies between the FreeRTOS+TCP code and the 
Ethernet driver, that is, the Ethernet driver must provide two 
functions.  The two functions are as per the following two bullet points:
<ul>
<li>The network interface port layer must provide a function called <a 
href="http://www.freertos.org/FreeRTOS-Plus/FreeRTOS_Plus_TCP/Embedded_Ethernet_Porting.html#xNetworkInterfaceInitialise">xNetworkInterfaceInitialise()</a> 
that initialises the MAC driver.</li>
<li>The network interface port layer must provide a function called <a 
href="http://www.freertos.org/FreeRTOS-Plus/FreeRTOS_Plus_TCP/Embedded_Ethernet_Porting.html#xNetworkInterfaceOutput">xNetworkInterfaceOutput()</a> 
that sends data received from the embedded TCP/IP stack to the Ethernet 
MAC driver for transmission.</li>
</ul>
If those two functions are not provided then the code won&#8217;t link, as 
they will be undefined references.
How those functions are implemented is up to you, but it is recommended 
to map them as closely as you can to functions that are already known to 
be working that perform similar functionality.
The implementation of those functions will inevitably call other 
hardware specific function to do things like set up port pins, provide a 
clock to the MAC hardware, probe the PHY, etc., they are the other 
functions you are seeing.  They are chip specific, and private to and 
only used internally by the driver &#8211; FreeRTOS+TCP does not need them to 
be defined and they can be anything that is required to make the driver 
work (and are nearly always provided for you by the chip vendor).
