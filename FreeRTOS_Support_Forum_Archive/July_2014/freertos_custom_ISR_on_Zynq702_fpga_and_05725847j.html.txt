The hardware, on certain occasions, raises an interrupt which i&#8217;m trying to catch and by using a semaphore to synchronize my task with my hardware. So far i have managed to catch the interrupt but i&#8217;m getting an assertion failure at tasks.c:2360 (configASSERT( pxUnblockedTCB );)
My code:
Modified Demo/CORTEX<em>A9</em>Zynq<em>ZC702/RTOSDemo/src/FreeRTOS</em>tick_config.c: vConfigureTickInterrupt()
<pre><code>// Install the foo ISR.
extern void rtos_fooISR(void *data) /*__attribute__ ((isr))*/;
/// (notice i don't use the __attribute__ (isr), more on this later)
XScuGic_SetPriorityTriggerType( &amp;xInterruptController, 90, (configMAX_API_CALL_INTERRUPT_PRIORITY) &lt;&lt; portPRIORITY_SHIFT, ucRisingEdge);
xStatus = XScuGic_Connect( &amp;xInterruptController, 90, (Xil_ExceptionHandler) rtos_fooISR, NULL);
configASSERT( xStatus == XST_SUCCESS );
( void ) xStatus;
XScuGic_Enable(&amp;xInterruptController, 90);
</code></pre>
Somewhere in main i initialize the binary semaphore:
    BaseType_t status;
    (void) status;
<pre><code>/// Initialize semaphore
foo_Semaphore = xSemaphoreCreateBinary();
configASSERT(foo_Semaphore != NULL);
status = xSemaphoreGive(foo_Semaphore);
configASSERT(status == pdTRUE);
</code></pre>
Here is the ISR:
    void rtos<em>fooISR(void *data)
    {
        static BaseType</em>t xHigherPriorityTaskWoken = 0;
        static volatile unsigned int *reg_addr = (unsigned int *)(BASE + foo_INTERRUPT);
        (void) data;
        /// Clear interrupt
        *reg_addr = 0x1;
        /// &#8220;give&#8221; semaphore
        /// xil_printf(&#8220;gnr&#8221;);
        xSemaphoreGiveFromISR(foo_Semaphore, &amp;xHigherPriorityTaskWoken);
        portYIELD_FROM_ISR(xHigherPriorityTaskWoken);
    }
And this is the function the task calls when it wants to synchronize with the hardware
    void rtos<em>waitForfoo(void)
    {
       xil</em>printf(&#8220;tnr&#8221;);
       xSemaphoreTake(foo<em>Semaphore, portMAX</em>DELAY);
    }
Is my code correct or i&#8217;m using a hack without being aware of it? Any idea why i get the assertion failure?
Also when i declare the rtos_fooISR function with the <strong>attribute</strong>((isr)) it appears that the interrupt stays on for ever. Why is that?
Thanks for your time.
</div></div><div class="thread-post"><h3 class="thread-post-title">custom ISR on Zynq702 fpga and </h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on July 5, 2014</div><div class="thread-post-content">I cannot see anything that is obviously wrong in your code.  You definitely don&#8217;t want to use the <strong>attribute</strong> on your ISR handler as that will cause the compiler to add interrupt handling prologue and epilogue code that will not be compatible with the FreeRTOS interrupt entry point.  There is a single interrupt entry point that already contains the necessary prologue code before calling your handler as a standard C function.
The assert that is failing is inside the xTaskRemoveFromEventList() function &#8211; which will be getting called from your interrupt handler, but probably from other places too.  Is the assert failing from inside your handler (so from inside the xSemaphoreGiveFromISR() function)?
Regards.
