However, my code doesn&#8217;t work as I expected. Judging by my testing with breakpoint, vInterruptHandler obviously never gets called so there is no switching to high priority task. What happens is the following: 
1.) tasks and semaphore get created and schedular gets running 
2.) vHandlerTask &#8220;takes&#8221; semaphore and prints &#8220;Handler task ->> Processing event&#8221; and turns on the LED. This is ok.
3.) Next, schedular switches to vPeriodicTask that waits for delay and then prints &#8220;About to generate SW interrupt&#8230;&#8221;. Then it generates SW interrupt and at that point the program freezes. Generated SW interrupt should wake up interrupt handler (that should then switch to vHandlerTask once again) but it does not.

</div></div><div class="thread-post"><h3 class="thread-post-title">Need help with &#8220;button&#8221; interrupt task (xSemaphoreGiveFromISR)</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on August 1, 2014</div><div class="thread-post-content">If the interrupt is never being entered then I would agree &#8211; it does not sound like FreeRTOS is causing the problem.  I would recommend getting the interrupt to work with a very simply loop in main(), before creating any tasks or starting the scheduler.
I presume the interrupt requires some hardware configuration in order for it to work configuration &#8211; and presumably that is done in the EXTI0<em>Config(); function.  Have you looked in that function to see what it does?  I imagine it will as a minimum enable the interrupt.  Is that the same function you were using before?  Next the EXTI</em>GenerateSWInterrupt() function &#8211; have a look in that to see what it is doing.  I suspect it will just be writing to one of the processors Set Pending registers.
When you say the code freezes, what is it actually doing?  If you stop on the debugger where are you?  If you are in a default interrupt handler, rather than the EXTI0 handler, then maybe it is the wrong interrupt that is being raised in the &#8216;generate&#8217; function, or that the handler for the interrupt is in the incorrect vector (did you install the handler in the vector table?).
Regards.

Actually I just find the problem &#8211; it was the interrupt handler function <strong>name</strong>! (Periodic task:) About to generate SW interrupt&#8230;.
Handler task ->> Processing event!!
(Periodic task:) &#8230;Interrupt was generated&#8230;

It was silly from me that I didn&#8217;t think of this issue before&#8230; What confused me was different handler interrupt name in that example I mentioned &#8211; but that was obviously because of of using different Cortex family I guess. Thanks for your answers anyway. Now I can finally move on my original idea &#8211; to use <strong>user button</strong> to generate interrupt.
</div></div><div class="thread-post"><h3 class="thread-post-title">Need help with &#8220;button&#8221; interrupt task (xSemaphoreGiveFromISR)</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on August 4, 2014</div><div class="thread-post-content">The name has to match the name in the interrupt vector table. If you call the function a different name then you will have to edit the vector table to so the names match. You will probably find the name in the vector table is EXTI0<em>1</em>IRQHandler, but the provided implementation of EXTI0<em>1</em>IRQHandler is declared weak, so it is replaced by your definition in the application code.
