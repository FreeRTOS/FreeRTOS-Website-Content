</div></div><div class="thread-post"><h3 class="thread-post-title">VtaskDelay before scheduler start</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on November 7, 2018</div><div class="thread-post-content">vTaskDelay won&#8217;t work before the scheduler is started, as the system tick hasn&#8217;t been started yet, and interrupts are disabled.
</div></div><div class="thread-post"><h3 class="thread-post-title">VtaskDelay before scheduler start</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/delphes">delphes</a> on November 7, 2018</div><div class="thread-post-content">Thanks Richard, in my case STM32L4 the initTick was already called before scheduler start so my FreeRTOS timer is working, so is there are other reason linked to task that not allow me to use vTaskDelay ?
</div></div><div class="thread-post"><h3 class="thread-post-title">VtaskDelay before scheduler start</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on November 7, 2018</div><div class="thread-post-content">Calling vTaskDelay() before the scheduler starts doesn&#8217;t really have any 
semantic sense as, if the scheduler has not been started, no tasks are 
executing, so no task can call vTaskDelay().  Calling vTaskDelay() from 
a function called by main() doesn&#8217;t make sense as its not a task.
What is the use case?
</div></div><div class="thread-post"><h3 class="thread-post-title">VtaskDelay before scheduler start</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richarddamon">richarddamon</a> on November 8, 2018</div><div class="thread-post-content">initTick is NOT the call to setup the tick for FreeRTOS, that sounds like maybe part of the STMicro library (maybe they somehow support a dual use for it).
Also, as Richard Barry said, what vTaskDelay does is put the current task into the blocked state and switch to another task for the duration, that sort of is hard to do before the schedule starts, since you don&#8217;t have any task, either current or another.
If you have some initiliation that needs those sorts of delays, either you need a spin wait delay loop, or you postpone that part of the initialization until after your enable the FreeRTOS scheduler.
</div></div><div class="thread-post"><h3 class="thread-post-title">VtaskDelay before scheduler start</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on November 8, 2018</div><div class="thread-post-content"><blockquote>
  initTick is NOT the call to setup the tick for FreeRTOS, that sounds 
  like maybe part of the STMicro library (maybe they somehow support a 
  dual use for it).
</blockquote>
ST chain their tick and the FreeRTOS tick.
<blockquote>
  If you have some initiliation that needs those sorts of delays, either 
  you need a spin wait delay loop, or you postpone that part of the 
  initialization until after your enable the FreeRTOS scheduler.
</blockquote>
There is also an intialisation hook, which runs in the context of the 
timer task (which means you need to have timers enabled).  It runs once 
when the scheduler starts and is provided to allow you to perform 
initialisation that requires the kernel.  More traditional methods use 
an &#8216;initialisation&#8217; task that performs the initialisation then creates 
all the other application tasks.
