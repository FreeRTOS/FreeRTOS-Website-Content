  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Port for AT91SAM7S-EK using CrossWorks GCC?</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/brucewehr">brucewehr</a> on March 17, 2006</div><div class="thread-post-content">I am new to both FreeRTOS and AT91, and would like to use the FreeRTOS demo as a launch pad to learn my way around both.&nbsp; I have the AT91SAM7S-EK evaluation board and Rowley&#8217;s CrossWorks &#40;GCC&#41; IDE.&nbsp; FreeRTOS provides ports of the demo for both the 7S processor &#40;but using the IAR IDE&#41; and GCC &#40;but using the 7X processor&#41;.
I&#8217;ve tried using the GCC 7X demo on the 7S-EK board with no luck &#40;verifier errors&#41;.&nbsp; Does anyone have a port of the demo &#40;or porting instructions&#41; for the S-EK eval board using GCC?
As an aside, does anyone know where I could get an AT91SAM7X-EK eval board?
Thanks.
</div></div><div class="thread-post"><h3 class="thread-post-title">Port for AT91SAM7S-EK using CrossWorks GCC?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on March 17, 2006</div><div class="thread-post-content">I think you should be able to get the SAM7X converted for the S fairly easily.
Do you get this error on the download?
Have you, checked the FreeRTOSConfig.h file to check the heap size is as per the S demo, ensure you have changed the CrossWorks target to the S to get the right linker script.
</div></div><div class="thread-post"><h3 class="thread-post-title">Port for AT91SAM7S-EK using CrossWorks GCC?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on March 18, 2006</div><div class="thread-post-content">I have not actually tried it but I think the following procedure will get you pretty close:
1&#41; Copy the demo/lwIP&#95;Demo&#95;Rowley&#95;ARM7 directory to a new directory called something like demo/Rowley&#95;SAM7S.
2&#41; From within CrossStudio open the rtosdemo workspace in the new Rowley&#95;SAM7S directory.
3&#41; In the project explorer right click on the rtosdemo project, select properties from the pop up menu, select the built tab of the pop up windows, and set the target processor to the one you are using.&nbsp; In the same pop up window select the linker tab and set the memory map file to the one for the processor you are using.
4&#41; Back in the project explorer window, delete the following files from the build:
i&#41; The entire lwIP folder.
ii&#41; USC-CDC.c
iii&#41; USBISR.c
iv&#41; semtest.c
v&#41; pollq.c
vi&#41; integer.c
vii&#41; blockq.c
viii&#41; BasicWEB.c
This leaves you with just the flash tasks for a simple starting point.
5&#41; The file partest.c contains the code that writes to the LED&#8217;s on the board.&nbsp; The code for this is therefore dependent on the&nbsp; EK you are using.&nbsp; Open up partest.c and write the function to initialise, set and LED and toggle an LED to use the correct ports for your target board.&nbsp; If you are using the same EK as per the FreeRTOS SAM7S IAR demo then look at the partest.c file that comes with this demo for most of the code you need.&nbsp; Test that the partest.c code works in isolation &#40;just create a main&#40;&#41; function that calls these functions so you know they work before you try and use them with the rtos&#41;.
6&#41; Take the FreeRTOSConfig.h file from the IAR SAM7S demo and copy all the &#35;defines into the FreeRTOSConfig.h file in your new Rowley&#95;SAM7S directory.&nbsp; Don&#8217;t just replace the file as it might contain other settings you require.
7&#41; Open port.c and replace the included header file AT91SAM7X256.h with the correct header for your processor.
Try compiling and see how you go.&nbsp; The Rowley tools have an excellent debugger so you should be able to isolate any problems fairly easily.
Regards.
