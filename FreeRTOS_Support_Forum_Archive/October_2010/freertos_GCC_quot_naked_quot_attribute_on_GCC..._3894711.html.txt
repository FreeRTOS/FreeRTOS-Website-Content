  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">GCC &#8220;naked&#8221; attribute on GCC&#8230;</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/spacewrench">spacewrench</a> on October 14, 2010</div><div class="thread-post-content">I&#8217;m getting back to some ARM programming after a while using AVR.&nbsp; I&#8217;d upgraded GCC a few times along the way, so I&#8217;m using 4.4.0 &#40;and tried 4.5.1&#41;.&nbsp; I can&#8217;t compile examples because of an internal compiler error associated with the naked attribute used on various ISRs and low-level functions.&nbsp; Looking through the GCC mailing lists and wikis, it appears that &#8220;naked&#8221; functions can no longer have arguments, local variables, or anything really except asm&#40;&#41; statements.  
Has anybody in the FreeRTOS community encountered this?&nbsp; Solved it?&nbsp; Perhaps I should just downgrade to 4.3.2 or something?  
Thanks&#33;
</div></div><div class="thread-post"><h3 class="thread-post-title">GCC &#8220;naked&#8221; attribute on GCC&#8230;</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on October 14, 2010</div><div class="thread-post-content">I don&#8217;t think any naked functions in FreeRTOS have any attributes as they are all ISRs. Where exactly in the FreeRTOS code is the problem occurring?  
Some naked functions contain C code, but these can be converted to asm easily if it is causing you a problem.  
The compiler should not crash no matter what you feed it so it sounds like a compiler bug. I am using V4.4.2 ok.
</div></div><div class="thread-post"><h3 class="thread-post-title">GCC &#8220;naked&#8221; attribute on GCC&#8230;</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/spacewrench">spacewrench</a> on October 14, 2010</div><div class="thread-post-content">My compilation of JC Wren&#8217;s LPC2148 sample code was crashing on some of his ISR code, not on the &#8220;naked&#8221; functions in the FreeRTOS-5.1.0 code that he uses.&nbsp; I posted here because I thought the FreeRTOS people might have encountered this and solved it.&nbsp; The people talking about it elsewhere appear to be Linux-ARM people and/or GCC people, and discussion tends to peter out after somebody points out that the GCC docs say &#8220;nothing but asm&#40;&#41; allowed in naked functions.&#8221;  
&#40;There is agreement that the compiler shouldn&#8217;t crash in any case, but apparently it&#8217;s harder to fix the crash than one might like, plus it could be that not many people outside the embedded community are encountering the problem.&#41;  
Anyway, my problem is not that I don&#8217;t know how to fix it / convert to non-naked, but that I&#8217;d rather do it without hacking up other people&#8217;s code, so for example I can drop in a new version of FreeRTOS when it comes out.  
I&#8217;ve had success by just reverting to GCC-4.3.2, so I&#8217;ll use that until the compiler guys figure out the Right Way to deal with this.  
Thanks&#33;
</div></div><div class="thread-post"><h3 class="thread-post-title">GCC &#8220;naked&#8221; attribute on GCC&#8230;</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/ben_fnr">ben_fnr</a> on October 14, 2010</div><div class="thread-post-content">Am using GCC 4.4.3 and naked ISR functions without any problems. I have never used local variables though as there is no stack setup for them when declaring the function as naked. If I need variables I just call another C function declared normally.
