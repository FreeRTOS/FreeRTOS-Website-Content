  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">FreeRTOS + STR912 with Ride7</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/mkyrylen">mkyrylen</a> on October 21, 2010</div><div class="thread-post-content">Hi,  
I am trying to convert an existing &#8216;bare metal&#8217; application to utilising FreeRTOS.&nbsp; I am new to FreeRTOS.<br />
Currently we are running a bootloader in Bank 1 of flash, which starts the main application in Bank 0.&nbsp; FreeRTOS is to only run in the main application.&nbsp; Bootloader has not been modified, but the main application has its own complete startup crt0.S &#40;only flash is not reconfigured, since it is setup correctly in bootloader&#41;.  
Based on a STR91x port of FreeRTOS, which uses Eclipse &#40;search for STF12&#41;, I have&nbsp; modified my crt0.S to match the STF12 crt0.S by:<br />
&#45; using portSAVE&#95;CONTEXT and portRESTORE&#95;CONTEXT for IRQ and SWI handlers<br />
&#45; changing the mode to supervisor &#40;MSR CPSR&#95;c, &#35;Mode&#95;SVC|I&#95;BIT|F&#95;BIT&#41; at the end of the stack setup<br />
port.c and portISR.c we obtained from STF12  
My testing involves trying to send data to UART0.&nbsp; I try to do this before the scheduler is started and on the starting of a single task.&nbsp; The text has never displayed within the task, and also does not display before scheduler started with the above configuration .  
I have looked at other ports, and tried any differences.&nbsp; So far no joy getting the above going.<br />
Any pointers?&nbsp; I can provide further details if needed.  
Thanks for any assistance,<br />
Mykola
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS + STR912 with Ride7</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on October 22, 2010</div><div class="thread-post-content">If you configure your interrupt to use the save and restore context then it would be wrong to try and use the interrupt before the scheduler has started. If trying to use the interrupt before the scheduler has started did not cause a crash then I think the interrupts are probably just globally disabled. Did you try putting a break point in the interrupt to see if it is hit?  
The contrib part of the FreeRTOS site &#40;<a href="http://interactive.freertos.org%29/">http://interactive.freertos.org&#41;</a> has some files posted by somebody called Stefano. He also has his own website with lots of FreeRTOS stuff that uses GCC &#40;as Ride does&#41;. Did you see these?
