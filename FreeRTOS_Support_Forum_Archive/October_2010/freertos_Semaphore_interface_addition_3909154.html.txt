  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Semaphore interface addition</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/williamhhowell">williamhhowell</a> on October 22, 2010</div><div class="thread-post-content">I&#8217;m using FreeRTOS V6.0.5, and have noticed that in the semphr.h interfaces that the interface to delete a semaphore is missing.  
I realize that underneath it all it&#8217;s simply a specialization of a queue &#40;as is evidenced by the other macros in semphr.h&#41;, and that vQueueDelete works just fine on them. I simply think that for completeness that the following should be added to the interface file:  
&#35;define vSemaphoreDelete&#40; xSemaphore &#41; vQueueDelete&#40; xSemaphore &#41;  
Regards,  
</div></div><div class="thread-post"><h3 class="thread-post-title">Semaphore interface addition</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on October 22, 2010</div><div class="thread-post-content">That is a good idea, and to be honest I didn&#8217;t realise this was missing.&nbsp; I would be grateful if you could open a Feature Request tracker item for this so it doesn&#8217;t get lost.  
There are dangers associated with deleting both queues and semaphores when tasks are in their blocked lists.&nbsp; Hopefully this is an obvious point, and easy to ensure the lists are empty prior to the queue/semaphore being deleted.  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">Semaphore interface addition</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/williamhhowell">williamhhowell</a> on October 25, 2010</div><div class="thread-post-content">Opened a Feature Request to add this interface.  
I ran across the need for this interface while creating a set of test cases to compare performance and size differences against other RTOS&#8217;s.<br />
There are separate pre-test setup and post-test teardown of resources functions to keep the creation/destruction sequencing straight.<br />
I&#8217;d have preferred to do all this in C++ with proper RAII usage inside classes, but am constrained to 64kbytes, so no C++ this time&#33;
