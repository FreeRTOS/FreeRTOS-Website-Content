  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Stack overflow when only Idle task running</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/*anonymous">*anonymous</a> on May 4, 2012</div><div class="thread-post-content">Hi everyone &#33;  
i actually got a &#8220;little&#8221; problem within my project: even when i don&#8217;t use any task &#40;so there shall only be the Idle one running&#41;, i got stack overflows after a while; using traceTASK&#95;SWITCHED&#95;IN&#40;&#41; and uxTaskGetStackHighWaterMark&#40;&#41; to print stack usage on UART, it seemed that the stack is continuously growing up to the overflow…  
Do you have any idea about where could it come from?<br />
I guess it&#8217;s probably an error in my port &#40;using a TI MSP430F5438 with mspgcc&#41;, as there ain&#8217;t many people talking about such a thing on the internet.<br />
TY<br />
Matt.
</div></div><div class="thread-post"><h3 class="thread-post-title">Stack overflow when only Idle task running</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on May 4, 2012</div><div class="thread-post-content">Where did you get the port from?  
If it was from the FreeRTOS distribution &#8211; then the FreeRTOS GCC port will only work on the base, rather than extended, MSP430 parts.&nbsp; There are official FreeRTOS ports to that device, but only for IAR and CCS.   
FreeRTOS has both an IAR MSP430 and an IAR MSP430X port, so if you want to have GCC running on an X part I would suggest looking at both IAR ports to see the differences, and then copy the differences into your GCC port layer.&nbsp; If you use it unmodified, I would not expect it to work.  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">Stack overflow when only Idle task running</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/*anonymous">*anonymous</a> on May 4, 2012</div><div class="thread-post-content">Wow&#33; the quick reply is quite impressive &#33; Thanks &#33; :&#41;  
The port has been made by a colleague, using the official versions from the demos &#40; i&#8217;m nearly shure that&#8217;s from the IAR one&#41;.  
So I guess i shall have a look at how he made his port.  
But there&#8217;s something weird : it looks like everything is working fine with some other projects which have the same port :-/
</div></div><div class="thread-post"><h3 class="thread-post-title">Stack overflow when only Idle task running</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/*anonymous">*anonymous</a> on May 4, 2012</div><div class="thread-post-content">Okay, i found the problem: i was using the <em>traceTASK&#95;SWITCHED&#95;IN&#40;&#41;</em> macro, but i was doing some printf&#40;&#41; inside…<br />
Once i removed them, everything came back to normal :-&#41;
