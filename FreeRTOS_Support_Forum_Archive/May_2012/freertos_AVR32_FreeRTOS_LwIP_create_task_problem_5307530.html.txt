  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">AVR32 + FreeRTOS + LwIP create task problem</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/*anonymous">*anonymous</a> on May 28, 2012</div><div class="thread-post-content">I am modifing the demo example : AVR32 with FreeRTOS and LwIP provided by Atmel for my application.  
I removed the original created task: Basic Web, Basic SMTP and BASIC TFTP, and added my own tasks: SIP&#95;UAC, SIP&#95;UAS and RTP.  
The stask size parameter in the create- task function is: SIP&#95;UAC: 256, SIP&#95;UAS: 256, RTP:128. They are smaller than the original provided tasks. When I run the software, I found that the SIP&#95;UAS task can not be created and return NULL. So I removed almost all the things inside the SIP&#95;UAS task and set the stack size parameter to 32 only, the code is now:  
<pre><code>#include "FreeRTOS.h"
#include "task.h"
portTASK_FUNCTION( vUASTask, pvParameters)
{
     vTaskDelay(100);
}
</code></pre>
However, the task still can not be created. Then I removed the SIP&#95;UAC, the SIP&#95;UAS task now can be created. And then I remove SIP&#95;UAS and restore SIP&#95;UAC, the task can be created. I found that it has problem if both SIP&#95;UAC and SIP&#95;UAS exist…..but the SIP&#95;UAS task basically has nothing inside except the vTaskDelay&#40;&#41; funcion…..&nbsp; anybody can give me some advice? Thank you very much
</div></div><div class="thread-post"><h3 class="thread-post-title">AVR32 + FreeRTOS + LwIP create task problem</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/*anonymous">*anonymous</a> on May 28, 2012</div><div class="thread-post-content">Sorry the code should be:  
<pre><code>#include "FreeRTOS.h"
#include "task.h"
portTASK_FUNCTION( vUASTask, pvParameters)
{
    for(;;){
     vTaskDelay(100);
    }
}
</code></pre>
</div></div><div class="thread-post"><h3 class="thread-post-title">AVR32 + FreeRTOS + LwIP create task problem</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on May 28, 2012</div><div class="thread-post-content">When you converted the Atmel project, did you change any setting in FreeRTOSConfig.h? If the project used to create more tasks with bigger stacks than your application is trying to do then you should not have an issue with the task stack sizes. Step through the xTaskCreate&#40;&#41; function to see where it fails. If you are using heap&#95;1.c or heap&#95;2.c then you can also define a malloc failed hook function &#40;vApplicationMallocFailed&#40;&#41; I think&#41; to trap memory allocation problems.  
What is configTOTAL&#95;HEAP&#95;SIZE set to in FreeRTOSConfig.h &#40;only relevant if heap&#95;1.c or heap&#95;2.c is used&#41;?
