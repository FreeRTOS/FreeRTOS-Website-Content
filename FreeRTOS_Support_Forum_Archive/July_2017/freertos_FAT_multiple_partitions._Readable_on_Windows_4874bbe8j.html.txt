</div></div><div class="thread-post"><h3 class="thread-post-title">+FAT multiple partitions.  Readable on Windows?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on July 25, 2017</div><div class="thread-post-content">Hi Michael, in the FreeRTOS+FAT demo projects, in <code>ff_sddisk.c</code>, you will see that :
<pre><code>BaseType_t xPartitionNumber = 0;
</code></pre>
Just because 99% percent of the memory cards have a single partition.
But there may be good reasons to use 2 partitions and +FAT will indeed recognise them: both primary as well as extended/logical partitions.
If you are using SD-cards, be aware that only the first partition will have it&#8217;s FAT table in a FAT-optimised area ( the second 4MB erase block ). So you might notice that subsequent partitions are slower, and maybe even less reliable.
Within <code>ff_ioman.c</code> you see how partitions are being discovered, with the function <code>FF_PartitionSearch()</code>:
~~~
    xPartitionCount = FF<em>PartitionSearch( pxIOManager, &amp;partsFound );
    if( FF</em>isERR( xPartitionCount ) )
    {
        xError = xPartitionCount;
        break;
    }
~~~
</div></div><div class="thread-post"><h3 class="thread-post-title">+FAT multiple partitions.  Readable on Windows?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on July 25, 2017</div><div class="thread-post-content">Forgot to tell how the two ( or more ) partitions will be represented in the file system.
Normally there is an SD-card with a single partition, which will be found in the root (<code>"/"</code>).
As an example, the following files are located in the first partition mounted on <code>"/"</code>:
~~~
    /readme.txt
    /etc/config.ini
    /firmware/bootloader.hex
~~~
The modules <code>ff_sys.c</code> and <code>ff_stdio.c</code> allow you to combine several volumes into a single file system. For instance, if you create a RAM disk, you can mount its root on e.g. <code>"/ram"</code> :
~~~
    /ram
    /ram/files/picture1.jpg
    /ram/tmp/_WM68C7.tmp
~~~
When the first partition of the SD-card is mounted as <code>"/"</code>, you can mount the second partition as follows:
~~~
    FF<em>FS</em>Add( &#8220;/part2&#8221;, pxDisk_2 );
~~~
The user interface of FreeRTOS+TCP has two layers:
1) Lower level functions that work on a single volume. <code>FF_Open()</code>, <code>FF_Read()</code>, <code>FF_Write()</code>. These functions will not recognise your <code>"/part2"</code>.
2) STDIO-compatible functions that do recognise mounted volumes, such as <code>"/ram"</code> and <code>"/part2"</code>, These functions have a prefix <code>"ff_"</code>, such as <code>ff_fopen()</code>, <code>ff_fread()</code>/<code>ff_fwrite()</code>, and <code>ff_fclose()</code>.
It sounds all more complicated than it actually is. It works very much like mounting in Linux, except that the mount-points are always located in the root directory.
There have recently been some essential changes to a few +FAT source files, I&#8217;m attaching these changes here below in <code>ff_sys.zip</code>.

</div></div><div class="thread-post"><h3 class="thread-post-title">+FAT multiple partitions.  Readable on Windows?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on August 5, 2017</div><div class="thread-post-content">Hi Machael, your original question in the email was:
<blockquote>
  Why would the two drives come together in a single file system?
  Shouldn&#8217;t each partition have its own file system?
</blockquote>
I will answer it for the other people following this thread:
you are right, each partition is a file system on its own. But <code>ff_sys.c</code> and <code>ff_stdio.c</code> will map one of the partitions onto a <strong>symbolic directory</strong>.
All files under e.g.<code>"/part2"</code> will refer to the second partition. Other files and directories within the root directory are all located on the first partition.
<blockquote>
  Better questions to follow&#8230;
</blockquote>
I&#8217;m all curious 🙂
</div></div><div class="thread-post"><h3 class="thread-post-title">+FAT multiple partitions.  Readable on Windows?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on August 5, 2017</div><div class="thread-post-content">Another way to look at it is that there are several ways to express a multi-volume/partition file system. In windows we are used to &#8216;Drive Letters&#8217; where the main hard drive is C:, and other drivers are given a distinct letter. This has a fundamental limit of 26 volumes/partitions. 
A second method, also used in windows is the &#92;servershare prefix.
A third method, used on *nix like systems is that / is the root of all systems and some directory (like /part2) is mapped to point to the other volumes/partitions.
