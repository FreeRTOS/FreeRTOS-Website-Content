I&#8217;m trying to run freeRTOS demo application in the Explorer16/32 demo board with PIC24FJ1024GB610 MCU. 
In<a href="https://sourceforge.net/p/freertos/discussion/382005/thread/6e192cab/"> other topic</a> I comment a problem related with the task (or set of tasks) named #4 in FreeRTOS demo application. It is failing. But another question came up observing the behavior of it. 
In this example, there is one task wich only role is to &#8220;talk&#8221; with the LCD (like a &#8216;gatekeeper task&#8217; according to the official comments). 
This task is initialized from main.c file:
~~~
/* Start the task that will control the LCD.  This returns the handle
to the queue used to write text out to the task. <em>/
xLCDQueue = xStartLCDTask();
~~~
xStartLCDTask() code is:
~~~
QueueHandle_t xStartLCDTask( void )
{
    /</em> Create the queue used by the LCD task.  Messages for display on the LCD
    are received via this queue. */
    xLCDQueue = xQueueCreate( lcdQUEUE_SIZE, sizeof( xLCDMessage ) );
<pre><code>/* Start the task that will write to the LCD.  The LCD hardware is
initialised from within the task itself so delays can be used. */
xTaskCreate( vLCDTask, "LCD", configMINIMAL_STACK_SIZE, NULL, tskIDLE_PRIORITY + 1, NULL );
return xLCDQueue;
</code></pre>
}
~~~
And the task code is next:
~~~
static void vLCDTask( void *pvParameters )
{
xLCDMessage xMessage;
unsigned short usRow = 0;
<pre><code>/* Remove compiler warnigns. */
( void ) pvParameters;
/* Initialise the hardware.  This uses delays so must not be called prior
to the scheduler being started. */
prvSetupLCD();
/* Welcome message. */
prvLCDPutString( "www.FreeRTOS.org" );
for( ;; )
{
    /* Wait for a message to arrive that requires displaying. */
    while( xQueueReceive( xLCDQueue, &amp;xMessage, portMAX_DELAY ) != pdPASS );
    /* Clear the current display value. */
    prvLCDClear();
    /* Switch rows each time so we can see that the display is still being
    updated. */
    prvLCDGotoRow( usRow &amp; 0x01 );
    usRow++;
    prvLCDPutString( xMessage.pcMessage );
    /* Delay the requested amount of time to ensure the text just written 
    to the LCD is not overwritten. */
    vTaskDelay( xMessage.xMinDisplayTime );     
}
</code></pre>
}
~~~
If I&#8217;m not wrong, the code** prvLCDPutString( &#8220;www.FreeRTOS.org&#8221; );** should run just once, when the <em>vLCDTask</em> is initialized. Instead, I&#8217;m watching the message** &#8220;www.FreeRTOS.org&#8221;** in my LCD display frecuently. <strong>So, is the demo application resetting itself?</strong>
On the other hand, like I mentioned at the beggining, Task #4 is failing and I don&#8217;t know the cause. 
<strong>Are this two issues related?</strong>
I apreciate a lot your help.
