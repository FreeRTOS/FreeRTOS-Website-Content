  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">xTaskNotifyGive() and suspended tasks</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rjc101">rjc101</a> on July 13, 2017</div><div class="thread-post-content">If I have a task suspended on a ulTaskNotifyTake with the delay set to portMAX_DELAY, I believe this is treated as a suspened rather than blocked task.  Is this the same state as a vTaskSuspend and if so could a xTaskNotifyGive() wake up a task that has been explicitly suspended with a vTaskSuspend()?
i.e. is a task explicitly suspended with vTaskSuspend able to be woken up with anything other than a vTaskResume ?
</div></div><div class="thread-post"><h3 class="thread-post-title">xTaskNotifyGive() and suspended tasks</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on July 13, 2017</div><div class="thread-post-content">Internally, within FreeRTOS, a task that is block indefinitely is stored 
in the Suspended list &#8211; but it is NOT in the Suspended state &#8211; it is 
just an internal implementation.  A task that is suspended using 
vTaskSuspend() can only be resumed using vTaskResume().  A task that is 
in the Blocked state, be it blocked on a notification or any other 
primitive, cannot be resumed using vTaskResume().
</div></div><div class="thread-post"><h3 class="thread-post-title">xTaskNotifyGive() and suspended tasks</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rjc101">rjc101</a> on July 13, 2017</div><div class="thread-post-content">Hmm, that is what I presumed should be happening but if I suspend a task that was probably already blocked by the ulTaskNofityTake if I send it a notification from xTaskNofityGivefromISR it seems to wake up again.  Does the order matter, i.e. the TaskNotifyTake would be before it was suspended?
I&#8217;ll see if I can replicate things to confirm what is happening, as it caught me by surpise to see a suspended task processing some data.  I&#8217;m using a PIC32MZ EF processor with FreeRTOS v9.  
</div></div><div class="thread-post"><h3 class="thread-post-title">xTaskNotifyGive() and suspended tasks</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rjc101">rjc101</a> on July 14, 2017</div><div class="thread-post-content">I can confirm that if I have a task suspended with a vTaskSuspend it can be resumed with a direct task  notification sent to a task that has a ulNotifyTake (regardless of the delay time set) pending, providing the task was waiting for a notification before being suspended.
</div></div><div class="thread-post"><h3 class="thread-post-title">xTaskNotifyGive() and suspended tasks</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on July 14, 2017</div><div class="thread-post-content">Looking through the checkin comments in SVN I see the following on

it is causing an issue you can get the head revision from the public SVN 
repository in SourceForge.
