  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">RTOS current consumption</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/pheeenix">pheeenix</a> on April 14, 2009</div><div class="thread-post-content">Hi, 
I think of using FreeRtos on my board but I want to supply the via batteries and so I would like to know how the FreeRTOS effects the current consuption. Is there any rule of thumb how the current consuption increases?
Maybe someone knows?
Thanks&#33;
</div></div><div class="thread-post"><h3 class="thread-post-title">RTOS current consumption</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on April 14, 2009</div><div class="thread-post-content">Using FreeRTOS shouldn&#8217;t affect your current consumption by much &#40;unless you fall into the trap of making your program do more now that it is easy to do.&#41; It may even let you save power if you can put a sleep instruction in the idle loop. The biggest key is to make sure that the &quot;tick&quot; period for FreeRTOS is appropriate, if you need to do things 50 time a second, use a 20 ms &#40;50Hz&#41; timer, not a 1ms &#40;1000Hz&#41; one.
</div></div><div class="thread-post"><h3 class="thread-post-title">RTOS current consumption</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on April 15, 2009</div><div class="thread-post-content">Using an RTOS can save current because you can design the system to be completely event driven &#8211; removing any CPU cycles that would otherwise be wasted by polling.&nbsp; When an event is not being processed the idle task will run and immediately put the processor into a power down state.
Using an RTOS can cost current because it needs a periodic tick to work.&nbsp; Lots of aps have a periodic interrupt anyway so if that is the case then it makes no difference.
As richard&#95;damon says, setting the tick to the slowest possible is key.&nbsp; We have in the past played around with slowing the clock down before placing the processor into sleep mode too.&nbsp; To do this you have to increment more than one tick each time the tick interrupt occurs.&nbsp; For example, if you half the clock speed then increment the tick twice on each tick interrupt &#40;while the clock remains slower&#41;.&nbsp; If you quarter the clock speed then increment the tick four times on each tick interrupt &#40;while the clock remains slower&#41;.&nbsp; Etc.&nbsp; Once an event occurs and there is processing to do set the clock back to its full speed, assuming the processing needs to be done quickly that is.
Regards.
