</div></div><div class="thread-post"><h3 class="thread-post-title">reallocate main program</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/aturowski">aturowski</a> on April 2, 2009</div><div class="thread-post-content">I am using this kind of assembly file:
/&#42;==============================================&#42;/
/&#42; exceptions and interrupt vectors table setup &#42;/
/&#42;==============================================&#42;/
 .section .startup,&quot;ax&quot;
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; .arm
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; .align 0
&nbsp;&nbsp;&nbsp; b&nbsp;&nbsp;&nbsp;&nbsp; start&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; /&#42; jump from here just after reset &#42;/
&nbsp;&nbsp;&nbsp; b&nbsp;&nbsp;&nbsp;&nbsp; vUndefinedInstructionException
&nbsp;&nbsp;&nbsp; b&nbsp;&nbsp;&nbsp;&nbsp; vPortYieldProcessor&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; /&#42; used for manual calling SWI instruction to call the scheduler and task yielding &#42;/
&nbsp;&nbsp;&nbsp; b&nbsp;&nbsp;&nbsp;&nbsp; vPrefetchAbortException
&nbsp;&nbsp;&nbsp; b&nbsp;&nbsp;&nbsp;&nbsp; vDataAbortException
&nbsp;&nbsp;&nbsp; b&nbsp;&nbsp;&nbsp;&nbsp; vReservedException
&nbsp;&nbsp;&nbsp; ldr&nbsp;&nbsp; pc,&#91;pc, &#35; -0xF20&#93;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; /&#42; jump to the interrupt exception handler address given in AIC register&#42;/
&nbsp;&nbsp;&nbsp; b&nbsp;&nbsp;&nbsp;&nbsp; vFiqException
This is setting up exception/reset vector table in section called &quot;.startup&quot;. In linker script I simply put this section where it belongs:
MEMORY
&#123;
&nbsp;&nbsp; FLASH&nbsp; : ORIGIN = 0x0, LENGTH = 256K
&nbsp;&nbsp; RAM : ORIGIN = 0x200000, LENGTH = 64K&nbsp;&nbsp; /&#42; length of RAM &#42;/
&#125;
&#95;&#95;ram&#95;end&#95;&#95; = RAM&#95;ORIGIN + RAM&#95;SIZE;
SECTIONS
&#123;
/&#42; setup TEXT section &#42;/
&nbsp; . = 0;
&nbsp; &#95;&#95;text&#95;beg&#95;&#95; = .;
&nbsp; startup :
&nbsp; &#123;
&nbsp;&nbsp;&nbsp; &#42;&#40;.startup&#41;
&nbsp; &#125; &gt; FLASH
Of course you can hardcode this section origin address in assembly, but I prefer to have that control in linker file.
Hope that helps.
Regards,
Adam

</div></div><div class="thread-post"><h3 class="thread-post-title">reallocate main program</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/incrediball">incrediball</a> on April 7, 2009</div><div class="thread-post-content">The problem with a bootloader is that it defines the default vector table and you would need to get the bootloader interrupt handling to relay all the interrupts through to the main program. This is messy, may not support all of the interrupt types &#40;e.g. SWI in your case&#41; and adds latency to the interrupt handling. To use get around this problem modify your main program so:
1&#46; Define your ROM or FLASH sector at 0x00100000 plus the size of the bootloader sector. For example if you reserve 4K for the bootloader &#40;this corresponds to the first lockable page on the AT91SAM7S64&#41; then define it at 0x00101000.
Note that the flash memory on the AT91SAM7S is really located at 0x00100000 so doing this is not a trick. This memory is only mirrored to 0x00000000 by default.
2&#46; Locate your vector table at 0x00200000, for example:
/&#42; Exception vectors located at 0x00200000. These are re-mapped to 0x00000000 by the re-map command &#42;/
/&#42; Note that undf, pabt, dabt just execute a null loop. &#42;/
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; .section&nbsp;&nbsp;&nbsp; .vectors
&#95;vectors:
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; b&nbsp;&nbsp;&nbsp; .&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; /&#42; 0x00 reset &#8211; not used since the processor has already reset when it re-maps the memory &#42;/
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; b&nbsp;&nbsp;&nbsp; .&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; /&#42; 0x04 undef &#42;/
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ldr&nbsp;&nbsp;&nbsp; pc, &#95;swi&#95;ram&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; /&#42; 0x08 swi &#42;/
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; b&nbsp;&nbsp;&nbsp; .&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; /&#42; 0x0C pabt &#42;/
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; b&nbsp;&nbsp;&nbsp; .&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; /&#42; 0x10 dabt &#42;/
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; nop&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; /&#42; 0x14 rsvd &#42;/
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ldr&nbsp;&nbsp;&nbsp; pc, &#91;pc,&#35;-0xF20&#93;&nbsp;&nbsp;&nbsp; /&#42; 0x18 irq &#8211; load PC with the interrupt vector in AT91C&#95;BASE&#95;AIC-&gt;AIC&#95;IVR &#42;/
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ldr&nbsp;&nbsp;&nbsp; pc, &#91;pc,&#35;-0xF20&#93;&nbsp;&nbsp;&nbsp; /&#42; 0x1c fiq &#8211; load PC with the interrupt vector in AT91C&#95;BASE&#95;AIC-&gt;AIC&#95;FVR &#42;/
&#95;swi&#95;ram:&nbsp;&nbsp;&nbsp; .word vPortYieldProcessor
You will need to modify your linker script to tell the linker to put the vectors section first in the RAM.
3&#46; Perform a remap command as soon as the main program starts up. This mirrors the vector table defined at 0x00200000 to 0x00000000 thus replacing the vector table defined by the bootloader.
