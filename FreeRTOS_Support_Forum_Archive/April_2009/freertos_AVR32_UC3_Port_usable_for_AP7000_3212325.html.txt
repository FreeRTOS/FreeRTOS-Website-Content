  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">AVR32 UC3 Port usable for AP7000?</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/bri1234">bri1234</a> on April 15, 2009</div><div class="thread-post-content">Does the AVR32 UC3 port work for a AVR32 AP7000 processor? If not can someone explain why it does not work?
I know there is a port for the AVR32 AP7000 &#40;ap7x-freertos&#41; but the port is not supported officially. Also the interrupt handling of the UC3 port looks more &quot;professional&quot; to me. 
</div></div><div class="thread-post"><h3 class="thread-post-title">AVR32 UC3 Port usable for AP7000?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on April 15, 2009</div><div class="thread-post-content">I have never looked at the AP7000 but I would guess as somebody started a new port for that processor then the two would not be compatible.
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">AVR32 UC3 Port usable for AP7000?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/bri1234">bri1234</a> on April 17, 2009</div><div class="thread-post-content">The development of the unofficial AP7000 port started one year before Atmel added the UC3 port to the FreeRTOS project.
I take a look at the sourcecode and I found a comment in the file exceptions.S that it supports the UC3 devices only. The other files in the directory &quot;portable&quot; can be used for all AVR32 devices. So I think it should be not too complicated to get FreeRTOS running on the AP7000 with the official UC3 port. I will give it a try.
</div></div><div class="thread-post"><h3 class="thread-post-title">AVR32 UC3 Port usable for AP7000?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/jesperv">jesperv</a> on April 27, 2009</div><div class="thread-post-content">Hi Bri
I&#8217;m also looking fo a working port for the AVR32AP7000. How is it working out?
Regards Jesper
</div></div><div class="thread-post"><h3 class="thread-post-title">AVR32 UC3 Port usable for AP7000?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/bri1234">bri1234</a> on May 3, 2009</div><div class="thread-post-content">Hi Jesper,
there are only minor problems &#40;e.g. renaming some variables&#41; to compile the UC3 port for a AP7000. But unfortunately the RTOS crashes after starting the scheduler &#40;vTaskStartScheduler&#41;. I tracked down the problem to the context switch code in the file &quot;portmacro.h&quot;. Some assembler instructions used in the code work different on the UC3 and the AP7000 processor: SCALL, RETS and RETE. On the UC3 the instructions save the state of some registers to the stack automaticially. The AP7000 uses shadow registers instead.
I am not very familiar with the AVR32 because I started programming the AVR32 three weeks ago. Therefore it might take some days to get it running. It would be nice if you could help me.
</div></div><div class="thread-post"><h3 class="thread-post-title">AVR32 UC3 Port usable for AP7000?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/jesperv">jesperv</a> on May 4, 2009</div><div class="thread-post-content">I&#8217;m also new to the avr32 programming but maybe you could look at the ap7x-freertos project and see how they implemented the context switch.
Can you provide the updated header files so i can try compiling the port?
Regards Jesper
</div></div><div class="thread-post"><h3 class="thread-post-title">AVR32 UC3 Port usable for AP7000?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/bri1234">bri1234</a> on May 5, 2009</div><div class="thread-post-content">Hi Jesper,
finally I got the FreeRTOS running on the AVR32 AP7000. Major changes in the file &quot;portmacro.h&quot; were needed. Espacially the context store/restore macros had to be modified. I will add my port to the FreeRTOS project within the next few days so you can checkout my changes for your project.
best regards, Torsten
