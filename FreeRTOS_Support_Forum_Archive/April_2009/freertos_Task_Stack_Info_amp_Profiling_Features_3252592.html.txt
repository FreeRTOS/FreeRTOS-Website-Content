  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Task Stack Info &#038; Profiling Features</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/cstrahm">cstrahm</a> on April 30, 2009</div><div class="thread-post-content">Most RTOS give stack space info and profiling.&nbsp; While FreeRTOS has the stackfree function, the tskTCB record doesn&#8217;t seem to retain the orignal stack space.&nbsp; I find it difficut to remember how much stack space I gave a task unless I go back and look it up in the code.&nbsp; I added that to my task.c tskTCB record and changed the prvListTaskWithinSingleList&#40;&#41; function to report the USED space and the TOTAL space, which I think is far more useful.&nbsp; My console task list output now looks like this:

<h1>IntVolt&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; B&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; 1&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; 39/&nbsp; 128&nbsp;&nbsp;&nbsp;&nbsp; 2</h1>

</div></div><div class="thread-post"><h3 class="thread-post-title">Task Stack Info &#038; Profiling Features</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on April 30, 2009</div><div class="thread-post-content">Sounds like a good idea to &#40;optionally&#41; include some profiling features.&nbsp; I would like to see how you have done it, either posted here &#40;formatting can be a problem&#41; or you could send it to me at r &#40;dot&#41; barry &#40;at&#41; freertos.org.
I have done similar things using the trace macros whereby the traceTASK&#95;SWITCHED&#95;IN&#40;&#41; macro is used in combination with a high frequency timer to &quot;count&quot; the time each task is running for.&nbsp; A function can then be written to either simply display the total time, or if processing overhead is not an issue display the time each task is running as a percentage.

</div></div><div class="thread-post"><h3 class="thread-post-title">Task Stack Info &#038; Profiling Features</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/cstrahm">cstrahm</a> on May 2, 2009</div><div class="thread-post-content">Doing the Profiling only takes a few hundred bytes of ROM on an ARM7 and minimal RAM.&nbsp; But I also have some other features in here such as a Performance Timer that has uSec resolution.&nbsp; I find it indispensible for timing routines and performance tuning.&nbsp; FreeRTOS doesn&#8217;t do anything with the main Timer Prescale, it is set to div by 1. Much better default would be to always set this up to provide a 1MHz master clock into the main Timer Counter, and then you have a standard 1uSec resolution time base.
I also have a single file module for a stand alone Console/printf/sprintf that dumps out the task info and profiling on demand to a RS232 terminal, and also takes commands from the terminal.&nbsp; Does not use any lib functions so that usually saves ROM space.&nbsp; You can easily add custom command support also to display anything you want.
I don&#8217;t think there&#8217;s anyway to attach files here, and it&#8217;s probably too much to stick in the msg portion.&nbsp; I will send Richard an email with the stuff.
