</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS+CLI beginner</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/markwrichardson">markwrichardson</a> on August 25, 2014</div><div class="thread-post-content">To me this question is not about FreeRTOS but about how to design an application. 
There are many, many simple programs that implement a Command Level Interface.  If you are unfamiliar with creating one find a simple program and study the layers and the technique.  The CLI requires parsing some strings, doing something and outputting some sort of feedback.  The &#8216;Hello World&#8217; sample is half of that.  You have to know many things that are outside of the scope of FreeRTOS support.  How does your connection to your device work?  How do you get and send data from the devices involved?  FreeRTOS doesn&#8217;t directly create any hardware specific solutions or interfaces.  Printf and most of the application functions are implemented in separate libraries the must be included in your project, usually by linking.  They have some good samples for the most common platforms with sample device drivers that may suit your needs.  
Knowing how to link a project is also not a FreeRTOS specific task.  It depends on what your are using for a development system, what modules you want to include in your project, your hardware constraints and what your goals are.  Compiling and linking are often done for you in development systems but knowing how to directly manage them (in case you need to) is required for embedded development.
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS+CLI beginner</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on August 25, 2014</div><div class="thread-post-content">As Mark says &#8211; where you direct printf() to is application specific and not dependent on FreeRTOS.  FreeRTOS does not itself use printf() &#8211; and I don&#8217;t think you would expect a system like FreeRTOS to.  The Atmel software framework has various functions for writing output to a UART or other terminal.  If you want something really light weight you can look for a file called printf-stdarg.c in the FreeRTOS/Demo directory &#8211; you will find lots of copies of it.  At the top of the file you will see that putchar() is stubbed out as follows:
<pre>
#define putchar(c) c
</pre>
If you comment out that line and already have the UART working then you can provide your own implementation of putchar() that simply writes &#8216;c&#8217; to the UART.  That is crude (not fast) but effective and easy to implement.
<blockquote>
  <blockquote>
    I was wondering if someone could guide me as to how should I create 
    a simple command just to, say printing something out on the PC terminal
  </blockquote>
</blockquote>
How to create your own command is documented on the website.  Go to http://www.freertos.org/cli then click on each step in the diagram you see in turn.  How you actually receive characters to pass to the CLI and how you write characters generated to the CLI to the terminal is application specific &#8211; but sounds like you want the characters to go to the UART in your case.  The download includes examples that write to a UART, as well as other examples that write to a UDP or TCP port.
Regards.

</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS+CLI beginner</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on September 1, 2014</div><div class="thread-post-content">The reason for the limited version of printf is so that just using printf doesn&#8217;t pull in big pieces of the floating point support library. If you are already using floating point, you can just use the standard printf routine provided by the complier. There isn&#8217;t really any FreeRTOS awareness needed here. The standard library should have a function you define to provide output for standard-out.
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS+CLI beginner</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/bowerymarc">bowerymarc</a> on September 1, 2014</div><div class="thread-post-content">If you don&#8217;t need general float support but just need limited support you could make your own &#8216;fake&#8217; float sprintf routine using divide and modulo&#8230; this is what I ended up doing when I needed to print some float values with three decimals, that were limited in range  to about +/- 10.0.  This would probably only be practical if you didn&#8217;t need &#8220;E&#8221; notation&#8230;.
