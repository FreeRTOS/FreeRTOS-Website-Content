  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">vPortFree on STM32 Demonstration Builder developer guide</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/erps">erps</a> on August 15, 2014</div><div class="thread-post-content">Hi:
I am working with a STMicrolectronics Demo STM3221G-EVA board. This Demo uses on FreeRTOS. I would like to add a GUI Module into this demo. I have followed the documentation UM1550 STM32 Demonstration Builder developer guide, at Chapter 5 Building a Module. Also I have used the template file provided with the Demo, to add this new module and I was successful to include an icon in the right location.
Now, when I click in the icon the code goes to an infinite loop at: (arrowed part)
static void TEMPLATE<em>INFO</em>SwitchPage(GL<em>Page</em>TypeDef* pParent, uint32<em>t PageIndex)
{
  /* Switch to new page, and free previous one. */
  GL</em>Page_TypeDef* NextPage = NULL;
  (<em>pParent).ShowPage(pParent, GL_FALSE);
  DestroyPage(pParent);
  vPortFree(pParent); /</em>&lt;&#8212; Code stuck here */
  pParent = NULL;
  if (PageIndex == PAGE<em>MENU)
  {
    GL</em>ShowMainMenu();
    return;
  }
This function is referenced in the following function:
static void TEMPLATE<em>INFO</em>Startup (void)
{
  vTaskSuspend(Core<em>Time</em>Task<em>Handle);
  TEMPLATE</em>INFO<em>SwitchPage(GL</em>HomePage, TEMPLATE<em>MAIN</em>PAGE);
}
vPortFree is a FreeRTOS function, but it may be a pointer problem where there&#8217;s no definition of the pointer or something, I don&#8217;t know. This Demo uses heap_2.c
The original Modules work ok. I am missing something here?
Thanks.
</div></div><div class="thread-post"><h3 class="thread-post-title">vPortFree on STM32 Demonstration Builder developer guide</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on August 15, 2014</div><div class="thread-post-content">I have no clue about that code, but vPortFree() is a very small function in heap_2.c so you should be able to see where it gets stuck.  I think the only place it could get stuck would be in the prvInsertBlockIntoFreeList() function, which would be an indication that the block being freed, or the heap itself, had been corrupted (overwritten) by something.
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">vPortFree on STM32 Demonstration Builder developer guide</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/erps">erps</a> on August 15, 2014</div><div class="thread-post-content">I just find out that if vPportFree(pParent) is replaced by free(pParent) works ok.
That tells you anything?
</div></div><div class="thread-post"><h3 class="thread-post-title">vPortFree on STM32 Demonstration Builder developer guide</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/edwards3">edwards3</a> on August 15, 2014</div><div class="thread-post-content">As you say you use heap_2 then if the memory was allocated with pvPortMalloc() then it must be freed by vPortFree(). If the memory was allocated by malloc() then it must be freed using free(). How was it allocated? You probably just leaked the memory.
</div></div><div class="thread-post"><h3 class="thread-post-title">vPortFree on STM32 Demonstration Builder developer guide</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/erps">erps</a> on August 15, 2014</div><div class="thread-post-content">Memory was allocated using malloc. That&#8217;s why.
