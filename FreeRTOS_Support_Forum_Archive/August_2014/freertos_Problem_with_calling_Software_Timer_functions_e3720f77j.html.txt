  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Problem with calling Software Timer functions</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/account002">account002</a> on August 31, 2014</div><div class="thread-post-content">Making a FreeRTOS project for TI Hercules RM48 microcontroller.
Got a problem with Software Timer functions (<strong>xTimerCreate()</strong>, <strong>xTimerReset()</strong>, <strong>xTimerStop()</strong> etc.):
<em>calling any of then inside a task causes a PREFETCH exception of the microcontroller.</em>
Calling them inside <strong>main</strong> function is ok.
FreeRTOS v.7.4.0
<strong>Parameters from FreeRTOSConfig.h</strong>
~~~~
<h1>define configUSE_TIMERS                1</h1>
<h1>define configTIMER<em>TASK</em>PRIORITY       ( configMAX_PRIORITIES &#8211; 2 )</h1>
<h1>define configTIMER<em>QUEUE</em>LENGTH        10</h1>
<h1>define configTIMER<em>TASK</em>STACK_DEPTH    ( 128 )</h1>
~~~~
<strong>The code</strong>
~~~~
<h1>include &#8220;sys_common.h&#8221;</h1>
<h1>include &#8220;het.h&#8221;</h1>
<h1>include &#8220;gio.h&#8221;</h1>
<h1>include &#8220;FreeRTOS.h&#8221;</h1>
<h1>include &#8220;timers.h&#8221;</h1>
<h1>include &#8220;task.h&#8221;</h1>
void vTask1(void *pvParameters);
uint32 i = 0;
xTimerHandle xTimer1;
// Timer callback function
void vTimerFunction(xTimerHandle xTimer)
{
    // toggle port bits
    gioToggleBit(hetPORT1, i);
    i++;
    if (i>31)
        i=0;
<pre><code>// restart timer
xTimerReset(xTimer1, 0);
</code></pre>
}
// Main function
void main(void)
{
    // configure port direction (outputs)
    gioSetDirection(hetPORT1, 0xFFFFFFFF);
    // configure port output pins initial value
    gioSetPort(hetPORT1, 0xFFFFFFFF);
<pre><code>// creating task
xTaskCreate(vTask1, (const signed char *)"TimerStart", 1024, NULL, (configMAX_PRIORITIES - 3), NULL);
vTaskStartScheduler();
while(1);
</code></pre>
}
// Task function
void vTask1(void *pvParameters)
{
<pre><code>xTimer1 = xTimerCreate((const signed char *)"Timer1", 80 / portTICK_RATE_MS, pdFALSE, (void*) 0, vTimerFunction);
if (xTimer1 != NULL)
    xTimerReset(xTimer1, 0);
// task self-destruction
vTaskDelete( NULL );
</code></pre>
}
~~~~
So, calling xTimerCreate causes strange error &#8211; prefetch exception.
Moving block
~~~~
    xTimer1 = xTimerCreate((const signed char <em>)&#8221;Timer1&#8243;, 80 / portTICK_RATE_MS, pdFALSE, (void</em>) 0, vTimerFunction);
    if (xTimer1 != NULL)
        xTimerReset(xTimer1, 0);
~~~~
into the <strong>main</strong> function (for example, before <strong>vTaskStartScheduler()</strong>) makes code working properly.
<strong><em>What&#8217;s wrong?</em></strong>
<strong><em>Any ideas, please&#8230;</em></strong>
</div></div><div class="thread-post"><h3 class="thread-post-title">Problem with calling Software Timer functions</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on August 31, 2014</div><div class="thread-post-content"><blockquote>
<pre><code> xTaskCreate(vTask1,  (const  signed  char  *)"TimerStart",  1024,  NULL,  (configMAX_PRIORITIES  -  3),  NULL);
</code></pre>
</blockquote>
I assume without creating the timer you find multiple tasks execute 
correctly?
If so my first suggestion would have been stack overflow, but you have 
given vTask1 a large stack, which I&#8217;m almost certain will be fine. 
Worth ensuring stack overflow detection is turned on all the same though.
Your FreeRTOS version is moderately old, and I don&#8217;t think a lot of the 
new configASSERT()s were added until V7.6.0, but it is worth ensuring 
that is defined too.
Is the error in xTimerCreate() or xTimerReset()?  Can you step through 
whichever function it is and let us know on which line the problem occurs.
</div></div><div class="thread-post"><h3 class="thread-post-title">Problem with calling Software Timer functions</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/account002">account002</a> on August 31, 2014</div><div class="thread-post-content">Thank you for response.
Actually the original project includes multiple tasks execution, queues, semaphores &#8211; everything works excelent.
After I tried to use Software Timers and got the described error, I wrote a simple version of project, which is shown above.
vTask1 really has a large stack, furthermore in the given project it does nothing, just tries to create timer&#8230;
But I&#8217;ll still try to check out everything about stack and configASSERT(). Actually, need to read some documentation before&#8230;
When I try to call xTimerCreate, the error is quite strange.
It&#8217;s not &#8220;inside&#8221; the function.
Using Assemly Step Into while calling xTimerCreate shows, that prefetch exception occures directly after uP tries to execute instruction <strong>BL xTimerCreate</strong>&#8230; (look at the attached screenshot)&#8230;
</div></div><div class="thread-post"><h3 class="thread-post-title">Problem with calling Software Timer functions</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on August 31, 2014</div><div class="thread-post-content">I have never seen such an error.  In this case I think you need to look 
at the address at which xTimerCreate() is located to see if it is a 
valid address in the hope of finding out why a simple branch instruction 
causes an abort.  Could it be an instruction set change problem if the 
timers code is build to pure ARM code?  If the address of the function 
looks valid then you will have to try and debug the abort from within 
the abort handler to determine why the abort occurred.
Regards.
