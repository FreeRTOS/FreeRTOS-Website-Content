  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">How to call xTaskGetTickCount(); from isr?</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/fojtik">fojtik</a> on May 15, 2008</div><div class="thread-post-content">Dears,
I have aattempted to call xTaskGetTickCount&#40;&#41; inside ISR. It causes RTOS to crash after several successfull calls. I hope that reading a single value should not do this.
Jara
</div></div><div class="thread-post"><h3 class="thread-post-title">How to call xTaskGetTickCount(); from isr?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on May 15, 2008</div><div class="thread-post-content">It will crash because of the critical section used.&nbsp; You can:
1&#41; Provide an new function xTaskGetTickCountFromISR&#40;&#41; that does not use a critical section.
2&#41; Remove the critical section if the tick count variable has a size that equals the word size of the architecture you are using.
3&#41; Just make uxTickCount global.
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">How to call xTaskGetTickCount(); from isr?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/incrediball">incrediball</a> on May 18, 2008</div><div class="thread-post-content">I find your second suggestion interesting. This obviously works because incrementing the tick count variable is an atomic operation which cannot be interrupted. However, if this is a reasonable thing to do, why not optimize all the ports to do that?
</div></div><div class="thread-post"><h3 class="thread-post-title">How to call xTaskGetTickCount(); from isr?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/ravaz">ravaz</a> on May 18, 2008</div><div class="thread-post-content">Incremnting a vairables is not an atomic operation because it&#8217;s done in at least three instruction &#40;load, increment and write back&#41;. Ovever the instruction xTaskGetTickCount is only reading the variable, and as said by richard if the processor as the same architecture size as the variable &#40;ie both 32bits&#41; this operation is atomic. 
</div></div><div class="thread-post"><h3 class="thread-post-title">How to call xTaskGetTickCount(); from isr?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/incrediball">incrediball</a> on May 21, 2008</div><div class="thread-post-content">Quite right. The early morning coffee hadn&#8217;t fully worked when I wrote that. &#40;Obviously the increment is not going to be interrupted either because it is done by the interrupt.&#41; Anyway, my question is still much the same: if it is valid to read the tick counter &#40;because the read operation is atomic&#41;, why not optimize all the relevant ports to do that?
</div></div><div class="thread-post"><h3 class="thread-post-title">How to call xTaskGetTickCount(); from isr?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on May 21, 2008</div><div class="thread-post-content">The read is only atomic when the variable is the natural word size for the architecture.&nbsp; There is an option in FreeRTOS.org to use either 16bit or 32bit variables for the tick count &#40;32bit giving you the ability to specify much longer block periods&#41;.&nbsp; An 8 or 16 bit device reading a 32bit tick count would not be atomic, hence the critical section.
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">How to call xTaskGetTickCount(); from isr?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/incrediball">incrediball</a> on May 22, 2008</div><div class="thread-post-content">I agree about the 8 and 16 bit devices, which is why I said &quot;all the relevant ports&quot;. For all the 32 bit devices such as AT91SAM7, etc the critical section could be excluded &#40;and in any other relevant places&#41;.
What actually happens if the variable is smaller than the natural word size? For example if the option to use 16 bit tick counts is used on the AT91SAM7, is that still atomic? It seems that 16 bit variables don&#8217;t seem to be handled as well by the ARM and the compiler usually produces larger code.
</div></div><div class="thread-post"><h3 class="thread-post-title">How to call xTaskGetTickCount(); from isr?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/fojtik">fojtik</a> on May 23, 2008</div><div class="thread-post-content">Thank you very much for your reply. I suspected somethink like this. As far as 32 bit CPU has been used, critical section is not needed. I will prefer solution 1.
Jara
