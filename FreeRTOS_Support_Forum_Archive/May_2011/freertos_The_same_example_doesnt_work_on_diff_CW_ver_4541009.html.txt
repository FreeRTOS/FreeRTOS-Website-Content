</div></div><div class="thread-post"><h3 class="thread-post-title">The same example doesn&#8217;t work on diff CW ver</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on May 22, 2011</div><div class="thread-post-content">Sorry &#8211; I have only tested the provided examples with one version of the CodeWarrier tools.&nbsp; However, one thing from memory is, if you are using the Processor Expert to generate &#8220;beans&#8221;, then these can auto generate code that overwrites manually edited drivers &#40;in exactly the way nobody would ever want them to&#41;.&nbsp; That meant that the code that implements the tick interrupt handler can get overwritten, and therefore break the tick handler code.&nbsp; The only way I found around the problem was to make the .c file in which the tick interrupt was defined read only &#8211; thus preventing the dumb code generator overwriting my code without warning.&nbsp; Is it possible that could be happening to you?

</div></div><div class="thread-post"><h3 class="thread-post-title">The same example doesn&#8217;t work on diff CW ver</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on May 23, 2011</div><div class="thread-post-content">It is generating the code from PE that causes the problem.&nbsp; It is fine to generate the code originally, but then you have to edit it to get the saving and restoring of the context correct.&nbsp; If you then keep the project connected to PE, the modifications get overwritten.&nbsp; At least, that is how it used to work.  
Take a look at a clean download of the port/demo.&nbsp; In that port, find the file that contains the tick interrupt handler, and see the modifications that have been made.&nbsp; Then ensure the same mods, or an unmodified file &#40;not overwritten by PE&#41; is used.&nbsp; Ideally, take the existing unmodified demo from the download, and just never connect it to PE, but that might not be possible if you are updating the version of CodeWarrier used.  
Sorry not to be more specific, but right now I am just working from memory and don&#8217;t have the project in front of me.
