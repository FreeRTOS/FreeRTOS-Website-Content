  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">configMAX_SYSCALL_INTERRUPT_PRIORITY=0  CM3</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/ramun">ramun</a> on May 26, 2011</div><div class="thread-post-content">Hi<br />
I ran into a problem concerning the configMAX&#95;SYSCALL&#95;INTERRUPT&#95;PRIORITY value.<br />
I&#8217;m using the EFM32 Cortex-M3 port of FreeRTOS V6.1.0. Since I didn&#8217;t want to care about the interrupt priorities, I thought it would be a good idea to set configMAX&#95;SYSCALL&#95;INTERRUPT&#95;PRIORITY to 0 &#40;the highest interrupt priority&#41;. But this leads to a sporadically crashing OS. Further examination of the problem showed that the configMAX&#95;SYSCALL&#95;INTERRUPT&#95;PRIORITY is used in the function <em>vPortSetInterruptMask</em> to set the <em>BASEPRI</em> register. But I think this has not the intended effect since setting <em>BASEPRI</em> to zero actually enables all interrupts &#40;disables the BASEPRI functionality&#41; instead of disabling them.<br />
Can anyone confirm this concern? 
</div></div><div class="thread-post"><h3 class="thread-post-title">configMAX_SYSCALL_INTERRUPT_PRIORITY=0  CM3</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/edwards3">edwards3</a> on May 26, 2011</div><div class="thread-post-content">Yes I can confirm it. Don&#8217;t set it to 0 because zero has a special meaning in basepri, as you found out yourself.
</div></div><div class="thread-post"><h3 class="thread-post-title">configMAX_SYSCALL_INTERRUPT_PRIORITY=0  CM3</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/ramun">ramun</a> on May 27, 2011</div><div class="thread-post-content">Ok, thanks a lot&#33;
</div></div><div class="thread-post"><h3 class="thread-post-title">configMAX_SYSCALL_INTERRUPT_PRIORITY=0  CM3</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/*anonymous">*anonymous</a> on July 18, 2012</div><div class="thread-post-content">I just got bitten by not configuring the priorities of my interrupts, so I did some research to understand ARM Cortex interrupt priorities and how they affect FreeRTOS.  
One thing I came across while researching was this tidbit int he ARM v7-M architecture reference manual:&nbsp; &#8220;When &#40;BASEPRI&#41; is cleared to 0, it has no effect on the priority.&nbsp; A non-zero value will act as a priority mask, the execution priority when the priority defined by the BASEPRI is higher than the current executing priority&#8221;.  
So basically, you&#8217;re right, setting configMAX&#95;SYSCALL&#95;INTERRUPT&#95;PRIORITY to zero actually prevents any interrupts from being &#8220;masked&#8221;, so none of your interrupt handlers can safely call into any FreeRTOS APIs.
</div></div><div class="thread-post"><h3 class="thread-post-title">configMAX_SYSCALL_INTERRUPT_PRIORITY=0  CM3</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on July 19, 2012</div><div class="thread-post-content">Here are some relevant links on the FreeRTOS web site:
