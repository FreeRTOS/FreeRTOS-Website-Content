My aim: Using C++ within my tasks  
My approach:<br />
1&#46; Rename main.c in main.cpp<br />
2&#46; add manual typecasting für the task-name in xTaskCreate by &#40;const signed char&#42;&#41;<br />
3&#46; add extern &#8220;C&#8221; in front of vApplicationTickHook and the includes of my own header-files, which declare the task I&#8217;ve created<br />
4&#46; alter makefile to compile main.cpp with g++, the rest with gcc and link both with g++<br />
So far so good, this compiles and runs as fine as before. My problems begin when trying to transform those files containing the tasks &#40;used by by xTaskCreate in main.cpp&#41; into C++ by moving the in the makefile from gcc to g++. The header-file &#40;sandbox.h&#41; looks like this.  
<pre><code>#ifdef __cplusplus
extern "C" {
#endif
void vTaskLED(void *pvParameters);
#ifdef __cplusplus
}
#endif
</code></pre>
While the definition in sandbox.cpp remains unchanged  
<pre><code>void vTaskLED(void *pvParameters)
{
    for(;;)
    {
        // some PIN-toggling
        vTaskDelay(500);
    }
    vTaskDelete( NULL );
}
</code></pre>
That&#8217;s all I did. Compiling works fine without warnings or errors, but the code just doesn&#8217;t run &#40;no blinking LED ;-&#40;. To get it working again I just move sandbox.cpp in my makefile back to gcc &#40;though there are warnings about the file ending&#41;.  
So apparently xTaskCreate has trouble digesting my task-functions when those are compiled with g++. I&#8217;m afraid I once again missed something obvious about making my C++-functions available to othe C-code. Can someone please give me a kick into the right direction.<br />
And while we&#8217;re at it: Why don&#8217;t I get any hints from the compiler that something is wrong?
