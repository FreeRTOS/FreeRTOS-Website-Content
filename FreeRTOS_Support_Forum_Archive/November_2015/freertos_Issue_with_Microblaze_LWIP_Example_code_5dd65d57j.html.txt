  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Issue with Microblaze LWIP Example code</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/timelmg">timelmg</a> on November 19, 2015</div><div class="thread-post-content">When I integrated this code into my code I found a strange error.  0x4000 was being inserted in the same place in random ethernet packets.  After a lot of investigation I found my culprit &#8211; code I got from the demo code.
~~~~
static void prvRxHandler( void <em>pvNetIf )
{
    /</em> This is taken from lwIP example code and therefore does not conform
    to the FreeRTOS coding standard. */
struct eth<em>hdr *pxHeader;
struct pbuf *p;
unsigned short usInputLength;
static unsigned char ucBuffer[ 1520 ] <strong>attribute</strong>((aligned(32)));
extern portBASE</em>TYPE xInsideISR;
struct netif *pxNetIf = ( struct netif * ) pvNetIf;
<pre><code>XIntc_AckIntr( XPAR_AXI_ETHERNETLITE_0_BASEADDR, XPAR_AXI_ETHERNETLITE_0_IP2INTC_IRPT_MASK );
/* Ensure the pbuf handling functions don't attempt to use critical
sections. */
xInsideISR++;
usInputLength = ( long ) XEmacLite_Recv( &amp;xEMACInstance, ucBuffer );
</code></pre>
 &#8230;
~~~~
This code is from lwIP/netif/ethernetif.c
The line <code>XIntc_AckIntr( XPAR_AXI_ETHERNETLITE_0_BASEADDR, XPAR_AXI_ETHERNETLITE_0_IP2INTC_IRPT_MASK );</code> is designed to acknowledge the interrupt but it writes to the Ethernet peripheral instead of the interrupt controller.  The place where it writes is in the middle of the outgoing buffer and the MASK has the value of 0x4000 in my code (it may be different in different systems).
The solution is to remove this line entirely as the interrupt acknowledgement is done in the interrupt controller driver and thus the line was irrelevant anyway.
Hopefully this will stop people getting mystery errors in the future.
Thanks,
Tim
