I am working on project with Tick-less FreeRTOS using deep sleep low power mode of LPC4337 working on it. In Deep-sleep mode the CPU clock and peripheral clocks are shut down to save power; logic states and SRAM memory are maintained.
Platform: LPC4337
Compiler:LPCXpresso7.9
FreeRTOS V8.0.1
Now I want to use Power Down mode in which all SRAM memory except for the upper 8 kB of the local SRAM located at 0x1008 0000 is maintain. In addition, Power down mode doesn&#8217;t do system reboot it resume from last instruction after wake-up.
My question is how I can reallocate Stack and heap memory in this 8kb safe memory area? What are the variable I need to save before I goto power-down mode to resume the normal functionality after wake-up (task stack, system stack other required variable to maintain RTOS kernel?
Regards,
</div></div><div class="thread-post"><h3 class="thread-post-title">Tick-less FreeRTOS with LPC4337 and power down mode</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on November 10, 2015</div><div class="thread-post-content">Hi Henna,
That is quite ambitious what you want to do!
I never went further than &#8220;Power-save mode&#8221; and &#8220;Sleep mode&#8221;, because that is much easier: clocks remain running.
<blockquote>
  the upper 8 kB of the local SRAM located at 0x1008 0000 is maintain[ed]
</blockquote>
If you use &#8216;portable/MemMang/heap_5.c&#8217; it is easy to tell where to put the HEAP. 
Or when using heap<em>4.c you can define &#8216;configAPPLICATION</em>ALLOCATED_HEAP=1&#8242; and tell the compiler where (in which sector) to put the ucHeap[] block.
See heap_4.c :
~~~~~
    #if( configAPPLICATION<em>ALLOCATED</em>HEAP == 1 )
        /* The application writer has already defined
        the array used for the RTOS heap &#8211; probably so
        it can be placed in a special segment or address. */
        extern uint8_t ucHeap[ configTOTAL_HEAP_SIZE ];
    #else
        uint8_t ucHeap[ configTOTAL_HEAP_SIZE ];
    #endif
~~~~~
Declare the HEAP space in your code:
~~~~~
<pre><code>__attribute__((aligned(8)))
__attribute__((section(".sram_high")))
    uint8_t ucHeap[ configTOTAL_HEAP_SIZE ];
/* '.sram_high' refers to a name defined in your xxx.ld
you will have to edit it. */
</code></pre>
~~~~~
Doesn&#8217;t your application need a notion of time, a continuous clock?
<blockquote>
  reallocate Stack and heap memory
</blockquote>
There is a temporary start-up stack that can be allocated anywhere, see your link file &#8216;xxx.ld&#8217;.
After vTaskStartScheduler() is called, only FreeRTOS stacks are in use, and these stacks are located in the HEAP ( by xTaskCreate() ).
Have you also tried-out lighter ways of sleeping? Normally the tickless mode uses the system clock or a hardware timer (TC&#42;) to count-down. That makes it possible to use the timed blocking options of FreeRTOS.
&#42;TC&#8217;s are preferable if you need long sleeps, they often have a 32-bit counter.
Some things are important for power consumption in the low-power/sleep modes :
<ul>
<li>Low CPU frequencies consume much less power. You might consider implementing an on-demand variable CPU frequency ( in analogy with the Linux kernel ).</li>
</ul>
GPIO&#8217;s are very important:
<ul>
<li>Make sure that inputs are never floating.</li>
<li>If an input has an internal pull-up, make sure it is not tied to ground</li>
<li>Same for outputs, make sure there is no current running</li>
<li>Make sleeps long enough, preferably at least 30 seconds.</li>
</ul>
Some more questions:
<ul>
<li>How many µA is your application allowed to consume while in low power?</li>
<li>Does it wake-up often? How long is is allowed to remain in low power?</li>
<li>What are the events that will wake-up your application?</li>
</ul>
Regards.

Of course it is still possible to put the other RAM area in a special section and declare variables that you can use during a wake-up session only, the contents is gone after a sleep:
~~~~~
<strong>attribute</strong>((section(&#8220;.non<em>permanent</em>ram&#8221;)))
    unsigned temporary_space[ 1024 ];
~~~~~
