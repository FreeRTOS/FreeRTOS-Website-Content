</div></div><div class="thread-post"><h3 class="thread-post-title">About Stack and Heap</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on January 3, 2007</div><div class="thread-post-content">The maximum stack size that can be specified is 0xffff as the parameter in the xTaskCreate&#40;&#41; function used to set the stack size is 16bits.&nbsp;&nbsp; Of coarse you are limited by the amount of RAM available in your system.
Note that the stack is specified as the number of variables that can be saved to the stack &#8211; so the number of bytes allocated depends on the size of the stack variables.&nbsp; For example, on a machine with a 32bit wide stack, requesting a stack size of 100 will result in 32&#42;100 bytes being allocated for the stack.
How the stack is used is dependent on your compiler.&nbsp; Generally it holds function call return addresses, parameter values, local variables, etc.&nbsp; Just like any other C program.
The FreeRTOS.org heap is the area of memory you allocated for use by the kernel.&nbsp; When a task is created the memory used by the task comes from the heap &#40;the task stack and the TCB structure&#41;.&nbsp; Likewise when you create a queue the memory used by the queue comes from the heap.
You may also setup a separate heap for use by your C program through the use of malloc and free library functions.
Regards.
