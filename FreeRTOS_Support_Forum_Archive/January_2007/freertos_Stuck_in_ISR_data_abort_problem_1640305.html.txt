  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Stuck in ISR, data abort problem ?</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/barden18">barden18</a> on January 2, 2007</div><div class="thread-post-content">Hi all, 
I am using the yagarto toolchain, with gnuarm 4.1.1 and eclipse.
i am currently working on a CAN driver for the sam7x.
I have a test setup with two dev. boards, where one of the boards sends
a data frame to the other every 100ms. And when the dev. baord receives this
data frame it responds with an other data frame.
When two dev. boards are connected to each other the communication works
fine and the rtos is running nicely. However if i disconnect the CAN link for
some time &#40;e.g 15 seconds&#41; and reconnect. The application gets stuck in the CAN ISR.
And the CAN task is never run again.
If i halt execution randomly after the communication failure, i can see the line &#95;&#95;dabt gets
executed.
if i have a breakpoint in the CAN ISR at this point, it will be continually hit. But there is no source
for the interrupt.
if i step through the last lines of the interrupt which are:
0x0010054c &lt;vCANISR+600&gt;: sub&nbsp;&nbsp; sp, r11, &#35;28&nbsp;&nbsp;&nbsp; ; 0x1c
0x00100550 &lt;vCANISR+604&gt;: ldmia sp, &#123;r0, r1, r2, r3, r11, sp, lr&#125;
0x00100554 &lt;vCANISR+608&gt;: ldmia sp&#33;, &#123;r12&#125;
0x00100558 &lt;vCANISR+612&gt;: subs&nbsp; pc, lr, &#35;4&nbsp;&nbsp;&nbsp; ; 0x4
0x0010055c &lt;vCANISR+616&gt;: eoreq r0, r0, r12, lsr r8
0x00100560 &lt;vCANISR+620&gt;: eoreq r0, r0, r8, lsr r8
0x00100564 &lt;vCANISR+624&gt;: eoreq r0, r0, r1, lsr r8
0x00100568 &lt;vCANISR+628&gt;: eoreq r0, r0, r0, lsr r8
0x0010056c &lt;vCANISR+632&gt;: eoreq r0, r0, r4, lsr r8
i get the following error when executing line 0x00100550:
Thread &#91;0&#93; &#40;Suspended: Signal &#8216;SIGINT&#8217; received. Description: Interrupt.&#41; &lt;Stack is not available: Cannot access memory at address 0x1111110d.&gt;
i have tried with different stack sizes from 200 to 1024. which didn&#8217;t solve the problem.
the weird thing though, is that if i step through the code, after reconnecting the CAN link &#40;in which case i will get a transmit interrupt&#41; the application is behaving as expected and returning nicely after completing the ISR.
any help with this is greatly appreciated. thx
</div></div><div class="thread-post"><h3 class="thread-post-title">Stuck in ISR, data abort problem ?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/barden18">barden18</a> on January 2, 2007</div><div class="thread-post-content">Hi again,
I have got to work with a rather crude workaround.
It seems that allthough 
ulIntStatus = AT91C&#95;BASE&#95;CAN-&gt;CAN&#95;SR; 
ulIntMask= AT91C&#95;BASE&#95;CAN-&gt;CAN&#95;IMR;
ulIntStatus &amp;= ulIntMask;
results in ulIntStatus = 0. The CAN ISR would still fire.
the workaround i made was to disable the CAN Controller if ulIntStatus = 0.
And then from my CAN task, from where i also send out data frames, check
CAN&#95;MR to see if it is disabled. And if it is, i reenable the CAN Controller.
If anyone has some experience using the CAN controller with freertos or otherwise,
i would be glad to some of the insights or solutions you might have to this problem.
regards,
Martin
