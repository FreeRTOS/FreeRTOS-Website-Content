  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">queue.c: *_interrupts vs. *_critical</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on January 12, 2007</div><div class="thread-post-content">&lt;&lt;And yes, I&#8217;m using anonymous on purpose.&gt;&gt;
Looking at queue.c and trying to write my own counting semaphores &#40;as an exercise and to contribute&#41;, I see the coroutine-specific portions calling portDISABLE&#95;INTERRUPTS directly rather than using taskENTER&#95;CRITICAL to count multiple depth.&nbsp; It would seem this could cause an error of enabling interrupts when the system is supposed to be in a nested critical section.
</div></div><div class="thread-post"><h3 class="thread-post-title">queue.c: *_interrupts vs. *_critical</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on January 12, 2007</div><div class="thread-post-content">The coroutine versions don&#8217;t nest interrupts.&nbsp; There is a very good reason for this, it just temporarily escapes me ;-&#41;
There was in fact a bug fix about two versions ago where a co-routine called a utility function within an if&#40;&#41; condition while interrupts were disabled.&nbsp; The utility function itself entered and exited a critical section &#8211; and in so doing resulted in interrupts being enabled when they should not have been for the very reason you point out.&nbsp; The utility macro was replaced with inlined code as the fix.
I think counting semaphores can be implemented in a similar way to the binary semaphores, just with a queue depth greater than 1 &#8211; which is where the &#8216;binary&#8217; comes from.
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">queue.c: *_interrupts vs. *_critical</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/dutchuncle">dutchuncle</a> on January 12, 2007</div><div class="thread-post-content">Maybe, but the queue implementation would try to allocate actual queue space which would be a waste.&nbsp; And it doesn&#8217;t need to be as complicated, either &#8211; posting a semaphore should always work unlike adding to a queue.
</div></div><div class="thread-post"><h3 class="thread-post-title">queue.c: *_interrupts vs. *_critical</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on January 12, 2007</div><div class="thread-post-content">The binary semaphore has an item size of 0 so nothing is actually copied into the queue and I don&#8217;t think any storage space allocated &#40;?&#41;.
The return value from the post to the sem could be ignored, or a wrapper function that converts the return value to something more friendly for a sem.
Dave.
</div></div><div class="thread-post"><h3 class="thread-post-title">queue.c: *_interrupts vs. *_critical</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/dutchuncle">dutchuncle</a> on January 16, 2007</div><div class="thread-post-content">&gt;&gt;There was in fact a bug &#8230; where a co-routine called a utility function &#8230; while interrupts were disabled. The utility function itself entered and exited a critical section &#8211; and in so doing resulted in interrupts being enabled when they should not have been &#8230; The utility macro was replaced with inlined code as the fix. 
I have the vague memory that VRTX&#8217;s interrupt-entry macro incremented the critical-section depth counter to avoid this problem . . . or else the critical-section code saved the status register on the first level, using the depth counter from zero &#42;down&#42; to use the condition code &#42;after&#42; the operation &#40;on 80&#215;86&#41;?&nbsp; Maybe I&#8217;m mixing up two.&nbsp; Point is, that should be handled.&nbsp; 
While acknowledging the specific goal of processor-independence, I would also like to see more processor- and compiler-specific inlining &#40;all of which of course defaults to common standard C code&#41;.&nbsp; Call me old-fashioned&#8230;.
</div></div><div class="thread-post"><h3 class="thread-post-title">queue.c: *_interrupts vs. *_critical</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on January 16, 2007</div><div class="thread-post-content">The interrupt macros do keep a count of the nesting depth.&nbsp; The coroutine thing is a special case.&nbsp; Normally you would not use portENABLE&#95;INTERRUPTS or portDISABLE&#95;INTERRUPTS from you code, but portENTER&#95;CRITICAL and portEXIT&#95;CRITICAL instead.
Dave.
