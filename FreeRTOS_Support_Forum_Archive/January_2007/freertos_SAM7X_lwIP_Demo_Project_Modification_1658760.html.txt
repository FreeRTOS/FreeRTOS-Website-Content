</div></div><div class="thread-post"><h3 class="thread-post-title">SAM7X lwIP_Demo Project Modification</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on January 26, 2007</div><div class="thread-post-content">Hi,
I did the same thing. I.e. removed demo project and tried to make use of lwip optional &#40;as its easier to fit the application to ram as lwip is not included to test different stuff&#41;. My make file source list looks like:
&#35; List C source files here
FREERTOS&#95;THUMB&#95;SRC= 
&nbsp; ../FreeRTOS/Source/tasks.c 
&nbsp; ../FreeRTOS/Source/queue.c 
&nbsp; ../FreeRTOS/Source/list.c 
&nbsp; ../FreeRTOS/Source/portable/GCC/ARM7&#95;AT91SAM7S/port.c 
&nbsp; ../FreeRTOS/Source/portable/MemMang/heap&#95;2.c
&nbsp; 
DEMO&#95;APP&#95;THMUB&#95;SRC= 
&nbsp; main.c 
&nbsp; serial/serial.c
&nbsp; 
&#35;&nbsp; BasicWEB.c
&#35;&nbsp; USB/USB-CDC.c 
&#35;&nbsp; ../FreeRTOS/Demo/Common/Minimal/flash.c 
&#35;&nbsp; ../FreeRTOS/Demo/Common/Minimal/BlockQ.c 
&#35;&nbsp; ../FreeRTOS/Demo/Common/Minimal/integer.c 
&#35;&nbsp; ../FreeRTOS/Demo/Common/Minimal/PollQ.c 
&#35;&nbsp; ../FreeRTOS/Demo/Common/Minimal/semtest.c 
ifeq &#40;$&#40;USE&#95;LWIP&#41;,YES&#41;
LWIP&#95;THUMB&#95;SRC= 
&nbsp; lwip-1.1.0/src/core/tcp&#95;out.c 
&nbsp; lwip-1.1.0/src/core/inet.c 
&nbsp; lwip-1.1.0/src/core/mem.c 
&nbsp; lwip-1.1.0/src/core/memp.c 
&nbsp; lwip-1.1.0/src/core/netif.c 
&nbsp; lwip-1.1.0/src/core/pbuf.c 
&nbsp; lwip-1.1.0/src/core/raw.c 
&nbsp; lwip-1.1.0/src/core/stats.c 
&nbsp; lwip-1.1.0/src/core/sys.c 
&nbsp; lwip-1.1.0/src/core/tcp.c 
&nbsp; lwip-1.1.0/src/core/tcp&#95;in.c 
&nbsp; lwip-1.1.0/src/core/ipv4/ip.c 
&nbsp; lwip-1.1.0/src/core/ipv4/ip&#95;addr.c 
&nbsp; lwip-1.1.0/src/core/ipv4/icmp.c 
&nbsp; lwip-1.1.0/src/api/tcpip.c 
&nbsp; lwip-1.1.0/src/api/api&#95;msg.c 
&nbsp; lwip-1.1.0/src/api/err.c 
&nbsp; lwip-1.1.0/src/api/api&#95;lib.c 
&nbsp; lwip-1.1.0/src/netif/etharp.c 
&nbsp; lwip-1.1.0/contrib/port/FreeRTOS/AT91SAM7X/sys&#95;arch.c 
&nbsp; lwip-1.1.0/src/netif/ethernetif.c 
&nbsp; EMAC/SAM7&#95;EMAC.c 
&nbsp; lwip-1.1.0/src/core/udp.c 
&nbsp; lwip-1.1.0/src/core/ipv4/ip&#95;frag.c
endif
ARM&#95;SRC= 
&nbsp; ../FreeRTOS/Source/portable/GCC/ARM7&#95;AT91SAM7S/portISR.c 
&nbsp; Cstartup&#95;SAM7.c 
&nbsp; serial/serial&#95;ISR.c
&nbsp; 
ifeq &#40;$&#40;USE&#95;LWIP&#41;,YES&#41;
&nbsp; ARM&#95;SRC += EMAC/SAM7&#95;EMAC&#95;ISR.c
endif
And had the same kind of problem as you. But I noticed that I forgot -mthumb-interwork from linker flags. Now I have:
LDFLAGS = $&#40;MCFLAGS&#41; -mthumb-interwork -nostartfiles -T$&#40;LDSCRIPT&#41; -Wl,-Map=$&#40;PROJECT&#41;.map,&#8211;no-warn-mismatch
and it works. Thing is that there are different versions of libraries under:
C:Program Filesyagartoarm-elflib
and linker has to know which one to use.
I hope this helps you,
Madis
