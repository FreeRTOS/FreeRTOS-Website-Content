  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">watchdog solution for system hang?</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on January 9, 2007</div><div class="thread-post-content">Hi there,
Is it possible that FreeRTOS will hang if something is wrong in the application code &#40;only applicatin tasks are faulty and the kernel code remain untouched&#41;?
Can I use watchdog to make sure the system resets in a hang condition?
The str91x port of freertos uses watchdog as tick interrupt. What else can I use on this port to get a watchdog like functionality?
</div></div><div class="thread-post"><h3 class="thread-post-title">watchdog solution for system hang?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on January 9, 2007</div><div class="thread-post-content">Without a MMU then the application can corrupt data within FreeRTOS making it crash.&nbsp; If the kernel code really is untouched then a badly written task could starve out all other lower priority tasks from running, or leave interrupts disabled.
I don&#8217;t know the STR91x but suspect it will contain two or three different timers, any of which can be used in place of the watchdog interrupt.
Dave.
</div></div><div class="thread-post"><h3 class="thread-post-title">watchdog solution for system hang?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/imajeff">imajeff</a> on January 10, 2007</div><div class="thread-post-content">Trust me&#8230; it is much easier to make it hang than to make it work&nbsp; :&#41;&nbsp; My biggest problem so far is stack overflows. Since each task has a stack, naturally I make them smaller to fit more, yet still give enough space in each.
Once you get the &#8216;hang&#8217; of it, you&#8217;ll appreciate how much you can do with the versatility. Having no MMU allowes very small processors to do alot, and still use any of it&#8217;s hardware including watchdog.
Be careful placing the COP &#40;watchdog timer&#41; reset because you could end up with only that thread running, so it never times out yet all other threads are crashed. A good practice would be have all critical tasks report to a single task which monitors them and resets the COP if working.
