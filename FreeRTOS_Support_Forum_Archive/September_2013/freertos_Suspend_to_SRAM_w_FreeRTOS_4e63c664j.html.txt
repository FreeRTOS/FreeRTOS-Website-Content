  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Suspend to SRAM w/ FreeRTOS?</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/kenkyee">kenkyee</a> on September 20, 2013</div><div class="thread-post-content">I&#8217;m wondering if FreeRTOS can do &#8220;suspend to SRAM&#8221; for a deeper sleep state than Tickless mode?
It would save the configuration state of all drivers and any system state to a secondary memory SRAM chip (not DRAM so that it doesn&#8217;t need any refreshing) and won&#8217;t wake up until a timer and/or RTC and/or external (pins/serial port, usb port) interrupt.  Then after the interrupt causes it to come back, it restores everything and comes out of Idle.
Most Cortex chips support this kind of ultra low power mode, but sadly don&#8217;t have anything that helps you save/restore system/peripheral state to memory 🙁
</div></div><div class="thread-post"><h3 class="thread-post-title">Suspend to SRAM w/ FreeRTOS?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on September 21, 2013</div><div class="thread-post-content">The tickless mode can currently use any sleep state that retains the RAM and CPU registers.  For example, the SAM4L demo (http://www.freertos.org/Atmel<em>SAM4L-EK</em>Low<em>Power</em>Tick-less<em>RTOS</em>Demo.html) uses an extreme low power state (measured at 3uA) that is the lowest this specialist low power chip can manage without loosing CPU register values.  Once the CPU registers are gone then you are into the sort of scheme discussed in this thread:
http://www.freertos.org/FreeRTOS<em>Support</em>Forum<em>Archive/September</em>2013/freertos<em>resuming</em>FreeRTOS<em>state</em>from<em>external</em>SRAM_8679833.html
and I&#8217;m not sure if keeping the external SRAM powered to take another micro amp off the power consumed by the CPU is going to same much.
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">Suspend to SRAM w/ FreeRTOS?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on September 21, 2013</div><div class="thread-post-content">The low power modes that loose memory contents are NOT designed to be used by a Real Time application that &#8220;saves&#8221; all of the state then goes into this mode. The problem being that this can take a lot of time, and what ever is going to remember that state will be taking power (or be very slow).
These states are used for applications that know they aren&#8217;t going to be needed for a while, to save a little bit of essential state, and turn the machine off except for a few critical I/O devices that can wake the system up, which the quickly &#8220;re-boots&#8221; the application, using the saved state information, and handles the request.
A generic operating system (like FreeRTOS) isn&#8217;t going to know how to distill the current state down enough, that is really an application specific operation.
