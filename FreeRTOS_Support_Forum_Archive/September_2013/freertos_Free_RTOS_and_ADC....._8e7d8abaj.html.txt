  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Free RTOS and ADC&#8230;..</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/*anonymous">*anonymous</a> on September 22, 2013</div><div class="thread-post-content">I am working with Atmel&#8217;s microcontroller AT32UC3A0512 &amp; using software Atmel studio 6.0
My program needs to calculate ADC values and send them to a a webpage&#8230;. 
However, there is a command  vTaskStartScheduler() that is creating a problem&#8230;.
If i put this line in main() before ADC GPIO MAP, the ADC doesn&#8217;t work but the webpage works fine and if i make this command the last line of my program, then the ADC works but the webpage doesn&#8217;t show up in browser&#8230;. (the taskscheduler only runs idle task)
I want both adc and webpage working together as i need to send adc values to webpage&#8230;. 
Anybody having an idea what the problem might be??
Please help me out&#8230;.
</div></div><div class="thread-post"><h3 class="thread-post-title">Free RTOS and ADC&#8230;..</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on September 22, 2013</div><div class="thread-post-content">Unfortunately, while I have been involved in the Atmel Software Framework for SAM parts, the UC3 ports and demos are the creation of Atmel so we are not able to support them directly.
However, vTaskStartScheduler() should only touch the hardware in one place, and that is when it configures the peripheral that generates the tick interrupt.  Assuming that is unrelated to either your ADC or Ethernet interrupts, then the only other thing the scheduler would do is disable interrupts before the scheduler is started and then re-enable them when the first task starts.
If the configuration of the tick interrupt is not effecting the vectors of your other interrupts, or the configuration of your other interrupts, and interrupts are indeed enabled when the first task starts&#8230;.then it would point to an application error.
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">Free RTOS and ADC&#8230;..</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/*anonymous">*anonymous</a> on September 22, 2013</div><div class="thread-post-content">Thanks for the reply.
Actually what i think is that tick interrupt is affecting ADC interrupt because if the webpage uploads, even then the ADC doesn&#8217;t work&#8230; It seems the program gets stuck at vTaskStartScheduler() and no code beyond this line is executed&#8230;.
Do you have any suggestion how to tackle this??
</div></div><div class="thread-post"><h3 class="thread-post-title">Free RTOS and ADC&#8230;..</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on September 22, 2013</div><div class="thread-post-content">As I&#8217;m not familiar with the port all I can suggest is that you step through the code to see what it is doing, and at what point you think it might be effecting your application.
There is no need to step through vTaskStartScheduler() itself, as that is code common to all ports, look for where vTaskStartScheduler() calls vPortStartScheduler() and step from there (or just find the function in port.c).
Regards.
