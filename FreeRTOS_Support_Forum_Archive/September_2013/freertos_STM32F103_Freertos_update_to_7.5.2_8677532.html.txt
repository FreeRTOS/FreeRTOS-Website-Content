</div></div><div class="thread-post"><h3 class="thread-post-title">STM32F103 Freertos update to 7.5.2</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on September 10, 2013</div><div class="thread-post-content">Heap1.c does not implement vPortFree&#40;&#41; so the assert is most likely highlighting an error in your code that has always been there.&nbsp; Please refer to <a href="http://www.freertos.org/a00111.html">http://www.freertos.org/a00111.html</a>  
I suspect previously you were deleting the task, but the memory used by the task&#8217;s stack and TCB were never actually being freed.  
The simplest memory allocation file that includes a free function is heap&#95;2.&nbsp; If you are doing a lot of freeing &#40;which I don&#8217;t think you are&#41; then use heap&#95;4.c as it prevents memory fragmentation as much as is possible.

</div></div><div class="thread-post"><h3 class="thread-post-title">STM32F103 Freertos update to 7.5.2</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/edwards3">edwards3</a> on September 11, 2013</div><div class="thread-post-content">The extra code probably comes from extra assert&#40;&#41; statements which will only be there when configASSERT&#40;&#41; is defined. I think any additional features in newer versions will default to be turned off. And if you are stripping dead code from your binaries new API functions would not make a difference.  
<blockquote>
  configLIBRARY&#95;MAX&#95;SYSCALL&#95;INTERRUPT&#95;PRIORITY &#8211; X
</blockquote>
You have configLIBRARY&#95;MAX&#95;SYSCALL&#95;INTERRUPT&#95;PRIORITY set to 5 so interrupts using FreeRTOS &#40;ISR safe&#41; calls can use priority 5 and lower priorities. Remember ARM does interrupt priorities backwards, so a priority of 6 is lower than 5 and a priority of 4 is higher than five. Your interrupts should be set to priorities configLIBRARY&#95;MAX&#95;SYSCALL&#95;INTERRUPT&#95;PRIORITY <strong><em>+</em></strong> X, where X can be 0 to 10 in this case, giving your priorities of 5 to 15 inc.  
FreeRTOS V7.5.2 includes extra code that should trigger an assert in the interrupt if you have this wrong though.
