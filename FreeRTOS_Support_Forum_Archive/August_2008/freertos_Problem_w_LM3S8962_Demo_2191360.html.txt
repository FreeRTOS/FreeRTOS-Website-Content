  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Problem w/ LM3S8962 Demo</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/jleung1102">jleung1102</a> on August 29, 2008</div><div class="thread-post-content">I tried setting up the LM3S8962 demo &#40;V5.0.3&#41; from both Keil RealView and Eclipse. Both of them gave me connection errors. RealView messaged: &quot;Error: Flash Download failed &#8211; Target DLL has been cancelled&quot;. I was able to download the blinky &#40;smaller&#41; example onto the board fine using RealView. This suggests that my problem is very unlikely a hardware problem &#40;may be a configuration problem?&#41;
I also tried programming the board from Eclipse using OpenOCD and JTAG. i ran into JTAG connection problem: &quot;jtag&#95;examine&#95;chain&#40;&#41;: JTAG communication failure, check connection, JTAG interface, target power etc.&quot; Interestingly, it did turn on the &quot;DEBUG OUT&quot; LED. 
Anyone ran into similar problems? Has anyone successfully set up the 8962 Demo?
</div></div><div class="thread-post"><h3 class="thread-post-title">Problem w/ LM3S8962 Demo</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on August 29, 2008</div><div class="thread-post-content">So maybe this is not going to help you much&#8230;.
I happen to have an 8962 board on my desk at the moment so I:
&#43; Took a clean FreeRTOS.org V5.0.3 installation.
&#43; Opened the project in Keil uVision.
&#43; Compiled &#8211; no errors.
&#43; Programmed the flash &#8211; no errors &#40;did you remember to do this step?&nbsp; I don&#8217;t think the project is set to automatically flash the device when you start a debug session&#41;.
&#43; Started a debug session and ran the code &#8211; again no problems.
I think did exactly the same with the Eclipse version and again did not run into any issues.&nbsp; On the Eclipse side the version of OpenOCD in the FreeRTOS.org download I think relies on Cygwin, but you would not be able to start it at all if this was the source of your problem.
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">Problem w/ LM3S8962 Demo</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/david_farrell">david_farrell</a> on August 29, 2008</div><div class="thread-post-content">I am using Code Sourcery G++ personal edition and I had no trouble.&nbsp; I assume you are using the on-board usb-jtag interface and not the debug connector?&nbsp; There are so many possible tests with OpenOCD I don&#8217;t know where to start explaining.&nbsp; You can load it &#40;OpenOCD&#41; from an command prompt, this will indicate if it detects the part, try verbose mode, Try to telnet into OpenOCD, scan the flash, etc. These are all things I normally do getting a new board up with OpenOCD but I don&#8217;t remember doing any of it with the 8962, it just worked&#8230;&nbsp; I also assume you are talking about the Luminary LM3S8962 Eval board.&nbsp; One other thing about OpenOCD, you have to be careful with file paths for config files, I generally use full paths to be safe.
