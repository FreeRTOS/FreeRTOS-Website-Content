Most will remove uncalled code. GCC will do it also but only if you add in the correct compile time options &#8211; 
-ffunction-sections -fdata-sections
and link time options
&#45;-gc-sections
</div></div><div class="thread-post"><h3 class="thread-post-title">Only co-routines needed</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/ringzro">ringzro</a> on August 24, 2008</div><div class="thread-post-content">Well, I am trying to port freeRTOS on NXP PXA51, using an evaluation version of RIDE&#40;8KB code&#41;. Of course, I could use SDCC, but support for PXA51 is &quot;not complete, discontinued&quot; as they say. 
So my best choice remains RIDE using my own introduced define &#8216;configUSE&#95;FREE&#95;RTOS&#8217; which masks out &#8216;tasking&#8217; code from both &#8216;tasks.c&#8217; and &#8216;queue.c&#8217;.

</div></div><div class="thread-post"><h3 class="thread-post-title">Only co-routines needed</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/dmitrycherepanv">dmitrycherepanv</a> on August 26, 2008</div><div class="thread-post-content">The FreeRTOS is the Real Time operating system with preemptive scheduling.
Do not need tasks using protothreads, OK.
no task protothreads -&gt; no preemptive scheduling -&gt; only cooperative scheduling -&gt; no condition races, no problems with simultaneous access to data -&gt; It is simple to replace queues on array or linked lists, any way if you want to use protothreads use Contikki Operating System for example.
