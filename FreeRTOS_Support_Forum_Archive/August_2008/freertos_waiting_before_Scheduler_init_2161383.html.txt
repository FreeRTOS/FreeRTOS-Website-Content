  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">waiting before Scheduler init</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/junavas">junavas</a> on August 11, 2008</div><div class="thread-post-content">Hi all,
I have a kinda general question but here it is, first of all I am working with FreeRTOS v5.02, AT91SAM7X port and GCC compiler.
I would like to use the SPI &#40;Serial Peripheral Interface&#41; of this processor to send data to an LCD, so I initialize this peripheric in the main function, as in the prvSetupHardware&#40;&#41; function in the demo. However, the initialization procedure requests to wait some dead time between commands are sent to LCD driver, and vTaskDelay&#40;&#41; funtion is useless as i didnt have called thevTaskStartScheduler function &#40;where system tick is set&#41;. I wouldn&#8217;t like to modify the FreeRTOS kernel, so I am searching for any alternative. Any ideas ?
Thanks, 
</div></div><div class="thread-post"><h3 class="thread-post-title">waiting before Scheduler init</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/bobbosyn">bobbosyn</a> on August 11, 2008</div><div class="thread-post-content">Most LCD drivers have a ‘Ready’ bit that can be read from the bus.&nbsp; I would suggest looping on a read to this condition instead of a simple dead timed loop.
</div></div><div class="thread-post"><h3 class="thread-post-title">waiting before Scheduler init</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on August 11, 2008</div><div class="thread-post-content">You could also do the LCD initialization from a task. This is how the LMI examples work. Another way is to have a start up task that does the init then spawns all the other tasks before entering its while&#40;1&#41; loop or simply deleting itself.
</div></div><div class="thread-post"><h3 class="thread-post-title">waiting before Scheduler init</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/junavas">junavas</a> on August 11, 2008</div><div class="thread-post-content">Thank you very much for your answers.
In my configuration it is not possible to read data from the LCD driver so the first proposal which is the proper way to do it itsn&#8217;t possible&#8230;
I saw the LMI LM3S102 demo and I think I will adopt Dave&#8217;s solution, deleting the initialization task.
Thanks again &#33;
