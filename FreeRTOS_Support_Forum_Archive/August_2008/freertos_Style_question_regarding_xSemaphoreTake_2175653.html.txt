  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Style question regarding xSemaphoreTake</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/jcwren">jcwren</a> on August 20, 2008</div><div class="thread-post-content">If one uses xSemaphoreTake with portMAX&#95;DELAY, is it worth checking the return result, assuming we know the semaphore handle to be valid?&nbsp; The question, of course, is what the appropriate course of action is should it fail.&nbsp; With a valid handle and portMAX&#95;DELAY, is it realistically possible for the take to fail?
</div></div><div class="thread-post"><h3 class="thread-post-title">Style question regarding xSemaphoreTake</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on August 20, 2008</div><div class="thread-post-content">Now that depends :&#41;
If you have INCLUDE&#95;vTaskSuspend defined as 1 then the function will only return it has taken the semaphore and you need not check the return value.
If you have INCLUDE&#95;vTaskSuspend defined as 0 then the call cannot block for ever and will return when portMAX&#95;DELAY ticks has expire and you must check the return value although if you have ticks defined to be a 32bit type this can be days/months/years depending on the tick frequency.
In the latter case the stype is
//Wait on semaphore.
while&#40; xSemaphoreTake&#40; semaphore, portMAX&#95;DELAY &#41; &#33;= 1 &#41;;
//We now have the semaphore.
</div></div><div class="thread-post"><h3 class="thread-post-title">Style question regarding xSemaphoreTake</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/jcwren">jcwren</a> on August 20, 2008</div><div class="thread-post-content">Glad you mentioned the INCLUDE&#95;vTaskSuspend.&nbsp; I am using that, and had noticed that in the docs, but failed to mention it in my scenario.&nbsp; There didn&#8217;t seem to be a failure case &#40;other than passing an invalid semaphore&#41;, so I thought a call with no error checking should be stylistically OK &#40;unless a stray alpha particle flips a bit in your semaphore handle&#8230;&#41;
