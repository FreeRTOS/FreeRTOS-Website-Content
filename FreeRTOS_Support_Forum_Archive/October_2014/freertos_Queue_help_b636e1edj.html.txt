</div></div><div class="thread-post"><h3 class="thread-post-title">Queue help</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/markwrichardson">markwrichardson</a> on October 28, 2014</div><div class="thread-post-content">UART1PutChar() will be called with the last character for every loop regardless of an item in the queue. </div></div><div class="thread-post"><h3 class="thread-post-title">Queue help</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on October 28, 2014</div><div class="thread-post-content"><blockquote>
  send it with a queue to a task.
</blockquote>
That is fine for low bandwidth comms, such as receiving key presses, but 
very inefficient for high bandwidth comms where a circular buffer or DMA 
is better.
<blockquote>
<pre><code> while  (1)
 {
     char  string_received;
     if(xQueueReceive(  UART_queue  ,  &amp;string_received  ,  1000))
     {
         if(  string_received=='s'  )
         {
             LATAbits.LATA0=1;
         }
         else  LATAbits.LATA0=0;
     }
     UART1PutChar(string_received);
 }
</code></pre>
  }
</blockquote>
If you receive only one character then this code will print out that 
character every 1000 ticks.  That is because you have the queue receive 
timeout set to 1000, and print the character stored in string_received 
whether a new value was received on the queue or not.  Moving the 
UART1PutChar() call inside the if() statement would fix that.
<blockquote>
  void  <strong>attribute</strong>((<strong>interrupt</strong>,  no<em>auto</em>psv))  _U1RXInterrupt(void)
</blockquote>
I&#8217;m guessing this is a PIC32?  Please read the documentation page for 
this port as the way you are defining your interrupt is going to waste a 
lot of RAM (although it will work).
<blockquote>
<pre><code> xQueueSend(UART_queue  ,  &amp;data_in  ,  1000);  // send data via queue
</code></pre>
</blockquote>
xQueueSend() cannot be called from an interrupt and <em>definitely</em> cannot 
attempt to block in an interrupt.  Please use <a 
href="http://www.freertos.org/a00119.html">xQueueSendFromISR()</a> 
instead and be sure to read the FAQs, especially the FAQ <a 
href="http://www.freertos.org/FAQHelp.html">&#8220;My application does not 
run, what could be wrong?&#8221;</a>.
Regards.
