  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Setup() with delay() functionality, before creating Task</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/vr6073">vr6073</a> on October 26, 2014</div><div class="thread-post-content">Hello,
I Am using freeRTOS with STM32 F2 microprocessor.
I need to execute some operations for configuring my hardware, before creating my Tasks. In this Setup operations,  I need to use any kind of delay() function.
But At the beginning of the program, vTaskDelay() is not still available. What is the way for using delay functionality before create Tasks and starts scheduler, by calling vTaskStartScheduler() ?
Or stated another way:
Do I have to create a Setup() function as a Task, and then the other Tasks have to wait to start till the setup() finalizes? Is there an specific freeRTOS function to synchronize them that way?
Thanks,
</div></div><div class="thread-post"><h3 class="thread-post-title">Setup() with delay() functionality, before creating Task</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on October 26, 2014</div><div class="thread-post-content">Hello,
If you want to have a blocking delay without using RTOS, you&#8217;ll have to setup a timer that triggers an interrupt.
What I would do:
<ul>
<li>Setup the clocks and a timer for RTOS</li>
<li>Start your first task and from there:</li>
<li>Call your Setup() and use vTaskDelay()</li>
<li>Start-up the other tasks</li>
</ul>
~~~~~~
    void vMainTask (void <em>pvParameters)
    {
        /</em> While running Setup(), there are
        no other tasks yet */
        Setup( );
<pre><code>    xTaskCreateStack (vMacbTASK, ...)
    xTaskCreateStack (vUsbTASK, ...)
    xTaskCreateStack (vLoggingTASK, ...)
    for( ; ; )
    {
        /* Do the normal work */
    }
}
</code></pre>
~~~~~~
Regards,
Hein
</div></div><div class="thread-post"><h3 class="thread-post-title">Setup() with delay() functionality, before creating Task</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/vr6073">vr6073</a> on October 30, 2014</div><div class="thread-post-content">Thank you, Hein,
I am testing another way to do it:
In order to be able to use vTaskDelay() in my Setup() function , I am creating all task at the same time, but Setup with higher priority. That way I am sure that it starts the first:
<pre><code>xTaskCreate(mySetup, "mySetup", STACK_SIZE, NULL, tskIDLE_PRIORITY+2, NULL);
xTaskCreate(Task1, "Task1", STACK_SIZE, NULL, tskIDLE_PRIORITY+1, &amp;xTasksHandle1);
xTaskCreate(AxisControl, "Task2", STACK_SIZE, NULL, tskIDLE_PRIORITY+1, &amp;xTasksHandle2);
</code></pre>
In the body of Setup, I suspend all others Tasks. At the end of Setup, I resume all other tasks and delete Setup Task.
void mySetup(void * pvParameters) {
<pre><code>vTaskSuspend(xTasksHandle1);       
vTaskSuspend(xTasksHandle2);    
for (;;) {
.........................    
......................... 
doing things, and using 
vTaskDelay() delays
.........................     
......................... 
// Resume the suspended tasks.
vTaskResume(xTasksHandle1);     
vTaskResume(xTasksHandle2);
// Delete Setup task (ourselves).
vTaskDelete(NULL);
}
</code></pre>
}
<pre><code>It is working right now...
</code></pre>
</div></div><div class="thread-post"><h3 class="thread-post-title">Setup() with delay() functionality, before creating Task</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/markwrichardson">markwrichardson</a> on October 30, 2014</div><div class="thread-post-content">When I encountered a similar issue in my design, I chose to implement as Hein described.  I felt this was better for the reader and eliminated the chance of a race condition.  The way you describe requires internal knowledge of the OS, which high-level code should not rely on.  For example, if a maintainer moved TaskCreate( mySetup ) after the other TaskCreates, then the outcome wouldn&#8217;t be clear even with knowledge of the priorities.
Anyone else have preferences they use ?
Mark
