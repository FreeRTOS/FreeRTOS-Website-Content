  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">FreeRTOS+lwip on lpc1833 controller.</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/jayeshbhoi">jayeshbhoi</a> on October 7, 2014</div><div class="thread-post-content">Hi,
I have ported the lwip stack on LPC1833 microcontroller(ARM cortex-M3). There are total 6 tasks in my application. This controller communicate with another device in which standard linux network stack is running. The communication is working fine for some minutes and after that it will continues in loop in task &#8220;prvIdleTask&#8221;. In this task it call the &#8220;prvCheckTasksWaitingTermination&#8221; and in which following condition always fail
while( uxTasksDeleted > ( unsigned portBASE_TYPE ) 0U )
{
   //some code
}
So, it will never enter in &#8220;while..loop&#8221; and not switch the task.
I am using freeRTOS V7.3.0 and lwip v1.4.1.
Can any one have idea about what is wrong here?
Regards,
Jayesh
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS+lwip on lpc1833 controller.</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on October 7, 2014</div><div class="thread-post-content">Here is a copy of the answer I just posted on the other forum on which you posted the exact same question:
&#8220;If the idle task is running then there are no application tasks that are able to run &#8211; so all your application tasks are blocked on something or are simply delaying.
Inside the idle task it is checking to see if any tasks have been deleted in order that it might clean up the RAM allocated to those tasks by the kernel. If no tasks have been deleted then it will not enter the loop. I think that is explained in the comments above the code you pasted. Is there any reason you think it should enter the loop?&#8221;
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS+lwip on lpc1833 controller.</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/jayeshbhoi">jayeshbhoi</a> on October 8, 2014</div><div class="thread-post-content">is any way to know in which task it&#8217;s stuck OR which tasks are blocked?
For your information the lwip&#8217;s tcp ip thread have highest priority 4, other two task have priority 3 and remaining three tasks have priority 2.
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS+lwip on lpc1833 controller.</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on October 8, 2014</div><div class="thread-post-content">You can use FreeRTOS+Trace to visualise the behaviour.  There are also 
several kernel aware state viewer plug-ins.  If you are using the 
LPCXpresso IDE then I think the Eclipse plug-in will work for you.
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS+lwip on lpc1833 controller.</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/jayeshbhoi">jayeshbhoi</a> on October 8, 2014</div><div class="thread-post-content">I manually check the task status by using <strong>eTaskStateGet</strong> function and found that two task are in block state,1 task is suspended state and other 3 are in ready state. 
So can suggest me why always running idle task?
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS+lwip on lpc1833 controller.</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on October 8, 2014</div><div class="thread-post-content"><blockquote>
