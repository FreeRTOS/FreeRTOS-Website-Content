  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Crashing in vPortSVCHandler on SAM3S </h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/dibosco">dibosco</a> on October 29, 2014</div><div class="thread-post-content">Not sure whether anyone will be able to help with this. I&#8217;m  having a really odd situation where FreeRTOS is crashing in vPortSVCHandler when the relocated version of the code has been loaded by a [custom] bootloader. If the version of FreeRTOS code loaded by the bootloader &#8211; which is relocated to 0x410000 &#8211; is loaded directly by Crossworks, it works correctly. 
However, even though the code that is loaded by the bootloader looks identical to that loaded by Crossworks, I&#8217;m crashing at the line:
bx r14
It takes me to a hard fault handler. 
The registers look the same in both cases (I can run the bootloader in the debugger and then let it take me through to the code loaded by the bootloader and see the source code by loading an additional elf file of the relocated file). In other works, what&#8217;s in r14, r0 etc look the same whether the code that&#8217;s running is what&#8217;s been loaded by the bootloader or whether I directly run the relocated code the bootloader loads. (I hope this makes sense.)
So, does anyone have any pointers or suggestions as to why it should crash in the last line of vPortSVCHandler in the version loaded by the bootloader? 
I&#8217;m not sure what other details to give.  
The code works fine in a SAM4S (albeit slightly modified for that architecture).
Would be most grateful for any suggestions/pointers. 
Many thanks! 
</div></div><div class="thread-post"><h3 class="thread-post-title">Crashing in vPortSVCHandler on SAM3S </h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on October 30, 2014</div><div class="thread-post-content">Normally when there are problems with bootloaders it is because the vector base address register has not been set correctly, but I don&#8217;t think that applies in this case as you have entered the SVC handler correctly.
What is in the r14 register?  Does it match the expected address of the function you want to jump to (the first task presumably) or does it contain an exec return value.
Regards.
