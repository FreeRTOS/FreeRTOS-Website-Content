  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">rtos on demo9s12xep100 (HCS12x) stack problem</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/andymant">andymant</a> on September 7, 2010</div><div class="thread-post-content">hi all,<br />
I&#8217;ve ported the freertos demo for HCS12 banked mode to the demo board DEMO9S12XEP100.<br />
The code crashes at the instruction<br />
&#95;&#95;asm&#40; &#8220;rti&#8221; &#41;;<br />
inside function&nbsp; xBankedStartScheduler&#40;&#41;.  
I found a funny thing that is:<br />
&#8220;rti&#8221; instruction is declared to behave as:  
&#40;M&#40;SP&#41;&#41; ⇒ CCR; &#40;SP&#41; + $0001 ⇒ SP<br />
&#40;M&#40;SP&#41; : M&#40;SP+1&#41;&#41; ⇒ B : A; &#40;SP&#41; + $0002 ⇒ SP<br />
&#40;M&#40;SP&#41; : M&#40;SP+1&#41;&#41; ⇒ XH : XL; &#40;SP&#41; + $0004 ⇒ SP<br />
&#40;M&#40;SP&#41; : M&#40;SP+1&#41;&#41; ⇒ PCH : PCL; &#40;SP&#41; + $0002 ⇒ SP<br />
&#40;M&#40;SP&#41; : M&#40;SP+1&#41;&#41; ⇒ YH : YL; &#40;SP&#41; + $0004 ⇒ SP  
the Freertos function&nbsp; pxPortInitialiseStack&#40;&#41; saves info in stack as specified above BUT once I execute the &#8220;rti&#8221;I I found that register values are wrong and application crashes.<br />
I found that &#8220;rti&#8221; increments SP by 1 &#40;SP+1 &#41; BEFORE doing what is declared &#33;<br />
I modified the pxPortInitialiseStack&#40;&#41; in order to add a dummy byte in stack and everithing works &#33;.<br />
Find below the modified code for pxPortInitialiseStack&#40;&#41;:  
portSTACK&#95;TYPE &#42;pxPortInitialiseStack&#40; portSTACK&#95;TYPE &#42;pxTopOfStack, pdTASK&#95;CODE pxCode, void &#42;pvParameters &#41;<br />
&#123;<br />
/&#42;<br />
Place a few bytes of known values on the bottom of the stack.<br />
This can be uncommented to provide useful stack markers when debugging.  
&#42;pxTopOfStack = &#40; portSTACK&#95;TYPE &#41; 0x11;<br />
pxTopOfStack-;<br />
&#42;pxTopOfStack = &#40; portSTACK&#95;TYPE &#41; 0x22;<br />
pxTopOfStack-;<br />
&#42;pxTopOfStack = &#40; portSTACK&#95;TYPE &#41; 0x33;<br />
pxTopOfStack-;<br />
&#42;/  
/&#42; Setup the initial stack of the task.&nbsp; The stack is set exactly as<br />
expected by the portRESTORE&#95;CONTEXT&#40;&#41; macro.&nbsp; In this case the stack as<br />
expected by the HCS12 RTI instruction. &#42;/  
/&#42; The address of the task function is placed in the stack byte at a time. &#42;/<br />
&#42;pxTopOfStack = &#40; portSTACK&#95;TYPE &#41; &#42;&#40; &#40;&#40;portSTACK&#95;TYPE &#42;&#41; &#40;&amp;pxCode&#41; &#41; + 1 &#41;;<br />
pxTopOfStack-;<br />
&#42;pxTopOfStack = &#40; portSTACK&#95;TYPE &#41; &#42;&#40; &#40;&#40;portSTACK&#95;TYPE &#42;&#41; &#40;&amp;pxCode&#41; &#41; + 0 &#41;;<br />
pxTopOfStack-;  
/&#42; Next are all the registers that form part of the task context. &#42;/  
/&#42; Y register &#42;/<br />
&#42;pxTopOfStack = &#40; portSTACK&#95;TYPE &#41; 0xff;<br />
pxTopOfStack-;<br />
&#42;pxTopOfStack = &#40; portSTACK&#95;TYPE &#41; 0xee;<br />
pxTopOfStack-;  
/&#42; X register &#42;/<br />
&#42;pxTopOfStack = &#40; portSTACK&#95;TYPE &#41; 0xdd;<br />
pxTopOfStack-;<br />
&#42;pxTopOfStack = &#40; portSTACK&#95;TYPE &#41; 0xcc;<br />
pxTopOfStack-;  
/&#42; A register contains parameter high byte. &#42;/<br />
&#42;pxTopOfStack = &#40; portSTACK&#95;TYPE &#41; &#42;&#40; &#40;&#40;portSTACK&#95;TYPE &#42;&#41; &#40;&amp;pvParameters&#41; &#41; + 0 &#41;;<br />
pxTopOfStack-;  
/&#42; B register contains parameter low byte. &#42;/<br />
&#42;pxTopOfStack = &#40; portSTACK&#95;TYPE &#41; &#42;&#40; &#40;&#40;portSTACK&#95;TYPE &#42;&#41; &#40;&amp;pvParameters&#41; &#41; + 1 &#41;;<br />
pxTopOfStack-;  
/&#42; CCR: Note that when the task starts interrupts will be enabled since<br />
&#8220;I&#8221; bit of CCR is cleared &#42;/<br />
&#42;pxTopOfStack = &#40; portSTACK&#95;TYPE &#41; 0x00;<br />
pxTopOfStack-;  
<strong>/&#42; WARNING: Mantovani: Added dummy byte cause RTI assembler instruction seems to be buged &#33;&#33;&#33;&#33; &#42;/<br />
&#42;pxTopOfStack = &#40; portSTACK&#95;TYPE &#41; 0x00;<br />
pxTopOfStack-;</strong>  
&#35;ifdef BANKED&#95;MODEL<br />
/&#42; The page of the task. &#42;/<br />
&#42;pxTopOfStack = &#40; portSTACK&#95;TYPE &#41; &#40; &#40; int &#41; pxCode &#41;;<br />
pxTopOfStack-;<br />
&#35;endif  
/&#42; Finally the critical nesting depth is initialised with 0 &#40;not within<br />
a critical section&#41;. &#42;/<br />
&#42;pxTopOfStack = &#40; portSTACK&#95;TYPE &#41; 0x00;  
return pxTopOfStack;<br />
&#125;  
It doesn&#8217;t seem a memory alignement issue rather that an &#8220;rti&#8221; hw implementation bug.<br />
Is it possible or I&#8217;m doing something wrong ?  
All suggestions are welcome.<br />
Thanks<br />
Andrea

&#40;M&#40;SP&#41; : M&#40;SP+1&#41;&#41; ⇒ B : A; &#40;SP&#41; + $0002 ⇒ SP<br />
&#40;M&#40;SP&#41; : M&#40;SP+1&#41;&#41; ⇒ XH : XL; &#40;SP&#41; + $0004 ⇒ SP<br />
&#40;M&#40;SP&#41; : M&#40;SP+1&#41;&#41; ⇒ PCH : PCL; &#40;SP&#41; – $0002 ⇒ SP<br />
&#40;M&#40;SP&#41; : M&#40;SP+1&#41;&#41; ⇒ YH : YL; &#40;SP&#41; + $0004 ⇒ SP
