The problem I&#8217;ve encountered is that when I insert a printf&#40;&#41; call anywhere in main&#40;&#41;, the application crashes at startup before even reaching main&#40;&#41;. The simulator says:  
<blockquote>
  Data Abort: ARM Instruction at 0000155CH, Memory Access at E3A02066H
</blockquote>
The processor <em>is</em> in Supervisor mode before the call to vTaskStartScheduler&#40;&#41;, as required.  
Any ideas?

</div></div><div class="thread-post"><h3 class="thread-post-title">Adding a printf call causes Demo to crash</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on September 22, 2010</div><div class="thread-post-content"><blockquote>
  emo on the Keil uVision3 simulator
</blockquote>
Thank you for stating that up front.&nbsp; The simulator is not the environment on which the port was developed or intended to run.&nbsp; Normally when people report problems in a simulated environment the problem does not exist in the real environment.  
<blockquote>
  nsert a printf&#40;&#41; call anywhere in main&#40;&#41;
  the application crashes at startup before even reaching main&#40;&#41;
</blockquote>
If the print is in main&#40;&#41;, and it is crashing in the startup code, then your problem is not &#40;yet at least&#41; related to FreeRTOS anyway.&nbsp; The kernel does not start and the stack pointer is not manipulated until the kernel vTaskStartScheduler&#40;&#41; is called.&nbsp; Up to that point, you just have a standard single threaded C program.  
I don&#8217;t know where printf&#40;&#41; is supposed to print to in the Keil tools.&nbsp; Have you configured it to actually do something &#40;print to COM port, debug terminal, or the like?&#41;.&nbsp; Is it attempting to use memory that has not been allocated?&nbsp; Etc. Etc.  
Regards.  
I think you are asking the question in the wrong place.&nbsp; Keil tech support should be able to answer questions about using printf&#40;&#41; and about using their simulator.  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">Adding a printf call causes Demo to crash</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/slrz1eqr">slrz1eqr</a> on September 30, 2010</div><div class="thread-post-content">Just in case anyone is interested. When you add printf&#40;&#41; or some other I/O or memory management C functions to your code, Keil C links in some library modules which make SWI calls at startup. This results in vPortYieldProcessor&#40;&#41; being called <em>before</em> vTaskStartScheduler&#40;&#41;. To avoid this, you should add to your code:  
<pre><code>#pragma import(__use_no_semihosting_swi)
</code></pre>
You will also have to retarget some of the library functions like fputc&#40;&#41;, fgetc&#40;&#41;, etc. In my case, the addition of KeilARMStartupretarget.c to my project was enough. For more info, see <a href="http://infocenter.arm.com/help/topic/com.arm.doc.dui0067d/Ciheeaja.html">Building an application for a nonsemihosted environment</a>.  
All the best.
