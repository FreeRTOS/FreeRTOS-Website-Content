But I am curious what takes so long to attach a card.  Can you trace that?  Is there a time-out that should not time out?
<blockquote>
  Max SD card Size
</blockquote>
I think that the ST driver only works with SDSC and SDHC cards. The max size of the latter is 32 GB.
<blockquote>
  one of the SD card got corrupted
</blockquote>
Is that one SD-card out of several? If you replace that card, will the new card also get corrupted?
I think that most corruptions are caused by an unexpected disconnection. The system goes asleep, or the card is removed too early. There are techniques to reduce this risk ( by flushing more frequently ).
Do you also have a Linux machine with an slot for SD-cards? The &#8220;fsck&#8221; program ( in FAT32 mode ) gives a very detailed analysis.

  <code>FF_SDDiskMount(pxDisk)</code> I found that this function makes the big delay for attach
</blockquote>
that function calls several other functions, among which <code>HAL_SD_Init()</code>. How long does that last?
( I&#8217;m sorry that I can not answer this, I have no hardware for testing here )
<blockquote>
  As of now one SD card got corrupted. &#8230;all others are working fine.
</blockquote>
It does happen that SD-cards get non-functional. There are great differences in quality between cards. Some developers blame the contacts: corrosion, pollution, grease, and even spiders. I also saw cheaper slots for uSD&#8217;s, that made an unreliable contact.
Note that an SD-card has internal firmware: it handles requests from outside and it has algorithms to do the housekeeping. Some cards do this better and faster than others. If the budget allows you, it is worth spending more money on better SD-cards.
<blockquote>
  This faulty SD card can be attached in windows PC. But unable to attach in RTOS.
</blockquote>
+FAT has logging, did you enable that by defining <code>FF_PRINTF()</code> ?
<blockquote>
  Regarding the &#8220;fsck&#8221;, i will try to get it.
</blockquote>
<code>fsck</code> is not just a program, you will need Ubuntu or another Linux desktop. It was of great help while developing FreeRTOS+FAT. <code>fsck</code> will also warn about minor errors.
