  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Increase Thread Stack Size on Microblaze System</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/mike-ascend">mike-ascend</a> on March 13, 2018</div><div class="thread-post-content">I am using a Microblaze CPU with FRTOS version 8.2.3. Is it possible to increase the stack size beyond the limit imposed by the prototype of function xTaskCreate.
usStackDepth is declared as a unsigned short which means, on a 32 bit Microblaze, the stack for threads has a maximum limit of 4 * 65353 = 262140 bytes (256 KB).
I know there a lot of questions regarding stacks size and I have been through them but they do not seem to answer the above question.
Thanks.
</div></div><div class="thread-post"><h3 class="thread-post-title">Increase Thread Stack Size on Microblaze System</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on March 13, 2018</div><div class="thread-post-content">FreeRTOS V10 introduced a macro configSTACK<em>DEPTH</em>TYPE that can be defined in FreeRTOSConfig.h to whichever type you like &#8211; if it is left undefined then it defaults to uint16_t for backward compatibility.
You could either just drop the FreeRTOS V10 source files over the top of your V8.2.3 files to upgrade the FreeRTOS version, or grep the V10 code to see everywhere where configSTACK<em>DEPTH</em>TYPE is used and make the same chanages in your V8.x code.
</div></div><div class="thread-post"><h3 class="thread-post-title">Increase Thread Stack Size on Microblaze System</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/mike-ascend">mike-ascend</a> on March 13, 2018</div><div class="thread-post-content">Thanks for the information.

</div></div><div class="thread-post"><h3 class="thread-post-title">Increase Thread Stack Size on Microblaze System</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on March 13, 2018</div><div class="thread-post-content">It should be a drop in replacement.  Best thing to do would be to take a 
back up of what you have already, drop the new files in (all of them, 
including the port layer, etc.) and give it a go.  You can always revert.
