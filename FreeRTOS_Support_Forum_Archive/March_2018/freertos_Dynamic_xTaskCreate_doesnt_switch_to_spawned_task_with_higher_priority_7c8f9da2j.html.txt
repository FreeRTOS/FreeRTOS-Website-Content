  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Dynamic xTaskCreate() doesn&#8217;t switch to spawned task with higher priority</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/jeronimo479">jeronimo479</a> on March 21, 2018</div><div class="thread-post-content">I&#8217;m using FreeRTOS v10.0.0 on an ARM M3 and heap_4.c.
From InitTask() with priority 5 I call:
~~~
result = xTaskCreate(
        GPIO<em>BlinkTask,             // task callback function
        &#8220;BlinkTsk&#8221;,                 // task nickname
        configMINIMAL</em>STACK_SIZE,   // stack size in words
        NULL,                       // passed parameter
        6,                          // task priority
        NULL);
~~~
I expected that the call to xTaskCreate() would leave GPIO_BlinkTask() ready to run, and 
therefore, FreeRTOS would switch to it, instead of retruning to InitTask(). I Looked through
xTaskCreate() and could not find any calls to the scheduler. This may or may not be a bug.
The FreeRTOS<em>Reference</em>Manual_v9.0.0 states: &#8220;Newly created tasks are initially placed in the Ready state, but will immediately become the Running state task if there are no higher priority tasks that are able to run.&#8221;
I expected that an RTOS will always have the highest task that is ready to run, running. Since
xTaskCreate() creates GPIO_BlinkTask() ready to run, why is it not immediately running?
I think I can solve this by calling vTaskDelay(0) just after xTaskCreate(GPIO_BlinkTask&#8230;)
Thanks,
Wayne
</div></div><div class="thread-post"><h3 class="thread-post-title">Dynamic xTaskCreate() doesn&#8217;t switch to spawned task with higher priority</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/jeronimo479">jeronimo479</a> on March 21, 2018</div><div class="thread-post-content">Please forgive me. I rebuilt all my libraries and source code, and now it works. The FreeRTOSConfig.h files had the max priorites set below the levels I was using, so that the levels were clipped at max, and being equals, there was no task switch after the creation.
Sorry
I would remove this topic if I knew how.
