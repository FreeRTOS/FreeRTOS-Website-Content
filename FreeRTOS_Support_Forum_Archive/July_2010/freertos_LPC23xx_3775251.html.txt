  I already seen some discussions about LPC2368 in the forum, I didn&#8217;t<br />
  find it for IAR at the new versions of IAR, so I suppose that &#8220;work&#8221;<br />

There is an IAR port layer for the LPC2000, with accompanying demo projects.&nbsp; Converting this to be correct for the LPC23xx should not be a big job, and it sounds like you have an understanding of what is required already.  
There are already LPC2000 and LPC23xx port layers for GCC, and these can be examined to see what the differences are.&nbsp; However, the syntax required between GCC and IAR is going to be very different, so its best to start with the IAR files, then edit the files as required to make them correct for the 2368.  
One way to do this would be to:  
1&#41; In the FreeRTOS directory tree, create a directory called FreeRTOSSourceportableIARLPC23xx, and into this directory copy all the files from the FreeRTOSSourceportableIARLPC2000 directory.&nbsp; This will hold the modified port layer files.  
2&#41; Also create a directory called FreeRTOSDemoARM7&#95;LPC2368&#95;IAR, and into this directory copy all the files from the FreeRTOSDemoARM7&#95;LPC2129&#95;IAR directory.&nbsp; This will hold the demo project workspace and files.  
3&#41; In IAR Embedded Workbench, open up the .eww file located in the new FreeRTOSDemoARM7&#95;LPC2368&#95;IAR directory and check that it builds.&nbsp; This will then be a good starting point, albeit targeted at the wrong CPU derivative.  
4&#41; In the IAR project workspace you will see a folder called &#8220;Scheduler Source&#8221;.&nbsp; From that folder &#40;within the IDE&#41; remove port.c and portasm.s79 as these will be located in the LPC2000 directory.&nbsp; In their place add the files that have the same names from the directory created in step &#40;1&#41; above.&nbsp; Try compiling again &#8211; no idea what will happen but it should still compile as the files thus far are identical.  
5&#41; Bring up the project options by pressing ALT+F7.&nbsp; Under the category &#8220;General Options&#8221; &#40;comes up by default&#41; you will see a tab called &#8220;Target&#8221; on which you can select the LPC2368 as the CPU derivative.&nbsp;&nbsp; Next select the linker category, and ensure the linker file being used is correct for the LPC2368 .  
6&#41; Open up FreeRTOSConfig.h from the demo directory created in step &#40;2&#41;.&nbsp; At the top you will see a device specific header file being included &#8211; change this to be correct for the LPC2368.  
7&#41; Next you will have to inspect and compare the Source/Portable/LPC2000 and Source/Portable/LPC23xx files to see what differences there are and make the same changes to the IAR equivalents that are now included in your IAR workspace.&nbsp; As you already mentioned the timer configuration is a bit different, but you should be able to see the differences easily enough.  
<blockquote>
  When I change the ASM &#40; port SAVE and port RESTORE &#41; it change the<br />
  result, but in fact, I can go far with it.  
</blockquote>
You should not need to change any asm code &#40;probably&#41;, but with the IAR projects the interrupt service routines need wrappers that are placed in asm files &#8211; whereas the GCC equivalent uses naked functions in C files instead.&nbsp; See the section &#8220;An example of an ISR with context switching capabilities&#8221; on the following page <a href="http://www.freertos.org/portlpciar.html">http://www.freertos.org/portlpciar.html</a> .  
<blockquote>
  The big issue is that in IAR there is no possible to call the code<br />
  like in GCC &#40; because of naked attribute &#8211; that&#8217;s why the code use ASM<br />
  MACRO &#41;  
</blockquote>
So how to make SAVE and RESTORE totaly compatible calling this 2 lines :  
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; &#40; void &#41; ulCriticalNesting;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; <br />
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; &#40; void &#41; pxCurrentTCB;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;   
Creating your project from the existing LPC2000 project as described about should prevent you having to change anything, I think.
