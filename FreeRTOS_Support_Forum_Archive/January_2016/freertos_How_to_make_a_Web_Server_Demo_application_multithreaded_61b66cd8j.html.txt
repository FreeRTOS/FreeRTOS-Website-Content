</div></div><div class="thread-post"><h3 class="thread-post-title">How to make a Web Server Demo application multithreaded?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on January 13, 2016</div><div class="thread-post-content">Are you talking about the FreeRTOS+TCP web server example here?  http://www.freertos.org/FreeRTOS-Plus/FreeRTOS<em>Plus</em>TCP/HTTP<em>web</em>Server.html .  That (which at the moment is quite basic) and the FTP server (which is more sophisticated) http://www.freertos.org/FreeRTOS-Plus/FreeRTOS<em>Plus</em>TCP/FTP<em>Server.html currently run in the same RTOS task.  So one &#8216;server task&#8217; is handling all HTTP and FTP connections, which is very efficient from a RAM point of view, and not too inefficient from a run time and throughput point of view as the file system is a bottleneck anyway as all the threads want to access the same file system.  You can see a little video demonstration of both running at once, along with three or four other TCP/IP and UPD/IP examples, all running simultaneously in less than 190K RAM.  In fact, it would work in less RAM too.  http://www.freertos.org/FreeRTOS-Plus/FreeRTOS</em>Plus<em>TCP/TCP-IP</em>In<em>190K</em>RAM_Video.html

</div></div><div class="thread-post"><h3 class="thread-post-title">How to make a Web Server Demo application multithreaded?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on January 14, 2016</div><div class="thread-post-content">Hi Joe,
Some more background information in addition to what Richard wrote:
It is a classical approach to have a TCP server that calls accept() and forks for every new connection (so fork() comes after a successful accept())
A child process or thread will exist as long as the TCP connection is alive.
That approach works OK in an environment with plenty of resources (lots of RAM).
In an embedded environment, we must be careful with resources. When a browser opens an interactive page, with some Java Script and asynchronous requests, it will open 6 connections to port 80.
A HTML or FTP server uses:
1) A disk
2) A network interface
3) CPU time
In most cases, there is only one of each: a single disk, which is often a memory card or flash. A single network adapter (peripheral). And finally, most smaller CPU&#8217;s have a single core.
So you can ask your self: what&#8217;s the use of creating extra tasks, if all those tasks are competing to use <strong>shared</strong> resources?
The FreeRTOS_select() library function is essential: it lets the server wait for specific events on <strong>any</strong> of the sockets in a socket-set. The server sockets (for which bind(), listen(), and accept() is called) are included in this socket-set, they wait for a READ event.
Another socket has it&#8217;s transmission buffer full of data, and it will wait for a WRITE event.
Yet a third socket has sent a file and it waits for a READ event.
FreeRTOS_listen() has a parameter called &#8220;backlog&#8221;. That protects the application against getting too many concurrent connections.
Regards.
