  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Recommendation for stack sizes</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/dansear">dansear</a> on July 27, 2007</div><div class="thread-post-content">Would it be possible to change the &#8216;unsigned portSHORT usStackDepth;&#8217;
to &#8216;unsigned portLONG&nbsp; ulStackDepth;&#8217; in struct tskTaskControlBlock?
&#40;and update the modified references&#41;
First, yes, I did need a stack larger than 64k variables.
2nd, being a short causes some compilers to emit slightly more code
than if the type were the natural integer size.
3rd, being a short in a structure opens up the possibilities
for problems with structure packing &#40;although not likely an issue
with this structure yet&#41;.
Dan Searles
</div></div><div class="thread-post"><h3 class="thread-post-title">Recommendation for stack sizes</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on July 27, 2007</div><div class="thread-post-content">You have been busy&#33;&nbsp; Thanks for your comments and suggestions.
The stack size used to be unsigned portBASE&#95;TYPE, but this caused problems on some 8bit systems where the stack could not be greater than 0xff.&nbsp; Long was considered too wasteful on 8bitters &#40;mainly because of its use in the TCB rather than just as a function parameter&#41;, so short became the compromise.&nbsp; FreeRTOS.org has come a long way since then however and finds most uses in the 32bit world.
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">Recommendation for stack sizes</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/adarkar9">adarkar9</a> on July 27, 2007</div><div class="thread-post-content">&gt; FreeRTOS.org&#8230;finds most uses in the 32bit world.
Really?&nbsp; Wow.&nbsp; Please don&#8217;t forget about all the 8-bitters though.&nbsp; I still agree that &quot;long&quot; is too wasteful.&nbsp; If you make any change, perhaps you should make it configurable.
