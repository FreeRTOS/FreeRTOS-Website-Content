During debugging I&#8217;ve noted in the portCOPY&#95;XRAM&#95;TO&#95;STACK macro the value of ucStackBytes = pxXRAMStack&#91; 0 &#93; is 0 and this causes a bad copy of ram into xram whith a coneguent reset.
regards
</div></div><div class="thread-post"><h3 class="thread-post-title">portCOPY_XRAM_TO_STACK on 8052 porting</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/adarkar9">adarkar9</a> on July 26, 2007</div><div class="thread-post-content">Are you checking the return value of the call to xTaskCreate&#40;&#41;?&nbsp; Assuming that xTaskCreate&#40;&#41; was able to allocate the required memory in prvAllocateTCBAndStack&#40;&#41;, the subsequent call to pxPortInitialiseStack&#40;&#41; should set up the task&#8217;s XRAM stack copy such that a call to portCOPY&#95;XRAM&#95;TO&#95;STACK&#40;&#41; would succeed.
Perhaps you don&#8217;t have enough heap space.&nbsp; What value of configTOTAL&#95;HEAP&#95;SIZE are you using?&nbsp; What tasks &#40;along with stack sizes&#41; are you trying to create?&nbsp; The Cygnal demo application allocates 8 flash tasks, 4 semaphore tasks, 1 integer math task, 2 polled queue tasks, 2 com tasks, 4 semaphore tasks, 2 FLOP tasks, a register test task, an error check task, and the idle task, each with about 200 bytes of stack space.&nbsp; That is roughly 5200 bytes of heap space before adding any of the queues, semaphores, or task structures &#40;the Cygnal port allocates 6 KiB for the heap&#41;.&nbsp; With only 1792 bytes of XRAM, you will have to cut way back on the number of tasks and/or size of stacks you use.
</div></div><div class="thread-post"><h3 class="thread-post-title">portCOPY_XRAM_TO_STACK on 8052 porting</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/superfede76">superfede76</a> on July 27, 2007</div><div class="thread-post-content">In my new porting i&#8217;ve used only a little test task because the little memory. When xPortStartScheduler call the macro portCOPY&#95;XRAM&#95;TO&#95;STACK there is no data saved into XRAM, the ucStackBytes value is zero, Because in his position there is non data,&nbsp; and the first decrementation cause his undeflow&#8230; 
Now my problem is: why portYield make nothing. I&#8217;m working on this.
