</div></div><div class="thread-post"><h3 class="thread-post-title">Dup echo replies </h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on April 12, 2012</div><div class="thread-post-content">You will probably find that the uIP network driver is configured to send every packet twice, in which case you are receiving the same number of replies as requests. This is done sometimes as a cheap &#40;if transmission is done by DMA&#41; way of getting around the throughput problems caused by delayed acks when talking from a real time system to a desktop system.
</div></div><div class="thread-post"><h3 class="thread-post-title">Dup echo replies </h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/thomas84">thomas84</a> on April 12, 2012</div><div class="thread-post-content">I have found the part where the second reply is sent and now there&#8217;s only one reply, BUT between the request and the reply there is something on the cable 010101010101…. for one frame like uIP always wants to send two frames and if i take one frame away, it just writes 01010101 for one frame. I want to tell uIP that i only want 1 frame to be send. Any idea what i can adjust?  
</div></div><div class="thread-post"><h3 class="thread-post-title">Dup echo replies </h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on April 12, 2012</div><div class="thread-post-content">In that particular project the double send is done in the ISR void vEMAC&#95;ISR&#40; void &#41; in emac.c  
<pre><code>    if( ulStatus &amp; INT_TX_DONE )
    {
        if( usSendLen &gt; 0 )
        {
            /* Send the data again, using the second descriptor.  As there are
            only two descriptors the index is set back to 0. */
            TX_DESC_PACKET( ( emacTX_DESC_INDEX + 1 ) ) = TX_DESC_PACKET( emacTX_DESC_INDEX );
            TX_DESC_CTRL( ( emacTX_DESC_INDEX + 1 ) ) = ( usSendLen | TCTRL_LAST | TCTRL_INT );
            LPC_EMAC-&gt;TxProduceIndex = ( emacTX_DESC_INDEX );
            /* This is the second Tx so set usSendLen to 0 to indicate that the
            Tx descriptors will be free again. */
            usSendLen = 0UL;
        }
        else
        {
            /* The Tx buffer is no longer required. */
            prvReturnBuffer( ( unsigned char * ) TX_DESC_PACKET( emacTX_DESC_INDEX ) );
            TX_DESC_PACKET( emacTX_DESC_INDEX ) = ( unsigned long ) NULL;
        }
    }
</code></pre>
I haven&#8217;t tried this, but it looks like you could remove the double send by changing it to something like this:  
<pre><code>    if( ulStatus &amp; INT_TX_DONE )
    {
        /* The Tx buffer is no longer required. */
        prvReturnBuffer( ( unsigned char * ) TX_DESC_PACKET( emacTX_DESC_INDEX ) );
        TX_DESC_PACKET( emacTX_DESC_INDEX ) = ( unsigned long ) NULL;
        LPC_EMAC-&gt;TxProduceIndex = ( emacTX_DESC_INDEX );
    }
</code></pre>
but I&#8217;m not 100% confident of that &#8211; you would have to look at how the transmit function was using the descriptor too.  
Regards.
