  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">PIC18F Fixes for heap, context bugs</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/malsyned">malsyned</a> on April 3, 2012</div><div class="thread-post-content">The PIC18F port in FreeRTOS has long had two bugs that make it unfit for reliable production use. One is a linker script which permits sections containing C variables to cross bank boundaries. The other is the built-in assumption that the .tmpdata and MATH&#95;DATA sections won&#8217;t change size, which they do often both as a project evolves and between compiler versions.  
This patch, made against FreeRTOSV7.1.0, contains both of my fixes.  
<a href="http://malsyned.net/files/patches/freertos-v7-mplab-pic18-heap-tmpdata-fix.patch">http://malsyned.net/files/patches/freertos-v7-mplab-pic18-heap-tmpdata-fix.patch</a>  
A complete write-up of the issues involved and how my patch fixes them can be read here:  
<a href="http://malsyned.net/files/freertos-pic-port-notes-wrapped.txt">http://malsyned.net/files/freertos-pic-port-notes-wrapped.txt</a>  
This patch also contains a small fix for the PIC18F demo projects because they do not compile cleanly since V7.0.0.  
Since V7, FreeRTOS and C18 both define a header named &#8220;timers.h&#8221;. The PIC18F ports.c includes &#8220;timers.h&#8221; from the Microchip libraries for the OpenTimer1 function and associated definitions. Because of this, the FreeRTOS PIC18F demos don&#8217;t compile in FreeRTOS V7 as the Microchip &#8220;timers.h&#8221; is shadowed by the FreeRTOS header.  
In order to make sure the demos compile, I have changed the order of the include paths in their Project Build Options to prioritize Microchip&#8217;s headers above FreeRTOS&#8217;s. This is sufficient to compile the demos, but in order to compile projects that use the FreeRTOS timers module a more complete solution will have to be devised.

</div></div><div class="thread-post"><h3 class="thread-post-title">PIC18F Fixes for heap, context bugs</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/malsyned">malsyned</a> on April 4, 2012</div><div class="thread-post-content"><a href="http://malsyned.net/files/freertos-mplab-pic18-flexible-interrupts.patch">http://malsyned.net/files/freertos-mplab-pic18-flexible-interrupts.patch</a>  
This patch adds a configuration define, configPORT&#95;USER&#95;ISR&#95;VECTOR, that can be set to the name of a function that handles vectoring to non-OS interrupts.  
This function &#40;interrupts.c:vUserInterruptVector in the Demo projects&#41; is limited in what instructions it can execute, since it cannot alter the values of any registers. As long as the pattern established in the Demo example is followed, this is an easy requirement to satisfy.  
This patch is independent of my other, but doesn&#8217;t quite apply cleanly on top of it. So I&#8217;ve also made a single patch file that combines both:  
<a href="http://malsyned.net/files/freertos-v7-mplab-pic18-heap-tmpdata-fix-flexible-interrupts.patch">http://malsyned.net/files/freertos-v7-mplab-pic18-heap-tmpdata-fix-flexible-interrupts.patch</a>  
I&#8217;ll post the combined patch to Interactive as well.
