</div></div><div class="thread-post"><h3 class="thread-post-title">Yielding from an ISR</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on April 24, 2012</div><div class="thread-post-content">On some ports it is <strong>extremely</strong> important, essential even, that the yielding is done as the last thing.&nbsp; On the Cortex-M however, it is not important, and either of your code snippets are fine, provided your doStuff&#40;&#41; function is only called from an interrupt.&nbsp; If it is not called from an interrupt then it will still be ok provided the function that calls it takes care of the yielding if one is required.  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">Yielding from an ISR</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/frankandersen">frankandersen</a> on April 24, 2012</div><div class="thread-post-content">Hi Richard,  
Could you please explain why the yield not is important on the Cortex-M?  
Best regards,  
Frank Andersen
</div></div><div class="thread-post"><h3 class="thread-post-title">Yielding from an ISR</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on April 24, 2012</div><div class="thread-post-content">Every port is different.&nbsp; Some require direct manipulation of the ISR exit code, in which case the yield must be at the end, or use function calls, which again means it has to be at the end, but the Cortex-M just pends the PendSV interrupt, and that can be done at any time because the interrupt won&#8217;t execute until the original ISR exits &#40;because the PendSV is the lowest priority&#41;.
