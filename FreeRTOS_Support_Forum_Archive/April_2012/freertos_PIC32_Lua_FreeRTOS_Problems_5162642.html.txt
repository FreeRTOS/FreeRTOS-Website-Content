  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">PIC32 + Lua + FreeRTOS Problems</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nathanwiebe">nathanwiebe</a> on April 3, 2012</div><div class="thread-post-content">I&#8217;m not sure how likely I am to find a solution to my problem&#40;s&#41;, but I hope to shed some light for people heading in the same direction as me.  
Long story short: Getting Lua running on FreeRTOS on PIC32 has been a huge battle.&nbsp; Here&#8217;s what doesn&#8217;t work:<br />
A&#41; Using the new C30 libc libraries doesn&#8217;t work even with stock Lua &#40;no FreeRTOS&#41;.&nbsp; Random crashes.<br />
B&#41; Any floating point operations in the simulator from a FreeRTOS thread.&nbsp; If called before starting the scheduler, they work.&nbsp; After, they return garbage.&nbsp; So… don&#8217;t depend on the simulator.<br />
C&#41; Floating point &#40;lua&#95;Number defined to double&#41; Lua from a thread.&nbsp; Even basic operations return garbage.&nbsp; &#40;e.g. 5 &#42; 7 gives 5.5623e-315&#41;.&nbsp; They work from main&#40;&#41;, but not once the scheduler is started.<br />
D&#41; I should note that I read of another guy porting Lua who mentioned that the debug build broke Lua &#40;w/o an RTOS&#41;.&nbsp; I haven&#8217;t experienced this, but be warned.&nbsp; Google: &#8220;ASKr PIC32 Lua&#8221;.&nbsp; He also confirms A&#41;  
Here&#8217;s what does work:<br />
A&#41; Stock Lua with no FreeRTOS &#40;in simulator, and in debug and release on real hardware&#41; using the legacy libc.<br />
B&#41; Integer Lua &#40;lua&#95;Number defined as long rather than double&#41; from a thread, but only on real hardware.  
I&#8217;ve tried all the obvious &#40;huge stack, huge heap, etc, etc.&#41;, optimizations on the code and libc off, only one thread running throughout, …  
-I REALLY don&#8217;t want to go with a stock Lua &#40;without FreeRTOS&#41; because of the power of the RTOS and the rich set of drivers I&#8217;ve written.<br />
-I REALLY don&#8217;t want to go with an integer version of Lua either.  
This really took Microchip down a couple pegs in my books.&nbsp; Combining 2 well-written, established pieces of code should not be such a battle, but random issues with Microchip software and libraries have made it so.  
Anyone out there with any ideas?&nbsp; Anyone actually get something like this working?
