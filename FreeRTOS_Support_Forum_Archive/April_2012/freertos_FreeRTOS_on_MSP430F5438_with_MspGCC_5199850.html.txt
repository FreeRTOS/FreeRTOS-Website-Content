But maybe i&#8217;ve passed through something important ?  
Thank you in advance for your help, i really don&#8217;t know where else i could ask for it…

</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS on MSP430F5438 with MspGCC</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on April 16, 2012</div><div class="thread-post-content">The FreeRTOS download contains an MSP430 port for GCC, but not an MSP430X port for GCC.&nbsp; However, it contains both an MSP430 and and MSP430X port for IAR.&nbsp; I therefore suggest comparing the directorie  
FreeRTOSSourceportableIARMSP430  
with the directory   
FreeRTOSSourceportableIARMSP430X  
to see the changes that are required to support the extended architecture, then make the same changes to the existing FreeRTOS MSP430 GCC port.  
Regards.

</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS on MSP430F5438 with MspGCC</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/edwards3">edwards3</a> on April 17, 2012</div><div class="thread-post-content">If GCC for MSP430 supports the naked function attribute, it is easiest to transfer the assembly code out of the assembly file and into a C file. To do this you define a function as naked to stop the compiler adding any assembly to the function entry point, and then use &#95;&#95;asm volatile to write assembly instructions.  
Update. Just looking at the SourceportableGCCMSP430F449port.c file I see this is what FreeRTOS is doing already. Look at the function vPortYield&#40;&#41;. The portSAVE&#95;CONTEXT and portRESTORE&#95;CONTEXT macros are asm macros and defined in the same file.

</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS on MSP430F5438 with MspGCC</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/pabigot">pabigot</a> on June 10, 2012</div><div class="thread-post-content">I&#8217;ve got the beginnings of a port for MSPGCC at <a href="https://github.com/pabigot/freertos-mspgcc.">https://github.com/pabigot/freertos-mspgcc.</a>&nbsp; A primary goal of this effort is to provide a test environment for non-trivial 20-bit-capable applications using MSPGCC, and at the moment it will probably only work correctly with the current development series available at <a href="https://sourceforge.net/projects/mspgcc/files/mspgcc/DEVEL-4.7.x/.">https://sourceforge.net/projects/mspgcc/files/mspgcc/DEVEL-4.7.x/.</a>&nbsp; I could probably be talked into adding support for the LTS&#95;20120406 release.  
There&#8217;s a very trivial demo for the EXP430F5438, and another for the EXP430G2 &#40;Launchpad&#41; using the MSP430G2553.&nbsp; The RAM limitations of the MSP430G2553 make it barely usable, but the demo for it does allow two flash coroutines to exist. More platforms and features are expected soon.  
See <a href="https://sourceforge.net/apps/mediawiki/mspgcc/index.php?title=MSPGCC_Wiki">https://sourceforge.net/apps/mediawiki/mspgcc/index.php?title=MSPGCC_Wiki</a> for general information about mspgcc.
