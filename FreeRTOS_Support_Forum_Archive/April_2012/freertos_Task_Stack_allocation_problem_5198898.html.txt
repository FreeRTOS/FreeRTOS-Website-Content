According to documentation individual task stacks are allocated from the Total Heap size we will be define and allocate in FreeRTOSConfig.h.<br />
Is there any possibility,&nbsp; of the addition of all individual task stacks exceeding the amount of total heap allocation?  
Thank you.  
</div></div><div class="thread-post"><h3 class="thread-post-title">Task Stack allocation problem</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on April 16, 2012</div><div class="thread-post-content"><blockquote>
  Is there any possibility,&nbsp; of the addition of all individual task stacks exceeding the amount of total heap allocation?
</blockquote>
Naturally, yes, there is a limited amount of RAM and a user can attempt to create an infinite amount of tasks.  
heap&#95;1.c and heap&#95;2.c both have a function xPortGetFreeHeapSize&#40;&#41; that allows you to query the stack remaining.&nbsp; heap&#95;3.c uses malloc&#40;&#41; and free&#40;&#41; so FreeRTOS itself cannot obtain the free space.&nbsp; There is also a malloc failed hook function that can be defined that will be called when an allocation fails.  
Regards.

The total heap size parameter is used in heap&#95;1 and heap&#95;2 to define the size of the heap to be created. For heap&#95;3 you need to use the method provided by your compiler/linker to set this, and the parameter in FreeRTOS is ignored.

</div></div><div class="thread-post"><h3 class="thread-post-title">Task Stack allocation problem</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on April 18, 2012</div><div class="thread-post-content">Forgive us, but your question was not clear.  
Each task has its own stack, that is used by the compiler to store things like function call return addresses and local variables.&nbsp; There is nothing different about the stack used by a task than any other stack &#8211; for example the stack allocated by the linker for use by the main&#40;&#41; function.
