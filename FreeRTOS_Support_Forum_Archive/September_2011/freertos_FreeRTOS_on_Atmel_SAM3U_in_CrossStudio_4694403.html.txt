  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">FreeRTOS on Atmel SAM3U in CrossStudio</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/dannyhaak">dannyhaak</a> on September 6, 2011</div><div class="thread-post-content">I try to get FreeRTOS running on a SAM3U&#40;-EK devkit&#41; in Rowley CrossStudio. While creating tasks goes fine, they do not seem to be executed.  
What I did:<br />
&#45; Generate a CrossStudio project for the SAM3U-EK devkit &#40;which includes Rowley start-up and configuration assembly files&#41;<br />
&#45; Include FreeRTOS .c and .h file &#8211; take the config file from the SAM3U example project for IAR<br />
&#45; Copy simple task from demo<br />
&#45; Include lowlevel&#42;.c/.h files from AT91LIB &#8211; including serveral drivers  
It compiles fine. but when I put a breakpoint inside the task, it never gets executed.  
My main.c:  
<pre><code>// general includes
#include &lt;stdbool.h&gt;
#include &lt;stdio.h&gt;
#include &lt;string.h&gt;
// includes for FreeRTOS
#include "FreeRTOS.h"
#include "task.h"
#include "queue.h"
#include "semphr.h"
int i;
void vATaskFunction( void *pvParameters );
int main()
{
  i = xTaskCreate( vATaskFunction, "test", 200, NULL, tskIDLE_PRIORITY, NULL );
  vTaskStartScheduler();
 for ( ;; );
}
void vATaskFunction( void *pvParameters )
{
  for( ;; )
  {
    int j = 0;
    i  = i +5;
    vTaskDelay(250 / portTICK_RATE_MS);
  }
}
</code></pre>
I guess something goes wrong with interrupts to execute ticks &#8211; but I&#8217;m lost where to fix this. Any help is really appreciated.
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS on Atmel SAM3U in CrossStudio</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on September 6, 2011</div><div class="thread-post-content">If you step through the call to vTaskStartScheduler&#40;&#41; you will find the answer to why the scheduler is not starting.  
My &#40;almost certain&#41; guess is that you have not populated the interrupt vector table with the interrupts required by FreeRTOS.&nbsp; That means, you will get to the call to the SVC assembler instruction in vPortStartFirstTask&#40;&#41; that is used to start the kernel, then just jump to the default SVC handler instead of the FreeRTOS SVC handler.  
If this is the case then, then install xPortSysTickHandler, vPortSVCHandler, xPortPendSVHandler and xPortSysTickHandler in the appropriate places in the vector table.&nbsp; Or, if the vector table is using CMSIS function names for the handlers, add the following lines to FreeRTOSConfig.h:  
&#35;define vPortSVCHandler SVC&#95;Handler<br />
&#35;define xPortPendSVHandler PendSV&#95;Handler<br />
&#35;define vPortSVCHandler SVC&#95;Handler<br />
&#35;define xPortSysTickHandler SysTick&#95;Handler  
regards.
