&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; vSemaphoreCreateBinary&#40; xSPI0Semaphore &#41;;
in running task I take semaphore:
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; xSemaphoreTake&#40; xSPI0Semaphore, portMAX&#95;DELAY &#41;;
WHAT IS WRONG:
Semaphore is taken in first call, without giving anywhere before. So first taking procedure is not blocking.
TRY:
I check semaphore before taking:
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; q = uxQueueMessagesWaiting&#40; xSPI0Semaphore &#41;;
and q value is &quot;1&quot;, but should be &quot;0&quot;.
Please help
</div></div><div class="thread-post"><h3 class="thread-post-title">Using semaphore problem</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/*anonymous">*anonymous</a> on May 13, 2009</div><div class="thread-post-content">This is the documented behaviour: binary semaphores are initially released. You might want to do a xSemaphoreTake&#40;xSPIOSemaphore, 0&#41; just after creating the semaphore if you want it to be taken before the scheduler starts &#40;the 0 doesn&#8217;t matter here, since you &#42;will&#42; get the semaphore immediately&#41;.
