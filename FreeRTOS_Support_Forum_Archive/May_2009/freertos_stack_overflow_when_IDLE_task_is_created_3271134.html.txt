  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">stack overflow when IDLE task is created</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/aviasaf">aviasaf</a> on May 12, 2009</div><div class="thread-post-content">Hello all,
I am working on the IAR workbench, with AT91sam7s256 processor.
I have ported the freertos to this processor based on the relevant docs.
I have a problem with the freertos IDLE task.
When the IDLE task is created by the freertos vTaskStartSchedulervTaskStartScheduler function, its stack and TCB is being allocated, the problem is that it&#8217;s run over other tasks that created before by the user.
Then I get &quot;stack overflow&quot; &#40;using freertos hook&#41; on tasks that really not doing anything.
Does any one have a clue what can be the problem?
thanks
</div></div><div class="thread-post"><h3 class="thread-post-title">stack overflow when IDLE task is created</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/aturowski">aturowski</a> on May 12, 2009</div><div class="thread-post-content">First I would check if there is enough space in your heap memory, which is used for allocation for stacks for all tasks.
I suspect also that one of your task stack size might be set too small and it overruns idle task stack.
Regards,
Adam
</div></div><div class="thread-post"><h3 class="thread-post-title">stack overflow when IDLE task is created</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/aviasaf">aviasaf</a> on May 12, 2009</div><div class="thread-post-content">hi
I saw that when the the IDLE stack is created its overrun others tasks.
I get overflow because the TCB of other tasks is overrun &#40;by the IDLE task&#41; and therefore the overflow-check function of freertos recognize it as stack overflow.
i don&#8217;t think that the problem is because of small stack of other tasks.&nbsp;&nbsp; 
</div></div><div class="thread-post"><h3 class="thread-post-title">stack overflow when IDLE task is created</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/aturowski">aturowski</a> on May 12, 2009</div><div class="thread-post-content">Idle task is created the same way as the other tasks are. First the memory for TCB and task stack is allocated on heap. Maybe there is a problem if allocate function returns wrong pointer. Please have a check if prvAllocateTCBAndStack function call in xTaskCreate works fine.
What heap implementation are you using?
</div></div><div class="thread-post"><h3 class="thread-post-title">stack overflow when IDLE task is created</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/aviasaf">aviasaf</a> on May 12, 2009</div><div class="thread-post-content">hi
i am using heap&#95;2 implementation, I think the allocation works fine, I have set breakpoint if the allocation has failed &#40;memory limitation&#41; 
I have got only 2 more tasks which allocation less then 0.5K ram.
how can I check if the address return from the allocation function is valid &#40;alignment problems???&#41; 
thanks
</div></div><div class="thread-post"><h3 class="thread-post-title">stack overflow when IDLE task is created</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/aviasaf">aviasaf</a> on May 12, 2009</div><div class="thread-post-content">sorry, i am using heap&#95;3
</div></div><div class="thread-post"><h3 class="thread-post-title">stack overflow when IDLE task is created</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/aturowski">aturowski</a> on May 12, 2009</div><div class="thread-post-content">xTaskCreate calls prvAllocateTCBAndStack function and this returns the pointer to allocated memory. Suggest set the breakpoint there and check if pointers returned during TCB/stack allocation have values as expected.
P.S. A basic point. Almost all FreeRTOS features &#40;queue/mutexes/semaphores etc.&#41; use heap to allocate needed memory. I assume that you have commented out all of them and still there is an issue. If you haven&#8217;t I suggest to have a look in pvPortMalloc function which will be used for all this allocation &#8211; please check if pointer returned doesn&#8217;t show any unexpected behaviour.
</div></div><div class="thread-post"><h3 class="thread-post-title">stack overflow when IDLE task is created</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/aturowski">aturowski</a> on May 12, 2009</div><div class="thread-post-content">xTaskCreate calls prvAllocateTCBAndStack function and this returns the pointer to allocated memory. Probably linker script is the cause.
