  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">vTaskDelay() in non-preemptive port</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/tzuchien_chiu">tzuchien_chiu</a> on August 29, 2006</div><div class="thread-post-content">Hello, everyone:
I have a non-preemptive port and I need a vTaskDelay. Using tick ISR is not an option &#40;as it&#8217;s a non-preemptive one&#41;, and I&#8217;m looking for an approximate solution.
The best one I come up with so far is inserting as many taskYIELD&#40;&#41; as possbile, and having the port of portYIELD&#40;&#41;:
&lt;pre&gt;
&#35;define taskYIELD portYEILD
&#35;define portYIELD do &#123; 
&nbsp;&nbsp;&nbsp; vTaskIncrementTick&#40;&#41;; 
&nbsp;&nbsp;&nbsp; here are same assembly to 
&nbsp;&nbsp;&nbsp; switch context, and call
&nbsp;&nbsp;&nbsp; vTaskSwitchContext&#40;&#41;
&nbsp;&nbsp;&nbsp; &#125; while &#40;0&#41;
&lt;/pre&gt;
The call to vTaskIncrementTick&#40;&#41; is required because it moves the tasks in the delayed list to ready list. Without it, the task calling vTaskDelay&#40;&#41; will be suspend forever.
Is there better solution?
&nbsp;&nbsp;&nbsp; 
&nbsp;&nbsp;&nbsp; 
</div></div><div class="thread-post"><h3 class="thread-post-title">vTaskDelay() in non-preemptive port</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on August 29, 2006</div><div class="thread-post-content">You cannot increment the tick each time yield is called.&nbsp; This will loose all track of time.
Why cannot you use task delay in cooperative mode?&nbsp; The tick interrupt will increment the time, wake any unblocked tasks BUT WILL NOT switch context until another task calles yield or blocks.
</div></div><div class="thread-post"><h3 class="thread-post-title">vTaskDelay() in non-preemptive port</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/tzuchien_chiu">tzuchien_chiu</a> on August 29, 2006</div><div class="thread-post-content">Thanks for reminding me the lose of time track.
Unfortunately, using tick interrupt is not an 
option because of buggy hardware implementation.
</div></div><div class="thread-post"><h3 class="thread-post-title">vTaskDelay() in non-preemptive port</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/adarkar9">adarkar9</a> on August 29, 2006</div><div class="thread-post-content">I get the impression that you are trying to use vTaskDelay&#40;&#41; incorrectly.
If you just want to switch between multiple tasks, you can use taskYIELD&#40;&#41; like you mentioned in your previous thread.&nbsp; However, the tasks must be at the same priority.&nbsp; Your problem with starving Task 1 was due to the fact that Task 2 was at a higher priority.
You will probably run into the same problem if you use vTaskDelay&#40;&#41; and then call vTaskIncrementTick&#40;&#41; within taskYIELD&#40;&#41;.
In other words, if you are running in cooperative mode and you are not tracking time and you want to switch between multiple tasks, you can make the priority of the tasks the same and use taskYIELD&#40;&#41;.
</div></div><div class="thread-post"><h3 class="thread-post-title">vTaskDelay() in non-preemptive port</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/tzuchien_chiu">tzuchien_chiu</a> on August 30, 2006</div><div class="thread-post-content">I have several tasks, and one of them does &#42;audio-video synchronization&#42; and needs trigger the hardware after a &#42;cacluated delay&#42; time &#40;the parameter to vTaskDelay&#41;. It cannot just spin for the specified time, because the processor time will be wasted, and our application cannot afford it. 
/&#42; spin without yield &#42;/
int begin = tick&#40;&#41;;
while &#40;1&#41; &#123;
&nbsp; if &#40;tick&#40;&#41; &#8211; begin &gt; DELAY&#41; break;
&#125; 
I know that in the cooperative mode the delay couldn&#8217;t be accurate, so I am just look for an approximated solution.
</div></div><div class="thread-post"><h3 class="thread-post-title">vTaskDelay() in non-preemptive port</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/adarkar9">adarkar9</a> on August 30, 2006</div><div class="thread-post-content">A design assumption made in the FreeRTOS code is that a timer with an interrupt is available for keeping track of time.&nbsp; You are attempting to run FreeRTOS without this.&nbsp; I think you may still be able to get what you need, but it requires some creativity.
This is an &quot;approximate&quot; solution that does have some potential holes.
I assume your &quot;buggy hardware implementation&quot; at least provides you with a timer that you can poll.&nbsp; You can add a poll of the timer in the idle task and call vTaskIncrementTick&#40;&#41; when the timer fires.&nbsp; This will work as long as the idle task gets sufficient execution time.&nbsp; You will miss ticks &#40;causing your delays to increase&#41; if the idle task is starved.
