</div></div><div class="thread-post"><h3 class="thread-post-title">portENTER_critical</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on August 24, 2006</div><div class="thread-post-content">Different ports use two methods for entering and exiting critical sections.
The first pushes the interrupt status onto the stack, then disables interrupts to enter, and simply pops the status off the stack to exit.&nbsp; It sounds like this is what your port is doing.&nbsp; This will only work if you have the compiler options set in a particular way.&nbsp; Otherwise, if you are using stack frame based addressing, changing the stack will cause the sort of problem you are seeing.
The way around this is to use the other method, which defines functions to enter and exit critical sections rather than modifying the stack.&nbsp; This is less efficient but guaranteed to work with all compiler options.
Take a look at some of the ARM ports to see what to do.&nbsp; Basically:
Define a variable in port.c, say ucCriticalNesting, and initialise it to a high value, say 0xf0.
Redefine portENTER&#95;CRITICAL and portEXIT&#95;CRITICAL &#40;in portmacro.h&#41; to call functions vPortEnterCritical&#40;&#41; and vPortExitCritical&#40;&#41;.&nbsp; These functions take the following form:
void vPortEnterCritical&#40; void &#41;
&#123;
&nbsp;&nbsp;&nbsp; portDISABLE&#95;INTERRUPTS&#40;&#41;;
&nbsp;&nbsp;&nbsp; ucCriticalNesting++;
&#125;
void vPortExitCritical&#40; void &#41;
&#123;
&nbsp;&nbsp;&nbsp; ucCriticalNesting&#8211;;
&nbsp;&nbsp;&nbsp; if&#40; ucCriticalNesting == 0 &#41;
&nbsp;&nbsp;&nbsp; &#123;
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; portENABLE&#95;INTERRUPTS&#40;&#41;;
&nbsp;&nbsp;&nbsp; &#125;
&#125;
This is the easy part.&nbsp; Then you have to save and restore the variable ucCriticalNesting on the stack of each task:
In pxPortInitialiseStack&#40;&#41; add another byte to the initial stack setup for the task.&nbsp; Set this byte to 0 so the task does not start within a critical section.
In portSAVE&#95;CONTEXT save the value of ucCriticalNesting in the same location on the stack.
In portRESTORE&#95;CONTEXT restore the value from the stack into ucCriticalNesting.
This is an overview.&nbsp; For details I suggest you look at one of the ARM IAR ports and just copy that.&nbsp; I think the variable is called uxCriticalNesting or ulCriticalNesting in that port.

</div></div><div class="thread-post"><h3 class="thread-post-title">portENTER_critical</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/ilgitano">ilgitano</a> on May 18, 2014</div><div class="thread-post-content">I know this is stale, and the issue seems to be widely known, but I&#8217;d like to highlight that the counter method proposed unconditionally enables interrupts when the outermost critical section is left. This makes it unuseable in interrupts or any function which might be used in an interrupt. I spent a weekend working this out when we tried to port to using FreeRTOS critical sections. It is pretty easy to fix though.
I&#8217;ve attached my alternative which can be used with interrupt code and ordinary code. This is coded for an MSP430F5438A on an IAR SBW development system. It&#8217;s tested and works. It also has the advantage of working independantly of FreeRTOS, so can be used before starting the task scheduler. The disadvantage is that for portable code, a generic means to test the current interrupt state would be needed; I think it would be worth doing though.
<pre><code>#define portENTER_CRITICAL()                                                            
{                                                                                       
extern volatile unsigned short usCriticalNesting;                                       
    if (__get_SR_register() &amp; __SR_GIE)                                                 
    {                                                                                   
        __disable_interrupt();                                                          
        /* If interrupts are set, start at zero. We then know to reenable interrupts */ 
        /* when the count returns to zero. If interrupts are disabled, we have no    */ 
        /* way of knowing if this is a first call, or a nested call. just increment. */ 
        usCriticalNesting = 0;                                                          
    }                                                                                   
    usCriticalNesting++;                                                                
}                                                                                       
#define portEXIT_CRITICAL()                                                             
{                                                                                       
extern volatile unsigned short usCriticalNesting;                                       
    usCriticalNesting--;                                                                
    if (usCriticalNesting == 0)                                                         
    {                                                                                   
        /* About to leave the outermost critical section; the next critical section  */ 
        /* started might be with interrupts enabled or might not, so set to 1.       */ 
        usCriticalNesting = 1;                                                          
        __enable_interrupt();                                                           
    }                                                                                   
}                                                                                       
</code></pre>
