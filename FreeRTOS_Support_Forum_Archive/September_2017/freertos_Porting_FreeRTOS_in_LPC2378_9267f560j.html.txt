</div></div><div class="thread-post"><h3 class="thread-post-title">Porting FreeRTOS in LPC2378</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on September 6, 2017</div><div class="thread-post-content"><blockquote>
  i have 
  downloaded the recently relesed version of FreeRTOS only, as i 
  mentioned. then, How come it will be an old port file. 
</blockquote>
Because the chip was designed a long time ago, and the FreeRTOS port was 
provided when the chip was designed.  There has not been any ARMv4 
development in FreeRTOS for years (the core used in the LPC23xx), with 
most development being for the ARMv7 (the core used in the Cortex-M 
parts), and now moving onto ARMv8 (the core used in the Cortex-2/3x 
parts).  I cannot foresee a time when such an old port would be updated.

Why not?  If this is important to you, as you say it is, investing i the

  portRESTORE_CONTEXT macro definition in portmacro.h file halts the 
  application.
</blockquote>
Which execution of the macro?  The first one?  If so, it <em>might</em> be that 
the CPU is not in the right mode when you call vPortStartScheduler(). 
It has to be in System mode, the easiest method of ensuring being to 
ensure the start up code calls main() from System mode.
