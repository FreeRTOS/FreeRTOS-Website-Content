What is the recommended way to initialize interrupts? Should I use the built in Xilinx drivers (SCUGIC), or are there FreeRTOS functions I should call to setup interrupts / handler functions?

So how should I setup interrupts?
Any thoughts appreciated.

</div></div><div class="thread-post"><h3 class="thread-post-title">interrupts (Zynq)</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on September 12, 2017</div><div class="thread-post-content">It has been a bit since I worked on the Zynq, but as I remember, I changed the FreeRTOS_SetupTickInterrrupt()) function to check if the interrupt controller was already initialized, and use the already setup one if it has been. I did use the low level BSP routines to set up the interrupts.
Just because a chip manufacture provides a Port Layer, doesn&#8217;t mean it was done well.
Because their routine initializes the control while setting up the tick, which happens in the call to start the FreeRTOS Scheduler, any interrupts setup previously are forgotten, so you need to configure your interrupts after the interrupts system is enabled, which in my mind is too late.

</div></div><div class="thread-post"><h3 class="thread-post-title">interrupts (Zynq)</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/eve-shadow">eve-shadow</a> on September 13, 2017</div><div class="thread-post-content">For the benefit of anyone else running into this problem:
In the Xilinx FreeRTOS (9.0.1) BSP, there is a file portZynq7000.c. This file contains a global definition of the interrupt controller
XScuGic xInterruptController;
I was able to get interrupts working by declaring in my code:
extern XScuGic xInterruptController;
You need to initialize it using the usual XScuGic<em>CfgInitialize and then you can connect your interrupt handlers with XScuGic</em>Connect &amp; XScuGic_Enable before vTaskStartScheduler().
