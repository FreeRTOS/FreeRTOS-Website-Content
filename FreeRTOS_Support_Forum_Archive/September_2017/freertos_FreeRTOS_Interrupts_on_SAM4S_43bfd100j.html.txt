</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS: Interrupts on SAM4S</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on September 18, 2017</div><div class="thread-post-content">Cortex-M3 devices always use the /source/[compiler]/ARM_CM3 port.
Cortex-M4 devices that do NOT have an MPU use the same port layer as 
Cortex-M3 devices.
Cortex-M4 devices that DO have an MPU use the 
/source/[compiler]/ARM_CM4F port layer.
Cortex-M7 devices that have an r0p1 core use the 
/source/[compiler]/ARM_CM7/r0p1 port layer.
All other Cortex-M7 devices use the same port layer as Cortex-M4 FPU 
devices.
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS: Interrupts on SAM4S</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on September 18, 2017</div><div class="thread-post-content">What happens if you take the call to print_str() out of the ISR? 
Printing in interrupts is normally a really bad idea, unless you are 
100% sure of the print() functions implementation (the print function 
must use a very tiny stack, be thread safe, not mess with interrupts, etc.).

I need to set a priority fo the interrupt. So I&#8217;ve added one line:
~~~
            //Interrupt konfigurieren
            pio<em>handler</em>set(PIOA, ID<em>PIOA, PIO</em>PA2, PIO<em>IT</em>FALL<em>EDGE, pin</em>edge<em>handler);

But I don&#8217;t understand why only priority values between 170 and 255 work. In my FreeRTOS config file:
~~~
/* The lowest interrupt priority that can be used in a call to a &#8220;set priority&#8221;
function. */
<h1>define configLIBRARY<em>LOWEST</em>INTERRUPT_PRIORITY         0x0f</h1>
/* The highest interrupt priority that can be used by any interrupt service
routine that makes calls to interrupt safe FreeRTOS API functions.  DO NOT CALL
INTERRUPT SAFE FREERTOS API FUNCTIONS FROM ANY INTERRUPT THAT HAS A HIGHER
PRIORITY THAN THIS! (higher priorities are lower numeric values. */
<h1>define configLIBRARY<em>MAX</em>SYSCALL<em>INTERRUPT</em>PRIORITY    10</h1>
/* Interrupt priorities used by the kernel port layer itself.  These are generic
to all Cortex-M ports, and do not rely on any particular library functions. */
<h1>define configKERNEL<em>INTERRUPT</em>PRIORITY         ( configLIBRARY<em>LOWEST</em>INTERRUPT<em>PRIORITY &lt;&lt; (8 &#8211; configPRIO</em>BITS) )</h1>
/* !!!! configMAX<em>SYSCALL</em>INTERRUPT_PRIORITY must not be set to zero !!!!
See http://www.FreeRTOS.org/RTOS-Cortex-M3-M4.html. */
<h1>define configMAX<em>SYSCALL</em>INTERRUPT<em>PRIORITY    ( configLIBRARY</em>MAX<em>SYSCALL</em>INTERRUPT<em>PRIORITY &lt;&lt; (8 &#8211; configPRIO</em>BITS) )</h1>
~~~
configPRIO_BITS is 4
Shifted with 0:
10&lt;&lt;4 = 10100000 = 160
0x0f&lt;&lt;4 = 11110000 = 240
Shifted with 1:
10&lt;&lt;4 = 10101111 = 175
0x0f&lt;&lt;4 = 11111111 = 255
In my opinion, 175 should be the limit and not 170.
