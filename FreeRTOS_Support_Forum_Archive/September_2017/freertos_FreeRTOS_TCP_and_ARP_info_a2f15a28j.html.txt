  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">FreeRTOS + TCP and ARP info</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/dsherman26">dsherman26</a> on September 8, 2017</div><div class="thread-post-content">I&#8217;ve been working on getting FreeRTOS + TCP working on a Freescale Kinetis K60 tower board.  I have DHCP working and I can get an IP address from a DSL modem I&#8217;m using as the DHCP host (COMTREND CT-5374).  I can see the tower boards DHCP address in the router&#8217;s DHCP table, but the ARP table does not show the tower board.  Is there some step I need to do to make the router aware of it?  I can&#8217;t ping it because the router reports that it is unaware of the IP address.
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS + TCP and ARP info</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on September 10, 2017</div><div class="thread-post-content">Hi Dave, it is difficult to see from a distance why you can not ping your device.
In my own testing environment, I have devices behind a router with WAN/LAN, as well as behind a LAN switch.
If you have a switch, I would try that first: either with a fixed IP-address, or by running a DHCP server on your laptop.
Have you also tried without DHCP?
<pre><code>#define ipconfigUSE_DHCP    0
</code></pre>
Can you confirm that your laptop and your &#8220;tower board&#8221; have the same network address?  For instance <code>192.168.1.10</code> and <code>192.168.1.11</code> ?
It would be very strange if a router does not pass ARP messages between the LAN ports ( &#8220;ETH1&#8221; to &#8220;ETH4&#8221; ).  Also the device will send-out so-called gratuitous ARP messages every 20 seconds:
<pre><code>#define arpGRATUITOUS_ARP_PERIOD       ( pdMS_TO_TICKS( 20000 ) )
</code></pre>
These packet help detecting IP-address conflicts.  A switch or a LAN router must forward these packets as well and you should see them when running WireShark.
I would also check the properties of &#8220;ETH1&#8221; to &#8220;ETH4&#8221; in the router&#8217;s setup-page.  Does the router allow communication between those ports?
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS + TCP and ARP info</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/dsherman26">dsherman26</a> on November 2, 2017</div><div class="thread-post-content">Thank you, sorry for the delay getting back.  I figured out it was because the stack was replying to the arp request at the beginning of the ping, and sending the arp information back.  The hardware was configured to add the checksum, but I had to make sure the checksum was zeroed before replying, otherwise the hardware would get the checksum wrong.  The arp table I&#8217;m not sure of, the router still does not show it, although I can ping it now.
