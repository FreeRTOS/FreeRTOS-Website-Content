</div></div><div class="thread-post"><h3 class="thread-post-title">dsPIC interrupt &#038; queue</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on November 17, 2007</div><div class="thread-post-content">I cannot see anything that is obviously wrong, on the assumption that cStringBuffer&#91;&#93; is large enough.&nbsp; It could be a stack overflow within the task.&nbsp; Can you try removing the call to sprintf&#40;&#41; because when using GCC this is likely to use a LOT of stack.&nbsp; Maybe just set cStringBuffer to a const string to make sure it contains something valid &#40; strcpy&#40; cStringBuffer, &quot;test&quot; &#41; &#41;.&nbsp; I know this removes the functionality of seeing the values but will be a good test.
You could try making the task stack bigger too, and ensuring there are no large variables on the stack &#40;is cStringBuffer on the stack&#41;.&nbsp; 
Any of these things making a difference would indicate a stack issue.
