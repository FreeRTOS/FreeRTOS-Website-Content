</div></div><div class="thread-post"><h3 class="thread-post-title">time and gettimeofday</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on December 1, 2010</div><div class="thread-post-content">gettimeofday&#40;&#41; can only be implemented if the hardware supplies a time of day clock. Desktop computers have a time of day clock, but very few small embedded systems do. It is not possible to implement gettimeofday&#40;&#41; in FreeRTOS because nearly all &#40;all?&#41; the hardware used for demonstrations have no way of maintaining time. If you embedded hardware has a time of day clock then the function could be implemented in the port layer, but not as part of the core FreeRTOS code.  
If you want a time in hours minutes and seconds since the system booted then this can be obtained easily enough from the tick count. If you want a time to be maintained across boots, or relative to a particular year, then I think you are out of luck &#40;unless your hardware provides this facility&#41;.
</div></div><div class="thread-post"><h3 class="thread-post-title">time and gettimeofday</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on December 1, 2010</div><div class="thread-post-content">f4zzy, the issue is that FreeRTOS is just a kernel, not a full blown OS, and as such provides only the basic task management routines, but no I/O or similar support functions. As Dave said, true time functions require hardware support &#40;or if your device is network connected, you might be able to fake it using NTP&#41;. The Posix spec calls for many things that FreeRTOS doesn&#8217;t include, but my guess is that you have probably include other packages &#40;like a TCP/IP package adapted to work with FreeRTOS&#41; to supply those needs. As a point of reference, files under the &#8220;Demo&#8221; directory aren&#8217;t really pieces of the base FreeRTOS kernel, but sample applications showing how to use it on various hardware.
</div></div><div class="thread-post"><h3 class="thread-post-title">time and gettimeofday</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/f4zzy">f4zzy</a> on December 1, 2010</div><div class="thread-post-content">yes of course i can&#8217;t have the same gettimeofday&#40;&#41; as the posix systems.<br />
I believe that just&nbsp; the tick count could be good for my purpose. Can you confirm that is xTickCount variable in task.c?<br />
If so, i have to think about a solution on my code when xTickCount overflows…<br />
Thanks a lot
</div></div><div class="thread-post"><h3 class="thread-post-title">time and gettimeofday</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on December 1, 2010</div><div class="thread-post-content">xTickCount is the variable that holds the number of ticks that have passed. The &#8216;proper&#8217; way to get that value is calling xTaskGetTickCount&#40;&#41;  
There is also a variable xNumOfOverflows which counts the number of times xTickCount has overflowed. There isn&#8217;t a function provided to get that value, but it wouldn&#8217;t be hard to add it. Maybe even make one to return the two values concatenated into a single large variable. &#40;If you write that, make sure you guard the access to the two variable with a critical section&#41;.
