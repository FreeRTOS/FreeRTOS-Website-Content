  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">PIC32 interrupt declaration</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/pya49">pya49</a> on December 24, 2010</div><div class="thread-post-content">I don&#8217;t understand interrupt declaration in FreeRtos.<br />
In the Pic32 demo for example :<br />
interupt prototype handler is declare with ipl set to 1 :<br />
void &#95;&#95;attribute&#95;&#95;&#40; &#40;interrupt&#40;ipl1&#41;, vector&#40;&#95;UART2&#95;VECTOR&#41;&#41;&#41; vU2InterruptWrapper&#40; void &#41;;<br />
But Uart2 interrupt priority is set to 2&nbsp; &#40;as configKERNEL&#95;INTERRUPT&#95;PRIORITY is set to 1&#41; :<br />
ConfigIntUART2&#40; &#40; configKERNEL&#95;INTERRUPT&#95;PRIORITY + 1 &#41; | UART&#95;INT&#95;SUB&#95;PR0 | UART&#95;TX&#95;INT&#95;EN | UART&#95;RX&#95;INT&#95;EN &#41;;  
So, what is the good setting ?  
Thanks for your help.
</div></div><div class="thread-post"><h3 class="thread-post-title">PIC32 interrupt declaration</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on December 24, 2010</div><div class="thread-post-content">I think this is really a question for Microchip as they provide both the compiler and the library &#8211; and both seem to provide a way of setting the priority.&nbsp; I asked the question when writing the port too.  
I think the &#95;&#95;attribute&#95;&#95; set priority level must only be used when you are not making library calls.&nbsp;   
In this case, as far as I know/recall, the priority passed to the ConfigIntUART2&#40;&#41; library function will be the one used at run time.
