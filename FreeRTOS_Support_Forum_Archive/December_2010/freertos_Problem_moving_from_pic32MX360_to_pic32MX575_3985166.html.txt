  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Problem moving from pic32MX360 to pic32MX575</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/steveb75">steveb75</a> on December 4, 2010</div><div class="thread-post-content">Hi All.  
Have put together several tasks, some tasks using UART/DMA/Interrupts and is running fine using the pic32 starter kit with pic32MX360F512L.  
Having problems trying to run the exact same code using pickit-3 with pic32MX575F512L.&nbsp; The &#95;general&#95;exception&#95;handler<br />
is called regardless of what I try.&nbsp; For example I have removed all tasks but 1 and the task is simplified to just spin in a loop.&nbsp; When starting the code, after a few seconds I hit a breakpoint set in the &#95;general&#95;exception&#95;handler.  
If removing all tasks, Queues, Sem declarations/definitons and just calling prvSetupHardware&#40;&#41; to init clocks, disable interrupts etc, followed by vTaskStartScheduler&#40;&#41;, same thing happens.  
If I remove vTaskStartScheduler&#40;&#41; and just spin in a loop e.g while &#40;TRUE&#41; &#123; i++; &#125;, it seems happy i.e. don&#8217;t hit the breakpoint in &#95;general&#95;exception&#95;handler&#40;&#41;.&nbsp; Note this all in main&#40;&#41; and the correct device is selected under the IDEs Configure-&gt;Select Device tab…  
I have looked at the exception codes but can&#8217;t determine anything from it:-<br />
Status&nbsp; = 0x103<br />
Cause = 0x8080041C<br />
According to the M4K software user guide, the exception code &#40;41C =&gt; 28 based on the bit mapping&#41; is a reserved value….  
A friend who is also using the same pickit-3/pic32MX575F512L setup is running similar/standalone code &#40;i.e. without freeRTOS&#41; and has no problems.  
One other observation is during initial debugging I noticed the time to step over code/functions seemed very slow when compared to using the pic starter kit/pic32MX360F512L.&nbsp; Not sure if this is just normal behaviour of the pickit-3 but I would expect the hardware config to be the same for both platforms along with the response/speed.  
Any help/advice would greatly appreciated.  
Regards,<br />
Steve
</div></div><div class="thread-post"><h3 class="thread-post-title">Problem moving from pic32MX360 to pic32MX575</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/steveb75">steveb75</a> on December 4, 2010</div><div class="thread-post-content">Correction to above:  
The exception code is 0x1C not 0x41C and equates to 7 not 28.  
Exception type is DBE: Bus error exception &#40;data reference: load or store&#41;
</div></div><div class="thread-post"><h3 class="thread-post-title">Problem moving from pic32MX360 to pic32MX575</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on December 4, 2010</div><div class="thread-post-content">I don&#8217;t know if this is the solution to your problem, but is something to check. It has tripped people before.  
The newer PIC32 devices need different pragma definitions &#40;fuse bit settings maybe, from memory of older PICs?&#41;. If you look at the pragmas at the top of main.c for the demo in FreeRTOSDemoPIC32MX&#95;MPLAB of the official download you will see this  
&#35;pragma config FPLLMUL = MUL&#95;20, FPLLIDIV = DIV&#95;2, FPLLODIV = DIV&#95;1, FWDTEN = OFF<br />
&#35;pragma config POSCMOD = HS, FNOSC = PRIPLL, FPBDIV = DIV&#95;2  
In the book examples, which use a different and newer PIC32 device, you will see this  
&#35;pragma config FPLLODIV = DIV&#95;1, FPLLMUL = MUL&#95;20, FPLLIDIV = DIV&#95;2<br />
&#35;pragma config FWDTEN = OFF, FPBDIV = DIV&#95;2, POSCMOD = XT, FNOSC = PRIPLL, CP = OFF<br />
&#35;pragma config FSRSSEL = PRIORITY&#95;7  
The FSRSSEL setting does not exist in the early PIC32 chips, but is essential in the newer ones.
