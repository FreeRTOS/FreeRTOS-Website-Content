</div></div><div class="thread-post"><h3 class="thread-post-title">trace Hook Macros</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on December 20, 2010</div><div class="thread-post-content">I have actually just written two new sections to the FreeRTOS tutorial book, one of which is specifically on the trace hook macros .  
The best place to define hook macros, such as traceTASK&#95;SWITCHED&#95;OUT&#40;&#41;, is in FreeRTOSConfig.h.&nbsp; That way the order in which macros are defined is guaranteed to be correct.&nbsp; If you are going to write complex macros then you can put them in their own header file, and include that header file from FreeRTOSConfig.h.  
The task hook function is only really required if you want each task to execute a different function.&nbsp; If ever task is to execute the same function you can call the function directly from your definition fo traceTASK&#95;SWITCHED&#95;OUT&#40;&#41;.  
See the following page for more examples &#40;if you have not done so already&#41;:<br />
<a href="http://www.freertos.org/rtos-trace-macros.html">http://www.freertos.org/rtos-trace-macros.html</a>

</div></div><div class="thread-post"><h3 class="thread-post-title">trace Hook Macros</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on August 19, 2012</div><div class="thread-post-content">pxCurrentTCB can be used in main by externing it &#8220;extern void &#42;pxCurrentTCB&#8221;, but it won&#8217;t do you much good because the &#40;deliberate&#41; data hiding policy used in FreeRTOS will note expose the structure members to you.&nbsp; If you define a macro that uses pxCurrentTCB, and that macro is defined in FreeRTOSConfig.h but called in tasks.c, then you can access the structure members because the code is in effect inlined in tasks.c &#40;which contains the full TCB structure definition&#41;.
