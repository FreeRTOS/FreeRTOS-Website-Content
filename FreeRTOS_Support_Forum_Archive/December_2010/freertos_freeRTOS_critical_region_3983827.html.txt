  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">freeRTOS critical region</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nishant13">nishant13</a> on December 3, 2010</div><div class="thread-post-content">Hi guys,  
I was able to successfully implement other software interrupts on the code, though I have not fully tested it. Now the other thing I am looking forward to implement is to remove disabling of interrupts. Usually with every call to the OS functions there is entering of critical region which disables the interrupt.  
Now what I need to confirm is<br />
<strong>Is the interrupts disabled to prevent the timer interrupt from doing any context switch?? Can other interrupts be allowed to be processed by just disabling the timer interrupt in the critical region. What are the reasons for disabling the interrupts??</strong>  
I ask this question because with ARM there is a semaphore instruction and if possible I am thinking of implementing it to prevent shared data problem in case of context switches and other OS function calls.  
Thanks and regards,<br />
Nishant Agrawal
</div></div><div class="thread-post"><h3 class="thread-post-title">freeRTOS critical region</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on December 3, 2010</div><div class="thread-post-content">I think the reasons for disabling interrupts should be obvious. Critical sections protect code segments from access by ANY interrupt, not just the FreeRTOS interrupts. Any interrupt that calls an API function would have to be disabled.  
If you are using an ARM Cortex M3 then the port allows interrupts to nest and has critical section calls that only disable interrupts to a certain priority level. It even has alternative critical section implementations that can be used in interrupts themselves. This should not be a problem for you then.  
If you are using an ARM7 then an interrupt nesting implementation is possible but stupidly clumsy, which I guess why its not implemented in the release code.
