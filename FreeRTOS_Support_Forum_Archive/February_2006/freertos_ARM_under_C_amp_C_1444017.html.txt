</div></div><div class="thread-post"><h3 class="thread-post-title">ARM under C &#038; C++</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on February 19, 2006</div><div class="thread-post-content">While it may not be asm related it still sounds like the same problem.&nbsp; Are you compiling some files as c++ and some as c?&nbsp; If so they will not link.&nbsp; You need to compile it all as c++ &#40;in which case I&#8217;m not sure it will work&#41; or declare the c code as extern &quot;c&quot; &#40;in which case it may work depending on what you are doing with the c++ code&#41;.
If you are not sure what this answer means then I suggest reading up a bit on mixing c and c++.
</div></div><div class="thread-post"><h3 class="thread-post-title">ARM under C &#038; C++</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/jra01">jra01</a> on February 20, 2006</div><div class="thread-post-content">Maybe the problem is that the compiler doesn&#8217;t see the extern &quot;C&quot; when compiling the OS, but when it compiles the c++ code. Therefore the C++ expects unmangled names, but the OS functions are mangled. Look in your link listing if you can find mangled versions of the OS functions &#40;in case you get a listing even with failed links&#41;.
Jokke
