  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">trouble in Demo/CodeWarrior_HCS12_banked</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/imajeff">imajeff</a> on February 17, 2006</div><div class="thread-post-content">Did the CodeWarrior/HCS12 Demo ever work? I don&#8217;t see how possible.
I have been using experimental ports for GCC/HCS12 for my own stuff, and now I&#8217;m getting serious about finishing the full Demo &quot;HCS12&#95;GCC&#95;banked&quot;. It is derived from the official &quot;HCS12&#95;CodeWarrior&#95;banked&quot;.
It was hard getting started with a normal debuger, but I&#8217;ve finally found the first problem why my demo is crashing when I vAltStartComTestTasks. In &quot;Demo/Common/comtest.c&quot; the demos use this global:
static xComPortHandle xPort = NULL;
The problem seems to be that xSerialPortInitMinimal&#40;&#41; returns NULL, and even if it did return the xComPortHandle as was probably intended, the global xPort is never initialized&#33; Somebody please let me know if you have got this demo to work in CodeWarrior.
I don&#8217;t have a CW setup, but I am going to try to resolve the bug to get my GCC/HCS12 demo working. I&#8217;ll drop a line when it works.
Using:
FreeRTOS V3.2.3
gcc version 3.0.4 m68hc1x-20030430 &#40;that is m68hc1x patch release 3.0.1&#41;
</div></div><div class="thread-post"><h3 class="thread-post-title">trouble in Demo/CodeWarrior_HCS12_banked</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on February 17, 2006</div><div class="thread-post-content">The demo serial port driver only supports one port.&nbsp; The API is generic &#40;used on all the ports&#41; so the port number is passed in and out of the API functions but NEVER used &#8211; the COM port used is hard coded and created/initialised using the &#8216;processor expert&#8217; addon to CodeWarrior not directly in the code.&nbsp; 
Therefore it is not intended that it gets used, and does not matter that it is not initialised.&nbsp; It is only there as something has to be passed into the function.
</div></div><div class="thread-post"><h3 class="thread-post-title">trouble in Demo/CodeWarrior_HCS12_banked</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/imajeff">imajeff</a> on February 18, 2006</div><div class="thread-post-content">Hello Mr. Nobody, thanks for responding to my probably-mistaken question.
I know it only supports one port, I couldn&#8217;t miss that when I&#8217;m this deep into development ;&#41;
but are you trying to imply &#40;without saying&#41; that you have actually seen the code work? It&#8217;s just hard to follow when I know it&#8217;s not working.
Don&#8217;t worry, I&#8217;ll probably catch what I missed about xPort not being used, after I sleep a little. It&#8217;s funny. I have a full application working which uses both serial ports on the MCU. That was one of the very things&#8230; I rewrote some stuff including using the xComPortHandle because I had to keep track. I probably knew back then how this demo really worked.
At least I&#8217;ve got that full app working. A transmitter sends wireless data and the FreeRTOS app reads it from one serial port, processes control code, and sends motor control to the second serial port to drive all the motors. It&#8217;s cool, but I just haven&#8217;t gotten my stupid Demo to work which doesn&#8217;t have to do anything useful. Strange, huh?
</div></div><div class="thread-post"><h3 class="thread-post-title">trouble in Demo/CodeWarrior_HCS12_banked</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on February 18, 2006</div><div class="thread-post-content">The demo applications are left on soak test for a week or so before they make it into the download, so yes, it has run before.&nbsp; It was built with Codewarrior tools, not GCC.
Sound like you have a nice application running which is more complex than the demo, which may be a clue.
The demo applications normally squeeze in as much as possible into the given ROM and RAM.&nbsp; Could it be that GCC is using more stack and therefore this is causing problems?
</div></div><div class="thread-post"><h3 class="thread-post-title">trouble in Demo/CodeWarrior_HCS12_banked</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/imajeff">imajeff</a> on February 20, 2006</div><div class="thread-post-content">&#45;- Richard said &#8212;
&quot;Sound like you have a nice application running which is more complex than the demo, which may be a clue.&quot;
Precisely why I was wrong :-/&nbsp; My application had required that handle to be used because it uses two COM ports. So the clues are throwing me off.
Stack seems likely, although I added 16 to the minimum and that didn&#8217;t solve it. I&#8217;ll try something huge if I still have the ram, but the problem might also be some small thing I added when taking out some CW stuff. That extra CW overhead sure looks big and silly when you see it outside of Processor Expert, in a simple example.
Thanks, I&#8217;ll post when I solve this.
</div></div><div class="thread-post"><h3 class="thread-post-title">trouble in Demo/CodeWarrior_HCS12_banked</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/imajeff">imajeff</a> on February 21, 2006</div><div class="thread-post-content">Oh, I think I got it.
Before, I thought I could guess how much the configMINIMAL&#95;STACK&#95;SIZE would need to increase, and then do a little more. Instead, apparently I should make the stack sizes obsessively huge at first, because now it is running&#33;
I think next I&#8217;ll look at a bunch of the stacks to see how oversized. I increased minimal size from 80 to 120. Maybe that&#8217;s not so bad but I try to be overly conservative :&#41;&nbsp; I&#8217;m just releived the demo seems to be fully working now.
When I clean this up, I&#8217;ll send the demo to Richard so hopefully he can add official support for GCC/HCS12.
I&#8217;ve also got a little documentation to write on this demo so people will know how to config things to their environment.
Thanks everyone helping with this port.&nbsp; &#8211;jeffs
</div></div><div class="thread-post"><h3 class="thread-post-title">trouble in Demo/CodeWarrior_HCS12_banked</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on February 21, 2006</div><div class="thread-post-content">The only place that configMINIMAL&#95;STACK&#95;SIZE&nbsp; is used in the kernel code itself &#91;rather than the demo application code&#93; is setting the size of the idle task stack.&nbsp; Each other task can use different size if best.
</div></div><div class="thread-post"><h3 class="thread-post-title">trouble in Demo/CodeWarrior_HCS12_banked</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/imajeff">imajeff</a> on February 24, 2006</div><div class="thread-post-content">Right, meaning the Demo crashed because the configMINIMAL&#95;STACK&#95;SIZE was too small. In my application, I don&#8217;t need as much stack as the demo tasks. It looks like the Integer math task was overflowing. It takes more stack than I anticipated for temporary storage while doing the math expressions.
I guess GCC was designed to use more registers, I turned off softregs &#40;i.e. &#95;.d1, &#95;.d1&#41;, and so it quitely allocates temp stack space for it.
