  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Return from Task</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/dmwilliams66">dmwilliams66</a> on February 15, 2006</div><div class="thread-post-content">I see there was a discussion about this a while back.&nbsp; Where did it end up?
Is it simple to add a mechanism that permits a task returning from its primary function to return to a place that calls vTaskDelete?&nbsp; I can foresee lots of my users thinking this is a natural thing to do.
Sorry in advance if this is a stupid question.
D.
</div></div><div class="thread-post"><h3 class="thread-post-title">Return from Task</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on February 15, 2006</div><div class="thread-post-content">If you want to do this, can you not just add a call to vTaskDelete at the end of your task function manually?&nbsp; It might not be wanted to add extra code to FreeRTOS to implement something that can be done very easily anyhow.
Just an opinion.
Alternatively you can place the return address that is on the inital stack &#40;setup when the task is created&#41; to jump to the delete function.&nbsp; Then it would happen automatically which is ok as long as this is what you expect to happen.
</div></div><div class="thread-post"><h3 class="thread-post-title">Return from Task</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/dmwilliams66">dmwilliams66</a> on February 15, 2006</div><div class="thread-post-content">Thanks for your suggestions.&nbsp; 
The reason that I want to be able to have the vTaskDelete function be called automatically is that my customers &#40;non-expert programmers&#41; will, I predict, frequently forget.&nbsp; In addition, I think it&#8217;s more natural to think of returning from a thread to mean that you&#8217;re done with it.
I like your second suggestion better, but I&#8217;m just getting started with FreeRTOS so I&#8217;m not super anxious to be playing with stack stuff just yet.&nbsp; Maybe a little project for myself in the near future.
