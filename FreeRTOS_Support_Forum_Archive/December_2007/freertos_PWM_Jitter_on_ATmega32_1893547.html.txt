  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">PWM Jitter on ATmega32</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/tmkupo">tmkupo</a> on December 15, 2007</div><div class="thread-post-content">Hi,
I&#8217;m trying to run some servos using the PWM features of ATmega32 hardware timers, producing a 1-2ms pulse with a 1/128ms resolution.&nbsp; My capture/compare interrupt code works as a stand-alone, but when I integrate it with freeRTOS, the signal jitters by about 30us which causes the servos to shake.
I&#8217;ve tried modifying the tick code to use timer2 instead of timer1, I&#8217;ve tried using naked interrupts, using enter/exit critical and also running the code as a plain hardware interrupt rather than using the interrupt to resume the task but nothing seems to work.
FreeRTOS is running the ATmega32&#8217;s 8MHz internal clock with a tick rate of 1000.&nbsp; Is the interrupt latency of the ATmega32 on freeRTOS too much for use with servos, or am I doing something wrong here?
Thanks,
Jon
</div></div><div class="thread-post"><h3 class="thread-post-title">PWM Jitter on ATmega32</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on December 17, 2007</div><div class="thread-post-content">Set the tick interrupt to use the lowest priority and the PWM interrupt to use a higher priority.&nbsp; This is ok provided you dont call FreeRTOS API functions from the PWM interrupt. Some ports have a configKERNEL&#95;INTERRUPT&#95;PRIORITY for this purpose.
</div></div><div class="thread-post"><h3 class="thread-post-title">PWM Jitter on ATmega32</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/jmr1972">jmr1972</a> on December 17, 2007</div><div class="thread-post-content">Well the first thing I would do is to lower the tick rate. Are you certain that you need to swap tasks every 1ms?
Also 30us is about 240 clock cycles at 8MHz that&#8217;s, in an average bit of code, around 200 instructions &#40;which isn&#8217;t bad at all&#41;.
If you really need to update your control loop at a 1ms rate then I would suggest that you go for a higher clock frequency &#40;this will reduce your jitter but it won&#8217;t eliminate it&#41;.
I would put the servo speed and position update loops into ISRs and leave the RTOS tick at a much lower rate say 50ms+&#41;
