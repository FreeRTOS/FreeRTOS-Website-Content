</div></div><div class="thread-post"><h3 class="thread-post-title">waiting on semaphores &#8211; indefinitely</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on December 18, 2007</div><div class="thread-post-content">&gt; 1. To wait indefinitely, one needs to use:
&gt; xSemaphoreTake&#40; xSemaPhore, portMAX&#95;DELAY &#41;; 
&gt; Also, the configuration &#35;define INCLUDE&#95;vTaskSuspend&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; 
&gt;&nbsp;&nbsp;&nbsp;&nbsp; 1
&gt; has to be set to 1.
&gt; What is the relationship between the two?
&gt; Is portMax&#95;DELAY not enough in itself?
Including INCLUDE&#95;vTaskSuspend causes a new state list to be included &#8211; one in which suspended tasks are referenced &#40;not surprisingly&#41;.&nbsp; Suspended tasks differ from blocked tasks as they do not have a timeout.&nbsp; If this list was not included in the build then the only option is to place tasks in a blocked list, from which it would eventually unblock.&nbsp; On 32bit systems unblocking after 0xffffffff ticks is usually very similar to blocking indefinitely anyway.
The suspended list is used for convenience only &#8211; tasks that are blocked indefinitely remain conceptually in the blocked state &#8211; not the suspended state.
If you don&#8217;t want to use INCLUDE&#95;vTaskSuspend then you have the option to place calls in a loop, for example:
while&#40; xSemaphoreTake&#40; xSemaphore, portMAX&#95;DELAY &#41; &#33;= pdPASS &#41;;
has the same effect as waiting indefinitely, if a little less efficient.
&gt; 
&gt; 2. Documentation on&nbsp; xSemaphoreCreateMutex&#40;&#41; in semaphor.h is 
&gt; confusing
&gt; It is defined as:
&gt; &#35;define xSemaphoreCreateMutex&#40;&#41; xQueueCreateMutex&#40;&#41;
&gt; where as the explanation calls for:
&gt; xSemaphoreCreateMutex&#40; xSemaphoreHandle xSemaphore &#41;
&gt; and the usage is:
&gt; XMutex = xSemaphoreCreateMutex&#40;&#41;;
Err &#8211; its even worse on the WEB site.&nbsp; I will fix this.&nbsp; Thought it had been already.
For now take a look in FreeRTOS/Demo/Common/Minimal/GenQTest.c for an example usage.
&gt; 3. What is the difference between binary semaphore and mutex &#8211; 
&gt; If taskA takes a semaphore xSemaphoreTake&#40; xSema1, portMAX&#95;DELAY &#41;;
&gt; and not give, can TaskB get the xSema1 or will it go into 
&gt; waiting for the sema
&gt; till it is given back by taskA?
The primary difference is that mutexes use priority inheritance, binary semaphores don&#8217;t.&nbsp; This means mutexes must always be &#8216;given back&#8217;, whereas binary semaphores can be used for unidirectional synchronisation, with an ISR for example, where the semaphore is always given by the ISR and always taken by a task and never the other way around.
Regards.
