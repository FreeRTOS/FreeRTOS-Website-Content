</div></div><div class="thread-post"><h3 class="thread-post-title">Stack Problem &#8211; Lattice MICO32 Port</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on December 30, 2007</div><div class="thread-post-content">I don&#8217;t know anything about this processor unfortunately, but have a thought about the compiler generated code.&nbsp; It will be ok to let the compiler insert these instructions &#40;not using the naked attribute &#8211; which is not supported by GCC for all targets&#41; ONLY if the code is exactly the same AT EVERY POINT that a context switch occurred.
For example, consider what happens when a task yields.&nbsp; Its gets swapped out by a call to YIELD &#8211; which modifies the stack by the compiler generated code, then saves the context.&nbsp; What would then happen if the same task was swapped back in again from an interrupt?&nbsp; Would the stack be unwound in exactly the same way &#8211; or would exiting the interrupt leave the stack in an unexpected position before the YIELD function was exited?
Whether this would work or not depends on the processor and compiler behaviour.&nbsp; If it does not work, and the naked attribute is not supported, then you might have to write an assembly code wrapper for the YIELD function.
Regards.
