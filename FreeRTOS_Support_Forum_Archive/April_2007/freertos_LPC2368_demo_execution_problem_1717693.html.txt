  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">LPC2368 demo execution problem</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/martinpb">martinpb</a> on April 18, 2007</div><div class="thread-post-content">Hi all,
I have tried the LPC2368 demo for the MCB2300 board, but it doesn&#8217;t seem to run.
my board is MCB2300 ver. 3.0.
And i am using the Rowley crossworks 1.6 IDE
I have compiled the demo from within rowley crossworks, but unfortunately i dont have a debugger available to me right now. I program the board using the Flash magic programming tool.
I did although notice that ARM/Thumb settings for each file in the project wasn&#8217;t set, so i did that myself before i compiled the project. So normal c files are compiled in thumb mode and isr&#8217;s are compiled in arm mode. Other than that, the options seems to be correct.
I have tried though to debug through the Eclipse, i have the arm-usb-ocd debugger from Olimex, using openocd as GDB server. But i never reach the main function. Instead i end up her:
0x000002ec &lt;reset&#95;wait&gt;:&nbsp;&nbsp; b 0x2ec &lt;reset&#95;wait&gt;
does anyone have an idea, as to what might be wrong ?
regards,
Martin
</div></div><div class="thread-post"><h3 class="thread-post-title">LPC2368 demo execution problem</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on April 18, 2007</div><div class="thread-post-content">The ARM/THUMB settings are set as far as I can see.&nbsp; The project settings are configured for COMMON, ARM, THUMB, etc. individually.&nbsp; If you look in the right place you get the setting.&nbsp; This is a Crossworks feature that is really nice once you get the hang of it but not otherwise obvious.
</div></div><div class="thread-post"><h3 class="thread-post-title">LPC2368 demo execution problem</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/martinpb">martinpb</a> on April 19, 2007</div><div class="thread-post-content">Ok i found the problem.
In the startup code Philips&#95;lpc230x&#95;startup.s, STARTUP&#95;FROM&#95;RESET wasn&#8217;t defined.
So i just added &#35;define STARTUP&#95;FROM&#95;RESET 1. And now it is running.
But shouldn&#8217;t this be defined elsewhere ?
regards,
Martin
</div></div><div class="thread-post"><h3 class="thread-post-title">LPC2368 demo execution problem</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/martinpb">martinpb</a> on April 19, 2007</div><div class="thread-post-content">Encountered another problem with the demo :&#41;
When I open a http connection to the device, the device stops responding.
Some of the page is shown. Has this demo been tested before release ?
The demo files are unmodified, just compiled with crossworks IDE 1.6.
</div></div><div class="thread-post"><h3 class="thread-post-title">LPC2368 demo execution problem</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on April 19, 2007</div><div class="thread-post-content">Ok that makes perfect sense.&nbsp; Start up from reset is defined in the project as a preprocessor constant.&nbsp; The &quot;debug&quot; builds don&#8217;t have startup from reset defined.&nbsp; The Release builds do.&nbsp; Therefore when you are not starting the code through the debugger you need to be using a release build or make the definition yourself.
</div></div><div class="thread-post"><h3 class="thread-post-title">LPC2368 demo execution problem</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/embeddedc">embeddedc</a> on April 19, 2007</div><div class="thread-post-content">Works ok for me &#40;I just replied to your other post too but it seemed to have lost my login cookie&#41;.&nbsp; I only changed the IP address, nothing else.
Does the rest of the demo work for you after the network stops responding?&nbsp; Do the LED&#8217;s still flash?
</div></div><div class="thread-post"><h3 class="thread-post-title">LPC2368 demo execution problem</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/martinpb">martinpb</a> on April 19, 2007</div><div class="thread-post-content">Hi embeddedc,
everything stops. It seems that the application crashes and raises an abort interrupt.
Unfortunately it isn&#8217;t too happy about me debugging the application, through eclipse using the olimex arm.usb-ocd, either. So i will wait till i
get the cross connect debugger back, before i continue :&#41;
I have previously been working with a sam7x and crossworks, where the boot from flash bit was set. So i wasn&#8217;t aware of the fact that there is that difference between debug and release mode.
