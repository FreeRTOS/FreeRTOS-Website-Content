</div></div><div class="thread-post"><h3 class="thread-post-title">PIC18 Memory corruption during context restor</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on April 25, 2007</div><div class="thread-post-content">Hey, the solution works&#33;
See the linker script snippet below:
&quot;
//DATABANK&nbsp;&nbsp; NAME=gpre&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; START=0x0&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; END=0x5F
DATABANK&nbsp;&nbsp; NAME=gpre&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; START=0x0&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; END=0x14&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; PROTECTED
DATABANK&nbsp;&nbsp; NAME=gpre2&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; START=0x15&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; END=0x5F
&quot;
Here I split database gpre in 2 parts. The first part just big enough to fit
mu .tmpdata + MATH&#95;DATA size.
This, in conjuction with:
&quot;
SECTION&nbsp;&nbsp;&nbsp; NAME=.tmpdata&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; RAM=gpre
SECTION&nbsp;&nbsp;&nbsp; NAME=MATH&#95;DATA&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; RAM=gpre
&quot;
forces the .tmpdata and MATH&#95;DATA sections to this part of memory.
When I Compile,&nbsp; the map file looks like:
&quot;
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; Section Info
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; Section&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; Type&nbsp;&nbsp;&nbsp; Address&nbsp;&nbsp; Location Size&#40;Bytes&#41;
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; &#8212;&#8212;&#8212;&nbsp; &#8212;&#8212;&#8212;&nbsp; &#8212;&#8212;&#8212;&nbsp; &#8212;&#8212;&#8212;&nbsp; &#8212;&#8212;&#8212;
