</div></div><div class="thread-post"><h3 class="thread-post-title">CAN Tx/Rx interrupt with LPC2290 and FreeRTOS</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on April 22, 2007</div><div class="thread-post-content">I cannot help with the CAN interrupts specifically, but I have some general comments.
The interrupts will not nest unless you have explicitly re enabled interrupts within the ISR.&nbsp; However you cannot do this without making some other changes in the macros otherwise you definitely will run into problems.&nbsp; Interrupt nesting is not really desirable.
My suggestion would be to process the CAN information within a high priority &#8216;interrupt task&#8217;.&nbsp; This would take the following structure:
void CANHandlerTask&#40; void&#42; parameters &#41;
&#123;
&#95;&#95;for&#40;;;&#41;
&#95;&#95;&#123;
&#95;&#95;&#95;&#95;// Wait for a CAN interrupt.
&#95;&#95;&#95;&#95;xSemaphoreTask&#40; CANSem &#41;;
&#95;&#95;&#95;&#95;if&#40; Rx interrupt received &#41;
&#95;&#95;&#95;&#95;&#123;
&#95;&#95;&#95;&#95;&#95;&#95;// Process Rx data.
&#95;&#95;&#95;&#95;&#125;
&#95;&#95;&#95;&#95;if&#40; Tx interrupt received &#41;
&#95;&#95;&#95;&#95;&#123;
&#95;&#95;&#95;&#95;&#95;&#95;// Process Tx data.
&#95;&#95;&#95;&#95;&#125;
&#95;&#95;&#125;
&#125;
Both the Rx and Tx ISRs then take the following format:
void CANTxISR&#40; void &#41; &#95;&#95;attribute&#95;&#95; &#40;&#40;naked&#41;&#41;
&#123;
&#95;&#95;portENTER&#95;SWITCHING&#95;ISR&#40;&#41;;
&#95;&#95;xSemaphoreGive&#40; CANSem &#41;;
&#95;&#95;//clear CAN interrupt here&#33;
&#95;&#95;//clear VIC here&#33;
&#95;&#95;portEXIT&#95;SWITCHING&#95;ISR&#40;1&#41;;
&#125;
CANHandlerTask&#40;&#41; is then given the highest priority of all tasks &#40;if this is desired&#41;.&nbsp; Then, when an interrupt occurs it wakes the CANHandlerTask&#40;&#41;, and as it is the highest priority, the ISR returns directly to the handler task.&nbsp; The processing is then immediate as if it was done in the ISR itself, but as it is at the task level interrupts are enabled and you can have other &#8216;interrupt tasks&#8217; running at various priorities without having to worry about nesting.
Dave.
