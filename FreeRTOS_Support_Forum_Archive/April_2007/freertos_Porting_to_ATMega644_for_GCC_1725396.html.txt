  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Porting to ATMega644 for GCC</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/hlachmann">hlachmann</a> on April 30, 2007</div><div class="thread-post-content">I started to port FreeRTOS to ATMega644. Now I got stuck with the following simulation error &quot;AVR Simulator: Invalid opcode 0x0053 at address 0x000017&quot; &#40;AVR Studio 4.13&#41;. This error occurs right after the first call to portRESTORE&#95;CONTEXT&#40;&#41; in function xPortStartScheduler &#40;file port.c&#41;. Did anybody successfully port FreeRTOS to ATMega644 for GCC and could help me? Thanks.
What I did so far:
1&#41; created new folder for ATMega644 and added &#35;ifdef to portable.h
2&#41; adjusted timer1 in port.c &#40;it works&#41;
3&#41; added the third byte of program counter &#40;PC&#41; in function pxPortInitialiseStack &#40;file port.c&#41; as described at http://sourceforge.net/forum/message.php?msg&#95;id=3823030. The PC of ATMega644 is three byte, but the highest program memory address is 0x007FFC. IMHO I can push just another 0x00 on the stack.
&gt;&gt;&gt;&gt;&gt;&gt;&gt;&gt;&gt;&gt;&gt;&gt;&gt;&gt;&gt;&gt;&gt;&gt;&gt;&gt;&gt;&gt;&gt;&gt;&gt;&gt;&gt;&gt;&gt;&gt;&gt;&gt;&gt;&gt;&gt;
&nbsp;&nbsp;&nbsp; /&#42; The start of the task code will be popped off the stack last, so place
&nbsp;&nbsp;&nbsp; it on first. &#42;/
&nbsp;&nbsp;&nbsp; usAddress = &#40; unsigned portSHORT &#41; pxCode;
&nbsp;&nbsp;&nbsp; &#42;pxTopOfStack = &#40; portSTACK&#95;TYPE &#41; &#40; usAddress &amp; &#40; unsigned portSHORT &#41; 0x00ff&nbsp; &#41;;
&nbsp;&nbsp;&nbsp; pxTopOfStack&#8211;;
&nbsp;&nbsp;&nbsp; usAddress &gt;&gt;= 8;
&nbsp;&nbsp;&nbsp; &#42;pxTopOfStack = &#40; portSTACK&#95;TYPE &#41; &#40; usAddress &amp; &#40; unsigned portSHORT &#41; 0x00ff&nbsp; &#41;;
&nbsp;&nbsp;&nbsp; pxTopOfStack&#8211;;
&nbsp;&nbsp;&nbsp; 
&nbsp;&nbsp;&nbsp; /&#42; The third byte of program counter is always 0x00. &#42;/
&nbsp;&nbsp;&nbsp; &#42;pxTopOfStack = &#40; portSTACK&#95;TYPE &#41; 0x00;
&nbsp;&nbsp;&nbsp; pxTopOfStack&#8211;;
&lt;&lt;&lt;&lt;&lt;&lt;&lt;&lt;&lt;&lt;&lt;&lt;&lt;&lt;&lt;&lt;&lt;&lt;&lt;&lt;&lt;&lt;&lt;&lt;&lt;&lt;&lt;&lt;&lt;&lt;&lt;&lt;&lt;&lt;&lt;
&#40;Just doing another 8-bit-shift didn&#8217;t work because of compiler complaints: pxCode is a pointer to a 16bit integer.&#41;
</div></div><div class="thread-post"><h3 class="thread-post-title">Porting to ATMega644 for GCC</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on April 30, 2007</div><div class="thread-post-content">Have you tried putting the extra byte first rather than last of the three.&nbsp; I have run code designed for 16bit program counter in the simulator when a 24bit program counter part was selected and it worked.&nbsp; It seemed illogical and I never worked out how come, but then I did not really study it that closely.
Failing that, can you step through the restore context assembly code and say at what point the error occurs?
</div></div><div class="thread-post"><h3 class="thread-post-title">Porting to ATMega644 for GCC</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/hlachmann">hlachmann</a> on April 30, 2007</div><div class="thread-post-content">Putting the extra byte first results in the same error with just different opcode / address. That your code worked has most likely something to do with a different endianess.
Unfortunately, I can&#8217;t step through the assembly code as the debugger doesn&#8217;t support it &#40;maybe there is a switch and I don&#8217;t know about it?&#41;. The error actually occurs at &quot;asm volatile &#40; &quot;ret&quot; &#41;;&quot; after portRESTORE&#95;CONTEXT&#40;&#41;. 
I don&#8217;t know how the stack is or should be organized for the ATMega644. Then I could check, if I see the expected values.
</div></div><div class="thread-post"><h3 class="thread-post-title">Porting to ATMega644 for GCC</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/hlachmann">hlachmann</a> on May 1, 2007</div><div class="thread-post-content">After debugging I finally solved the problem: 
1&#41; Even though the PC of ATMega644 is 3 byte long &#40;compared to 2 byte of ATMega32&#41;, an additional third byte for the PC must NOT be added in function pxPortInitialiseStack.
2&#41; The simulator errors occured due to a stack overflow &#40;a different problem&#41;
