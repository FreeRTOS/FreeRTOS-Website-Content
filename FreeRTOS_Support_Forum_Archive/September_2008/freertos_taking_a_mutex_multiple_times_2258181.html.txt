  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">taking a mutex multiple times</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/hooverphonique">hooverphonique</a> on September 18, 2008</div><div class="thread-post-content">the mutex documentation says:
&quot;This means the mutex must always be &#8216;given&#8217; back &#8211; otherwise the higher priority task will never be able to obtain the mutex, and the lower priority task will never &#8216;disinherit&#8217; the priority. An example of a mutex being used to implement mutual exclusion is provided on the xSemaphoreTake&#40;&#41; documentation page. &quot;
which implies that a task can take a mutex as many times as it wants and then give it back once, when done with it.. 
Is this a correct observation? &#40;note: i&#8217;m talking regular mutexes, not recursive ones.&#41;
cheers..
</div></div><div class="thread-post"><h3 class="thread-post-title">taking a mutex multiple times</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on September 18, 2008</div><div class="thread-post-content">Mutexes are like binary semaphores in that they are either available or not. You can take it as many times as you like but only the first take call will return pdTRUE assuming the mutex was available. Following calls will return pdFALSE until you have given the semaphore back.
</div></div><div class="thread-post"><h3 class="thread-post-title">taking a mutex multiple times</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/hooverphonique">hooverphonique</a> on September 18, 2008</div><div class="thread-post-content">ok.. what i was after was a &quot;reentrant&quot; mutex that can be taken succesfully an infinite number of times by the same task &#40;assuming it is initially available&#41;..
</div></div><div class="thread-post"><h3 class="thread-post-title">taking a mutex multiple times</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on September 18, 2008</div><div class="thread-post-content">I think that would be easy enough to implement. The mutuex holder is saved in the pxMutexHolder member so if the same task takes the mutuex but is already the mutuex holder it can return true. It might be better to keep the FreeRTOS code unchanged, and provide your own wrapper to the take function to add in this extra functionality.
</div></div><div class="thread-post"><h3 class="thread-post-title">taking a mutex multiple times</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/hooverphonique">hooverphonique</a> on October 3, 2008</div><div class="thread-post-content">That looks easy enough, yah&#8230; only thing is, the xQUEUE type is private to FreeRTOS, so the wrapper would have to be a hack..
richard, if you read this:
maybe it would be an idea to have a function in the API like
xMutexTake&#40;xSemaphoreHandle, portTickType, portBASE&#95;TYPE reentrant&#41;;
that would just call xSemaphoreTake if reentrant is false and use xTaskGetCurrentTaskHandle to check pxMutexHolder if true and then skip calling xSemaphoreTake if the current task is already the owner&#8230;
cheers&#8230;
