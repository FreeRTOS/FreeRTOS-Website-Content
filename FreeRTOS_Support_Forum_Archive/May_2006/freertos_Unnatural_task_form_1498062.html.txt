  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Unnatural task form</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on May 15, 2006</div><div class="thread-post-content">Hi, I think that endless-loop form of task function is somewhat weird.
Why not automatically put NULL and pointer to vTaskDelete on the stack of newly created task?
This way you get plain and simple void function as task code which may end-by-return&#8230;
Regards
</div></div><div class="thread-post"><h3 class="thread-post-title">Unnatural task form</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on May 15, 2006</div><div class="thread-post-content">Most tasks are implemented as an endless loop.&nbsp; If you want the task to run just once, then probably not a good candidate for a task.&nbsp; If you want the task to delete, just place vTaskDelete&#40;NULL&#41; at the end of the function and you have not wasted any stack.
</div></div><div class="thread-post"><h3 class="thread-post-title">Unnatural task form</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on May 15, 2006</div><div class="thread-post-content">Well, I will defend my point of view:
I didn&#8217;t mean to run task once. It is just more portable and safe &#40;what happens now if u return from task?&#41; to have the task cleaned up automatically. The four bytes &#40;AVR&#41; of data &#40;16b NULL + pointer to vTaskDelete&#41; is not much for ability to just &quot;return&quot; from task.
Maybe FreeRTOS author will answer this from professional&#8217;s point of view.
</div></div><div class="thread-post"><h3 class="thread-post-title">Unnatural task form</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on May 15, 2006</div><div class="thread-post-content">If this forum was like some of the others, you&#8217;d get rained on now.&nbsp; The endless loop task structure is the way it is done in most if not all multitasking environments.&nbsp; Certainly all I have ever seen.&nbsp; It is just as &quot;safe&quot; as any other form.&nbsp; Just follow the rules.&nbsp; The rest of us don&#8217;t want the added overhead of support for those who don&#8217;t want to do it the way the documentation says it should be done.&nbsp; If I were Richard, I wouldn&#8217;t waste my time arguing with you about this.
</div></div><div class="thread-post"><h3 class="thread-post-title">Unnatural task form</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on May 15, 2006</div><div class="thread-post-content">Hmm, I don&#8217;t want to sit on the fence too much, but I don&#8217;t really see it as a big issue.&nbsp; It is just an implementation choice.
Placing a jump to a delete function on the return stack is valid and neat, but does require more stack &#40;albeit a few bytes, remember FreeRTOS runs on some tiny processors&#41;.&nbsp; I don&#8217;t see how this gets around having most tasks as an infinite loop however.
The current implementation will allow users to crash the code by running off the bottom of a task.&nbsp; Doing so would show a lack of understanding of the system they were programming so I doubt this would be their only problem ;-&#41;&nbsp; There are lots of ways you can cause a crash, and as a small fast implementation FreeRTOS does not try to guard against them all.&nbsp; Placing a vTaskDelete call outside of the loop is not a big issue, and more explicit of how you intend the task to function.
So I don&#8217;t have strong feelings either way.&nbsp; FreeRTOS provides all the source code so you can make your application function however you wish by editing if you so desire.
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">Unnatural task form</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/jwestmoreland">jwestmoreland</a> on May 15, 2006</div><div class="thread-post-content">I think I&#8217;m repeating here &#8211; but it seems that the functionality of what &#8216;nobody&#8217; wants is already in FreeRTOS.&nbsp; vTaskDelete&#40;&#41; gives the ability asked for.
As Richard has stated &#8211; the source code is there.&nbsp; In port.c &#8211; you can make the stack behave any way you want.&nbsp; There are issues of both compiler &#40;tool-sets&#41; and the target MCU.&nbsp; It doesn&#8217;t seem to be a very portable approach IMHO, but the source is there for you to modify as you wish.
As FreeRTOS runs on a lot of RAM constrained systems &#8211; I think &#40;IMHO&#41; that leaving the stack alone is the way to go vs. adding more args on the stack.
Just my 2 cents,
John W.
