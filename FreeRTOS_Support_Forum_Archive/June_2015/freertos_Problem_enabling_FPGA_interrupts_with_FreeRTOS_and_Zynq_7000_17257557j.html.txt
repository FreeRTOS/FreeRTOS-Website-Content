  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Problem enabling FPGA interrupts with FreeRTOS and Zynq 7000</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/wonger">wonger</a> on June 25, 2015</div><div class="thread-post-content">I&#8217;m running FreeRTOS on a Zynq 7000 (dual core ARM Cortex-A9, but only using 1 core for FreeRTOS). I enabled FPGA2 interrupt (IntID 63) with the following:
~~~~~~
XScuGic<em>Connect( &amp;xInterruptController, XPS</em>FPGA2<em>INT</em>ID, (Xil<em>ExceptionHandler) FPGA2</em>IntHandler, NULL);
XScuGic<em>SetPriorityTriggerType( &amp;xInterruptController, XPS</em>FPGA2<em>INT</em>ID, configMAX<em>API</em>CALL<em>INTERRUPT</em>PRIORITY &lt;&lt; portPRIORITY<em>SHIFT, 3 );
XScuGic</em>Enable(&amp;xInterruptController, XPS<em>FPGA2</em>INT_ID);
~~~~~~
The FreeRTOS tick timer interrupt handler is triggering, but not this FPGA2 interrupt handler. I can see the interrupt input line toggling on spi<em>status</em>0 register.  This code on a bare-metal application triggers the FPGA2 interrupt handler, but not in FreeRTOS. Anyone know what I&#8217;m missing?
Thanks for your help.
</div></div><div class="thread-post"><h3 class="thread-post-title">Problem enabling FPGA interrupts with FreeRTOS and Zynq 7000</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on June 25, 2015</div><div class="thread-post-content">I can&#8217;t see anything obviously wrong.  Did you use the code in vConfigureTickInterrupt() as a reference?
I&#8217;ve never tried using that particular interrupt &#8211; is there anything different about it compared to say the UART or Ethernet interrupts?  [both of which I have used]
</div></div><div class="thread-post"><h3 class="thread-post-title">Problem enabling FPGA interrupts with FreeRTOS and Zynq 7000</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/wonger">wonger</a> on June 25, 2015</div><div class="thread-post-content">I found out the problem.  I put the FPGA2 interrupt enable code above in prvSetupHardware().  I adapted the demo code from the blinky demo, so I&#8217;ll put everything in context of that.  When main_blinky() runs, it calls vTaskStartScheduler() which eventually gets to vConfigureTickInterrupt().
vConfigureTickInterrupt() calls XScuGic_LookupConfig() and _CfgInitialize() again (they were already called in prvSetupHardware()).  This clears out the FPGA2 interrupt enable bit and renders it disabled.  
To get it to work, I took out the calls to XScuGic_LookupConfig() and _CfgInitialize() and removed the static reference to xInterruptController in vConfigureTickInterrupt().  I used the global xInterruptController defined in main.c instead, the one initialized by prvSetupHardware().
Is there anything wrong with what I did to get it to work?  Why in the demo code does vConfigureTickInterrupt() use a static reference to the interrupt controller rather than the global one define in main.c?  Will anything come back to bite me in removing the static reference and using the global one?
</div></div><div class="thread-post"><h3 class="thread-post-title">Problem enabling FPGA interrupts with FreeRTOS and Zynq 7000</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/wonger">wonger</a> on June 25, 2015</div><div class="thread-post-content">It also occurred to me that if I put the FPGA2 interrupt enable code in prvQueueSendTask() or prvQueueRecieveTask() (the tasks that drive the blinky demo), I would not have run into this problem. And perhaps that is the more proper place to put this code?  Not in those tasks per se, but in a related task that would use FPGA2 interrupt.
</div></div><div class="thread-post"><h3 class="thread-post-title">Problem enabling FPGA interrupts with FreeRTOS and Zynq 7000</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on June 26, 2015</div><div class="thread-post-content">Note that the vConfigureTickInterrupt() is demo code (and thus part of the application) and NOT &#8216;FreeRTOS Kernal code&#8217; that shouldn&#8217;t normally be changed. I have changed that code to use a common instance so the ScuGic isn&#8217;t reinitialized at this point (and thus lose all the interrupt previously enabled).
