  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Problem with Semaphore and Task-Delay</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/lctromnml">lctromnml</a> on June 12, 2015</div><div class="thread-post-content">Hi, 
I am working with FreeRTOS and have encountered a problem with one task. The task in general looks this way: 
&#35;define MILLISECONDS( x ) ( x / portTICK<em>PERIOD</em>MS)
void foo(void* pvParameters)
{
    const TickType<em>t delay = MILLISECONDS(10);
    const TickType</em>t unblockSmphrDelay =  MILLISECONDS(1000);
<pre><code>xSemaphoreTake(SyncStatusRegSmphr, 0);
for (;;)
{
    xSemaphoreTake(SyncStatusRegSmphr,unblockSmphrDelay);
    //Send CAN message
    vTaskDelay(delay);
}
</code></pre>
}
It runs with FreeRTOS V8.1.2 on an STM32F407VGT6 controller. The task can be unblocked from different tasks/ISRs (ISRs with xSemaphoreGiveFromISR). The intention is to send event based CAN messages, but with a maximum frequency of 10ms, no matter how many events occur. Also the message should be sent at least every second, even if there were no events that unblocked the task. 
The behaviour is as follows: The task works as it should for a time that seems random to me (at least for some minutes, sometimes for several hours). But sporadically it occurs, that the CAN-message is not sent anymore. The controller does not crash and several other tasks keep sending on the CAN-bus. The controller still executes anything it should except this task. 
My question would be, if it is ok to write the task in this way in general, and how this behavior can occur? 
Thanks! 
Simon
</div></div><div class="thread-post"><h3 class="thread-post-title">Problem with Semaphore and Task-Delay</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on June 12, 2015</div><div class="thread-post-content">First a small remark. If you want to transform milliseconds to a tick-count, it is more correct to use &#8216;<code>pdMS_TO_TICKS</code>&#8216;. In this example 5 seconds:
<pre><code>TickType_t xTickCount = pdMS_TO_TICKS( 5000ul )
</code></pre>
The example that you give looks perfect to me, nothing wrong with it. I&#8217;m afraid that the problem is in the code that you&#8217;re not showing.
You are sending a CAN message, is that resource well-protected, is it &#8220;re-entrant&#8221; ?
Regards.
