  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">v9.0.0 &#8211; ARM Port &#8211; Idle Task Items Stop Running &#8211; But Heap OK</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/westmorelandeng">westmorelandeng</a> on August 12, 2016</div><div class="thread-post-content">Hello All,
In my port &#8211; after a while; I have some debug printf&#8217;s in the idle task &#8211; and they stop running;  I have a task hook that prints the available heap &#8211; and that is OK (unchanged).  I would have thought I would see a memory leak that caused the idle task issue; but so far I am not seeing that.  I am using heap5.c.
All of the other tasks appear to be OK.
Has anyone seen this behavior?  I don&#8217;t see it until the port runs for more than 1 hour or so.
Thanks In Advance,
John W.
</div></div><div class="thread-post"><h3 class="thread-post-title">v9.0.0 &#8211; ARM Port &#8211; Idle Task Items Stop Running &#8211; But Heap OK</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on August 12, 2016</div><div class="thread-post-content">So the system is still running, but the messages printed from the idle task stop&#8230;so either the Idle task has stopped or printf() is no longer outputting to the terminal.
After this has happened, are you able to put a break point in the Idle task and see the break point get hit?  Or if that is not possible, have the idle task increment a global variable, and pause on the debugger a few times and see if the variable is still being incremented, indicating that the Idle task is still cycling.
If the Idle task is still cycling then it would seem that the problem was simply that printf() was no longer working.  Where is printf() sending its output?  (UART, terminal, UDP port, etc.)
</div></div><div class="thread-post"><h3 class="thread-post-title">v9.0.0 &#8211; ARM Port &#8211; Idle Task Items Stop Running &#8211; But Heap OK</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/westmorelandeng">westmorelandeng</a> on August 12, 2016</div><div class="thread-post-content">With this debugger &#8211; I can connect to a running target &#8211; none of the breakpoints in the Idle task ever got hit &#8211; hence the Idle task appeared not to be running at all; or had gotten suspended or the equivalent of that.
</div></div><div class="thread-post"><h3 class="thread-post-title">v9.0.0 &#8211; ARM Port &#8211; Idle Task Items Stop Running &#8211; But Heap OK</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/westmorelandeng">westmorelandeng</a> on September 8, 2016</div><div class="thread-post-content">Here&#8217;s an example:
 main:ADC11 id: 0xb, data: 0x7b9 main:ADC11 id: 0xb, data: 0x7b9 main:ADC11 id: 0xb, data: 0x7b9 &#8211; task hook &#8211; :0xcb80
  &#8211; task hook &#8211; :0xcb80
 &#8211; task hook &#8211; :0xcb80
 The printf in the idle task hook stops &#8211; that is the one that starts:  main:ADC&#8230;
 but the task hook is a printf in a task hook &#8211; and that keeps running.  The 0xcb80 is what is returned from reading what is available on the heap.
 Thanks,
 John W.
</div></div><div class="thread-post"><h3 class="thread-post-title">v9.0.0 &#8211; ARM Port &#8211; Idle Task Items Stop Running &#8211; But Heap OK</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on September 8, 2016</div><div class="thread-post-content">Can you take the printf out and instead toggle a pin in the idle task, then check the pin is still toggling? Maybe the printf is the problem.
