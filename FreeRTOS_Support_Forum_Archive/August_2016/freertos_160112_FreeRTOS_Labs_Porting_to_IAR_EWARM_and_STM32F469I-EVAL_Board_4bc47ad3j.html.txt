Everything works on both the STM3241G-EVAL board, which contains an STM32F417IGH6 processor.
So far, so good&#8230;
Now I&#8217;m trying to get it to run on an STM32469I-EVAL board, which contains an STM32F469NIH6 processor.  However, the CMSIS and HAL Driver files in the 160112<em>FreeRTOS</em>Labs project are not new enough to support the STM32F469xx processor.
So, I updated my project with all the relevant CMSIS and HAL files from the latest STM32Cube<em>FW</em>F4_V1.13.0 repository and I actually got it to compile.  However, now when I use my updated source tree to build for the STM3241G-EVAL board, the build succeeds but it won&#8217;t run on the STM3241G-EVAL board.
Here is where it seems to be getting stuck:
    1.  IP-task task is created.
    2.  SvrWork task is created.
    3.  IDLE task is created.
    4.  EMAC task is created.
    5.  The vDHCPProcess() function sends a proper DHCP Discover packet and my network&#8217;s DHCP Server responds with a proper DHCP Offer packet, but the vDHCPProcess() function does not receive the packet.
    6.  No other tasks are created because of the failure in step 5.
Any ideas?

</div></div><div class="thread-post"><h3 class="thread-post-title">160112_FreeRTOS_Labs Porting to IAR EWARM and STM32F469I-EVAL Board</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nomad8201">nomad8201</a> on August 23, 2016</div><div class="thread-post-content">Hello Hein,
That would be great.  I should warn you that I had to change 3 of the new HAL files to get it to compile:
<strong>stm32f4xx<em>hal</em>gpio.h</strong> &#8211; For some reason, ST decided to change the names of the GPIO speed definitions.  So I added the following definitions for backward compatibility:
<pre><code>#define GPIO_SPEED_LOW      GPIO_SPEED_FREQ_LOW
#define GPIO_SPEED_MEDIUM   GPIO_SPEED_FREQ_MEDIUM
#define GPIO_SPEED_FAST     GPIO_SPEED_FREQ_HIGH
#define GPIO_SPEED_HIGH     GPIO_SPEED_FREQ_VERY_HIGH
</code></pre>
<strong>stm32f4xx<em>hal</em>sd.h</strong> &#8211; The standard file does not have <strong>SD_EventSetupFunctionTypeDef</strong> or <strong>SD_EventWaitFunctionTypeDef</strong> definitions and does not have <strong>EventSetupFunction</strong> or <strong>EventWaitFunction</strong> elements in its <strong>SD_HandleTypeDef</strong> definition.  So, I added these by copying them from the same file in the <strong>160112<em>FreeRTOS</em>Labs.zip</strong> download.
<strong>stm32f4xx<em>hal</em>sd.c</strong> &#8211; In the standard file, the <strong>HAL<em>SD</em>Init()</strong> function unconditionally initializes <strong>tmpinit.BusWide</strong> to <strong>SDIO<em>BUS</em>WIDE_1B</strong>.  So, I changed this to the following, which I copied from the same file in the <strong>160112<em>FreeRTOS</em>Labs.zip</strong> download:
<pre><code>#if( BUS_4BITS != 0 )
{
    tmpinit.BusWide             = SDIO_BUS_WIDE_4B;
}
#else
{
    tmpinit.BusWide             = SDIO_BUS_WIDE_1B;
}
#endif
</code></pre>
Thanks,
Damon
