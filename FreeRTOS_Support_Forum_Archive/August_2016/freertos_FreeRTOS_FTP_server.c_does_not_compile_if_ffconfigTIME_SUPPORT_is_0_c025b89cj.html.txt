</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS_FTP_server.c does not compile if ffconfigTIME_SUPPORT is 0</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on August 3, 2016</div><div class="thread-post-content">The <a href="https://tools.ietf.org/html/rfc3659#section-3">&#8220;MDTM&#8221; command</a> is quite essential to FTP. It needs support for time &amp; date in +FAT.
So unless you have a good reason not to use it, I would enable it in your FreeRTOSFATConfig.h:
<pre><code>#define ffconfigTIME_SUPPORT      1
</code></pre>
and also include the source file &#8220;ff_time.c&#8221;.
Regards

But you <strong>do</strong>have NTP 🙂
What I often do is synchronise with NTP and use FreeRTOS to maintain the real time.
<blockquote>

</blockquote>
I&#8217;m not sure if it saves a lot of code. Have you calculated that?
<blockquote>
  I had the impression that some &#8220;time&#8221; stuff drawn in from glibc. But I&#8217;m not sure.

Not that I&#8217;m aware off. Several time-functions have been rewritten in order make it independent from the libraries provided by the compiler.
Now if you insist on not using time-support, I (or you) could make a change, remove the MDTM line from:
~~~~
    static const char pcFeatAnswer[] =
        &#8220;211-Features:x0a&#8221;
<h1>if( ffconfigTIME_SUPPORT != 0 )</h1>
<pre><code>    "MDTMx0a"
</code></pre>
<h1>endif</h1>
<pre><code>    " REST STREAMx0a"
    " SIZEx0dx0a"
    "211 Endx0dx0a";
</code></pre>
~~~~
and also:
~~~~
    #if ffconfigTIME<em>SUPPORT == 0
    {
        xLength = snprintf( pcCOMMAND</em>BUFFER,
            sizeof( pcCOMMAND_BUFFER ),
            &#8220;213 19700101000000rn&#8221;);
    }
    #else
    {
          // return the time
    }
    #endif
~~~~
