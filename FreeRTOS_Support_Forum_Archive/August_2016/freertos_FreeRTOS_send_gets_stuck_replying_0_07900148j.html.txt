  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">FreeRTOS_send gets stuck replying 0</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/dibosco">dibosco</a> on August 30, 2016</div><div class="thread-post-content">Folks,
I have a situation where, ocassionally, FreeRTOS_send() returns 0.
I followed the premise on this page:
http://www.freertos.org/FreeRTOS-Plus/FreeRTOS<em>Plus</em>TCP/TCP<em>Networking</em>Tutorial<em>Sending</em>TCP_Data.html
However, very ocassionally, I find that in this part:
if( FreeRTOS<em>connect( xSocket, &amp;xRemoteAddress, sizeof( xRemoteAddress ) ) == 0 )
{
    /* Keep sending until the entire buffer has been sent. */
    while( xAlreadyTransmitted &lt; xTotalLengthToSend )
    {
        /* How many bytes are left to send? */
        xLenToSend = xTotalLengthToSend &#8211; xAlreadyTransmitted;
        xBytesSent = FreeRTOS</em>send( /* The socket being sent to. <em>/
                                    xSocket,
                                    /</em> The data being sent. <em>/
                                    &amp;( pcBufferToTransmit[ xAlreadyTransmitted ] ),
                                    /</em> The remaining length of data to send. <em>/
                                    xLenToSend,
                                    /</em> ulFlags. */
                                    0 );
<pre><code>    if( xBytesSent &gt;= 0 )
    {
        /* Data was sent successfully. */
        xAlreadyTransmitted += xBytesSent;
    }
    else
    {
        /* Error - break out of the loop for graceful socket close. */
        break;
    }
}
</code></pre>
}
The xBytesSent is <em>always</em> zero and therefore the thread gets stuck infinitely in that bit of the code and the whole web server just stops responding,
I changed the line from:
if( xBytesSent >= 0 )
to 
if( xBytesSent > 0 )
And that seems to stop the thread from locking up, but I very ocassionally get my auto-refresh page not responding and have to manually refresh the page, then all is well again.
I&#8217;m using a version of the TCP/IP stack that is around a year old. Is it worth updating it? Or do these symptoms point to something more sinister? 
If it&#8217;s of any help I did step into the code and found that the zero return value was here:
<pre><code>else if( pxSocket-&gt;u.xTcp.bits.bFinSent )
{
    /* This TCP connection is closing already, the FIN flag has been sent.
    Maybe it is still delivering or receiving data.
    Return OK in order not to get closed/deleted too quickly */
    xResult = 0;
}
</code></pre>
Which is in prvTCPSendCheck() which is called by  FreeRTOS_send().
Many thanks!
Rob
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS_send gets stuck replying 0</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on August 30, 2016</div><div class="thread-post-content">Hi Rob,
There is a newer release available of the +TCP library than the one that you are using:
http://www.freertos.org/FreeRTOS-Labs/RTOS<em>labs</em>download.html
Just thinking out loud: if the FIN has been sent (<code>bFinSent</code>), then the connection is in a closing state.
Apparently, the peer has not yet acknowledged the FIN, because <code>ucTCPState != eCLOSED</code> yet, the connection isn&#8217;t closed.
It would be interesting to see a PCAP dump of that conversation in which send() hangs. Can you create that?
On itself, your code seems correct: eventually <code>FreeRTOS_send()</code> will either send all data, or the connection gets closed and <code>FreeRTOS_send()</code> will return a negative errno code.
If <code>FreeRTOS_send()</code> returns 0, it means that the buffers are full. Does the call still block when nothing can be sent? Isn&#8217;t it just spinning around on a too high priority?
Do you have these enabled?
~~~~
    #define ipconfigTCP<em>HANG</em>PROTECTION         1
    #define ipconfigTCP<em>KEEP</em>ALIVE              1
~~~~
Not sure if it would help you with this problem though 🙂
What does your code do after sending the file? After the last successful call to <code>FreeRTOS_send()</code>? Do you wait for the data to be properly delivered?
Do you use the same socket for more transactions?
Regards.
