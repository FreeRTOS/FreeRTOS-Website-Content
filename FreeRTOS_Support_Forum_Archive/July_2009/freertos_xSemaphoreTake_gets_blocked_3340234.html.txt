</div></div><div class="thread-post"><h3 class="thread-post-title">xSemaphoreTake gets blocked</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/spacewrench">spacewrench</a> on July 20, 2009</div><div class="thread-post-content">I&#8217;ve written several FreeRTOS programs that run on Luminary chips.&nbsp; Interrupts work correctly, but you have to be careful about priority.&nbsp; Specifically, in the NVIC, lower-numbered priorities are higher.&nbsp; Also, there&#8217;s an intermediate priority level &#40;configMAX&#95;SYSCALL&#95;INTERRUPT&#95;PRIORITY&#41; above which you can&#8217;t call FreeRTOS routines.&nbsp; There&#8217;s a lot more information on the FreeRTOS website, but it&#8217;s slightly difficult to find.&nbsp; &#40;It would be nice if there was a FAQ about it, or a more-prominent link in a section talking about Cortex procs.&#41;&nbsp; Here&#8217;s where to start reading:
/wp-content/uploads/2019/07/index.html?http://www.freertos.org/portcortexgcc.html
Near the bottom of the main frame, under the heading &quot;RTOS Port specific configuration&quot;
</div></div><div class="thread-post"><h3 class="thread-post-title">xSemaphoreTake gets blocked</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on July 20, 2009</div><div class="thread-post-content">I&#8217;m not sure what you mean by &quot;custom interrupts have to be avoided&quot;.&nbsp; Its fine to have any interrupts you want provided there are no resource conflicts.
Was your interrupt using the FreeRTOS API?&nbsp; If so then ensure only API functions that end in FromISR were being used and that the interrupt priority was less than or equal to configMAX&#95;SYSCALL&#95;INTERRUPT&#95;PRIORITY &#40;remembering that low number mean high priorities on the Cortex M3&#41;.
Regards.
