  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">high priorized isr in arm 7</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/i_stolze">i_stolze</a> on July 24, 2009</div><div class="thread-post-content">I&#8217;m using FreeRTOS 5.3 on a TMS470 &#40;ARM7&#41;. I want to use FIQ &#40;high piorized interrupt&#41; which can interrupt normal IRQs using portSAVE&#95;CONTEXT&#40;&#41; and portRESTORE&#95;CONTEXT&#40;&#41; and can interrupt the OS-ISR vPortYieldProcessor&#40;&#41;. In the FIQ is no context switch. possible or desired. 
I have used&nbsp; &#95;&#95;attribute&#95;&#95; &#40;&#40;interrupt &#40;&quot;FIQ&quot;&#41;&#41;&#41; of the arm-elf-gcc &#40;GCC&#41; 4.1.2 &#40;WinARM 4/2007&#41;for the fiq, but i have some trouble on starting the application. After some &#40;10 to 50&#41; reboots the application runs fine. I&#8217;m not able to determine the reason for reboots exactly, but I gues the reason is the register saving and restoring of the fiq. 
The gcc generates following code for the FIQ:&nbsp; 
sub&nbsp;&nbsp;&nbsp; lr, lr, &#35;4
stmfd&nbsp;&nbsp;&nbsp; sp&#33;, &#123;r0, r1, r2, r3, lr&#125;
bl&nbsp;&nbsp;&nbsp; RtiTimer2Isr
ldmfd&nbsp;&nbsp;&nbsp; sp&#33;, &#123;r0, r1, r2, r3, pc&#125;^
What&#8217;s wrong?
</div></div><div class="thread-post"><h3 class="thread-post-title">high priorized isr in arm 7</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on July 25, 2009</div><div class="thread-post-content">The FIQ mode has some registers all to itself, the compiler should know which to save and restore but the &#95;&#95;attribtute&#95;&#95; features of GCC are notoriously problematic.
As an aside, check the definitions of portENABLE&#95;INTERRUPTS and portDISABLE&#95;INTERRUPTS &#40;or what ever is used to disable and enable interrupts in critical sections&#41; to ensure it only manipulates the IRQ bit and not the FIQ bit.
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">high priorized isr in arm 7</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/incrediball">incrediball</a> on July 26, 2009</div><div class="thread-post-content">I didn&#8217;t trust the interrupt attributes when I did this after reading about all the problems that others had with them so I coded the entry and exit code myself. This is what I did and it seems to work well:
Firstly use &#95;&#95;attribute&#95;&#95;&#40;&#40;naked&#41;&#41; to ensure there is no automatic entry &amp; exit code.
Entry code:
&nbsp;&nbsp;&nbsp; // Save context for FIQ interrupt. Left in FIQ mode with F &amp; I bits set &#40;all interrupts disabled&#41;
&nbsp;&nbsp;&nbsp; asm volatile &#40;
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; &quot;stmfd&nbsp;&nbsp;&nbsp; sp&#33;, &#123;r0-r7,lr&#125;&quot;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; // store unbanked registers and lr
&nbsp;&nbsp;&nbsp; &#41;;
Exit code:
&nbsp;&nbsp;&nbsp; asm volatile &#40;
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; &quot;ldmia&nbsp;&nbsp;&nbsp; sp&#33;, &#123;r0-r7,lr&#125;&nbsp;&nbsp;&nbsp; nt&quot;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; // restore unbanked registers and lr
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; &quot;subs&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; pc, lr, &#35;4&quot;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; // Restore the Program Counter using the LR&#95;fiq directly into the PC
&nbsp;&nbsp;&nbsp; &#41;;
The whole function is expected to run in ARM mode.
Make sure you have defined a stack and a vector for the FIQ interrupt in your startup code. Richard&#8217;s tip about disabling/enabling interrupts and critical sections is important since you probably don&#8217;t want high latencies. The FIQ should be able to interrupt critical sections but make sure the FIQ does not interact with FreeRTOS or anything else that the critical sections are supposed to protect.
