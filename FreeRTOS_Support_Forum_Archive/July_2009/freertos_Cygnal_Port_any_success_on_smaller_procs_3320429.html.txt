I&#8217;m currently groveling through the pointer machinery, but wondered if anybody has gotten FreeRTOS running on SiLabs procs other than the F120 that the Cygnal demo is set up for.&nbsp; Any advice, such as &quot;don&#8217;t bother, there&#8217;s not enough memory to do anything&quot; could save me a few hours of fiddling.
Thanks,
d.
</div></div><div class="thread-post"><h3 class="thread-post-title">Cygnal Port: any success on smaller procs?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on July 2, 2009</div><div class="thread-post-content">There have been issues reported with the later versions of SDCC &#8211; unfortunately I have not got around to looking at this yet as its not one of the most used ports.
You have to recompile the libraries to be re-entrant.&nbsp; The FreeRTOS site links to some libraries that I pre-build several years ago, but I don&#8217;t know if they are still compatible with the newer SDCC versions.
Do you have the kernel running before the library problem occurs?
Regards.

No, I&#8217;ve printf-debugged / fixed through the mallocs in CreateTask &#40;my single task plus the Idle task&#41; but the first context switch never happens.&nbsp; I don&#8217;t have much in the way of debugging capability, so it&#8217;s nigh impossible to catch / inspect things as they happen.
Given my trouble with memset&#40;&#41;, it seems very likely that I don&#8217;t have reentrancy handled right.&nbsp; I skimmed that section in the SDCC docs, but I&#8217;m not familiar enough with the 8051 architecture yet to understand how the way SDCC does things, interacts with the way FreeRTOS handles stacks and context switches.
&#40;The 8051 is totally cringe-inducing after playing with ARMs and even the AVR8.&nbsp; Ugh&#33;&#41;

Won&#8217;t run with 2.6.0 or above. I have not tried re-compiling the libs but I built a dead simple test program that just increments a counter in each of 2 tasks so it is not calling any lib functions and it still won&#8217;t work above 2.5.0.&nbsp; It would be nice to get it working with 2.9.0

</div></div><div class="thread-post"><h3 class="thread-post-title">Cygnal Port: any success on smaller procs?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/ragbagger">ragbagger</a> on July 9, 2009</div><div class="thread-post-content">I am currently debugging using the Sililabs IDE that comes with the 8051F120 prototype board. It is fairly good. I have found that the program will run normally through task creation and then starts the scheduler ok. The last task created then runs until either a tick interrupt or other task changing command at which point the stack appears to get bloan away and execution jumps to 0x0000. It may be a problem with malloc and how the initial stack for each task gets created. I want to test what the stacks for each task look like with 2.5.0 and 2.6.0 to see if they are different. If you find anything please post me a note&#33;
