</div></div><div class="thread-post"><h3 class="thread-post-title">V.5.4.0 Posting</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on July 8, 2009</div><div class="thread-post-content">Hi John,
V5.4.0 is not going to be released as a .zip file.&nbsp; I released it in SVN to meet a customer time scale, and users should be aware that the LPC1768 demos are not in a consistent state.
The change log, which I have also not published yet &#40;it will get published when the next .zip file is released&#41; looks like this:
Changes between V5.3.1 and V5.4.0 released July 7th 2009
&nbsp;&nbsp;&nbsp; + Added Virtex5 / PPC440 port and demos.
&nbsp;&nbsp;&nbsp; + Reworked byte alignment code to ensure 8 byte alignment works correctly.
&nbsp;&nbsp;&nbsp; + Set configUSE&#95;16&#95;BIT&#95;TICKS to 0 in the PPC405 demo projects.
&nbsp;&nbsp;&nbsp; + Changed the initial stack setup for the PPC405 to ensure the small data
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; area pointers are setup correctly.
</div></div><div class="thread-post"><h3 class="thread-post-title">V.5.4.0 Posting</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/jwestmoreland">jwestmoreland</a> on July 9, 2009</div><div class="thread-post-content">Richard,
Do you mean the byte alignment code in the demo&#8217;s or in the core?
Thanks,
John
</div></div><div class="thread-post"><h3 class="thread-post-title">V.5.4.0 Posting</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on July 9, 2009</div><div class="thread-post-content">heap&#95;1.c, heap&#95;2.c and tasks.c all have minor modifications.&nbsp; Heap&#95;1.c and heap&#95;2.c&nbsp; allow the heap structs to be 8 byte aligned &#40;4 was the max before&#41;.&nbsp; tasks.c ensures the top of stack is properly aligned when 8 byte alignment is used.&nbsp; These should not effect the MSP430 ports.
Regards.
