I&#8217;m using the V4.2.0 ARM7&#95;LPC2000 port of the FreeRTOS and am now getting the dabort irq on the first call to portSAVE&#95;CONTEXT.&nbsp; Previously I did not have this problem but I think I have changed something.&nbsp; I am using source code control but reverting to a previous commit doesn&#8217;t seem to help.&nbsp; I have been trying to work this out for a while now and have been browsing the forums for similar problems but have had no luck.&nbsp; Does anyone have any ideas to what I have done?&nbsp; Thanks in advance.
Nick

Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">dabort irq on 1st call to portSAVE_CONTEXT</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nixw">nixw</a> on July 5, 2009</div><div class="thread-post-content">Yes the kernel seems to have started correctly.&nbsp; The tick interrupt is working, memory seems to be successfully allocated to the tasks and the program runs into the last defined task.&nbsp; I&#8217;ll check the CPU mode asap.
</div></div><div class="thread-post"><h3 class="thread-post-title">dabort irq on 1st call to portSAVE_CONTEXT</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nixw">nixw</a> on July 6, 2009</div><div class="thread-post-content">In the current task the CPSR register shows that it is in System mode and just before portSAVE&#95;CONTEXT is called it is in Supervisor mode.&nbsp; I have to break it on the line &#8216;asm volatile &#40; &quot;ADD LR, LR, &#35;4&quot;&#41;;&#8217; else it will not break and the board needs to be disconnected from the PC to get it to work again.
Cheers
</div></div><div class="thread-post"><h3 class="thread-post-title">dabort irq on 1st call to portSAVE_CONTEXT</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nixw">nixw</a> on July 6, 2009</div><div class="thread-post-content">In the current task the CPSR register shows that it is in System mode and just before portSAVE&#95;CONTEXT is called it is in Supervisor mode.&nbsp; I have to break it on the line &#8216;asm volatile &#40; &quot;ADD LR, LR, &#35;4&quot;&#41;;&#8217; else it will not break and the board needs to be disconnected from the PC to get it to work again.
Cheers
</div></div><div class="thread-post"><h3 class="thread-post-title">dabort irq on 1st call to portSAVE_CONTEXT</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nixw">nixw</a> on July 6, 2009</div><div class="thread-post-content">I discovered that for some reason the CPU mode had changed to FIQ after power up and before vTaskStartScheduler was being called.&nbsp; This made me look at the start up files &#8216;Philips&#95;LPC230X&#95;Startup.s&#8217; and &#8216;crt0.s&#8217; and discovered that crt0.s had been changed &#40;particularly the supervisor set up for some unknown reason&#41; from the original project &#40;unfortunately not currently under revision control&#41;.&nbsp; Using the old version of the file from a backup fixed this problem.&nbsp;&nbsp; Thanks heaps for your help Richard.&nbsp; I wasn&#8217;t very familiar with the CPU modes and their use in OS design till you prompted me to look into it.&nbsp; Cheers.
