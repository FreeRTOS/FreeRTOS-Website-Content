  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Web server demo gets stuck.</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/teppo">teppo</a> on December 20, 2011</div><div class="thread-post-content">Hi,  
I am running Full demo on SmartFusion &#40; CORTEX&#95;A2F200&#95;SoftConsole &#41;, using FreeRTOS version 7.0.1 and Microsemi toolkit from Libero 9.1.  
The webserver of the Full demo enters occasionally enters infinite loop.<br />
The error is most likely caused by a long IP packet in my LAN. Flow of events:<br />
&#42; MSS&#95;MAC&#95;rx&#95;packet returns a negative number &#40; FreeRTOS/Demo/CORTEX&#95;A2F200&#95;SoftConsole/MicroSemi&#95;Code/drivers/mss&#95;ethernet&#95;mac/mss&#95;ethernet&#95;mac.c line 585&#41;<br />
&#42; vuIP&#95;task only handles positive return values &#40; FreeRTOS/Demo/CORTEX&#95;A2F200&#95;SoftConsole/uIP&#95;Task.c line 180 &#41;<br />
&#42; The supposedly-too-large packet is never acknowledged, and hence all subsequent packets are lost.<br />
&#42; webserver no longer serves anything, as IP receive queues is stuck.  
I do not know who generates the those too large packets in 1st packet; my LAN is large and noisy and the error is rather infrequent. Artificially they can be generated e.g. with ping -s  
Where and how should this be fixed ?<br />
The following seems to make the problem go away, but I am not sure if this is the best way.  
<pre><code>--- Demo/CORTEX_A2F200_SoftConsole/MicroSemi_Code/drivers/mss_ethernet_mac/mss_ethernet_mac.c  2011-12-20 16:12:18.000000000 +0200
+++ Demo/CORTEX_A2F200_SoftConsole/MicroSemi_Code/drivers/mss_ethernet_mac/mss_ethernet_mac.c  2011-12-20 16:12:54.000000000 +0200
@@ -582,6 +582,7 @@
         frame_length -= 4u;
         if( frame_length &gt; macBUFFER_SIZE ) {
+               MSS_MAC_prepare_rx_descriptor();
                return MAC_NOT_ENOUGH_SPACE;
         }
</code></pre>
</div></div><div class="thread-post"><h3 class="thread-post-title">Web server demo gets stuck.</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on December 20, 2011</div><div class="thread-post-content"><blockquote>
  &#42; MSS&#95;MAC&#95;rx&#95;packet returns a negative number &#40; FreeRTOS/Demo/CORTEX&#95;A2F200&#95;SoftConsole/MicroSemi&#95;Code/drivers/mss&#95;ethernet&#95;mac/mss&#95;ethernet&#95;mac.c line 585&#41;
</blockquote>
I&#8217;m not sure how that line could be hit, as macBUFFER&#95;SIZE appears to be large enough.&nbsp; Do you know how big frame&#95;length is when MAC&#95;NOT&#95;ENOUGH&#95;SPACE is returned?&nbsp; It might be that you can increase macBUFFER&#95;SIZE but it should not make any difference.&nbsp; If frame&#95;length is very large, or even just bigger than a valid Ethernet frame, then it could be a problem with the drivers configuration of the MAC interface, or just plain old data corruption somewhere.&nbsp; This is Actel/Microsemi code.  
<blockquote>
  &#42; vuIP&#95;task only handles positive return values &#40; FreeRTOS/Demo/CORTEX&#95;A2F200&#95;SoftConsole/uIP&#95;Task.c line 180 &#41;
</blockquote>
Ideally the driver should clean up then silently ignore bad data, but un-ideally you could extend the code here to look for error values coming back, and then to a manual clean up when they do.&nbsp; That would prevent you having to change the driver code.  
Regards.
