  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Measuring CPU usage?</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/ksoldavin">ksoldavin</a> on December 6, 2011</div><div class="thread-post-content">I have an application I am currently developing that requires me to report the CPU usage of the system periodically. I have my code compiled &#40;FreeRTOS 7.0.1, ARM7, IAR 6.2&#41; with the configGENERATE&#95;RUN&#95;TIME&#95;STATS flag set and I can display the stats off all tasks on my debug screen. What I am looking for is not the stats of each individual task but of the overall system. My thought was that if I can get the stats for the Idle task I can subtract the number from 100 and get the total CPU usage. My problem is that I do not know how, or if it is even possible, to get the usage stats of an individual task. One option would be to get the stats for all the tasks and parse out the idle task information but that would be a waste of resources which I don&#8217;t have.  
The one thing I tried, that didn&#8217;t seem to work well, is to set up idle and tick hook functions that incremented a uint32 variable every time they are entered. I used these values to try to calculate the percentage of time in idle. Unfortunately the values I calculated did not correspond to the RTOS task stats.  
Does anyone have any suggestions?<br />
Thanks<br />
Keith
</div></div><div class="thread-post"><h3 class="thread-post-title">Measuring CPU usage?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on December 6, 2011</div><div class="thread-post-content">You can use the traceTASK&#95;SWICHED&#95;IN macro.  
In the macro, if pxCurrentTCB equals the handle of the idle task, then you know the idle task has just been switched in and you can start a high frequency timer &#40;or note the time of a free running high frequency timer&#41;. If the idle task was running, and pxCurrentTCB is no longer the idle task, you know the idle task has just been switched out and you can stop the high frequency timer and note the elapsed time &#40;or again note the time of a free running high frequency timer&#41;.  
If you use FreeRTOS 7.0.2 and define INCLUDE&#95;xTaskGetIdleTaskHandle to 1 in FreeRTOSConfig.h, then you can use xTaskGetIdleTaskHandle&#40;&#41; after the scheduler is started to get the idle task handle.
