</div></div><div class="thread-post"><h3 class="thread-post-title">PIC32 MPLAB Demo stops</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on April 3, 2012</div><div class="thread-post-content">Could this be related to the CPU&#8217;s use of shadow registers.&nbsp; The newer PIC32 CPU&#8217;s require an extra &#35;pragma  
<pre><code>#pragma config FSRSSEL = PRIORITY_7
</code></pre>
This says interrupt priority 7 should use the shadow registers &#8211; in which case you should just avoid using interrupt priority 7.&nbsp; The older CPU&#8217;s don&#8217;t use the shadow registers, and therefore don&#8217;t need this pragma.

Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">PIC32 MPLAB Demo stops</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on May 5, 2012</div><div class="thread-post-content">If anybody is still reading this thread….  
After three days of debugging, this problem <em>seems</em> related to the different way the lines of C code that clear timer interrupts in the interrupt nesting test are converted into asm code between the compiler versions.&nbsp; Both lines are in file FreeRTOS/Demo/PIC32MX&#95;MPLAB/IntQueueTimer.c:  
Line 113:&nbsp; IFS0bits.T3IF = 0;  
Line 120:&nbsp; IFS0bits.T4IF = 0;  
The lines can be replaced with:  
Line 113:&nbsp; IFS0CLR = &#95;IFS0&#95;T3IF&#95;MASK;  
and   
Line 120:&nbsp; IFS0CLR = &#95;IFS0&#95;T4IF&#95;MASK;  
Let me know if this fixes it for you.  
Regards.
