  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Lib with conditional compiling&#8230;</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/ulmus71">ulmus71</a> on February 22, 2012</div><div class="thread-post-content">I have some library i want conditionaly compile: with or without freertos.<br />
What is the best defined const&nbsp; in FreeRTOS to use with &#8216;&#35;ifdef xxxxx&#8217; statement?  
&#35;ifdef INC&#95;FREERTOS&#95;H<br />
or something else?  
</div></div><div class="thread-post"><h3 class="thread-post-title">Lib with conditional compiling&#8230;</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on February 22, 2012</div><div class="thread-post-content">You are going to have to add some define to tell you source code if you want to use FreeRTOS or not. The issues is that you will want to conditionally include the needed FreeRTOS headers based on this. This of course means you will need to build two versions of your library &#40;one with and one without this define&#41; and link to the appropriate version.  
Otherwise you are going to run into a chicken and egg issue, to try and test a FreeRTOS define, you will have to know if you need to include the FreeRTOS headers before you have included the headers that would define the symbol. The only way to do that would be to use some compiler option to force the inclusion of the base FreeRTOS header at the start of your program. It is probably better to add the define in your compiler config &#40;something like -DFREERTOS&#41; than to force the header inclusion.  
It is generally impossible to have the library check at link time to see if the rest of the program is using a software package and somehow &#8220;automagically&#8221; change the code of the library based on this, you need to pre-generate the different versions of the library, then there MAY be a way to select which library to use, or you need to change which library is specifed in the link options. 
</div></div><div class="thread-post"><h3 class="thread-post-title">Lib with conditional compiling&#8230;</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/ulmus71">ulmus71</a> on February 22, 2012</div><div class="thread-post-content">I was not so clear i&#8217;d wanted to. When i was saying &#8216;library&#8217; i was thinking about source library &#40;&#42;.c, &#42;.h files&#41;, not precompiled library.
</div></div><div class="thread-post"><h3 class="thread-post-title">Lib with conditional compiling&#8230;</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on February 22, 2012</div><div class="thread-post-content">If you have .c files, it does&#8217;t really make a difference. Each .c file is generally compiled independently, so it can not tell if the FreeRTOS files are being used by other .c files. You are still going to need to add some define in the compliers configuration to tell it that you are using FreeRTOS or not. If your library is a &#8220;pure header&#8221; library &#40;which is unusual in C, it means ALL operations need to be with inline functions, and any globals needed will need to be setup by the user&#41; then you could require it to be include after the include of FreeRTOS.h and detect the INC&#95;FREERTOS&#95;H define, but that could lead to interesting problems if the user make a mistake and puts it before the include.  
An older style of using FreeRTOS was to define a variable in the compiler &#40;with a forced define&#41; to indicate which port to use, and you could use that to select. The more recent standard is to just put the appropriate port directory on the include path, which won&#8217;t help you. That is why I suggest you select for yourself a configuration define to allow you to detect if you are going to use FreeRTOS or not.  
The other option is to use a &#8220;porting&#8221; layer.&nbsp; If you can define your library based on some generic interface, and then have a porting .h/.c file&#40;s&#41; that define that interface to the environment you are targeting to. You then do like FreeRTOS and add the appropriate sub directory to the include path, and maybe need to add the appropriate myport.c to your project. &#40;this assumes that your design doesn&#8217;t radically differ based on targeted environment, although since that myport.h would include FreeRTOS.h if you were using FreeRTOS, you could then check for INC&#95;FREERTOS&#95;H being defined.&nbsp;
