</div></div><div class="thread-post"><h3 class="thread-post-title">STMF4 taskyield() help</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on February 28, 2012</div><div class="thread-post-content">I&#8217;m not going to download at look at somebody elses port, only the official STM32F4 demo is supported &#40;<a href="http://www.freertos.org/FreeRTOS-for-STM32F4xx-Cortex-M4F-IAR.html%29">http://www.freertos.org/FreeRTOS-for-STM32F4xx-Cortex-M4F-IAR.html&#41;</a> but will comment on the rest of your post.  
Calling taskYIELD&#40;&#41; only offers to give up processing time to a task of equal priority, it will not cause the task to be blocked if there are not tasks of equal priority, and will definitely not cause the idle task to run if the task calling taskYIELD&#40;&#41; has a priority above the idle priority.

</div></div><div class="thread-post"><h3 class="thread-post-title">STMF4 taskyield() help</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on February 29, 2012</div><div class="thread-post-content">The Debug task will be spending most of its time suspended in the xQueueReceive&#40;xDebugQueue&#41; call when the output is ready to send a character but your queue doesn&#8217;t have anything to send.  
It would be much better to make the Serial port interrupt driven where the sender puts the characters in the queue &#40;and kick starts the port if needed&#41;, and the serial interrupt pulls the characters out of the queue, and serial input stuffs the characters received into a queue and the receiving task waits on the queue for data.   
Having polling loops is normally a sign that you aren&#8217;t doing things right. &#40;The exceptions are if you need to busy wait for something that WILL happen very quickly, faster than a context switch, or need to wait on a flag that can&#8217;t generate an interrupt&#41;.

</div></div><div class="thread-post"><h3 class="thread-post-title">STMF4 taskyield() help</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on February 29, 2012</div><div class="thread-post-content">Your question is a bit confusing, but as soon as the higher priority tasks suspends, the next highest available task will start. If this is the Idle task, it will start to run where it left off, which is a loop cleaning up resources from deleted tasks and calling vApplicationIdleHook. There is no &#8220;minimum delay&#8221; to get to the idle hook, it might run many times in a tick
