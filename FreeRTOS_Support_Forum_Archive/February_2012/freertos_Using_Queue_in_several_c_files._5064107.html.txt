</div></div><div class="thread-post"><h3 class="thread-post-title">Using Queue in several c files.</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on February 24, 2012</div><div class="thread-post-content">Since the code is in two files, make sure the queue handle is in a global and both files are accessing the same exact variable. if a file declares that handle as static, or inside of a function, then the other file will use a different version of the variable even if they have the same name.  
there should probably be an extern declaration in a header they both include, and a global definition in just one file.

</div></div><div class="thread-post"><h3 class="thread-post-title">Using Queue in several c files.</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/paulgcoleman">paulgcoleman</a> on February 27, 2012</div><div class="thread-post-content">Is your problem caused by the fact that you are not returning xHigherPriorityTaskWoken from your ISR? I had a similar problem where a task wasn&#8217;t responding to a queue and it was because I didn&#8217;t understand how that mechanism works and therefore the task was not getting unblocked. My ISRs all have the following format…  
&#95;&#95;attribute&#95;&#95;&#40;&#40;&#95;&#95;noinline&#95;&#95;&#41;&#41;<br />
portBASE&#95;TYPE IntHandlerNonNaked&#40;void&#41;<br />
&#123;<br />
portBASE&#95;TYPE xHigherPriorityTaskWoken = pdFALSE;   
portENTER&#95;CRITICAL&#40;&#41;;<br />
xQueueSendFromISR&#40;…, &amp;xHigherPriorityTaskWoken&#41;;<br />
portEXIT&#95;CRITICAL&#40;&#41;;  
return xHigherPriorityTaskWoken;&nbsp;&nbsp;&nbsp; // this does actually get used&#33;&#33;&#33;&#33;<br />
&#125;  
&#95;&#95;attribute&#95;&#95;&#40;&#40;&#95;&#95;naked&#95;&#95;&#41;&#41;<br />
void IntHandler&#40;void&#41;<br />
&#123;<br />
portENTER&#95;SWITCHING&#95;ISR&#40;&#41;;<br />
IntHandlerNonNaked&#40;&#41;;<br />
portEXIT&#95;SWITCHING&#95;ISR&#40;&#41;;<br />
&#125;  
It looks as though return xHigherPriorityTaskWoken doesn&#8217;t actually get used but it does&#33;&#33;&#33; The macro portEXIT&#95;SWITCHING&#95;ISR retrieves the value directly from the register. All of this is port specific so you need to check the demo for your particular architecture.  
Paul.
