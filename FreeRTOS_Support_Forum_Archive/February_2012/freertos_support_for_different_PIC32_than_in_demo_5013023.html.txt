  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">support for different PIC32 than in demo</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/macieksaczuk">macieksaczuk</a> on February 12, 2012</div><div class="thread-post-content">Hi,<br />
PIC32MX360F512L was used in the demo project. Another part PIC32MX795F512L is used in projects from the &#8216;Using the FreeRTOS Real Time Kernel PIC32 Edition&#8217; book &#40;that I&#8217;ve just purchased&#41;.<br />
Is it simple to run the demo projects on some other PIC32 parts &#40;like PIC32MX564F064H for example&#41; ?<br />
And what should be changed ?  
Thanks for help<br />
Maciek
</div></div><div class="thread-post"><h3 class="thread-post-title">support for different PIC32 than in demo</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on February 12, 2012</div><div class="thread-post-content">The kernel itself should run on any PIC32 part, although the application code may have to change slightly when moving between parts.&nbsp;   
For example, if you look at the configuration bit settings in main&#40;&#41; for the two projects you reference in your original post you will see the 795 part has an extra option &#40;although I think that is no longer necessary with the latest parts/tools because it is defaulted to the required setting anyway now&#41;.&nbsp; Also, the interrupt behaviour is different between the two parts, which means the UART example on the 360 does not run on the 795 because how/where the interrupt is clears in the ISR itself has to change.&nbsp;   
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">support for different PIC32 than in demo</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/macieksaczuk">macieksaczuk</a> on February 12, 2012</div><div class="thread-post-content">Thanks for the response. Thanks for help<br />
Maciek
