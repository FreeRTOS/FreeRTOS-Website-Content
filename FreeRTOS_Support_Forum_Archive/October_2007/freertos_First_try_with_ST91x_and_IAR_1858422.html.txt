</div></div><div class="thread-post"><h3 class="thread-post-title">First try with ST91x and IAR</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/sotd">sotd</a> on October 31, 2007</div><div class="thread-post-content">search through this forum for topics of IAR 5.&nbsp; Basically all the FreeRTOS projects use the new v4 that was released at the same time as V5.&nbsp; This is as V5 does not yet support cortex mcu.&nbsp; You can download the latest v4 from IAR.&nbsp; If you have change the startup code to enable V5 use then make sure that you set the code such that supervisor mode is used to call main.&nbsp; This might fix your problem.
</div></div><div class="thread-post"><h3 class="thread-post-title">First try with ST91x and IAR</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/soundso">soundso</a> on October 31, 2007</div><div class="thread-post-content">Thanks for the tip. I continued trying it with IAR 5 and i allready found the first problem. vTaskStartScheduler was not called in supervisor-mode but uncommenting a line at the startup-file solved this. Now the higherprior task is executed, but there is no scheduling and switching to other tasks. I also changed the SWI&#95;Addr to vPortYieldProcessor, but i think theres the problem&#8230; Can anybody tell me what to do at the startup to configure everything right?&#33;
</div></div><div class="thread-post"><h3 class="thread-post-title">First try with ST91x and IAR</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on October 31, 2007</div><div class="thread-post-content">There are two methods of installing interrupts that can cause a context switch that are used by FreeRTOS.org for ARM7/9 devices.&nbsp; The first is to have a common entry point that saves the task context then calls a standard c function to perform the processing, before restoring the context of the next task to run.&nbsp; The second is to vector directly to the handler for the interrupting peripheral, then have this handler save and restore the context if necessary.&nbsp; The STR9 demo uses the first method.
If you look in 91x&#95;vect&#95;IAR.s you will see the function IRQHandler.&nbsp; Have you moved this across to your IAR version 5 project?&nbsp; I have not used version 5 yet because I can&#8217;t have two versions on my computer at the same time, and need IAR to also compile for Cortex-M3.&nbsp; The version 5 is only a half way house thus far.
