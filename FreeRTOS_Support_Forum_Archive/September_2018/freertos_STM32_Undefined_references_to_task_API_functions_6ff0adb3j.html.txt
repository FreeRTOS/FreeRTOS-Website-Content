  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">[STM32] Undefined references to task API functions</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/dpakp">dpakp</a> on September 20, 2018</div><div class="thread-post-content">Hi everyone,
I am trying to get FreeRTOS 10.1.1 compiling without using STM32Cube for an STM32F413 using Atollic TrueSTUDIO, but I have two compilation errors in my main function, given below. We are choosing not to use STM32Cube for our project.
The errors are:
<ul>
<li>Undefined reference to &#8216;xTaskCreate&#8217;</li>
<li>Undefined reference to &#8216;vTaskStartScheduler&#8217;</li>
</ul>
Going to the declarations of both functions in <code>task.h</code> shows that both are simply marked as <code>PRIVELEGED FUNCTION</code>.  However, both functions are defined properly in <code>tasks.c</code>. This is true both in FreeRTOS 10.1.1 and in the FreeRTOS 9.0.0 that comes in STM32Cube, but for some reason TrueSTUDIO has no trouble compiling a FreeRTOS 9.0.0-based project generated by STM32Cube.
How can I get these API calls to work? I.E. how do I make sure that the correct definitions in <code>tasks.c</code> are used instead of the <code>PRIVELEGED FUNCTION</code> declarations in <code>task.h</code>?
main.c below:
~~~
:::C
<h1>include &lt;stdint.h></h1>
<h1>include &#8220;stm32f4xx.h&#8221;</h1>
<h1>include &#8220;stm32f4xx_hal.h&#8221;</h1>
<h1>include &#8220;FreeRTOS.h&#8221;</h1>
<h1>include &#8220;task.h&#8221;</h1>
<h1>include &#8220;my_tasks.h&#8221;</h1>
int main(void) {
    systemClockConfig();
<pre><code>// https://www.freertos.org/RTOS-Cortex-M3-M4.html
HAL_NVIC_SetPriorityGrouping( NVIC_PRIORITYGROUP_4 );
// Make tasks here
xTaskCreate( vMyLEDTask, "LED", configMINIMAL_STACK_SIZE, NULL, 1, NULL );
vTaskStartScheduler();
</code></pre>
}
~~~
</div></div><div class="thread-post"><h3 class="thread-post-title">[STM32] Undefined references to task API functions</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on September 20, 2018</div><div class="thread-post-content">These functions are always available provided tasks.c is being built &#8211; double check that is the case.
</div></div><div class="thread-post"><h3 class="thread-post-title">[STM32] Undefined references to task API functions</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/dpakp">dpakp</a> on September 20, 2018</div><div class="thread-post-content">Thank you for the heads up, after some Googling I was able to solve the issue. The problem is with TrueSTUDIO (which is based on Eclipse), not FreeRTOS.
The directory containing tasks.c is included in the compiler settings within TrueSTUDIO. Additionally, the xTaskCreate function definition is inside an <code>#if( configSUPPORT_DYNAMIC_ALLOCATION == 1 )</code> section, and my <code>FreeRTOSConfig.h</code> file does indeed have this macro set to 1.
The problem was that the FreeRTOS folder was excluded from the build because I did not add it as a <strong>source folder</strong> in Eclipse. Apparently if you add a new regular folder it will automatically be excluded from the build. See the attached screenshot, where &#8220;myFolder&#8221; was added as a regular folder, not a source folder. You can see there is no &#8220;C&#8221; in the folder icon, and if you right-click on the folder, go to Resource Configurations->Exclude from Build, it will show that the folder is excluded in all your builds configurations. Uncheck these boxes and you will see the &#8220;C&#8221; appear in the folder icon, and TrueSTUDIO will now include the files in &#8220;myFolder&#8221; in the next build.
<a href="https://stackoverflow.com/questions/51498765/truestudio-compilation-error-for-freertos-compilation-on-stm32">Here is a link to a stack overflow post that helped me with this.</a>
