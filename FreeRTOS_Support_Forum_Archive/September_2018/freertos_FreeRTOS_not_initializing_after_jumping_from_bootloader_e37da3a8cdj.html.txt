  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">FreeRTOS not initializing after jumping from bootloader</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/mslavov">mslavov</a> on September 28, 2018</div><div class="thread-post-content">Hello,
I have been developing a firmware application for our STM32F746 &#8211;  based product. 
The idea idea to have a bootloader code that can do firmware update and/or jump to the application.
I have been using IAR Embedded Workbench for my development, with Cortex-M7 / ST STM32F746VG as target CPU
The bootloader code is loaded at address 0x08000000, and the application &#8211; at address 0x08080000 in internal flash.
This is my initial buttloader code; it is not using any external libraries, and not doing any extra operations yet (this would be added later):
//&#8212;&#8212;
/*
       STM32F746
       Flash:                   0x08000000 &#8211; 0x080FFFFF (1 MB)
       Bootloader:      0x08000000 &#8211; 0x0807FFFF (5212KB)
       Application:     0x08080000 &#8211; 0x080FFFFF (512KB)
 */
<h1>include &lt;stdio.h>**</h1>
<h1>include &lt;stdint.h></h1>
<h1>include &lt;intrinsics.h></h1>
<h1>include &#8220;stm32f7xx.h&#8221;      // STM32F746VG Cortex-M7 Device</h1>
<h1>include &lt;core_cm7.h>       // STM32F746VG Cortex-M7 Core</h1>
typedef void (application_t) (void);
extern const uint32<em>t app</em>vector;   // Application vector address symbol from 
                                                                               // the linker configuration file: 0x08080000
typedef struct vector
{
    uint32<em>t        stack</em>addr;     // intvec[0] is initial Stack Pointer
    application<em>t   *func</em>p;        // intvec[1] is initial Program Counter
} vector_t;
int main(void)
{
    const vector<em>t *vector</em>p  = (vector<em>t*) &amp;app</em>vector;
    volatile uint32<em>t stack</em>arr[100]  = {0};  // Allocate some stack just to show that
                                                                                           // the SP should be reset  before the jump &#8211; or the
                                                                                           // stack won&#8217;t be configured correctly.
    __enable<em>interrupt();
    printf(&#8220;Hello from bootloader!n&#8221;);
   __disable</em>interrupt();                                         // 1. Disable interrupts
    __set<em>SP(vector</em>p->stack<em>addr);               // 2. Configure stack pointer
    SCB->VTOR = (uint32</em>t) &#038;app<em>vector; // 3. Configure VTOR
    vector</em>p->func_p();                                            // 4. Jump to application
}
//&#8212;&#8212;
And this is my application&#8217; main() function; it is using STM HALL library ant FreeRTOS libtrary (it is a multitasking application)
//&#8212;&#8212;
int main(void)
{
    printf(&#8220;Hello from application!n&#8221;);
<pre><code>/* Enable the CPU Cache */
CPU_CACHE_Enable();
</code></pre>
   /* Reset of all peripherals, Initializes the Flash interface and the Systick. */
    HAL_Init();
<pre><code>/* Configure the system clock */
SystemClock_Config();
/* Several modules initialization */
/* ...... */
/* Call init function for freertos objects (in freertos.c) */
MX_FREERTOS_Init();
/* Start scheduler */
osKernelStart();
/* We should never get here as control is now taken by the scheduler */
while ( 1 );
</code></pre>
}
//&#8212;&#8212;
The jump to application is successfull, and everything executes ok until &#8220;MX<em>FREERTOS</em>Init();&#8221;
I was able to trace the issue to:
MX<em>FREERTOS</em>Init() ->
    myMutex01Handle = osMutexCreate(osMutex(myMutex01)); ->
         return xSemaphoreCreateMutex();  = xQueueCreateMutex( queueQUEUE<em>TYPE</em>MUTEX ); ->
             xQueueGenericCreate( uxMutexLength, uxMutexSize, ucQueueType ); ->
                   pvPortMalloc( sizeof( Queue<em>t ) + xQueueSizeInBytes ); ->
                         ( void ) xTaskResumeAll(); ->
                               taskENTER</em>CRITICAL() = portENTER<em>CRITICAL() = vPortEnterCritical() ->
                                         portDISABLE</em>INTERRUPTS();   // stalls here!
I broke the last macro into containing functions:
    __disable<em>interrupt();<br />
    __set</em>BASEPRI( configMAX<em>SYSCALL</em>INTERRUPT<em>PRIORITY );<br />
    __DSB();<br />
    __ISB();<br />
    __enable</em>interrupt();   
The code run stalls in the last instruction: __enable_interrupt();
Any idea what can be frong?
Note: If the application is loaded at address 0x08000000 (no bootloader), it runs OK.
-Thanks!
