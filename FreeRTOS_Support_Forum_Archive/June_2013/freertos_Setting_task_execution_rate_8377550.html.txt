Investigating using FreeRTOS in an upcoming project. I&#8217;ve searched the forums and the documentation, as best I&#8217;m able being unfamiliar with the project, but can&#8217;t find an answer to my most important question.  
How can one set the rate at which a task is executed?  
I guess that I should ask, is this even possible?  
Example; In my code &#40;using µC/OS-II&#41; I have a 200Hz &#40;highest priority&#41;, 100Hz &#40;middle priority&#41;, and 10Hz &#40;lowest priority&#41; task. These tasks need to execute at precisely these frequencies.  
How would this be done in FreeRTOS?   
Of course an example would be ideal :&#41;, but a pointer to the correct general location in the documentation would be helpful.  
Kevin
</div></div><div class="thread-post"><h3 class="thread-post-title">Setting task execution rate</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on June 1, 2013</div><div class="thread-post-content">To create a periodic task with good accuracy you can use <a href="http://www.freertos.org/vtaskdelayuntil.html">vTaskDelayUntil&#40;&#41;</a>.  
There is also the slightly simpler <a href="http://www.freertos.org/a00127.html">vTaskDelay&#40;&#41;</a>, but that delays relative to when the function is called rather than relative to an absolute time.  
Depending on what the code is doing,&nbsp; you may also be able to use a <a href="http://www.freertos.org/RTOS-software-timer.html">software timer</a> in place of a task.  
Block/delay times are specified in ticks.&nbsp; Provided the tick period &#40;set by configTICK&#95;RATE&#95;HZ in FreeRTOSConfig.h&#41; is less than 1KHz then you can convert milliseconds into ticks by dividing by portTICK&#95;RATE&#95;MS.&nbsp; So delaying for 200ms can be achieved by calling vTaskDelay&#40; 200 / portTICK&#95;RATE&#95;MS &#41;;  
With regards to priority then that is set when the <a href="http://www.freertos.org/a00125.html">task is created</a>, with 0 being the lowest priority &#40;makes sense, it is the lowest number…&#41; and the maximum priority being set by the FreeRTOSConfig.h constant configMAX&#95;PRIORITIES.&nbsp; Therefore the highest priority is &#40; configMAX&#95;PRIORITIES &#8211; 1 &#41;.&nbsp; Task priorities can be changed at run time too.  
Hope this helps.  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">Setting task execution rate</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/edwards3">edwards3</a> on June 1, 2013</div><div class="thread-post-content">Look at prvQueueSendTask&#40;&#41; on this page <a href="http://www.freertos.org/Hardware-independent-RTOS-example.html.">http://www.freertos.org/Hardware-independent-RTOS-example.html.</a> It runs at 5Hz.
</div></div><div class="thread-post"><h3 class="thread-post-title">Setting task execution rate</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/ksweeney21">ksweeney21</a> on June 3, 2013</div><div class="thread-post-content">Let me describe how I set thread execution rate now and perhaps you can tell me if something similar is possible in FreeRTOS .  
Assume that the system tick rate is set at 200Hz.<br />
At the start of every task I acquire a semaphore for that task, Sem200Hz, for example, for the 200Hz task.<br />
In µC/OS-II there is a function that is user modifiable and called at every system tick.   
<pre><code>void OSTimeTickHook (void)
{    
    OSSemPost(Sem200Hz); //release semaphore
    if(!(TickCount % 2))
    {
        OSSemPost(Sem100Hz); //release semaphore
    }
    if(!(TickCount % 20))
    {
        OSSemPost(Sem10Hz); //release semaphore
    }
}
</code></pre>
Works well in my application. Would this be possible in FreeRTOS ?  
Kevin
</div></div><div class="thread-post"><h3 class="thread-post-title">Setting task execution rate</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on June 3, 2013</div><div class="thread-post-content">You can do exactly the same in FreeRTOS, but I would really not recommend that structure because you are greatly increasing the execution time of every tick interrupt, especially when you are doing mod divides in the interrupt.&nbsp; Also, you are manually scheduling tasks, which defeats the object of using a scheduler in the first place.&nbsp; If you absolutely must do it that way, then the equivalent would be:  
In FreeRTOSConfig.h:<br />
&#35;define configUSE&#95;TICK&#95;HOOK 1  
In any C file:  
<pre><code>void vApplicationTickHook( void )
{
/* Could also use a static count in the hook function instead of getting the tick count. */
portTickType xTickCount = xTaskGetTickCountFromISR();
    [url=http://www.freertos.org/a00124.html]xSemaphoreGiveFromISR[/url]( Sem200Hz, NULL );
    /* Avoid mod divide. */
    if( ( xTickCount &amp; 0x01 ) == 0 )
    {
        xSemaphoreGiveFromISR( Sem100Hz, NULL );
    }
    /* Etc. */
}
</code></pre>
Note FreeRTOS uses data hiding &#40;standard engineering good practice&#41; so the tick count cannot be accessed directly.&nbsp; Also to ensure the fastest and simplest interrupt entry and exit code, and the smallest code size, there is a separate API for use in interrupts.&nbsp; Therefore, because the tick hook is called from an interrupt context, the &#8220;FromISR&#8221; versions of the API are being used.  
Regards.
