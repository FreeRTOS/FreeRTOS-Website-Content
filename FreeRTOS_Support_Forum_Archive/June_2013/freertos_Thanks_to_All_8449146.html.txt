</div></div><div class="thread-post"><h3 class="thread-post-title">Thanks to All!</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/groufosse">groufosse</a> on June 26, 2013</div><div class="thread-post-content">Hi John,  
I found it fairly straightforward to do, so you&nbsp; need to have used both tool sets to some degree already&#33;<br />
It&#8217;s really as simple as creating at least on task in FreeRTOS as the &#8220;visualState&#8221; handling task, and should be running at an interval appropriate the the events occurring in your application. Mine runs at 243ms. I pick task numbers that don&#8217;t occur at even intervals with others.&nbsp; 8~0<br />
When created this task will handle the vS events generated by your state machine, or you can &#8220;throw&#8221; events. You&#8217;ll create a &#8220;vS User&#8221; module of C/C++ functions that are &#8220;action functions&#8221; that are called upon specific events occurring. Within these action functions are then perhaps calls into various FreeRTOS functions, such as queue creation, task creation, etc. For asynchronous messaging, I found the FreeRTOS queue mechanism very good and reliable.<br />
The only other note of caution is adjusting stack sizes appropriately. if you get mysterious crashes &#40;or, WDT timeouts as I use the WDT on mine&#41; start looking to task sizes. Another is task pointers; find a method to track them as they can cause grief if not managed right &#40;as you may already know&#41;  
Regards,<br />
Gary
