  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">webserver slow after flash write</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/pierreculot">pierreculot</a> on June 17, 2013</div><div class="thread-post-content">Hello,  
I use FreeRTOS and lwIP for a webserver on STM32F217. The web page is used to change settings that are stored in flash &#40;on the last page which is free&#41;.<br />
The problem is that after the update to flash the webserver is very slow.<br />
The erase time the page is very long &#40;depending datasheets can go up to several seconds&#41;.<br />
For now the update of the flash is a sub-function of the Webserver task.  
I see this alternative:<br />
Save the page in RAM &#40;RAM backup area eg.&#41; And create a separate save RAM to flash task.  
Is there are others?<br />
Thank you. Pierre
</div></div><div class="thread-post"><h3 class="thread-post-title">webserver slow after flash write</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on June 17, 2013</div><div class="thread-post-content">Do you mean the web server is very slow while the flash is being written to?  
I&#8217;m afraid I don&#8217;t have any experience of writing to flash while executing a program on that or other part.&nbsp; The only way I have done it before is to run code from RAM while the flash is being programmed, but normally you can only fit a small amount of code in RAM, just the function that does the actual re-programming.&nbsp; Other than suggesting you have the flash writing performed in a task other than the lwIP task I&#8217;m not sure what to suggest &#40;the write can be initiated by the lwIP task, but performed by another task&#41;.  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">webserver slow after flash write</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/jdurand">jdurand</a> on June 17, 2013</div><div class="thread-post-content">I&#8217;m starting to use microSD cards embedded instead of regular flash chips. They have built-in wear leveling and as long as you don&#8217;t do a bulk erase they&#8217;re decently fast at saving.  
With any flash or EEPROM type device, they&#8217;re fastest if you can do multiple block writes.&nbsp; You have to keep things aligned to the pages or sectors in the part but you fill the device&#8217;s buffer and then it writes it all at once.  
I found a nice holder for micro SD that&#8217;s intended for this application &#40;insert memory when you assemble the PC board and then forget it&#41;.&nbsp;&nbsp; ALPS &#35;SCHD3A0100 , Mouser.com has them.  
I also found out an old Kingston brand card I have has a bad CRC in one of their tables…always a surprise someplace.  
</div></div><div class="thread-post"><h3 class="thread-post-title">webserver slow after flash write</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/pierreculot">pierreculot</a> on June 17, 2013</div><div class="thread-post-content">Dear Richard,  
<blockquote>
  Do you mean the web server is very slow while the flash is being written to?
</blockquote>
Not only, after writing in flash all the lwip stack becomes slow. One ping takes hundred of ms instead one ms.  
It seems the systick for FreeRTOS follow to run while the flash writing.  
About the SD card, you are right, I use it for another project with success but here there are econnomic constraints and it is just for a fifteen of bytes. And probably one rewrite by card in its live.<br />
Pierre
</div></div><div class="thread-post"><h3 class="thread-post-title">webserver slow after flash write</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/jdurand">jdurand</a> on June 17, 2013</div><div class="thread-post-content">For 15 bytes I&#8217;d use one of the very small EEPROMS, 1 k Bit ones go for $0.20 in single piece &#40;US dollars&#41;.  
If it&#8217;s going to be erased only a few times, just dedicate a segment of your processor Flash memory and sequentially write updates &#40;no need to actually erase anything, only add a new record like a multi-session CD&#41;.
</div></div><div class="thread-post"><h3 class="thread-post-title">webserver slow after flash write</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/pierreculot">pierreculot</a> on June 18, 2013</div><div class="thread-post-content">Finally the problem is in the driver ethernetif.c.<br />
