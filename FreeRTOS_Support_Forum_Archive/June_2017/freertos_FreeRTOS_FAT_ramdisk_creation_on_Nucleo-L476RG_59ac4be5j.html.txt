</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS+FAT ramdisk creation on Nucleo-L476RG</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on June 4, 2017</div><div class="thread-post-content">Sachin, sure it is possible to have a very small volume.
You have to overrule the MS standards though, which define the minimum amount of clusters for FAT16 ( or FAT32 ).
~~~
<h1>ifdef ffconfigMIN<em>CLUSTERS</em>FAT32</h1>
<pre><code>#define MIN_CLUSTER_COUNT_FAT32        ffconfigMIN_CLUSTERS_FAT32
</code></pre>
<h1>else</h1>
<pre><code>#define MIN_CLUSTER_COUNT_FAT32        ( 65525 )
</code></pre>
<h1>endif</h1>
<h1>ifdef ffconfigMIN<em>CLUSTERS</em>FAT16</h1>
<pre><code>#define MIN_CLUSTERS_FAT16            ffconfigMIN_CLUSTERS_FAT16
</code></pre>
<h1>else</h1>
<pre><code>#define MIN_CLUSTERS_FAT16            ( 4085 + 1 )
</code></pre>
<h1>endif</h1>
~~~
Have a try with FAT16 and define <code>ffconfigMIN_CLUSTERS_FAT16</code> very low:
~~~
    #define ffconfigMIN<em>CLUSTERS</em>FAT16    32
~~~
Within <code>ff_ramdisk.c</code> you might want to decrease <code>ramHIDDEN_SECTOR_COUNT</code>, I think that zero should work.
Also, for FAT16, you will have a root directory which can contain up to 512 entries. Not sure if you need that many?
~~~
    ucFATType = FF<em>T</em>FAT16;
    iFAT32RootClusters = 0;
    ulFATReservedSectors = 1u;
    iFAT16RootSectors = 32; /* to get 512 dir entries */
~~~
You could make <code>iFAT16RootSectors</code> lower, and <code>ulFATReservedSectors</code> as zero.
Please report back, good luck!
