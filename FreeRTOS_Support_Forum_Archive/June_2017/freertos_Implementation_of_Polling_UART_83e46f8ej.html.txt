  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Implementation of Polling UART</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/groger57">groger57</a> on June 22, 2017</div><div class="thread-post-content">I currently have a function that can be called from 3 tasks. The function includes some string formatting for a screen. Inside this function is a semaphore that encapsulates all the formatting. From within that, I use sendQueue to send messages to a UART. I have a dedicated structure for the send and receive queues. It contains a string buffer of 50, and a single uint8. However &#8211; it is failing to take the semaphore quite often, even with a 1000ms wait. 
aFunction( &#8230; )
{
if( xSemaphoreTake( xMutexUARTaccess, 1000 ) == pdPASS )<br />
{
    //&#8230;some stuff
   xQueueSend( mssgQueue, (void*)&amp;queMssg, 500); 
}
else
{
    //&#8230;semaphore was not obtained&#8230;
    printf(&#8220;Semaphore not taken.n&#8221;);
}
}
The receiveQueue task uses a send and poll, like this:
<pre><code>xStatus = xQueueReceive( xQueue, &amp;queMssg, 1000 );   
    if( xStatus == pdPASS )
    {
        volatile uint16_t rxCode = 0x0;
        char *s = &amp;queMssg.message[0];
        while(*s)
        {
            while( USART_GetFlagStatus(USART2, USART_FLAG_TXE ) == RESET); 
            USART_SendData(USART2, *s++);
        }    
        while(1) // poll response
        {
            while( USART_GetFlagStatus( USART2, USART_FLAG_RXNE) == RESET ); 
            rxCode = USART_ReceiveData( USART2 ); 
            if( rxCode == RCVD_PROMPT )
            {
                //one more for 0xD (end of message)
                while( USART_GetFlagStatus( USART2, USART_FLAG_RXNE) == RESET ); 
                rxCode = USART_ReceiveData( USART2 );                         
                break;
            } 
        }
    }
</code></pre>
Using this method, what could be the reason for the semaphore not to be taken so often, given the long number of ticks to wait? 
Further, is there a better way to implement the UART send and receive? Should they use a send and receive queue on their own, rather than encapsulating them as above? 
Thank you for any advice or help.
</div></div><div class="thread-post"><h3 class="thread-post-title">Implementation of Polling UART</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on June 22, 2017</div><div class="thread-post-content">Hi Roger,
you take <code>xMutexUARTaccess</code>, but in the code shown, you never release it?
Beside that, queues do not need to be protected by a mutex. All queue access functions are &#8220;thread safe&#8221;, they will temporarily suspend the scheduler, or enter a critical section when necessary.
~~~
aFunction( &#8230; )
{
        //&#8230;some stuff
        /* xQueueSend will either send the message,
        or it will time-out after 500 clock-ticks. <em>/
        xQueueSend( mssgQueue, (void</em>)&amp;queMssg, 500);
}
~~~
Your server will only become available in case it receives a character <code>RCVD_PROMPT</code>. Are you sure that it will always be received? Doesn&#8217;t that loop need a time-out protection?

Aren&#8217;t you mistaken here?
The task is receiving from a queue, with a time-out of 500 clock ticks. When the time-out is reached, the function <code>xQueueReceive()</code> returns <code>pdFAIL</code> and your message will be printed.
<blockquote>
  Is calling the function that formats and then xQueueSend
  safe to do from the 2 running tasks? 
</blockquote>
The function <code>xQueueSend()</code> is well protected and can be called simultaneously.
I can not see your message formatting, so I don&#8217;t know if that is <em>re-entrant</em> safe code
</div></div><div class="thread-post"><h3 class="thread-post-title">Implementation of Polling UART</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/groger57">groger57</a> on June 23, 2017</div><div class="thread-post-content">Hein,
Thank you for taking the time to reply. Instead of continuing down this path, let me ask this a different way. I now understand the problem space so I need now to understand implementation.
Let&#8217;s say I have 3 concurrent tasks (TaskA, TaskB, TaskC). I have 15 different structure (SCROBJ) instances that are malloc&#8217;d at initialization. Each one has different information about it&#8217;s &#8220;object&#8221; (obj1, obj2&#8230;obj14). Each task can (and will) access and modify and particular object, at any time in concurrency. &#8220;Access&#8221; means to send information to a function that will then send that object&#8217;s data through the UART. In truth, a single call to the function requires several UART sends to complete the &#8220;transaction&#8221;. Additionally, the UART response is polled (I have done that part and works OK) 
As you expect, it&#8217;s not possible to have a single function to service these Task calls without something getting corrupted. For example, if TaskA has called the function for sending Obj5, and TaskB begins formatting the string for Obj5 at the same time, trouble is imminent. 
Clearly the way to fix this is using a FreeRTOS message queue. But this raises questions. I could create a message structure that is of type SCROBJ that the RTOS function QueueSend will use (stack allocated). But at some point, I need to modify (change) the members of that structure to match the object that I am sending through the UART. I understand that QueueReceive makes a copy of the incoming structure. Can I use a pointer of the obj in QueueSend ? Will QueueReceive make a copy of the sending structure&#8217;s members? Should the QueueSend and QueueReceive structure be created and heap allocated, same as the &#8220;obj1&#8230;etc, structures, instead of stck allocation?
If receive does make a copy, this would be safe as QueueReceive would protect the structure until it&#8217;s completed and shouldn&#8217;t get corrupted by another task. From within the QueueReceive function, on pdPass, I would begin sending the various structure elements into the UART. 
I appreciate your feedback to figure this out. 
Thanks,
Roger

</div></div><div class="thread-post"><h3 class="thread-post-title">Implementation of Polling UART</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on June 24, 2017</div><div class="thread-post-content"><blockquote>
  if TaskA has called the function for sending Obj5, and TaskB begins formatting
  the string for Obj5 at the same time, trouble is imminent.
</blockquote>
You can create an array of these objects, and send these objects to a <code>QueueFree</code>. When you need such an object, take from <code>QueueFree</code> and pass it the the UART task. After handling the message, the object will be returned to <code>QueueFree</code>.
<blockquote>
  I understand that QueueReceive makes a copy of the incoming structure.
  Can I use a pointer of the obj in QueueSend ?
</blockquote>
Yes, do not store the entire object ( of N bytes ) in a queue, but store a pointer. And the 4 bytes of a pointer will get copied.
<blockquote>
  Should the QueueSend and QueueReceive structure be created and heap allocated
</blockquote>
I would think of <code>QueueFree</code> and <code>QueueUart</code>. Initially ( a pointer to ) each object is linked to <code>QueueFree</code>. grab one from there, change the contents and pass it to <code>QueueUart</code>. The Uart task will handle the message and return the object to <code>QueueFree</code>?
<blockquote>
  Just a bit of clean up in the code and all is well
</blockquote>
Good to hear. You&#8217;re welcome, Hein
