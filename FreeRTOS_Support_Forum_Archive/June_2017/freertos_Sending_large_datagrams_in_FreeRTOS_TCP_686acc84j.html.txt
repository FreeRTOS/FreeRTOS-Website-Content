  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Sending large datagrams in FreeRTOS+TCP</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/jtbr">jtbr</a> on June 14, 2017</div><div class="thread-post-content">I have large datagrams I&#8217;d like to send over UDP, and in investigating why they weren&#8217;t being sent I realized that FREERTOS_sendto() caps the size of datagrams at the payload size for a single packet. 
It should be possible to allow fragmentation at the IP leve,l for reassembly at the destination. I saw <a href="http://www.freertos.org/FreeRTOS-Plus/FreeRTOS_Plus_UDP/UDP_IP_Configuration.shtml">this config option</a> ipconfigCAN<em>FRAGMENT</em>OUTGOING_PACKETS that seems to allow exactly what I need. But it appears not to be implemented in +TCP. 
Is there any plan to include this functionality in +TCP?
As an alternative, I considered increasing the MTU, but it would be memory-prohibitive as I need to send datagrams up to 24Kb, and I&#8217;m also not sure about the hardware level support for that. So now I&#8217;m considering if I need to implement a fragmentation and reassembly as a part of my own protocol, but that would be somewhat unfortunate.
Thanks for any help.
</div></div><div class="thread-post"><h3 class="thread-post-title">Sending large datagrams in FreeRTOS+TCP</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on June 14, 2017</div><div class="thread-post-content">Hi Justin,
In the earlier FreeRTOS+UDP stack there was indeed an option <code>ipconfigCAN_FRAGMENT_OUTGOING_PACKETS</code>. That stack is still distributed along with the kernel, e.g. :
~~~
    FreeRTOSv9.0.0/FreeRTOS-Plus/Source/FreeRTOS-Plus-UDP
~~~
As the option says, it will only work for outgoing packets, which is enough for you.
When developing +TCP, it was decided to stop supporting UDP packet fragmentation. That decision saved a lot of code and it made the code easier to read.
And in fact, TCP can do exactly what you need: split up and join packets in a reliable way.
You can set MTU to 1500, or a little bit longer in case your peripheral, switches and router support jumbo packets.
So you can use TCP, or, alternatively, give your UDP packets a small header and make your own fragmentation. That should not be <strong>too</strong> difficult 🙂
</div></div><div class="thread-post"><h3 class="thread-post-title">Sending large datagrams in FreeRTOS+TCP</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/jtbr">jtbr</a> on June 14, 2017</div><div class="thread-post-content">Thanks for the info. I must say you have succeeded in making +TCP very readable.
The nice thing about UDP is that I can broadcast datagrams and listeners can listen as they want or are able. But since I also need and use TCP for more connection-oriented comms, using just +UDP isn&#8217;t an option.
I&#8217;ll look into breaking up and reassembling UDP at the application level then.
