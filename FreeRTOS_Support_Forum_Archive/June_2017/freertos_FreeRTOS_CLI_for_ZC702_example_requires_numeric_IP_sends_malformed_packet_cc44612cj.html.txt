  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">FreeRTOS+CLI for ZC702 example requires numeric IP &#038; sends malformed packet</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/mdesm2005">mdesm2005</a> on June 18, 2017</div><div class="thread-post-content">I&#8217;m trying out the FreeRTOS example for the Xilinx Zynq using a ZC702 evaluation board.  I found two small issues. I recommmend put them in the documentation (at least). One is that you must use a numerical IP with a  UDP client (such as YAT) to connect with the command line interface (CLI) UDP server.  This is odd, because I can ping using the name &#8220;RTOSDemo&#8221;.  I got the numerical IP that DHCP assigned to my ZC702 via ping BTW. Another thing that&#8217;s odd is that a TCP client on my PC can connect with the FreeRTOS TCP echo task using the name &#8220;RTOSDemo&#8221;. It&#8217;s just the UDP clients that can&#8217;t. I tried YAT and I tried a home made client in Python. Same behavior.  A second issue is that the CLI server always returns a carriage return first, and in one packet. And Wireshark flags this as a &#8220;[malformed packet CPFI]&#8221;.  I don&#8217;t know if this is a problem.  Finally , the YAT example shown in the documentation shows and outdated version of YAT. You should pick the &#8220;UDP/IP client&#8221; option, not &#8220;UDP/IP socket&#8221; and you only need to enter the server port (5001).

That is indeed strange.
I have not worked with YAT YET 🙂
~~~
/* Include support for LLMNR: Link-local Multicast Name Resolution */
<h1>define ipconfigUSE_LLMNR                   ( 1 )</h1>
/* Include support for NBNS: NetBIOS Name Service (Microsoft) */
<h1>define ipconfigUSE_NBNS                    ( 0 )</h1>
~~~
When you use Wireshark, maybe you can see if YAT uses LLMNR or NBNS (or both) to resolve the name. In case it uses NBNS, you may want to enable NBNS.
<blockquote>
  A second issue is that the CLI server always returns a carriage
  return first, and in one packet. And Wireshark flags this as a
  &#8220;[malformed packet CPFI]&#8221;.
</blockquote>
I do not think it is really mal-formed. The CPFI protocol happens to use UDP port numbers 5000/5001.
Could you change the port numbers to something high and random, e.g. 67890 ?
