</div></div><div class="thread-post"><h3 class="thread-post-title">Advice: reduce memory usage</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on June 23, 2017</div><div class="thread-post-content">Hi Pavel,
<blockquote>
  The way to optimise that is to create independent task for RFID driver and
  perform communication between tasks with messages of notifications.
</blockquote>
I agree very much. RFID drivers are quite complex and have some slow operations, it is good to isolate that in a dedicated task.
<blockquote>
  So, in summary, I need to understand, if we do not require to have a multiple
  instance of one task, can we keep it in flash and not copy to ram?
</blockquote>
I&#8217;m reading your text over and again, but things are not clear.
What CPU are you using?
What compilers?
Where did you get the software that you&#8217;re working with?
Or did you write it yourself?
Normally, in smaller MCU&#8217;s, RAM is scarce and the code runs directly from flash ( non-volatile memory ). You can use a compiler option that puts a individual function <strong>permanently</strong> in RAM. E.g. this can be a function that writes to flash.
Sometimes flash is very slow ( serial flash ), and then functions running from RAM will be faster.
Creating a task under FreeRTOS does not mean that you copy code to RAM. Creating a task means :
● creating a Task Control Block, information about the task ( hidden in <code>task.c</code> )
● creating a Task Stack
● passing the task to the scheduler
Normally the memories for the TCB&#8217;s and stack are allocated dynamically by calling <code>pvPortMalloc()</code>. But if you like you can declare space for a task and its stack space statically ( v9.0.0 ).

Dont trust vTaskList command. It shows not real heap size. Only already dedicated. Use this event to report if memory is low:
void vApplicationStackOverflowHook( TaskHandle_t xTask, signed char *pcTaskName )
{
    /* Stack overflow */
    printf(&#8220;Task %s stack overflow!n&#8221;, pcTaskName);
}

</div></div><div class="thread-post"><h3 class="thread-post-title">Advice: reduce memory usage</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on June 24, 2017</div><div class="thread-post-content"><blockquote>
  <code>void vApplicationStackOverflowHook( TaskHandle_t, signed char* )</code>
  <code>{</code>
  <code>/* Stack overflow */</code>
  <code>printf("Task %s stack overflow!n", pcTaskName);</code>
  <code>}</code>
</blockquote>
You will use:
~~~
    #define configCHECK<em>FOR</em>STACK_OVERFLOW     2
~~~
It will catch stack overflows, but beware of two things:
your application might still crash, e.g. if you have a function that claims a big amount of stack space:
~~~
    void foo()
    {
    char buffer[ 65536 ];
        /* Program might still crash here. */
        sprintf( buffer, &#8220;Hello world&#8221; );
    }
~~~
And secondly, note that checking the free stack space may decrease performance. When releasing your software, you might want to disable it.
