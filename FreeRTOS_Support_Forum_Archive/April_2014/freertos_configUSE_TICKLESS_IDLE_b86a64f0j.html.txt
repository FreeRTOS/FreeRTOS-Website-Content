if( xExpectedIdleTime >= configEXPECTED<em>IDLE</em>TIME<em>BEFORE</em>SLEEP )
{
     portSUPPRESS<em>TICKS</em>AND_SLEEP( xExpectedIdleTime );
}
else{
   __WFI(); //add wait for interrupt here
}
</div></div><div class="thread-post"><h3 class="thread-post-title">configUSE_TICKLESS_IDLE</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on April 4, 2014</div><div class="thread-post-content">It may be that, in your particular application, you get some benefit from doing that, but if so I would not recommend changing the source code in that way but instead define an idle hook function that just calls wfi.
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">configUSE_TICKLESS_IDLE</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/l4n4">l4n4</a> on April 4, 2014</div><div class="thread-post-content">The idle hook will be called all the time and before portSUPPRESS<em>TICKS</em>AND<em>SLEEP, so it will always sleep for 1 tick time first before do any further checks. This means : 
&#8211; if xExpectedIdleTime &lt; 2 : this is ok
&#8211; if xExpectedIdleTime == 2 : Idle hook will sleep for 1 tick and portSUPPRESS</em>TICKS<em>AND</em>SLEEP will not be called. I would like the portSUPPRESS<em>TICKS</em>AND_SLEEP to be called in this condition. 
&#8211; xExpectedIdleTime > 2 : this is ok
Thanks!
</div></div><div class="thread-post"><h3 class="thread-post-title">configUSE_TICKLESS_IDLE</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on April 4, 2014</div><div class="thread-post-content">How about setting configEXPECTED<em>IDLE</em>TIME<em>BEFORE</em>SLEEP to 0 (may cause a compiler warning where the >= check is performed) then use the <a href="http://www.freertos.org/low-power-ARM-cortex-rtos.html">configPRE<em>SLEEP</em>PROCESSING</a> to check the expected idle time and if the expected idle time is below a threshold set by yourself it can just call wfi and cancel the tickless entry (the macros parameter can be used for cancelling the tickless entry).
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">configUSE_TICKLESS_IDLE</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/mplmht">mplmht</a> on January 10, 2017</div><div class="thread-post-content">I have the same concern here but I would like to keep usage of configEXPECTED<em>IDLE</em>TIME<em>BEFORE</em>SLEEP functionnality which is interesting I beleive.
I would like to get your advice on following code change proposal:
&#8211; when tickless idle feature is enabled, call to the idle hook
when xExpectedIdleTime is below configEXPECTED<em>IDLE</em>TIME<em>BEFORE</em>SLEEP
&#8211; when tickless idle feature is not enabled, keep calling the idle hook the same way as now.
The code change could look like below in portTASK_FUNCTION function of tasks.c (line 3177 of v9.0.0)?
<pre><code>#if ( configUSE_TICKLESS_IDLE == 0 )
    #if ( configUSE_IDLE_HOOK == 1 )
    {
        extern void vApplicationIdleHook( void );
        /* Call the user defined function from within the idle task.  This
        allows the application designer to add background functionality
        without the overhead of a separate task.
        NOTE: vApplicationIdleHook() MUST NOT, UNDER ANY CIRCUMSTANCES,
        CALL A FUNCTION THAT MIGHT BLOCK. */
        vApplicationIdleHook();
    }
    #endif /* ( configUSE_IDLE_HOOK == 1 ) */
/* This conditional compilation should use inequality to 0, not equality
to 1.  This is to ensure portSUPPRESS_TICKS_AND_SLEEP() is called when
user defined low power mode implementations require
configUSE_TICKLESS_IDLE to be set to a value other than 1. */
#else /* configUSE_TICKLESS_IDLE != 0 */
{
TickType_t xExpectedIdleTime;
    /* It is not desirable to suspend then resume the scheduler on
    each iteration of the idle task.  Therefore, a preliminary
    test of the expected idle time is performed without the
    scheduler suspended.  The result here is not necessarily
    valid. */
    xExpectedIdleTime = prvGetExpectedIdleTime();
    if( xExpectedIdleTime &gt;= configEXPECTED_IDLE_TIME_BEFORE_SLEEP )
    {
        vTaskSuspendAll();
        {
            /* Now the scheduler is suspended, the expected idle
            time can be sampled again, and this time its value can
            be used. */
            configASSERT( xNextTaskUnblockTime &gt;= xTickCount );
            xExpectedIdleTime = prvGetExpectedIdleTime();
            if( xExpectedIdleTime &gt;= configEXPECTED_IDLE_TIME_BEFORE_SLEEP )
            {
                traceLOW_POWER_IDLE_BEGIN();
                portSUPPRESS_TICKS_AND_SLEEP( xExpectedIdleTime );
                traceLOW_POWER_IDLE_END();
            }
            else
            {
                mtCOVERAGE_TEST_MARKER();
                #if ( configUSE_IDLE_HOOK == 1 )
                {
                    extern void vApplicationIdleHook( void );
                    /* Call the user defined function from within the idle task.  This
                    allows the application designer to add background functionality
                    without the overhead of a separate task.
                    NOTE: vApplicationIdleHook() MUST NOT, UNDER ANY CIRCUMSTANCES,
                    CALL A FUNCTION THAT MIGHT BLOCK. */
                    vApplicationIdleHook();
                }
                #endif /* configUSE_IDLE_HOOK */
            }
        }
        ( void ) xTaskResumeAll();
    }
    else
    {
        mtCOVERAGE_TEST_MARKER();
    }
}
#endif /* configUSE_TICKLESS_IDLE */
</code></pre>
