  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Tickless idle query</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/l4na">l4na</a> on April 22, 2014</div><div class="thread-post-content">Regarding the tickless idle implementation for the Cortex M3, I notice that it calls in this sequence:
__asm volatile( &#8220;cpsid i&#8221; ); //disable interrupt
&#8230;
if( xModifiableIdleTime > 0 )
{
    __asm volatile( &#8220;wfi&#8221; ); 
}
configPOST<em>SLEEP</em>PROCESSING( xExpectedIdleTime );
&#8230;
__asm volatile( &#8220;cpsie i&#8221; );//enable interrupt
Some questions:
<ul>
<li>Why disable interrupt globally before goes to the &#8220;wfi&#8221; mode and only re-enable it after the &#8220;wfi&#8221; is woken up ? </li>
<li>Will this mean that the &#8220;wfi&#8221; can&#8217;t be woken up by any other interrupt (other than systick)?</li>
<li>Currently, I have usb audio enabled. This means that the usb interrupt comes at 1 msec interval and I keep on missing the interrupt once I enable the tickless idle option. What&#8217;s the best way to configure this tickless idle to work together with this kind of high frequency interrupt? </li>
</ul>
Thanks.
</div></div><div class="thread-post"><h3 class="thread-post-title">Tickless idle query</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on April 22, 2014</div><div class="thread-post-content"><blockquote>
  Will this mean that the &#8220;wfi&#8221; can&#8217;t be woken up by any other interrupt (other than systick)?
</blockquote>
No. Please read the hardware manual, the comments in the code, and other posts in the forum  to lean how the hardware works. For example, just yesterday http://sourceforge.net/p/freertos/discussion/382005/thread/aa2c2eeb/#4c96
I don&#8217;t think tickless idle is appropriate if you have a 1ms interrupt because presumably the 1ms interrupt is either faster than or the same speed as the tick interrupt anyway so you cannot gain anything by turning the tick off.
</div></div><div class="thread-post"><h3 class="thread-post-title">Tickless idle query</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/l4na">l4na</a> on April 23, 2014</div><div class="thread-post-content">Hi Dave,  got it. Is there a way to enable tickless idle when the USB disconnected and disable it when the USB connected without changing the freertos core code? Or do you think this is recommended way of handling this use case?
Thanks.
</div></div><div class="thread-post"><h3 class="thread-post-title">Tickless idle query</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on April 23, 2014</div><div class="thread-post-content">You can use the pre-sleep hook macro for that purpose.  If the USB is connected then have the pre-sleep hook abort low power entry.  If the USB is not connected then use the pre-sleep hook do nothing.
Search for configPRE<em>SLEEP</em>PROCESSING on http://www.freertos.org/low-power-ARM-cortex-rtos.html
Regards.
