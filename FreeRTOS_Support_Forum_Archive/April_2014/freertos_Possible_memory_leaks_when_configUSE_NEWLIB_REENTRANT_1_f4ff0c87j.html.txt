  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Possible memory leaks when configUSE_NEWLIB_REENTRANT 1</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/wella">wella</a> on April 8, 2014</div><div class="thread-post-content">Hello,
before submitting a bug I would like to discuss the following issue.
I am using GNU Tools for ARM Embedded Processors with the Newlib libray. I have also enabled the configUSE<em>NEWLIB</em>REENTRANT macro to support task concurrency. However during the task deletion (no so much realtime&#8230;) the <em>reent xNewLib</em>reent is simply freed with the TCB. As far as I know the <em>reent struct should be reclaimed by calling _reclaim</em>reent at first. However such call is missing in prvDeleteTCB( TCB_t *pxTCB ).
There should be 
<pre><code>    #if ( configUSE_NEWLIB_REENTRANT == 1 )
    {
        _reclaim_reent(&amp;(pxTCB-&gt;xNewLib_reent));
    }
    #endif /* configUSE_NEWLIB_REENTRANT */
</code></pre>
before vPortFree( pxTCB ).
This is even more critical with the Newlib compiled with <em>REENT</em>SMALL.
There is a workaround to hook to portCLEAN<em>UP</em>TCB( pxTCB ) but the user needs to access pxTCB directly.
Anyway thank you for supporting Newlib.
Best
Martin

Take a look at <a href="https://sourceforge.net/p/freertos/code/HEAD/tree/trunk/FreeRTOS/Source/tasks.c">tasks.c in the head revision</a> to see if it is correctly meeting your needs now.

When the thread terminates, you should clean up all stdio usage by
the thread and call of its own atexit handlers by calling (see &#8220;reent.c&#8221;):

source: http://andrewsterian.com/424/Lecture17.pdf

Assuming this function has been really only introduced for RTEMS,
and given that it&#8217;s not used in newlib nor in RTEMS, I just removed
it now, as you proposed.
source: https://sourceware.org/ml/newlib/2013/msg00372.html
