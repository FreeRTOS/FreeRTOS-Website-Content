</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS and emWin on STM32F4</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on April 7, 2014</div><div class="thread-post-content">If you are using FreeRTOS V7.6.0 or higher then configASSERT() will automatically check the interrupt priorities.
GRAPH<em>DATA</em>YT<em>AddValue() is being called from more than one task.  If it is accessing a shared resource (memory, C structure, peripheral, etc.) then calling it from more than one task risks the resource becoming corrupted.  This can happen if, for example, one task is half way through updating the resource while the other that is reading from the resource.  If this sort of corruption can happen then GRAPH</em>DATA<em>YT</em>AddValue() is not thread safe, and you must take steps to ensure it can only be accessed by one task at a time.  That can be achieved by protecting the resource with a mutex (so a task has to first obtain the mutex before it is allowed to update the resource, then give the mutex back when it has finished its update), or by locking the scheduler while the resource is in an inconsistent state (so not other task can be switched in and access the resource until it is once again in a consistent state).
Regards.
