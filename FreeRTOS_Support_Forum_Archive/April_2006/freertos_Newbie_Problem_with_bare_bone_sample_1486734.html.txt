</div></div><div class="thread-post"><h3 class="thread-post-title">Newbie: Problem with bare bone sample</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on April 21, 2006</div><div class="thread-post-content">Your uart routine is busy waiting for the DRE bit to clear, with a yield function being called each loop.&nbsp; When the uart is the highest priority task the yeild will always return to the uart task which will immediately yield again, tying up the CPU.&nbsp; When the uart code is not the highest priority it will still always go back to the uart task when the other task is blocked.&nbsp; This is probably not your intended behavior.
