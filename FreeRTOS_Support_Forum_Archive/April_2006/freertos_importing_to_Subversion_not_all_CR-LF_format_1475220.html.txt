  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">importing to Subversion, not all CR-LF format</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/imajeff">imajeff</a> on April 3, 2006</div><div class="thread-post-content">I&#8217;m trying to import FreeRTOS 4.0.0 to Subversion.
I wonder why several files have mixed newline formats? More precisely, after checking a coulple, I found that in general the files use &quot;rn&quot;. That would be great, but svn does not automatically set an attribute on these few files &#40;in different ports&#41; which sometimes us &quot;nn&quot; as a double linefeed instead.
It would be more portable code if you could filter it so they all use the Windows CRLF format. Sad I&#8217;m saying that since I use Linux, but linux can handle the CRLF easily, just not so much the confused format.
</div></div><div class="thread-post"><h3 class="thread-post-title">importing to Subversion, not all CR-LF format</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/daveyjcrocket">daveyjcrocket</a> on April 3, 2006</div><div class="thread-post-content">i guess submitters to FreeRTOS could &#8216;dos2unix -D&#8217;
their stuff before submitting?
Or the poster could clean before importing to subversion?
Maybe they could run &#8216;indent&#8217; too since we&#8217;re on the beautification bandwagon.
</div></div><div class="thread-post"><h3 class="thread-post-title">importing to Subversion, not all CR-LF format</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/imajeff">imajeff</a> on April 3, 2006</div><div class="thread-post-content">Huh, it&#8217;s a thought. I&#8217;d just like to know what kind of wacky editor is making mixed line ends. And I don&#8217;t think it would be hard to figure out. I beleive only one person actually submits anything to his own repository, from what he&#8217;s said recently.
Clean&#8230; That wouldn&#8217;t help anything &#40;I also see he already does that&#8211;not related&#41;.
And no, I&#8217;m not on any sort of beautification bandwagon. The indentation looks good to me, and has never stopped the import like the CRLF/LFLF confusion did, and there is not reason to mix them. I mean the current state has no benefit and is sometimes harmful.
As far as indentation, anyone can argue that the current indentation in any source is better the way it is.
</div></div><div class="thread-post"><h3 class="thread-post-title">importing to Subversion, not all CR-LF format</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on April 4, 2006</div><div class="thread-post-content">I actually did the same thing myself recently &#8211; take the source code &#40;not including the demo apps&#41; into Subversion, but I did not encounter any problems.
The source code gets edited and debugged in a whole range of different editors and debuggers, some of which are Windoze native and some of which aren&#8217;t.&nbsp; I wasn&#8217;t aware that there was a problem with line ends getting mixed up.&nbsp; I have made a note to check this prior to the next release.
As for formatting &#8211; if you use tabs and set 1 tab to equal 4 spaces then it should already be &quot;beautiful&quot; ;-&#41; but this is in the eye of the beholder and the formatting is just my preference.
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">importing to Subversion, not all CR-LF format</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/imajeff">imajeff</a> on April 4, 2006</div><div class="thread-post-content">Hi Richard,
I guess it&#8217;s not too surprizing that you didn&#8217;t have any problems in your svn. I use auto properties &#40;not default&#41; which detect file types and set whether they should be checked out as ascii text and newlines converted for whichever environment they are being checked out for.
Since the auto properties is not default, you are simply preserving those files as binary. The reason I would not want that is because then if I use certain popular editors in Win, for example, I could not properly view a file that was edited in Linux.
Of course if it&#8217;s just too hard to prepare newlines that way for release downloads, then it means &#42;somebody&#42; will have to have a hard time with it.
