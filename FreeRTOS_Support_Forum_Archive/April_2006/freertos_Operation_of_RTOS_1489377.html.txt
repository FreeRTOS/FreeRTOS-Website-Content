  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Operation of RTOS</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on April 28, 2006</div><div class="thread-post-content">I&#8217;m studing your rtos code for Atmel AVR.
But I&#8217;ve some question about priority and task execution time.
This is my problem :
suppose we have 3 task &#40;A, B, C&#41;
I want to be sure that each task is executed every 1 mSec independently from their time of elaboration.
But the important thing is that the scheduler must stops task A&nbsp; , task B or task C and start the other tasks independently from their work.
I explain : if task A &#40;in reponse to an user input&#8230;a stupid example&#8230;an user has entered to calc the sqr from 1 to 25000000&#41; needs about 10 mSec for his work, I want that the kernel stops task A and executes task B.
Same thing for the other task. Task B must be stopped &#40;if not finished&#41; after max 1 msec because another task needs starting
Is it possible with freertos ???
Another question:
In the article about context switching you write &quot;TaskB has a higher priority than TaskA so vTaskSwitchContext&#40;&#41; selects TaskB as the task to be given processing time when the ISR completes&quot; &#40;http://www.techonline.com/static/feature&#95;articles/barry/step4.html&#41;
But if I have only two task &#40;A and B&#41; in my program and the task B has low priority then task A, the context switch will never happens ???
Excuse me, but I&#8217;m a primer with rtos.
Thank you 
Best regards
</div></div><div class="thread-post"><h3 class="thread-post-title">Operation of RTOS</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on April 28, 2006</div><div class="thread-post-content">I&#8217;m not sure I follow your questions fully, but I think they are both referring to the scheduling policy.
FreeRTOS is a preemptive priority based kernel.&nbsp; A task will never execute if there is a task of higher priority that is ready to execute &#40;not blocked&#41;.&nbsp; In other words, the scheduler will always choose to run the highest priority task that is able to run at the expense of any lower priority tasks.
If the preemptive scheduler is being used then task can be given the same priority.&nbsp; When there are more than one task of the same priority a context switch will occur each kernel tick.&nbsp; So I think the answer to your first question is that if each of the three tasks are given the same priority they will share the processing time, provided there are no tasks of higher priority that are able to run.
Regards.
