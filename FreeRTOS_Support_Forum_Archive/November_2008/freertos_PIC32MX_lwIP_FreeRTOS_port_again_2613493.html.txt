  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">PIC32MX lwIP + FreeRTOS port again</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/akhe">akhe</a> on November 26, 2008</div><div class="thread-post-content">I received and send frames now which is a success. There is a problem though in the Tctcpip thread. It appears to be FreeRTOS related so I ask here. Quite complex to explain the problem byt here we go.
In the tcpip thread the code waits for a frame. This is done with
sys&#95;mbox&#95;fetch&#40;mbox, &#40;void &#42;&#41;&amp;msg&#41;;
which is defined in the sys&#95;arch.c&nbsp; When called I get an exception.
I have checked that the mbox has been initialized and can trace the fault to a list iteration in vListInsert &#40;called in vTaskPlaceOnEventList&#41;
for&#40; pxIterator = &#40; xListItem &#42; &#41; &amp;&#40; pxList-&gt;xListEnd &#41;; pxIterator-&gt;pxNext-&gt;xItemValue &lt;= xValueOfInsertion; pxIterator = pxIterator-&gt;pxNext &#41;
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; &#123;
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; /&#42; There is nothing to do here, we are just iterating to the
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; wanted insertion position. &#42;/
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; &#125;
As I can see the list pointers are messed up as this point giving the exception. I have not been able to figure out why yet.
Call stack is
&#45; tcpip&#95;thread
&#45; sys&#95;mbox&#95;fetch
&#45; sys&#95;arch&#95;mbox&#95;fetch
&#45; xQueueGenericReceive
&#45; vTaskPlaceOnEventList
Any hints appreciated.
Cheers
/Ake
</div></div><div class="thread-post"><h3 class="thread-post-title">PIC32MX lwIP + FreeRTOS port again</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on November 26, 2008</div><div class="thread-post-content">Most likely cause of this is stack overflow &#8211; the lwIP threads can use quite a bit of stack, especially when using standard GCC C library functions such as sprintf&#40;&#41; &#91;you can use cut down versions that are more stack friendly on embedded systems&#93;.
Check the task that implements your lwIP functionality AND any task that is created using sys&#95;thread&#95;new&#40;&#41; within sys&#95;arch.c.&nbsp; Put a break point in sys&#95;thread&#95;new&#40;&#41; to ensure you catch each time it is called.
Regards.
