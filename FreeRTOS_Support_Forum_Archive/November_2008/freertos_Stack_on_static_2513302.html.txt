I&#8217;m using FreeRTOS on a board with external SDRAM and LPC2478. As I have some collision on external bus &#40;as I located HEAP on external RAM&#41;, I would like to know if is possible to set STACK of each task on static &#40;and for me&#41; internal RAM
If yes, I&#8217;m able to avoid access to external RAM on each PUSH/POP improving performance
Note that I placed HEAP on external ram as I need a lot of it, I&#8217;m using FLTK for GUI.
Thank you
Enrico Dalla Mariga
</div></div><div class="thread-post"><h3 class="thread-post-title">Stack on static</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on November 7, 2008</div><div class="thread-post-content">The stacks are allocated from the FreeRTOS.org heap &#8211; normally from heap&#95;1.c or heap&#95;2.c.&nbsp; This is separate from the heap your linker script will probably setup, so if you main heap is in external RAM you should be able to setup the FreeRTOS.org heap to use internal RAM.&nbsp; How this is done will depend on the compiler and linker as each uses its own syntax for placement.
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">Stack on static</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/enrico_adelco">enrico_adelco</a> on November 11, 2008</div><div class="thread-post-content">But I used heap model heap&#95;3.c, to be able to allocate dynamic object in secure section &#40;with vTaskSuspendAll and xTaskResumeAll&#41;

In other words, if I use malloc in 2 different task, I have to be sure to make it in critical region as if I will be interrupted during malloc by another task that want to make another malloc, I think &#40;never tried&#41; that it will soon crash&#33;&#33;&#33;
It would be useful to allow xTaskCreate to get pointer to static STACK, which can be in HEAP or not
What do you think?
I need these improvements as I&#8217;m working in critical condition &#40;ARM7 LPC2478 with external RAM, LCD 800&#215;480 and FLTK+nanoX+microwindows over FreeRTOS&#41;
Thanks in advance

When you create a new task, you have to pass, on pvParameters, pointer to portSTACK&#95;TYPE array of number of elements equal to usStackDepth. For example:
&#35;define MY&#95;STACK&#95;SIZE 100
static portSTACK&#95;TYPE myStack&#91;MY&#95;STACK&#95;SIZE&#93;;
&#8230;
xTaskCreate&#40;task1, &quot;Task1&quot;, MY&#95;STACK&#95;SIZE, myStack, TASK&#95;PRIORITY, NULL&#41;;
Make sure that configMAX&#95;TASK&#95;NUMBER is more or equal than xTaskCreate calls.
NOTES:
&#45; Tested on ARM7 LPC2000 porting &#40;LPC2478 w/external memory and LCD&#41;
&#45; No support for vTaskDelete&#33;&#33;&#33; TCB location are not free&#8217;d
&#45; No check for array of TCB insufficient
These changes are very useful if you use dynamic allocation &#40;malloc/free&#41; in HEAP located on external memory. After these changes, my application duplicated speed on widgets drawing
