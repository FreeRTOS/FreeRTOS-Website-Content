  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Run-time multitasking support</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nvass">nvass</a> on November 11, 2008</div><div class="thread-post-content">hi, guys
I am not sure that here is the most suitable place for my question, but here it is:
Does anybody know how run-time support &#40;starting a new tasks at run-time&#41; is delivered by embedded RTOS &#40;preserving the real-time properties of the tasks&#41;? 
My question comes from the fact that if the system has for example 2 tasks and we try to execute a new task at run-time, it is possible it &#40;the new task&#41; to cause some of the other tasks to miss their deadlines &#40;for example the new task is blocked in critical section and could not be preempted&#41;. To make things more complicated lets assume that tasks have asynchronous behavior :&#41;
Does any of the contemporary embedded RTOS makes such a check/ test before starting a new tasks in run-time?
Regards. 
</div></div><div class="thread-post"><h3 class="thread-post-title">Run-time multitasking support</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on November 11, 2008</div><div class="thread-post-content">You can create tasks at any time as long as there is enough RAM left in the heap. If your processor does not have enough power to perform all the required functions in the given time then the RTOS cannot change the physics. An RTOS can give the you the opportunity to get more done in a fixed time though as it removes the need to continuously poll events that have not happened.
</div></div><div class="thread-post"><h3 class="thread-post-title">Run-time multitasking support</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nvass">nvass</a> on November 11, 2008</div><div class="thread-post-content">I am agree with you, but I didn&#8217;t get the answer that I need it, I will try to clarify myself with simple example:
Lets have an simple RISK processor which has an RTOS and it is executing 2 real-time applications. Both applications are transmitting some data on UART &#40;or any other interface&#41;.
So far so good :&#41; &#8230;..
After some period of time the user wants to execute third real-time application on the same&nbsp; device &#40;I assume that the device has enough heap memory to store the applications&#41;, and the 3rd application is started&#8230;
&#8230;..
after some period of time the 3rd applications receive asynchronous event which cause it to enter in critical section i.e. it block the processor for some period of time. And I assume that the blocking cause 2nd application to miss its deadline, so there is my question &#40;I don&#8217;t want to change the physics :&#41;&#41; &#41;::
Is there any contemporary RTOS which can predict and reject that a new application, that the USER want to start in run-time, will cause deadline miss in already running applications?
Does anybody get faced with this problem?
