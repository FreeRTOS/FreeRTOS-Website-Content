</div></div><div class="thread-post"><h3 class="thread-post-title">ATMega323 port for ATMega16L</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on May 26, 2005</div><div class="thread-post-content">The demo application uses all the heap &#8211; so if you have reduced the heap size it is likely that the scheduler is running out of memory and not starting.
Try reducing the number of tasks that are created &#8211; in FreeRTOS/Demo/AVR&#95;ATMega323&#95;WinAVR/main.c comment out the lines:
vStartIntegerMathsTasks&#40;&#41;
vAltStartComTestTasks&#40;&#41;
vStartPolledQueueTasks&#40;&#41;
xTaskCreate&#40; vErrorChecks, &#8230;
This should just leave the LED flash tasks so you can see if anything is running.
</div></div><div class="thread-post"><h3 class="thread-post-title">ATMega323 port for ATMega16L</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on May 26, 2005</div><div class="thread-post-content">Thanks it works now&#33; :-&#41; But i am surprised at the number of tasks that can run in parallel with 1KByte of RAM&#33;
Next i plan to use the ATmega128 with 4KBytes of RAM. How many tasks can i run in parallel assuming default default default stack size and Global variables not exceeding 200 bytes?
</div></div><div class="thread-post"><h3 class="thread-post-title">ATMega323 port for ATMega16L</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on May 26, 2005</div><div class="thread-post-content">Take a look at this page:
