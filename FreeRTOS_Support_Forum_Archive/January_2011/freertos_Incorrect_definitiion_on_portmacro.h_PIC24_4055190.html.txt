  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Incorrect definitiion on portmacro.h PIC24</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/*anonymous">*anonymous</a> on January 15, 2011</div><div class="thread-post-content">Hello everybody;  
The define of portTICK&#95;RATE&#95;MS is wrong for PIC24 :  
Original :<br />
&#35;define portTICK&#95;RATE&#95;MS &#40; &#40; portTickType &#41; 1000 / configTICK&#95;RATE&#95;HZ &#41;  
If configTICK&#95;RATE&#95;HZ == 100, so 100 TICKs per second, then portTICK&#95;RATE&#95;MS egal 10, and the real rate&nbsp; is 100 ms, not 1 ms&nbsp; …  
Correct version :  
&#35;if configTICK&#95;RATE&#95;HZ &gt;= 1000<br />
&nbsp; &#35;define portTICK&#95;RATE&#95;MS &#40; configTICK&#95;RATE&#95;HZ / 1000&#41;<br />
&#35;endif  
Cordially.
</div></div><div class="thread-post"><h3 class="thread-post-title">Incorrect definitiion on portmacro.h PIC24</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on January 15, 2011</div><div class="thread-post-content">configTICK&#95;RATE&#95;HZ is not used in the kernel code anywhere.&nbsp; It is provided just for convenience, so you can change the tick rate without having to change all delay and block times.&nbsp; It is used extensively in the demo tasks.  
To convert ms into ticks, you divide the ms value by configTICK&#95;RATE&#95;HZ &#40;provided the tick rate is equal to or slower than 1KHz&#41;.  
If you want to block for 1 second, then you want to block for 1000ms.&nbsp; If your tick rate is 100Hz, you want to block for 100 ticks.&nbsp; In this case, with the definition as it stands, portTICK&#95;RATE&#95;MS would be 1000 / 100 = 10.&nbsp; Converting 1 second &#40;1000ms&#41; into ticks would be 1000ms / configTICK&#95;RATE&#95;HZ == 1000 / 100 == 10 == the right answer.  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">Incorrect definitiion on portmacro.h PIC24</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on January 15, 2011</div><div class="thread-post-content">Correction:
