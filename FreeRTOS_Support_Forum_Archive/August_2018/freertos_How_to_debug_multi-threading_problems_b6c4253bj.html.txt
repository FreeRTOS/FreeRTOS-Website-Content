</div></div><div class="thread-post"><h3 class="thread-post-title">How to debug multi-threading problems</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on August 21, 2018</div><div class="thread-post-content">As I&#8217;m afraid this is not our code, and the project was not provided by 
us, and the libraries you are using are third party and not libraries we 
are familiar with (other than the kernel)&#8230;.there is just too much code 
for us to look through here so we can&#8217;t offer directed replies.  I would 
however note that this did catch my eye while skimming:
<pre><code> vTaskSuspendAll();
 USBThreadId = NULL;
 vTaskDelete( xTask );
 xTaskResumeAll();
</code></pre>
As a rule of thumb, FreeRTOS API functions should never be called from 
within a critical section or with the scheduler suspended.  Not that it 
should be an issue in that particular case, but you are venturing out of 
documented behaviour.
