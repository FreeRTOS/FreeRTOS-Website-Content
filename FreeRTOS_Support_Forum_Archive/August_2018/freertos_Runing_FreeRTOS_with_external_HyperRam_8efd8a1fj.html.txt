  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Runing  FreeRTOS with external HyperRam</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/gauravpatni">gauravpatni</a> on August 6, 2018</div><div class="thread-post-content">Dear Support team,
In one of the project we are planning to use FreeRTOS with external <strong>HyperRAM</strong>  S70KL1281  ( http://www.cypress.com/file/183506/download ) with <strong>STM32L4R5ZI</strong>   ( having Octal-SPI support https://www.st.com/content/ccc/resource/technical/document/application_note/group0/91/dd/af/52/e1/d3/48/8e/DM00407776/files/DM00407776.pdf/jcr:content/translations/en.DM00407776.pdf )
we need to execute all FreeRTOS functionality from FreeRTOS ( mainly heap memory )
But I have some basic doubts regarding context switching while communicating with External HyperRAM as follows:
<ol>
<li>as per datasheet of hyperRAM , (S70KL1281 section 3.2Command/Address Bit Assignments ) , it takes several clock cycles to start data transfer .</li>
<li>most importantly data bus of HyperRAM is of 8 bit &amp; RTOS functionality is considering 32 bit ( as MCU is 32 bit ) . So data communication might not be &#8216;atomic&#8217; .</li>
</ol>
So what will happen if  context switching happens during operation ? how to prevent external HyperRAM data corruption ?
Thanks,
Gaurav
</div></div><div class="thread-post"><h3 class="thread-post-title">Runing  FreeRTOS with external HyperRam</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richarddamon">richarddamon</a> on August 6, 2018</div><div class="thread-post-content">I am not familiar with that particular combination, but here are my general observations:
The datasheet says that the processor make the external memory look like internal memory, so that means that at the processor level, a request from the chip will processed a pull a bit from that memory into a local cache, transparently to the program.
First, this means that you don&#8217;t need to worry about switching in the middle of a operation, the processor will handle the details itself.
It does mean that you will get a slightly increased latency, as such a request will stall the processor (just like a request to other external memories, or sometimes even internal flash). Unless you have nano-second level latency requirements this probably isn&#8217;t a concern.
Also, you don&#8217;t need to worry about the device being &#8216;8 bits&#8217;, the processor will grab enough data to do the operation.
