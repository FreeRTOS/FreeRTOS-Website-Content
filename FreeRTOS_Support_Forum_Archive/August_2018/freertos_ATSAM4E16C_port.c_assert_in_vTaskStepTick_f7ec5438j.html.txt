</div></div><div class="thread-post"><h3 class="thread-post-title">ATSAM4E16C port.c assert in vTaskStepTick()</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/lctromnml">lctromnml</a> on March 25, 2019</div><div class="thread-post-content">I think I have solved the problem (at least for me). In the errata of the microcontroller I found the following: 
&#8220;Issue: Unpredictable Behavior When Entering Sleep Mode
When entering Sleep mode, if an interrupt occurs during WFI or WFE (PMC_FSMR.LPM = 0) instruction processing, the ARM core may read an incorrect data, thus leading to unpredictable behavior of the software. This issue is not present in Wait mode.
Workaround: The following conditions must be met:
1. The interrupt vector table must be located in Flash.
2. The Matrix slave interface for the Flash must be set to &#8216;No default master&#8217;. This is done by setting the field DEFMSTR<em>TYPE to 0 in the register MATRIX</em>SCFG. The code example below can be used to program the NO<em>DEFAULT</em>MASTER state:
<code>MATRIX_SCFG[2] = MATRIX_SCFG_SLOT_CYCLE(0xFF) | MATRIX_SCFG_DEFMSTR_TYPE(0x0);</code>
This must be done once in the software before entering Sleep mode.&#8221;
I followed the workaround and did not have any configASSERTs since then anymore.
