  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">one-shot timer in FreeRTOS</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/umnurw">umnurw</a> on February 10, 2011</div><div class="thread-post-content">Hi,  
Is there any method to use one-shot timer in FreeRTOS?  
thanks.  
</div></div><div class="thread-post"><h3 class="thread-post-title">one-shot timer in FreeRTOS</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on February 10, 2011</div><div class="thread-post-content">The current V6.1.1 implementation of FreeRTOS does not have a specific method of doing this, although it is perfectly possible to use the tick hook, and other methods, etc. to obtain this functionality.  
V6.2.0 of FreeRTOS &#40;not released yet&#41; has a new specific timer implementation that has this functionality.&nbsp; The implementation is in the head revision of the SVN repository now, although it is not complete yet because there is now overflow protection yet &#8211; I am adding that functionality today.&nbsp;   
The timer implementation is not documented yet, although there is a demo/test app for it FreeRTOS/Demo/Common/Minimal/TimerDemo.c &#8211; again this is in the head revision of SVN.&nbsp; At the moment that file is a bit of a mess because there is a lot of test code in one large function.&nbsp; It will be modularised before release.  
Writing a timer implementation is actually very easy &#8211; what is not easy is writing an efficient timer implementation.&nbsp; Often timers are written to execute in the interrupt context, which is not a good plan for the timer callback functions, and has an overhead on every single tick interrupt even when no timers need servicing.&nbsp; Also, implementations can require linked lists to be walked either in an interrupt, or with interrupts disabled.&nbsp; These are things that FreeRTOS never does.&nbsp; The implementation I have come up with hopefully gets around both these points.&nbsp; The timers are serviced by a timer daemon task, so executes in the task context.&nbsp; Also, the task blocks until a timer actually needs servicing, so there is no overhead when timers are all just waiting to expire.  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">one-shot timer in FreeRTOS</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/peter03">peter03</a> on February 28, 2011</div><div class="thread-post-content">When will v6.2.0. be released? I&#8217;d like to appy freeRTOS Timer methods.
</div></div><div class="thread-post"><h3 class="thread-post-title">one-shot timer in FreeRTOS</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on February 28, 2011</div><div class="thread-post-content">It will get released as soon as I have time to document the new features, and test some changes that were made to a couple of ports.&nbsp; In the mean time, you can obtain a copy of the timers code from the FreeRTOS SourceForge SVN repository.&nbsp; The timers code has completed testing now so should not change much if at all between now and release.  
The file to add to a project in order to use software timers is FreeRTOS/Source/Timers.c  
The demo application tasks &#40;which are actually quite complex because they are more of a test task than a demo task&#41; is in FreeRTOS/Demo/Common/Minimal/TimerDemo.c  
The MSVC Win32 simulator demo has been updated to use the timer module, this is in FreeRTOSDemoWIN32-MSVC and uses the free MSVC Express edition to compile.  
Note the MSVC project has the following additions to its FreeRTOSConfig.h:  
&#35;define configUSE&#95;TIMERS 1<br />
&#35;define configTIMER&#95;TASK&#95;PRIORITY 2<br />
&#35;define configTIMER&#95;QUEUE&#95;LENGTH 20<br />
&#35;define configTIMER&#95;TASK&#95;STACK&#95;DEPTH &#40; configMINIMAL&#95;STACK&#95;SIZE &#42; 2 &#41;  
/&#42; Nothing to do with timers, but to do with the new assertion points added in the core code. &#42;/<br />
extern void vAssertCalled&#40; void &#41;;<br />
&#35;define configASSERT&#40; x &#41; if&#40; &#40; x &#41; == 0 &#41; vAssertCalled&#40;&#41;  
The API for the timers module is in FreeRTOSSourceincludetimers.h &#42;but&#42; this is not yet commented.  
Regards.
