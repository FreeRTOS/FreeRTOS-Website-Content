  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Custom IRQ handler not working with FreeRTOS</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/tjohansen">tjohansen</a> on February 17, 2011</div><div class="thread-post-content">Hallo  
Im using a bootloader to boot the FreeRTOS with. Therefore I cannot use the LDR&nbsp;&nbsp;&nbsp;&nbsp; PC,&nbsp; from the startup.s file, because that is relative to the program counter &#40;PC&#41;. The reason is that the application will be compiled to 0x5100 and VicVectAddr can not be addressed with an offset relative to PC &#40;since vector originally located at 0x18<br />
is now at 0x5118 in the application downloaded by the bootloader&#41;.  
I have therefore written my own IRQ handler to get the correct adress from VivVector  
IRQ handler:  
void IRQ&#95;Handler &#40;void&#41; &#95;&#95;irq<br />
&#123;<br />
&nbsp; void &#40;&#42;interrupt&#95;function&#41;&#40;&#41;;<br />
&nbsp; unsigned int vector;<br />
&nbsp; vector=VICVectAddr;<br />
&nbsp; interrupt&#95;function=&#40;void&#40;&#42;&#41;&#40;&#41;&#41;vector;<br />
&nbsp; interrupt&#95;function&#40;&#41;;<br />
&nbsp; VICVectAddr = 0;<br />
&#125;  
I then use this in my Startup.s file instead:  
IMPORT&nbsp; IRQ&#95;Handler  
LDR&nbsp;&nbsp;&nbsp;&nbsp; PC, IRQ&#95;Addr  
IRQ&#95;Addr&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; DCD&nbsp;&nbsp;&nbsp;&nbsp; IRQ&#95;Handler  
But for testing I haven&#8217;t build the application with any flash offset. Just to test the IRQ handler  
But doing this doesn&#8217;t work. If I set a breakpoint in the IRQ&#95;Handler the correct ISR is called. But after that one IRQ FreeRTOS crashes and CPU is in Undefined exception.  
So my question:  
Is this not possible with FreeRTOS or have I done something wrong?  
Cannot se way this crashes FreeRTOS.   
Using LPS2478 and FreeRTOS 5.1.2  
Thomas  
</div></div><div class="thread-post"><h3 class="thread-post-title">Custom IRQ handler not working with FreeRTOS</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on February 17, 2011</div><div class="thread-post-content">I believe richard&#95;daemon has gone to some length to look up how to do this for you in post 4 of the following thread:  
<a href="http://sourceforge.net/projects/freertos/forums/forum/382005/topic/4363931">http://sourceforge.net/projects/freertos/forums/forum/382005/topic/4363931</a>  
If you want to perform a context switch from an ISR &#40;which the SWI ISR &#42;must&#42; do&#41; then you need to following the instructions for writing ISR function that are on the documentation page for the port you are using &#8211; and also demonstrated in the demo projects that are provided for the port you are using.
