</div></div><div class="thread-post"><h3 class="thread-post-title">The problem about interrupt on HT32 that a chip like STM32</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on February 19, 2014</div><div class="thread-post-content">Generally the ISR needs to do the immediate actions that trigger the interrupt. That generally includes for a serial port getting the character and putting it some where. (This doesn&#8217;t apply for using DMA, but then when you use DMA, you don&#8217;t get character ready interrupts, you get DMA complete interrupts).
The ISR could put the character in a queue if the data rate is somewhat slow. For faster channels it should build up a &#8220;message&#8221; and on receipt of a complete message signal a task to process it.
