I was getting error from the complier that It could not find: portmacro.h.<br />
It was in all the Include paths that I tried, I was blaming the IDE for NOT doing Inclusion correctly.  
The &#8220;problem&#8221; is that the new IDE support using a forward slash in ALL path name under Windows, Linux and Mac OSX, but will also support a back slash under Windows. One&#8217;s eyes, can&#8217;t tell one from the other when look at a path error messages…  
The Portable.h file for the PIC devices, use a back slash as it should for the older IDE under Windows…. fixing this, provide a clean compile.  
testing was done with Beta IDE 7.01, C30 ver 3.30b on MAC OSX 10.7  
same issue will be there for PIC18 and PIC 32  
I change the preprocessor macro in the compiler to: MPLABX&#95;DSPIC&#95;PORT

<blockquote>
  Thank you indeed for taking the time to provide this feedback.  
</blockquote>
I myself am just a Windows user, so have been tripped up by case<br />
sensitivity and slash &#8216;orientation&#8217; issues before, and it is always<br />
appreciated when people point these out.  
With regards to the lines you have indicated in portable.h, which select<br />
which portmacro.h file to include.&nbsp; These lines are problematic for a<br />
number of reasons, not least of which is that they expect a certain<br />
directory structure to exist, and people will often change the structure<br />
to suite their requirements.&nbsp; The other problems are first the one you<br />
have just run into, and second that it requires people to have a symbol<br />
defined in their project options &#40;MPLAB&#95;PIC32MX&#95;PORT for example&#41;.&nbsp; For<br />
these reasons, their use is now deprecated, although they are retained<br />
for backward compatibility.&nbsp; If you look at the bottom of the list of<br />
entries &#40;part of which you have cut into your email&#41; you will see a line<br />
has been added to just &#35;include &#8220;portmacro.h&#8221; without any path, if<br />
portmacro.h has not already been included.  
This dropping of use is not advertised anywhere, and many older projects<br />
exist that still use them &#40;I cannot go through all the projects to<br />
change them as there are too many&#41;, but newer projects just add the path<br />
to the required portmacro.h header file to the list of existing include<br />
paths to ensure the right one gets included.&nbsp; I would recommend doing<br />
the same in your new MPLAB-X projects.
