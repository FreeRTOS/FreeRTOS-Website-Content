</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS Features &#8211; help please</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on August 12, 2011</div><div class="thread-post-content">&gt; Hello estimated colleagues. I am considering the use of FreeRTOS for an upcoming<br />
&gt; project &#40;switching from ThreadX&#41;   
Why do you want to switch from ThreadX?  
&gt; and I have a few questions regarding its features<br />
&gt; that I need answered before I proceed. Can any of you check the following list<br />
&gt; and tell me whether these features are available? Your help is greatly<br />
&gt; appreciated&#33;  
The information you want is all on the web site. Start here<br />
<a href="http://www.freertos.org/FreeRTOS_Features.html">http://www.freertos.org/FreeRTOS_Features.html</a> Normally, if a feature is not explicitly provided, you can use other features to achieve the same effect.  
&gt; Feature:<br />
&gt; -Fixed size memory management  
Apparently there used to be, but people found it too complicated. See<br />
<a href="http://www.freertos.org/a00111.html">http://www.freertos.org/a00111.html</a>  
&gt; -Signal a task without requiring a semaphore<br />
&gt; -Send messages to a task without needing a message queue  
If you mean a posix style signal, then no.  
Remember in FreeRTOS code size is king. Queues are used as the base primitive for all task to task and task to interrupt coms, and queues have event management built in.  
&gt; -Is it ROMable?  
Yes. What isn&#8217;t?  
&gt; -ASCII names for each kernel object?  
Tasks and timers by default. Queues and the various semaphore types can be added to a registry with an ascii name.  
&gt; -Task registers  
?  
&gt; -Built-in performance measurement  
<a href="http://www.freertos.org/rtos-run-time-stats.html">http://www.freertos.org/rtos-run-time-stats.html</a><br />
<a href="http://www.freertos.org/rtos-trace-macros.html">http://www.freertos.org/rtos-trace-macros.html</a>  
&gt; -User definable hook functions  
Task switch hooks &#40;definable per task&#41;, idle hooks, tick hooks, malloc fail hooks, stack overflow hooks.  
&gt; -Time stamps on posts  
You can post a structure that has a time stamp you add yourself.  
&gt; -Built-in Kernel Awareness support  
The kernel is aware of itself, yes.  
&gt; -optimizable scheduler  
There are features that allow memory use to be inspected and so optimised. The kernel is configurable too, and you have all the source code.  
&gt; -tick handling at task level  
?  
&gt; -Number of services?  
?

Even though this case seems unlikely since forum-support seems very solid, perhaps there would be a case were I would need urgent support or training, and I need to plan for everything.  
Going back to the features, I like the Task trace functions. Also when I asked about the number of services I meant the number of kernel services provided, such as task management, task scheduling, etc. I&#8217;ve seen a few that have from 50 to 100 services. I was just curious.   
Thanks&#33;
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS Features &#8211; help please</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on August 12, 2011</div><div class="thread-post-content"><blockquote>
  Speaking of budget, do you &#40;or anyone else&#41; have an idea of how much would i have to pay if I want them to write me a port? The board I plan to work with is a Renesas board for which there is no port available, the RX610.
</blockquote>
If you write to me directly, I can send you a support and information pack, you can find the email address here <a href="http://www.freertos.org/RTOS-contact-and-support.html.">http://www.freertos.org/RTOS-contact-and-support.html.</a>&nbsp; However, currently price is not really the limiting factor, scheduling is.&nbsp; The development road map, both for kernel enhancements and new ports is extremely busy, and unfortunately the RX610 is not currently on the list.&nbsp; I could add it to the list, but could not guarantee when the work could start.&nbsp; I do have a commercial partner company who can also quote for work, but there rates are &#40;understandably&#41; somewhere more commercial than mine.&nbsp; If you are the same person that inquired through the ticketing system then you will have their details already.  
<blockquote>
  How about prices for private training sessions or support by phone?
</blockquote>
If you send an email to training&nbsp; freertos.org, with details of the type of training you would be interested in, then I can forward it to our official training partner who can then enter into a dialogue with you &#40;he is currently on vacation for a few weeks though&#41;.&nbsp; You can see more information here:&nbsp; <a href="http://www.freertos.org/training.">http://www.freertos.org/training.</a>&nbsp; There are a few people around the world doing training with FreeRTOS, but I can&#8217;t recommend anybody in particular without first being familiar with their training material myself.  
FreeRTOS is what I would call a mini, preemptive, real time scheduler.&nbsp; It is designed to be small and portable.&nbsp; That means it does not necessarily provide all the features of larger systems.&nbsp; I&#8217;m not too familiar with ThreadX myself &#40;although I understand it is a good system&#41; so can&#8217;t really give a direct comparison.  
One thing you might consider is trying the FreeRTOS Windows simulator.&nbsp; <a href="http://www.freertos.org/FreeRTOS-Windows-Simulator-Emulator-for-Visual-Studio-and-Eclipse-MingW.html">http://www.freertos.org/FreeRTOS-Windows-Simulator-Emulator-for-Visual-Studio-and-Eclipse-MingW.html</a>&nbsp; It is quite comprehensive as it is used as a test and development bench too, so not so good for newbies, but for somebody such as yourself with previous kernel experience it is a convenient way of kicking the tires &#40;if you know that expression&#41;.&nbsp; Don&#8217;t expect real time out of it though &#8211; Windows idea of fine grain or accurate timing is very different to a microcontrollers idea.&nbsp; If you set it to &#8216;simulate&#8217; a 1KHz tick is think you will get about 1/30th of the intended speed.&nbsp; Setting it to a slower tick allows a more accurate representation, at the cost of less fine grained timing.  
Regards.
