  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Bug with vCoRoutineSchedule()</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/dkure">dkure</a> on August 22, 2011</div><div class="thread-post-content">Hi All,  
I hit what I think is a bug with the CoRoutine Scheduler.  
The bug is this.  
Place vCoRoutineSchedule&#40;&#41; in vApplicationIdleHook&#40;&#41;.<br />
Create one task, that calls while &#40;1&#41; vTaskDelay&#40;10&#41;;<br />
Watch the board crash.  
The problem with this arcitecture is that a co-routine must be created<br />
before calling vCoRoutineSchedule&#40;&#41;. This is because vCoRoutineSchedule&#40;&#41;<br />
depends on prvInitialiseCoRoutineLists&#40;&#41;, which is only called by&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; xCoRoutineCreate&#40;&#41;.  
However from the code in xCoRoutineCreate&#40;&#41; I can see no need for it calling<br />
prvInitialiseCoRoutineLists&#40;&#41;, instead I think that&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; prvInitialiseCoRoutineLists&#40;&#41; should be called by vTaskStartScheduler&#40;&#41;.  
The reason I have the architecure above is so that I can initialise hardware<br />
with the use a vTaskDelay&#40;&#41; when waiting for hardware to come up.<br />
After hardware is initialised I then start worker tasks, and in this case<br />
I start a watchdog worker co-routine.  
Richard what do you think of the problem &amp; solution? If you don&#8217;t really like&nbsp;&nbsp; the solution I am open to other ideas. Alternatively could you please place a&nbsp;&nbsp; mention somewhere in the API documentation that a co-routine must be created&nbsp;&nbsp;&nbsp; BEFORE calling vCoRoutineSchedule&#40;&#41;.  
Regards Paul
</div></div><div class="thread-post"><h3 class="thread-post-title">Bug with vCoRoutineSchedule()</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on August 22, 2011</div><div class="thread-post-content">I will have to take a look at it.&nbsp; Co-routines don&#8217;t get used that often, and I think all the examples create the co-routines before the scheduler is started.&nbsp; I would be grateful if you could open a bug tracker &#40;in SourceForge&#41; for this so it doesn&#8217;t get lost until I get time to look at it.  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">Bug with vCoRoutineSchedule()</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/dkure">dkure</a> on August 22, 2011</div><div class="thread-post-content">Richard,  
You are correct saying all the examples create co-routines before starting the scheduler. So hopefully not many people have hit this bug.  
I&#8217;ll post it on the bug tracker and place a link here so the two can be married up.
