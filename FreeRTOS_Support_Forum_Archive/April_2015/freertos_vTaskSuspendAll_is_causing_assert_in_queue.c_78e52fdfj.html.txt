  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">vTaskSuspendAll() is causing assert in queue.c</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/lantczak">lantczak</a> on April 7, 2015</div><div class="thread-post-content">Hi,
I found following problem.  
The vTaskSuspendAll() suspends scheduler.  It is called in many places in internal
freeRtos files (e.g. queue.c, task.c, heap_4.c)
The problem is that if scheduler is suspended and the IRQ occur and inside this IRQ I call
some API from freertos (e.g. xSemaphoreGiveFromISR or xQueueSendFromISR) then this call is
triggering following assert:
<pre><code>            #if ( ( INCLUDE_xTaskGetSchedulerState == 1 ) || ( configUSE_TIMERS == 1 )
</code></pre>
)
<pre><code>            {
                            configASSERT( !( ( xTaskGetSchedulerState() ==
</code></pre>
taskSCHEDULER_SUSPENDED ) &amp;&amp; ( xTicksToWait != 0 ) ) );
<pre><code>            }
</code></pre>
File queue.c function xQueueGenericSend. 
Simple test:
<pre><code>xSemaphoreHandle transmissionEnd;
transmissionEnd = xSemaphoreCreateBinary ();
UTILS_ASSERT (NULL != transmissionEnd);
vTaskSuspendAll();
xSemaphoreGiveFromISR (transmissionEnd, NULL); =&gt; this will trigger assert
</code></pre>
I&#8217;m using v8.0.0 but I suspect that it is also in the newest version
Any ideas ? 
<hr />
Best regards
Łukasz Antczak
</div></div><div class="thread-post"><h3 class="thread-post-title">vTaskSuspendAll() is causing assert in queue.c</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on April 7, 2015</div><div class="thread-post-content">I just searched the source files (V8.2.1, not V8.0.0 admittedly) and can find four occurrences of:
<pre>
configASSERT( !( ( xTaskGetSchedulerState() == taskSCHEDULER_SUSPENDED ) && ( xTicksToWait != 0 ) ) );</pre>
Two are in event_groups.c, so I have not looked at those.  Two are in queue.c.
One of the two in queue.c is in xQueueGenericReceive(), and the other is in xQueueGenericSend() &#8211; but neither of those functions should get called in an ISR.  xSemaphoreGiveFromISR() calls xQueueGiveFromISR() (or probably xQueueSendFromISR() in your version).
So I don&#8217;t know why you would hit those asserts &#8211; other than to say it looks like a non-ISR safe function is being called from an ISR.
I would recommend stopping on the debugger when the assert has been hit and looking at the call stack to see the sequence of function calls that took you to the assert.
Regards.
