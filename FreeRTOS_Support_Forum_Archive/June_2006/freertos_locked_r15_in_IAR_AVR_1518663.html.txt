  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">locked r15 in IAR AVR</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on June 14, 2006</div><div class="thread-post-content">Regarding the locked register r15 in iar avr port,
can i use c code in the enter critical-exit critical macro instead of the asm? i do not like the idea of having a reg less in a whole project just for saving the interupt status 
also the asm&#40; &quot;st -y, r15&quot; &#41; of enter critical and asm&#40; &quot;ld r15, y+&quot; &#41; in exit, can that cause troubles as the y index must be in the correct position when using exit critical?
I was thinking of using a static pointer to a location in ram&#40;that will be excluded from compiler usage&#41; and using c code in the macros thus removing the need for a locked register and tempering with stack, is that correct ?
</div></div><div class="thread-post"><h3 class="thread-post-title">locked r15 in IAR AVR</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on June 14, 2006</div><div class="thread-post-content">&gt; Regarding the locked register r15 in iar avr port,
&gt; can i use c code in the enter critical-exit critical macro instead of the asm?
This AVR port is one of the original ports and overdue for some improvements.&nbsp; It is based on the GCC port which has a tmp register that can always be scratched.&nbsp; Rather than IARing the port it was basically copied, hence the need for a locked register to mimic the GCC tmp register.
Newer ports keep a variable that has a critical nesting count &#40;look for CriticalNesting in the port files&#41;.&nbsp; This is saved as part of the task context.&nbsp; Doing it this way is a little less efficient but can be used no matter what the addressing mode of the processor as it does not alter the stack &#40;as the AVR port does&#41;.
Do you mean you want to write the enter and exit critical macros in C rather than assembly.&nbsp; Or that you want to place C code amid the assembly code?&nbsp; Provided you store the interrupt flag in a manner that allows calls to enter critical to be nested then I think you could do what you want.
&gt; also the asm&#40; &quot;st -y, r15&quot; &#41; of enter critical and asm&#40; &quot;ld r15, y+&quot; &#41; in exit,
&gt; can that cause troubles as the y index must be in the correct position when
&gt; using exit critical?
The y reg is used by the compiler as the stack pointer, so this will always just push onto the stack.
