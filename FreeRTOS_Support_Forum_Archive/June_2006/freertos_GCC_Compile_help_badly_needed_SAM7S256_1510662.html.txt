I have for some time now tried to compile FreeRTOS-4.0.2 without much success :-&#40;
Steps:
Downloaded and installed WinARM-20060331&#40;2&#41;.zip
Downloaded and unpacked FreeRTOSV4.0.2.zip
In Demo-&gt;ARM7&#95;LPC2106&#95;GCC typed &quot;make&quot; and this one compiles just fine. No Problem.
In Deme-&gt;lwIP&#95;Demo&#95;Rowley&#95;ARM7 typed &quot;make&quot; after adjusting the Heap Size it complains about &quot;undefined reference to &#96;&#95;sbrk&#95;r&#8217;&quot; and a lot of other udefined references to what I beleive belongs to Newlib.
I have searched for other references to this problem, but so far no luck. I saw one fix it with something related to syscalls.c/.h but didn&#8217;t rellay catch the hint.
Can someone out there help me make a succesfull build that I can later on &quot;Convert&quot; to a SAM7S256 ?
Cheers
RaceMouse
</div></div><div class="thread-post"><h3 class="thread-post-title">GCC Compile help badly needed ! (SAM7S256)</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on June 2, 2006</div><div class="thread-post-content">The ARM7&#95;LPC2106&#95;GCC demo should be built using one of the .bat files included in the same directory.&nbsp; These setup the parameters for ARM Vs THUMB and ROM Vs RAM builds.&nbsp; I did not think it would build simply by typing &#8216;make&#8217; but seems I am wrong.
The lwIP demo does require the change you have made to the heap size, but then builds with no warnings or errors for me.&nbsp; I am using gnuarm &#40;http://www.gnuarm.org/&#41; not winarm which is the compiler suggested on the FreeRTOS site.&nbsp; Have you tried this?
</div></div><div class="thread-post"><h3 class="thread-post-title">GCC Compile help badly needed ! I have never tried the winarm version of GCC.&nbsp; I suggest trying the www.gnuarm.com version as this is what the port was originally created with.&nbsp; You should find no compile time errors.
Regards.

</div></div><div class="thread-post"><h3 class="thread-post-title">GCC Compile help badly needed ! (SAM7S256)</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on June 2, 2006</div><div class="thread-post-content">Search your hard disk for cygwin1.dll &#8211; it is likely that you have more than one and the incorrect version is being picked up.
I just installed GNUARM using the prebuilt single Windows installation file.
My version is &quot;arm-elf-gcc &#40;GCC&#41; 4.0.2&quot;
With reference to Linux builds &#8211; I only test under Windows so often make the mistake of having case problems in include files.&nbsp; Windows does not care about this as it is case insensitive on file names, but of coarse Linux does care.&nbsp; I correct these are people point them out to me.
Regards.
