</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS API for running external file</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on July 22, 2011</div><div class="thread-post-content">As others have commented, you can&#8217;t load a &#8220;file.c&#8221; file into a machine &#40;unless you are writing an interpreter, which is a major task&#41;. You also can&#8217;t easily compile that &#8220;file.c&#8221; and load that into a running program. The closest operations to what you are describing is either build a dynamically linked library and dynamically loading it at run time, or the building of a second independent program that is loaded into memory in free space, which then runs, and when done returns back to the &#8220;executive&#8221; program.  
The first operation is probably what you are really asking for, but this sort of operation is in the domain of major operating systems &#40;like Windows or Unix&#41;, not real time kernels like FreeRTOS. I suppose you could build this on your own built on FreeRTOS, but it is a major undertaking. It may be possible to do a limited version if you can live with some constraints:<br />
1&#41; You will only load a single extra program at a time &#40;or able to divide them into 1 from column A and 1 from column B&#41;, and you reserve the space in your main program.  
2&#41; You can define a fixed and limited number of entry points into the loaded module that the main program will interact with &#40;this might be just an init function, that will setup the desired tasks&#41;, and assign fixed locations to place jumps to these entry points &#40;likely at the beginning of the reserved memory block&#41;   
3&#41; You can define a fixed and limited number of routines/data members that the loaded program needs to be able to call from the main program.&nbsp; This will probably include the set of FreeRTOS routines that the loaded program needs to be able to call, as well as some routines from the C library that you don&#8217;t want duplicated &#40;like malloc and free&#41;. You need to get your system to build a jump table for these functions at a fixed location in memory, and create a stub library that the loaded program is linked with the points calls to those routines to that jump table.  
This is doable, but is a significant project, and requires you to understand a lot of details about your implementation to make sure that you make the list in part 3 complete.

I regularly have programs that to add features I add a new source file, and than add a call to an init function in main&#40;&#41; to set up the task and any queues it needs.&nbsp; Since standard C has no way to force actions before main starts, you are going to need to edit main, or at least some file with some sort of list of init functions &#40;or tasks&#41; to process.
