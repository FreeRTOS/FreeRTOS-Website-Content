</div></div><div class="thread-post"><h3 class="thread-post-title">Stack size calculation</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on July 20, 2011</div><div class="thread-post-content"><blockquote>
  I was wandering how to calculate a stack size for a particular task ?
</blockquote>
That is not really a FreeRTOS question.&nbsp; You would calculate the stack size in exactly the same way you would for any other C program &#40;what is the maximum function call depth, what is placed on the stack by your application when at the maximum call depth, etc.&#41;.&nbsp; What FreeRTOS does do, however, is provide tools that will tell you how close the stack has ever come to overflowing &#40;the stack &#8220;high water mark&#8221;&#41;, so you have data you can use to adjust the stack accordingly to avoid RAM being wasted.  
<blockquote>
  What does it mean &#8220;Do I have to open source my application code that makes use of the FreeRTOS services? &#8211;&gt;&gt;<br />
  No, as long as the code provides functionality that is distinct from that provided by FreeRTOS 
</blockquote>
I&#8217;m not sure I can put it more succinctly than the table on this page: <a href="http://www.freertos.org/a00114.html">http://www.freertos.org/a00114.html</a>&nbsp; If your application makes use of FreeRTOS through its API but is not itself anything to do with implementing multitasking, then your application can be closed source, and only the kernel is open source.&nbsp; If you modify the kernel or add extra multitasking features to the existing kernel, then your modifications remain open source because they are in effect part of the kernel, but your application that uses the kernel still remains closed source.  
Regards.
