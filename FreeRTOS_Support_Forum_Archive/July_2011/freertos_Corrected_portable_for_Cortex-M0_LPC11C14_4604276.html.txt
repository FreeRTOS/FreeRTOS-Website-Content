  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Corrected portable for Cortex-M0 (LPC11C14)</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/dnadler">dnadler</a> on July 12, 2011</div><div class="thread-post-content">First thanks again Richard for the support &#33;  
It appears that crashing I encountered was caused by some<br />
problems in the &#8220;portable&#8221; components published by NXP.<br />
I&#8217;ve corrected sources, merging the M0-specific changes<br />
from NXP into FreeRTOS V7 ARM&#95;M3 distributed files:<br />
<a href="http://www.nadler.com/backups/20110712_portable_ARM_CM0.zip">www.nadler.com/backups/20110712&#95;portable&#95;ARM&#95;CM0.zip</a>  
Not included, and I&#8217;m not sure where this should go:<br />
MSP should be set up to point to a reserved small stack,<br />
just after switching the stack in use to PSP.<br />
Here&#8217;s the code I&#8217;m using &#40;for now in my main&#41;:  
<pre><code>  int answer = 46;
  debug_printf("CONTROL register=%08x, stack in use is %sn",__get_CONTROL(), (__get_CONTROL()&amp;0x2)?"PSP":"MSP");
  debug_printf("Handler mode ALWAYS uses MSP ('Main' stack pointer')n");
  debug_printf("Thread 'normal' mode is *recommended* to use PSP ('Process' stack pointer),n");
  debug_printf("...but defaults (on startup) to MSPn");
  // Set up "process" stack pointer and switch to it
  __set_PSP(__get_MSP()); // copy current stack pointer value into PSP
  __set_CONTROL(0x00000002); // switch to "process" stack pointer PSP
  debug_printf("After stack pointer switch: CONTROL register=%08x, stack in use is %sn",__get_CONTROL(), (__get_CONTROL()&amp;0x2)?"PSP":"MSP");
  debug_printf("The answer is %d (should be 46)n",answer);
  // Set MSP to a "safe reserved area", so an exception can run safely...
  static MSP_stack[100];
  __set_MSP((int)&amp;MSP_stack[99]);
</code></pre>
Any comments on my &#8220;portable&#8221; merge appreciated &#33;<br />
Thanks again,<br />
Best Regards, Dave  
PS: My app has now processed &gt;1 million CAN msgs<br />
very happily ;-&#41;
</div></div><div class="thread-post"><h3 class="thread-post-title">Corrected portable for Cortex-M0 (LPC11C14)</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/edwards3">edwards3</a> on July 12, 2011</div><div class="thread-post-content">I don&#8217;t know how the m0 compares to the m3, but on the m3 the interrupt stack uses the stack that was used by main before the kernel was started. The location of the start of the stack is read from the first position of the vector table, if I remember.  
If you have a modified port it would be good if you could post it to the <a href="http://interactive.freertos.org/">http://interactive.freertos.org</a> site. I&#8217;m sure people would appreciated that.
