</div></div><div class="thread-post"><h3 class="thread-post-title">why freertos use mostly static variables?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on July 23, 2011</div><div class="thread-post-content">I&#8217;m not sure I understand your question.&nbsp; You asked why <strong>FreeRTOS</strong> uses static <strong>members</strong>, and received a reasonable reply.&nbsp; However, the code you have posted is your own code, not FreeRTOS code.&nbsp; You can write your own code however you want.  
To use the same semaphore in two files you could make the semaphore declaration static, the provide a &#8216;get&#8217; function for the other file to receive a reference to it &#8211; but that would seem overkill.&nbsp; It would be better just to make it global.  
A comment on the code you posted though.&nbsp; It is breaking two very fundamental rules.&nbsp; First, it is calling a FreeRTOS API function that does not end in &#8220;FromISR&#8221; from an ISR.&nbsp; Second, the API function has a block time specified.&nbsp; You cannot block in an interrupt&#33;  
Regards.

</div></div><div class="thread-post"><h3 class="thread-post-title">why freertos use mostly static variables?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on July 24, 2011</div><div class="thread-post-content">If you need to protect a variable used in both tasks and interrupts, you need to use a critical section &#40;which basically disables interrupts&#41;. Because of how they work, they need to be kept short. The other option is to move the code in the interrupt that needs to access the variable into a high priority task, and have it waiting on a semaphore/queue from the interrupt.  
As to where the rule on API usage in interrupts, it is at <a href="http://www.freertos.org/api.html%2C">http://www.freertos.org/api.html,</a> in the paragraph marked &#8220;API Usage&#8221;
