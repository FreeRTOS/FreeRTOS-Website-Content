Defaulting xNextTaskUnblockTime to 0 will cause the Blocked task list to not be looked at until the tick count had overflowed &#8211; which would be a long long time in the future &#8211; unless a task entered the Blocked state, which would cause xNextTaskUnblockTime to be set to whatever the unblock time of that task was.&nbsp; In other words, I would not expect it to have any effect, and I could only find out why it did by stepping through the code.&nbsp; I would however, expect that is not related to whatever problem you are having.

</div></div><div class="thread-post"><h3 class="thread-post-title">xNextTaskUnblockTime in tasks.c  v7.0.1</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/mr4a494d4c">mr4a494d4c</a> on July 20, 2011</div><div class="thread-post-content">I solved the problem. Your last question pointed me in the right direction.<br />
Again thanks for your time and help.  
The vector table is placed at start of RAM, the first two items are:<br />
The first location in RAM&nbsp; 0x10000000 is the initial stack pointer&nbsp; &#95;vStackTop &#40;0x10002000&#41;&nbsp; gets put into SP out of reset and is defined in the linker file.<br />
The second location in RAM 0x10000004 is the address of&nbsp; ResetISR&#40;&#41;&nbsp;&nbsp; gets put into PC out of reset.  
The linker file:<br />
Defines &#95;vStackTop as &#40;0x10000000 + 0x2000&#41;&nbsp; // Top of 8K RAM and grows down, this gets put into initial stack pointer. OK so far.<br />
The LPC11C24 has 8K of RAM.  
The code needs a place to store the link register temporarily and it uses the initial stack pointer address 0x10002000.<br />
Well the address 0x10002000 points past the 8K RAM in hardware so it wraps around and points to 0x10000000 clobbering any variable sitting there.  
<pre><code>Snippet from xPortPendSVHandler( void )
" ldr r0, =0x0      n" /* cm0 has fixed vector table at address 0x0 */
" ldr r0, [r0]      n" /* Get initial stack pointer address (0x10002000)*/
" mov r4, r14       n" /* Load link register in r4 */  
" str r4, [r0]      n" /* Save r14 */     Save r14 to 0x10002000 which wraps around and points to 0x10000000
</code></pre>
