  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">EFM32 Demo not running (gcc tool chain)</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/tbrandon">tbrandon</a> on July 13, 2011</div><div class="thread-post-content">Copied the CORTEX&#95;EFMG890F128&#95;IAR directory to CORTEX&#95;EFMG890F128&#95;GCC and created a Makefile to use with the codesourcery tool chain &#40;version arm-2010q1&#41;.&nbsp; Unfortunately the demo does nothing … literary.&nbsp; After vTaskStartScheduler is called, the other tasks appear to be never called.&nbsp;   
Using gdb&nbsp; ^C reports:&nbsp;&nbsp;&nbsp; 0x000000c0 in &#95;IRQHandlerinterrupt &#40;&#41;  
Any ideas?  
Thanks.  
</div></div><div class="thread-post"><h3 class="thread-post-title">EFM32 Demo not running (gcc tool chain)</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on July 14, 2011</div><div class="thread-post-content">Well there could be one of twenty different things.&nbsp; From a three line description of what you have done I can only speculate on the most likely &#8211; and that would be that you have not populated the interrupt vector table correctly.&nbsp; Look at the other Cortex-M3 GCC demos &#8211; you need to populate the PendSV, SysTick and SVC interrupts with xPortPendSVHandler, vPortSysTickHandler and vPortSVCHandler respectively.  
If your project is using CMSIS, then you can map these to the CMSIS names by adding the following lines to FreeRTOSConfig.h, then including FreeRTOSConfig.h in the file that defines the vector table.  
&#35;define vPortSVCHandler SVC&#95;Handler<br />
&#35;define xPortPendSVHandler PendSV&#95;Handler<br />
&#35;define xPortSysTickHandler SysTick&#95;Handler  
Regards.
