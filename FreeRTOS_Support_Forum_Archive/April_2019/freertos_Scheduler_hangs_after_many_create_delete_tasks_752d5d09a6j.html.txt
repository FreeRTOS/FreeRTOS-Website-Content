</div></div><div class="thread-post"><h3 class="thread-post-title">Scheduler hangs after many create/delete tasks</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richarddamon">richarddamon</a> on April 19, 2019</div><div class="thread-post-content">Toni, the port.c assumes that the values are in the lower bits of the value, and computes the bits to shift into the control register.
What the assert would have caught is that you used that values someplace that needed them shifted up, it would see the priority as 0 which is too low.
</div></div><div class="thread-post"><h3 class="thread-post-title">Scheduler hangs after many create/delete tasks</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on April 19, 2019</div><div class="thread-post-content">Both configMAX<em>SYSCALL</em>INTERRUPT<em>PRIORITY and
configKERNEL</em>INTERRUPT_PRIORITY should be raw (therefore shifted)
values, assuming you are using an unedited version of FreeRTOS.
The asserts will not check you got the values as you intended them, as
it doesn&#8217;t know that, it will check that the values are consistent with
each other and consistent with the hardware.
