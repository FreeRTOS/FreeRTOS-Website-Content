  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">RTOS with CAN Bus</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/srcad">srcad</a> on April 27, 2019</div><div class="thread-post-content">Hi,
I&#8217;m having problems unblocking a task.
First, the project consists of two MCU&#8217;s communicating over the CAN Bus, and works fine before conversion to RTOS.
I&#8217;m starting by converting one device to RTOS, but I&#8217;m having problems unblocking the CAN RX task.
For this conversion,
I create two tasks of priority 2:
xTaskCreate(vtask<em>can</em>tx<em>data</em>handler, &#8220;TASK<em>TX&#8221;, 500, NULL, 2, &amp;xTaskHandle1);
xTaskCreate(vtask</em>can<em>rx</em>data<em>handler, &#8220;TASK</em>RX&#8221;, 500, NULL, 2, &amp;xTaskHandle2);
Timer 6 interrupt unblocks the vtask<em>can</em>tx<em>data</em>handler task with this line of code:
xTaskNotifyFromISR(xTaskHandle1, 0x00, eIncrement, pxHigherPriorityTaskWoken); //Unblock task from ISR
vtask<em>can</em>tx<em>data</em>handler then transmits CAN messages, and this works with no problems.
The other CAN device then sends a message back.
The trouble is with the can rx part.
When CAN data is received, the CAN rx interrupt occurs in:
void HAL<em>CAN</em>RxFifo0MsgPendingCallback(CAN_HandleTypeDef *hcan)
Here, I try to unblock the vtask<em>can</em>rx<em>data</em>handler task with a similar notification:
xTaskNotifyFromISR(xTaskHandle2, 0x00, eIncrement, pxHigherPriorityTaskWoken); //Unblock task from ISR
Putting a break point here, I know CAN data is being received and this line is being executed every time, but for some reason my vtask<em>can</em>rx<em>data</em>handler task never executes.
If I  just create the tx task and put the rx routine directly into:
void HAL<em>CAN</em>RxFifo0MsgPendingCallback(CAN_HandleTypeDef *hcan),
the program works fine with just the can tx task.
Also, as a test, if I unblock the rx task from a timer interrupt, it also executes. The problem seems to be related to unblocking it from void HAL<em>CAN</em>RxFifo0MsgPendingCallback(CAN_HandleTypeDef *hcan), and I can&#8217;t figure this out.
I tried increasing the stack size up to 8192 for each task and also making the priority of the rx task higher than the tx task, and using taskYIELD(); at the end of the tx task, but the rx task still does not execute.
When communication stops, I hit pause in the debugger to see where it might be hung up, but can&#8217;t really identify a problem as it always seems to be in a different part of the code. I&#8217;m not sure what to look for.
What do you think is the problem?
Thanks
</div></div><div class="thread-post"><h3 class="thread-post-title">RTOS with CAN Bus</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/srcad">srcad</a> on April 27, 2019</div><div class="thread-post-content">Also, the rx task is as follows:
void vtask<em>can</em>rx<em>data</em>handler(void *params)
{
    uint32_t current_notification_value = 0;
    while(1)  //Task should never return.
    {
            //Wait until receive notification (unblocked) from CAN rx interrupt.
            if(xTaskNotifyWait(0,0,&amp;current_notification_value,portMAX_DELAY) == pdTRUE)
            {
                //Process RX data, or just print a message for now&#8230;
            }
    }
}
</div></div><div class="thread-post"><h3 class="thread-post-title">RTOS with CAN Bus</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on April 27, 2019</div><div class="thread-post-content">If the code works from the timer interrupt but not the CAN interrupt
then my immediate thought is that there is something wrong in the
implementation of the CAN interrupt outside of the code that is
unblocking the task (as you have proven that part by running it in the
timer interrupt).  Are you clearing the CAN interrupt correctly?  Maybe
it is just continuously re-entering the interrupt handler.
</div></div><div class="thread-post"><h3 class="thread-post-title">RTOS with CAN Bus</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/srcad">srcad</a> on April 27, 2019</div><div class="thread-post-content">Thanks for the response Richard.
I think the HAL CAN API is handling the interrupt clearing, in addition to calling:
void HAL<em>CAN</em>RxFifo0MsgPendingCallback(CAN_HandleTypeDef *hcan)
As I mentioned, if instead of unblocking the task, I just put the contents of the task here, it works fine, and I don&#8217;t add any additional &#8220;clearing&#8221; function. Just like this:
void HAL<em>CAN</em>RxFifo0MsgPendingCallback(CAN_HandleTypeDef *hcan)
{
    //Process RX data, or just print a message for now, directly from here instead of unblocking a       task. //This works fine, but I just can&#8217;t seem to unblock a task from here.
}
</div></div><div class="thread-post"><h3 class="thread-post-title">RTOS with CAN Bus</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/srcad">srcad</a> on April 28, 2019</div><div class="thread-post-content">Actually Richard, you are correct.
I realized it this morning that the interrupt gets cleared after the received data is read.
In my case, its the HAL<em>CAN</em>GetRxMessage().
So, I call this from HAL<em>CAN</em>RxFifo0MsgPendingCallback(), unblock the task, then process the data in the task. Working great.
Two thumbs up, Thanks!
