</div></div><div class="thread-post"><h3 class="thread-post-title">Can FreeRTOS_select() be used with TCP type sockets?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on April 9, 2019</div><div class="thread-post-content"><blockquote>
  In other words is there anyway of having a non-blocking
  FreeRTOS<em>recv? Or a blocking FreeRTOS</em>recv for say 1 second?
  maybe using FreeRTOS_setsockopt()?
</blockquote>
Yes you can set the maximum time that <code>FreeRTOS_recv()</code> will wait by setting the socket option <code>FREERTOS_SO_RCVTIMEO</code>.
There are three different possibilities to handle multiple socket within a single task:
<pre><code>Method 1) Semaphores
Method 2) Socket call-backs
Method 3) Use select
</code></pre>
What you can do is call <code>FreeRTOS_recv()</code> and <code>FreeRTOS_send()</code> in a non-blocking way, and let the task block in a central place, either on a semaphore, or a task-notification, or a call to select().
<h2>Method 1) Semaphores</h2>
Give the task a semaphore and anyone can wake-up your task by giving to the semaphore ( <code>xSemaphoreGive()</code> or <code>xSemaphoreGiveFromISR()</code> ).
The IP-task can also give to the semaphore if you bind a socket to that semaphore ( on reception of data, on TX space available, on disconnect etc. )
Define in FreeRTOSIPConfig.h:
~~~
    #define ipconfigSOCKET<em>HAS</em>USER_SEMAPHORE    1
~~~
and bind the semaphore to every socket owned by the task. There is a NTP-demo (Network Time Protocol) which uses a semaphore:
~~~
    // Declare it
    static SemaphoreHandle_t xNTPWakeupSem = NULL;
<pre><code>// Create it
xNTPWakeupSem = xSemaphoreCreateBinary();
// Bind it
FreeRTOS_setsockopt(
    xUDPSocket,
    0,
    FREERTOS_SO_SET_SEMAPHORE,
    ( void * ) &amp;xNTPWakeupSem, sizeof( xNTPWakeupSem ) );
</code></pre>
~~~
This is a UDP socket, but it works the same for TCP sockets. The IP-task will give to the semaphore for <strong>any</strong> relevant event:
<ul>
<li>Data has arrived</li>
<li>Data has been sent and TX space is available ( TCP-only )</li>
<li>A connection is established ( either <code>accept()</code> or <code>connect()</code> )</li>
<li>A connection is broken ( or an error occurred )</li>
</ul>
~~~
    for( ;; )
    {
        // Sleep for 10 seconds
        xSemaphoreTake( xNTPWakeupSem, pdMS<em>TO</em>TICKS( 10000ul ) );
<pre><code>    /* Check sockets and messages in a non-blocking way. */
}
</code></pre>
~~~
<h2>Method 2) Socket call-backs</h2>
Define <code>ipconfigUSE_CALLBACKS</code> as 1 in FreeRTOSIPConfig.h
Now you can bind call-back ( application hooks ) to each of the sockets:
~~~
FREERTOS<em>SO</em>TCP<em>CONN</em>HANDLER  ( 6 )  /* Install a callback for (dis) connection events. <em>/
FREERTOS_SO_TCP_RECV_HANDLER  ( 7 )  /</em> Install a callback for receiving TCP data. <em>/
FREERTOS_SO_TCP_SENT_HANDLER  ( 8 )  /</em> Install a callback for sending TCP data. */
FREERTOS<em>SO</em>UDP<em>RECV</em>HANDLER  ( 9 )  /* Install a callback for receiving UDP data. <em>/
FREERTOS_SO_UDP_SENT_HANDLER  ( 10 ) /</em> Install a callback for sending UDP data. */
~~~
Define a handler, e.g. on-tcp-receive
~~~
    BaseType<em>t xOnTcpReceive( Socket</em>t xSocket, void * pData, size_t xLength )
    {
        xSemaphoreGive( myTaskSemaphore );
        // or
        xTaskNotifyGive( myTaskHandle );
<pre><code>    return 0; // KEEP the packet, it will be stored in the RX buffer of the socket
              // FreeRTOS_recv() must be called later-on
    // or
    return 1; // DISCARD the packet, it will not be stored
}
F_TCP_UDP_Handler_t handler;
handler.pxOnTcpReceive = xOnTcpReceive;
FreeRTOS_setsockopt( sock, 0, FREERTOS_SO_TCP_RECV_HANDLER,
    ( void * ) &amp;handler, sizeof( handler ) );
</code></pre>
~~~
Call-backs ( Application Hooks ) are always error-prone: it looks like user code, but in fact the code is run ( called ) from the IP-task.  Thus most +TCP API&#8217;s <strong>can not be called</strong> from within the call-back.
<h2>Method 3) Use select</h2>
Define <code>ipconfigSUPPORT_SELECT_FUNCTION</code> as 1 in your FreeRTOSIPConfig.h
And now you can use the select() functions. <a href="https://freertos.org/FreeRTOS-Plus/FreeRTOS_Plus_TCP/API/select.html">Here</a> you find documentation.
Using select() is less flexible: you can only wake-up the task if you can access the sockets.
You could use:
~~~
    #define ipconfigSUPPORT_SIGNALS     1
~~~
and interrupt a select() buy calling :
~~~
    FreeRTOS_SignalSocket()
~~~
Most compatible is 3) select(), while 2) semaphore is by far the easiest.
The FTP/HTTP demo servers use a single task. It blocks in a call to select(). It can handle an unlimited number of FTP- or HTTP-clients, only limited by the amount of available RAM.
