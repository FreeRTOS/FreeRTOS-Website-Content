  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">vTaskResume in an ISR</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on July 23, 2005</div><div class="thread-post-content">I&#8217;m playing with the LPC2106 + GCC &#8230; it seems that vTaskResume has an issue &#40;causes a pabort when it starts going through taskEXIT&#95;CRITICAL&#40;&#41;&#41; when it&#8217;s executed from the ISR. I was just wondering if this is normal before I start poking the port files&#8230;I have a timerISR that should resume the suspended task&#8230; I guess I could use the vTaskDelay but the timer provides me with exact timing which is kind of important in this case&#8230;&nbsp; 
</div></div><div class="thread-post"><h3 class="thread-post-title">vTaskResume in an ISR</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on July 23, 2005</div><div class="thread-post-content">vTaskResume&#40;&#41; can cause portYIELD&#40;&#41; to be called.&nbsp; This will happen if the task being resumed has a priority higher than the calling task&nbsp; or in your case if the task being resumed has a priority higher than the task that was interrupted.
Generally care must be taken using portYIELD&#40;&#41; from within an ISR.&nbsp; How it works is port dependent.&nbsp; In general, it should only ever be used at the end of an ISR.
If your application needs to do this then I suggest creating a xTaskResumeFromISR&#40;&#41; function.&nbsp; This would return whether or not a context switch is required or not, rather than actually perform the context switch.&nbsp; This would be easy to do&nbsp; take a look at the function xTaskResume&#40;&#41;.&nbsp; You will see the variable xYieldRequired&nbsp; this should be returned and the call to portYIELD&#40;&#41; removed.
This is then the equivalent to the xQueueSend&#40;&#41; and xQueueSendFromISR&#40;&#41; functions.&nbsp; You cant take a look at these two functions to see what I mean, and take a look at the FreeRTOSDemoARM7&#95;LPC2106&#95;GCCserialserialISR.c file to see how they are used.&nbsp; In serialISR.c the function vUART&#95;ISR&#40;&#41; uses xQueueReceiveFromISR&#40;&#41; and xQueueSendFromISR&#40;&#41;.&nbsp; The idea is that rather than have these function perform a context switch &#40;which you dont want from the middle of the ISR&#41;, they return whether or not a switch is required.&nbsp; Then at the end of the ISR&nbsp; when everything is cleaned up and the interrupt serviced and reset&nbsp; you can perform the context switch if required by calling portEXIT&#95;SWITCHING&#95;ISR&#40;&#41;.&nbsp; Note also that you require portENTER&#95;SWITCHING&#95;ISR&#40;&#41; at the top of the ISR.
An exact timing can be created for a task using vTaskDelayUntil&#40;&#41;&nbsp; providing the tick frequency is an exact multiple of the period you require.
