  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Using vTaskSuspend/vTaskResume</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on July 5, 2005</div><div class="thread-post-content">Hello&#33;
I want to use vTaskSuspend to suspend a task from sampling values. When the task is not suspended I use vTaskDelayUntil in order to get the task to execute every 1000 ticks. BUT, when the task has been suspended for some time and then resumed this delay does not apply for some reason. The task executes without any delay until it has &quot;caught up&quot; with the time somehow??&#33;&#33; Why is this and how do I fix it??
Thanks&#33;
/MB
</div></div><div class="thread-post"><h3 class="thread-post-title">Using vTaskSuspend/vTaskResume</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on July 5, 2005</div><div class="thread-post-content">Taking the example:
void vTaskFunction&#40; void &#42; pvParameters &#41;
&#123;
portTickType xLastWakeTime;
const portTickType xFrequency = 10;
&#95;&#95;&#95;&#95;// Initialise the xLastWakeTime variable with the
&#95;&#95;&#95;&#95;current time.
&#95;&#95;&#95;&#95;xLastWakeTime = xTaskGetTickCount&#40;&#41;;
&#95;&#95;&#95;&#95;for&#40; ;; &#41;
&#95;&#95;&#95;&#95;&#123;
&#95;&#95;&#95;&#95;&#95;&#95;&#95;&#95;// Wait for the next cycle.
&#95;&#95;&#95;&#95;&#95;&#95;&#95;&#95;vTaskDelayUntil&#40; &amp;xLastWakeTime, xFrequency &#41;;
&#95;&#95;&#95;&#95;&#95;&#95;&#95;&#95;// Perform action here.
&#95;&#95;&#95;&#95;&#125;
&#125;
xLastWakeTime holds the time in ticks the task was last unblocked from the vTaskDelayUntil&#40;&#41; call.&nbsp; When vTaskDelayUntil&#40;&#41; is called again the block time is added to xLastWakeTime to create the time at which the task should again be unblocked.
For example, if xLastWakeTime is 1000, the delay period is 100 and 50 ticks have passed since the task last unblocked then:&nbsp;&nbsp;&nbsp;&nbsp; xLastWakeTime is set to 1100, the current time is 1050 and the task will block for 50 ticks &#40;until the actual time reaches the wanted unblock time&#41;.
Now if the time that has passed between calles is greater than the block time then the value of xLastWakeTime will be less than the current time and the task will not block.
For example, if xLastWakeTime is 1000, and the delay period is 100, but 200 ticks have passed since the task was last unblocked then:&nbsp;&nbsp;&nbsp;&nbsp; xLastWakeTime will be set to 1100 but the current time will be 1200.&nbsp; If the task wants to unblock at time 1100 but the time is already 1200 then the unblock time has passed and the task never blocks.
This is what will happen if you suspend the task &#8211; and is the correct behaviour.&nbsp; The tick count continues when the task is suspended so the wanted wake time will be less than the current time and the task will not block.
To get around this you will need to reinitialise xLastWakeTime when the task is unblocked using:
xLastWakeTime = xTaskGetTickCount&#40;&#41;;
This should only be done when the task unblocks, not each cycle of the loop.
This line will refresh the xLastWakeTime with the current time, so the generated block time is relative to the current time, not the time the task last unblocked.
Maybe I have made this sound too complex &#40;?&#41; it is not really.
Regards.
