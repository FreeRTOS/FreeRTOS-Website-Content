  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">comtest/serial demo for ATmega128</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on July 28, 2005</div><div class="thread-post-content">I have been trying to get the demo code working on an atmega128 and I have succeeded at every point except for the function vAltStartComTestTasks.&nbsp; LED 4 is blinking very rapidly indicating transmitting, but LED 5 is not blinking at all; and LED 7 is not blinking.&nbsp; If I comment out the ErrorCheck for &#8230;ComTestTasks, then LED 7 will blink.&nbsp; So all the other tasks are running fine.&nbsp; &#40;I have connected pins 2,3 on the DB-9 connector.&#41;
I am not using an STK500 board and have the following questions concerning the instructions for porting to it:
1&#41; What is being done when PORTD bits 0, 1 are connected to RS &#40;what does RS mean?&#41;?
2&#41; What is being done when SPROG3 is connected to ISP6PIN? &#40;Are these things I need to worry about; I am using an ATmega128 development board from PRLLC&#41;
And then in comtest.c, the tasks vComTxTask and vComRxTask are created, but in all my searching of the source files and headers I cannot find where they are defined.&nbsp; It seems these could play a very important role in the code or not much of one at all.&nbsp; I see that at the beginning of comtest.c there are declarations:
static portTASK&#95;FUNCTION&#95;PROTO &#40;&#41; 
with the two tasks being a parameter each time it is declared, but I am not quite understanding what is going on here.&nbsp; 
Thanks for any and all help,
Josh
</div></div><div class="thread-post"><h3 class="thread-post-title">comtest/serial demo for ATmega128</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on August 3, 2005</div><div class="thread-post-content">I finally got everything up and running.&nbsp; It was simply a matter of naming convention.&nbsp; In Minimal/comtest.c I needed to change SIG&#95;UART&#95;RECV and SIG&#95;UART&#95;DATA to SIG&#95;UART1&#95;RECV and SIG&#95;UART1&#95;DATA.
Thanks again for the quick replies and the help
-Josh
