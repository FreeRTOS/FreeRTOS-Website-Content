i saw the uIP demo for lpc2368 and would like to use the smallest 
&#40;and cheapest&#41; possible lpc23xx controller instead of the 2368.
as i still don&#8217;t have any lpc hardware here, i&#8217;d like to know 
if i can get it to fit on a 2364 and still have a little room 
to add my own application code.
so how much flash and sram memory is still free with this demo
on the 2368?
P.S.: the difference in memory size between the devices is the following:
device&nbsp; / flash / local bus sram 
lpc2364 / 128kB / 8kB
lpc2366 / 256kB / 32kB
lpc2368 / 512kB / 32kB&nbsp; 
</div></div><div class="thread-post"><h3 class="thread-post-title">uIP demo on lpc23xx: how much memory?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on May 16, 2007</div><div class="thread-post-content">As downloaded the kernel and uIP stack only have a footprint as follows:
Kernel &#8211; 7.4K ROM and 350bytes RAM + the heap
uIP &#8211; 14K ROM including the WEB pages, and 11K RAM
Note however:
No effort has been made to reduce the code size.&nbsp; This is not fully optimised, and unused symbols have not been removed.&nbsp; Using GCC it has been proven to me that the kernel size can be a little as 4K &#40;actually about the same as the IAR build&#41; if unused symbols are removed.
The more RAM you provide uIP the better the throughput can be.&nbsp; You can provide uIP with tiny buffers of a few hundred bytes if slow throughput is ok for your application.&nbsp; I can&#8217;t recall the buffers allocated to the Ethernet hardware itself.
Read the memory management section of the FreeRTOS.org site for information on the heap usage, and the memory FAQ for information on how much heap each task and queue will take.
I think your best bet is to get a copy of CrossWorks &#40;eval versions are available&#41; and try configuring it for the low RAM version of the LPC to see if you can get it to fit or not.&nbsp; 8K is really not very much, so I think it will be a push.
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">uIP demo on lpc23xx: how much memory?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on May 16, 2007</div><div class="thread-post-content">thanks for the info
as i understand from what you write, the one thing that eats up a lot is uIP for ethernet buffers.
what i didn&#8217;t write in the &quot;memory difference&quot; listing &#40;cause it&#8217;s the same for all lpc23xx&#41; is 
that all these devices have an independent 16kB SRAM just for the ethernet mac buffers. the ethernet
dma transfers go directly from/to there.
i read this buffer mem is mapped to local sram, but i don&#8217;t know if that means it can be used for
general purpose memory stuff.
so the question is: does the uIP demo for lpc23xx use those 16kB special ethernet sram for buffers
&#40;in which case there shouldn&#8217;t be a real problem with 8kB normal sram&#41; or does it only know general
sram and doesn&#8217;t make the difference between the 16kB buffers and the 8kB general purpose sram?
if the latter is the case, the question is: can the 16kB buffer mem be used like normal sram 
&#40;in which case the lpc2364 would have 24kB usable sram&#41; or not?
