  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">robot controller recommendation</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/jstrout">jstrout</a> on May 24, 2007</div><div class="thread-post-content">I&#8217;m looking for a microcontroller board for hobby robotics projects.&nbsp; I can see the advantages of FreeRTOS &#40;thanks in part to the article by Phil Davis in the September &#8217;06 Servo&#41;.&nbsp; I&#8217;m hoping someone here can suggest something that:
&#45; can be easily programmed from a Mac OS X machine
&#45; sports a reasonable number of digital I/O lines and A/D inputs
&#45; costs less than $50
&#45; and of course, is compatible with FreeRTOS
I rather like the looks of the gnuarm toolchain &#40;they have precompiled binaries available for my platform, which is a big plus&#33;&#41;.&nbsp; But I&#8217;d take an AVR board too if you can recommend a toolchain.
If it helps, ARM boards I&#8217;ve seen are the Futurlec &quot;ET-ARM Stamp&quot; &#40;uses an LPC2119&#41;, the Futurlec &quot;ARM2103&quot; &#40;LPC2103&#41;, the New Micros &quot;Tini2131&quot; &#40;LPC2131&#41;, and the Coridium &quot;ARMmite&quot; &#40;ARM7&#41;.
In the AVR world, I&#8217;ve seen various controllers in my price range based on the ATMega128 and ATMega168.&nbsp; I&#8217;m still unsure how easy it is to program these from OS X, but I think it can be done.
So.&nbsp; From a FreeRTOS point of view, any recommendations?
Thanks,
— Joe

Thanks,
&#45; Joe
</div></div><div class="thread-post"><h3 class="thread-post-title">robot controller recommendation</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on May 24, 2007</div><div class="thread-post-content">Sorry, I misunderstood.&nbsp; I thought you were saying that you had seen and discounted the use of those boards.
FreeRTOS will run on any AVR or LPC that has enough RAM.&nbsp; It might be that the LPC210x devices don&#8217;t have enough RAM &#40;I have not checked, but I know they are small devices&#41;.&nbsp; Take a look at the FAQ on the FreeRTOS site for some figures on the required RAM usage on ARM7.&nbsp; If there is not enough RAM you can still use co-routines as these all share a stack.
If there is not a FreeRTOS port directly for the board/chip you required then generally all you need to do is change the linker script used by the makefile to correctly describe the memory layout for the chip you are using.
A couple of things to watch out for.&nbsp; First some AVRs now have a three byte program counter, which is not compatible with the AVR port in the download.&nbsp; I think there is some information in this group about how to make it compatible.&nbsp; Second, some of the newer LPC devices have a slightly different timer peripheral.&nbsp; There are two LPC port types, one for the LPC2368 style timer and one for the LPC2106 type timer.&nbsp; The differences are very small and example code is available for both.
Dave.
