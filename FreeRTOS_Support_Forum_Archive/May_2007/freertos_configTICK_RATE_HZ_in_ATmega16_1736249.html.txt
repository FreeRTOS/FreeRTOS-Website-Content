</div></div><div class="thread-post"><h3 class="thread-post-title">configTICK_RATE_HZ in ATmega16</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on May 16, 2007</div><div class="thread-post-content">Take a look at the function prvSetupTimerInterrupt&#40;&#41; in port.c for the GCC/AVR port.&nbsp; It might be that the compare match value written to the timer peripheral is overflowing because you are dividing the clock frequency by such a low number &#40;20 instead of 1000&#41;.&nbsp; If this is the case then you might need to adjust the timer prescale, or do something similar.
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">configTICK_RATE_HZ in ATmega16</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on May 17, 2007</div><div class="thread-post-content">I figured it out :-&#41; After trying change same values on the prvSetupTimerInterrupt&#40;&#41;, I did discover the real problem :-&#41; LOL
I work on Linux and I was on this directory: &quot;/media/data/05&#95;assembly/ATMEL/FreeRTOS/Demo/AVR&#95;ATMega323&#95;WinAVR&quot; and I also had this one &quot;/media/data/05&#95;assembly/ATMEL/FreeRTOS/Demo/AVR&#95;ATMega323&#95;WinAVR-copy&quot;. I don&#8217;t know why, but looks like the system was using the &quot;FreeRTOSConfig.h&quot; from directory &quot;AVR&#95;ATMega323&#95;WinAVR-copy&quot; instead of that where I was working &quot;AVR&#95;ATMega323&#95;WinAVR&quot;&#33;&#33;
Now all works ok after delete &quot;AVR&#95;ATMega323&#95;WinAVR-copy&quot; ;-&#41; :-&#41;
