  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Difference between FreeRTOS examples for CM0 </h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/safwathimel">safwathimel</a> on December 18, 2012</div><div class="thread-post-content">Hi,<br />
I am working on a LPCXpresso 1227 board, which is a M0 device.<br />
Looking at the official demo provided with FreeRTOS for other M0 devices&#40;LPC1114 and STM32F051&#41; I don&#8217;t see the following parameters in the &#8220;FreeRTOSConfig.h&#8221; file.  
<pre><code>#define configKERNEL_INTERRUPT_PRIORITY 
#define configMAX_SYSCALL_INTERRUPT_PRIORITY
</code></pre>
The documentations describes a reference method for handling interrupts by using semaphores to sync a task with the ISR and use portEND&#95;SWITCHING&#95;ISR&#40;&#41;.  
My confusion arises when i look at the LPCXpresso support site over at NXP, where they are providing demos which make use of the configKERNEL&#95;INTERRUPT&#95;PRIORITY and configMAX&#95;SYSCALL&#95;INTERRUPT&#95;PRIORITY &#40;at least they are defined in FreeRTOSConfig.h&#41;  
Another difference is that they dont include the following mapping…  
<pre><code>    #define vPortSVCHandler      SVC_Handler
    #define xPortPendSVHandler   PendSV_Handler
    #define xPortSysTickHandler  SysTick_Handler
</code></pre>
Which are present in the the official M0 port.  
Can someone tell me, are both of them correct?<br />
Why does the NXP demo omit the mapping of the IRQ handlers?<br />
Why are settings for configKERNEL&#95;INTERRUPT&#95;PRIORITY and configMAX&#95;SYSCALL&#95;INTERRUPT&#95;PRIORITY not configurable in the official FreeRTOS port?   
I am facing some frequent system hangs when using the LPC1200 Series demo at NXP site, my system uses UART and GPIO interrupts. Might be my code, but I wanted to understand this topic first. Thanks to anyone who helps.
</div></div><div class="thread-post"><h3 class="thread-post-title">Difference between FreeRTOS examples for CM0 </h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on December 18, 2012</div><div class="thread-post-content"><blockquote>
  Looking at the official demo provided with FreeRTOS for other M0 devices&#40;LPC1114 and STM32F051&#41; I don&#8217;t see the following parameters in the &#8220;FreeRTOSConfig.h&#8221; file.  
</blockquote>
&#35;define configKERNEL&#95;INTERRUPT&#95;PRIORITY<br />
&#35;define configMAX&#95;SYSCALL&#95;INTERRUPT&#95;PRIORITY
These are not used in M0 ports.&nbsp; They are in M3, M4 and M4F.  
<blockquote>
  Another difference is that they dont include the following mapping…  
</blockquote>
&#35;define vPortSVCHandler&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; SVC&#95;Handler<br />
&#35;define xPortPendSVHandler&nbsp;&nbsp; PendSV&#95;Handler<br />
&#35;define xPortSysTickHandler&nbsp; SysTick&#95;Handler  
Which are present in the the official M0 port.
They probably install the handlers directly into the vector table.&nbsp; See item one here <a href="http://www.freertos.org/FAQHelp.html">http://www.freertos.org/FAQHelp.html</a>  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">Difference between FreeRTOS examples for CM0 </h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/safwathimel">safwathimel</a> on December 19, 2012</div><div class="thread-post-content">Thanks for the quick reply.  
I found that NXP did actually install those handlers directly in the vector table. So that part is understandable.  
As for the first question, If M0 port does not require&nbsp; <strong><em>configKERNEL&#95;INTERRUPT&#95;PRIORITY</em></strong> and <em><strong>configMAX&#95;SYSCALL&#95;INTERRUPT&#95;PRIORITY</strong></em> does it mean I can leave my peripheral interrupt priorities at their default level &#40;which is the maximum&#41;?&nbsp;   
I have interrupt handlers which makes queue access. So I am using the ISR safe version of the API functions with <em>portEND&#95;SWITCHING&#95;ISR&#40;&#41;</em> at the end of the ISR to ensure context switch.   
Just want to make sure my concept of using ISR is correct for a m0 port.
