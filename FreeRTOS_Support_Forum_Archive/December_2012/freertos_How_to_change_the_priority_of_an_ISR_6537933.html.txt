  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">How to change the priority of an ISR?</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/joe0x7f">joe0x7f</a> on December 30, 2012</div><div class="thread-post-content">On page 155 of the &#8220;Using The FreeRTOS Real Time Kernel, NXP LPC17xx Edition&#8221; 2nd edition book, it says, &#8220;Do not use any &lt;FreeRTOS&gt; API functions from an interrupt &lt;ISR&gt; that has been assigned&nbsp; an interrupt priority above configMAX&#95;SYSCALL&#95;INTERRUPT&#95;PRIORITY.&#8221;  
My question is how can I violate this rule?<br />
If I am reading/understanding this correctly, how can I change the priority of an ISR?&nbsp; Is there more than one way to change this priority?  
Thanks&#33;  
</div></div><div class="thread-post"><h3 class="thread-post-title">How to change the priority of an ISR?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on December 31, 2012</div><div class="thread-post-content">All the &#40;non exception&#41; interrupt priorities can be configured directly by writing to the NVIC &#40;Nested Vectored Interrupt Controller&#41; registers, which are part of the Cortex-M3 core.&nbsp; Working out how to do this directly is however somewhat difficult and required reading the Cortex-M technical reference manuals from ARM &#40;to get the register addresses&#41; and the datasheet from the microcontroller manufacturer &#40;to find which peripheral interrupts map to which NVIC interrupts&#41;.&nbsp; Therefore, these days at least, it is extremely rare to try and do this yourself.&nbsp; Instead there are library functions that make the task much easier.  
If you are using CMSIS libraries then you can use the NVIC&#95;SetPriority&#40;&#41; function.&nbsp; For example on the LPC17xx you can call NVIC&#95;SetPriority&#40;TIMER0&#95;IRQn, configMAX&#95;SYSCALL&#95;INTERRUPT&#95;PRIORITY&#41;; to give an interrupt priority the maximum value allowable if it uses a FreeRTOS API function .  
Other manufacturers use different API functions, but the CMSIS version is normally available too.  
There are two things that complicate it further &#40;interrupts on the Cortex-M are generally more complex than other CPUs&#41;:  
1&#41; Different microcontrollers implement a different number priority bits.&nbsp; Again if you are using CMSIS you should have &#95;&#95;NVIC&#95;PRIO&#95;BITS defined which tells you how many there are.&nbsp; On the LPC17xx I think it is 4, so priorities can go from 0 &#40;the highest&#41; to 0x0f &#40;the lowest&#41;.  
2&#41; The priority bits are sub-divided into preemption priority and sub priority.&nbsp; You want all the bits to be assigned to be preemption priority bits, and that is the default in the NXP libraries so you need not worry about that &#40;generally in my experience the libraries from ST are the only ones where this is not the case.  
Further reading on the subject if you are feeling brave:<br />
<a href="http://www.freertos.org/RTOS-Cortex-M3-M4.html">http://www.freertos.org/RTOS-Cortex-M3-M4.html</a>  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">How to change the priority of an ISR?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/joe0x7f">joe0x7f</a> on December 31, 2012</div><div class="thread-post-content">Thanks Richard&#33;  
How do we tell what priority an ISR has relative to the other tasks?  
</div></div><div class="thread-post"><h3 class="thread-post-title">How to change the priority of an ISR?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on December 31, 2012</div><div class="thread-post-content">Don&#8217;t confuse interrupt priorities with task priorities.&nbsp;   
Interrupt priorities are purely a hardware thing.&nbsp; Task priorities are purely a software thing.&nbsp; Tasks have the ability to mask out interrupts, but if interrupts are not masked they will <strong>always</strong> interrupt a task &#8211; even if it is the lowest priority interrupt that is interrupting the highest priority task.  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">How to change the priority of an ISR?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/joe0x7f">joe0x7f</a> on December 31, 2012</div><div class="thread-post-content">So FreeRTOS can mask interrupts with this:  
taskENTER&#95;CRITICAL&#40;&#41; and taskEXIT&#95;CRITICAL&#40;&#41; sections of code.  
Are there other FreeRTOS ways of doing this?  
Thanks&#33;  
</div></div><div class="thread-post"><h3 class="thread-post-title">How to change the priority of an ISR?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on December 31, 2012</div><div class="thread-post-content">It is intended that taskENTER&#95;CRITICAL&#40;&#41; and taskEXIT&#95;CRITICAL&#40;&#41; is the only method used as these count the call nesting depth.&nbsp; For example, if you call ENTER&#95;CRITICAL&#40;&#41; twice you also have to call EXIT&#95;CRITICAL&#40;&#41; twice before interrupts are unmasked again.  
Regards.
