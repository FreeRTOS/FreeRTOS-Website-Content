</div></div><div class="thread-post"><h3 class="thread-post-title">STM32 eval board version</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on December 18, 2012</div><div class="thread-post-content">The board I have is almost certainly to be a first revision as I tend to get hardware in advance of release.&nbsp; I don&#8217;t think you will be able to purchase anything but the latest revision anyway.&nbsp; The LCD used on the board is the most likely thing to change as the production life of LCDs is limited as technology advances.&nbsp; In any case, it might be a completely different LCD if the board is not the same.  
The parts of the demo that do not rely on IO should run anyway, provided you have the linker script and start up files correct for your hardware.&nbsp; As the code is running, then start up would not seem to be an issue.  
At what point does it stop running?&nbsp; If it stops running when you try and start the scheduler then see if the first item in the list on this page helps:&nbsp; <a href="http://www.freertos.org/FAQHelp.html">http://www.freertos.org/FAQHelp.html</a>  
I would suggest starting by ensuring you can blink the LEDs on your hardware.&nbsp; The LED IO functions can be found in partest.c &#40;historical name, used to stand for &#8220;parallel port IO test&#8221;&#41;.&nbsp; In main try calling:  
vParTestSetLED&#40; 0, 1 &#41;; /&#42; LED 0 on. &#42;/<br />
vParTestSetLED&#40; 0, 0 &#41;; /&#42; LED 0 off. &#42;/<br />
vParTestSetLED&#40; 1, 1 &#41;; /&#42; LED 1 on. &#42;/<br />
vParTestSetLED&#40; 1, 0 &#41;; /&#42; Etc. &#42;/<br />
vParTestSetLED&#40; 2, 1 &#41;;<br />
vParTestSetLED&#40; 2, 0 &#41;;  
to see if the LEDs toggle.&nbsp; If they don&#8217;t, adjust the IO used in partest.c &#40;and possibly the prvSetupHardware&#40;&#41; function in main.c if that is where the IO port is initialised&#41; until they do.&nbsp; Once the LEDs work you will get some visual feedback as to whether the code is running.  
Next comment out all the demo tasks that are created in main&#40;&#41; other than the ones that toggle the LEDs &#40;the LEDs will be toggled either by the Flash tasks, or possibly by software timers&#41; and run the code.&nbsp; Do the LEDs flash?&nbsp; If not, what is the code doing and do the flash tasks ever get entered &#40;put a break point at the top of the task&#41;.  
Regards.
