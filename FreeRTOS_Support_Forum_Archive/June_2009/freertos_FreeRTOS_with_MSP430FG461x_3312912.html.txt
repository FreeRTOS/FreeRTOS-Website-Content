  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">FreeRTOS with MSP430FG461x</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/cantiwrx16">cantiwrx16</a> on June 24, 2009</div><div class="thread-post-content">Hi,
I&#8217;m working on a project that may deem necessary to implement freeRTOS with the MSP430.&nbsp; The board we&#8217;re using is TI Experimenter&#8217;s board with the MSP430FG4618.&nbsp; I altered the demo code from the MSP430IAR port and got it to compile and download. The problem is the scheduler won&#8217;t execute any task.&nbsp; I checked the LED test file and also the hardware setting and they seem fine &#40;I had the LED and serial communication to work before running the scheduler&#41;. I also made sure the code conforms with the addressing scheme of the interrupt vector of that chip.&nbsp; One thing I noticed is that the timer interrupt is not being called.&nbsp; Does anyone have experienced working with FreeRTOS on this chip that can help me get the demo to work?&nbsp;&nbsp;&nbsp; 
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS with MSP430FG461x</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/jakbird">jakbird</a> on June 25, 2009</div><div class="thread-post-content">The MSP430F461x family uses the extended MSP430X architecture, with 20 bit registers.&nbsp; If you are accessing anything above the 64K boundary or do 20-bit calculations then you&#8217;ll have problems with the FreeRTOS distribution for MSP430, as the context switching doesn&#8217;t handle 20-bit registers.
I have a portable.c module working on the MSP430F5438, using CCE3 compiler, but not well-tested.&nbsp; I can email the portable code if your problem is in the MSP430X changes.
Did you check the error code when you try to start the scheduler?&nbsp; You may not have enough heap memory.&nbsp; If the scheduler doesn&#8217;t start, and enable interrupts, then you wouldn&#8217;t see the timer interrupt.
&nbsp; Jack Peacock
