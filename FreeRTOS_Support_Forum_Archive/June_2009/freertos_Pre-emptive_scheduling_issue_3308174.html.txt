  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Pre-emptive scheduling issue</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/vchandra">vchandra</a> on June 19, 2009</div><div class="thread-post-content">Dear All
I am getting round robin scheduling &#40; equal time slice between tasks &#41; behavior even though i have configured to&nbsp; 
Preemptive scheduling mechanism. I tried to explain my sample application below. 
Microcontroller : NEC V850
Tick rate : 8ms
configUSE&#95;PREEMPTION : 1
Sample Application : 1
Two tasks were created with priority 1 and 2. In each task,seperate test pin &#40;I/O pin configured as Output&#41; is toggled continuesly for DSO measurement.
I expected that highest priority task always executes continously without allowing low priority task. But it executes by round robin scheduling manner.
Now i have changed both tasks priority to 1. Still it executes by round robin scheduling manner irrespective of priority changes.
Is my expectation correct?
If anything is wrong then please reply&#33;
Regards
</div></div><div class="thread-post"><h3 class="thread-post-title">Pre-emptive scheduling issue</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on June 19, 2009</div><div class="thread-post-content">Does the higher priority task wait for anything? &#40;Like a call to vTaskDelay?&#41; If so, when it does so it tells the kernel it doesn&#8217;t need the processor at the moment and it gives time to the lower priority task.
</div></div><div class="thread-post"><h3 class="thread-post-title">Pre-emptive scheduling issue</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/vchandra">vchandra</a> on June 22, 2009</div><div class="thread-post-content">Hi
Thanks for your feedback. 
I didn&#8217;t use delay routine. I am new to freeRTOS usage. So i want to test pre-emptive schedular feature between tasks and also round robin scheduler feature.
As per my understanding, Low priority will not get chance to get execute if higher task is executing without any possibilities of block/suspend state. Thats what i expected in sample application.
Regards
</div></div><div class="thread-post"><h3 class="thread-post-title">Pre-emptive scheduling issue</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/incrediball">incrediball</a> on June 22, 2009</div><div class="thread-post-content">Your assumption is correct. The low priority task will not run as long as the high priority task is not suspended. It can be suspended by a delay command, when taking a semaphore, waiting for queued data, etc.
