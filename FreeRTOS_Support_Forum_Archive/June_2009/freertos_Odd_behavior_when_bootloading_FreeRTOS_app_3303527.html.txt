  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Odd behavior when bootloading FreeRTOS app</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/marshallmallow">marshallmallow</a> on June 15, 2009</div><div class="thread-post-content">I&#8217;ve written a boot loader for an ARM7 lpc2148.&nbsp; The bootloader simply looks for a firmware file on an sd card and writes the file out to program memory.&nbsp; It then starts execution of the firmware.&nbsp; The firmware is the same as the orginal app, only the linker script designates program memory starting at address 0x20000.
When the bootloader starts execution of the app, I&#8217;m seeing some very odd behavior.&nbsp; When the first task is run, if I step into each line of code,&nbsp; everything works fine.&nbsp; If I step over each line of code, then the first time I step over a function in the task, execution goes back to the bootloader.&nbsp; I&#8217;m not seeing any kind of ARM exception such as data abort, execution just appears to restart at 0x0000.
Is there something I&#8217;m missing?&nbsp; I don&#8217;t see why there would be any problem with what I&#8217;m doing.&nbsp; Since all of the stacks are reinitialized when the app starts execution and the first task is actually starting, then why would there be a problem during the first function call?
Thanks for any insight.
</div></div><div class="thread-post"><h3 class="thread-post-title">Odd behavior when bootloading FreeRTOS app</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on June 15, 2009</div><div class="thread-post-content">These problems are normally down to the vector table location. Where are you putting the vector table and how are you telling the mcu where it is? The ARM7 will attempt to read it from 0.
</div></div><div class="thread-post"><h3 class="thread-post-title">Odd behavior when bootloading FreeRTOS app</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/marshallmallow">marshallmallow</a> on June 15, 2009</div><div class="thread-post-content">You are indeed correct.&nbsp; I stepped through until I hit a taskYield&#40;&#41; and saw that execution dropped back to 0x0008 so the ARM7 is looking for the vector table at 0 as you said.&nbsp; Apparently, stepping over function calls was giving FreeRTOS enough time to preempt the task I was looking at and perform a context switch.&nbsp; I assume single stepping prevented the timer interrupt from being called enough to require a context switch.
Looks like I just need to map the interrupts to ram and copy them over for the bootloaded app.
Thanks&#33;
