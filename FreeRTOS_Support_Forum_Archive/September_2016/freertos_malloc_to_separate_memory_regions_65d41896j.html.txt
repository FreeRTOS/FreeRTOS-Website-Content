  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">malloc to separate memory regions</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/logicanalyzer">logicanalyzer</a> on September 16, 2016</div><div class="thread-post-content">I have different classes of memory, (faster, slower, nearby, farther away) and I would like to control where malloc allocates memory. The heap_5 scheme allows the heap to span multiple non-contiguous memory regions but treats them as a single heap.
I need separate heaps and a way to control which one malloc allocates from. Is there a straightforward way to do this, or do I need to write heap_6.c?
</div></div><div class="thread-post"><h3 class="thread-post-title">malloc to separate memory regions</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on September 16, 2016</div><div class="thread-post-content">I think there might be a change request on this topic already.  Basically it is not a straight forward change because it would need a new parameter to the pvPortMalloc() function, and that would have lots of backward compatibility issues.  However, you can have more than one memory allocator in your application &#8211; so the FreeRTOS code would call the &#8216;standard&#8217; pvPortMalloc(), and your application can call whichever memory allocation function is most appropriate for the memory being allocated.

I&#8217;m new to FreeRTOS and in reading the docs it states: <em>&#8220;Using two heap implementations simultaneously permits task stacks and other RTOS objects to be placed in fast internal RAM, and application data to be placed in slower external RAM. &#8220;</em> but then later (regarding the five heap implementations) it states: <em>&#8220;Exactly one of these source files should be included in a project at a time&#8221;</em>
 That seems a bit contradictory. I guess this raises two different questions:
<ul>
<li>Can you define which heap region will be used when making a call to pvPortMalloc()? I have SRAM and SDRAM (slower) which I&#8217;d like to use for different purposes as the example suggests.
<ul>
<li>Can you actually use two implementations as the first quote suggests? This seems like less of a concern but I&#8217;m still confused by the wording.</li>
</ul></li>
</ul>
An actual example, or more clarification on the documentation page would be helpful. Overall the docs are very good, but I want to make sure I understand this before jumping into my project.
</div></div><div class="thread-post"><h3 class="thread-post-title">malloc to separate memory regions</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on May 19, 2018</div><div class="thread-post-content">You can edit the name of the functions in one of the version of the heap files, and then you can include both. </div></div><div class="thread-post"><h3 class="thread-post-title">malloc to separate memory regions</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on May 20, 2018</div><div class="thread-post-content">Yes &#8211; and I suspect the quoted text is basically saying this in that 
RTOS code (internally) can call pvPortMalloc() and application code can 
call malloc() directly (with all the normal thread safety, etc., caveats 
around that) so the RTOS objects come from a different heap to 
everything else.
