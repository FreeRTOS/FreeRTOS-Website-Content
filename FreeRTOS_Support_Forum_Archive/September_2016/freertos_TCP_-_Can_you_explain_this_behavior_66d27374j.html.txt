</div></div><div class="thread-post"><h3 class="thread-post-title">TCP &#8211; Can you explain this behavior?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on September 28, 2016</div><div class="thread-post-content">A TCP server socket has a fixed port number and it may be reused again and again.
If a TCP client socket uses the same local port number, it is very confusing.
A connection is identified by 4 numbers:
<ul>
<li>source IP-address</li>
<li>source port number</li>
<li>target IP-address</li>
<li>target port number</li>
</ul>
Now you try to build up connection-A, close it, and then you want a new connection-A (using the same 4 numbers).
Routers won&#8217;t like it and also the target machine may have memories of the earlier connection-A.

</div></div><div class="thread-post"><h3 class="thread-post-title">TCP &#8211; Can you explain this behavior?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/jeanpaulh">jeanpaulh</a> on October 1, 2016</div><div class="thread-post-content">Hi Joe,
I think the timing in your pcap file is a bit odd. If you look for example at the start of the request:
Package 9 is a SYN request (normal behaviour) immediately followed by
Package 10 an ACK. This is odd; there is nothing to ACK?
Package 11 a GET request. But the server has not yet acknowledged any connection at this point.
At package 12 the server sends the SYN-ACK. This should occur between package 9 and package 10.
Package 13 is the ACK to the actual GET request (sequence=1, ack=99. The length of package 11 is 98 bytes so that makes sense).
But then at package 14 you acknowlegde data that has not been send yet (ack=261). Besides the sequence number is way out of sequence. 
This doesn&#8217;t answer the question why the second request fails, but I&#8217;m more surprised that the first one actually succeeded.
Can you please verify the tcpdump you have made? 
In the screenshot you can see the normal sequence you would expect when requesting the file.
Jean-Paul
