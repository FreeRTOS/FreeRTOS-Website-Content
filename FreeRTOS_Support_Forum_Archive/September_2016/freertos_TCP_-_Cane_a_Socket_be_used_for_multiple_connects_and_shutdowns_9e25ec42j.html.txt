  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">TCP &#8211; Cane a Socket be used for multiple connects and shutdowns</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/joehinkle">joehinkle</a> on September 28, 2016</div><div class="thread-post-content">I&#8217;m thinking about heap fragmentation.
I&#8217;m using heap4.
I have to acquire from 1 to 5 files from a Server.
Currently, I&#8217;m shutting down each connection after a file is acquired (think HTTP 1.0). and closing the socket.
Since a TCP socket acquires multiple buffers from the heap, each time a file is processed, buffers are acquired and freed from the heap because the socket is being acquired and freed.
Can a task acquire a socket and then perform multiple connects and shutdowns on the socket without closing the socket?
Thanks.
Joe
</div></div><div class="thread-post"><h3 class="thread-post-title">TCP &#8211; Cane a Socket be used for multiple connects and shutdowns</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on September 28, 2016</div><div class="thread-post-content">Hi Joe,
I think this <em>should</em> be legal, according to the TCP state machine, but it will mean you will create a new connection using the same IP address and port number, and I believe that has the potential to cause problems with anything in between your client and server (firewalls, routers, etc.) that could could maintain state of the previous connection.  I will have to defer to Hein for anything further.
Regards.

You inferred that, I think, by stating that the port number might not be changed with a new connection.
Local Port number being associated wth socket and not the current connection.  Is this a socket specification or an implementataion action?
Thanks.
Joe
</div></div><div class="thread-post"><h3 class="thread-post-title">TCP &#8211; Cane a Socket be used for multiple connects and shutdowns</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on September 28, 2016</div><div class="thread-post-content"><blockquote>
  Can a task acquire a socket and then perform multiple connects
  and shutdowns on the socket without closing the socket?
</blockquote>
Unfortunately that is not possible.
The only socket that can connect multiple times is a server socket that uses the resocket option <code>FREERTOS_SO_REUSE_LISTEN_SOCKET</code>.  That is no use for you now.
Have you really seen that a lot of fragmentation occurs? Because normally, when you allocated N blocks, and then de-allocate them (in any order), there should be no fragmentation left.
heap4 will split-up memory blocks, but free will join the blocks again.
</div></div><div class="thread-post"><h3 class="thread-post-title">TCP &#8211; Cane a Socket be used for multiple connects and shutdowns</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on September 28, 2016</div><div class="thread-post-content">The port number is assigned when the socket is &#8216;bound&#8217;.  Re-using the 
socket does not re-bind the socket.  It may be possible to explicitly 
re-bind the socket by calling FreeRTOS_bind(), but I would have to check 
the source code to see if that would work &#8211; it is possible the bind() 
function will only proceed if the socket is not already bound to a port.
</div></div><div class="thread-post"><h3 class="thread-post-title">TCP &#8211; Cane a Socket be used for multiple connects and shutdowns</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/joehinkle">joehinkle</a> on September 28, 2016</div><div class="thread-post-content">Fragmentation was just a concern &#8212; I have not investigated actual results, just potential concern because of my process.
