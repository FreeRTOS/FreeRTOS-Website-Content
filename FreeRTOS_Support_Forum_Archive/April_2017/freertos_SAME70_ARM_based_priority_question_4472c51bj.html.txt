This forum is not a customer service where you can put your complaints. Many people try hard to give every person an appropriate answer within a reasonable time. When you show your impatience within a day already, some people may get irritated and unwilling to answer you.
Also you might clarify better what it is that you want (to do).
I&#8217;ll try to answer your questions, although I&#8217;m not an expert on Cortex-M7 and its NVIC.
~~~
<h1>define configMAX_PRIORITIES ( 15 )</h1>
~~~
This defines the number of different <strong>task</strong>-priorities that you can use. In your example the highest task-priority is 14.
Do not confuse this with interrupt priorities.
The rest here below is all about interrupt priorities:
~~~
<h1>define configPRIO_BITS 4</h1>
~~~
This macro was sometimes used to indicate the number of valid priority bits (for interrupts).
Sometime defined as <code>__NVIC_PRIO_BITS</code>.
It gives you 16 different priorities, <code>15</code> being the lowest, <code>0</code> the highest. Priority 0 can not be masked.
~~~
<h1>define configLIBRARY<em>LOWEST</em>INTERRUPT_PRIORITY 0x0f</h1>
~~~
Should be correct when <code>configPRIO_BITS</code> equals 4
~~~
<h1>define configLIBRARY<em>MAX</em>SYSCALL<em>INTERRUPT</em>PRIORITY 10</h1>
~~~
/&#42; The highest interrupt priority that can be used by any interrupt service
routine that makes calls to interrupt safe FreeRTOS API functions.  DO NOT CALL
INTERRUPT SAFE FREERTOS API FUNCTIONS FROM ANY INTERRUPT THAT HAS A HIGHER
PRIORITY THAN THIS! (higher priorities are lower numeric values). &#42;/
&#8216;INTERRUPT SAFE FREERTOS API FUNCTIONS&#8217; are functions with a name like xxxFromISR().
~~~
<h1>define configKERNEL<em>INTERRUPT</em>PRIORITY ( configLIBRARY<em>LOWEST</em>INTERRUPT<em>PRIORITY &lt;&lt; (8 &#8211; configPRIO</em>BITS) )</h1>
~~~
Defines the priority of the interrupts used by the kernel: <code>PENDSV</code> and <code>SYSTICK</code>.
The shift-left makes sure that the bits end up as the most significant bits: <code>"pppp...."</code>, so that the value can be used to set an NVIC register (<code>SYSPRI2</code>).
~~~
<h1>define configMAX<em>SYSCALL</em>INTERRUPT<em>PRIORITY ( configLIBRARY</em>MAX<em>SYSCALL</em>INTERRUPT<em>PRIORITY &lt;&lt; (8 &#8211; configPRIO</em>BITS) )</h1>
~~~
Same thing for the highest interrupt priority.
<blockquote>
  Although I read the document about the ARM Cortex Priorities
  I am not quite sure what this means for me.
</blockquote>
I hope the distinction is now clear: task priorities have nothing to do with ARM NVIC priorities.
<blockquote>
  Does this mean That my freeRTOS User Task Priorities have to be between 0 (highest) and 15 (lowest)??
</blockquote>
In your example (<code>configMAX_PRIORITIES = 15</code>, the range would be <code>0 .. 14</code>, where 14 is the <strong>highest</strong>. The Idle Task always has the lowest priority <code>0</code>.
<blockquote>
  Right now my timer does nun start and I don&#8217;t know why.
</blockquote>
Did you get that running already?
