~~~
    xReturn = xTaskCreate( prvTimerTask,
                           &#8220;Tmr Svc&#8221;,
                           configTIMER<em>TASK</em>STACK<em>DEPTH,
                           NULL,
                           ( ( UBaseType</em>t ) configTIMER<em>TASK</em>PRIORITY ) | portPRIVILEGE_BIT,
                           &amp;xTimerTaskHandle );
~~~
This task will be created automatically if <code>configUSE_TIMERS = 1</code>
This is an example of a non-blocking task:
~~~
void vMyTask( void <em>pvParameters )
{
    /</em> This task will not allow any other task to become active, except
    for tasks that have a higher priority than this one. */
    volatile int counter = 0;
    for( ;; )
    {
        counter++;
    }
}
~~~
A task can block (sleep) in many different ways, while waiting for a notification, an event group, a queue, a semaphore, and also while calling <code>vTaskDelay()</code> :
<pre><code>const TickType_t xTimeTicks = pdMS_TO_TICKS( 1000 );
for( ;; )
{
    /* Sleep for 1000 ms. */
    vTaskDelay( xTimeTicks );
    counter++;
}
</code></pre>
Regards.

</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS software timer not working </h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on April 6, 2017</div><div class="thread-post-content">Your project will start 4 tasks:
Prio-1 : The task <code>TaskScanSwitch()</code> is <strong>never blocking</strong>. 
Prio-1 : The task <code>TaskSerial()</code> is <strong>not blocking</strong>, unless <code>Serial::available()</code> blocks, which I don&#8217;t think.
Prio-3 : The task <code>TaskProcessSwitch()</code> blocks in a call to <code>xSemaphoreTake()</code>.
Prio-1 : The task <code>TaskSerialConsole()</code> blocks in a call to <code>xSemaphoreTake()</code>.
With &#8216;blocking&#8217; I mean &#8216;sleeping&#8217;, or refrain from using the CPU so that other tasks get a chance to run.
In some embedded RTOS projects, you will find a task that never blocks. It is given the lowest priority, often the &#8220;idle priority&#8221; ( tskIDLE_PRIORITY ), in order to give priority to all other tasks.
But it is more usual to let each task sleep ( block ) on a semaphore or any other blocking API. Especially when low power consumption becomes important.
I&#8217;m not sure if it is OK to call <code>xTimerCreate()</code> and <code>xTimerStart()</code> <strong>before</strong> the scheduler is started. Try to call these from within any of the running tasks.
There is a lot of excellent documentation about FreeRTOS, e.g. have a look <a href="http://www.freertos.org/Documentation/RTOS_book.html">here</a>.
The following items might be interesting to read about:
● Tasks and priorities
● Pre-emption
● Queues, Semaphores, and (recursive) Mutexes
● Task notification
● Event groups
I&#8217;m not sure what platform you&#8217;re using, but the easiest platform is probably the Windows simulation. You don&#8217;t need any special hardware for that.
Regards
