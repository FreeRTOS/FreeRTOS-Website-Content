  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">FreeRTOS+TCP example build error with Zynq SDK2016.4 + MicroZed HW platform</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/kenchang1">kenchang1</a> on April 20, 2017</div><div class="thread-post-content">Hi,
When I try to build the +TCP example project for the Zynq (MicroZed BSP), I am getting this error:
&#8220;The Hardware Project referenced by this BSP (RTOSDemo<em>bsp) was not found in this workspace. As a result, this BSP will not build properly. To fix this error, please import the associated hardware project or recreate a new BSP targeting an existing hardware platform.&#8221;
I am using SDK 2016.4 and I did not include the ZC702</em>hw<em>platform project. When I do include this HW project, there are no error messages. I have followed these instructions: http://www.freertos.org/FreeRTOS-Plus/FreeRTOS</em>Plus<em>TCP/TCPIP</em>FAT<em>Examples</em>Xilinx<em>Zynq.html besides that I have included the MicroZed</em>hw<em>platform and excluded the ZC702</em>hw<em>platform project.
Should I change a setting in the RTOSDemo</em>bsp project and recreate the BSP?
I do see a generated elf binary, and it seems to run on the board. Can I ignore the error message above?
regards,
Ken
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS+TCP example build error with Zynq SDK2016.4 + MicroZed HW platform</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on April 20, 2017</div><div class="thread-post-content">I think this relates to changes in the SDK versions.  The demos don&#8217;t 
use anything outside of the MAC (which is the same on both hardware 
platforms) the SD card slot (which I&#8217;m assuming is the same on both 
platforms, especially as you say it is working), and a few LEDs (which 
no doubt are different on the two platforms).  So if you see everything 
working other than the LEDs then I would suggest you just go with what 
is working for you &#8211; you can probably adjust the LED pin mapping 
yourself with a little help from the MicroZed hardware manual.
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS+TCP example build error with Zynq SDK2016.4 + MicroZed HW platform</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on April 20, 2017</div><div class="thread-post-content">Not sure if it helps, but I made a picture of <a href="https://sourceforge.net/p/freertos/discussion/382005/thread/697b1d62/?limit=25#3c5f">a working Zynq project here</a>
Please check and compare every little detail in the picture.
When you start using a Xilinx demo, make sure that you import all available projects, also the &#8220;standalone<em>bsp</em>0&#8243;, or so.
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS+TCP example build error with Zynq SDK2016.4 + MicroZed HW platform</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/kenchang1">kenchang1</a> on April 21, 2017</div><div class="thread-post-content">I think the MicroZed<em>hw</em>platform project is missing a .hdf file. 
The ZC702<em>hw</em>platform project does have this system.hdf file (Zip file) containing all HW description files. 
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS+TCP example build error with Zynq SDK2016.4 + MicroZed HW platform</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/kenchang1">kenchang1</a> on April 21, 2017</div><div class="thread-post-content">OK, I have found the solution.
It seems that the default BSP in the example called RTOSDemo<em>bsp is hardwired to ZC702</em>hw<em>platform. I was not able to change this in the SDK. I can hack into the .sdkproject file, but I don&#8217;t want to do that.
So, the solution is to create a new bsp project and link that to MicroZed</em>hw_platform. After that RTOSDemo project has to be linked to the newly created bsp project.
