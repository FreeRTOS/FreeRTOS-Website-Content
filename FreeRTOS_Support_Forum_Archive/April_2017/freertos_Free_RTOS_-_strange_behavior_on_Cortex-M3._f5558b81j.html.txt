I am working on freeRTOS V9.0 on Cortex M3.   I have two application threads and 2 interrupts. Both the threads blocks on event  which are posted by interrupts (I am using API ending with ISR from interrupts). Evevryting works fine if I have multiple thread and a single interrupt. 
Have multiple randomobservation on my setup on each boot.<br />
<strong>Case-1:</strong> System hangs after starting RTOS. Both threads and Interrupts not working
<strong>Case-2:</strong> Threads are not running but both the interrupts working !
<strong>Case-3:</strong>  Threasds start running automatically after some time (about 60 seconds) after 10/20 interrupt processing
<strong>Case-4:</strong> Everything works fine without any problem
I understood freeRTOS configuration requirement for interrupts from here and everything looks fine !
http://www.freertos.org/FAQHelp.html
http://www.freertos.org/a00110.html#kernel_priority
Appreciate your bvaluable feedback 🙂
Thanks 
</div></div><div class="thread-post"><h3 class="thread-post-title">Free RTOS &#8211; strange behavior on Cortex-M3.</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/edwards3">edwards3</a> on April 26, 2017</div><div class="thread-post-content">Do you have configASSERT() defined?
Which M3 are you using and what is configMAX<em>SYSCALL</em>INTERRUPT_PRIORITY set to?
</div></div><div class="thread-post"><h3 class="thread-post-title">Free RTOS &#8211; strange behavior on Cortex-M3.</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/ravikiranhv">ravikiranhv</a> on April 27, 2017</div><div class="thread-post-content">Yes configASSERT() is defined. Our Cortex M3 implements 3 bits(MSB) for priority 
configMAX<em>SYSCALL</em>INTERRUPT<em>PRIORITY (191) //(i.e. priority 5).
configKERNEL</em>INTERRUPT_PRIORITY     (240)
Both ISR&#8217;s calling free RTOS API&#8217;s are set to priority 240. 
Please suggets if I am missing anything.
Thanks in advance
</div></div><div class="thread-post"><h3 class="thread-post-title">Free RTOS &#8211; strange behavior on Cortex-M3.</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on April 27, 2017</div><div class="thread-post-content">240 is actually using 4 bits, but that shouldn&#8217;t matter because the 
unimplemented bit will be ignored anyway.
Can you please say which chip you are using &#8211; if it is an STM32 then you 
also have to explicitly tell it not to sub-divide the priorities.  Are 
you 100% sure it has three priority bits defined?  We have had incidents 
where documentation on this has been wrong, which is why the head 
revision Cortex-M code in SVN has additional asserts() to actually 
measure this to determine if the configuration file settings are correct.
</div></div><div class="thread-post"><h3 class="thread-post-title">Free RTOS &#8211; strange behavior on Cortex-M3.</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/ravikiranhv">ravikiranhv</a> on April 29, 2017</div><div class="thread-post-content">Hi,
Thanks for the inputs. 
I am using Max32550 controller from Maxim with 3 bit priority implementation. 
Please suggest how to go about.
Appreciate your help 
</div></div><div class="thread-post"><h3 class="thread-post-title">Free RTOS &#8211; strange behavior on Cortex-M3.</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on April 30, 2017</div><div class="thread-post-content">Try setting configKERNEL<em>INTERRUPT</em>PRIORITY to 224, and if that does not 
help, update to the latest version of port.c, which contains more 
configASSERT() statements.  Link assumes GCC, and the new asserts assume 
either __NVIC<em>PRIO</em>BITS or configPRIO<em>BITS is set to 3 in 
FreeRTOSConfig.h: 
https://sourceforge.net/p/freertos/code/HEAD/tree/trunk/FreeRTOS/Source/portable/GCC/ARM</em>CM3/
