</div></div><div class="thread-post"><h3 class="thread-post-title">pcTaskGetName question</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on April 5, 2017</div><div class="thread-post-content">What do you mean you get a pointer to &#8220;main&#8221;?  The string &#8220;main&#8221;, or the 
main() function?  Do you have task that is called &#8220;main&#8221;?
Are you calling this after the scheduler has been started?
The code for pcTaskGetName() is very simple, as below, step into it in 
the debugger to see what it is doing.
<pre>
char *pcTaskGetName( TaskHandle_t xTaskToQuery )
{
TCB_t *pxTCB;
     /* If null is passed in here then the name of the calling task is being
     queried. */
     pxTCB = prvGetTCBFromHandle( xTaskToQuery );
     configASSERT( pxTCB );
     return &( pxTCB->pcTaskName[ 0 ] );
}
</pre>

</div></div><div class="thread-post"><h3 class="thread-post-title">pcTaskGetName question</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on April 6, 2017</div><div class="thread-post-content"><code>pcTaskGetName( NULL )</code> will return the name of the task that is currently active.
So if you call <code>pcTaskGetName( NULL )</code> from a task whose name is <code>"main"</code>, it is logical that it returns that string.
Didn&#8217;t you create your task with <code>xTaskCreate( pvFunction, "main", xxx)</code> ?
If the idle-task would call <code>pcTaskGetName( NULL )</code>, it would see <code>"IDLE"</code>
Or if your task would call <code>pcTaskGetName( xIdleTaskHandle )</code>, it would also receive the string &#8220;IDLE&#8221;
( NB. <code>TaskHandle_t xIdleTaskHandle</code> is declared static in <code>tasks.c</code>, so you can not easily try that )
Does that answer your question?
