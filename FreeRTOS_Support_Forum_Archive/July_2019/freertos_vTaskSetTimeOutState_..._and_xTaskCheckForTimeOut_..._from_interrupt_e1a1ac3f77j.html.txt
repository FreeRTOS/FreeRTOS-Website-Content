void vTaskSetTimeOutState( TimeOut_t * const pxTimeOut )
{
UBaseType_t uxSavedInterruptStatus;
    configASSERT( pxTimeOut );
    uxSavedInterruptStatus = portSET_INTERRUPT_MASK_FROM_ISR();
    {
        pxTimeOut->xOverflowCount = xNumOfOverflows;
        pxTimeOut->xTimeOnEntering = xTickCount;
    }
    portCLEAR_INTERRUPT_MASK_FROM_ISR( uxSavedInterruptStatus );
}

Even though it has a .h extension, think of it as a .c file for your program. (I personally might have called it something like freertos<em>tasks</em>c_additions.c to be clearer that it shouldn&#8217;t be included elsewhere (but then you do need to make sure it isn&#8217;t compiled as an indendant file also)
Code in freertos<em>tasks</em>c_additions.h, since it is include by tasks.c, has full access to all the variables and defintions inside tasks.c. You add your code there, and it effectively gets added to tasks.c without needing to actually change the file. Because the code in there wants to see the private internals of tasks.c, it can&#8217;t be included elsewhere in your system. You will need to have a header file to provide the needed declerations of the functions in that file so other files can call them.
