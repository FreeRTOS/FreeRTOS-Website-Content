</div></div><div class="thread-post"><h3 class="thread-post-title">Adding FreeRTOS with TCP/IP stack to a Vivado project (ZC702 board)</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on July 2, 2019</div><div class="thread-post-content">Marc,
<blockquote>
  PS. It&#8217;s very confusing to call the TCP/IP stack &#8220;FreeRTOS+TCP&#8221;,
  all new comer will think that in includes both the RTOS and the TCP/IP stack.
  How else could be it looked at? Renaming this would reduce confusion.
</blockquote>
I&#8217;m sorry about this misunderstanding. But today it is too late to change the names of products that have existed for so many years:
<ul>
<li>FreeRTOS<em>Plus</em>IO</li>
<li>FreeRTOS<em>Plus</em>UDP</li>
<li>FreeRTOS-Plus-IoT-SDK</li>
<li>FreeRTOS+Trace</li>
<li>FreeRTOS+POSIX</li>
<li>FreeRTOS+CLI</li>
<li>FreeRTOS+FAT</li>
<li>FreeRTOS+TCP</li>
</ul>
It all started with the FreeRTOS kernel, and later there were many additions which were named FreeRTOS<em>Plus</em>xxx. The &#8220;FreeRTOS+TCP&#8221; is just a shorter name.
Some of these products can be found in the /Plus section. Other products were stored in a /Labs section, meaning that they were kind of experimental.
Both +TCP and +FAT are adult and stable now. +TCP is also available from <a href="https://github.com/aws/amazon-freertos/">amazon/aws</a> and <a href="https://sourceforge.net/p/freertos/code/HEAD/tree/">FreeRTOS&#8217;s SVN</a>. +FAT doe not have a new home yet. +TCP also contains the UDP protocol, so it can <strong>replace</strong> the  FreeRTOS<em>Plus</em>UDP library.
<blockquote>
  <code>FreeRTOS.h No such file or directory</code>
</blockquote>
You can Google this error message. Of course it has to do with the include path settings ( <code>-I</code> )
There is an application for Xilinx that demonstrates both +TCP and +FAT <a href="https://www.freertos.org/FreeRTOS-Plus/FreeRTOS_Plus_TCP/TCP_FAT_demo_projects.html">here</a>.
This demo project is a bit outdated though, and it might come with an older kernel.
If you have problems to get that demo running, you can ask questions in this post.
I attach the latest +TCP Network Interface for Xilinx as <code>Zynq_02_july_2019.7z</code>
Unfortunately I have no experience with memory-mapped IP&#8217;s.

</div></div><div class="thread-post"><h3 class="thread-post-title">Adding FreeRTOS with TCP/IP stack to a Vivado project (ZC702 board)</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on July 5, 2019</div><div class="thread-post-content">Xilinx still use lwIP though.  The top level of the FreeRTOS download
has a FreeRTOS directory and a FreeRTOS-Plus directory. The demo in the
FreeRTOS directory uses Xilinx created projects that include lwiP. You
can use the Xilinx tools to generate projects with or without lwiP and
with or without FreeRTOS.  The FreeRTOS-Plus directory contains projects
created by the FreeRTOS team directly so the demos in the FreeRTOS-Plus
directory use the FreeRTOS TCP/IP stack, so FreeRTOS themselves don&#8217;t
create projects using lwIP any more but third parties do.
The older labs project you refer to demonstrates all the files and build
options that are needed, but also uses an older version of the Xilinx
provided driver files and an older version of the FreeRTOS TCP stack.
Updating the FreeRTOS TCP stack to the latest should be easy enough.
Updating the Xilinx drivers can be harder but people on this forum will
have newer Xilinx drivers (especially Hein who is a primary maintainer
of the TCP stack).
