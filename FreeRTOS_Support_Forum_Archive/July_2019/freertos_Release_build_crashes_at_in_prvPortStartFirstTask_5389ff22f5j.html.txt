  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Release build crashes at  in prvPortStartFirstTask</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/dnadler">dnadler</a> on July 25, 2019</div><div class="thread-post-content">Apologies, crash may be in xPortStartScheduler, but it looks like it crashed on entering StartFirstTask.
<strong>Background:</strong>
STM32F429, STM32cubeIDE, FreeRTOS V10.0.1 as supplied by STM&#8217;s &#8220;Cube&#8221;.
Optimization -O1 (except trap handler for register visibility)
define configUSE<em>PORT</em>OPTIMISED<em>TASK</em>SELECTION  0
Not using static allocation option.
systick timer for FreeRTOS, peripheral timer for Cube timing utilities.
<strong>Detail:</strong>
Debug builds and runs application AOK. Plenty of memory (FreeRTOS pool, newlib heap, stack).
Registers in fault handler:
<img src="http://www.nadler.com/backups/FreeRTOScrashStartFirstTask.PNG" alt="" />
Stack, code dissasembly:
<img src="http://www.nadler.com/backups/FreeRTOScrashStartFirstTask_codeAndStack.PNG" alt="" />
Much obliged for any ideas where to look&#8230;
Thanks!
Best Regards, Dave
</div></div><div class="thread-post"><h3 class="thread-post-title">Release build crashes at  in prvPortStartFirstTask</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/dnadler">dnadler</a> on July 25, 2019</div><div class="thread-post-content">Sorry, solved, problem was wrong library specification.
Release newlib selected was <em>Reduced C, Reduced C++</em> (should be <em>Standard C, Reduced C++</em>).
Application works with correct library selected.
<strong>Not sure why this causes a crash here though&#8230;</strong>
Aaarrrggg&#8230;
