</div></div><div class="thread-post"><h3 class="thread-post-title">EventGroupWaitBits disfunction on tasks with same priority</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on July 23, 2019</div><div class="thread-post-content">Not run the code yet, but a couple of things for you to try upfront.
1) Set configCHECK<em>FOR</em>STACK_OVERFLOW to 2 (you have it set to 1).
2) Define configASSERT()
https://www.freertos.org/a00110.html#configASSERT &#8211; this is critical
while developing, especially if you are learning.
Simplest thing to do, assuming you have a debugger can will be able to
break a debug session to see that the assert has been hit, is to define
it as:
~~~
<h1>define configASSERT( ( x ) )     if( ( x ) == 0 ) {</h1>
taskDISABLE_INTERRUPTS(); for( ;; ); }
~~~
</div></div><div class="thread-post"><h3 class="thread-post-title">EventGroupWaitBits disfunction on tasks with same priority</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on July 23, 2019</div><div class="thread-post-content">Also, two of your tasks access local variables called ComptFin, and two
access a global variable called ComptFin &#8211; that may be confusing things.
In your original post you said the event bit was getting set, but the
task was not running &#8211; how did you determine that was the case?
</div></div><div class="thread-post"><h3 class="thread-post-title">EventGroupWaitBits disfunction on tasks with same priority</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/aggarg-aws">aggarg-aws</a> on July 23, 2019</div><div class="thread-post-content">The problem with your code is that you create ComptFin_Group in the task DetectLimitReach and all three Raz tasks use that. Since all of these tasks are of same priority, there is no guarantee which one of them will run first. 
<ul>
<li>If DetectLimitReach runs first, it will create the event group first and everything will work fine.</li>
<li>If any of the Raz task runs first, it will call xEventGroupWaitBits Or xEventGroupSetBits with NULL and that will result in a crash.</li>
</ul>
You need to move the creation of the event group before starting the scheduler. I made this change and then I am able to successfully run your code (on a different STM32 MCU though). 
~~~
  ComptFin<em>Group = xEventGroupCreate(); //nom du EventGroup
    if (ComptFin</em>Group == NULL)
    {   while (1);  }//fatal error
<pre><code>/* Start the RTOS Scheduler */
vTaskStartScheduler();
</code></pre>
~~~
Some other suggestions:
<ul>
<li>Defining configASSERT will help you detect problems faster. In this specific case you will hit assert in the xEventGroupWaitBits function when you pass NULL for the EventGroupHandle_t parameter.</li>
<li>Although you are not using ComptFin, it is generally better to not have same name for local and global variables.</li>
</ul>
Thanks.
