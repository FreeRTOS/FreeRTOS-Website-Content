http://www.freertos.org/a00098.html
The part about the tick timer having a different configuration is relevant to the Mega16.
The Mega16 has half the memory of the 323, which means it cannot run all the tasks in th demo application.&nbsp; If you wish to use an OS maybe external RAM would be preferable as the 16 only has 1K.
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">freeRTOS and ATmega16</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on November 11, 2004</div><div class="thread-post-content">If i dont want to use an external RAM,what changes should i do in the source code in order to use ATmega16
</div></div><div class="thread-post"><h3 class="thread-post-title">freeRTOS and ATmega16</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on November 12, 2004</div><div class="thread-post-content">Assuming you have already looked at the &quot;To use a microcontroller other than an AVR ATMega323&quot; section of http://www.freertos.org/a00098.html&nbsp; &#8211; and followed the instructions there &#8211; then in addition to use a part with only 1K of RAM you will have to create less tasks.
To just run the flash tasks &#40;assuming you have an STK500&#41;:
1&#41; Remove the lines in demo/ATMega323/main.c that create tasks, other than the flash tasks&#8230;so delete the lines :
vStartIntegerMathTasks&#40; tskIDLE&#95;PRIORITY &#41;;
vAltStartComTestTasks&#40; mainCOM&#95;TEST&#95;PRIORITY, mainCOM&#95;TEST&#95;BAUD&#95;RATE, mainCOM&#95;TEST&#95;LED &#41;;
vStartPolledQueueTasks&#40; mainQUEUE&#95;POLL&#95;PRIORITY &#41;;
 and
sTaskCreate&#40; vErrorChecks, &quot;Check&quot;, portMINIMAL&#95;STACK&#95;SIZE, NULL, mainCHECK&#95;TASK&#95;PRIORITY, NULL &#41;;
I tried this in the AVRStudio simulator with portTOTAL&#95;HEAP&#95;SIZE set to 700.
As stated previously, I think the timer setup is slightly different on the 16 than the 323 &#8211; so this will require modification in port.c.
