  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Extending number of MPU regions</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/hdtx">hdtx</a> on February 21, 2017</div><div class="thread-post-content">I&#8217;m using GCC on a Cortex-M4F (LPC43xx family).
I need more than the 3 configurable MPU regions for this port. I decided to do away with the privileged flash area because I don&#8217;t need it (privileged background map is enabled and my unprivileged flash area does not reach there, so privileged accesses are enabled by default and unprivleged accesses are blocked).
What I did:
<ul>
<li>added the fourth area to all my task parameters (all tasks are created using xTaskCreateRestricted);</li>
<li>took out the lines setting portMPU<em>REGION</em>BASE<em>ADDRESS</em>REG and portMPU<em>REGION</em>ATTRIBUTE_REG for the privileged flash area in prvSetupMPU (mpu/port.c);</li>
<li>changed a few lines at the start of mpu/portmacro.h from
~~~</li>
</ul>
<h1>define portUNPRIVILEGED<em>FLASH</em>REGION       ( 0UL )</h1>
<h1>define portPRIVILEGED<em>FLASH</em>REGION         ( 1UL )</h1>
<h1>define portPRIVILEGED<em>RAM</em>REGION           ( 2UL )</h1>
<h1>define portGENERAL<em>PERIPHERALS</em>REGION      ( 3UL )</h1>
<h1>define portSTACK_REGION                    ( 4UL )</h1>
<h1>define portFIRST<em>CONFIGURABLE</em>REGION       ( 5UL )</h1>
<h1>define portLAST<em>CONFIGURABLE</em>REGION        ( 7UL )</h1>
~~~
to
~~~
<h1>define portUNPRIVILEGED<em>FLASH</em>REGION       ( 0UL )</h1>
<h1>define portPRIVILEGED<em>RAM</em>REGION           ( 1UL )</h1>
<h1>define portGENERAL<em>PERIPHERALS</em>REGION      ( 2UL )</h1>
<h1>define portSTACK_REGION                    ( 3UL )</h1>
<h1>define portFIRST<em>CONFIGURABLE</em>REGION       ( 4UL )</h1>
<h1>define portLAST<em>CONFIGURABLE</em>REGION        ( 7UL )</h1>
~~~
What did not work: the fourth area is never set (whatever region I put there does not get activated).
I checked portNUM<em>CONFIGURABLE</em>REGIONS, it&#8217;s obviously 4 instead of 3 now. I looked at the FreeRTOS code and the fourth region should be working, I have no idea why it&#8217;s not. I appreciate any help.
</div></div><div class="thread-post"><h3 class="thread-post-title">Extending number of MPU regions</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/hdtx">hdtx</a> on February 21, 2017</div><div class="thread-post-content">Never mind, I found it&#8230; xPortPendSVHandler in mpu/port.c only swaps in 4 regions at most (including the stack region), so I added a few lines that fixed it. If anyone has the same problem, delete line 495 and add this in its place (assuming you defined the appropriate symbol):
~~~
<h1>if !defined(FREERTOS<em>EXTRA</em>MPU_REGION)</h1>
<pre><code>    "   stmia r2!, {r4-r11}                 n" // original line
</code></pre>
<h1>else</h1>
<pre><code>    "   stmia r2, {r4-r11}                  n" // don't update r2
    "   ldmia r1!, {r4-r5}                  n" // load 1 set of MPU regs
    "   stmia r2, {r4-r5}                   n" // write 1 set of MPU regs
</code></pre>
<h1>endif</h1>
~~~
