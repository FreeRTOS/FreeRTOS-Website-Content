It <strong>is</strong> complex to write a zero-copy NetworkInterface.
<blockquote>
  I&#8217;m trying to create Zero-Copy driver for my stm32f429.
  As describe here I should to declare handler (standard
  RTOS task) where DMA descriptor with incoming frame (that
  references the Ethernet buffer containing the received data)
  are swapped with free FreeRTOS+TCP descriptor. But in my MCU
  DMA descriptor have only 3 parameters:
</blockquote>
~~~~
// DMA Descriptors.
typedef struct {
    volatile u32 Stat;
    u32 Ctrl;
    u32 Addr;
    u32 Next;
} RX_Desc;
~~~~
You only need to set the <code>Addr</code> field. DMA will read from that address while transmitting, or it will write to that address when receiving a packet.
This is <strong>wrong</strong>:
~~~~
    Rx_Desc[i].Addr = (u32)&amp;activeFrRtsDesc[i]->pucEthernetBuffer;
~~~~
This is what you meant to do, without the <code>&amp;</code>,l translating a <code>uint8_t*</code> to a <code>uint32_t</code> :
~~~~
    Rx_Desc[i].Addr = (u32)activeFrRtsDesc[i]->pucEthernetBuffer;
~~~~
Now DMA will write to your <code>pucEthernetBuffer</code> in stead of <strong>currupting</strong> your Network Buffer 🙂
<blockquote>
  So I can&#8217;t just swap two pointers. So I am trying to bind DMA
  descriptors with buffers in Pre-created FreeRTOS+TCP descriptors
</blockquote>
Your text is correct.
I wouldn&#8217;t use arrays <code>activeFrRtsDesc</code> and <code>freeFrtsDesc</code>. The actual descriptors (<code>Rx_Desc</code> and <code>Tx_Desc</code>) will store the pointers for you and no-one will change them.
The following function translates from a <code>uint8_t* pucEthernetBuffer</code> back to <code>NetworkBufferDescriptor_t *</code>:
~~~~
    NetworkBufferDescriptor<em>t *pxPacketBuffer</em>to_NetworkBuffer( void *pvBuffer );
~~~~
So when a transmission is complete, you can do the following:
~~~~
    uint8<em>t* ucBuffer = ( uint8</em>t * )Tx<em>Desc[i].Addr;
    NetworkBufferDescriptor</em>t <em>pxNetworkBuffer = pxPacketBuffer_to_NetworkBuffer( ( void * )ucBuffer );
    /</em> Remove the reference. <em>/
    Tx_Desc[i].Addr = ( uint32_t )0u;
    /</em> Release the buffer because it has been sent. */
    vReleaseNetworkBufferAndDescriptor( pxNetworkBuffer );
~~~~
Sending a packet will need:
~~~~
    /* Pass the buffer to the descriptor. <em>/
    Tx_Desc[i].Addr = ( uint32_t )pxDescriptor->pucEthernetBuffer;
    /</em> Ask to set the IPv4 checksum. Also need an Interrupt on Completion <em>/
    Tx_Desc[i].Stat |= ETH_DMATXDESC_CHECKSUMTCPUDPICMPFULL | ETH_DMATXDESC_IC;
    /</em> The Network Buffer has been passed to DMA, no need to release it. */
    bReleaseAfterSend = pdFALSE;
~~~~
<blockquote>
  When Ethernet interrupt occurs I swap activeFrRtsDesc and freeFrtsDesc:
</blockquote>
My advice is: do as little as possible from within an ETH ISR.
Two interrupts will be interesting for a zero-copy driver: reception and transmission complete. When these interrupts occur, just set a (volatile) flag and wake-up your <code>prvEMACHandlerTask()</code>. As is done in all examples of NetworkInterface.c
From<code>prvEMACHandlerTask()</code>, a normal task, you will follow <code>Rx_Desc[]</code> as long as the <code>DMA_RX_OWN</code> bit is low.
~~~~
    NetworkBufferDescriptor<em>t *pxNetworkBuffer = ( NetworkBufferDescriptor</em>t * )Rx<em>Desc[i].Addr;
    /* Now pass pxNetworkBuffer to the IP-task in a normal way,
    using xSendEventStructToIPTask(). */
    pxNetworkBuffer = pxGetNetworkBufferWithDescriptor( );
    if( pxNetworkBuffer != NULL )
    {
        Rx</em>Desc[i].Addr = pxNetworkBuffer->pucEthernetBuffer;
    }
~~~~
<blockquote>
  In prvEMACHandlerTask I proceed and free realised FreeRTOS+TCP descriptors:
  Does it correct? I get hardfault on eConsiderFrameForProcessing().
  What am I doing wrong?
</blockquote>
At least one assignment was wrong.
But as I said above, I wouldn&#8217;t do processing from within the ISR. <code>prvEMACHandlerTask()</code> should have a pretty high priority so that after the ISR, it will quickly become active.
The task will send the Network Buffers received to the IP-task, set new buffers, and it will release TX buffers that have been sent.
The handling of received packets in your <code>prvEMACHandlerTask()</code> looks good. Call <code>eConsiderFrameForProcessing()</code> as early as possible in order to spare a Network Buffer. If you&#8217;re not taking a Network Buffer, there is no need to release it.  All you&#8217;d have to do is to set <code>DMA_RX_OWN</code> again.
Do not forget to set <code>ipconfigETHERNET_DRIVER_FILTERS_FRAME_TYPES = 1</code> because you already filter the packets.
Good luck
