</div></div><div class="thread-post"><h3 class="thread-post-title">Combine FreeRTOS tasks and C++ objects</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on February 23, 2017</div><div class="thread-post-content">Hi Mourad,
<blockquote>
  Creating object from within a task ?
</blockquote>
Objects ( instances of C++ classes ) can be created and used from within a task. In fact, after <code>vTaskStartScheduler()</code> has been called, all code is running from within a task. Except ISR&#8217;s, who have their own life and rules.
<blockquote>
  Create a task from within an object ( i think wrappers are needed in this case) 
</blockquote>
That is also possible. Wrappers will make your code nicer, easier to read, but they&#8217;re not necessary.
When creating tasks ( from within an object, or wherever ), remember that you work on an embedded project, with limited resources: limited in CPU-speed, limited in memory.
When you start a modern browser on a laptop, it will easily create 7 processes, each process will create 16 threads, and the program will allocate e.g. 37 MB of RAM.
On the contrary, an embedded HTTP-server ( from FreeRTOS+TCP ) will run in a single task and allocate KB&#8217;s in stead of MB&#8217;s. Well, unless your hardware has external SDRAM.
<blockquote>
  Combine the task and boject ( 1 task correspnds to on object )
  and the deletion of the one means the deletion of the other. 
</blockquote>
That&#8217;s a nice idea: each task (except Idle, that you do not own) is bound to an object, and when the object is deleted, its task will be terminated.
In <a href="https://sourceforge.net/p/freertos/discussion/382005/thread/2aa2a047">another thread</a> about C++, yesterday, I referred to <a href="https://github.com/richard-damon/FreeRTOScpp">Richard Damon&#8217;s C++ project</a>
I wrote that <code>new()</code> and <code>delete()</code> must be <a href="https://sourceforge.net/p/freertos/discussion/382005/thread/2aa2a047/?limit=25#ddd4">redefined</a> in order to use task-safe allocators. These allocators are defined in one of the <code>heap_x.c</code> modules.
I often like the addition of C++ to embedded projects. The presence of constructors and destructors formalise important steps. Object-oriented thinking can make life easier.

</div></div><div class="thread-post"><h3 class="thread-post-title">Combine FreeRTOS tasks and C++ objects</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richarddamon">richarddamon</a> on February 23, 2017</div><div class="thread-post-content">Putting your tasks into objects can be helpful to keep things organized. Certainly most objects will not have a task as part of them (have a reason to create a task). It is also quite possible to use C++ and virtually no heap (or no post-initilization heap), though it does require some discipline and knowledge of what things you need to avoid.
