  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">FAT-SL Exception in Demo code when F_FS_THREAD_AWARE = 1</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/trexmsuee">trexmsuee</a> on February 6, 2017</div><div class="thread-post-content">Hi Guys,
I&#8217;m fairly new to FreeRTOS. My development environment is:
Atmel Studio 7.0 
Atmel SAME70-XPLD demo board (with SAME70Q21 Cortex -M7 processor)
FreeRTOS 9.0.0
Percepio Trace 3.1
Using heap_3.c
I will need multiple tasks to access the file system on an uSD card. I&#8217;ve incorporated FAT-SL into my project, and got the default sample code, using the RAM drive, up and running. 
Problem ->> if I set <strong>F<em>FS</em>THREAD_AWARE == 1</strong>, I get a call to <strong>vApplicationStackOverflowHook</strong>.
To narrow this down, an exepction is being thrown (somewhere in the bowels of the RTOS), in prvCreateDemoFilesUsing<em>f</em>write(), contained within vCreateAndVerifySampleFiles(). I can comment this, and the associated prvVerifyDemoFileUsing<em>f</em>read() out, and it works fine. In other words, I can still leave in prvCreateDemoFileUsing<em>f</em>putc() and prvVerifyDemoFileUsing<em>f</em>getc() (this is the code used to create the nested subdirectories).
Also, if <strong>F<em>FS</em>THREAD_AWARE = 0</strong>, the entirity of  the demo code works fine.
I&#8217;ve tired tuning parameters in config<em>fat</em>sl.h, to no avail. I&#8217;m unable to exactly pinpoint the exact cause of the exeception, within the sequence of prvCreateDemoFilesUsing<em>f</em>write(). 
I&#8217;m assuming this is some issue associated with the port to the -M7. But at this point, I&#8217;m getting over my head.
I&#8217;d greatly appreciate any advice, or additional troubleshooting steps, anyone could offer.
Thanks much,
</div></div><div class="thread-post"><h3 class="thread-post-title">FAT-SL Exception in Demo code when F_FS_THREAD_AWARE = 1</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on February 6, 2017</div><div class="thread-post-content">If the stack overflow hook is being called then a task has overflowed 
its stack.  Increase the size of the stack allocated to the offending 
task: http://www.freertos.org/Stacks-and-stack-overflow-checking.html
</div></div><div class="thread-post"><h3 class="thread-post-title">FAT-SL Exception in Demo code when F_FS_THREAD_AWARE = 1</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/trexmsuee">trexmsuee</a> on February 7, 2017</div><div class="thread-post-content">Hi &#8211; I  changed the stack size of the Idle task to 256 bytes, and all appears happy with the world! I should have thought of this!
I do appreciate your prompt reply!
Best Regards,
