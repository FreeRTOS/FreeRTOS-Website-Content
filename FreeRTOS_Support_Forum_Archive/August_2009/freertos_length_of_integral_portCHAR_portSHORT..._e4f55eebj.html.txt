  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">length of integral portCHAR portSHORT&#8230;</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/*anonymous">*anonymous</a> on August 14, 2009</div><div class="thread-post-content">Just wondering if all integral data type, such as portCHAR portSHORT portLONG are of fixed length. I supposed them to be yes. For example, portCHAR always 8bits, portSHORT always 16bit and portLONG always 32bits, is that true?
Thanks.
</div></div><div class="thread-post"><h3 class="thread-post-title">length of integral portCHAR portSHORT&#8230;</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/spacewrench">spacewrench</a> on August 14, 2009</div><div class="thread-post-content">Yes, within the compilation of any set of files that are to be linked together successfully, the data types will be of fixed &#40;and equal&#41; lengths.&nbsp; &#40;That is, all portCHARs will be the same size, which is usually 8 bits.&nbsp; All portSHORTs will be the same size, and usually 16 bits, etc.&#41;
The reason these are defined and used is so that you can change/fix things in one place if necessary.&nbsp; I&#8217;m not a C/C++ standards expert, but I think the rule on integral sizes is something like sizeof&#40;char&#41;&lt;=sizeof&#40;short&#41;&lt;=sizeof&#40;int&#41;&lt;=sizeof&#40;long&#41;.&nbsp; So theoretically, a char could be the same size as a long.&nbsp; This would cause problems for code that assumed that a short always has at least 16 bits.&nbsp; However, since FreeRTOS uses portSHORT everywhere, you can &#35;define or typedef that to be whatever type causes the compiler to give you at least 16 bits.
</div></div><div class="thread-post"><h3 class="thread-post-title">length of integral portCHAR portSHORT&#8230;</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/*anonymous">*anonymous</a> on August 14, 2009</div><div class="thread-post-content">and what about this portBASE&#95;TYPE? this seems not to be of fixed length, looks like size&#95;t, correct?
</div></div><div class="thread-post"><h3 class="thread-post-title">length of integral portCHAR portSHORT&#8230;</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on August 14, 2009</div><div class="thread-post-content">Look right at the bottom of this page:
http://www.freertos.org/a00017.html&#35;DataTypes
As has already been said, portSHORT is always 16 bits and portLONG is always 32 bits.&nbsp; int is never used.&nbsp; The kernel code uses these definitions in any source file that is compiled for all processors &#40;8, 16 and 32bits&#41;, so the kernel code and the common demo code uses them.&nbsp; Your application code does not need to use them unless you want it to be portable across 8, 16 and 32bit architectures too.
portBASE&#95;TYPE is generally used for Boolean values and is set to whatever is the most efficient type for the architecture.&nbsp; Generally this is a char for 8 bitters, short for 16 bitters and long for 32 bitters.
portTickType can be 16 or 32 bits, but it would be very odd to use 16 bits on a 32 bit architecture.
Regards.
