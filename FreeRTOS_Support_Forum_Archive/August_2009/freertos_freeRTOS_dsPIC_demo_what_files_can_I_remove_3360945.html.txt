</div></div><div class="thread-post"><h3 class="thread-post-title">freeRTOS dsPIC demo : what files can I remove</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on August 10, 2009</div><div class="thread-post-content">See http://www.freertos.org/a00017.html &#8211; anything that is in the FreeRTOS/Source directory is part of FreeRTOS and required &#8211; anything that is in the FreeRTOS/Demo directory is part of the demo app and is not required.
A quick and simple way is to remove anything that is in the FreeRTOS/Demo directory other than main&#40;&#41;, then delete the whole of main&#40;&#41; other than vTaskStartScheduler&#40;&#41;, finally create your own tasks before vTaskStartScheduler&#40;&#41; is called.
If you run out of RAM then reduce configTOTAL&#95;HEAP&#95;SIZE in FreeRTOSConfig.h.&nbsp; I think this is an FAQ.
Regards.

It looks like I&#8217;ve gotten in over my head on this as I have no idea what to do. I see chapter 5 in the eBook and I see heap&#95;1.c. Is the kernel expecting to find and call pvPortMalloc to do the memory allocation or do I have to call it from my function?
</div></div><div class="thread-post"><h3 class="thread-post-title">freeRTOS dsPIC demo : what files can I remove</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on August 11, 2009</div><div class="thread-post-content">The linker will require a heap if functions you have added use calls to malloc&#40;&#41;. FreeRTOS does not call malloc but instead calls pvPortMalloc&#40;&#41;. This allows the malloc implementation to be replaced and this is what heap&#95;1, heap&#95;2 and heap&#95;3 do. Does your code call malloc&#40;&#41;? If so try replacing it with pvPortMalloc&#40;&#41; instead.
