With 4.80 I have exactly same issues as with the new release. Then I looked into subversion for changes between these versions, it turns out that if I use queue.c before rev255 it works fine. &#40; this revision was supposed to be more efficient re-implementation of queue &#41;.
I didn&#8217;t try to see what exactly caused the issue on queue.c as the change was almost complete re-implementation. 
Would it be safe to use the old rev 222 queue.c with the new 5.4 freeRTOS ? Does anyone have ideas how it caused this kind of complication for this demo? &#40; I believe that the problem is very confined and has not been widely known because of that &#41;. I saw one post on this forum complaining about this demo after the change was made back in 2008 https://sourceforge.net/forum/message.php?msg&#95;id=5023157
Any help with this would be highly appreciated.

teemu

Today I also tried to use freeRTOS 5.42 code with queue.c, semphr.h and queue.h from 4.72 &#40; to accommodate old queue on new code I also changed to xSemaphoreGiveFromISR calls on the interrupt handler of the demo &#41;. This combination works perfectly.

I assume this is as much as the lwip can send without getting ack from client, on ethernet analyzer it looks like it sends a few segments and then suddenly stops until client resends the acknowledge.
