  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Semaphore/vTaskResume &#8211; 7.3.0</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/westmorelandeng">westmorelandeng</a> on November 2, 2012</div><div class="thread-post-content">First &#8211; Richard &#8211; I haven&#8217;t had a chance to go through the new items in v7.3 &#8211; but for the low power additions &#8211; anything there specific for the MSP430 in the updated kernel?&nbsp; I will take a look.  
2nd question &#8211; just a sanity check:<br />
I have a semaphore that is given from an ISR periodically from a Timer IRQ.&nbsp; There is a task that blocks on this &#8211; but the task is also resumed asynchronously to, but not necessarily so, by another task.&nbsp;<br />
Question is &#8211; if the timer IRQ makes the semaphore available more than once &#8211; and the task isn&#8221;t resumed &#8211; is that a problem?&nbsp; The semaphore is a binary semaphore &#8211; the ones preferred to be used from a timer IRQ &#8211; correct?  
Thanks In Advance,<br />
John
</div></div><div class="thread-post"><h3 class="thread-post-title">Semaphore/vTaskResume &#8211; 7.3.0</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on November 2, 2012</div><div class="thread-post-content"><blockquote>
  anything there specific for the MSP430 in the updated kernel
</blockquote>
There is not yet anything specific to the MSP430.&nbsp; There are generic hooks that allow the tickless mode to be used with a little coding on the application site too, as explained here: <a href="http://www.freertos.org/low-power-tickless-rtos.html.">http://www.freertos.org/low-power-tickless-rtos.html.</a>&nbsp; The Cortex-M ports have a built in implementation, and other ports will do in the future.  
<blockquote>
  Question is &#8211; if the timer IRQ makes the semaphore available more than once &#8211; and the task isn&#8221;t resumed &#8211; is that a problem?
</blockquote>
So, if the task is being resumed, it must have been suspended?&nbsp; Is that correct?  
If it is suspended while it is waiting for a semaphore, when it is resumed it will re-check to see if the semaphore is available.&nbsp; If the semaphore is not available then it will block again to wait for it &#40;assuming any specified block time remains&#41;.&nbsp; If the semaphore is available it will take it and exit the xSemaphoreTake&#40;&#41; function.  
If an interrupt &#8216;gives&#8217; the semaphore twice while the task is suspended then the task will recognise the semaphore is available when it is resumed, but it won&#8217;t recognise that the semaphore has been given twice.&nbsp; If you need it to know the semaphore has been given twice then use a counting semaphore.  
Whether a binary or counting semaphore is preferred depends on the application.&nbsp;   
Regards.
