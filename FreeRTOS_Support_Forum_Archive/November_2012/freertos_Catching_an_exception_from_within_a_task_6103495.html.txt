  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Catching an exception from within a task</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/herschy">herschy</a> on November 1, 2012</div><div class="thread-post-content">Hi&#33;<br />
Currently working with CCS v5.1 compiling code for an ARM MCU LM3S1968 Cortex-M3 using tms470, v4.9.1.<br />
For the time being, I am using FreeRTOS v6.0.5.  
I am programming c++ and compiler options have been set to support &#8220;GCC extensions&#8221; and &#8220;C++ exception handling&#8221;.  
My problem: catching an exception from within a running task when an object is throwing the exception  
THIS WORKS:<br />
having a try-catch inside my task and explicitly throwing an exception. The exception is caught in the exception handler as expected to. All well&#33;<br />
try&#123;<br />
throw 5;<br />
&#125;<br />
catch&#40;int&amp; e&#41;<br />
&#123;<br />
//exception is caught :-&#41;<br />
&#125;  
THIS DOES NOT WORK &#40;for me&#41;:<br />
when an object inside the try-block raises an exception it never gets caught.  
Myclass my1;<br />
try&#123;<br />
my1.MethodThrowsException&#40;&#41;;<br />
&#125;<br />
catch&#40;…&#41; //regardless of what I put here<br />
&#123;<br />
exception is never caught :-&#40;<br />
&#125;<br />
Can anyone explain why? Is there a workaround?  
Any help would be highly appreciated  
</div></div><div class="thread-post"><h3 class="thread-post-title">Catching an exception from within a task</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on November 2, 2012</div><div class="thread-post-content">Sorry &#8211; there is no official CCS5 CM3 port, and C++ is not supported.&nbsp; All I can do is direct you to the FreeRTOS Interactive site where several people have provided C++ projects and frameworks, to see if there is anything there that can assist you.&nbsp; You might also be able to search through the support archive as C++ usage is discussed periodically.  
Regards.
