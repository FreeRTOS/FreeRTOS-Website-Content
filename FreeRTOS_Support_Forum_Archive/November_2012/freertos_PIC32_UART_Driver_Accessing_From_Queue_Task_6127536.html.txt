</div></div><div class="thread-post"><h3 class="thread-post-title">PIC32 UART Driver Accessing From Queue Task </h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on November 5, 2012</div><div class="thread-post-content">You create a queue that holds five messages of sizeof&#40;LogMessage&#41; bytes. I don&#8217;t know how many bytes that is, but will assume it is more than 4 &#8211;  
<pre><code>xQueueHandleGSMSend2 = xQueueCreate(5, sizeof(LogMessage));
</code></pre>
You create a variable that is a pointer to a LogMessage. A pointer on a PIC32 is 4 bytes &#8211;  
<pre><code>LogMessage* lReceivedData2;
</code></pre>
You then copy sizeof&#40;LogMessage&#41; bytes into the variable that is 4 bytes &#8211;  
<pre><code>xStatus = xQueueReceive(xQueueHandleGSMSend2, &amp;lReceivedData2, portMAX_DELAY);
</code></pre>
If sizeof&#40;LogMessage&#41; bytes is more than four then more than four bytes will be copied into the pointer, and you will corrupt your stack. Even if sizeof&#40;LogMessage&#41; is only 4 bytes, you will not end up with a pointer to a log message. I suspect you want to do something like this &#8211;  
Create a variable that is a LogMessage &#40;not a pointer to one&#41; &#8211;  
<pre><code>LogMessage lReceivedData2;
</code></pre>
Copy a log message from the queue into the variable that is of type LogMessage &#8211;  
<pre><code>xStatus = xQueueReceive(xQueueHandleGSMSend2, &amp;lReceivedData2, portMAX_DELAY);
</code></pre>
Not related to your problem, but this code &#8211;  
<pre><code>    //cleans buffers
    for(i=0; i&lt;SIZE_OF_BUFFER_OUT; i++){
        buffer_out = ' ';
        second_buffer_out = ' ';
    }
</code></pre>
does not appear to do anything except repeatedly set the same two variables to  .  
same comment for this code &#8211;  
<pre><code>      //clears input buffer
         for( i=0; i&lt;SIZE_OF_BUFFER_IN; i++)
             buffer_in = ' ';
</code></pre>
