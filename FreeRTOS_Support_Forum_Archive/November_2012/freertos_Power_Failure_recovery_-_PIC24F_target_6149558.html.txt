  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Power Failure recovery &#8211; PIC24F target</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/savexp">savexp</a> on November 9, 2012</div><div class="thread-post-content">Target microcontroller is PIC24F256GB210 and FreeRTOS is 7.2.0.&nbsp;&nbsp; Currently developing the application using explorer 16 development board.<br />
Our project has a power fail recovery scenario, where in we check the power failure using an external interrupt and leave behind a cookie if power fails.&nbsp; On every reset we check for this cookie, if set then we go into power fail recovery mode and the application has to start again from its last known state.&nbsp; I would like to know if there is any help guide or manuals or demo projects in freertos that can help me on what to do on the freertos kernel for this scenario?&nbsp; Thanks.
</div></div><div class="thread-post"><h3 class="thread-post-title">Power Failure recovery &#8211; PIC24F target</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on November 9, 2012</div><div class="thread-post-content">In a word….no.  
The stat of the system has several components:  
1&#41; The value of the CPU registers.<br />
2&#41; The value of the RAM &#8211; which holds the stack and register values for each task.<br />
3&#41; The value of the program counter.  
If any of these change, and you cannot recover them, then you cannot get back to the exact same state.  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">Power Failure recovery &#8211; PIC24F target</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on November 11, 2012</div><div class="thread-post-content">The PIC24 family has a reset status register to tell you the reason for the reset, and you could thus detect that you didn&#8217;t have a &#8220;power fail&#8221; but something less serious that perhaps some of the ram data might be recoverable &#40;assuming you make sure the startup routine doesn&#8217;t kill their values by marking them properly.  
You will not be able to just pickup where you stopped, as not enough information will be saved/preserved.  
YOUR application will need to save the data needed to restart your application &#8220;in the middle&#8221;, as this is extremely application specific. If you really want to handle going through a power-down, you will need some form of non-volitile memory in the system to keep updated with the state to restart at.
