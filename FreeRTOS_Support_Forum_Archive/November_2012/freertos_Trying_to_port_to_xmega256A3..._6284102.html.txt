  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Trying to port to xmega256A3&#8230;</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/travisgriggs">travisgriggs</a> on November 26, 2012</div><div class="thread-post-content">We have some code where I work at that runs on an xmega256A3. I think it&#8217;s overtly complex with all of its state machines, and would like to try using FreeRTOS with it. I&#8217;m new to this. I&#8217;ve read through a bunch of the docs. I downloaded the latest &#40;I&#8217;m excited about the tickless support, because we frequently sleep to save power&#41;. And I think I&#8217;m correct in noticing that this processor is not an official supported port. I&#8217;m developing on an OSX box with CrossPack&#8217;s AVR toolchain and avrdude.  
So I cloned Demo/AVR&#95;ATMega323&#95;WinAVR, that seemed like it would be the most similar to the xmega256a3 and my platform. I made minor adjustments to the makefile &#40;adjusted the DIRAVR and MCU variables&#41;.  
When I try to &#8216;make&#8217; from there, I get the following error:  
ParTest/ParTest.c:102:2: error: &#8216;DDRB&#8217; undeclared &#40;first use in this function&#41;  
What confuses me though, is where DDRB would normally come from? A &#8216;grep -R &#8220;DDRB&#8221; &#42;&#8217; at the root FreeRTOS directory level, doesn&#8217;t turn up anything that gives me any hints about what to do to resolve it for my target…  
Any help/hints with this specific issue, as well as any general guidance about what else I&#8217;m going to need to do to make this work, are much appreciated. I would love to hear that there&#8217;s already been a port to the xmega256a3…
</div></div><div class="thread-post"><h3 class="thread-post-title">Trying to port to xmega256A3&#8230;</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/edwards3">edwards3</a> on November 26, 2012</div><div class="thread-post-content">I just looked in partest.c &#40;the file that generates the error&#41; for the AVR GCC port and it contains the line:  
<blockquote>
  DDRB = partstALL&#95;BITS&#95;OUTPUT;
</blockquote>
FreeRTOSConfig.h includes &lt;avr/io.h&gt; so the definition must come from there.  
I guess that is a data direction register for port B? I suspect the name used by the compiler has changed since the demo was written.  
You will find other AVR ports in the Interactive site <a href="http://interactive.freertos.org/forums/103473-atmel">http://interactive.freertos.org/forums/103473-atmel</a>. Also check out the forums at 
<blockquote>
  <a href="http://www.avrfreaks.net/">http://www.avrfreaks.net</a>
</blockquote>
where there are some FreeRTOS users.
