  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">How to exit low power mode with IDLE Hook?</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/marting2015">marting2015</a> on February 16, 2015</div><div class="thread-post-content">I have enabled the IDLE hook and using it to put the processor into a low power mode.  How do I exit low power mode?  It would seem I would need another hook that tells me when a non-IDLE task is scheduled&#8230; I am also using tickles mode.  
I can see that the scheduler is turned off (SUSPEND) and there is a call to RESUME when FreeRTOS exits sleep mode (see portTASK_FUNCTION()).  One solution could be to trigger a special (highest priority) task that restores the CPU (exit low power) before any of the other tasks run, which I guess could be done with a semaphore to a high priority task, and GIVE the semaphore when xTaskResumeAll() is called.  However I don&#8217;t want to touch FreeRTOS functions, so I don&#8217;t think this is the right approach.
I tried putting my exit<em>low</em>power code in vPortSuppressTicksAndSleep() but the target crashes hard&#8230; I suspect because my exit<em>low</em>power uses FreeRTOS APIs, and vPortSuppressTicksAndSleep() is probably running in special (interrupt?) context where I can&#8217;t call those APIs.  Because I am using tickles mode, my openOCD GDB connection won&#8217;t work to debug it further.
</div></div><div class="thread-post"><h3 class="thread-post-title">How to exit low power mode with IDLE Hook?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on February 16, 2015</div><div class="thread-post-content">As we were just discussing in this thread: http://sourceforge.net/p/freertos/discussion/382005/thread/e717bb2f/#d81e if you are using tickles idle then you should >not&lt; be doing any of this stuff in the idle hook &#8211; all you should be doing is defining the pre and post sleep macros if that is desirable to do something chip specific before and after the sleep respectively.
You cannot use another hook, or another task, because when the CPU is sleeping nothing is running (so the task you want to use to wake up is not running so can&#8217;t wake you up).
The tickless idle mode takes care of all this for you.  It will wake up at the right time, or when an interrupt occurs.
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">How to exit low power mode with IDLE Hook?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/marting2015">marting2015</a> on February 17, 2015</div><div class="thread-post-content">I thought this was a different enough topic to start a new thread.  I think my question is slightly different&#8230;
Lets say that I have an LDO that I want to turn off when that component is not being used, and I know its not being used when the IDLE task is running.  But when any other task is running, the component may be used.  So in the IDLE hook I would turn off the component.  But when do I turn it on?
Based on your answer above, and from the other thread, I can use the pre and post sleep macros to turn OFF/ON the LDO.  That makes sense.  And works in tickles mode.  In tick mode, though, those macros aren&#8217;t called.
If I wanted to use the IDLE hook to turn off the LDO, if there a mechanism to turn on the LDO when the IDLE task is pre-empted to run (any) other task?
</div></div><div class="thread-post"><h3 class="thread-post-title">How to exit low power mode with IDLE Hook?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on February 17, 2015</div><div class="thread-post-content">I think you would have to do that from a trace macro &#8211; you could use 
traceTASK<em>SWITCHED</em>OUT( x ).  If x is not the idle task then do whatever 
you need to do.  Note the macro might be called from an interrupt 
though, so whatever you do will have to be fast.
If INCLUDE<em>xTaskGetIdleTaskHandle() is set to 1 in FreeRTOSConfig.h then 
inside the traceTASK</em>SWITCHED_OUT() macro the handle of the idle task is 
held in a variable called xIdleTaskHandle.
To ensure future proofing the code though you would be better off 
calling xTaskGetIdleTaskHandle() yourself rather than relying on the 
name of the variable not changing in future FreeRTOS versions.
Regards.
