I&#8217;ve configured FreeRTOS+TCP labs (141019) and written an interface driver for the TM4C part. 
I&#8217;m writing an HTTP server that has a thread listening for inbound TCP connections. Once the connection is received, the new socket will be passed to a thread pool via a queue and handled there. My problem is that the FreeRTOS_accept call doesn&#8217;t wake up the thread. I can see in Wire Shark that the TCP stack takes the connection (SYN, ACK, HTTP request), but the handling thread is never woken up to handle it, so it just remains connected until some other event closes the socket.
If I configure the listening socket w/ a non-zero FREERTOS<em>SO</em>RCVTIMEO, the accept call returns. If no connection was found, I retry. If a connection is found, I pass it along and it is handled correctly, data flows, and all is well. But I&#8217;d prefer the accept call wake up my thread when a connection is received to reduce both latency and un-needed cycles. Is this not supported in the current version of FreeRTOS+TCP?
I am very ready to acknowledge that I may have mis-configured FreeRTOS or FreeRTOS+TCP.
My connection accepting thread:
~~~~~~
void http<em>server(void * params)
{
    static const TickType</em>t xReceiveTimeOut = 1000 / portTICK<em>RATE</em>MS; // portMAX_DELAY;

Please note that all settings done with <code>FreeRTOS_setsockopt()</code> will be inherited by the child-sockets. That includes all timings and buffer sizes.
In some cases a connection may have a very short life, like 25 ms to receive 50 KB. The handling task may wake-up after the connection has gone. The data can still be read though.

&#8216;<code>xNetworkEventQueue</code>&#8216; is the Queue that hold the messages for the IP-task. It should never run out of space.
Some NetworkInterface.c files already had the following check in their MAC task:
~~~~~
    {
        uxCurrentCount = uxGetMinimumFreeNetworkBuffers();
        if( uxLastMinBufferCount != uxCurrentCount )
        {
            /* The logging produced below may be helpful
            while tuning +TCP: see how many buffers are in use. */
            uxLastMinBufferCount = uxCurrentCount;
            FreeRTOS_printf( ( &#8220;Network buffers: %lu lowest %lun&#8221;,
                uxGetNumberOfFreeNetworkBuffers(), uxCurrentCount ) );
        }
    }
~~~~~
It would be good to monitor the space in the &#8216;<code>xNetworkEventQueue</code>&#8216; as well.
Without changing anything to FreeRTOS_IP.c you can define this macro in your &#8216;FreeRTOSIPConfig.h&#8217;:
~~~~~
    extern UBaseType<em>t uxQueueMinimumSpace;
    #define iptraceNETWORK</em>EVENT<em>RECEIVED( EventType ) 
    { 
        if( xReceivedEvent.eEventType != eNoEvent ) 
        { 
        UBaseType</em>t uxCount; 
             uxCount = uxQueueSpacesAvailable( xNetworkEventQueue ); 
            if( uxQueueMinimumSpace > uxCount ) 
            { 
                uxQueueMinimumSpace = uxCount; 
            } 
        } 
    }
~~~~~
Declare and initialise it as follows:
~~~~~
    /* Define and initialise &#8216;uxQueueMinimumSpace&#8217; */
    UBaseType_t uxQueueMinimumSpace = ipconfigEVENT_QUEUE_LENGTH;
~~~~~
and finally add some logging:
~~~~~
    if( uxLastLowCount != uxQueueMinimumSpace )
    {
        uxLastLowCount = uxQueueMinimumSpace;
        FreeRTOS_printf( ( &#8220;Lowest queue space: %lun&#8221;,
            uxLastLowCount ) );
    }
~~~~~
