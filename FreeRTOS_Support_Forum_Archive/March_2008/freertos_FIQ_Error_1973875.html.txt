Controller: AT91SAM7S256
Dev Board:&nbsp; AT91SAM7S-EK
Compiler:&nbsp;&nbsp; IAR 5.11
&nbsp;&nbsp;&nbsp;&nbsp; I have downloaded demo project provided for the above said configuration, compiled and transferred it to the target using ATMEL SAM-ICE &#40;J-Link&#41;. But when I say run it hangs when it tries to execute the following line
orr&nbsp;&nbsp;&nbsp;&nbsp; r0,r0,&#35;FIQ&#95;MODE&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ; Set FIQ mode bits
and comes to the following section of the code
&#95;&#95;und&#95;handler:
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ldr&nbsp; pc,&#91;pc,&#35;+24&#93;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ;; Undefined instructions
I guess a interrupt is getting generated. But cant understand it fully. 
Looking forward for replies.
</div></div><div class="thread-post"><h3 class="thread-post-title">FIQ Error</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on March 18, 2008</div><div class="thread-post-content">This is in the startup code right, before main&#40;&#41; is called? All it does is set r0 so nothing that could cause it to jump to the FIQ handler. Does the program hang when you run it without the debugger also? It could be the debugger is not initializing the micro correctly so there is an FIQ pending. I don&#8217;t think this can be the case though as setting the processor into FIQ mode is very different from actually generating an FIQ.
</div></div><div class="thread-post"><h3 class="thread-post-title">FIQ Error</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on March 18, 2008</div><div class="thread-post-content">more &#8211;
I note you are using the S256. Did you change the target device in the project settings to be for this device, and select the correct linker script. I think the demo yo are basing it on is for a SAM7 with less memory.
