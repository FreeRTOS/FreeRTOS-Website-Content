  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">AVR32 UC3 and GCC Tools</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/klvaneyll">klvaneyll</a> on March 31, 2008</div><div class="thread-post-content">There&#8217;s a recently identified problem with Atmel&#8217;s AVR32 UC3 build GCC build tools. The problem seems to be that the linker will include an entire library instead of scanning the library for used functions. This results in a program file bloated with unnecessary and uncalled functions. I&#8217;m working on a USB application that almost triples in size when build with the GCC tools vs. IAR&#8217;s kickstart version.
To get around this I had to add tell the linker to not use the standard gcc library &#40;-nostdlib linker option&#41;. I then had to modify the FreeRTOS source code to remove the standard library calls, replacing them with functions added to port.c.
Being new to open source code I&#8217;m not sure of the procedure for modifying the code. I know I have to make changes publicly available. &#40;This is a commercial application&#41;. It seems it may be useful to someone to not use any library calls in the main RTOS code, and include library calls only in port.c which could be removed by conditional compile flag. Would this be useful to any one else?
Atmel has admitted this problem but I havent&#8217; heard a timeframe for getting it fixed.
</div></div><div class="thread-post"><h3 class="thread-post-title">AVR32 UC3 and GCC Tools</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on March 31, 2008</div><div class="thread-post-content">Thanks for the info.
Does the makefile use the -ffunction-sections and -fdata-sections compiler options, and then the &#8211;gc-sections linker option?&nbsp; I think in theory this should reduce the code size by removing unused functions but it can be difficult.
If you send your modification to me &#40;r &#95;dot&#95; barry &#95;@&#95; freertos.org&#41; then I can hold them on record, and then forward them to anybody else who expresses after reading this post.&nbsp; That way the source code is &#8216;available&#8217;.
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">AVR32 UC3 and GCC Tools</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/klvaneyll">klvaneyll</a> on April 1, 2008</div><div class="thread-post-content">Even with the compiler and linker options you mentioned, the program file is huge. Apparently the problem is with the gcc library crt0.o startup file. To workaround, use the startup file included in the software framework provided by Atmel &#40;UTILS/STARTUP&#95;FILES/GCC/crt0.S&#41; then use the -ffunction-sections and -fdata-sections compile options, and &#8211;gc-sections and -nostdlib linker options. memset&#40;&#41;, memcpy&#40;&#41;, and strncpy&#40;&#41; functions will need to be replaced. After this my program size went from 88kB to 36kB.
Ideally Atmel will resolve this before production release of this product, if not, or if anybody else is interested I&#8217;ll send you the modified source code.
