I&#8217;m working on getting my LPC2368 development board running with FreeRTOS 5.0.2.&nbsp; I&#8217;ve used FreeRTOS in the past with an AT91SAM7XC256 with ease, mostly because the work was already done :&#41;.&nbsp; I see that there are ports available for this processor, just not for this compiler.&nbsp; I have a Keil MCB2300 development board that IAR has a demo project for.&nbsp; This demo project works just fine.&nbsp; I&#8217;ll list the steps I performed trying to get this working.
&#42; I started with the LPC2129 IAR FreeRTOS project.
&#42; I changed the ICF and startup.s files to what IAR supplied for the MCB2300 board, these files work fine in my demo application.
&#42; I included LPC230x.h header file instead of the 2129 file.&nbsp; This required a few semantic changes in the project; mainly IO1CLR to IOCLR1 and the like.&nbsp; This file was provided by IAR and I&#8217;m using it in my other application.
&#42; I changed the core under options to a 2368 instead of the 2129.
&#42; I also changed the processor speed in FreeRTOSConfig.h to 57600000.
&#42; I&#8217;m using the PLL setup code from my other application in place of the hardware setup code in main&#40;&#41; from the 2129 port.&nbsp; I&#8217;m not setting up the MAM since the version of the chip I have has an errata on it that was fixed in a newer revision, as such I won&#8217;t be using it just yet.
The original 2129 port uses the &quot;FreeRTOSSourceportableIARLPC2000&quot; port files, which I&#8217;m assuming by the name will work with the 2368.&nbsp; &quot;LPC2000&#95;IAR&quot; is defined so the correct portmacro.h file is included.
All of this compiles and loads without warnings.&nbsp; I&#8217;m getting a prefetch abort after the call to &quot;vTaskStartScheduler&quot;.&nbsp; 
vTaskStartScheduler -&gt; xPortStartScheduler -&gt; vPortStartFirstTask -&gt; portRESTORE&#95;CONTEXT
portRESTORE&#95;CONTEXT is located in ISR&#95;Support.h.&nbsp; &quot;LDR LR, &#91;LR, &#35;+60&#93;&quot; ends up with 0x00 in LR, then the operation after that &quot;SUBS PC, LR, &#35;0x4&quot; results in the prefetch abort.
My assembly isn&#8217;t terrific, I&#8217;m going to figure out what those two operations should actually result in.&nbsp; If anyone has any input it would be well received.&nbsp; I can send my project files off to whoever might be interested.&nbsp; If someone has a project already started and would like to share I would be very grateful.

</div></div><div class="thread-post"><h3 class="thread-post-title">Issue with LPC2368 with IAR</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on July 29, 2008</div><div class="thread-post-content">If you take a look in the file lpc2xxx&#95;cstartup.s that is located in the DemoARM7&#95;LPC2129&#95;IARSrcIAR directory you will see the lines:
;
; Add more initialization here
;
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; BIC&nbsp;&nbsp;&nbsp;&nbsp; r0, r0, &#35;MODE&#95;BITS&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ; Clear the mode bits
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ORR&nbsp;&nbsp;&nbsp;&nbsp; r0, r0, &#35;SVC&#95;MODE&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ; Set SVC mode bits
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; MSR&nbsp;&nbsp;&nbsp;&nbsp; cpsr&#95;c, r0&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ; Change the mode
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; 
; Continue to ?main for C-level initialization.
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; LDR&nbsp;&nbsp;&nbsp;&nbsp; r0, =?main
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; BX&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; r0
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; END
This changes the mode before calling main.&nbsp; It might be that you can just use the same file.&nbsp; If you are not familiar with this then also note also that the file sets up a stack for each processor mode.&nbsp; You must set up an IRQ stack and Supervisor stack as a minimum.
You need to look in the ARM7 core documentation for information on the CPU modes, rather than the device data sheet.&nbsp; Search for a document called &quot;ddi0100e&quot;, often referred to as the &quot;ARM ARM&quot;.
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">Issue with LPC2368 with IAR</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/kenfarr">kenfarr</a> on July 29, 2008</div><div class="thread-post-content">Okay, 
I compared the timing setup differences and made mine work identical to the GCC version for the 2368.&nbsp; I actually went through all the port files to make sure the IAR 2368 code was doing equivalent work.&nbsp; This lead me to notice that in the 2368 IAR file the SPSR register was being set to System Mode but THUMB mode was not enabled.&nbsp; Originally the portINITIAL&#95;SPSR was defined as 0x1f in both GCC versions but 0x3f in the IAR version.&nbsp; I have an ARM Architect Reference Manual, Second Edition, and in section A2-10 it defines the bits for this register.&nbsp; 
bits 0-4 &#8211; MODE bits
bit&nbsp; 5&nbsp;&nbsp; &#8211; T Bit, 1=THUMB 0=ARM
bit&nbsp; 6&nbsp;&nbsp; &#8211; FIQ, 0=enabled, 1=disabled
bit&nbsp; 7&nbsp;&nbsp; &#8211; IRQ, 0=enabled, 1=disabled
So, 0x1F would put the system into non-thumb mode.&nbsp; This might be a bug in the GCC version, that&#8217;s why I mention it, I&#8217;m compiling for thumb mode so I left it.
I added a software interrupt handler &#40;branch to vPortYieldProcessor&#41; and everything appears to be working now as expected.&nbsp; I&#8217;ll perform more tests and see what I can do to make the actual project function on this board with this hardware.&nbsp; After I clean up my work I&#8217;ll send you the project so you can add it to your demo lists.
-Ken
