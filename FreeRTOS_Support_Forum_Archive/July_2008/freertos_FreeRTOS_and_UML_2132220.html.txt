</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS and UML</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/johughes2002">johughes2002</a> on July 28, 2008</div><div class="thread-post-content">I worked for Telelogic at their office in Germany for a practicum a couple of years ago, just before they purchased Rhapsody. The other UML tool that they have is called TAU and was developed in-house. One of the things I worked on was to increase the number of supported embedded targets you could run UML state machines on. Basically the UML tool would generate a bunch of c code which would run the model. Porting was simply a matter of providing the generators with macros to hook into the system calls needed from the target. I did ports to LegOS and OpenOSEK. I can&#8217;t see the process being much different for Rhapsody, although I admittedly have never seen the way Rhapsody generates its code.
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS and UML</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/quantum-leaps">quantum-leaps</a> on July 28, 2008</div><div class="thread-post-content">The QP family of ultra-light, open source, UML state machine frameworks has been just recently ported to FreeRTOS.org. The open source QP should fit very well the lightweight, open-source nature of FreeRTOS.org.
QP is not a traditional UML tool. Rather, QP is a lightweight framework, similar to the Rhapsody’s OXF &#40;Object Execution Framework&#41; or the IDF &#40;Interrupt Driven Framework&#41;, except QP is designed for manual coding. With QP, coding of modern UML state machines &#40;UML statecharts&#41; directly in C or C++ is a non-issue and no big design automation tools are needed.
QP consists of a universal UML-compliant event processor &#40;QEP&#41;, a portable event-driven framework &#40;QF&#41;, and a portability layer for an RTOS/Kernel of your choice. QP also provides a cooperative as well as a fully preemptive kernel &#40;QK&#41;. Current versions of QP include: QP/C and QP/C++, which require about 4KB of code and a few hundred bytes of RAM, and the ultra-lightweight QP-nano, which requires only 1-2KB of code and just several bytes of RAM. QP is described in great detail in the book “Practical UML Statecharts in C/C++, Second Edition”, &#40;Newnes, 2008&#41;.
The QP port to FreeRTOS is available for download from www.state-machine.com/freertos. The QP port has been tested on the STR912-SK &#40;ARM9&#41; board with the IAR compiler. The QP port comes with a detailed manual in PDF available at http://www.state-machine.com/freertos/QDK&#95;FreeRTOS.pdf.
Please visit www.state-machine.com for more details about QP.
Miro Samek
miro@quantum-leaps.com
