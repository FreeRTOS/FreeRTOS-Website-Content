  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">FreeRTOS, fatfs, and spi. interrupt issues?</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/sjkklein">sjkklein</a> on July 1, 2016</div><div class="thread-post-content">Hello all!
This is my first time using freertos. I am using a SAM4 chip and trying to configure it so that it can write to an sd card. 
I currently have it setup for one task to simply write to the sd. When I read back the file it is all good except for at extremely regular intervals I get a segment of extended ascii garbage inside my file, but mostly I just see the good data. My first instinct was that the tick interrupt was causing an error in my spi communications. 
The first thing I tried was a lazy approach that I thought was garaunteed to work. I surrounded each call to a fatfs function with portENTER<em>CRITICAL and portEXIT</em>CRITICAL. I realize that is not a good way to do it and it was really just a diagnostic measure. But anyways&#8230; No dice, identacle behavior to before. 
The next thing I tried was to write one thing and then wait for the next tic in order to write again. I know that the write fits in between ticks. I get the same data corruption in (weirdly) the exact same spot.
I know that this is RTOS related because when I run very similar code without the rtos it writes perfectly.
Any ideas? I don&#8217;t even know what to try next. I seem to get corrupt data every 400 characters or so.
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS, fatfs, and spi. interrupt issues?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on July 2, 2016</div><div class="thread-post-content">Are you 100% sure the SPI to SD card interface is working solidly when 
you are not using FreeRTOS?
How is the SPI driver functioning, is it using interrupts or just polling?
Are you sure the SPI is not accessed by any other tasks.
If you share the fatfs file system between tasks then you have to set a 
constant in the file system&#8217;s configuration file, but as you are only 
using it from one task that should not be necessary.
(by the way, we have our own file system working on Atmel Cortex-M chips 
too &#8211; see 
http://www.freertos.org/FreeRTOS-Plus/FreeRTOS<em>Plus</em>TCP/TCPIP<em>FAT</em>Examples<em>Atmel</em>SAM4E.html 
)
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS, fatfs, and spi. interrupt issues?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/sjkklein">sjkklein</a> on July 5, 2016</div><div class="thread-post-content">I am 100% sure that the interfaces works without FreeRTOS. 
Currently it is configured for polling, but ultimately I want to use the DMA and change it to interrupt based.
I have only been running one task because I can&#8217;t get it to work, so it is certainly the only one accessing SPI.
Thanks for posting that link! That is some good stuff. I may try to just implement it with that FAT filesystem used in those demo examples. I am really at a loss, I cannot trace down my error.
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS, fatfs, and spi. interrupt issues?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/sjkklein">sjkklein</a> on July 5, 2016</div><div class="thread-post-content">I&#8217;m posting here for the people that inevitably run into the same problem. The above comment made me realize I was mounting the SD in the main, so I guess sharing the filesystem between main and the task caused an issue. When I ran the code without free rtos I was just calling the task function and it worked perfectly. When I used FreeRTOS it did not work until I mounted it once within the function. I don&#8217;t know why that worked, but I think I don&#8217;t understand mounting very well&#8230;
