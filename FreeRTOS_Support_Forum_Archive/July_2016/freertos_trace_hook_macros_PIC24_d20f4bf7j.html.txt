</div></div><div class="thread-post"><h3 class="thread-post-title">trace hook macros (PIC24)</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on July 6, 2016</div><div class="thread-post-content">Store the handle of vPrintTask() in a variable, say xPrintTask.  Then 
define your traceTASK<em>SWITCHED</em>IN() and traceTASK<em>SWITCHED</em>OUT() macros 
at the END of FreeRTOSConfig.h.  The task being switched in or out is 
stored in the pxCurrentTCB variable.  So&#8230;
<pre>
#define traceTASK_SWITCHED_OUT()     
     if( xPrintTask == pxCurrentTCB ) 
     {                                
         /* xPrintTask is being switched out. */ 
     }
#define traceTASK_SWITCHED_IN()      
     if( xPrintTask == pxCurrentTCB ) 
     {                                
         /* xPrintTask is being switched in. */ 
     }
</pre>
See the table on http://www.freertos.org/rtos-trace-macros.html

</div></div><div class="thread-post"><h3 class="thread-post-title">trace hook macros (PIC24)</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on July 7, 2016</div><div class="thread-post-content">1) sprintf() is probably using masses of stack, and may even be calling 
malloc().
2) it is never a good idea to use any of the printf() style string 
formatting functions inside an interrupt, or malloc, or any other 
non-reentrant stack hungry function that could potentially take a long 
time to execute &#8211; these macros are called from inside an interrupt.
