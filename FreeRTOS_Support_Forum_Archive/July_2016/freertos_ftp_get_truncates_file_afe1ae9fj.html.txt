The mentioned defines must appear in your <code>FreeRTOSFATConfig.h</code>.
In your case, when <code>ffconfigDEV_PATH</code> is an empty string, the string &#8220;<code>//test.txt</code>&#8221; refers to a device and not a file.
A size of 2048 bytes is returned for a device and in your case &#8220;<code>//test.txt</code>&#8221;  is still interpreted as a divice.
By the way, there is an easy way of sending out logging:
<pre><code>FreeRTOS-Plus/Demo/Common/Utilities/UDPLoggingPrintf.c
</code></pre>
It has some buffering of the logging lines and it also precedes each line with a millisecond-time-stamp, such as:
<pre><code>2016-07-18 23:43:12.896 IP Address: 192.168.2.1
</code></pre>
It is easy to add TCP logging to this module. I normally connect it to a telnet server.
<code>lUDPLoggingPrintf</code> is not interrupt-proof 🙁
~~~~
    strcat( pcWriteBuffer, cliNEW_LINE )
~~~~
Some telnet clients like this, because only complete lines (with a LF) will be flushed.
For others (also for me), the extra LF can be confusing.
In <code>UDPLoggingPrintf.c</code>, no LF&#8217;s will be added. Also it has an option to turn every LF into a LF/CR:
~~~~
    #define configUDP<em>LOGGING</em>NEEDS<em>CR</em>LF    1
~~~~
&#8220;<code>hello worldn</code>&#8221; will be then sent as &#8220;<code>hello worldrn</code>&#8221;
