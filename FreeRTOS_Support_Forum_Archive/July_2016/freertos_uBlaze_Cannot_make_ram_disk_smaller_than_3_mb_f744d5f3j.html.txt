</div></div><div class="thread-post"><h3 class="thread-post-title">uBlaze: Cannot make ram disk smaller than 3 mb</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rasty1">rasty1</a> on July 25, 2016</div><div class="thread-post-content">How can I force it to use FAT12?
</div></div><div class="thread-post"><h3 class="thread-post-title">uBlaze: Cannot make ram disk smaller than 3 mb</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on July 25, 2016</div><div class="thread-post-content">Unfortunately, the <code>FF_Format()</code> routine does not (yet) support FAT12, only FAT16 and FAT32.
Two parameters indicate your preference:
<code>xPreferFAT16</code>: try to use FAT16, if not possible, try FAT32
<code>xSmallClusters</code>: try small clusters first, if not possibly, try larger clusters.
Larger clusters are more efficient in terms of speed, small clusters have less waste of space.
Microsoft states that:
~~~~
    if( CountofClusters &lt; 4085 )
    {
        /* Volume is FAT12 <em>/
    }
    else if( CountofClusters &lt; 65525 )
    {
        /</em> Volume is FAT16 <em>/
    }
    else
    {
        /</em> Volume is FAT32 */
    }
~~~~
+FAT is following Microsoft&#8217;s guidelines to get a maximum compatibility. However, you are not going to exchange your RAM disk with another system.
You could try the following in <code>ff_format.c</code> :
~~~~
<h1>ifdef ffconfigMIN<em>CLUSTERS</em>FAT16</h1>
<pre><code>#define MIN_CLUSTERS_FAT16    ffconfigMIN_CLUSTERS_FAT16
</code></pre>
<h1>else</h1>
<pre><code>#define MIN_CLUSTERS_FAT16    ( 4085 + 1 )
</code></pre>
<h1>endif</h1>
~~~~
And define <code>ffconfigMIN_CLUSTERS_FAT16</code> in your <code>FreeRTOSFATConfig.h</code> with a smaller value of e.g. :
~~~~
    #define ffconfigMIN<em>CLUSTERS</em>FAT16   1800
~~~~
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">uBlaze: Cannot make ram disk smaller than 3 mb</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on July 25, 2016</div><div class="thread-post-content">Just tested in the WIN32 demo project and it works as expected.
A 2MB RAM-disk will get <strong>4023</strong> clusters, a 1MB disk gets<strong>1991</strong> clusters. In these cases, each cluster will contain a single sector of 512 bytes.
