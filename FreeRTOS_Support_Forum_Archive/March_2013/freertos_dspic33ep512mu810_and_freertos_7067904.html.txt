</div></div><div class="thread-post"><h3 class="thread-post-title">dspic33ep512mu810 and freertos</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on March 18, 2013</div><div class="thread-post-content">The current port for the 16 bit PICS &#40;PIC24 and dsPIC&#41; doesn&#8217;t have support for the E series with extended memory &#40;as I remember, and the fact you are asking says it is probably still true&#41;. The difference between the F families and the E families is a change in the memory mapping registers.   
All that should be needed is to &#40;via an ifdef or something similar&#41; change the saving/restoring of the memory mapping register and add the needed data into the initial stack frame code.

</div></div><div class="thread-post"><h3 class="thread-post-title">dspic33ep512mu810 and freertos</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on March 18, 2013</div><div class="thread-post-content">Actually, FreeRTOS V7.4.0 does have support for the E series for PIC24, but not dsPIC as I wasn&#8217;t quite sure what else was needed on the dsPIC parts.  
The PIC24 port layer should swap automatically between the E and F parts if you are using the latest microchip compiler &#40;XC&#41;.&nbsp; If you look at the port layer files &#40;C and asm&#41; you will see how this is done as the code uses the preprocessor to check for a definition that is provided by the compiler itself.
