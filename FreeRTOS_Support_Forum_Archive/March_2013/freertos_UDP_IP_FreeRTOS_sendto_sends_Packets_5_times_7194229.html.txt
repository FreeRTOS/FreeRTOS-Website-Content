  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">UDP/IP FreeRTOS_sendto sends Packets 5 times</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/hisdudeness23">hisdudeness23</a> on March 25, 2013</div><div class="thread-post-content">I use a LPC1769 MCU with the FreeRTOS UDP/IP stack. I think I have ported the drivers correctly. I use the Standard Implementations &#40;not the Zero Copy types&#41;.<br />
Everytime I use the <strong>FreeRTOS&#95;sendto&#40;&#41;</strong> function, the packets are sent 5 times.<br />
When I do a ping from a Linux machine, I get one normal answer-packet and 4 additional &#40;<strong>DUP&#33;</strong>&#41;-Packets.  
I have used the same code on the raspberry pi with the standard Linux-Berkeley-Sockets implementation and it works perfectly.  
I will do some digging tonight, to localize the problem. But maybe somebody has experienced the same or a similar problem?  
Thanks in advance for an answer&#33;  
The Dude.
</div></div><div class="thread-post"><h3 class="thread-post-title">UDP/IP FreeRTOS_sendto sends Packets 5 times</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on March 25, 2013</div><div class="thread-post-content">I would concentrate your initial investigation in the driver layer &#8211; for example, is there a DMA which is sending the same packet multiple times because there is an error in the descriptor configuration &#40;maybe the last packet is not marked as such in the descriptor&#41;?&nbsp;   
I would suggest counting how many times the xNetworkInterfaceOutput&#40;&#41; function gets called compared to how many packets you see on the wire.&nbsp; That will allow us to narrow down where to look.  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">UDP/IP FreeRTOS_sendto sends Packets 5 times</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/hisdudeness23">hisdudeness23</a> on March 25, 2013</div><div class="thread-post-content">Thank you very much Mr. Barry,  
I will do that right now and I will post the result.
</div></div><div class="thread-post"><h3 class="thread-post-title">UDP/IP FreeRTOS_sendto sends Packets 5 times</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/hisdudeness23">hisdudeness23</a> on March 25, 2013</div><div class="thread-post-content">Dear Mr. Barry,  
the Number of xNetworkInterfaceOutput&#40;&#41; function-calls matches the number of my FreeRTOS&#95;sendto calls and the ratio of the number of packets on the wire and the sendto calls is 5:1, so I think you were right, Sir. The problem should be within the driver layer.  
Thank you very much for your help&#33;
</div></div><div class="thread-post"><h3 class="thread-post-title">UDP/IP FreeRTOS_sendto sends Packets 5 times</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/hisdudeness23">hisdudeness23</a> on March 25, 2013</div><div class="thread-post-content">Problem solved&#33;  
The SendData&#40;&#41; function had no break condition in the for-loop in a successful case. netifMAX&#95;TX&#95;ATTEMPTS was set to 5, so the packet was sent 5 times.  
Thanks again Mr. Barry&#33;<br />
And sorry for interrupting your talk to the guy from i-sysem on the Embedded World. I was that dude, who asked all the questions about the UDP-IP Stack. I hope I didn&#8217;t have messed it up for you.  
Best Regards,<br />
The Dude.
