I&#8217;m trying to use FreeRTOS port on dsPIC33FJ128GP206 and I need to drive a lot of servos. Servos are being driven with OC1-3 channels through multiplexers, OCx are using timer2. FreeRTOS is using timer1, as in example and is running at lowest priority timer interrupt &#40;priority 1&#41;, while timer2 is running at priority 7. When tasks are switching it causes a lag or something and servos shake during context switch.<br />
Just to do some research on issue, I&#8217;ve replaced timer1 handler with some dummy code, to see if it will occur with same interrup priorities &#8211; everything is ok. As soon as I add RTOS functionality &#8211; jitter is back.<br />
How can I get rid of this? I think I&#8217;ve already tried everything, but the jitter is still present. The more tasks I add, the more jitter there is &#8211; shake per task &#40;switch&#41;
</div></div><div class="thread-post"><h3 class="thread-post-title">PWM on dsPIC33</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on March 30, 2013</div><div class="thread-post-content">Are your drives being processed from an interrupt?&nbsp; If so, then setting the interrupt priority above configKERNEL&#95;INTERRUPT&#95;PRIORITY will ensure the interrupts do not get delayed by anything the kernel is doing.&nbsp; It does however also mean that the interrupts cannot call FreeRTOS API function &#40;the functions that end in FromISR are safe on a PIC24/33 only if called from interrupts that run with a priority equal to configKERNEL&#95;INTERRUPT&#95;PRIORITY&#41;.  
Regards.

I am not using any FreeRTOS functions inside interrupt handler and my interrupts are running above configKERNEL&#95;INTERRUPT&#95;PRIORITY while this happens
</div></div><div class="thread-post"><h3 class="thread-post-title">PWM on dsPIC33</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on March 31, 2013</div><div class="thread-post-content">Does that mean your drives are being processed by the interrupts? &#123; IEC0bits.OC1IE = 0;<br />
