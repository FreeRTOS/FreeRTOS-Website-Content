I see that Microchip launched a new IDE and compiler toolchain of which<br />

&nbsp; From what I&#8217;ve seen it wont be an issue, quote MPlab page on Microchip<br />
&nbsp; site &#8220;Can be used with all C++ or mixed C/C++ projects in MPLAB® XC, All<br />
&nbsp; Microchip C language extensions are available for use&#8221; but still, I want<br />
&nbsp; to be sure, so your advice will be appreciated. I&#8217;m, using the all sweet<br />
&nbsp; PIC32MX795f512L controller.  
Thank you<br />
Ruben
</div></div><div class="thread-post"><h3 class="thread-post-title">MPLab X IDE and XC++ compiler</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on March 6, 2013</div><div class="thread-post-content">There has been a lot written in these forums about using FreeRTOS in C++, and intereactive.freertos.org has some C++ frameworks. Search the archive <a href="http://www.freertos.org/FreeRTOS_Support_Forum_Archive/freertos_support_forum_archive_index.html/">http://www.freertos.org/FreeRTOS_Support_Forum_Archive/freertos_support_forum_archive_index.html</a>  
In summary, FreeRTOS is only tested as a C program but it contains the necessary &#8220;extern C&#8221; declarations in header files to allow it to be included in a C++ project provided the FreeRTOS files themselves are still compiled as pure C &#40;the extern C then takes care of the C to C++ linkage&#41;. Up until FreeRTOS V7.4.0 used data hiding by defining types differently in different files, and that is not C++ friendly. Changes to queue.c in FreeRTOS V7.4.0 might have fixed that issue, so there is a chance you could compile the code as C++ now but I don&#8217;t know for sure.
