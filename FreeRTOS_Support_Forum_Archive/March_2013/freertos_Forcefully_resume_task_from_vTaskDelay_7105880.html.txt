  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Forcefully resume task from vTaskDelay()</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/tron21net">tron21net</a> on March 21, 2013</div><div class="thread-post-content">I&#8217;ve looked around in the <strong>task.h</strong> and <strong>semphr.h</strong> header files trying to find the answer, but no available. Is it possible to forcefully resume a task that is in a suspended state via <strong>vTaskDelay</strong>&#40;&#41; by using the <strong>vTaskResume</strong>&#40;&#41; function or another similar function? If this will not work then what alternatives do I have to accomplish the same result?  
My intentions for doing this is for a crude uITRON 4.0 event flag <strong>twai&#95;flg</strong>&#40;&#41; function implementation I&#8217;m doing for an uITRON API compatibility wrapper I&#8217;m creating for FreeRTOS. I&#8217;ve got some driver code that was designed for uITRON for a specific SoC I&#8217;m working with and instead of trying to modify the rat&#8217;s nest condition that the driver code is in I&#8217;m creating the support wrapper API for the driver code to indirectly make use of FreeRTOS&#8217;s APIs as much as possible.  
The idea is for tasks that call twai&#95;flg&#40;&#41; with <strong>tmout</strong> &#33;= <strong>TMO&#95;FEVR || TMO&#95;POL</strong> to place the task&#8217;s handle into a linked list of tasks waiting on a specific flag bit pattern and then they perform <strong>vTaskDelay</strong>&#40;<em>tmout / portTICK&#95;RATE&#95;MS</em>&#41;; so that they&#8217;re sitting in a timeout-able suspended state. Once the event flag&#8217;s bit pattern has changed and matches that of a waiting task I need to wake up/resume the suspended task as its wait condition has been met. So, this is where I&#8217;m stuck. I&#8217;m trying to have the task only be suspended for up to <strong>tmout</strong> value &#40;<em>in milliseconds in this case</em>&#41; and be able to forcefully resume said task upon waiting condition met, the condition checking will be done for each individual waiting task upon successful <strong>set&#95;flg</strong>&#40;&#41; and <strong>clr&#95;flg</strong>&#40;&#41; uITRON API calls in my implementation.  
I did look over the various semaphores that FreeRTOS provides and I couldn&#8217;t find any that would be acceptable for what uITRON&#8217;s event flags are required to do. Perhaps I&#8217;m wrong and overlooked something, so suggestions are welcome.  
Thanks&#33;  
</div></div><div class="thread-post"><h3 class="thread-post-title">Forcefully resume task from vTaskDelay()</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/edwards3">edwards3</a> on March 21, 2013</div><div class="thread-post-content">There is no way of doing what you want if you block on a vTaskDelay. You could suspend on a semaphore with a timeout, then give the semaphore when the event flags are in the right state. If the event flags never get into the right state the semaphore is not given and the task will time out at the appropriate time.  
According to Richard, FreeRTOS does not directly support event flags because the implementations thus far have not been good enough to make it into the FreeRTOS code because they are not deterministic and have long critical sections.
