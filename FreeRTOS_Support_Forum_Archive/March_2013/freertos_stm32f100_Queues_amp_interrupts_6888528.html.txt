</div></div><div class="thread-post"><h3 class="thread-post-title">stm32f100 Queues &#038; interrupts</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on March 6, 2013</div><div class="thread-post-content">The functions do different things. NVIC&#95;SetPriority&#40;&#41; sets the preemption and sub priority values for one interrupts, but does not tell the Cortex NVIC how many bits to use for each. You have to tell it how many bits to use for each before the values passed into NVIC&#95;SetPriority&#40;&#41; make sense. For example, you can try to set the sub priority to 2 in a call to NVIC&#95;SetPriority, but the sub priority will still be 0 if NVIC&#95;PriorityGroupConfig has set the number of bits to use for the sub priority to 0. Another example, if you use NVIC&#95;PriorityGroupConfig to set the number of sub priority bits to 1, then using NVIC&#95;SetPriority to set a sub priority value of 2 is invalid because only 0 and 1 are valid when a single bit is used.
