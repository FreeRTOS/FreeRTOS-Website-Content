</div></div><div class="thread-post"><h3 class="thread-post-title">SAM7 and GCC</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on August 19, 2005</div><div class="thread-post-content">Hi, 
As the WEB documentation says, it is always best to start a new project based on an existing project.&nbsp; That way you have all the correct setup &#40;startup files, command line options, etc.&#41;.&nbsp; Take a look at the ARM7&#95;AT91FR40008&#95;GCC demo.&nbsp; This has all the setup you require, just for the wrong &#40;but similar&#41; chip&#33;
In particular take a look at the startup files.&nbsp; These are much simpler than the Atmel files you are using.
This thread provides more information: https://sourceforge.net/forum/forum.php?thread&#95;id=1334178&amp;forum&#95;id=382005
The startup files have to setup stacks for the relevant modes, then ensure main is called from the Supervisor mode.&nbsp; Not much else.&nbsp; The interrupt handling saving and restoring of the context is then handled by the macros we have previously discussed.&nbsp; At the moment when you get an interrupt the Atmel code is running, then the FreeRTOS code, so things are getting muddled up.
I have send you the startup files that I am using with my Rowley CrossWorks GCC port on the SAM7.&nbsp; Hopefully you will be able to use these directly, but remember I am using a slightly different chip so there could be some differences in the C file &#40;perhaps&#41;.
Let us know how you get on.
Regards.

&#95;.

easily be called as the first thing done in main&#40;&#41;.
It builds and links, but I have not tried it.&nbsp; What hardware are you using?
I only have the IAR demo boards with SAM7 chips.&nbsp; Also I am using a
different build of GCC.
Make sure you have the environment variables set correctly, as per my
previous email, before building.
