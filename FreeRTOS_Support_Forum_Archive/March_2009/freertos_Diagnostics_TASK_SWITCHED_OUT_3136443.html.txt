  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Diagnostics_TASK_SWITCHED_OUT</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/meandmyself">meandmyself</a> on March 25, 2009</div><div class="thread-post-content">strangely enough the first macro to be called is:
traceTASK&#95;SWITCHED&#95;OUT
not
traceTASK&#95;SWITCHED&#95;IN
I saw the code of
void vTaskSwitchContext&#40; void &#41; in tasks.c and in fact the &#95;OUT macro is called at the begin and the &#95;IN at the end.
Any reason for this?
Shouldn&#8217;t at least a call&nbsp; to the &#95;IN macro be missing when the task is put to run for the very first time?
thanks
</div></div><div class="thread-post"><h3 class="thread-post-title">Diagnostics_TASK_SWITCHED_OUT</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on March 25, 2009</div><div class="thread-post-content">traceTASK&#95;SWITCHED&#95;OUT&#40;&#41; should be called first.&nbsp; When SWICTHED&#95;OUT is called pxCurrentTCB points to the TCB of the task that was running prior to the context switch.&nbsp; When SWITCHED&#95;IN is called pxCurrentTCB points to the TCB of the task that is selected to run when next.
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">Diagnostics_TASK_SWITCHED_OUT</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/liljenvall">liljenvall</a> on September 11, 2012</div><div class="thread-post-content">Hi,  
But the very first task will not be preceeded by an SWITCHED&#95;IN call, I think it would be good to get an call also before the first task is started, this way i can measure the execution time of the first run for the first task aswell.  
Best Regards<br />
Fredrik Liljenvall
</div></div><div class="thread-post"><h3 class="thread-post-title">Diagnostics_TASK_SWITCHED_OUT</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on September 11, 2012</div><div class="thread-post-content">The scheduler is started from the port layer &#8211; that is &#8211; the code that is not common to every microcontroller.&nbsp; It would not be easy to go through all 31 ports and update the code to make a call to the SWITCHED&#95;IN macro.  
You know which task is running first, because the SWITCHED&#95;OUT macro that gets called first will tell you.&nbsp; The only information you are missing is the exact time the first task executed for.&nbsp; It would be easier to get this by adding in a new macro in vTaskStartScheduler&#40;&#41;.&nbsp; The new macro could then be used to start the run time stats counter &#8211; if it was already running before the scheduler started.&nbsp; Please add a feature request in the SourceForge feature request tracker if you would like that added.  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">Diagnostics_TASK_SWITCHED_OUT</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/liljenvall">liljenvall</a> on September 13, 2012</div><div class="thread-post-content">Hi Richard,
