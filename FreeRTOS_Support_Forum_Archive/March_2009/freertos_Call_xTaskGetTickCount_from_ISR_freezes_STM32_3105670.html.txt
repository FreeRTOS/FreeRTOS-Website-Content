  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Call xTaskGetTickCount from ISR freezes STM32</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/tmech">tmech</a> on March 15, 2009</div><div class="thread-post-content">I am using STM32 w/ FreeRTOS 5.1.2
When I call xTaskGetTickCount&#40;&#41; from an ISR &#40;specifically EXTI0&#41;, the application freezes up.
The solution was to remove the taskENTER&#95;CRITICAL&#40;&#41;; and taskEXIT&#95;CRITICAL&#40;&#41;; calls from the xTaskGetTickCount&#40;&#41; function, these are not needed on 32-bit anyway.
My suggestion for future versions is a &#35;IF to remove these calls on 32-bit architectures.
Todd
</div></div><div class="thread-post"><h3 class="thread-post-title">Call xTaskGetTickCount from ISR freezes STM32</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on March 16, 2009</div><div class="thread-post-content">See number 3 on the following page: http://www.freertos.org/FAQHelp.html
Version 5.2.0 has removed critical sections from a few places where they were not necessary, however the type used to hold the tick count is configurable so the critical section remains there.
It might be better to have a &quot;get tick count from isr&quot; function, or to just make the tick count accessible.
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">Call xTaskGetTickCount from ISR freezes STM32</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/tmech">tmech</a> on March 17, 2009</div><div class="thread-post-content">I agree that a &quot;get tick count from isr&quot; function would be beneficial. As an example, my application uses a hall sensor that measures RPM of a motor. Every rotation of the shaft generates a interrupt which measures the time since the last interrupt. I could imagine a few other situations were the &quot;get tick from isr&quot; would be helpful.
Hopefully this can be implemented in a future version.
Todd
</div></div><div class="thread-post"><h3 class="thread-post-title">Call xTaskGetTickCount from ISR freezes STM32</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/*anonymous">*anonymous</a> on March 19, 2009</div><div class="thread-post-content">Todd: in your case, I think you should use another timer in counter mode, maybe automatically triggered by the interrupt from the hall sensor.
The system tick will typically have a quite low frequency &#40;1ms&#41;, while you could easily get much more accurate information.
