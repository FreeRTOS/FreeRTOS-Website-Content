Please, help me and tell me answer for following questions:
1&#41;&nbsp;&nbsp;&nbsp; heap &#8211; what is it?? I though that is kind of stack :&#41;. It&#8217;s divided between all task &#40;each task has its own stac, but all the stacks are on heap&#41;, and it’s also used by queues and semaphores. 
2&#41;&nbsp;&nbsp;&nbsp; where is the heap?? I had though that heap is a part of normal stack so in linker script I should give enough space for stack. But I had no idea what kind of stack it should be &#40;User Mode, Supervisor Mode, maybe IRQ Mode??&#41; No I think that heap is kept in the “normal ram” &#40;bss&#95;section&#41; like a regular variable. Is it OK?
3&#41;&nbsp;&nbsp;&nbsp; Is freeRTOS using regular stack?? I think that it use “regular stack” but only in ISR and in kernel-function. It uses a supervisor mode’s stack ind IRQ mode’s stack &#40;sometimes FIQ&#41;. Tasks have their own stacks on heap and their don’t use the stack defined in bss&#95;sectrion in linker script. </div></div><div class="thread-post"><h3 class="thread-post-title">How the memory is menaged in ARM7?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on March 24, 2009</div><div class="thread-post-content">&gt; Please, help me and tell me answer for following questions:
&gt; 1&#41;&nbsp;&nbsp;&nbsp; heap &#8211; what is it?? I though that is kind of stack :&#41;. 
&gt; It&#8217;s divided between
&gt; all task &#40;each task has its own stac, but all the stacks are 
&gt; on heap&#41;, and it’s
&gt; also used by queues and semaphores.
That is right.&nbsp; The heap is the memory that malloc&#40;&#41; uses to allocate memory. In this case pvPortMalloc&#40;&#41; is used so you can implement the heap however you like.&nbsp; See http://www.freertos.org/a00111.html
&gt; of stack it should be &#40;User Mode, Supervisor Mode, maybe IRQ 
&gt; Mode??&#41; No I think
&gt; that heap is kept in the “normal ram” &#40;bss&#95;section&#41; like a 
&gt; regular variable.
&gt; Is it OK?
If you use heap&#95;1.c or heap&#95;2.c then the heap is just an array. Declared as a normal array variable.
main&#40;&#41; is called from Supervisor mode so you need a Supervisor stack &#40;the kernel also uses that stack&#41;. Tasks use system mode but their stack comes from the heap so you don&#8217;t have to allocate anything in the startup file for them. You will also need an IRQ stack for interrupts. No other stacks are required by the kernel, but your application may require other stacks &#40;FIQ for example&#41;.
&gt; 
&gt; 3&#41;&nbsp;&nbsp;&nbsp; Is freeRTOS using regular stack?? I think that it use 
&gt; “regular stack”
&gt; but only in ISR and in kernel-function. It uses a supervisor 
&gt; mode’s stack
&gt; ind IRQ mode’s stack &#40;sometimes FIQ&#41;. Tasks have their own 
&gt; stacks on heap
&gt; and their don’t use the stack defined in bss&#95;sectrion in 
&gt; linker script. It
&gt; means that stack size typically could be smaller than heap 
&gt; size. Is it OK??
The Supervisor mode stack only needs to be big enough for main&#40;&#41; to run, and taskYIELD&#40;&#41; to be called. It can normally be very small.
&gt; 
&gt; 4&#41;&nbsp;&nbsp;&nbsp; What does author mean when writing paragraph Stack 
&gt; Overflow Detection on
&gt; freertos.org site &#40;User Documentation  Configuration  Stack 
&gt; Overflow Detection&#41;?
&gt; I think that is about overflowing task’s specific stack which 
&gt; really is on
&gt; the heap, not in the regular stack. Is it true?
It is true that it is talking about the task stacks. The task starts are normal stacks, its just that they are allocated from the heap. They are the User/System mode stacks. The stack can be anywhere you point the stack pointer to.
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">How the memory is menaged in ARM7?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/konoppo">konoppo</a> on March 24, 2009</div><div class="thread-post-content">Thanks for great help :&#41;. Now I&#8217;m finally unterstand what&#8217;s going on ;&#41;&#8230;&nbsp; In 4&#41; when I say &quot;stack&quot; I have in mind the stack declared in the startup file ;&#41;&#8230; So the regular stac = stack declared in startup file, and stack which is located on heap &#8211; is not &quot;regular&quot; stack :&#41;.
This questions were so important for me because I use ethernet ram as a &quot;universal purpose ram&quot; in my project and I had to decide how to divide variables, heap and stack between two regions of RAM &#40;regular 8K RAM and 16K ethernet ram&#41;. Now I&#8217;m using a 8kB RAM for regular stack and variables, and 16kB Ethernet RAM for heap.
