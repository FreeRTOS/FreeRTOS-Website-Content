thanks
</div></div><div class="thread-post"><h3 class="thread-post-title">DHCP takes some time</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on May 16, 2019</div><div class="thread-post-content">WireShark would be useful, but I&#8217;m afraid you will only see the broadcast packets, and not the unicast between DHCP server and device.
You could try out the Windows demo and run it from your laptop: in that case you can see the complete DHCP negotiations.
Or if your device is able to send logging, you could enable debug logging in <code>FreeRTOSIPConfig.h</code>:
~~~
<h1>define ipconfigHAS<em>DEBUG</em>PRINTF   1</h1>
<h1>if( ipconfigHAS<em>DEBUG</em>PRINTF == 1 )</h1>
<pre><code>extern void uart_printf( const pcFormat, ... );
#define FreeRTOS_debug_printf(X)    uart_printf X
</code></pre>
<h1>endif</h1>
~~~
DHCP may last a while, but I think that 7 seconds is very long.

</div></div><div class="thread-post"><h3 class="thread-post-title">DHCP takes some time</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/eduardo1966">eduardo1966</a> on May 16, 2019</div><div class="thread-post-content">Apparently the Hirschamnn switches we are using take something like 380 seconds to perform an acknowledgement of a DHCP request!
