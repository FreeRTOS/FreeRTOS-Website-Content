  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">HardFault in PendSV_Handler when using FSL I2C FreeRTOS driver</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/aneedles">aneedles</a> on May 17, 2019</div><div class="thread-post-content">I am using developing on a MK66 custom board, using GCC in MCUXpresso (Eclipse), with  FreeRTOS Kernel V10.0.1.
I sucessfully utilized the FSL I2C driver to use the MCU peripheral and wanted to transition to a FreeRTOS non-blocking version. However, I am getting a HardFault seemingly upon a taskENTER_CRITICAL() call in xQueueSemaphoreTake. Using the &#8220;Debugging a ARM Cortex-M Hard Fault&#8221; method, I receive the core register values right as the HardFault occured as follows:
r0: 4294967260<br />
r1: 536872372<br />
r2: 536872368<br />
r3: 536891636<br />
r12: 0<br />
lr: 4294967289<br />
pc: 1110<br />
psr: 553672718  
At the address of 1110 (0x456) we are in the middle of PendSV_Handler as follows:
~~~
<blockquote>
  PendSV<em>Handler:
  00000440:   mrs     r0, PSP
  00000444:   isb     sy
  00000448:   ldr     r3, [pc, #84]   ; (0x4a0 &lt;PendSV</em>Handler+96>)
  0000044a:   ldr     r2, [r3, #0]
  0000044c:   tst.w   lr, #16
  00000450:   it      eq
  00000452:   vstmdbeq        r0!, {s16-s31}
  00000456:   stmdb   r0!, {r4, r5, r6, r7, r8, r9, r10, r11, lr}
  0000045a:   str     r0, [r2, #0]
  0000045c:   stmdb   sp!, {r0, r3}
  00000460:   mov.w   r0, #160        ; 0xa0
  00000464:   msr     BASEPRI, r0
  00000468:   dsb     sy
  0000046c:   isb     sy
  00000470:   bl      0x24a8 <vtaskswitchcontext>
  00000474:   mov.w   r0, #0
  00000478:   msr     BASEPRI, r0
  0000047c:   pop     {r0, r3}
  ~~~
</blockquote>
I&#8217;m lost in what to really do with this information. Basically, I am able to pass through the kENTER<em>CRITICAL() one time, observe I2C operation, but the the second entering of kENTER</em>CRITICAL() HardFaults.
</div></div><div class="thread-post"><h3 class="thread-post-title">HardFault in PendSV_Handler when using FSL I2C FreeRTOS driver</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on May 18, 2019</div><div class="thread-post-content">Is taskENTER_CRITICAL() getting called from an interrupt service
routine?  That would happen if you call a FreeRTOS API function from the
routine.  If you have configASSERT() defined then it should hit the
assert as you need to use the interrupt safe alternatives to the macros.
 If you are still stuck then please post the ISR code too.
