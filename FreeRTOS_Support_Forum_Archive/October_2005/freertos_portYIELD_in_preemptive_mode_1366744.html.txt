  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">portYIELD() in preemptive mode</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/imajeff">imajeff</a> on October 12, 2005</div><div class="thread-post-content">I&#8217;m trying to work out some functions on a board with a port to GCC/HCS12 that is not proven yet. I have been successful with two tasks on different priority, who toggle an LED using vTaskDelay&#40;&#41;. I&#8217;ve tested this with either portYIELD&#40;&#41; or preemptive mode. It was working after my message
at 2005-08-05 16:35
Now I am apparently stuck on using vApplicationIdleHook&#40;&#41;, which may not be execuding, and don&#8217;t know if I&#8217;m using portYIELD&#40;&#41; properly.
I use preemptive mode. In a task, priority 1, I have these lines
.&nbsp;&nbsp;&nbsp; while &#40;&#33;&#40;SCISR1 &amp; RDRF&#41;&#41;
.&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; portYIELD&#40;&#41;;
&nbsp; I think this is supposed to mean that on every kernel tick, it would check for the flag above &#40;because it&#8217;s the highest priority&#41;, and then if not flag it would execute the idle hook for the rest of the tick period.&nbsp; Am I wrong? I don&#8217;t ever see the output I coded in the idle hook.
</div></div><div class="thread-post"><h3 class="thread-post-title">portYIELD() in preemptive mode</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on October 12, 2005</div><div class="thread-post-content">portYIELD&#40;&#41; forces a context switch, but if the task calling yield is the highest priority task in the system it will run again immediately as you have not asked it to block, therefore the idle task will never execute.&nbsp; Try using vTaskDelay&#40;1&#41; instead.&nbsp; This will block the calling task until the next tick.
</div></div><div class="thread-post"><h3 class="thread-post-title">portYIELD() in preemptive mode</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/imajeff">imajeff</a> on October 12, 2005</div><div class="thread-post-content">Yeah, thanks.&nbsp; I guess Yield only has a use in the same-priority group &#40;and cooperative mode&#41;.
Someday I hope I can follow this scheduler implementation. Funny, having no background in task swapping, I thought it would be more complex than it is. I&#8217;m not the type to rely on school or books, so it has been a challenge getting started.
