  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Cannot allow Idle task to block?</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/imajeff">imajeff</a> on October 13, 2005</div><div class="thread-post-content">If I recall correctly, I must not put code in vApplicationIdleHook&#40;&#41; which might block, because there is no lower priority task to execute.
I did not realize until now that means I probably should not use xSemaphoreTake&#40;&#41; with a time greater than 0. Can I use 0? Or maybe in the implementation, it is ok to use a higher block time. Docs say the reason IdleTask should not block is because there must always be a task ready to run. What if xSemaphoreTake only blocks while a higher priority is using the same resource?
</div></div><div class="thread-post"><h3 class="thread-post-title">Cannot allow Idle task to block?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on October 14, 2005</div><div class="thread-post-content">The idle task is the low power task &#8211; if you wish it to be &#8211; by using it to place the processor into power save mode.
Using 0 for the block time should be fine, as the task will remain in a ready state.
Using none 0 would be ok provided you can guarantee that there is always at least one task that is able to run &#8211; which I think would be difficult to guarantee in most applications.
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">Cannot allow Idle task to block?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/imajeff">imajeff</a> on October 14, 2005</div><div class="thread-post-content">Ok, it seems to work. The reason I could block IdleTask on the specific semaphore is because the highest priority task is the other one that takes it. Since that task does not block while having the semaphore, then it will only block after the semaphore is returned, at wich time IdleTask would be readied.
Or is there a flaw in that logic?
</div></div><div class="thread-post"><h3 class="thread-post-title">Cannot allow Idle task to block?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on October 14, 2005</div><div class="thread-post-content">Seems to make sense &#8211; should work fine.&nbsp; Give it a go.
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">Cannot allow Idle task to block?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/imajeff">imajeff</a> on October 14, 2005</div><div class="thread-post-content">I just realized that increasing from 0 would not serve any purpose, as IdleTask would never begin executing while the higher priority was still executing.
So with this design I don&#8217;t even need IdleTask to check the semaphore&#33;
