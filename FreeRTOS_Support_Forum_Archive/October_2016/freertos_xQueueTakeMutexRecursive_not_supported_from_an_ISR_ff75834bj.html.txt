  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">xQueueTakeMutexRecursive not supported from an ISR</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/jon-gordon">jon-gordon</a> on October 13, 2016</div><div class="thread-post-content">Using Tracealyzer for FreeRTOS, I&#8217;m trying to call a vTracePrintF from inside an ISR.
The code works fine for non-ISR and I see my event printed but inside the ISR, I end up with an assert failure because in xQueueTakeMutexRecursive, there is a call to xQueueGenericReceive without checking whether the &#8220;fromISR&#8221; alternative should be called instead.
Is this an oversight or am I missing something?
Cheers,
Jon
</div></div><div class="thread-post"><h3 class="thread-post-title">xQueueTakeMutexRecursive not supported from an ISR</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/edwards3">edwards3</a> on October 13, 2016</div><div class="thread-post-content">The trace recorder is source code so you can edit the code to check if you are in an interrupt, but also check if vTracePrintF is ok to call from an interrupt. You would not normally want to call the library printf() from there because its slow, stack heavy and not reentrant.
</div></div><div class="thread-post"><h3 class="thread-post-title">xQueueTakeMutexRecursive not supported from an ISR</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on October 13, 2016</div><div class="thread-post-content">Generally it doesn&#8217;t make sense to use a mutex in an ISR, as the ISR has no way to &#8216;wait&#8217; for the shared resource to become available.
As MEdwards said, &#8216;printing&#8217; something in a ISR is almost certainly a bad idea, 
</div></div><div class="thread-post"><h3 class="thread-post-title">xQueueTakeMutexRecursive not supported from an ISR</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/jon-gordon">jon-gordon</a> on October 17, 2016</div><div class="thread-post-content">I had figured it was using its own derived version of a printf routine but alas, no, it uses my compiler&#8217;s version which attempts to be thread safe by using a mutex &#8211; hence the problem.
I&#8217;ll stick to SEGGER&#8217;s RTT for printing in an ISR then.  Would just have been nice to have the interrupt behaviour observed in Tracealyzer but I must be missing something else there.
