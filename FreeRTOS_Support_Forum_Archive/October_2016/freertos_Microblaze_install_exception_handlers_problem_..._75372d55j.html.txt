  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Microblaze install exception handlers problem &#8230;</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/debugasm">debugasm</a> on October 20, 2016</div><div class="thread-post-content">I&#8217;m using freeRTOS for a quick test. I&#8217;m going to use the functionality 
of &#8220;EXCEPTION_HANDLERS&#8221; on Microblaze CPU.
I created the MicroBlaze CPU with these settings for &#8220;exceptions&#8221;:
~~~
PARAMETER C<em>M</em>AXI<em>I</em>BUS<em>EXCEPTION = 1
PARAMETER C</em>M<em>AXI</em>D<em>BUS</em>EXCEPTION = 1
PARAMETER C<em>ILL</em>OPCODE<em>EXCEPTION = 1
PARAMETER C</em>OPCODE<em>0x0</em>ILLEGAL = 1
PARAMETER C<em>USE</em>STACK<em>PROTECTION = 1
PARAMETER C</em>UNALIGNED<em>EXCEPTIONS = 1
PARAMETER C</em>PVR = 2
~~~
I compiled the BSP in Eclipse activating exceptions:
~~~
PARAMETER MICROBLAZE_EXCEPTIONS = true
~~~
In &#8220;FreeRTOSConfig.h&#8221; I have activate installation of exception handling:
~~~
<h1>define configINSTALL<em>EXCEPTION</em>HANDLERS 1</h1>
~~~
The compilation is successful.
The system works, I blink two LEDs with two separate tasks, using a 
third task where the serial run I try to start a routine that triggers 
an exception:
~~~
&#8230;
unsigned crash<em>instructions[10];
typedef void (*crash</em>instructions_t) (void);
crash<em>instructions</em>t crash<em>instructions</em>p;
crash<em>instructions[0] = 0;
crash</em>instructions[1] = 1;
crash<em>instructions[2] = 2;
crash</em>instructions[3] = 3;
crash<em>instructions</em>p = (crash<em>instructions</em>t) crash<em>instructions;
(*crash</em>instructions_p)();
&#8230;
~~~
I put a breakpoint at 0x20 &#8220;vectorhwexception&#8221; and one on the 
&#8220;vPortExceptionHandle&#8221; function.
Once I triggered the exception I have the first break at 0x20 
&#8220;vectorhwexception&#8221;, but once again given the &#8220;run&#8221; the 
&#8220;VPortExceptionHandle&#8221; function is never called, and debugging ends.
Performing &#8220;vectorhwexception&#8221; step by step, I notice that the execution 
is always crashes here:
~~~
        &#8230;
        ori     r6, r0, 7;
        cmp     r6, r5, r6;
        bgti    r6, handle<em>other</em>ex_tail;
        ori     r5, r0, 0x7; 
handle<em>other</em>ex<em>tail:<br />
        PUSH</em>REG(7);            &lt;&lt;&lt;&lt;&lt; block on this instruction
        PUSH<em>REG(8);<br />
        PUSH</em>REG(9);<br />
        PUSH<em>REG(10);<br />
        PUSH</em>REG(11);<br />
        PUSH<em>REG(12);
        PUSH</em>REG(15);
        PUSH_REG(18);<br />
        &#8230;
~~~
I had a look to the example supplied with freeRTOS: &#8220;MicroBlaze<em>Kintex7</em>EthernetLite&#8221;
but not well-known differences, excluding exception of FP and DIV.
What could it be ?
debugasm
</div></div><div class="thread-post"><h3 class="thread-post-title">Microblaze install exception handlers problem &#8230;</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on October 20, 2016</div><div class="thread-post-content">I&#8217;m afraid this is a little detailed as the device is so configurable, 
so my comments here are suggestions to look for, rather than absolutes.
The instruction you say is causing the issue is pushing a register so:
If a separate exception stack is being used (can&#8217;t recall without 
digging out the hardware manual), is the stack defined and set up correctly?
If certain stack alignment is required, could it be that the alignment 
is not being maintained, and the exception is itself causing an exception?
