Have you already started using <a href="http://www.freertos.org/FreeRTOS-Plus/FreeRTOS_Plus_TCP/index.html">FreeRTOS+TCP</a>? That library can also be used for UDP-only applications.
I&#8217;m not sure how things worked in the earlier UDP-only version. The same, but a little different sometimes.
The following:
~~~~
    /* The EMAC now owns the buffer. */
    pxNetworkBuffer->pucEthernetBuffer = NULL;
~~~~
can only be done in case the buffer space will be released (freed) after the data have been sent.
When <code>vNetworkBufferRelease()</code> will be called, <code>pucEthernetBuffer</code> will be NULL, and <code>vPortFree()</code> will ignore the NULL pointer. But who will finally release the <code>pucEthernetBuffer</code>?
Normally a TX-completion interrupt would follow after sending. That would wake-up the <code>prvEMACHandlerTask()</code> function, which will check all DMA TX descriptors.
You can have a look at this <a href="https://sourceforge.net/p/freertos/discussion/382005/thread/39bcfcfb/?limit=25#3ee0">zero-copy STM32F4 driver</a>.
It transfers the ownership of the <code>pxNetworkBuffer</code> to DMA. An interrupt follows, and <code>vClearTXBuffers()</code> will be called. It will take the following steps:
~~~~
    /* Get the payload buffer. */
    ucPayLoad = ( uint8_t * )DMATxDescToClear->Buffer1Addr;
