  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">vApplicationIdleHook in a C++ application</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/stanislaus123">stanislaus123</a> on January 5, 2018</div><div class="thread-post-content">I am using ZYNQ on a MicroZed 
My application is defined as a C++ application !
Below is the absolute minimum program
void vApplicationIdleHook( void );
void MyTask(void* param)
{
    for(;;){
        print(&#8220;blah blahn&#8221;);
        vTaskDelay(100);
    }
}
void vApplicationIdleHook( void )
{
int i=0;
    for(;;){
        i++;    //In my application will never be called
}
int main()
{
    xTaskCreate( MyTask, &#8220;MyTask&#8221;, 1024, NULL, 2, NULL);
    vTaskStartScheduler();
    for(;;)
    return 0;
}
FreeRTOS provides an idle task function called 
void vApplicationIdleHook( void ) <strong>attribute</strong>((weak));        //in portZynq7000.c
To enable the idle function you must
define configUSE<em>IDLE</em>HOOK 1                        //in FreeRTOSConfig.h
Since the idle hook function is declared as &#8220;weak&#8221;, I should be able to override
it inside my own application simply by declaring and defining it again like usual
This works just fine in C and the linker will give me NO error, but it does not work when the main application was created as a C++ application like    main.cc   The overridden function will not be called, but instead the weak function in    portZynq7000.c   will be called.
Does anybody know a simple trick to make this work in a simple manner?
Thanks
Kurt
</div></div><div class="thread-post"><h3 class="thread-post-title">vApplicationIdleHook in a C++ application</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on January 5, 2018</div><div class="thread-post-content"><blockquote>
  Does anybody know a simple trick to make this work in a simple manner?
</blockquote>
No, I don&#8217;t, but sure the C++ folks here will have a more knowledgeable 
answer&#8230;.that said, is portZynq7000.c being compiled as C or C++?  If 
it were compiled as C, or extern &#8220;C&#8221; were used, then maybe it would work?
</div></div><div class="thread-post"><h3 class="thread-post-title">vApplicationIdleHook in a C++ application</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on January 5, 2018</div><div class="thread-post-content">For FreeRTOS callback functions yoou need to define them something like:
extern &#8220;C&#8221; {
void vApplicationIdleHook( void );
}
To force name mangling off for the function. You can either include the full defintion of the function inside the extern &#8220;C&#8221; block or just a forward decleration.
