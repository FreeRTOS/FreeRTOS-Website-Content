</div></div><div class="thread-post"><h3 class="thread-post-title">SysTick Timer ARM Cortex M0 and configTICK_RATE_HZ</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on January 20, 2018</div><div class="thread-post-content">The SysTick timer is intended for use by an RTOS. It normally runs at the same frequency as the core. Set configCPU<em>CLOCK</em>HZ to the frequency the core will be executing at, then configTICK<em>RATE</em>HZ to the rate at which you want the RTOS tick interrupt to execute at, and the RTOS will setup the SysTick timer for you when the scheduler is started.
Typing on my phone so I can’t give you the links, but the config parameters are documented on the FreeRTOS.org website, where you will also find a free to download (if a little out of date) book.
</div></div><div class="thread-post"><h3 class="thread-post-title">SysTick Timer ARM Cortex M0 and configTICK_RATE_HZ</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on January 21, 2018</div><div class="thread-post-content"><a href="https://sourceforge.net/p/freertos/discussion/382005/thread/6ee2acb9/?limit=250#2622">Here</a> you can find a summary of the clocks in an STM32F.
The systick frequency is obtained by dividing the CPU clock frequency.
<blockquote>
  Is there any documentation, or could you provide any direction,
  on where you would look in the code to change the timer being used?
</blockquote>
It is possible, but why would you want to use a different timer for this?
You would have to make sure the the priorities are set correctly.
In most ports, the code for the <code>SysTick_handler()</code> is provided directly by the port itself (see <code>xPortSysTickHandler()</code> ).
But beware that the STM32F HAL drivers also wants to define a systick handler in a file called <code>stm32f4xx_it.c</code>:
~~~
void SysTick<em>Handler(void)
{
    /* USER CODE BEGIN SysTick</em>IRQn 0 */
<pre><code>/* USER CODE END SysTick_IRQn 0 */
if( xTaskGetSchedulerState() != taskSCHEDULER_NOT_STARTED )
{
    xPortSysTickHandler();
}
HAL_IncTick();
/* USER CODE BEGIN SysTick_IRQn 1 */
/* USER CODE END SysTick_IRQn 1 */
</code></pre>
}
/* And defined in stm32f4xx_hal.c: */
__weak void HAL_IncTick(void)
{
    uwTick++;
}
__weak uint32<em>t HAL</em>GetTick(void)
{
    return uwTick;
}
~~~
<code>FreeRTOSConfig.h</code> will often have this comment:
~~~
/* IMPORTANT: This define MUST be commented when used with STM32Cube firmware,
              to prevent overwriting SysTick<em>Handler defined within STM32Cube HAL */
/* #define xPortSysTickHandler SysTick</em>Handler */
~~~
In my own projects, I tend to :
<ul>
<li>enable the above <code>#define</code></li>
<li>remove the HAL version of <code>SysTick_Handler()</code></li>
<li>provide my own version of <code>HAL_GetTick()</code>.</li>
</ul>
Note that a working <code>HAL_GetTick()</code> is important for some of the HAL drivers.
Therefore some drivers can only be started up once the systick interrupt is active.
Good luck!

In case you also want to use the systick, there is an application hook that you can use:
~~~
<h1>if ( configUSE<em>TICK</em>HOOK == 1 )</h1>
<pre><code>void vApplicationTickHook()
{
    /* This function will be called at a rate of "configTICK_RATE_HZ" */
}
</code></pre>
<h1>endif</h1>
~~~
If you want your handler to be called at a higher frequency, I would use some Time-Counter interrupt.
Remind that your ISR code is not supposed to call normal FreeRTOS API&#8217;s.  From an interrupt service routine, you should call functions that end with <code>FromISR()</code>.
When <code>configASSERT()</code> is defined, the NVIC priorities will be checked for. When the priorities are not OK, the program will be kept in an infinite loop in <code>vAssertCalled()</code>.
