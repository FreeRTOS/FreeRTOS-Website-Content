I am trying to implement a TCP MODBUS Server in FREERTOS (for STM32F7). I am using LWIP Sockets. When I use only one task, it works fine, but when I use more than one, the task that uses accept() and recv() gets blocked and I don&#8217;t know why&#8230; 
Could someone help me?
</div></div><div class="thread-post"><h3 class="thread-post-title">LWIP Sockets in Multithreading</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on December 13, 2018</div><div class="thread-post-content">It is hard to tell what goes wrong with so little information.
It is perfectly normal for <code>accept()</code> and <code>recv(</code>) to block for a certain time. This time-out can be configured with a call to <code>setsockopt()</code>.
When <code>accept()</code> never wakes up, it sounds like there is no incoming request to connect.
When <code>recv()</code> blocks for ever, apparently there is no incoming data.
Please keep in mind that your tasks run in a multi-tasking environment. Only one task be be active at a time, and so be aware that every task <strong>must</strong> block or sleep regularly. Could it be that you have a task that is just spinning and refuses to block ( yield )? 
</div></div><div class="thread-post"><h3 class="thread-post-title">LWIP Sockets in Multithreading</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on December 13, 2018</div><div class="thread-post-content">Hmm, there are many ways you could have done the integration so 
assistance is not that easy (this is after all a third party piece of 
software, not FreeRTOS, which is the subject of this forum).  Some time 
back I did a reference integration using the Windows simulator &#8211; that 
project is still available in the FreeRTOS Interactive site 
(http://interactive.freertos.org &#8211; under the non vendor specific 
category) although both FreeRTOS and lwIP have moved on a long way since 
then.  As I recall, at that time (maybe still, don&#8217;t know), lwIP was 
only thread safe if you used its sockets API.  Also, from memory, one of 
the key factors was how you handled memory allocation for packets 
received in interrupts &#8211; best to defer the memory allocation to the task 
level (but then lwIP also has many memory allocation schemes).  I&#8217;m 
afraid that is about as much as I can do&#8230;

</div></div><div class="thread-post"><h3 class="thread-post-title">LWIP Sockets in Multithreading</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on December 14, 2018</div><div class="thread-post-content">Hi Victor, Richard has already tried to explain that lwIP is third-party software, and we can not give support on it. lwIP also has a forum which is actively monitored by some great engineers.
Maybe you want to have a look at our FreeRTOS+TCP library. It is an alternative for lwIP. It is well integrated with the FreeRTOS kernel ( 8.0 or higer ).
You can find information on <a href="https://freertos.org/FreeRTOS-Plus/FreeRTOS_Plus_TCP/index.html">freertos.org/tcp</a> and you can download the latest source code from <a href="https://github.com/aws/amazon-freertos">github</a>.
If you have questions about FreeRTOS+TCP, we&#8217;re happy to answer them on this forum.

It sounds like you&#8217;re doing something basically wrong: a second task doesn&#8217;t seem to yield ( block, sleep ). That task prevents the other task from becoming active.
