  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Fails to link on arm-none-eabi-gcc 8.2.0 with -flto (CM4F)</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/philip-karlsson">philip-karlsson</a> on December 21, 2018</div><div class="thread-post-content">Hi, we have recently tried to update our compiler at work but we are having some difficulties with getting the project to link. It appears that the ldr:s in <strong>source/portable/GCC/ARM_CM4F/port.c</strong>
~~~
static void prvPortStartFirstTask( void )
{
__asm volatile(
  &#8221; ldr r0, =0xE000ED08 n&#8221; /* Use the NVIC offset register to locate the stack. <em>/
  &#8221; ldr r0, [r0] n&#8221;
  &#8221; ldr r0, [r0] n&#8221;
  &#8221; msr msp, r0 n&#8221; /</em> Set the msp back to the start of the stack. <em>/
  &#8221; cpsie i n&#8221; /</em> Globally enable interrupts. <em>/
  &#8221; cpsie f n&#8221;
  &#8221; dsb n&#8221;
  &#8221; isb n&#8221;
  &#8221; svc 0 n&#8221; /</em> System call to start first task. */
  &#8221; nop n&#8221;);
}
and
static void vPortEnableVFP( void )
{
__asm volatile (
  &#8221; ldr.w r0, =0xE000ED88 n&#8221; /* The FPU enable bits are in the CPACR. <em>/
  &#8221; ldr r1, [r0] n&#8221;
  &#8221; n&#8221;
  &#8221; orr r1, r1, #( 0xf &lt;&lt; 20 ) n&#8221; /</em> Enable CP10 and CP11 coprocessors, then save back. */
  &#8221; str r1, [r0] n&#8221;
  &#8221; bx r14 &#8220;);
}
~~~
Gets a too long PC relative offset when building with -flto. For some reason the literal pool ends up too far away from the instruction.  I propose that .ltorg directives are placed at the end of each function in order to explicitly declare the literal pool straight after the epilogue:
~~~
static void prvPortStartFirstTask( void )
{
__asm volatile(
  &#8221; ldr r0, =0xE000ED08 n&#8221; /* Use the NVIC offset register to locate the stack. <em>/
  &#8221; ldr r0, [r0] n&#8221;
  &#8221; ldr r0, [r0] n&#8221;
  &#8221; msr msp, r0 n&#8221; /</em> Set the msp back to the start of the stack. <em>/
  &#8221; cpsie i n&#8221; /</em> Globally enable interrupts. <em>/
  &#8221; cpsie f n&#8221;
  &#8221; dsb n&#8221;
  &#8221; isb n&#8221;
  &#8221; svc 0 n&#8221; /</em> System call to start first task. <em>/
  &#8221; nop n&#8221;
  &#8221; .ltorg n&#8221;); /</em> Ensure a literal pool for the first ldr in range when using lto */
}
static void vPortEnableVFP( void )
{
__asm volatile (
  &#8221; ldr.w r0, =0xE000ED88 n&#8221; /* The FPU enable bits are in the CPACR. <em>/
  &#8221; ldr r1, [r0] n&#8221;
  &#8221; n&#8221;
  &#8221; orr r1, r1, #( 0xf &lt;&lt; 20 ) n&#8221; /</em> Enable CP10 and CP11 coprocessors, then save back. <em>/
  &#8221; str r1, [r0] n&#8221;
  &#8221; bx r14 n&#8221;
  &#8221; .ltorg &#8220;); /</em> Ensure a literal pool for the first ldr in range when using lto */
}
~~~
With these changes, the project links and when looking at the generated machine code the PC relative load is within ~20 bytes.
Kind regrads,
Philip
