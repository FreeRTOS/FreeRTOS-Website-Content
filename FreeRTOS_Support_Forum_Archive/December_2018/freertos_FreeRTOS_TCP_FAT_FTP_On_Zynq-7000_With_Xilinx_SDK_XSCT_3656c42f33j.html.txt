was chosen to avoid including the original &#8220;xemacpsif&#8221; files located in BSP directories.

One reoccurring difficulty is always drivers, where we are dependent on third-party software. The BSP files need changes for the drivers and at the same time the factories keep-on releasing new versions of BSP ( or HAL ) libraries&#8230; which may not be downward compatible.

<code>ipconfigNIC_N_RX_DESC</code> and <code>ipconfigNIC_N_TX_DESC</code> define the number of DMA descriptors for reception and transmission. These are used in the NetworkInterface.
<code>ipconfigNUM_NETWORK_BUFFER_DESCRIPTORS</code> defines to total number of network buffers. Note that with a zero-copy reception, <code>ipconfigNIC_N_RX_DESC</code> network buffers are being <strong>reserved</strong> for reception.
<code>ipconfigNIC_N_TX_DESC</code> is often much smaller: it doesn&#8217;t take long before queued packets are being sentso it needs a short queue ( +/- 4 should be enough ).

</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS+ TCP &#038; FAT FTP On Zynq-7000 With Xilinx SDK/XSCT</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on January 2, 2019</div><div class="thread-post-content"><code>xCheckLoopback()</code>: as many users asked for a loop-back mechanism, I added one.
<a href="https://sourceforge.net/p/freertos/discussion/382005/thread/760109c4/?limit=250#8a99">This</a> is the original post about it.
The function <code>xCheckLoopback()</code> will be called from <code>xNetworkInterfaceOutput()</code>. If the packet is targeted to the device it self ( matching with MAC-address ), the packet will be returned to the IP-task for processing. This simple mechanism works wonderfully well.
So for instance, you can create two TCP sockets and connect them to eachother by using the board&#8217;s IP address.
I&#8217;m attaching <code>xCheckLoopback.c</code> which you can use for modifying FreeRTOS_ARP.c
I hope that in the coming year, the loop-back mechanisme will make it to the main release. It would make testing easier.
Regarding the CLI : thanks for taking the effort to write this down. It may help other users.
