</div></div><div class="thread-post"><h3 class="thread-post-title">freeRTOS 9.0+ TCP/IP keepalive</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on January 22, 2017</div><div class="thread-post-content">Hi,
It sounds like a problem with compiling your project.
In the demo projects, <code>ipconfigTCP_KEEP_ALIVE_INTERVAL</code> is defined as 20 seconds. When you observe that the actual keep alive messages are sent every 20 seconds, it looks like <code>FreeRTOS_TCP_IP.c</code> doesn&#8217;t see your new value.
You should make the setting in your <code>FreeRTOSIPConfig.h</code>. Make sure that the include path for the compiler points to the proper <code>FreeRTOSIPConfig.h</code>.
Advice: never put private files into the public include directories, such as <code>FreeRTOS-Plus-TCP/include</code> or <code>FreeRTOS/source/include</code>.
You could write the following in your <code>FreeRTOSIPConfig.h</code>:
~~~~
    #warning setting keep-alive
    #define ipconfigTCP<em>KEEP</em>ALIVE_INTERVAL 120
~~~~
and make sure the the compilere sees the #warning 🙂

</div></div><div class="thread-post"><h3 class="thread-post-title">freeRTOS 9.0+ TCP/IP keepalive</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on January 23, 2017</div><div class="thread-post-content">Good, so changing the value of <code>ipconfigTCP_KEEP_ALIVE_INTERVAL</code> does make a difference.
What you observe is that the actual times are being rounded up to a multiple of 20 seconds.
That is caused by the function <code>prvTCPNextTimeout()</code>, which let&#8217;s the socket &#8216;sleep&#8217; for 20 seconds when it is idle.
If you want, I will prepare a patch in which this sleeping time will be configurable.
Regards.

</div></div><div class="thread-post"><h3 class="thread-post-title">freeRTOS 9.0+ TCP/IP keepalive</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on January 23, 2017</div><div class="thread-post-content">Normally I would set the keep-alive period <code>ìpconfigTCP_KEEP_ALIVE_INTERVAL</code> at least 60 seconds.  Only when a keep-alive message is not responded to (and <code>ucKeepRepCount</code> increases), the intervals will be much shorter. After three times now answer, the socket will be forcefully closed.
I have sent you an email with patched source code. If you test it we can make it an official change.
Note that for an embedded TCP application, the keep-alive messages are essential. It avoids that sockets stack in a connected state for hours, thus occupying valuable resources.
The keep-alive messages do not always work, some routers might refuse to pass them through.
