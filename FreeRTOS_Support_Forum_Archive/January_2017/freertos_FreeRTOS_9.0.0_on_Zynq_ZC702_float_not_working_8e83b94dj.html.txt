  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">FreeRTOS 9.0.0 on Zynq ZC702 float not working</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/ea4mz">ea4mz</a> on January 16, 2017</div><div class="thread-post-content">Hi,
Thanks for reading this. I am using FreeRTOS 9.0.0 on Zynq ZC702 and trying to implement a binary TCP server on port 7081. Using FreeRtos Labs 160919 and Xilinx SDK 2016.3
Everything goes fine, unless you try to assign a value to a float, then FreeRTOS crashes.
I have already set:
&#8220;#define configUSE<em>TASK</em>FPU_SUPPORT             2&#8243;, in FreeRTOSConfig.h
The code snippet that crashes FreeRTOS is:
static uint8<em>t counter;
float   UL1</em>RMS;
counter = 1;
&#8230;&#8230;..
UL1_RMS = (float)counter;
Is there anything more that should be configured in order to handle float values in a task?
Thanks in advance for your help.
Mo.
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS 9.0.0 on Zynq ZC702 float not working</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on January 16, 2017</div><div class="thread-post-content">Hi Mo,
Your post is a bit similar to <a href="https://sourceforge.net/p/freertos/discussion/382005/thread/0ee03454">this one</a>.
Can you try the same conversion somewhere in <code>main()</code>, just before calling <code>vTaskStartScheduler()</code>?  Will that also crash?
Does the problem also occur when using <code>double</code>?
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS 9.0.0 on Zynq ZC702 float not working</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on January 16, 2017</div><div class="thread-post-content">In addition &#8211; does this problem occur inside an interrupt?  There is a 
known issue with alignment for floats in V9.0.0.  If this is the case 
please either make the assignment outside of the ISR, or get back to me 
and I can let you know the fix.
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS 9.0.0 on Zynq ZC702 float not working</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/ea4mz">ea4mz</a> on January 17, 2017</div><div class="thread-post-content">Hi Hein and RTE,
Thank you very much for your answer, I will try to explain more in detail the problem:
The binary parser I am trying to implement on port 7081 is quite similar to the one implemented in FreeRTOS labs for the echo server:
<ul>
<li>There is a server listening for incomming connections to port 7081</li>
<li>When there is a new connection it spawns a task to handle it</li>
<li>The handler decodes the command and then answer back the data, result, etc.</li>
</ul>
There is not any interrupt involved in my code, unless the handling of sockets in FreeRTOS is interrupt driven???
Here is the structure I am filling with values inside the task that handle values:
typedef struct
{
    char    Ip0;                            // 1
    char    Ip1;                            // 2
    char    Ip2;                            // 3
    char    Ip3;                            // 4
&#8230;
<pre><code>float   UL1_RMS;
float   UL2_RMS;
float   UL3_RMS;
</code></pre>
&#8230;
} StandardInfo_t;
Then when you handle this inside the task:
<pre><code>uint8_t counter;
StandardInfo_t *StandardInfo_p;
</code></pre>
Assign and address to pointer:
<pre><code>StandardInfo_p = (StandardInfo_t *)FIRST_BYTE_ANSWER_PTR;   
</code></pre>
Then assing a value to the elements inside the structure:
<pre><code>counter = 1;
StandardInfo_p-&gt;Ip0   = (char)counter;
StandardInfo_p-&gt;Ip1   = (char)counter;
StandardInfo_p-&gt;Ip2   = (char)counter;
StandardInfo_p-&gt;Ip3   = (char)counter;
</code></pre>
Everything is OK until you start assigning a value to float, then it crashes:
<pre><code>StandardInfo_p-&gt;UL1_RMS = (float)counter;
StandardInfo_p-&gt;UL2_RMS = (float)counter;
StandardInfo_p-&gt;UL3_RMS = (float)counter;
</code></pre>
When using another commands that do not use floats everything is OK.
Thanks again for your help.
Regards,
Mo.
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS 9.0.0 on Zynq ZC702 float not working</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on January 17, 2017</div><div class="thread-post-content">What is the value of FIRST<em>BYTE</em>ANSWER_PTR?  It must be a value that 
results in your floating point variables within the structure being 
8-byte aligned.  I don&#8217;t think this is a FreeRTOS issue.
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS 9.0.0 on Zynq ZC702 float not working</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/ea4mz">ea4mz</a> on January 18, 2017</div><div class="thread-post-content">Thank you very much for your help, you are right.
That&#8217;s  the value of FIRST<em>BYTE</em>ANSWER_PTR where pucTxBuffer was allocated previously.
That resulted in floats not been 8-byte aligned:
~~~
<h1>define SIZE<em>OF</em>HEADER                  4</h1>
<h1>define SIZE<em>OF</em>ANSWER                  3</h1>
<h1>define FIRST<em>BYTE</em>ANSWER<em>PTR           ((uint8</em>t *)(pucTxBuffer + SIZE_OF_HEADER + SIZE_OF_ANSWER))</h1>
~~~
Thanks again, best regards,
Moises.
