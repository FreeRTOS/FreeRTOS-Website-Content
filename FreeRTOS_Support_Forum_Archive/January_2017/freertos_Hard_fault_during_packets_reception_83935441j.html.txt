</div></div><div class="thread-post"><h3 class="thread-post-title">Hard fault during packets reception</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on January 17, 2017</div><div class="thread-post-content">Hi Orit,
Hard-faults are a bit difficult to debug, but if you catch them properly, you must be able to see the values of all registers at the time of the fault. Two registers are interesting in particular: pc and lr.
These registers point to locations in the code: please open your LSS listing and look-up both addresses.
If an address is odd (e.g. 0x45029), look for the address minus 1 (0x45028).
If you really run out of ideas, you can write me at h point tibosch at freertos point org, and I&#8217;ll try to help you more in detail.

  0x00045800 0x00002000 Zero RW 450 STACK startup<em>CMSDK</em>CM3.o

The size of the heap &#8211; stack section is 128 KB. The heap starts at an offset of 150 KB.
<blockquote>
  On the other hand, according to the debugger the start addresses of tasks
  stack are: 0x00010DE8, 0x00011728, 0x00011B50, 0x000123C8. I don&#8217;t
  understand why they are not located in the STACK memory region.

The stack at 0x45800 will only be used <strong>at start-up</strong>. Once <code>vTaskStartScheduler()</code> has been called, each task will have its own stack, allocated by heap_4.c
<blockquote>
  0x0001178c 0x00013880 Zero RW 1106 .bss heap_4.o
</blockquote>
You reserved 80,000 bytes of HEAP.
I suppose that &#8220;HEAP startup<em>CMSDK</em>CM3&#8243; is the system heap, which is unused? If it is unused, you might want to increase your actual heap in <code>heap_4.c</code>.
Are you using <code>pvPortMalloc()</code> and <code>vPortFree()</code> in all cases, and not <code>malloc()</code> and <code>free()</code>?
What MCU are you using? Are the above memory addresses all located in valid RAM?
~~~~
<blockquote>
  lr = 0x0000031F
  pc = 0x41000000
  psr = 0xA5A5A5A5 
  ~~~~
</blockquote>
It looks like <code>lr</code> points to a RAM location. But it may also be rubbish.
And <code>pc = 0x41000000</code>, isn&#8217;t that a reset address?
Are you using BufferAllocation<em>1.c or BufferAllocation</em>2.c?
In case you use BufferAllocation<em>1.c, what does your <code>vNetworkInterfaceAllocateRAMToBuffers()</code> look like?
Note that BufferAllocation</em>1.c contains some useful debugging code, in case you define <code>ipconfigTCP_IP_SANITY = 1</code>.
If you want you can email all relevant source code to me and I will check it.
It will be something simple like calling <code>vReleaseNetworkBufferAndDescriptor()</code> once too often, or writing to memory that has been released already.
