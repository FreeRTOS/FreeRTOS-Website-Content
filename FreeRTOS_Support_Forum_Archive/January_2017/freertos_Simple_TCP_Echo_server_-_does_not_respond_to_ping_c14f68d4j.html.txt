Within &#8220;PING request.pcapng&#8221;, I see three gratuitous ARP requests, sent at an acceptable frequency of two per minute.
The ping command (e.g. ping 192.168.0.2) will always start with an ARP command. In you PCAP, the ARP commando isn&#8217;t answered by the device. 
As the device <strong>is</strong> sending gratuitous ARP requests, I would conclude that its RX path isn&#8217;t working properly.

</div></div><div class="thread-post"><h3 class="thread-post-title">Simple TCP Echo server &#8211; does not respond to ping</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on October 21, 2017</div><div class="thread-post-content">Hi Andrei, it looks like you have correctly defined <code>ipconfigPACKET_FILLER_SIZE</code> in your <code>FreeRTOSIPConfig.h</code> as follows:
<pre><code>#define ipconfigPACKET_FILLER_SIZE   2
</code></pre>
See a discussion about this padding here:
<a href="https://sourceforge.net/p/freertos/discussion/382005/thread/cc4d0b2a">FreeRTOS<em>TCP &#8211; zero copy &#8211; ipBUFFER</em>PADDING</a>
This means that any Ethernet packet (<code>pxDescriptor-&gt;pucEthernetBuffer</code>) will start at a (32-bit) aligned offset <strong>plus 2</strong>. The reason for this is that almost all 32-bit values in the IP and TCP/UDP packets will become 32-bit aligned.
But your CPU peripheral must know that you want packets to be written at a +2 byte offset. This is done by setting:
~~~
    GMAC Network Configuration Register: GMAC_NCFGR
<pre><code>● RXBUFO: Receive Buffer Offset
Indicates the number of bytes by which the received data is
offset from the start of the receive buffer.
</code></pre>
~~~
You could set the offset like this:
~~~
    gmac<em>set</em>config(p<em>gmac,
        ( gmac</em>get<em>config(p</em>gmac) &amp; ~GMAC<em>NCFGR</em>RXBUFO<em>Msk ) |
          GMAC</em>NCFGR<em>RFCS |   /*  Remove FCS, frame check sequence (last 4 bytes) */
          GMAC</em>NCFGR<em>PEN |    /* Pause Enable */
          GMAC</em>NCFGR<em>RXBUFO( ipconfigPACKET</em>FILLER<em>SIZE ) | /* Set Ethernet Offset  */
          GMAC</em>RXD_RXCOEN );    /* RXCOEN related function */
~~~
For transmitting packets there should not be a problem: the contents of <code>pucEthernetBuffer</code> will be sent, which is already aligned with an offset of 2 bytes.
Please let me know if this helps. Hein
