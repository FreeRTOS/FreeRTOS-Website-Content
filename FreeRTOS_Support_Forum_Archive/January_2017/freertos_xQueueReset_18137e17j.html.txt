Can xQueueReset be used from within an ISR?
If not, which function should be used?
Thanks in advance.
</div></div><div class="thread-post"><h3 class="thread-post-title">xQueueReset</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on January 31, 2017</div><div class="thread-post-content">As you might have guessed, <code>xQueueReset()</code> doesn&#8217;t end with <code>fromISR</code> and it is not supposed to be called from an ISR.
I wouldn&#8217;t know a good reason to reset a queue from within an ISR.
All I ever do with a queue from within an interrupt is post a message, give to a semaphore, and always using the <code>fromISR</code> functions.
Can you explain why you would want to reset a queue ?
</div></div><div class="thread-post"><h3 class="thread-post-title">xQueueReset</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on January 31, 2017</div><div class="thread-post-content">Only functions that end if FromISR can be used in an ISR.
If you want to reset a queue from an interrupt then one option would be 
to create a function that wraps the xQueueReset() API, and pend the 
function from the ISR.  Be aware that the queue won&#8217;t actually get reset 
until the ISR has exited though: 
http://www.freertos.org/xTimerPendFunctionCallFromISR.html
</div></div><div class="thread-post"><h3 class="thread-post-title">xQueueReset</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/jalegre2003">jalegre2003</a> on January 31, 2017</div><div class="thread-post-content">I&#8217;m making a kind of simple SPI <--> UART bridge.
Through SPI commands I am able to configure, write, read&#8230; the UART ports.
For example, I use a queue to hold the bytes received from the UART side.
In the SPI side, when a RECEIVE<em>UART</em>CHAR command is received, the SPI ISR takes one character out of that queue and resends it through SPI.
One of the possible commands is CLEAR_BUFFER, which, as expected, should empty/reset that queue.
A xQueueReset<strong>FromISR</strong> would perfectly do the work.
Any ideas?
Thanks.
</div></div><div class="thread-post"><h3 class="thread-post-title">xQueueReset</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on January 31, 2017</div><div class="thread-post-content">Something like the following should work, but note this is completely 
untested, not even compiled.
<pre>
BaseType_t xQueueResetFromISR( QueueHandle_t xQueue )
{
Queue_t * const pxQueue = ( Queue_t * ) xQueue;
UBaseType_t uxSavedInterruptStatus;
     configASSERT( pxQueue );
     uxSavedInterruptStatus = portSET_INTERRUPT_MASK_FROM_ISR();
     {
         pxQueue->pcTail = pxQueue->pcHead + ( pxQueue->uxLength * 
pxQueue->uxItemSize );
         pxQueue->uxMessagesWaiting = ( UBaseType_t ) 0U;
         pxQueue->pcWriteTo = pxQueue->pcHead;
         pxQueue->u.pcReadFrom = pxQueue->pcHead + ( ( pxQueue->uxLength 
- ( UBaseType_t ) 1U ) * pxQueue->uxItemSize );
         pxQueue->cRxLock = queueUNLOCKED;
         pxQueue->cTxLock = queueUNLOCKED;
         vListInitialise( &( pxQueue->xTasksWaitingToSend ) );
         vListInitialise( &( pxQueue->xTasksWaitingToReceive ) );
     }
     portCLEAR_INTERRUPT_MASK_FROM_ISR( uxSavedInterruptStatus );
}
</pre>
</div></div><div class="thread-post"><h3 class="thread-post-title">xQueueReset</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/jalegre2003">jalegre2003</a> on February 1, 2017</div><div class="thread-post-content">Thanks a lot!
I&#8217;ve tried that code and it compiles ok. It also seems that it works ok but, anyway, I&#8217;m going to use the pending mechanism option because I think it&#8217;s, for now, a safer option, until Real Time Engineers decide to release (I hope so) such a feature (xQueueResetFromISR).
Again, thanks for the provided solutions.
