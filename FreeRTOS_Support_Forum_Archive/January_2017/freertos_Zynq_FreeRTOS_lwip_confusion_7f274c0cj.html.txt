  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Zynq/FreeRTOS/lwip confusion</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/krbvroc1">krbvroc1</a> on January 18, 2017</div><div class="thread-post-content">I am trying to come up to speed with this environment and have confused myself.
I am using the FreeRTOS 8.2.3 and LWIP1.4.1 that comes with Vivado (came with my Zybo [Zynq 7010] trainer board).
lwip says to use the RAW API for high performance TCP which I want to do. I planned on running the lwip it its own thread. The lwip RAW API examples
show a simple mainloop design that would appear to chew up 100% CPU in a tight loop polling for packets to process. I would seem a better design to invoke the receiver 
from the DMA ISR (or use a task notification / semaphore) so it is interrupt / DMA driven.
It seems that in order to use the RAW API I have to define my lwip with NO_SYS even though I am running with FreeRTOS. (That is how vivado configured it). 
I understand I will need to limit my interaction with lwip to a single thread and use FreeRTOS to communicate with the thread.
The very first thing I notice is that lwip says to create its threads using a sys<em>thread</em>new() call. If I am reading the lwip/Xilinx library correctly, that appears to be a wrapper for pthread<em>create().
How is that going to work with FreeRTOS and using xTaskCreate()  and trying to communicate using a queue or task notify between the two. On the surface it doesn&#8217;t make sense and the whole thing is 
confusing. Or do I ignore the lwip docs and use xTaskCreate() for my single lwip task &#8212; perhaps sys</em>thread_new is only when using socket/netconn API. I really just want to let lwip run in a single task and interact
with that task via the FreeRTOS stuff described in the book like task notifications, event groups, etc.
</div></div><div class="thread-post"><h3 class="thread-post-title">Zynq/FreeRTOS/lwip confusion</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on January 18, 2017</div><div class="thread-post-content">Not an expert of lwIP, but it was not originally designed to run 
multi-threaded, so what you are saying is not a surprise.  We have run 
it that way too &#8211; so long as you only use the code from one thread it works.
Don&#8217;t ignore the lwIP docs.  You need to use a FreeRTOS port layer so 
sys<em>thread</em>new() calls xTaskCreate().  Xilinx have one, as do we, in 
fact if you use the SDK wizard to create a FreeRTOS project you have the 
option of adding lwIP into the mix too.  Alternatively the main FreeRTOS 
download has an lwIP example for the Zynq 
(http://www.freertos.org/RTOS-Xilinx-Zynq.html) and we have our own 
multi-threaded TCP running on the Zynq too: 
http://www.freertos.org/FreeRTOS-Plus/FreeRTOS<em>Plus</em>TCP/TCPIP<em>FAT</em>Examples<em>Xilinx</em>Zynq.html
</div></div><div class="thread-post"><h3 class="thread-post-title">Zynq/FreeRTOS/lwip confusion</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/krbvroc1">krbvroc1</a> on January 18, 2017</div><div class="thread-post-content">I guess this is why I am confused. I used the SDK to create a FreeRTOS project and I added in the lwip to the BSP settings and I generated the FreeRTOS hello world example that the SDK creates for me. So far that is all I have done and the examples passes.
I would think the Xilinx SDK would have handled this. But when I look at the lwipopt include file it has NO<em>SYS set (and there is no mention of OS</em>IS_FREERTOS). I would think both of those would need to be set for the FreeRTOS layer to be present that you mention. But then the lwip documentation talks about RAW API mode is for standalone without an OS. I got the impression that FreeRTOS port layer is only for the higher level socket/netconn API, not the RAW API. That is why I was thinking maybe for RAW API only I should use xTaskCreate() and run the lwip stuff in that task. Since it is single threaded it should not be creating or communicating with any other tasks.
I don&#8217;t know if I have the liberty to use the FreeRTOS+TCP and I know I need to support multiple (x3) netif.
</div></div><div class="thread-post"><h3 class="thread-post-title">Zynq/FreeRTOS/lwip confusion</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on January 19, 2017</div><div class="thread-post-content">If you decide to use lwIP, why not the latest <a href="http://savannah.nongnu.org/forum/forum.php?forum_id=8733">2.0.0 version</a> ?
FreeRTOS+TCP has recently been extended with the possibility to use multiple interfaces (NIC&#8217;s). That works well with IPv4 sockets. That version has not been released officially, but anyone is welcome to try out this beta release.
FreeRTOS+TCP is simple to use as it only offers a <strong>BSD socket interface and API&#8217;s</strong>. It does have optimisations like zero-copy <code>send()</code>/<code>recv()</code>.
