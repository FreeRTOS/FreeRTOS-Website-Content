  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">vsnprintf() problem with gcc+eclipse+LPC2214</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/the-moog">the-moog</a> on September 8, 2006</div><div class="thread-post-content">Hi,
I&#8217;m using vsnprintf&#40;&#41; to try to create a version of printf&#40;&#41; that will work with preemtive multi tasking &#8211; preventing output text being mixed up.
I am using the serial.c library distributed with the source, modified to support two serial ports and called with a new function that replaces printf&#40;&#41; using vsnprintf&#40;&#41; to format the text before being sent to vSerialPutString&#40;&#41;.&nbsp; A semaphore prevents the output texts from numerours tasks being mixed up.
The trouble is my code crashes with a memory access exception within the call to vsnprintf&#40;&#41;.
I&#8217;ve even tried it with const text and sprintf&#40;&#41; and it does the same.
Why would these functions not work when the RTOS is running, yet I can use them before the scheduler starts without a problem?
If I replace them with puts&#40;&#41; instead I get the format text as expected &#40;obviously via a different software route&#41;
Any suggestions of other tests I can do to isolate the problem which appears to be an interaction between FreeRTOS and libc or libgcc.
Cheers,
Jason.
</div></div><div class="thread-post"><h3 class="thread-post-title">vsnprintf() problem with gcc+eclipse+LPC2214</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on September 8, 2006</div><div class="thread-post-content">sprintf type functions in GCC are nutorios for using a LOT of stack.&nbsp; I suspect your problem is just a stack overflow.
Take a look at the LPC2148 CrossFire demo in the freertos download.&nbsp; This uses a task to control printing &#8211; if any other task wants to print it sends the text to print to the printer task.&nbsp; The printer task is the only task that is allowed to access the IO.
</div></div><div class="thread-post"><h3 class="thread-post-title">vsnprintf() problem with gcc+eclipse+LPC2214</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on September 11, 2006</div><div class="thread-post-content">Hi,
No worries, fixed it.&nbsp;&nbsp; The new printf function is being called from many tasks.&nbsp; Some of these tasks had a too small size stack, causing the stack to become corrupted.
Pity the RTOS does not have stack checking as standard.&nbsp;&nbsp; I have noticed that others have done a patch that implements this, I&#8217;ll take a look at it.
j.
