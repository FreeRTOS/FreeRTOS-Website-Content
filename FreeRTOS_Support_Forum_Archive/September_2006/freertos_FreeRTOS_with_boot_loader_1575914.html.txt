  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">FreeRTOS with boot loader</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on September 19, 2006</div><div class="thread-post-content">I want to start my initialisation with a bootloader, witch gave me the opportunity for updating the RTOS.
Also should it be possible to jump from the RTOS back to the bootloader to update the OS.
The first point should be no problem.
But I have no idea, how it is to update while running.
Could it work like this:
&#45; stop all running tasks 
&#45; jump to bootloader
&#45; overwrite the RTOS
&#45; &#40;software reset&#41; restart the system
?
Is it enough to stop all running tasks or must there be done more?
Is this the way it will work?
Have you some experiences with updating a FreeRTOS?
Are there some examples?
Thanks for Your Answer,
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS with boot loader</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on September 19, 2006</div><div class="thread-post-content">The x86 ports implement the end scheduler function as these ports are booted from DOS &#8211; and therefore can return to DOS when the scheduler ends.&nbsp; Generally with other ports I have not bothered to implement the end scheduler function as there is nowhere for the execution to return to.&nbsp; You could have a look at the x86 ports to see what these do, but I think this would be overkill for your needs &#8211; really all you want to do is stop the scheduler running then reset the system.&nbsp; Resetting the processor will ensure the scheduler starts up in a consistent initialised state, so you don&#8217;t need to do this manually.
To stop the scheduler you need to stop the tick interrupt.&nbsp; This can be done by halting the timer used to generate the tick.&nbsp; Alternatively you can disable interrupts &#40;but this might effect your ability to reprogram the flash&#41; or call vTaskSuspendAll&#40;&#41; without calling vTaskResumeAll&#40;&#41;.&nbsp; This last option would not stop the tick interrupt, but it would prevent the tick interrupt from attempting to switch task contexts.
Regards.
