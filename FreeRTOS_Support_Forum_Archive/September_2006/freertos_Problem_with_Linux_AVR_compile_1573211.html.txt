</div></div><div class="thread-post"><h3 class="thread-post-title">Problem with Linux AVR compile</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on September 17, 2006</div><div class="thread-post-content">The ports are only tested on Windows, so normally compilation problems on Linux are attributed to incorrect case of incorrect direction of / within either the makefile of &#35;include&#8217;s.&nbsp; In this case it appears it is because you are using a different version of AVR GCC.
Check you are actually using avr-gcc, and not accidentally picking up a different version of GCC from somewhere in your path.
When I type gcc &#8211;version I get:
avr-gcc &#40;GCC&#41; 3.4.6

Thanks&#33;

</div></div><div class="thread-post"><h3 class="thread-post-title">Problem with Linux AVR compile</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on September 18, 2006</div><div class="thread-post-content">I think not all AVR GCC versions use signals in the same way.&nbsp; Some features were deprecated and FreeRTOS updated accordingly.&nbsp; I should try updating to the latest AVR GCC version and see if that helps, or at least if the messages change.
