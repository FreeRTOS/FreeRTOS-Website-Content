  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Cygnal port optimisation.</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on September 18, 2006</div><div class="thread-post-content">&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; On the Cygnal port page:&quot;Currently the task context is pushed onto the stack and the stack then copied to XRAM before checking to see if a higher priority task is ready to run. This could be modified so the context is pushed onto the stack, but the stack only copied to XRAM if necessary. If no context switch is required the original task would just pop its context off the stack and continue. This change would make the code very 8051 specific &#40;which is why I have not done it&#41;.&quot;
&nbsp;&nbsp;&nbsp;&nbsp; Can anyone give me some suggestion how to do it?
&nbsp;&nbsp;&nbsp;&nbsp; Thanks,
</div></div><div class="thread-post"><h3 class="thread-post-title">Cygnal port optimisation.</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/adarkar9">adarkar9</a> on September 18, 2006</div><div class="thread-post-content">I don&#8217;t agree with the argument made on the Cygnal port page.&nbsp; I have performed the suggested optimization on the Keil Cygnal port that I am working on and it works quite nicely.&nbsp; I don&#8217;t agree with the 8051-specific argument because the modification only affects the port files.&nbsp; My port of vPortYield&#40;&#41; is in assembly because Keil&#8217;s C51 does not support the &#95;naked attribute, but I can give you the gist of my change in this untested back-port to C:
/&#42; A place to remember the task running before vTaskSwitchContext&#40;&#41;. &#42;/
static tskTCB &#42; pxOldTCB;
void vPortYield&#40; void &#41; &#95;naked
&#123;
&nbsp;&nbsp;&nbsp; /&#42; Save the execution context onto the stack. &#42;/
&nbsp;&nbsp;&nbsp; portSAVE&#95;CONTEXT&#40;&#41;;
&nbsp;&nbsp;&nbsp; /&#42; Remember what task was running before calling vTaskSwitchContext&#40;&#41;. &#42;/
&nbsp;&nbsp;&nbsp; pxOldTCB = pxCurrentTCB;
&nbsp;&nbsp;&nbsp; /&#42; Call the standard scheduler context switch function. &#42;/
&nbsp;&nbsp;&nbsp; vTaskSwitchContext&#40;&#41;;
&nbsp;&nbsp;&nbsp; /&#42; Only peform stack copy if a new task will be running. &#42;/
&nbsp;&nbsp;&nbsp; if&#40; pxOldTCB &#33;= pxCurrentTCB &#41;
&nbsp;&nbsp;&nbsp; &#123;
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; /&#42; Copy the entire stack to XRAM.&nbsp; This is necessary as the internal
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; RAM is only large enough to hold one stack, and we want one per task. &#42;/
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; portCOPY&#95;STACK&#95;TO&#95;XRAM&#40; pxOldTCB &#41;;
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; /&#42; Copy the stack of the task about to execute from XRAM into RAM. &#42;/
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; portCOPY&#95;XRAM&#95;TO&#95;STACK&#40; pxCurrentTCB &#41;;
&nbsp;&nbsp;&nbsp; &#125;
&nbsp;&nbsp;&nbsp; /&#42; Restore the context of the task from the stack. &#42;/
&nbsp;&nbsp;&nbsp; portRESTORE&#95;CONTEXT&#40;&#41;;
&#125;
The idea here is to compare the value of pxCurrentTCB before you execute vTaskSwitchContext&#40;&#41; with the value of pxCurrentTCB after you execute vTaskSwitchContext&#40;&#41;.&nbsp; You only have to perform the stack copy if these values are different.&nbsp; You must perform the same modification to vTimer2ISR&#40;&#41; as well.
The major modification outside of these functions is to change the macros that copy the stack to and from XRAM to accept as a parameter, the address of the TCB to use for the copy.&nbsp; Alternatively, you could modify portCOPY&#95;STACK&#95;TO&#95;XRAM&#40;&#41; to always work with pxOldTCB and portCOPY&#95;XRAM&#95;TO&#95;STACK&#40;&#41; to always work with pxCurrentTCB.&nbsp; My assembly port does the former because it makes the macros more generic.
Regards,
David Hawks
</div></div><div class="thread-post"><h3 class="thread-post-title">Cygnal port optimisation.</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/adarkar9">adarkar9</a> on September 18, 2006</div><div class="thread-post-content">Please note that my above post does have reentrancy problems.&nbsp; The use of statically-allocated memory &#40;for pxOldTCB&#41; makes vPortYield&#40;&#41; non-reentrant.&nbsp; As I said, this was an untested back-port to C of my assembly modification.&nbsp; The value of pxCurrentTCB should be pushed on the stack before calling vTaskSwitchContext&#40;&#41; and then popped off the stack into registers for the comparison after the call to vTaskSwitchContext&#40;&#41;.&nbsp; This is easily done is assembly, but perhaps not so easily done in C.
Regards,
David
