</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS Event groups</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on September 12, 2015</div><div class="thread-post-content">Hi Larry,
That is an interesting challenge!
It depends on the way in which Event Groups are being used by the Freescale SDK drivers. Some properties of the Event Groups are much more difficult to simulate than others.
Simplicity: the simulation of Event Groups would be easier if you have the following limitations:
<ul>
<li>event groups are not being accessed from an interrupt</li>
<li>there is one Taker ( a task constantly calling <code>xEventGroupWaitBits()</code> )</li>
<li>there are many Givers ( calling <code>xEventGroupSetBits()</code> ).</li>
</ul>
In that case, I would store the following information in a struct:
~~~~~
    typedef struct {
        /* The event bits. <em>/
        EventBits_t uxEventBits;
        /</em> Information about the waiting task. */
        QueueHandle_t xWaitQueue;
        EventBits_t uxBitsToWaitFor;
    } EventGroupInfo_t;
~~~~~
