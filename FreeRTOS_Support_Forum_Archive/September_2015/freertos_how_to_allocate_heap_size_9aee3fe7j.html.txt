</div></div><div class="thread-post"><h3 class="thread-post-title">how to allocate heap size</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on September 9, 2015</div><div class="thread-post-content">Hi Sudhakar,
All FreeRTOS demo project have a define <code>configMINIMAL_STACK_SIZE</code>. That should give enough space on the stack for a minimal task like blinking a LED (and some more).
Just start playing with it and see how much stack and heap is being used.
For instance, <code>uxTaskGetSystemState()</code> gives detailed information about each task, including a field called <code>usStackHighWaterMark</code>: the minimum amount of stack available.
While playing: make sure that the tasks have more than enough stack space. A shortage of stack often results in a crash which makes debugging extremely difficult.
Managing the HEAP is a bit easier. The modules <code>heap_4.c</code> and <code>heap_5.c</code> have a function <code>xPortGetMinimumEverFreeHeapSize()</code> which returns the lowest amount of HEAP available during a run.
Personally, when I have enough RAM, I&#8217;d rather assign more RAM to the stack than allocate items statically or on the heap.
Using stack has two advantages:
<ul>
<li>the allocation and deallocation are very fast, a decrement of SP (Stack Pointer register)</li>
<li>the same RAM space can be reused for many different purposes</li>
</ul>
Regards.

</div></div><div class="thread-post"><h3 class="thread-post-title">how to allocate heap size</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on September 10, 2015</div><div class="thread-post-content">Hi Sudhakar,
What compiler are you using?
Which module for memory allocation are you planning to use (<code>portableMemMangheap_x.c</code>) ?
You might want to read this recent post:
https://sourceforge.net/p/freertos/discussion/382005/thread/14fb7b28/?limit=25#b406
It is about the various heap allocation functions.
A stack size of N means that N registers can be pushed. In an ATmega644, a register is 16-bits wide, so a stack_size of 128 will cost 256 bytes.
Before you start the scheduler (<code>vTaskStartScheduler()</code>), you already have a stack. Have a look at where it is located and how big it is: you may want to reuse that SRAM space later on, once the scheduler is running.
Regards.

</div></div><div class="thread-post"><h3 class="thread-post-title">how to allocate heap size</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on September 10, 2015</div><div class="thread-post-content">You will have to configure <code>configTOTAL_HEAP_SIZE</code> in your <code>FreeRTOSConfig.h</code>.
How large should it be? Only <strong>you</strong> can tell. And if you don&#8217;t know how much heap you&#8217;ll need, just start playing with it.
Normally the heap gets &#8220;what is left over&#8221;. Your program will use the 4 KB of SRAM and 64 KB of flash in the following ways:
~~~~~
  section             size       addr
  .data               0xd4   0x800100 &lt;= SRAM
  .text             0x7afa        0x0 &lt;= flash
  .bss               0x520   0x8001d4 &lt;= SRAM
~~~~~
Here you find a clear explanation about the above sections:
<a href="http://mcuoneclipse.com/2013/04/14/text-data-and-bss-code-and-data-size-explained">text, data and bss: Code and Data Size&nbsp;Explained</a>
And further: the stack grows downwards, it is often declared at the top of the RAM memory. The heap is located right after the .data and .bss sections, just below the stack.
Once you have started the scheduler, the stacks will (normally) be located in the heap and the original stack space will be vacant.
So how big will you make <code>configTOTAL_HEAP_SIZE</code> ?
Sum the size of <code>.data</code>, <code>.bss</code> and your boot stack (128 x 2 = 256 bytes). Subtract this amount from the available 4KB and that is how much heap you can declare.
Regards.
Correction: the location of the <strong>default heap</strong> is between the <code>.data</code> / <code>.bss</code> segments and the stack.
When you use a FreeRTOS heap module (like heap_1.c), your heap space will be located in the .bss section.
