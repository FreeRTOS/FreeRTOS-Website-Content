  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">V8.2.2 Xilinx Repository Makefile Issues (Ubuntu)</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/razed11">razed11</a> on September 26, 2015</div><div class="thread-post-content">Hi,
I&#8217;m using Xilinx SDK 15.2 and there are some minor issues when using the repository to create a BSP on Linux.
First, CreateRepoDirectoryStructure.bat doesn&#8217;t work on Linux 🙂 but it&#8217;s easy enough to change .bat to .sh, replace copy with cp, and switch the direction of the slashes.
After including the repository and creating the BSP the build failed. It complains that arm-none-eabi-* commands do not exist. I noticed that Makefile, Makefile<em>dep, and makefile</em>ps7_cortexa9 contain the following.
~~~~
ARCH_PREFIX = arm-none-eabi
#
<h1>gnu tools for Makefile</h1>
#
CC = $(ARCH<em>PREFIX)-gcc
AS = arm-none-as
AR = $(ARCH</em>PREFIX)-ar
CP = cp
~~~~
I changed the ARCH<em>PREFIX and AS to use arm-xilinx-eabi and everything built but I have not yet linked and tried the application (I wanted to submit this before going home for the weekend). It&#8217;s been a while since I wrote a fancy makefile but I thought there was a way to inherit ARCH</em>PREFIX because it is passed explicitly as arm-xilinx.eabi to the top level make file.
Also the file *.s is created under src. I think this may be because there are no lower case .s files so the following expands to literally *.s on Linux. On windows it probably duplicates the files but I&#8217;m not sure.
~~~~
KERNEL<em>AR</em>OBJS = *.c *.S *.s
~~~~

When you have everything sorted out I can add a link to this post from the web page that describes how to use the BSP version to help other Linux users.
Note the makesfiles etc. are all generated by the Xilinx tools, which is predominently a Linux tool, although I only use it on Windows.  Could the mismatch in compiler names be due to a mismatch in SDK versions?
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">V8.2.2 Xilinx Repository Makefile Issues (Ubuntu)</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/razed11">razed11</a> on September 28, 2015</div><div class="thread-post-content">I believe I have this sorted out.
First, please find a shell script that is equivilent to the .bat script attached.
While Xilinx generates the makefiles it seems to simply copy the one included in the repository to BSP<em>DIRECTORY/ps7</em>cortexa9<em>1/libsrc/freertos822</em>xilinx<em>v1</em>0/src. Unlike the other libraries which simply have a single makefile called Makefile, Makefile<em>dep and Makefile</em>ps7_cortexa9 are also generated. These three makefiles have the same contents.
I made two changes to Makefile<em>ps7</em>cortexa9 which is the repository makefile.
I changed the AS definition to also use $(ARCH<em>PREFIX). The definition of ARCH</em>PREFIX is fine because it is indeed overridden by the definition passed at the command line (arm-xilinx-eabi).
~~~~
ARCH_PREFIX = arm-none-eabi
#
<h1>gnu tools for Makefile</h1>
#
CC = $(ARCH<em>PREFIX)-gcc
AS = $(ARCH</em>PREFIX)-as
AR = $(ARCH_PREFIX)-ar
~~~~
To correct the &#42;.s file that is created (literally a file named &#42;.s is created) I used  $(wildcard):
~~~~
KERNEL<em>AR</em>OBJS = $(wildcard *.c *.S *.s)
~~~~
I think these two changes will work for both Windows and Linux.
Finally &#8220;make clean&#8221; does not remove libfreertos.a. This is something that needs to be added to the root makefile. I&#8217;m not sure how to get that one fixed as I&#8217;ve found the Xilinx forum to be an unreliable place to post.
