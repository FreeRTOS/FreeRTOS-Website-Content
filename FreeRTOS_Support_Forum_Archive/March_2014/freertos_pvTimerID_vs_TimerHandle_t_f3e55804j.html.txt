  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">pvTimerID vs TimerHandle_t </h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/sagi2097">sagi2097</a> on March 14, 2014</div><div class="thread-post-content">Hello, I was wondering if having both TimerHandle_t and pvTimerID , has any special functionality , other than simplifying the way to refer/recognise a Timer. Maybe it is obvious and i am blind, but it seems to me that both are unique identifiers for the same Timer, so one could do all the functionality with just one of them.
Please enlighten my!
Alex
</div></div><div class="thread-post"><h3 class="thread-post-title">pvTimerID vs TimerHandle_t </h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on March 14, 2014</div><div class="thread-post-content">I&#8217;m not sure of the context in which you are asking your question.  TimerHandle_t is the type of variables used to point to timer handles, whereas presumably the pvTimerID you are referring to is the ID that is assigned to the timer.
If so, then the ID is assigned to the timer to allow the same callback function to be used by multiple timers.  When you are inside the callback function you can <a href="http://www.freertos.org/FreeRTOS-timers-pvTimerGetTimerID.html">query the timer&#8217;s ID</a> to see which time actually expired.
Look at the vTimerCallback() function in the example on the following page to see how this is done: http://www.freertos.org/FreeRTOS-timers-xTimerCreate.html
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">pvTimerID vs TimerHandle_t </h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/sagi2097">sagi2097</a> on March 14, 2014</div><div class="thread-post-content">I assume I understand what you tell me&#8230; or better that is what I already thought. But then wouldn&#8217;t it be equivalent to run through the array of saved TimerHandle<em>t s&#8217; and get my own ID from the array Index? In the example there is the following concept:
<c>
TimerHandle</em>t timers[5];
for(int i=0;i&lt;5;i++) timers[i]=xTimerCreate(..);
</c>
wouldn&#8217;t this allow me to recover the actual timer by running the array and comparing the handle?
Thank You 
Alex
</div></div><div class="thread-post"><h3 class="thread-post-title">pvTimerID vs TimerHandle_t </h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on March 14, 2014</div><div class="thread-post-content">Yes &#8211; that would be equally as valid.
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">pvTimerID vs TimerHandle_t </h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on March 15, 2014</div><div class="thread-post-content">The difference is that YOU get to control the pvTimerID value, so it can point directly to data you want/need the timer to use.
The TimerHandle_t on the other hand is an opaque pointer to the Timer Control block, so to use that to identify the timer requires doing a time wasting search through a list of timers, but is just what FreeRTOS needs to process the timer.
