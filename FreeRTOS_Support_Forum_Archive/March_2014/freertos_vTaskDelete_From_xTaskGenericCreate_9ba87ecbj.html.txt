  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">vTaskDelete From xTaskGenericCreate</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/l4n4">l4n4</a> on March 31, 2014</div><div class="thread-post-content">Since the current vTaskDelete is only called when the Idle Task is running, I encounter some cases when my system is too busy to let the idle task run &amp; do the clean-up. Currently I&#8217;m trying not to create/delete tasks too many times, but still hoping to add a way to handle it when it happens. I&#8217;m considering to add another call to vTaskDelete from xTaskGenericCreate. In this way, when the idle task have a chance to run, it still going to delete the task waiting for termination. But when the idle task has no chance, the next task create will do the actual clean-up. Any thoughts on this? Thanks.
</div></div><div class="thread-post"><h3 class="thread-post-title">vTaskDelete From xTaskGenericCreate</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on March 31, 2014</div><div class="thread-post-content">You could define a trace macro to insert the code you want into the task create function as follows (insert at the bottom of FreeRTOSConfig.h):
<pre><code>
#define traceTASK_CREATE( x ) while( uxTasksDeleted > 0 ) prvCheckTasksWaitingTermination()
</code></pre>
Note that would only be called after memory was allocated for the task being created.
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">vTaskDelete From xTaskGenericCreate</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/l4n4">l4n4</a> on March 31, 2014</div><div class="thread-post-content">Ok. Any specific reason why the deletion should be done after the memory is allocated for the new task? Because if the system has a very limited memory, it might be useful to do clean-up before any allocation. Thanks again.
</div></div><div class="thread-post"><h3 class="thread-post-title">vTaskDelete From xTaskGenericCreate</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on March 31, 2014</div><div class="thread-post-content">It does not have to be &#8211; that is just where the trace macro I suggested defining is called from.  Doing what you want using a trace macro just prevents you from having to edit the source files.
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">vTaskDelete From xTaskGenericCreate</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/tlafleur">tlafleur</a> on March 31, 2014</div><div class="thread-post-content">In general terms, limited memory system should build static task.  Ie: never delete a task.
