</div></div><div class="thread-post"><h3 class="thread-post-title">PIC24F configKERNEL_INTERRUPT_PRIORITY &#038;&#8230;</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on August 19, 2012</div><div class="thread-post-content">The kernel uses the configKERNEL&#95;INTERRUPT&#95;PRIORITY setting to mask interrupts under a certain priority in critical sections.&nbsp; Where this is done from C code the constant is used directly so nothing needs to change, but where this is done in assembly code the value used is hard coded &#40;although, as this is effectively GCC, it could probably be used in the asm code to&#41;.&nbsp; You will find the &#35;32 FreeRTOS/source/portable/MPLAB/portasm&#95;PIC24.S.  
I would however not recommend using a value other than 1 for configKERNEL&#95;INTERRUPT&#95;PRIORITY.&nbsp; It is normally best to have the kernel interrupts at the lowest possible interrupt priority as things can get conceptually awkward if interrupts are running below that priority.

</div></div><div class="thread-post"><h3 class="thread-post-title">PIC24F configKERNEL_INTERRUPT_PRIORITY &#038;&#8230;</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on August 20, 2012</div><div class="thread-post-content">Critical sections in tasks already mask interrupts up to configKERNEL&#95;INTERRUPT&#95;PRIORITY.&nbsp; If you raise configKERNEL&#95;INTERRUPT&#95;PRIORITY then you will need an equivalent critical section implementation that works from interrupts.&nbsp; The core FreeRTOS code includes macros called portSET&#95;INTERRUPT&#95;MASK&#95;FROM&#95;ISR&#40;&#41; and portCLEAR&#95;INTERRUPT&#95;MASK&#95;FROM&#95;ISR&#40;&#41; for this purpose &#8211; but these are &#42;not&#42; defined in the PIC24 port and just get &#35;defined to nothing.&nbsp; If you were to define them, then it might be ok to raise configKERNEL&#95;INTERRUPT&#95;PRIORITY &#8211; but I have not tried it.  
portSET&#95;INTERRUPT&#95;MASK&#95;FROM&#95;ISR&#40;&#41; needs to set the interrupt mask to configKERNEL&#95;INTERRUPT&#95;PRIORITY&#40;&#41;, then return the original mask value &#40;before it was raised&#41;.&nbsp; portCLEAR&#95;INTERRUPT&#95;MASK&#95;FROM&#95;ISR&#40;&#41; takes one parameter, which was the original interrupt mask value so it can restore it.&nbsp; You can see an example implementation in the PIC32 port layer &#8211; albeit for a different architecture.  
Hope this helps.  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">PIC24F configKERNEL_INTERRUPT_PRIORITY &#038;&#8230;</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/dnadler">dnadler</a> on August 21, 2012</div><div class="thread-post-content">OK, does the following all look correct ?  
PIC24F implements priority levels 1-7 &#40;7 is highest&#41;. It has unique interrupt vectors for many sources &#40;an interrupt vector is not typically shared; for example a single serial port has many vectors for RX, TX, etc&#41;. Each source&#8217;s interrupt priority is set individually in “IPC” registers. Setting a source&#8217;s IPC to 0 disables the interrupt. At a device Reset, all user interrupt IPC registers are initialized to priority level 4.  
The current operating priority level of the CPU is in the “IPL” &#40;interrupt priority level&#41; bits of the “SR” &#40;processor status&#41; register. The IPL is set when an interrupt is serviced, and restored when the SR is restored during the return-from-interrupt instruction. The IPL can be freely set as a means of controlling what interrupts will be serviced &#40;to implement a critical section for example&#41;. Setting IPL to 7 disables interrupts.  
Hence…  
<pre><code>// DRN: "FromISR" critical sections can be called from an ISR at lower
// DRN: priority than kernel (but may never be called from a priority
// DRN: higher than kernel, which could permit reentrancy). To prevent
// DRN: kernel reentrancy, mask: interrupts up through kernel priority.
#if configKERNEL_INTERRUPT_PRIORITY &gt; 1  // DRN: 1 is lowest PIC24F priority (7 is max)
  inline unsigned portBASE_TYPE __portSET_INTERRUPT_MASK_FROM_ISR(void) { // DRN
    unsigned portBASE_TYPE saved_IPL = _IPL; // DRN
    _IPL = configKERNEL_INTERRUPT_PRIORITY;  // DRN
    return saved_IPL;                        // DRN
  }                                          // DRN
  #define portSET_INTERRUPT_MASK_FROM_ISR() __portSET_INTERRUPT_MASK_FROM_ISR() // DRN
  #define portCLEAR_INTERRUPT_MASK_FROM_ISR( uxSavedStatusValue ) (_IPL = (uxSavedStatusValue) ) // DRN
#endif // DRN
</code></pre>
