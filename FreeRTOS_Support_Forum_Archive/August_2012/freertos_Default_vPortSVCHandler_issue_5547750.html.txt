The implementation of the vPortSVCHandler&#40;&#41; is simplely adding a function in the main.c:<br />
void SVC&#95;Handler&#40;void&#41;<br />
&#123;<br />
vPortSVCHandler&#40;&#41;;<br />
&#125;  
When entering the SVC mode, beginning address of SVC&#95;Handler&#40;&#41;, the lr value is correct: 0xfffffff9. But when stepping in, after entering vPortSVCHandler, the lr will changed to the SVC&#95;Handler&#40;&#41; &#33; It is supposed to 0xffffff9 as the default SVC handler code:<br />
&#8221; orr r14, &#35;0xd&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; n&#8221;<br />
&#8221; bx r14&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; n&#8221;  
So is this a compiler issue or code issue? If we add a &#8220;mov r14, &#35;0xfffffff9 n&#8221; before the &#8220;orr r14, &#35;0xd n&#8221;, the code will working. But the same code works on the IAR EWARM and codesourcery.  
The armgcc version is arm-none-eabi-gcc.exe &#40;crosstool-NG 1.13.1 &#8211; Atmel build: 13&#41; 4.6.1

</div></div><div class="thread-post"><h3 class="thread-post-title">Default  vPortSVCHandler() issue</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/sunxinyan">sunxinyan</a> on August 16, 2012</div><div class="thread-post-content">Thanks, Richard,

The vector table should be right as the same code is working on the IAR EWARM 6.2 and codesourcery GCC:arm-none-eabi-gcc &#40;Sourcery G++ Lite 2011.03-42&#41; 4.5.2.<br />
But it is not working only on the arm-none-eabi-gcc.exe &#40;crosstool-NG 1.13.1 &#8211; Atmel build: 13&#41; 4.6.1.  
It seemslike a compiler issue as 2 toolchain works and only 1 fails. But if we added the &#8220;mov r14, &#35;0xfffffff9 n&#8221; to update the lr in the SVC handler, the code is working.  
The problem is when the code running from SVC&#95;Handler&#40;&#41; to vPortSVCHandler&#40;&#41;, the lr is changed. It can and should be changed as it is a APCS call. If we set a breakpoint at vPortSVCHandler&#40;&#41;, the lr value is the address of SVC&#95;Handler&#40;&#41;.  
But on the IAR, on the other hand, this toolchain has optimize the code. If we set a breakpoint on the beginning of vPortSVCHandler&#40;&#41;, the lr value is 0xfffffff9 which proved the optimization.  
So that&#8217;s why i&#8217;m a bit confused. Is it a compile issue or a code issue. If a compile issue, how can we reslove it?
