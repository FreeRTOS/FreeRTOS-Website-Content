  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Order of thread execution?</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/kuku2010">kuku2010</a> on August 27, 2012</div><div class="thread-post-content">3 threads: A @ priority 3, B @2, C @1, one interrupt D, system tick is 1ms  
All threads takes only a small fraction of time to run most time.  
A ran for a fraction of ms and wait for the semaphore to be given by D, so the next thread will run<br />
B ran for a fraction of ms and use vTaskDelay&#40;1&#41; to allow the next thread to run<br />
C ran for a fraction of ms and called&nbsp; vTaskDelay&#40;1&#41;   
At this point, 1ms hasn&#8217;t passed yet, so will the system enter some idle state until the next tick? If so, is there a way to wake up a specific thread? For example, wake up B and it runs until the next tick, which will be A&#8217;s turn again.  
&#40;Still no system tick&#41; If D gives the semaphore, will A resume immediately? If so, when the next system tick occurs, I assume A continue since it has the highest priority  
Thanks for your time&#33;  
</div></div><div class="thread-post"><h3 class="thread-post-title">Order of thread execution?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on August 27, 2012</div><div class="thread-post-content"><blockquote>
  At this point, 1ms hasn&#8217;t passed yet, so will the system enter some idle state until the next tick?
</blockquote>
The idle task will run at priority 0.  
<blockquote>
  For example, wake up B and it runs until the next tick, which will be A&#8217;s turn again.
</blockquote>
Your code has told B to wait for 1 tick, so that is what it will do. You could run B at priority 0 too, in which case it will share processing with the idle task when A and C are not running. Setting configIDLE&#95;SHOULD&#95;YIELD to 1 in FreeRTOSConfig.h makes the idle task always yield to B straight away if B is not blocked. Alternatively you can make B block on a semaphore instead of vTaskDelay&#40;1&#41; and give the semaphore from the idle hook function but that would seem like overkill.  
<blockquote>
  If D gives the semaphore, will A resume immediately?
</blockquote>
Yes, if that is what you told it to do, of course. The port you are using will have a YIELD&#95;FROM&#95;ISR or END&#95;SWITCHING&#95;ISR macro to ensure it happens. Both macros do the same thing, different ports just use different names for some reason. Look at the examples that come with your port. <a href="http://www.freertos.org/a00090.html">http://www.freertos.org/a00090.html</a>  
<blockquote>
  If so, when the next system tick occurs, I assume A continue since it has the highest priority
</blockquote>
Yes. The highest priority task that is not blocked or suspended will always run, and time slice with other tasks that have the same priority and are also not blocked if there are any.
</div></div><div class="thread-post"><h3 class="thread-post-title">Order of thread execution?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/kuku2010">kuku2010</a> on August 28, 2012</div><div class="thread-post-content">&#8220;Setting configIDLE&#95;SHOULD&#95;YIELD to 1 &#8220;, do you mean &#8220;Setting configIDLE&#95;SHOULD&#95;YIELD to 2&#8221;, since B has priority of 2?
</div></div><div class="thread-post"><h3 class="thread-post-title">Order of thread execution?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on August 28, 2012</div><div class="thread-post-content"><blockquote>
  Setting configIDLE&#95;SHOULD&#95;YIELD to 1 &#8220;, do you mean &#8220;Setting configIDLE&#95;SHOULD&#95;YIELD to 2&#8221;, since B has priority of 2
</blockquote>
No, configIDLE&#95;SHOULD&#95;YIELD is binary, 1 or 0. I mentioned it in context of running the other task at priority 0 &#40;idle priority&#41;. Look it up on <a href="http://www.freertos.org/a00110.html">http://www.freertos.org/a00110.html</a>
