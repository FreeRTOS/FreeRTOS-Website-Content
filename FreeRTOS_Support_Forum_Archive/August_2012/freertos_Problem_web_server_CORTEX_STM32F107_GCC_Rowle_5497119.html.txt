</div></div><div class="thread-post"><h3 class="thread-post-title">Problem web server CORTEX_STM32F107_GCC_Rowle</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on August 3, 2012</div><div class="thread-post-content">In a real system the MAC address would come from ROM somewhere, as each has to be unique.&nbsp; In test systems the MAC address is just fixed in the C code, but still has to be unique on the network, so connecting two boards to the same network requires two separate configurations.  
In your demo the MAC address is defined by the constants:  
&#35;define configMAC&#95;ADDR0 0x00<br />
&#35;define configMAC&#95;ADDR1 0x12<br />
&#35;define configMAC&#95;ADDR2 0x13<br />
&#35;define configMAC&#95;ADDR3 0x10<br />
&#35;define configMAC&#95;ADDR4 0x15<br />
&#35;define configMAC&#95;ADDR5 0x11  
which you will find in FreeRTOSConfig.h.  
If data is being received, as it seems it is, the next thing to do would be to follow the packet through the uIP stack using the debugger to see if it gets dropped somewhere &#40;in which case you will see why&#41; or if it generated some output.  
Do you have Wireshark connected so you can see the traffic going back and forth?  
Regards.
