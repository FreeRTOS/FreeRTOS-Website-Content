  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Race condition between vTaskSwitchContext and xTaskNotifyFromISR?</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/n1vg">n1vg</a> on October 9, 2018</div><div class="thread-post-content">I&#8217;m running FreeRTOS 10.0.1 on a Kinetis MK22FN1M0AVLH12 (Cortex M4F core), specifically the MCUonEclipse port, with MCUXpresso and gcc.
I&#8217;ve been chasing an intermittent crash for weeks and I&#8217;m finally narrowing in on it.  I have a temporary fix that seems to be working but I don&#8217;t see why it&#8217;d be necessary.  It&#8217;s been hard to track down until now because it&#8217;d usually take hours to crash.
What&#8217;s happening is that vTaskSwitchContext is sometimes being interrupted by a flex timer peripheral IRQ which uses xTaskNotifyFromISR.   Normally this works fine, but if the interrupt happens at the wrong place in listGET<em>OWNER</em>OF<em>NEXT</em>ENTRY it ends up setting pxCurrentTCB to null and the system crashes &#8211; with the stack clobbered, which has been slowing down my debugging.  The SysTick and PendSV priorities are set to 15 (minimum), and the maximum API call priority is 5.  The timer IRQ is set to priority 7 at the moment. 
To make the problem more apparent and speed up testing, I changed listGET<em>OWNER</em>OF<em>NEXT</em>ENTRY to include a delay (line continuation backslashes omitted for clarity):
~~~
<h1>define listGET<em>OWNER</em>OF<em>NEXT</em>ENTRY( pxTCB, pxList )</h1>
{<br />
List_t * const pxConstList = ( pxList );
    /* Increment the index to the next item and return the item, ensuring */
    /* we don&#8217;t return the marker used at the end of the list.  */
    ( pxConstList )->pxIndex = ( pxConstList )->pxIndex->pxNext;
    if( ( void * ) ( pxConstList )->pxIndex == ( void * ) &amp;( ( pxConstList )->xListEnd ) )
    {
        ( pxConstList )->pxIndex = ( pxConstList )->pxIndex->pxNext;
    }
    for (int ix = 2000; ix; ix&#8211;) {};
    ( pxTCB ) = ( pxConstList )->pxIndex->pvOwner;
}
~~~
This just stretches out the time between the adjacent lines of code by a very large amount, so instead of taking several hours to crash it does so in seconds.
My fix for the moment is to globally disable interrupts in vTaskSwitchContext before taskSELECT<em>HIGHEST</em>PRIORITY_TASK:
~~~
        __asm (&#8220;CPSID  i&#8221;);
        taskSELECT<em>HIGHEST</em>PRIORITY<em>TASK();
        traceTASK</em>SWITCHED_IN();
        __asm (&#8220;CPSIE  i&#8221;);
~~~
I&#8217;m assuming there must be something wrong with my configuration, or maybe an oversight in this particular port, but I don&#8217;t know the FreeRTOS internals well enough to know where that might be.  I&#8217;ve been through every resource I can find on Cortex M3/4 ports.
Any ideas?
Thanks!
Scott
