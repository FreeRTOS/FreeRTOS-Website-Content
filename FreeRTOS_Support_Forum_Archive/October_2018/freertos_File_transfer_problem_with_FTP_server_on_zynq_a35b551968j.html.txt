  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">File transfer problem with FTP server on zynq</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/claudiorossi">claudiorossi</a> on October 5, 2018</div><div class="thread-post-content">Hi all
I&#8217;m using FreeRTOS+TCP, FreeRTOS+FAT and FreeRTOS FTP server to connect Filezilla to my board 
in order to manage the SD card.
The software run correctly and I can see the SD card content, create folder, upload and download file from/to PC and the memory card.
However files transferred from PC to the SD card appear with some random data corrupted.
Instead files transferred from SD card to PC are ok.
I have tried the following:
1) Used FreeRTOS+TCP 2.01 and 2.07
2) Modified circular buffer size 
but the probelm persist.
If I print out the data received from TCP in function prvStoreFileWork I see that data received from socket
are corrupted (the problem is not in +FAT).
This is my FreeRTOSIPconfig file:
~~~
<h1>ifndef FREERTOS<em>IP</em>CONFIG_H</h1>
<h1>define FREERTOS<em>IP</em>CONFIG_H</h1>
/* Define the byte order of the target MCU (the MCU FreeRTOS+TCP is executing

<h1>define ipconfigBYTE<em>ORDER pdFREERTOS</em>LITTLE_ENDIAN</h1>
/* If the network card/driver includes checksum offloading (IP/TCP/UDP checksums)

stack repeating the checksum calculations. */
<h1>define ipconfigDRIVER<em>INCLUDED</em>TX<em>IP</em>CHECKSUM      ( 1 )</h1>
<h1>define ipconfigDRIVER<em>INCLUDED</em>RX<em>IP</em>CHECKSUM      ( 1 )</h1>

used as defaults. */
<h1>define ipconfigSOCK<em>DEFAULT</em>RECEIVE<em>BLOCK</em>TIME ( 5000 )</h1>
<h1>define ipconfigSOCK<em>DEFAULT</em>SEND<em>BLOCK</em>TIME    ( 5000 )</h1>
/* Include support for LLMNR: Link-local Multicast Name Resolution

<h1>define ipconfigUSE_LLMNR                   ( 0 )</h1>

<h1>define ipconfigUSE_NBNS                    ( 0 )</h1>

<h1>define ipconfigUSE<em>DNS</em>CACHE               ( 1 )</h1>

priority) to (configMAX<em>PRIORITIES &#8211; 1) (the highest priority).
configMAX</em>PRIORITIES is a standard FreeRTOS configuration parameter defined in

http://www.freertos.org/Stacks-and-stack-overflow-checking.html */
<h1>define ipconfigIP<em>TASK</em>STACK<em>SIZE</em>WORDS    ( configMINIMAL<em>STACK</em>SIZE * 5 )</h1>
/* ipconfigRAND32() is called by the IP stack to generate random numbers for

<h1>define ipconfigUSE<em>NETWORK</em>EVENT_HOOK 1</h1>
/* Sockets have a send block time attribute.  If FreeRTOS<em>sendto() is called but

then the send operation is aborted.  The maximum allowable send block time is
capped to the value set by ipconfigMAX</em>SEND<em>BLOCK</em>TIME<em>TICKS.  Capping the
maximum allowable send block time prevents prevents a deadlock occurring when
all the network buffers are in use and the tasks that process (and subsequently
free) the network buffers are themselves blocked waiting for a network buffer.
ipconfigMAX</em>SEND<em>BLOCK</em>TIME<em>TICKS is specified in RTOS ticks.  A time in
milliseconds can be converted to a time in ticks by dividing the time in
milliseconds by portTICK</em>PERIOD_MS. */
<h1>define ipconfigUDP<em>MAX</em>SEND<em>BLOCK</em>TIME<em>TICKS ( 5000 / portTICK</em>PERIOD_MS )</h1>
/* If ipconfigUSE<em>DHCP is 1 then FreeRTOS+TCP will attempt to retrieve an IP
address, netmask, DNS server address and gateway address from a DHCP server.  If
ipconfigUSE</em>DHCP is 0 then FreeRTOS+TCP will use a static IP address.  The
stack will revert to using the static IP address even when ipconfigUSE<em>DHCP is

<h1>define ipconfigUSE_DHCP                0</h1>
<h1>define ipconfigDHCP<em>REGISTER</em>HOSTNAME  0</h1>
<h1>define ipconfigUSE<em>DHCP</em>HOOK           0</h1>
/* When ipconfigUSE<em>DHCP is set to 1, DHCP requests will be sent out at
increasing time intervals until either a reply is received from a DHCP server
and accepted, or the interval between transmissions reaches
ipconfigMAXIMUM</em>DISCOVER<em>TX</em>PERIOD.  The IP stack will revert to using the
static IP address passed as a parameter to FreeRTOS<em>IPInit() if the

a DHCP reply being received. */
<h1>define ipconfigMAXIMUM<em>DISCOVER</em>TX<em>PERIOD      ( pdMS</em>TO_TICKS( 30000 ) )</h1>
/* The ARP cache is a table that maps IP addresses to MAC addresses.  The IP

address associated with the IP address, or the MAC address of the router used to
contact the remote IP address.  When a UDP message is received from a remote IP
address the MAC address and IP address are added to the ARP cache.  When a UDP
message is sent to a remote IP address that does not already appear in the ARP

<h1>define ipconfigARP<em>CACHE</em>ENTRIES       6</h1>
/* ARP requests that do not result in an ARP response will be re-transmitted a

<h1>define ipconfigMAX<em>ARP</em>RETRANSMISSIONS ( 5 )</h1>
/* ipconfigMAX<em>ARP</em>AGE defines the maximum time between an entry in the ARP
table being created or refreshed and the entry being removed because it is stale.
New ARP requests are sent for ARP cache entries that are nearing their maximum
age.  ipconfigMAX<em>ARP</em>AGE is specified in tens of seconds, so a value of 150 is
equal to 1500 seconds (or 25 minutes). */
<h1>define ipconfigMAX<em>ARP</em>AGE         150</h1>
/* Implementing FreeRTOS<em>inet</em>addr() necessitates the use of string handling

FreeRTOS<em>inet</em>addr() implementation is made optional, and a smaller and faster
alternative called FreeRTOS<em>inet</em>addr<em>quick() is provided.  FreeRTOS</em>inet<em>addr()
takes an IP in decimal dot format (for example, &#8220;192.168.0.1&#8221;) as its parameter.
FreeRTOS</em>inet<em>addr</em>quick() takes an IP address as four separate numerical octets
(for example, 192, 168, 0, 1) as its parameters.  If
ipconfigINCLUDE<em>FULL</em>INET<em>ADDR is set to 1 then both FreeRTOS</em>inet<em>addr() and
FreeRTOS</em>indet<em>addr</em>quick() are available.  If ipconfigINCLUDE<em>FULL</em>INET<em>ADDR is
not set to 1 then only FreeRTOS</em>indet<em>addr</em>quick() is available. */
<h1>define ipconfigINCLUDE<em>FULL</em>INET_ADDR  1</h1>
/* ipconfigNUM<em>NETWORK</em>BUFFER_DESCRIPTORS defines the total number of network buffer that
are available to the IP stack.  The total number of network buffers is limited
to ensure the total amount of RAM that can be consumed by the IP stack is capped
to a pre-determinable value. */
<h1>define ipconfigNUM<em>NETWORK</em>BUFFER_DESCRIPTORS      96</h1>
/* Optimisation that allows more than one Rx buffer to be passed to the TCP task
at a time &#8211; requires driver support. */
<h1>define ipconfigUSE<em>LINKED</em>RX_MESSAGES      ( 1 )</h1>
/* A FreeRTOS queue is used to send events from application tasks to the IP
stack.  ipconfigEVENT<em>QUEUE</em>LENGTH sets the maximum number of events that can
be queued for processing at any one time.  The event queue must be a minimum of
5 greater than the total number of network buffers. */
<h1>define ipconfigEVENT<em>QUEUE</em>LENGTH      ( ipconfigNUM<em>NETWORK</em>BUFFER_DESCRIPTORS + 5 )</h1>
/* The address of a socket is the combination of its IP address and its port
number.  FreeRTOS<em>bind() is used to manually allocate a port number to a socket
(to &#8216;bind&#8217; the socket to a port), but manual binding is not normally necessary
for client sockets (those sockets that initiate outgoing connections rather than
wait for incoming connections on a known port number).  If
ipconfigALLOW</em>SOCKET<em>SEND</em>WITHOUT<em>BIND is set to 1 then calling
FreeRTOS</em>sendto() on a socket that has not yet been bound will result in the IP
stack automatically binding the socket to a port number from the range
socketAUTO<em>PORT</em>ALLOCATION<em>START</em>NUMBER to 0xffff.  If
ipconfigALLOW<em>SOCKET</em>SEND<em>WITHOUT</em>BIND is set to 0 then calling FreeRTOS_sendto()
on a socket that has not yet been bound will result in the send operation being
aborted. */
<h1>define ipconfigALLOW<em>SOCKET</em>SEND<em>WITHOUT</em>BIND 1</h1>
/* Defines the Time To Live (TTL) values used in outgoing UDP packets. */
<h1>define ipconfigUDP<em>TIME</em>TO_LIVE        128</h1>
<h1>define ipconfigTCP<em>TIME</em>TO_LIVE        128 /* also defined in FreeRTOSIPConfigDefaults.h */</h1>
/* USE_TCP: Use TCP and all its features */
<h1>define ipconfigUSE_TCP             ( 1 )</h1>
/* USE_WIN: Let TCP use windowing mechanism. */
<h1>define ipconfigUSE<em>TCP</em>WIN         ( 1 )</h1>
/* The MTU is the maximum number of bytes the payload of a network frame can
contain.  For normal Ethernet V2 frames the maximum MTU is 1500.  Setting a
lower value can save RAM, depending on the buffer management scheme used.  If
ipconfigCAN<em>FRAGMENT</em>OUTGOING<em>PACKETS is 1 then (ipconfigNETWORK</em>MTU &#8211; 28) must
be divisible by 8. */
<h1>define ipconfigNETWORK_MTU     1500</h1>
/* Set ipconfigUSE<em>DNS to 1 to include a basic DNS client/resolver.  DNS is used
through the FreeRTOS</em>gethostbyname() API function. */
<h1>define ipconfigUSE_DNS         0</h1>
/* If ipconfigREPLY<em>TO</em>INCOMING_PINGS is set to 1 then the IP stack will
generate replies to incoming ICMP echo (ping) requests. */
<h1>define ipconfigREPLY<em>TO</em>INCOMING_PINGS             1</h1>
/* If ipconfigSUPPORT<em>OUTGOING</em>PINGS is set to 1 then the
FreeRTOS_SendPingRequest() API function is available. */
<h1>define ipconfigSUPPORT<em>OUTGOING</em>PINGS              0</h1>
/* If ipconfigSUPPORT<em>SELECT</em>FUNCTION is set to 1 then the FreeRTOS_select()
(and associated) API function is available. */
<h1>define ipconfigSUPPORT<em>SELECT</em>FUNCTION             1</h1>
/* If ipconfigFILTER<em>OUT</em>NON<em>ETHERNET</em>II_FRAMES is set to 1 then Ethernet frames
that are not in Ethernet II format will be dropped.  This option is included for
potential future IP stack developments. */
<h1>define ipconfigFILTER<em>OUT</em>NON<em>ETHERNET</em>II_FRAMES  1</h1>
/* If ipconfigETHERNET<em>DRIVER</em>FILTERS<em>FRAME</em>TYPES is set to 1 then it is the
responsibility of the Ethernet interface to filter out packets that are of no
interest.  If the Ethernet interface does not implement this functionality, then
set ipconfigETHERNET<em>DRIVER</em>FILTERS<em>FRAME</em>TYPES to 0 to have the IP stack
perform the filtering instead (it is much less efficient for the stack to do it
because the packet will already have been passed into the stack).  If the
Ethernet driver does all the necessary filtering in hardware then software
filtering can be removed by using a value other than 1 or 0. */
<h1>define ipconfigETHERNET<em>DRIVER</em>FILTERS<em>FRAME</em>TYPES 1</h1>
/* The windows simulator cannot really simulate MAC interrupts, and needs to
block occasionally to allow other tasks to run. */
<h1>define configWINDOWS<em>MAC</em>INTERRUPT<em>SIMULATOR</em>DELAY ( 2 / portTICK<em>PERIOD</em>MS )</h1>
/* Advanced only: in order to access 32-bit fields in the IP packets with
32-bit memory instructions, all packets will be stored 32-bit-aligned, plus 16-bits.
This has to do with the contents of the IP-packets: all 32-bit fields are
32-bit-aligned, plus 16-bit(!) */
<h1>define ipconfigPACKET<em>FILLER</em>SIZE 2</h1>
/* Define the size of the pool of TCP window descriptors.  On the average, each

outstanding packets (for Rx and Tx).  When using up to 10 TP sockets
simultaneously, one could define TCP<em>WIN</em>SEG_COUNT as 120. */
<h1>define ipconfigTCP<em>WIN</em>SEG_COUNT 240</h1>
/* Each TCP socket has a circular buffers for Rx and Tx, which have a fixed

<h1>define ipconfigTCP<em>RX</em>BUFFER_LENGTH            ( 0x4000 )</h1>
/* Define the size of Tx buffer for TCP sockets. */
<h1>define ipconfigTCP<em>TX</em>BUFFER_LENGTH            ( 0x4000 )</h1>
/* When using call-back handlers, the driver may check if the handler points to

<h1>define ipconfigIS<em>VALID</em>PROG_ADDRESS(x) ( (x) != NULL )</h1>
/* Include support for TCP hang protection.  All sockets in a connecting or

<h1>define ipconfigTCP<em>HANG</em>PROTECTION             ( 1 )</h1>

The difference between the two modules with respect to caching is:
● <strong>BufferAllocation_1.c</strong> pre allocates all buffers well-aligned, each with a length of 1536.
The length 1536 is dividable by 32, which is the size of a DCache line.
<code>Xil_DCacheInvalidateRange()</code> will work only on the buffer, not on neighbouring buffers.
● <strong>BufferAllocation_2.c</strong> has dynamic allocation: it will call <code>vPortMalloc()</code> each time
when a network buffer is needed, and call <code>vPortFree()</code> when ready.
Each time it will have a varying size and a 4-byte or 8-byte alignment.
These buffers are not aligned with the data cache.
