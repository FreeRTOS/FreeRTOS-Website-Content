</div></div><div class="thread-post"><h3 class="thread-post-title">snprintf error (PIC32MZ2048EFM064)</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/ldb">ldb</a> on November 13, 2018</div><div class="thread-post-content">Most likely the problem is FreeRTOS is using dynamic memory allocator and it&#8217;s clashing with the standard memory allocator. Usually the C memory system positions the heap based on something like a marker in the linker file like _end. It&#8217;s likely  your FreeRTOS allocator is using the same or an overlapping marker.  It is quite normal in many implementations for Printf , snprintf and all the variants to malloc a small buffer. 
Option 1: Find out what in the linker file is used to mark the heap in both systems and then change it in FreeRTOS and make the allocators avoid each other.
Option2: Make FreeRTOS use the C system malloc functions.

</div></div><div class="thread-post"><h3 class="thread-post-title">snprintf error (PIC32MZ2048EFM064)</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/ldb">ldb</a> on November 16, 2018</div><div class="thread-post-content">So use heap_2.c and make sure you follow the  instructions are below, it&#8217;s a simply array you put in your main  c file and set the flag
configAPPLICATION<em>ALLOCATED</em>HEAP = 1
You need to set configTOTAL<em>HEAP</em>SIZE with some suitable size for the array that is all the memory your allocator has so make sure you make it big enough (AKA what are you allocating for each of your tasks) and add some reasonable overhead. 
If that doesn&#8217;t work then there is something a lot deeper at play.
~~~
configAPPLICATION<em>ALLOCATED</em>HEAP
By default the FreeRTOS heap is declared by FreeRTOS and placed in memory by the linker. Setting configAPPLICATION<em>ALLOCATED</em>HEAP to 1 allows the heap to instead be declared by the application writer, which allows the application writer to place the heap wherever they like in memory.
If heap<em>1.c, heap</em>2.c or heap<em>4.c is used, and configAPPLICATION</em>ALLOCATED<em>HEAP is set to 1, then the application writer must provide a uint8</em>t array with the exact name and dimension as shown below. The array will be used as the FreeRTOS heap. How the array is placed at a specific memory location is dependent on the compiler being used &#8211; refer to your compiler&#8217;s documentation.
uint8<em>t ucHeap[ configTOTAL</em>HEAP_SIZE ];
~~~
