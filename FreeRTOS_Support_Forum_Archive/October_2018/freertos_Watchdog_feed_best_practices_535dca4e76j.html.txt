  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Watchdog feed best practices</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/didi71">didi71</a> on October 16, 2018</div><div class="thread-post-content">Hello everybody.
The typical sequence for to feed the watchdog onto one LPC17xx is the follow:
<pre><code>LPC_WDT-&gt;WDFEED = 0xAA;
LPC_WDT-&gt;WDFEED = 0x55;
</code></pre>
My question: is It recommended to wrap the upper two lines inside a 
taskENTER<em>CRITICAL() 
taskEXIT</em>CRITICAL() 
section?
I got very rare watchdog events and I start to believe that they could be caused because one task switch happen between the two rows.
Thanks in advance.
Diego.
</div></div><div class="thread-post"><h3 class="thread-post-title">Watchdog feed best practices</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richarddamon">richarddamon</a> on October 17, 2018</div><div class="thread-post-content">Yes, I would wrap the sequence in a critical section if not a full interrupt disable as even with a very high priority interrupt you don&#8217;t want to break the pattern and risk getting the dog to trip.
</div></div><div class="thread-post"><h3 class="thread-post-title">Watchdog feed best practices</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on October 17, 2018</div><div class="thread-post-content">Also, try to access the watchdog from only one task.  I often have one 
task that monitors all the other tasks, and kicks the watchdog only if 
it is happy with everything (for example, it has determined that all the 
tasks have executed within their expected time frame, etc.).  Having 
only one task access reduces the risk of interleaved writes of the key.
</div></div><div class="thread-post"><h3 class="thread-post-title">Watchdog feed best practices</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richarddamon">richarddamon</a> on October 17, 2018</div><div class="thread-post-content">One thing worth pointing out is that in my experiance, for most watchdogs the sequence isn&#8217;t just first write the first value, and then some time later write the second, but that the two writes need to be very tightly timed to each other, so an interrupt seperating them, even if it doesn&#8217;t touch the watchdog, is enough to disrupt the kick of the watchdog.  For some processors it needs a very specific instruction sequence, and there is a macro defined that will generate it.
This is why I suggest it should be wrapped in a full interrupt disable.
</div></div><div class="thread-post"><h3 class="thread-post-title">Watchdog feed best practices</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/didi71">didi71</a> on October 17, 2018</div><div class="thread-post-content">Hi Richard.
Thank you for your fast reply.
If I well understood the macro&#8217;s <strong>taskENTER_CRITICAL()</strong>  and <strong>taskEXIT_CRITICAL()</strong> aren&#8217;t enough?
Do you suggest to use disable<em>irq() and  enable</em>irq() instead?
Or not?
</div></div><div class="thread-post"><h3 class="thread-post-title">Watchdog feed best practices</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/didi71">didi71</a> on October 17, 2018</div><div class="thread-post-content">Thank you Richard.
My current implementation triggers the watchdog from only one task.
Diego.
</div></div><div class="thread-post"><h3 class="thread-post-title">Watchdog feed best practices</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/didi71">didi71</a> on October 17, 2018</div><div class="thread-post-content">Hi everybody.
I&#8217;ve wrapped my watchdog trigger function inside the safe blocks as follows:
taskENTER<em>CRITICAL();
{
    LPC</em>WDT->WDFEED = 0xAA;
    LPC<em>WDT->WDFEED = 0x55;
}
taskEXIT</em>CRITICAL();
Currently I&#8217;m doing an extensive stress test to check if this solution can fixs my issue.
I keep you updated.
Thank you so much.
Diego.
</div></div><div class="thread-post"><h3 class="thread-post-title">Watchdog feed best practices</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richarddamon">richarddamon</a> on October 20, 2018</div><div class="thread-post-content">taskENTER<em>CRITICAL is good enough IF there are no other interrupts that might happen that don&#8217;t use the FreeRTOS Interrupt API that might still happen. If such an interrupt exists in your system then you want to wrap with a total interrupt disable block (not just taskENTER</em>CRITICAL).
</div></div><div class="thread-post"><h3 class="thread-post-title">Watchdog feed best practices</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/didi71">didi71</a> on October 22, 2018</div><div class="thread-post-content">Hello.
After few days of extensive tests I can confirm (on my system) that taskENTER<em>CRITICAL / taskEXIT</em>CRITICAL are not enough.
I must wrapping the watchdog trigger code with disable<em>irq()  / enable</em>irq() macros.
Doing so It seems to woks reliable.
My system has several interrupts, mostly comes form timers and UART.
Thank you so much for the suggestions.
Best regards.
Diego.
