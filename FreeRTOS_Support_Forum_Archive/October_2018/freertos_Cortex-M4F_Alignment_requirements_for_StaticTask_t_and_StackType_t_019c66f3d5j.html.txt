  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Cortex-M4F: Alignment requirements for StaticTask_t and StackType_t</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/damien_d">damien_d</a> on October 15, 2018</div><div class="thread-post-content">Dear All,
I am looking to clarify if alignment is required when using statically allocated tasks and, by extension, statically allocated stacks for Idle and Timers.
I am currently using <a href="https://developer.arm.com/open-source/gnu-toolchain/gnu-rm">GCC</a> with an <a href="https://www.nxp.com/support/developer-resources/evaluation-and-development-boards/analog-toolbox/s32k144-evaluation-board:S32K144EVB">NXP S32K144 EVK</a> (ARM Cortex M4F).
For example, I am currently allocating my tasks using the following pattern, following the examplies in the <a href="https://www.freertos.org/Static_Vs_Dynamic_Memory_Allocation.html">documentation</a>:
~~~
// Does either StaticTask<em>t or StackType</em>t need to be aligned on 8-bytes? 
// This:     #define ALIGN<em>8</em>BYTES
// or this?  #define ALIGN<em>8</em>BYTES <strong>attribute</strong> ((aligned (8)))
<h1>define STACK<em>DEPTH</em>FLASH_LED    256</h1>
static TaskHandle<em>t xTaskHandle</em>FlashLED;
static StaticTask<em>t ALIGN</em>8<em>BYTES m</em>xTaskBuffer<em>FlashLED;
static StackType</em>t  ALIGN<em>8</em>BYTES m<em>xStack</em>FlashLED[STACK<em>DEPTH</em>FLASH_LED];
<h1>define NO<em>THREAD</em>PARAMETERS    NULL</h1>
xTaskHandle<em>FlashLED = xTaskCreateStatic(
            vTask</em>FlashLED,
            &#8220;flash<em>led&#8221;,
            STACK</em>DEPTH<em>FLASH</em>LED,
            NO<em>THREAD</em>PARAMETERS,
            TASK<em>PRIORITY</em>FLASH<em>LED,
            m</em>xStack<em>FlashLED,
            &amp;m</em>xTaskBuffer_FlashLED);
~~~
When looking at tasks.c for the dynamic case, the allocated memory will be aligned to (in the case of the CM4F) 8-byte boundaries, as guarunteed by pvPortAlloc:
~~~
{
        StackType_t *pxStack;
<pre><code>        /* Allocate space for the stack used by the task being created. */
        pxStack = pvPortMalloc( ( ( ( size_t ) usStackDepth ) * sizeof( StackType_t ) ) ); /*lint !e9079 All values returned by pvPortMalloc() have at least the alignment required by the MCU's stack and this allocation is the stack. */
        if( pxStack != NULL )
        {
            /* Allocate space for the TCB. */
            pxNewTCB = ( TCB_t * ) pvPortMalloc( sizeof( TCB_t ) ); /*lint !e9087 !e9079 All values returned by pvPortMalloc() have at least the alignment required by the MCU's stack, and the first member of TCB_t is always a pointer to the task's stack. */
            if( pxNewTCB != NULL )
            {
                /* Store the stack location in the TCB. */
                pxNewTCB-&gt;pxStack = pxStack;
            }
            else
            {
                /* The stack cannot be used as the TCB was not created.  Free
                it again. */
                vPortFree( pxStack );
            }
        }
        else
        {
            pxNewTCB = NULL;
        }
    }
</code></pre>
~~~
As I understand it, The CM4F requires that the stack is 8-byte aligned.  However, since StackType<em>t is a uint32</em>t, then GCC will allocate this to a 4-byte boundary, not an 8-byte boundary, e.g.
~~~
 .bss.m<em>xTaskBuffer</em>FlashLED
                0x000000002000435c       0x4c /tmp/ccRQFTy2.ltrans0.ltrans.o
~~~
So, should the statically allocated stack also be 8-byte aligned using gcc&#8217;s <strong>attribute</strong> ((aligned (8))) to ensure alignment?  What is the likely consequence if this is not the case.  Certainly, this does indeed force aligment:
~~~
 <em>fill</em>         0x00000000200043c4        0x4 
 .bss.m<em>xTaskBuffer</em>FlashLED
                0x00000000200043c8       0x4c /tmp/ccPCqzB6.ltrans0.ltrans.o
~~~
And, would this be consequential for other statically alloctaed buffer, especially queues since the storage area is declared as a uint8_t:
For example:
~~~
<h1>define DEBUG<em>UART</em>QUEUE_SIZE       32</h1>
<h1>define DEBUG<em>UART</em>QUEUE<em>ITEM</em>SIZE  sizeof(SUARTDatagram)</h1>
static QueueHandle<em>t m</em>queue_DebugUART;
static ALIGN<em>8</em>BYTES uint8<em>t m</em>queue<em>DebugUART</em>storageArea[
        DEBUG<em>UART</em>QUEUE<em>SIZE * DEBUG</em>UART<em>QUEUE</em>ITEM_SIZE];
static ALIGN<em>8</em>BYTES StaticQueue<em>t m</em>queue<em>DebugUART</em>StaticQueue;
m<em>queue</em>DebugUART = xQueueCreateStatic(
            DEBUG<em>UART</em>QUEUE<em>SIZE,
            DEBUG</em>UART<em>QUEUE</em>ITEM<em>SIZE,
            m</em>queue<em>DebugUART</em>storageArea,
            &amp;m<em>queue</em>DebugUART_StaticQueue);
~~~
Kind regards,
Damien.
