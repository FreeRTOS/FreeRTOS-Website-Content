</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS_gethostbyname max delay</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on October 18, 2018</div><div class="thread-post-content"><blockquote>
  I was under the impression that this is defined by
  <code>ipconfigSOCK_DEFAULT_RECEIVE_BLOCK_TIME</code>
  however I am getting blocks at least twice this time
</blockquote>
The DNS requests are sent repeatedly, up to <code>ipconfigDNS_REQUEST_ATTEMPTS</code> times.
Have you defined this macro? It defaults to:
~~~
/* The maximum number of times a DNS request should be
sent out if a response is not received, before giving up. */
<h1>ifndef ipconfigDNS<em>REQUEST</em>ATTEMPTS</h1>
<pre><code>#define ipconfigDNS_REQUEST_ATTEMPTS        5
</code></pre>
<h1>endif</h1>
~~~
<blockquote>
  Looking at the code for <code>byname_a</code>, it would appear to fall through to
  <code>prvGetHostByName</code> anyway, so how does this avoid blocking?
</blockquote>
<code>prvGetHostByName()</code> will be called in a non-blocking way because the parameter <code>xReadTimeOut_ms</code> has been set to zero.
If you are using the latest FreeRTOS+TCP from github, unfortunately, <code>FreeRTOS_gethostbyname_a()</code> will not work properly.
I repaired it in <a href="https://github.com/htibosch/amazon-freertos/tree/hein_tibosch/lib/FreeRTOS-Plus-TCP/source">my own branch on Github</a>
Please use <code>FreeRTOS_DNS.c</code> and <code>FreeRTOS_UDP_IP.c</code>.
The idea of the call-back is as follows:
Send out a DNS request. Do not wait for an answer. When the DNS reply comes in, call the registered call-back routine.

<code>FreeRTOS_gethostbyname_cancel()</code> calls <code>vDNSCheckCallBack()</code>, which will call <code>uxListRemove()</code>.
You&#8217;re saying that you see an exception occurring in <code>vListInsertEnd()</code>. I don&#8217;t see how it can get there?

  on line 907?
  It seems that this should rather be defined in the headers as an option.
</blockquote>
The DNS server option is already included in <code>ucDHCPDiscoverOptions[]</code>.
