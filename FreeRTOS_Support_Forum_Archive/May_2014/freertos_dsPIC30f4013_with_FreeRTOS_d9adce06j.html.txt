</div></div><div class="thread-post"><h3 class="thread-post-title">dsPIC30f4013 with FreeRTOS</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on May 4, 2014</div><div class="thread-post-content"><blockquote>
  undefined reference tovApplicationIdleHook&#8217;
</blockquote>
If you have configUSE<em>IDLE</em>HOOK set to 1 in FreeRTOSConfig.h then you must provide an application callback function called vApplicationIdleHook().  Either provide the implementation of the function or set configUSE<em>IDLE</em>HOOK to 0: 
http://www.freertos.org/a00016.html
<blockquote>
  undefined reference to vPortYield&#8217;
</blockquote>
vPortYield is defined in portasm<em>DSPic.S, which you are building, but your device is not a dsPIC device so the preprocessor directives prevent the function outputting any code.  You should be building portasm</em>PIC24.S instead.
Regards.

</div></div><div class="thread-post"><h3 class="thread-post-title">dsPIC30f4013 with FreeRTOS</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on May 4, 2014</div><div class="thread-post-content"><blockquote>
  Now i need to know where should this line go, in wich file?:
</blockquote>
You don&#8217;t need to add that line anywhere, it is already in portASM_pic24.S file, therefore if neither <strong>dsPIC30F</strong> or <strong>dsPIC33F</strong> is defined then vPortYield() will be excluded from the build, and I suspect this is what your problem is.
Those definitions come from the Microchip provided architecture header files, you should not need to defined them manually as setting the correct compiler options will result in the correct header files being included, which in turn will result in the correct chip specific pre-processor macros being defined.
Regards.
