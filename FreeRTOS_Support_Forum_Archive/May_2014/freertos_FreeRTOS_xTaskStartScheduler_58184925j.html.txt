  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">FreeRTOS xTaskStartScheduler </h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/jirachi2">jirachi2</a> on May 16, 2014</div><div class="thread-post-content">I have a question. If I create a task with xTaskCreate(), and then start the scheduler with xTaskStartScheduler(), can I later on add new tasks? I think I can&#8217;t because I have to set the priority in xTaskCreate.. and then it would mess up the priority of others maybe?
So If I cant, I have to create ALL tasks before I start the scheduler?
And can I later on delete tasks while the scheduler is running?
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS xTaskStartScheduler </h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on May 16, 2014</div><div class="thread-post-content">You can create tasks before or after the scheduler has been started.
You can delete tasks after the scheduler has been started.
The following rather old (and interestingly still using version 7.x types in places) standard demo does nothing but create and delete tasks while the scheduler is running:
https://sourceforge.net/p/freertos/code/HEAD/tree/trunk/FreeRTOS/Demo/Common/Minimal/death.c
Note if you delete tasks you must allow the idle task to run occasionally as it performs some clean up.
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS xTaskStartScheduler </h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/jirachi2">jirachi2</a> on May 16, 2014</div><div class="thread-post-content">Thanks! If I create a task with xTaskCreate() after the scheduler has started, does the new task automatically run? Don&#8217;t I have to call startScheduler() again or something alike?
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS xTaskStartScheduler </h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on May 16, 2014</div><div class="thread-post-content">vTaskStartScheduler() should only ever be called once.  Any tasks created after the scheduler has started will automatically be added to the pool of tasks that are available to the scheduler, and will in fact run immediately if the task being created is given a priority that is higher than the task that created it.
Look at the example in the link already posted above.
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS xTaskStartScheduler </h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/jirachi2">jirachi2</a> on May 16, 2014</div><div class="thread-post-content">Thanks. ( i guess least is least priority, because often you don&#8217;t know how many threads in the future are created))
