</div></div><div class="thread-post"><h3 class="thread-post-title">MinGW port building issue</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on May 3, 2014</div><div class="thread-post-content">I just tried a clean 8.0.1 build and did not have any issues.  My build output is below.
From the output you provided it looks like the issues is coming from the FreeRTOS+Trace recorder code, and I suspect the trace configuration file in your project is set to an ARM port &#8211; hence the inclusion of ARM instructions.
If you build the code exactly as it is provided in the FreeRTOS zip file download, do you get the same problem.
The root of the FreeRTOS distribution contains a FreeRTOS directory and a FreeRTOS-Plus directory.  Have you mixed these two directories from two different FreeRTOS versions?
Regards.

</div></div><div class="thread-post"><h3 class="thread-post-title">MinGW port building issue</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on May 4, 2014</div><div class="thread-post-content">I just tried on a completely new clean machine, installed Eclipse Kepler, installed MingW, downloaded a clean FreeRTOS V8.0.1, imported the FreeRTOSDemoWIN32-MingW project, and everything built without even a warning.  Executed ok too.
The trace recorder configuration is in trcConfig.h (within the Trace<em>Recorder</em>Config directory visible in Eclipse&#8217;s project explorer).  The setting within that files includes the correct Trace port for the target environment is SELECTED_PORT, which if the files have not been modified should be set as follows:
<pre><code>
<h1>define SELECTED<em>PORT PORT</em>Win32</h1>
</pre></code>
Regards.
