The first two steps are working, I modified vParTestInitialise() however, since my LEDs are on PORTC and I set configTOTAL<em>HEAP</em>SIZE to 700 to fit the 1k SRAM.
I have problems with step three. This is working:
// Code goes here &#8230;
short main( void )
{
    prvIncrementResetCount();

Since I haven&#8217;t used coroutines before it&#8217;s hard for me to anaylze where this behavior comes from. I looked at the code, but I don&#8217;t see it doing anything concerning the LED controlled by vErrorChecks.

</div></div><div class="thread-post"><h3 class="thread-post-title">Using ATmega323 port with ATmega16</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on May 12, 2014</div><div class="thread-post-content">1K of RAM is really a very small amount to use a multi tasking system where each task has its own stack.
<blockquote>
  If I use more at the same it doesn&#8217;t work, meaning no LEDs are flashing
</blockquote>
So presumably you are running out of heap.  Are you checking the return value of xTaskCreate() and do you have a <a href="http://www.freertos.org/a00016.html">malloc failed hook</a> defined? 
<blockquote>
  If I comment out vStartFlashCoRoutines nothing works anymore
</blockquote>
If you have not created any co-routines did you also set configUSE<em>CO</em>ROUTINES to 0 in FreeRTOSConfig.h?  I think it is necessary.
<blockquote>
  Am I correct, that I should be fine if the sum of data and bss is smaller than 1000?
</blockquote>
If you are using heap<em>1.c, heap</em>2.c or heap_3.c then yes, I think that is correct.
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">Using ATmega323 port with ATmega16</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/joh4289">joh4289</a> on May 12, 2014</div><div class="thread-post-content">I think too, that I&#8217;m running out of heap, if I use more tasks. 
Setting configUSE<em>CO</em>ROUTINES to 0 in FreeRTOSConfig.h pointed me in the right direction. Turned out I had vCoRoutineSchedule in vApplicationIdleHook. Commenting it out solved my problem. 
I think I&#8217;ll set configUSE<em>IDLE</em>HOOK to 0 too.
Thx!
