  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Bug in AVR32 portmacro.h</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/johandc">johandc</a> on May 22, 2014</div><div class="thread-post-content">Hi, i have discovered a bug in portRESTORE_CONTEXT() in the AVR32 port of FreeRTOS. The issue relates to both the official port and the one in &#8216;atmel software framework&#8217;.
<strong>Problem:</strong> The portRESTORE_CONTEXT() call does not restore the status register and PC in one atomic operation. It first restores SR, then the PC. When restoring the SR, the interrupts will be enabled before the correct program counter has been set. This will allow any pending interrupt to be processed, and when the interrupt routine finishes the stack have been altered, which eventually will cause the call to set the program counter to crash the CPU.
<strong>Solution:</strong> By using the &#8216;rets&#8217; instruction, the processor will pop both the SR and PC off the stack in one operation. And the pending interrupt will first be allowed to run after the PC have been set.
Here&#8217;s a patch: 
<pre><code>--- a/thirdparty/freertos/freertos-8.0.0/Source/portable/GCC/AVR32_UC3/portmacro.h
+++ b/thirdparty/freertos/freertos-8.0.0/Source/portable/GCC/AVR32_UC3/portmacro.h
@@ -215,18 +215,7 @@ extern void *pvPortRealloc( void *pv, size_t xSize );
     /* Restore R0..R7 */
     "ldm     sp++, r0-r7
-    /* R0-R7 should not be used below this line */
-    /* Skip PC and SR (will do it at the end) */
-    "sub     sp, -2*4
-    /* Restore R8..R12 and LR */
-    "ldm     sp++, r8-r12, lr
-    /* Restore SR */
-    "ld.w    r0, sp[-8*4]nt" /* R0 is modified, is restored later. */
-    "mtsr    %[SR], r0
-    /* Restore r0 */
-    "ld.w    r0, sp[-9*4]
-    /* Restore PC */
-    "ld.w    pc, sp[-7*4]" /* Get PC from stack - PC is the 7th register saved */
+    "rets"
     :
     : [ulCriticalNesting] "i" (&amp;ulCriticalNesting),
       [pxCurrentTCB] "i" (&amp;pxCurrentTCB),
</code></pre>
<em>Note: I know that this will also not set the R8&#8230;R12 and LR, but doing so would require a change of the initialStackLayout to set SR and PC at the top, not in the middle. But it proves the issue.</em>
<strong>Steps to reproduce:</strong>
1) Setup freertos on avr32 target
2) Setup a perihperal interrupt in main.c. Do not enable the global interrupt.
3) Trigger the interrupt source, thus causing an interrupt to be pending.
4) call vTaskStartScheduler()
<strong>Problematic behaviour:</strong>
5) The system executes the ISR, then hangs.
<strong>Expected behaviour:</strong>
5) The system executes the ISR, then continues to the highest priority task.
Regards,
Johan Christiansen

I must admit that I have never set up any interrupt before starting the scheduler. My main() would just configure the clocks and memory and start the first task.
If you still want to load the complete initial stack (including R8&#8230;R12 and LR), and also use the rets instruction, this patch could be used:
&#8212; a/portmacro.h
+++ b/portmacro.h
@@ -219,14 +219,9 @@ extern void <em>pvPortRealloc( void *pv, size_t xSize );
     /</em> Skip PC and SR (will do it at the end) <em>/
     &#8220;sub     sp, -2</em>4&#8243;
     /* Restore R8..R12 and LR <em>/
&#8211;    &#8220;ldm     sp++, r8-r12, lr&#8221;
&#8211;    /</em> Restore SR <em>/
&#8211;    &#8220;ld.w    r0, sp[-8</em>4]nt&#8221; /* R0 is modified, is restored later. <em>/
&#8211;    &#8220;mtsr    %[SR], r0&#8221;
&#8211;    /</em> Restore r0 <em>/
&#8211;    &#8220;ld.w    r0, sp[-9</em>4]&#8221;
&#8211;    /* Restore PC <em>/
&#8211;    &#8220;ld.w    pc, sp[-7</em>4]&#8221; /* Get PC from stack &#8211; PC is the 7th register saved */
+    &#8220;ldm     sp, r8-r12, lr&#8221;
+    &#8220;sub     sp, 8&#8221;
+    &#8220;rets
     :
     : [ulCriticalNesting] &#8220;i&#8221; (&amp;ulCriticalNesting),
<h2>       [pxCurrentTCB] &#8220;i&#8221; (&amp;pxCurrentTCB),</h2>
1.9.1
