  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Startup FreeRTOS 9.0.0, STM32F4, interrupt before starting scheduler &#8211; hang</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/digdas">digdas</a> on April 4, 2018</div><div class="thread-post-content">Using FreeRTOS 9.0.0, when I start my program on a STM32F407 MCU, it will hang in the interrupt routine (crash, in xTaskIncrementTick(), on this line:
~~~
xItemValue = listGET<em>LIST</em>ITEM_VALUE( &amp;( pxTCB->xStateListItem ) );
~~~
All elements in pxTCB are 0.
This happens before the vTaskStartScheduler() is called (during the creation of the tasks / hardware etc)
To &#8220;solve&#8221; this I do
~~~
static int freeRTOSstarted = 0;
&#8230;
main(){
    HAL<em>Init();
    HAL</em>ResumeTick();
// Initialize hardware, starting tasks, and do other initialization&#8230;.
    freeRTOSstarted = 1;
    vTaskStartScheduler();
}
void SysTick<em>Handler(void) {
    HAL</em>IncTick();
    HAL<em>SYSTICK</em>IRQHandler();
    if (freeRTOSstarted) {
        xPortSysTickHandler();
    }
}
~~~
But is this the right way? Or did I overlook something?
</div></div><div class="thread-post"><h3 class="thread-post-title">Startup FreeRTOS 9.0.0, STM32F4, interrupt before starting scheduler &#8211; hang</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on April 4, 2018</div><div class="thread-post-content"><blockquote>
  This happens before the vTaskStartScheduler() is called (during the 
  creation of the tasks / hardware etc)
</blockquote>
You should not allow tick interrupts to execute until the scheduler has 
started.  If they are executing then something else is enabling the 
SysTick interrupt.  Simply calling taskENTER_CRITICAL() will prevent 
that happening (assuming all interrupt priorities are set correctly) &#8211; 
the critical section will be exited when the scheduler starts.
You need to find why the SysTick interrupt, which executes the tick 
interrupt, is executing before you have started the scheduler.
</div></div><div class="thread-post"><h3 class="thread-post-title">Startup FreeRTOS 9.0.0, STM32F4, interrupt before starting scheduler &#8211; hang</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/digdas">digdas</a> on April 5, 2018</div><div class="thread-post-content">Thanks, that is what I wanted to know. The HAL<em>ResumeTick() is starting the ticks (is needed in hardware initialization).
For now I will do it like I did specify, with a flag (in my example: freeRTOSstarted)
Will look at your suggestion with taskENTER</em>CRITICAL() later as well.
