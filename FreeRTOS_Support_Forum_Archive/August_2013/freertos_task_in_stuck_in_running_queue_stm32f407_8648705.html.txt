</div></div><div class="thread-post"><h3 class="thread-post-title">task in stuck in running queue stm32f407</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/edwards3">edwards3</a> on August 24, 2013</div><div class="thread-post-content"><blockquote>
  I am using stm32f407 with freertos 7.5.0
</blockquote>
If you are using the ST peripheral drivers then you should update to 7.5.2. 7.5.2 is just for STM32 users. See the change history<br />
<a href="http://www.freertos.org/History.txt">http://www.freertos.org/History.txt</a>  
<blockquote>
  if&#40; xHigherPriorityTaskWoken &#33;= pdFALSE &#41;<br />
  &nbsp; &#123;<br />
  &nbsp;&nbsp;&nbsp; portEND&#95;SWITCHING&#95;ISR&#40; xHigherPriorityTaskWoken &#41;;<br />
  &nbsp; &#125;
</blockquote>
You don&#8217;t need the if&#40;&#41;&#123;&#125; because that is done for you inside the portEND&#95;SWITCHING&#95;ISR&#40;&#41; macro.  
When the ethernet task gets stuck, place a break point in the ethernet interrupt to see if it is still getting called. It might be that its interrupt was never enabled again.
</div></div><div class="thread-post"><h3 class="thread-post-title">task in stuck in running queue stm32f407</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/edwards3">edwards3</a> on August 24, 2013</div><div class="thread-post-content"><blockquote>
  NVIC&#95;SET&#95;PRIORITY&#40;ETH&#95;IRQn, configLIBRARY&#95;MAX&#95;SYSCALL&#95;INTERRUPT&#95;PRIORITY&#41;;
</blockquote>
Where is that function coming from? Again if you are using the STM32 peripheral driver libraries you also need to set the mapping of priority bits so all bits are preemption priority. The ST libraries crash if you leave it at its default value. See the red text on this link<br />
<a href="http://www.freertos.org/RTOS-Cortex-M3-M4.html">http://www.freertos.org/RTOS-Cortex-M3-M4.html</a>  
Do that, and also set configASSERT&#40;&#41; to a null loop if you have not done so already. If you are using V7.5.2 that will trap any configuration mistake.
</div></div><div class="thread-post"><h3 class="thread-post-title">task in stuck in running queue stm32f407</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/*anonymous">*anonymous</a> on August 24, 2013</div><div class="thread-post-content">Hi,<br />
thanks for helping me. below is the defination of the NVIC&#95;SET&#95;PRIORITY<br />
Also as stm32f407 has 4 bits of priority, i am using a priority group value of 3 instead of 4. A value of 3 means 4 bits are being used for group priority &#40;arm reference manual&#41;. And my code does work for some time before it dies out.  
<pre><code>#define __NVIC_PRIO_BITS    4
static inline void NVIC_SET_PRIORITY(IRQn_Type IRQn, uint32_t priority)
{
  if(IRQn &lt; 0) {
    SCB-&gt;SHPR[((uint32_t)(IRQn) &amp; 0xF)-4] = ((priority &lt;&lt; (8 - __NVIC_PRIO_BITS)) &amp; 0xff); } /* set Priority for Cortex-M  System Interrupts */
  else {
    NVIC-&gt;IPR[((uint32_t)(IRQn)/4)] = ((priority &lt;&lt; (8 - __NVIC_PRIO_BITS)) &amp; 0xff);    }        /* set Priority for device specific Interrupts  */
}
</code></pre>
