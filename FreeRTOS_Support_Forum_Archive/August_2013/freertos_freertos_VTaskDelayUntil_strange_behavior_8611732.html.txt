  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">freertos VTaskDelayUntil strange behavior </h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/fayyazrafiq">fayyazrafiq</a> on August 4, 2013</div><div class="thread-post-content">I am using FreeRTOS Zynq port for software development on ZedBoard. I have a periodic task, which I need to call after a specified interval. For periodic delay, I am using vTaskDelayUntil freertos method for absolute delay. Below is my setting for the tick timer.   
XScuTimer&#95;LoadTimer&#40;&amp;Timer, XSCUTIMER&#95;CLOCK&#95;HZ / configTICK&#95;RATE&#95;HZ&#41;;  
XSCUTIMER&#95;CLOCK&#95;HZ = 666666687/2;<br />
configTICK&#95;RATE&#95;HZ =100<br />
So, Timer reloads value after every interrupt is 3333333.435<br />
According to this setting, after every 10 us , timer interrupt will be called. But when I call vTaskDelayUntil&#40; &amp;prevValue, 10&#41;, it took so much time, roughly around 30~40 seconds. However, in actual, it should take 100 us delay . I tried many things and would not be succeeded. If anybody can help me, I would be very grateful.  
</div></div><div class="thread-post"><h3 class="thread-post-title">freertos VTaskDelayUntil strange behavior </h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on August 4, 2013</div><div class="thread-post-content">The Zynq port is not an official port &#40;there is now an official Cortex-A9 port, but the Zynq code is not using it as far as I&#8217;m aware&#41;, and I am not familiar with the timers is provides at all.&nbsp; In any case, we cannot normally provide direct support to chip specific configuration as there are such a mass of chips and timer peripherals on the market.  
However, the easy way to know if your tick configuration is setup correctly is to toggle an LED from a <a href="http://www.freertos.org/a00016.html">tick hook function</a>, then measure the toggle frequency on a scope.&nbsp; Once you are confident that the tick is occurring at the correct frequency your vTaskDelayUntil&#40;&#41; function should function as expected.  
Regards.

</div></div><div class="thread-post"><h3 class="thread-post-title">freertos VTaskDelayUntil strange behavior </h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/fayyazrafiq">fayyazrafiq</a> on August 4, 2013</div><div class="thread-post-content">Dear Sir,  
Sorry- The only peripheral I have is the private timer &#40;also called &#8220;scutimer&#8221; for port tick&#41;, I checked the timer peripheral configuration, it looks fine. What others , do you think the possibility of this type of error? Your help is highly appreciated.  
Regards
</div></div><div class="thread-post"><h3 class="thread-post-title">freertos VTaskDelayUntil strange behavior </h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on August 4, 2013</div><div class="thread-post-content">If your timer interrupt is generating interrupts at the wrong frequency it is doubtful that your problem is related to FreeRTOS, meaning this is not the best place to get advice on a solution.  
I would suggest creating a very simply non-FreeRTOS project that does absolutely nothing other than configure the timer to generate periodic interrupts, then sits in a loop to allow you to measure the period using a scope.&nbsp; That will allow you to check the peripheral&#8217;s configuration, and the configuration of the Zynq&#8217;s main clocks &#40;that presumably feed the peripheral timer&#41;.&nbsp; Once you are sure they are all correct and functioning as you expect you can copy the configuration into your FreeRTOS project.  
If the time then still misbehaves in the FreeRTOS project it would give a clue as to where to look.  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">freertos VTaskDelayUntil strange behavior </h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/fayyazrafiq">fayyazrafiq</a> on August 5, 2013</div><div class="thread-post-content">Dear Sir,  
I tested the scu timer as a standalone application as suggested by you and found that timer frequency is very low &#40;1.35 MHz&#41;.&nbsp; It is also not stable. When I use the lower timer value, I measured the time period on the scope using gpio, it is around 1.6 us &#40;0.625 MHz&#41;. But when I tried larger timer reload value 10^6, the timer gives me 740 ns &#40;1.35 MHz&#41;.&nbsp; As mentioned in&nbsp; the ug585- page 193. &#8220;Each Cortex-A9 processor has its own private 32-bit timer. These timers are always clocked at 1/2 of the CPU frequency &#40;CPU&#95;3x2x&#41;.&#8221; In my case, CPU frequency is 667 MHz, so timer should run at 667/2 MHz. I checked the CPU frequency, that is also ok.

Fayyaz
