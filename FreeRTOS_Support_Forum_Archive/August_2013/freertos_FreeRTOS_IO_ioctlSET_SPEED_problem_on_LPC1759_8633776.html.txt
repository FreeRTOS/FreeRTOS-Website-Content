</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS+IO ioctlSET_SPEED problem on LPC1759</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on August 16, 2013</div><div class="thread-post-content">So 9600 works when it is the default, but does not work when it is not the default but gets set to 9600 using FreeRTOS&#95;ioctl&#40;&#41;?

<pre><code>xUARTConfig.Baud_rate = boardDEFAULT_UART_BAUD;
xUARTConfig.Databits = UART_DATABIT_8;
xUARTConfig.Parity = UART_PARITY_NONE;
xUARTConfig.Stopbits = UART_STOPBIT_1;
UART_Init( pxUART, &amp;xUARTConfig );
</code></pre>
The baud rate is set up within ioctl&#40;&#41; using the following code:  
<pre><code>xUARTConfig.Baud_rate = ulValue;
xUARTConfig.Databits = UART_DATABIT_8;
xUARTConfig.Parity = UART_PARITY_NONE;
xUARTConfig.Stopbits = UART_STOPBIT_1;
UART_Init( pxUART, &amp;xUARTConfig );
</code></pre>
so provided ulValue is 9600 it would appear the code snippets were the same.

</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS+IO ioctlSET_SPEED problem on LPC1759</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on August 16, 2013</div><div class="thread-post-content">As you are using the code on an LPC17xx you are covered by the commercial license terms, so there is no problem with you implementing the functions yourself.&nbsp; Of course it would be nice if you shared the modifications in the FreeRTOS interactive site &#40;<a href="http://interactive.freertos.org%29./">http://interactive.freertos.org&#41;.</a>  
To make a quick test you can just add a few lines into the existing code to disable the UART, make the change, then enable it again.&nbsp; In fact, you could disable it manually by calling the UART driver code directly &#40;not through FreeRTOS+IO&#41; before calling the ioctl&#40;&#41; function.  
Let us know what you find.  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS+IO ioctlSET_SPEED problem on LPC1759</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/tronics03">tronics03</a> on November 21, 2013</div><div class="thread-post-content">Dear Richard,
I have finally came back to this issue. The problem was that Tx was disabled after the UART<em>Init() call. The solution is to call the UART</em>TxCmd(). I have made this change in FreeRTOS<em>UART</em>ioctl() function, like this:
<pre><code>case ioctlSET_SPEED :
        /* Set up the default UART configuration. */
        xUARTConfig.Baud_rate = ulValue;
        xUARTConfig.Databits = UART_DATABIT_8;
        xUARTConfig.Parity = UART_PARITY_NONE;
        xUARTConfig.Stopbits = UART_STOPBIT_1;
        UART_Init( pxUART, &amp;xUARTConfig );
        /* Enable Tx. */
        UART_TxCmd( pxUART, ENABLE );
        break;
</code></pre>
I havent tried this on 1769 as I promissed, but for 1759 this solves the problem.
Thanks again for your help,
Best regards
