  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">STM32F103 with GCC systick err</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/labelsrbb">labelsrbb</a> on August 22, 2013</div><div class="thread-post-content">Hi,<br />
&nbsp;&nbsp; I use FreeRTOS V7.5.2 on STM32F103RE with GCC compile. But systick seem to be wrong. When I use:<br />
vTaskDelay&#40;1000 / portTICK&#95;RATE&#95;MS&#41;, the delay time seem to be 10 second, not 1 second. xQueueReceive&#40;g&#95;VolCtrlQ, &amp;stQItem,400 / portTICK&#95;RATE&#95;MS&#41; also delay about 4 second, not 400ms.&nbsp; But I run IAR Demo project is OK. Does any body meet this problem? Can anybody give me some advice? Thanks a lot.
</div></div><div class="thread-post"><h3 class="thread-post-title">STM32F103 with GCC systick err</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on August 22, 2013</div><div class="thread-post-content">Are you using the same FreeRTOSConfig.h between the IAR and GCC projects?&nbsp;   
If so, how is configCPU&#95;CLOCK&#95;HZ being set?&nbsp; If it is just mapped to SystemCoreClock then your GCC and IAR projects are probably setting SystemCoreClock differently, or the GCC project is not setting it at all.  
If no, then is configCPU&#95;CLOCK&#95;HZ set to the same value in both files?  
Are your IAR and GCC projects executing the same start up code?  
It is likely the IAR project will be running start up code that configures the MCU clocks, and may even call a configuration file provided by the application before it calls main&#40;&#41;.&nbsp; If you GCC project is not doing this then the frequency the chips are running at when main&#40;&#41; is called could be different.  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">STM32F103 with GCC systick err</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/mrichmond68">mrichmond68</a> on December 11, 2014</div><div class="thread-post-content">I&#8217;m also working with the STM32F103 and the GCC/ARM<em>CM3 port.  Just wanted to add that as a newbie (which I am) it was not automatically clear how configCPU</em>CLOCK_HZ should be set and how much configuring I should do manually of sysTick before the freeRTOS got hold of it.  
So here is what I found for V8.1.2, the GCC ARM<em>CM3 port.  configCPU</em>CLOCK<em>HZ should be set to the core clock rate, not to the core clock/8, and I don&#8217;t need to do anything to SysTick.  freeRTOS configures the SysTick clock source to be the core clock.  This happens in FreeRTOSSourceportableGCCARM</em>CM3port.c,vPortSetupTimerInterrupt().
