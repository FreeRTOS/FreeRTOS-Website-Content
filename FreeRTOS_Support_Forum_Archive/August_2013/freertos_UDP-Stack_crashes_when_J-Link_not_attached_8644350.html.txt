  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">UDP-Stack crashes when J-Link not attached</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/hisdudeness23">hisdudeness23</a> on August 22, 2013</div><div class="thread-post-content">Hi,  
I have ported the <strong>FreeRTOS UDP</strong>-Stack to <strong>LPC1769</strong> and I am running the Standard socket implementation &#40;<strong>no Zero Copy</strong>&#41;.<br />
Everything works perfect as long as I have my J-Link SWV Debugger attached and I run a Debug session with <strong>gdb</strong>.<br />
I am not using any ITM-Channel.<br />
Once I let the program run without the Debugger, it crashes after about 2.4 seconds. &#40;The HardFault-Handler is being called. I know this by letting a LED light up, when this happens&#41; I think this should be about the time, where the DHCP-Request is made.  
The problem now is to debug this without a debugger:&#41;  
Has anybody experienced something like this?  
My next move will be to try to get the program counter value of the crash within the hardfault out of the MCU without using the debugger.  
Any help or suggestions would be very appreciated.  
Best Regards,<br />
Dude.
</div></div><div class="thread-post"><h3 class="thread-post-title">UDP-Stack crashes when J-Link not attached</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on August 22, 2013</div><div class="thread-post-content">Depending on your tools, you may be able to connect the debugger after the crash without the board resetting or being re-flashed.&nbsp; If you are able to do that you will be able to follow the <a href="http://www.freertos.org/Debugging-Hard-Faults-On-Cortex-M-Microcontrollers.html">instructions here</a> to work out the program counter position.  
Do you have configASSERT&#40;&#41; defined?&nbsp; If not I would recommend defining it because it may allow you to trap the problem &#42;before&#42; the hard fault.  
Assuming you are running the same code, I can&#8217;t think off hand what difference having the debugger connected would make.&nbsp; Is it possible the code is built with semi-hosting libraries?&nbsp; If so, it would be worth turning semi-hosting off completely.  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">UDP-Stack crashes when J-Link not attached</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/hisdudeness23">hisdudeness23</a> on August 22, 2013</div><div class="thread-post-content">Dear Mr. Barry,  
thank you for the quick response. I am using Atollic True Studio and I have turned of resetting and res-flashing, but the debugger hangs then and I am not able to read any core registers.<br />
I am not using any semi-hosting libraries &#8211; just the Newlib standard library. &#40;But I don&#8217;t use any printf or any other instruction, that would send stuff to the debugger&#41;<br />
I use the configASSERT&#40;&#41; with the forever loop which is provided in FreeRTOSConfig.h + LED-Output, but the LED stays off.<br />
I have used tcpdump to see, if the DHCP-Request is sent out, before the crash and it is. The DHCP-Server responds and this might be the point, where it crashes.<br />
I will try to dig deeper.  
Best Regards,<br />
Dude.
</div></div><div class="thread-post"><h3 class="thread-post-title">UDP-Stack crashes when J-Link not attached</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/hisdudeness23">hisdudeness23</a> on August 22, 2013</div><div class="thread-post-content">P.S. It may be interesting to mention, that when I boot the device with the debugger and then just unplug it after a view seconds without stopping the debugging-process everything works fine. So the crash has to have something to do with the initialization process.
</div></div><div class="thread-post"><h3 class="thread-post-title">UDP-Stack crashes when J-Link not attached</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/edwards3">edwards3</a> on August 23, 2013</div><div class="thread-post-content">Does the atollic debugger run any scripts when it connects to or downloads to the target?&nbsp; like the IAR debugger does. Maybe it is doing some configuration in a debug script rather than in the source files.
</div></div><div class="thread-post"><h3 class="thread-post-title">UDP-Stack crashes when J-Link not attached</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/hisdudeness23">hisdudeness23</a> on August 23, 2013</div><div class="thread-post-content">Thanks for the suggestion edwards3,

I will take a closer look at the network drivers on the weekend and I will try to program some debugging interface on the serial port to get a little bit more information out of the microcontroller.
