</div></div><div class="thread-post"><h3 class="thread-post-title">how to monitor those task</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on August 9, 2013</div><div class="thread-post-content">Not sure I understand your question.&nbsp; Are you just asking how to tell if a task is still running?&nbsp; If so then this is done in all the standard demos.&nbsp; Have the task you are monitoring increment a number at key points in its functionality, then have a high priority monitoring task check the number is incrementing as expected.  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">how to monitor those task</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/vicui">vicui</a> on August 9, 2013</div><div class="thread-post-content">yes, i need to monitor one task is running or not . but those task blocks in lwip&#95;recv&#40;&#41; function and never exist, there is no demo about it 
</div></div><div class="thread-post"><h3 class="thread-post-title">how to monitor those task</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on August 9, 2013</div><div class="thread-post-content">One solution would be to have it not block with a large/infinite timeout, but to use a short timeout, and test for the time out, and when it happens set a flag to say you are running and go back into the block for a little bit. If the flag doesn&#8217;t get bumped over a time period longer than that timeout &#40;or any other busy time the task might have&#41; then you can assume something is wrong.  
The one problem with this, is that there isn&#8217;t much you can really do if a task dies, as you don&#8217;t really know what might need to be cleaned up.&nbsp; It isn&#8217;t like a process on a &#8220;big&#8221; computer which has a fully dedicated environment to run in and can be started anew.
