</div></div><div class="thread-post"><h3 class="thread-post-title">Arduino Due Interrupt Problems using RTOS</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on August 24, 2013</div><div class="thread-post-content">A quick scan of your code does not show anything obviously wrong &#8211; if the application was running &#8216;bare metal&#8217; &#40;say using Atmel Studio rather than the Arduino IDE&#41;, but I&#8217;m not familiar with the internal workings of the Arduino system.&nbsp; There could be a start up code issue perhaps, or a clash between a resource used by FreeRTOS and a resource used by Arduino, or even a problem because it is C++.  
<strong>However</strong>, in this case you are starting the scheduler from the setup&#40;&#41; function.&nbsp; If doing that is appropriate and the call passes then nothing past vTaskStartScheduler&#40;&#41; will be called because the tasks will be running, meaning your call to interrupts&#40;&#41; will never be executed, loop&#40;&#41; will never be executed, and the internal Arduino polling scheduler will never execute.&nbsp;   
If you wanted loop&#40;&#41; to be executed you could put it in the idle task hook.  
You could alternatively switch to Atmel Studio, the ASF Wizard has a FreeRTOS project that targets the Duo hardware.  
Regards.
