  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Timer Interrupt stop working after malloc</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/ricardo_crudo">ricardo_crudo</a> on August 19, 2013</div><div class="thread-post-content">I am using the FreeRTOS V7.4.2 with ARM-CM3 port &#40;NXP LPC1788&#41; and GCC cross compiler.   
Below is a pseudo code to reproduce my trouble:  
<pre><code>void main()
{
  setup_timer1_with_interrupt_1ms();
  /*   when the two below lines are commented, all works fine */
  char *p = pvPortMalloc(16);
  if (p) turn_on_led2();
  while(1);
  the_function();
  // task creations and other setups
  vTaskStartScheduler();
}
void timer1_handler(void)
{
  count_until_500_and_toggle_led1();
}
</code></pre>
When I run this piece of code the led1 don&#8217;t blink and the led2 turn on, but when I comment the malloc line the led1 blink, so, the Time1 interrupt stop working after allocate memory. I knew that malloc disable/re-enable the interrupts, so, Is possible that re-enable is not restoring the interrupts properly?  
</div></div><div class="thread-post"><h3 class="thread-post-title">Timer Interrupt stop working after malloc</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/ricardo_crudo">ricardo_crudo</a> on August 19, 2013</div><div class="thread-post-content">I noticed that after the scheduler is started the interrupt works properly. Is not possible use the interrupts while the scheduler is not running, even with timer priority out of configMAX&#95;SYSCALL&#95;INTERRUPT&#95;PRIORITY range? 
</div></div><div class="thread-post"><h3 class="thread-post-title">Timer Interrupt stop working after malloc</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on August 19, 2013</div><div class="thread-post-content">We always recommend leaving interrupts disabled until the scheduler has started, and, as your found out, if you call certain &#40;most&#41; API functions before the scheduler has started then interrupts will be left masked when the API function exits.&nbsp; Interrupts will automatically be enabled when the scheduler starts.  
However, I would only expect interrupts below configMAX&#95;SYSCALL&#95;INTERRUPT&#95;PRIORITY to be masked.  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">Timer Interrupt stop working after malloc</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/ricardo_crudo">ricardo_crudo</a> on August 19, 2013</div><div class="thread-post-content">Thanks for your reply Richard.  
My timer1 interrupt don&#8217;t use FreeRTOS API. I found a post with exact same situation that I am facing: <a href="http://www.embeddedrelated.com/groups/AT91SAM/show/4236.php%2C">http://www.embeddedrelated.com/groups/AT91SAM/show/4236.php,</a> and I guess that solution response it&#8217;s yours.  
My Makefile use -mthumb for all sources files, but I gotten a error when I tried use the -marm flag in gcc &#40;target CPU does not support ARM mode&#41;.&nbsp; And the -mthumb-interwork flag, build fine, but don&#8217;t work too.
