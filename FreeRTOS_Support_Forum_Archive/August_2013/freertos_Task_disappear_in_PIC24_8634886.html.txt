  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Task disappear in PIC24</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/ccliuhk">ccliuhk</a> on August 17, 2013</div><div class="thread-post-content">I am developing software for microchip microcontroller PIC24 &#40;PIC24EP&#41; and we choose FreeRTOS as OS.  
I find that after few hours running of our program, a task which is blocked forever. After tracking the problem, I find that it is waiting a message in a queue but the another task which should send message to the queue disappear.  
The situation is exactly as same as following post.  
<a href="https://sourceforge.net/projects/freertos/forums/forum/382005/topic/6754242">https://sourceforge.net/projects/freertos/forums/forum/382005/topic/6754242</a>  
Originally, I am using same FreeRTOSConfig.h from Demo. After reading above post, I tried to adjust configKERNEL&#95;INTERRUPT&#95;PRIORITY to higher priority level. However, it does not help.  
I wonder if anyone can help on it.
</div></div><div class="thread-post"><h3 class="thread-post-title">Task disappear in PIC24</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on August 17, 2013</div><div class="thread-post-content">Leave configKERNEL&#95;INTERRUPT&#95;PRIORITY at 1. Do you have any other interrupts in your system? If so, do they use any FreeRTOS API functions? If so, what priority are they running at, and can you post their code here?   
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">Task disappear in PIC24</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/ccliuhk">ccliuhk</a> on August 17, 2013</div><div class="thread-post-content">Yes. There are a number of interrupts in this system. For uart&#8217;s interrupt, they use FreeRTOS API &#40;ISR type&#41; for sending message to wake up waiting tasks. I am on the road and I may post them once backed home. BTW, what priority I should set for interrupt with using FreeRTOS APIs and without using APIs?
</div></div><div class="thread-post"><h3 class="thread-post-title">Task disappear in PIC24</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on August 17, 2013</div><div class="thread-post-content">According to the documentation on a PIC24 any task using the FreeRTOS API must run with the same priority as the kernel.
</div></div><div class="thread-post"><h3 class="thread-post-title">Task disappear in PIC24</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on August 17, 2013</div><div class="thread-post-content">Small correction to DaveDoors  
any INTERRUPT using the FreeRTOS API must run with the same priority as the kernel
