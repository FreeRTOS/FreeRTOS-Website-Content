  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Running FreeRTOS on Basys3 Board (Artix-7 FPGA) with MicroBlaze</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/droz">droz</a> on October 27, 2017</div><div class="thread-post-content">I&#8217;m trying to run FreeRTOS on the Basys3 board, which features the Artix-7 FPGA, with the MicroBlaze soft processor, but I&#8217;ve had issues with the lack of enough ILMB memory. The Basys3 has 1800Kb of BRAM on it, so the MicroBlaze can only have a maximum <strong>128 KB</strong> memory configuration. When I try making a new FreeRTOS &#8220;Hello World&#8221; application in Xilinx SDK,  gives me the error: 
&#8220;lab8bf.elf section <code>.bss' will not fit in region</code>microblaze<em>0</em>local<em>memory</em>ilmb<em>bram</em>if<em>cntlr</em>Mem<em>microblaze</em>0<em>local</em>memory<em>dlmb</em>bram<em>if</em>cntlr<em>Mem'&#8221; 
 `microblaze</em>0<em>local</em>memory<em>ilmb</em>bram<em>if</em>cntlr<em>Mem</em>microblaze<em>0</em>local<em>memory</em>dlmb<em>bram</em>if<em>cntlr</em>Mem&#8217; overflowed by <strong>61744 bytes</strong>  
My question is: how much memory does a basic FreeRTOS application need? Is there any way to decrease the size of the .bss region of a FreeRTOS .elf, or to allow MicroBlaze to increase its ILMB size further? 
</div></div><div class="thread-post"><h3 class="thread-post-title">Running FreeRTOS on Basys3 Board (Artix-7 FPGA) with MicroBlaze</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on October 27, 2017</div><div class="thread-post-content"><blockquote>
  My question is: how much memory does a basic FreeRTOS application need? 
</blockquote>
If you are talking about the application that uses FreeRTOS, then I have 
no idea, as its not my application and I&#8217;ve never seen it.  If you mean 
to ask how much RAM does FreeRTOS need then in itself it is very little 
(about 200 bytes), but you also need RAM for the stack of each task 
created.  The RAM for task stacks comes from the FreeRTOS heap, and the 
size of the FreeRTOS heap is set by the linker script if you are using 
heap<em>3.c, or configTOTAL</em>HEAP_SIZE if you are using any of the other 
four heap implementations.  I would recommend trying to reduce the heap 
size.
http://www.freertos.org/a00111.html
</div></div><div class="thread-post"><h3 class="thread-post-title">Running FreeRTOS on Basys3 Board (Artix-7 FPGA) with MicroBlaze</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rocco-matano">rocco-matano</a> on October 29, 2017</div><div class="thread-post-content">The standard projects that the Xilinx SDK (version 2017) creates request a heap size of 64k. That is done by creating a FreeRTOSConfig.h with the line
<code>#define configTOTAL_HEAP_SIZE ( ( size_t ) ( 65536 ) )</code>
I think this can be changed by editing the properties of the generated BSP.
While 64k is more than a simple application needs, you still need some heap space. Since the linker reports 61744 missing bytes, just reducing the heap size probably won&#8217;t be the only thing you have to change in order to fit your application into 128k.
</div></div><div class="thread-post"><h3 class="thread-post-title">Running FreeRTOS on Basys3 Board (Artix-7 FPGA) with MicroBlaze</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/droz">droz</a> on November 5, 2017</div><div class="thread-post-content">Thanks for the additional information. What is the smallest possible application that I can make that uses FreeRTOS on the MicroBlaze processor?  For now, I&#8217;m willing to use any sample program that will build in this 128 KB space. If the &#8220;FreeRTOS Hello World&#8221; application built into Xilinx SDK is too large, what could I do to bring it down to a more reasonable size? 
</div></div><div class="thread-post"><h3 class="thread-post-title">Running FreeRTOS on Basys3 Board (Artix-7 FPGA) with MicroBlaze</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on November 5, 2017</div><div class="thread-post-content">I would be very surprised if a &#8216;hello world&#8217; application that just sat
