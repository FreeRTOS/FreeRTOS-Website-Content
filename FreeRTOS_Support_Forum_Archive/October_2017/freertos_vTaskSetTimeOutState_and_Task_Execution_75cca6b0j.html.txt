  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">vTaskSetTimeOutState and Task Execution</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/groger57">groger57</a> on October 24, 2017</div><div class="thread-post-content">Hello:
I am presently using a task that waits for a binary semaphore &#8220;give&#8221; from the ISR. This works good. Now, I want to change that to a task that executes differently based on the existence of a response, or timeout, whicever occurs first. 
1 &#8211; A command is transmitted
2 &#8211; A response (1 byte) should be received in 2000ms. If not, set the sequence as &#8220;incomplete&#8221;
I know that I will be using vTaskSetTimeOutState. My question is this. How does the task that uses vTaskSetTimeOutState know that it should start executing and subsequently using up the 2000ms timeout? Does the task get created like any other task, then suspended, and resumed just after transmitting the command?
Thanks for your help, always appreciated!
FYI: The  current sempahore task:
static void prvCOMprocessTask( void <em>pvParameters )
{
    configASSERT( xCOMsemaphore );
    /</em> Take semaphore to get it to correct state. */
    xSemaphoreTake( xCOMsemaphore, mainDONT_BLOCK );
<pre><code>for( ;; )
{
xSemaphoreTake( xCOMsemaphore, portMAX_DELAY );
    /* do some stuff, I got a message.... */
}
</code></pre>
}
</div></div><div class="thread-post"><h3 class="thread-post-title">vTaskSetTimeOutState and Task Execution</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on October 24, 2017</div><div class="thread-post-content">It sounds like what you want to do is rather than wait for portMAX_DELAY, you wait for your timeout period, and check the return value of xSemaphoreTake(). If it is success, they you got the message, if it is a timeout error, you didn&#8217;t in the time period.
</div></div><div class="thread-post"><h3 class="thread-post-title">vTaskSetTimeOutState and Task Execution</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/groger57">groger57</a> on October 25, 2017</div><div class="thread-post-content">Ok, thanks! It makes sense&#8230;I will try it.
Just one other question &#8211; is there any advantage/disadvantage between this, and using vTaskSetTimeOutState ?
</div></div><div class="thread-post"><h3 class="thread-post-title">vTaskSetTimeOutState and Task Execution</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on October 25, 2017</div><div class="thread-post-content">I would use vTaskSetTimeOutState if you need to abort a wait for some other reason than a timeout, but still want a &#8216;failure&#8217;. Maybe something like the task is blocked on a queue waiting for a reply, but you get some sort of NAK or error instead, No need at that point to wait for the timeout, you can just tell the task no answer is comming.
