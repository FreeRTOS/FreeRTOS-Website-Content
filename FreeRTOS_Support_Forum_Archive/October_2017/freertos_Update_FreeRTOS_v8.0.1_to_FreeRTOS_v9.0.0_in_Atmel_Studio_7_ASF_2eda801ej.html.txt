The standard demo works perfectly. However, I want to use pdMS<em>TO</em>TICK() function, but it&#8217;s not defined, and it seems it was introduced in a later version of FreeRTOS which is not directly accesible from the ASF wizard in Atmel Studio 7.
What are the steps needed to update the FreeRTOS version to use v9 in Atmel Studio 7 for SAM L21 board? 
</div></div><div class="thread-post"><h3 class="thread-post-title">Update FreeRTOS v8.0.1 to FreeRTOS v9.0.0 in Atmel Studio 7 ASF </h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on October 18, 2017</div><div class="thread-post-content">Once Atmel studio has created the project you can just copy the latest 
FreeRTOS source files and header files over the top of the same files in 
the generated project.

How should this file be updated so the OLED demo can function with V9?
Moreover, asf.h from the original demo calls several FreeRTOSheader files, and the ASF wizard shows only v8.0.1. Should something be updated in the ASF header or anywhere else, to configure the ASF to use v9?
</div></div><div class="thread-post"><h3 class="thread-post-title">Update FreeRTOS v8.0.1 to FreeRTOS v9.0.0 in Atmel Studio 7 ASF </h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on October 23, 2017</div><div class="thread-post-content"><blockquote>
  I have done that replacement. I see there is still FreeRTOSConfig.h 
  header, which was created by the demo for V8.0.1.
</blockquote>
That should be backward compatible. 
http://www.freertos.org/FreeRTOS-V9.html
<blockquote>
  There is no demo for 
  SAML21 with v9.0.0 where I can copy this file from, only for SAMD20.
</blockquote>
There is no difference between the SAMD20 and SAML21 as far as the 
FreeRTOS code goes, use the same port files on both.
<blockquote>
  How should this file be updated so the OLED demo can function with V9?
</blockquote>
I don&#8217;t know what the OLED demo is, presumably Atmel code.
<blockquote>
  Moreover, asf.h from the original demo calls several FreeRTOSheader 
  files, and the ASF wizard shows only v8.0.1. Should something be updated 
  in the ASF header or anywhere else, to configure the ASF to use v9?
</blockquote>
You need to copy the V9 source (.c) and header (.h) files into the 
project.  Did you do that?  If so, then they are the files being built. 
Nothing in Atmel Studio will change, it won&#8217;t know you have updated the 
files so may still say the old version.

I have added both declarations following the instructions here: http://www.freertos.org/a00110.html#configSUPPORT<em>STATIC</em>ALLOCATION 
I added the two declarations into timers.c and tasks.c respectively copying the code from the previous link, but I get same error. I noticed the prototype in tasks.c says:
~~~
<h1>if( configSUPPORT<em>STATIC</em>ALLOCATION == 1 )</h1>
<pre><code>extern void vApplicationGetIdleTaskMemory( StaticTask_t **ppxIdleTaskTCBBuffer, StackType_t **ppxIdleTaskStackBuffer, uint32_t *pulIdleTaskStackSize );
</code></pre>
<h1>endif</h1>
~~~
I guess it&#8217;s just simply a matter of knowing where and how this functions should be defined&#8230; could a knowledgeable mind shed some light in here?
</div></div><div class="thread-post"><h3 class="thread-post-title">Update FreeRTOS v8.0.1 to FreeRTOS v9.0.0 in Atmel Studio 7 ASF </h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on October 26, 2017</div><div class="thread-post-content">vApplicationGetIdleTaskMemory() (and the timer task equivalent) can be 
implemented in any C file that is built, provided they are not declared 
static.  Grep the FreeRTOS/Demo directory to find several examples.  For 
example line 247 (at the time of writing) here: 
https://sourceforge.net/p/freertos/code/HEAD/tree/trunk/FreeRTOS/Demo/WIN32-MSVC-Static-Allocation-Only/main.c
