</div></div><div class="thread-post"><h3 class="thread-post-title">arduino freertos configTICK_RATE_HZ 62</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on October 24, 2017</div><div class="thread-post-content">Sorry &#8211; I&#8217;m not familiar with that port or how it runs.  In the demos we 
provide the configTICK<em>RATE</em>HZ constant is used in the port layer where 
the clock is set up to generate the RTOS tick interrupt.  That code gets 
called between vTaskStartScheduler() being called in the application 
code and the first task starting to run.  The application is statically 
linked so it runs when you boot the system up.  That last part might be 
different on the Arduino if you are downloading sketches to an already 
running system.
</div></div><div class="thread-post"><h3 class="thread-post-title">arduino freertos configTICK_RATE_HZ 62</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/tlafleur">tlafleur</a> on October 24, 2017</div><div class="thread-post-content">The Arduino ports of FreeRTOS that I have seen uses the watch dog timer for
