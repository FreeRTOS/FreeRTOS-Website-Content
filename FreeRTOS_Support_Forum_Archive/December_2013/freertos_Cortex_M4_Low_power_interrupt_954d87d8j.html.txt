I am doing some stability testing and have found that my build crashes within 24 hours. My build is using the ast timer as the ticks for freertos as the demo provides. I created an interrupt that uses a semaphore to resume a task. My interrupts are coming in at 200hz and set the priority level to be configLIBRARY<em>MAX</em>SYSCALL<em>INTERRUPT</em>PRIORITY. When running this The system freezes in under 24 hours. In this freezing I noticed the ast interrupts (ticks for freertos) and my external interrupts stop coming in also.<br />
This is how I set my interrupts. 
~~~~~~
    struct eic<em>line</em>config eic<em>line</em>conf;
<pre><code>ioport_set_pin_mode(PIN_PA16, MUX_PA16C_EIC_EXTINT1 | IOPORT_MODE_PULLUP);
ioport_disable_pin(PIN_PA16);
/* Setup Motion interrupt PIN as EIC*/
eic_line_conf.eic_mode = EIC_MODE_EDGE_TRIGGERED;
eic_line_conf.eic_edge = EIC_EDGE_FALLING_EDGE;
eic_line_conf.eic_level = EIC_LEVEL_LOW_LEVEL;
eic_line_conf.eic_filter = EIC_FILTER_DISABLED;
eic_line_conf.eic_async = EIC_ASYNCH_MODE;
eic_enable(EIC);
eic_line_set_config(EIC, EXT_INT1,
&amp;eic_line_conf);
eic_line_set_callback(EIC, EXT_INT1, cb,
EIC_1_IRQn, 1);
eic_line_enable(EIC, EXT_INT1);
sysclk_disable_peripheral_clock(EIC);
</code></pre>

~~~~~~
    static void cb(){
            SemaphoreGiveFromISR(sem<em>id);
        }
        void task(){
            for(;;){
                if(SemaphoreTake(sem</em>id){
                    //toggle led
                }
            }<br />
        }

</div></div><div class="thread-post"><h3 class="thread-post-title">Cortex M4 Low power interrupt</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on December 8, 2013</div><div class="thread-post-content"><blockquote>
   and set the priority level to be  configLIBRARY<em>MAX</em>SYSCALL<em>INTERRUPT</em>PRIORITY
</blockquote>
There is a comment in the code as follows:
/* Tick interrupt MUST execute at the lowest interrupt priority. */
Try setting the priority level to configLIBRARY<em>LOWEST</em>INTERRUPT_PRIORITY.
Also, when the ticks stop, look at the alarm value.  While creating a low power demo for another port I ensured the equivalent of the alarm value is never set to 0.  It doesn&#8217;t look like the same check is included in the SAM4L demo in the following place in the code:
<code>
<pre>
/* The alarm value is set to whatever fraction of a single tick period remains. */
ulAlarmValue = ast_read_counter_value( AST ) - ( ulCompleteTickPeriods * ulAlarmValueForOneTick );
ast_write_alarm0_value( AST, ulAlarmValue );
</pre>
</code>
Try adding the following lines in between those two lines (which are in SAM4L<em>low</em>power<em>tick</em>management.c).
<code>
<pre>
if( ulAlarmValue == 0 )
{
    /* There is no fraction remaining. */
    ulAlarmValue = ulAlarmValueForOneTick;
    ulCompleteTickPeriods++;
}
</pre>
</code>
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">Cortex M4 Low power interrupt</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on December 8, 2013</div><div class="thread-post-content">See https://sourceforge.net/p/freertos/code/HEAD/tree/trunk/FreeRTOS/Demo/CORTEX<em>M4</em>ATSAM4L<em>Atmel</em>Studio/src/SAM4L<em>low</em>power<em>tick</em>management.c
Note that change will only make a difference if something other than the tick interrupt brings the MCU out of its sleep state.
