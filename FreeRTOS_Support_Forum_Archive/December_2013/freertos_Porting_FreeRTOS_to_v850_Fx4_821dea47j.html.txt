  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Porting FreeRTOS to v850 Fx4</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/huzhiping">huzhiping</a> on December 13, 2013</div><div class="thread-post-content">I am trying to port FreeRTOS to v850 Fx4 based on Fx3, but using GreenHills compiler.
Sereval issues found:
1. From FreeRTOS offical website, it is said &#8220;6.If the stack on the microcontroller being ported to grows downward from high memory to low memory then set portSTACK<em>GROWTH in portmacro.h to -1, otherwise set portSTACK</em>GROWTH to 0.&#8221; &#8211;> in here, http://www.freertos.org/FreeRTOS-porting-guide.html&#8230;, if you set &#8220;portSTACK<em>GROWTH to 0&#8243;, then you got a compiler error, &#8220;pxEndOfStack&#8221; is undefined, you have to set &#8220;portSTACK</em>GROWTH to be greater than 0&#8243;, which in Tasks.c, the condition is &#8220;portSTACK_GROWTH > 0&#8221;.
<ol>
<li>I created 2 simple tasks with function by setting a different LED ON in each task, When I using debugger, 2 tasks (priority is different, task 2 is 2, task1 is 1) and the idle task all created successfully, but in function &#8220;xPortStartScheduler()&#8211;>vPortStart() -> portRESTORE<em>CONTEXT (assembly macro), it can NOT get the right address of &#8220;</em>pxCurrentTCB&#8221; that is for task2. my vPortStart() function is:</li>
</ol>
<em>vPortStart:
    portRESTORE</em>CONTEXT                     &#8212; Restore the context of whichever task the &#8230;
    ld.w    0[sp],lp
    ldsr    lp,5                            &#8212; restore PSW
    DI
    ld.w    4[sp],lp                        &#8212; restore LP
    ld.w    8[sp],lp                        &#8212; restore LP
    ADD     0x0C,sp                         &#8212; set SP to right position
    EI
    jmp     [lp]
<ol>
<li>I tried different heap<em>x.c, I found each time after call vPortStat()->portRESTORE</em>CONTEXT
the stack pointer of &#8220;<em>pxCurrentTCB&#8221; is different. I double checked the &#8220;portRESTORE</em>CONTEXT&#8221; and &#8220;portSAVE_CONTEXT&#8221;, it looks like correct.
I attched these assembly macro below:</li>
</ol>
.macro portSAVE<em>CONTEXT
    prepare {r20,r21,r22,r23,r24,r26,r27,r28,r29,r30},18,sp     &#8212; save general purpose registers
    sst.w   r19,68[ep]
    sst.w   r18,64[ep]
    sst.w   r17,60[ep]
    sst.w   r16,56[ep]
    sst.w   r15,52[ep]
    sst.w   r14,48[ep]
    sst.w   r13,44[ep]
    sst.w   r12,40[ep]
    sst.w   r11,36[ep]
    sst.w   r10,32[ep]
    sst.w   r9,28[ep]
    sst.w   r8,24[ep]
    sst.w   r7,20[ep]
    sst.w   r6,16[ep]
    sst.w   r5,12[ep]
    sst.w   r2,8[ep]
    sst.w   r1,4[ep]
    MOVHI   hi(</em>usCriticalNesting),r0,r1             &#8212; save usCriticalNesting value to stack
    ld.w    lo(<em>usCriticalNesting)[r1],r2
    sst.w   r2,0[ep]
    MOVHI   hi(</em>pxCurrentTCB),r0,r1                  &#8212; save SP to top of current TCB
    ld.w    lo(_pxCurrentTCB)[r1],r2
    st.w    sp,0[r2]
.endm
.macro portRESTORE<em>CONTEXT
    MOVHI   hi(</em>pxCurrentTCB),r0,r1          &#8212; get Stackpointer address
    ld.w    lo(<em>pxCurrentTCB)[r1],sp
    MOV     sp,r1
    ld.w    0[r1],sp                        &#8212; load stackpointer
    MOV     sp,ep                           &#8212; set stack pointer to element pointer
    sld.w   0[ep],r1                        &#8212; load usCriticalNesting value from stack
    MOVHI   hi(</em>usCriticalNesting),r0,r2
    st.w    r1,lo(_usCriticalNesting)[r2]
    sld.w   4[ep],r1                        &#8212; restore general purpose registers
    sld.w   8[ep],r2
    sld.w   12[ep],r5
    sld.w   16[ep],r6
    sld.w   20[ep],r7
    sld.w   24[ep],r8
    sld.w   28[ep],r9
    sld.w   32[ep],r10
    sld.w   36[ep],r11
    sld.w   40[ep],r12
    sld.w   44[ep],r13
    sld.w   48[ep],r14
    sld.w   52[ep],r15
    sld.w   56[ep],r16
    sld.w   60[ep],r17
    sld.w   64[ep],r18
    sld.w   68[ep],r19
    dispose 18,{r20,r21,r22,r23,r24,r26,r27,r28,r29,r30}
.endm
I don&#8217;t know how to do it next, hopefully I can get help from you.
Thanks in advance!
Albert
