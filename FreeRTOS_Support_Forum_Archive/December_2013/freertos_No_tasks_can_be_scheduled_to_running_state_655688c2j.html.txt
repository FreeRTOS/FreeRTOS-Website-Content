  I&#8217;m face a problem while trying to startup LM3S811 on qemu.
  I have build and run Demo:CORTEX<em>LM3S811</em>GCC on qemu, what modification I&#8217;ve made is just removing all existing tasks and then creating one task which will print message periodically. But after vTaskStartScheduler run, there is no any message printed out.
   xTaskCreate( vAliveTask, &#8220;Alive&#8221;, configMINIMAL<em>STACK</em>SIZE, NULL, configMAX_PRIORITIES &#8211; 1, NULL );
218 static void vAliveTask( void *pvParameters )
219 {
220         OSRAMClear();
221         OSRAMStringDraw(&#8220;Start&#8221;, 0, 0);
222 
223         while (1)
224         {
225                 OSRAMClear();
226                 OSRAMStringDraw(&#8220;ALIVE &#8230;&#8221;, 0, 0);
227                 vTaskDelay( 2000 / portTICK_RATE_MS );
228         }
229 }
$ qemu-system-arm -machine lm3s811evb -kernel gcc/RTOSDemo.axf
   I have debugged this issue by gdb and found that xPortPendSVHandler has never been called, this means no context switch occurred. So my question is: did I miss any configurations or are there any mistakes I&#8217;ve made?
Thanks!
</div></div><div class="thread-post"><h3 class="thread-post-title">No tasks can be scheduled to running state</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on December 20, 2013</div><div class="thread-post-content">I&#8217;m afraid we cannot provide direct support for code running in emulators &#8211; we have no idea if your code will run in the emulator or not, especially when you are attempting to use the OSRAM display.
In this case, as you ask a specific question, I can only provide the same answer as if you were running on a real Cortex-M device, and that would be to ask if you are sure you have actually installed the FreeRTOS interrupt service routines correctly.  See the &#8220;Note for Cortex-M users&#8221; section of the first FAQ on this page: http://www.freertos.org/FAQHelp.html
