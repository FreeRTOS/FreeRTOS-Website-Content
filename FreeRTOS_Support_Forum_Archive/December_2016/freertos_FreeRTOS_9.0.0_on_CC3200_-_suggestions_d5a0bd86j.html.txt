  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">FreeRTOS 9.0.0 on CC3200 &#8211; suggestions</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/mimmux">mimmux</a> on December 16, 2016</div><div class="thread-post-content">Hi All,
First of all, thanks for your great work!
I&#8217;ve recently downloaded FreeRTOS 9.0.0 and tried to run it on a TI CC3200 LaunchPad using GCC
Now, neither the ARM<em>CM4F nor the ARM</em>CM4_MPU ports seem to work.
So I had a look at the port ARM<em>CM4 that is shipped by Texas Instruments in their CC3200 SDK for FreeRTOS 8.0.1, and to my untrained eye it seemed pretty similar to the ARM</em>CM3 port. And I tried both the old port by TI, and the FreeRTOS 9.0.0 port for ARM_CM3, and they both seem to work on a simple example using tasks and queues.
My questions would be:
1. Is it likely that this board becomes directly supported by FreeRTOS?
2. Is the approach of using the ARM<em>CM3 port correct? Or would it be better to use the ARM</em>CM4 port shipped by TI for FreeRTOS 8.0.1 ?
Thank you very much.
Dom.
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS 9.0.0 on CC3200 &#8211; suggestions</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on December 16, 2016</div><div class="thread-post-content">The port to use depends on the hardware available in the MCU device.
If the MCU has a floating point unit (FPU) then use the 
/FreeRTOS/Source/portable/ARM_CM4F port code.
If the MCU does not have an FPU, or the FPU is going to be left 
disabled, then use the /FreeRTOS/Source/portable/ARM_CM3 port code &#8211; 
even if the MCU is actually an M4.
Hope that helps.
