  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">STM32F4 bootloader with freeRTOS+TCP</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/unknown49">unknown49</a> on December 14, 2016</div><div class="thread-post-content">Hi, 
I am working on a project that requires a us to push updates to our embedded board. We have already developed the API for getting the updates from the server and storing it in Flash. 
We know need a bootloader that automatically applies that update by overwriting flash with the binary file. Can anyone provide help on doing this. I am hoping that someone may have already implemented a bootloader this. 
We have a basic idea on how to write the bootloader but not sure what required on freeRTOS side, since RTOS won&#8217;t be starting at the resert vector (0x8000000)
</div></div><div class="thread-post"><h3 class="thread-post-title">STM32F4 bootloader with freeRTOS+TCP</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on December 14, 2016</div><div class="thread-post-content">For which platform / MCU are you developing?
Both your application as well as your bootloader can run FreeRTOS.  Each program has its own interrupt table and its own copy of the kernel.  The compiler will make sure that your <code>main()</code> will get called, and that function will start the FreeRTOS kernel.
It sounds like your bootloader will need some code to read the binary image and to program the application flash.
</div></div><div class="thread-post"><h3 class="thread-post-title">STM32F4 bootloader with freeRTOS+TCP</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/dibosco">dibosco</a> on December 14, 2016</div><div class="thread-post-content">I&#8217;ve done bootloaders for the STM32F4. The vital thing is to reset the VTOR register to point to the new vector table and clear and disable all interrupts before you jump to the new app as well as stopping the sys tick &#8211; the latter has really stumped me in the past.  I had a situation where I was jumping to the new app, the sys tick timer went off and was trying to jump to the next thread before any threads were initialised! 
This kind of thing works well for me going from a run to complete or from FreeRTOS.
~~~
typedef  void (*pFunction)(void);
pFunction Jump_To_Application;
<h1>define APPLICATION<em>START</em>ADDRESS 0x8008000</h1>
void JumpToNormalApplication(void)
{
<pre><code>    volatile uint32_t JumpAddress;
    uint32_t temp;
   // Disable all interrupts
    NVIC-&gt;ICER[0] = 0xFFFFFFFF;
    NVIC-&gt;ICER[1] = 0xFFFFFFFF;
    NVIC-&gt;ICER[2] = 0xFFFFFFFF;
</code></pre>
  // Clear pendings 
        NVIC->ICPR[0] = 0xFFFFFFFF;
        NVIC->ICPR[1] = 0xFFFFFFFF;
        NVIC->ICPR[2] = 0xFFFFFFFF;
// Stop sys tick
        temp = SysTick->CTRL;
        temp &amp;= ~0x02;
        SysTick->CTRL = temp;
<pre><code>    SCB-&gt;VTOR = (unsigned long)APPLICATION_START_ADDRESS;
     JumpAddress = *(volatile unsigned long*) (APPLICATION_START_ADDRESS + 4);
     Jump_To_Application = (pFunction) JumpAddress;
      Jump_To_Application();
</code></pre>
}
~~~
This is for going from bootloader to the new, updated, application. For going the other way (if relevant) use the same type of thing, but change:
<code>#define APPLICATION_START_ADDRESS</code> 0x8008000
to
<code>#define APPLICATION_START_ADDRESS 0x8000000</code>
Please note that the APPLICATION<em>START</em>ADDRESS will change depending on how big the bootloader is.  I&#8217;ve managed to fit a USART one into a very small amount of flash; USB and Ethernet versions obviously take a lot more space. Only you&#8217;ll be able to know &#8211; when you&#8217;ve finished the bootloader. Remember to check for page sizes. Some devices have larger page sizes at different parts of memory. I can never remember without checking the manuals whether it&#8217;s the SAM devices or STM32 that don&#8217;t have the same page sizes all the way through memory. 
If you need any functions for writing the actual code to flash from inside the bootloader I can send you that.
