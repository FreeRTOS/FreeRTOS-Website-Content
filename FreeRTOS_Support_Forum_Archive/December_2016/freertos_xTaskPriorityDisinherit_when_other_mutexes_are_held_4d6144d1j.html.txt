  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">xTaskPriorityDisinherit when other mutexes are held</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/eklundn">eklundn</a> on December 8, 2016</div><div class="thread-post-content">Hi.
In the function xTaskPriorityDisinherit there is the following check:
~~~
                /* Only disinherit if no other mutexes are held. */
                if( pxTCB->uxMutexesHeld == ( UBaseType_t ) 0 )
~~~
Why does the task not disinherit priority when other mutexes are held? The other mutexes might have a lower priority than the current one, but still higher than uxBasePriority.
Best regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">xTaskPriorityDisinherit when other mutexes are held</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on December 8, 2016</div><div class="thread-post-content">This is a simplification in the priority inheritance implementation done 
in the interest of simplicity.  A full priority inheritance 
implementation is complex due to the number of scenarios (there are many 
combinations of the order in which tasks of various priority can take 
and release semaphores) and thus results in a lot of additional code and 
data space requirements for scenarios that almost never occur &#8211; hence we 
opted to implement this simplification.
</div></div><div class="thread-post"><h3 class="thread-post-title">xTaskPriorityDisinherit when other mutexes are held</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/eklundn">eklundn</a> on December 12, 2016</div><div class="thread-post-content">Thanks for the reply. Is there any write up on the alternative, full priority inheritance implementation? And the different situations that are handled or unhandled?
Because at first sight (actually quite many read through) of the code, it seems possible add full support in very few lines of code. First remove the line in my first post, then add lines that set pxTCB->uxPriority to the highest priority of any task that is blocked by other held mutexes, or to pxTCB->uxBasePriority if no tasks of higher priority is blocked.
Would there be any implications of this proposal?
Best regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">xTaskPriorityDisinherit when other mutexes are held</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on December 12, 2016</div><div class="thread-post-content"><blockquote>
  add lines that set pxTCB->uxPriority to the highest priority of any task that is blocked by other held
  mutexes
</blockquote>
There is no way to get that information.
</div></div><div class="thread-post"><h3 class="thread-post-title">xTaskPriorityDisinherit when other mutexes are held</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/eklundn">eklundn</a> on December 14, 2016</div><div class="thread-post-content"><blockquote>
  There is no way to get that information.
</blockquote>
Well, it could be done by changing <code>uxMutexesHeld</code> to a (linked) list of held mutexes. Then for each <code>mutex</code> in <code>uxMutexesHeld</code> in <code>xTaskPriorityDisinherit</code> do something like:
~~~
xTCB *pxWaitingTCB = listGET_OWNER_OF_HEAD_ENTRY(mutex->xTasksWaitingToReceive);
if( NULL != pxWaitingTCB &amp;&amp; pxWaitingTCB->uxPriority > uxDisinheritPriority)
{
    uxDisinheritPrioriy = pxWaitingTCB->uxPriority;
}
~~~
Finaly setting <code>pxTCB-&gt;uxPriority = uxDisinheritPriority;</code>
It is not much code and it will not generate significant performance impact since the list of mutexes held will probably be quite short.
