</div></div><div class="thread-post"><h3 class="thread-post-title">Interrupts with FreeRTOS task causing task overflow</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on December 17, 2016</div><div class="thread-post-content">It sounds like there could be something in the ISR that is stomping over 
the task&#8217;s stack.  Assuming you have configCHECK<em>FOR</em>STACK_OVERFLOW set 
to 2 then the stack overflow will be noted if anything writes over the 
end of the task stack.  Normally that memory will get written too 
because the task stack has grown too large, but it could be anything 
that writes to that memory.
