  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Hangs on PIC32 uxPortSetInterruptMaskFromISR</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/l4na">l4na</a> on July 22, 2013</div><div class="thread-post-content">Hi, I just started using FreeRTOS &#40; PIC32 &#41; and got an issue once I call xSemaphoreGiveFromISR. I call this API from an interrupt that is set to priority 1. I narrow down the hang to the uxPortSetInterruptMaskFromISR, when it tries to &#95;CP0&#95;SET&#95;STATUS. Couple of questions :<br />
1&#46; uxSavedStatusRegister = &#95;CP0&#95;GET&#95;STATUS&#40;&#41; | 0x01;<br />
Is this call really needed?&nbsp; when the interrupt happens, the IE bit should already set unless it is disable by the &#8220;asm volatile &#40;&#8221;di&#8221;&#41;&#8221; ? Any idea what might cause the hang? What puzzling is the Timer tick interrupt is also running with priority 1 and it has no issue.  
2&#46; portALL&#95;IPL&#95;BITS is set to 0x3fUL. From what I read in PIC32 spec, the IPL bits are bit 10-12 &#40;3bits&#41;, shouldn&#8217;t this value be 0x7UL ?  
Thanks.   
</div></div><div class="thread-post"><h3 class="thread-post-title">Hangs on PIC32 uxPortSetInterruptMaskFromISR</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/l4na">l4na</a> on July 22, 2013</div><div class="thread-post-content">Some update on issue 1, I found out the hang is caused by the interrupt bit is not yet cleared when I call that function.&nbsp; So as long as I clear the interrupt bit before calling the uxPortSetInterruptMaskFromISR , everything works fine.   
</div></div><div class="thread-post"><h3 class="thread-post-title">Hangs on PIC32 uxPortSetInterruptMaskFromISR</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on July 22, 2013</div><div class="thread-post-content">Are you following the instructions in the &#8220;Interrupt Service Routines&#8221; section of the following page: <a href="http://www.freertos.org/port_PIC32_MIPS_MK4.html">http://www.freertos.org/port_PIC32_MIPS_MK4.html</a> ?&nbsp; You should never find interrupts are disabled inside the interrupt handler unless you disabled them.  
Regards.
