</div></div><div class="thread-post"><h3 class="thread-post-title">vTaskDelay(250) causes a “Hard Fault&#038;&#8230;</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on July 1, 2013</div><div class="thread-post-content"><blockquote>

</div></div><div class="thread-post"><h3 class="thread-post-title">vTaskDelay(250) causes a “Hard Fault&#038;&#8230;</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on July 1, 2013</div><div class="thread-post-content">The stack in use when you call main&#40;&#41; is recycled for use by all interrupt handlers.  
The stack used by tasks is <a href="http://www.freertos.org/a00111.html">allocated when the task is created</a>.  
So when an interrupt occurs the stack pointer is switched from the stack used by the interrupted task, so the stack that was originally used by main&#40;&#41;.&nbsp; If that was not done then <strong>each task</strong> would have to allocate enough&nbsp; space on its stack for the maximum possible interrupt nesting depth, rather than having this space allocated just one.&nbsp;   
Note the run time stack overflow checking only checks the task stacks because the scheduler knows how big each task stack is.&nbsp; It does not check the interrupt stack because it does not know &#40;in a portable way&#41; how big that is.  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">vTaskDelay(250) causes a “Hard Fault&#038;&#8230;</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/travfrog">travfrog</a> on July 1, 2013</div><div class="thread-post-content">Richard, just to be clear, if I start main and immediately create a few auto variables &#8211; they will be put in the main &#8216;C&#8217; stack.   
Once the scheduler runs, those auto-variables still occupy the stack right so when the OS starts using it, the stack is actually that much shorter?  
Mike, be aware that any initialization you are doing before starting the scheduler uses the main stack so it has to be large enough to handle deep calls to initialization routines &#8211; especially if those routines create temporary arrays.
</div></div><div class="thread-post"><h3 class="thread-post-title">vTaskDelay(250) causes a “Hard Fault&#038;&#8230;</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on July 1, 2013</div><div class="thread-post-content">No, when the scheduler starts the stack pointer is set back to the start of the stack, so interrupts have the whole stack available.&nbsp;&nbsp; There is no way back to main&#40;&#41; once the scheduler has started so there is no point in preserving any variables that were put on main&#8217;s stack before the scheduler was started.  
Regards.
