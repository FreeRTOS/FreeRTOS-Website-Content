I&#8217;m having some trouble with the tick rate. I am using the CORTEX<em>STM32F107</em>GCC_Rowley demo, but on a different board with the same exact chip and crystal clock frequency of 25MHz. The prvSetupHardware() func sets the clock up for 62.5MHz. I have I2C and UART working at the correct rates. What I can can&#8217;t seem to get working at the expected timing is the tick rate. My tick rate is set for 1000Hz. When I run a single and simple task that simply toggles a pin and then vTaskDelayUntil for 1 tick, it ends up being ~30ms when it should be 1ms. I&#8217;ve been trying to figure out what I&#8217;m doing wrong, but haven&#8217;t. Any help is greatly appreciated!
Thank you
I am using:
Chip: STM32F107VC (Cortex-M3)
Compiler: arm-none-eabi-gcc
Version: FreeRTOS V8.0.1
</div></div><div class="thread-post"><h3 class="thread-post-title">Tick Rate Problem</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/edwards3">edwards3</a> on December 23, 2014</div><div class="thread-post-content">You have set your tick to give you a resolution of 1ms, so if you try and block for 1ms I would expect to block for between 0.00001 and 0.99999ms, so you will get odd results, but you should not get longer than 1ms. If you are getting 30ms then likely the SysTick clock in your STM32 is not running at the frequency you think it is. The SysTick is part of the core of the STM32.

  RCC_DeInit();

  {
  }

  *( ( unsigned long * ) 0x40022000 ) = 0x02;
  /* HCLK = SYSCLK */
  RCC_HCLKConfig( RCC_SYSCLK_Div1 );

  RCC_PCLK2Config( RCC_HCLK_Div1 );

</div></div><div class="thread-post"><h3 class="thread-post-title">Tick Rate Problem</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/k3nt00">k3nt00</a> on December 24, 2014</div><div class="thread-post-content">Thank you very much for your responses!
I found the problem.
Apologies for the lack of relevance to FreeRTOS. 
In the demo program, the prvSetupHardware() function sets the clock as so:
~~~~~~
  /* PLLCLK = (25MHz / 2 ) * 5 = 62.5 MHz. */
  RCC_PLLConfig( RCC_PLLSource_HSI_Div2, RCC_PLLMul_5 );
~~~~~~
But in the most recent stm32f10x<em>rcc.h, RCC</em>PLLSource<em>HSE</em>Div2 is not defined for STM32F10X_CL, which is this chip.
~~~~~~
/** @defgroup PLL<em>entry</em>clock_source 
  * @{
  */
<h1>define RCC<em>PLLSource</em>HSI<em>Div2           ((uint32</em>t)0x00000000)</h1>
<h1>if !defined (STM32F10X<em>LD</em>VL) &amp;&amp; !defined (STM32F10X<em>MD</em>VL) &amp;&amp; !defined (STM32F10X<em>HD</em>VL) &amp;&amp; !defined (STM32F10X_CL)</h1>
 #define RCC<em>PLLSource</em>HSE<em>Div1           ((uint32</em>t)0x00010000)
 #define RCC<em>PLLSource</em>HSE<em>Div2           ((uint32</em>t)0x00030000)
 #define IS<em>RCC</em>PLL<em>SOURCE(SOURCE) (((SOURCE) == RCC</em>PLLSource<em>HSI</em>Div2) || 
                                   ((SOURCE) == RCC<em>PLLSource</em>HSE<em>Div1) || 
                                   ((SOURCE) == RCC</em>PLLSource<em>HSE</em>Div2))
<h1>else</h1>
 #define RCC<em>PLLSource</em>PREDIV1            ((uint32<em>t)0x00010000)
 #define IS</em>RCC<em>PLL</em>SOURCE(SOURCE) (((SOURCE) == RCC<em>PLLSource</em>HSI<em>Div2) || 
                                   ((SOURCE) == RCC</em>PLLSource_PREDIV1))
<h1>endif /* STM32F10X_CL */</h1>
~~~~~~
I used the value ((uint32_t)0x00030000), and I am now getting ~10ms.
