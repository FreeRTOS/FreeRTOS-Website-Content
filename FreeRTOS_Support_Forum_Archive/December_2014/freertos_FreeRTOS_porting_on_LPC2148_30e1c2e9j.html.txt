</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS porting on LPC2148</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on December 2, 2014</div><div class="thread-post-content">You don&#8217;t say which compiler you are using, but from the syntax I am <strong><em>guessing</em></strong> (I love guessing) it is Keil?  In which case you would need to also include an assembly file in your project &#8211; which is called portASM.s.  As your code is compiling and running, up to a point anyway, I presume you are already building the required asm file.
Are you sure it is crashing in the function you state, rather than completing that function, starting a task, then crashing in the task.  You can step through the code to determine that, and if you step through the code you will also see the definition of vPortStartFirstTask().
If it is crashing in vPortStartFirstTask() then the most likely cause is the processor is in the wrong state when main() is called.  It needs to be in Supervisor state.  This used to be an FAQ when ARM7 was the most common architecture, but is rarely mentioned now.
Regards.

</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS porting on LPC2148</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on December 5, 2014</div><div class="thread-post-content">I would recommend starting with a simpler system.
First have just one task that does this:
volatile uint32_t ulTask1 = 0, ulTask2 = 0;
void vTask1( void *pvParameters )
{
     for( ;; )
     {
         ulTask1++;
         taskYIELD();
     }
}
to check a task can yield to itself, ulTask1 should increment very quickly.
then add a second task at the same priority:
void vTask2( void *pvParameters )
{
     for( ;; )
     {
         ulTask2++;
         taskYIELD();
     }
}
to check both ulTask1 and ulTask2 increment.
Then you can add in blocking code, etc. to check that is working too.
Regards.
