  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">&#8220;static clustering&#8221; option on IAR optimization causes hard fault </h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/kilombo">kilombo</a> on December 7, 2014</div><div class="thread-post-content">Hello all&#8230;
I am using STM32L151 family with IAR 6.21 on my FreeRTOS project and I have encountered some problems with &#8220;xQueueSend&#8221; and &#8220;xQueueSendFromISR&#8221; functions.
When using these functions from my tasks, it causes the CPU generate a &#8220;hard fault&#8221; interrupt.
I traced the problem to the function that copies the data to the queue( where the number of bytes to copy is messed up). After a lot of debugging time, I have found that when I un-check the box of &#8220;static clustering&#8221; option on IAR optimizer, the program runs fine without the &#8220;hard fault&#8221;.
So, I have a few qeustions regarding this phenomena. Have anyone encountered a similar problem?
Anyone knows what is &#8220;static clustering&#8221; option on IAR optimizer (I have looked on IAR documentation but the explanation is hardly satisfaing)?
And the most important, what can I do to make it work? Assume I want to keep the level of optimization as high as possible.
Thank you.
Itay     
</div></div><div class="thread-post"><h3 class="thread-post-title">&#8220;static clustering&#8221; option on IAR optimization causes hard fault </h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on December 7, 2014</div><div class="thread-post-content">This is a known thing, and is &#8216;normally&#8217; the case.  Generally in EWARM you can set optimisaiton to maximum, then manually uncheck the static clustering option.  I have never worked out why, and, as you say, the documentation on what static clustering does is not informative (just something like &#8220;makes statics cluster&#8221;, or &#8220;clusters statics when turned on&#8221;, &#8230;).  I would guess it was doing something to place certain variables near each other for faster access, but it is a guess.
All demos are tested with zero, maximum speed and maximum code size optimisations, and this one option (specific to IAR) is the only one we are aware of that causes an issue.
Regards.

Itay.
