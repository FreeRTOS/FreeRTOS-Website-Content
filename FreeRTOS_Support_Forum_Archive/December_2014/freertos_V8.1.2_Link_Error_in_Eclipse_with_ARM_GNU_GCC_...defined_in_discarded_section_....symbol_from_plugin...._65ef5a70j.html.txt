  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">V8.1.2 Link Error in Eclipse with ARM GNU GCC &#8230;defined in discarded section &#8230;.symbol from plugin&#8230;.</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/mrichmond68">mrichmond68</a> on December 11, 2014</div><div class="thread-post-content">I am working from the V8.1.2 GCC/ARM<em>CM3 port.  I have successfully built myself a demo in Eclipse(Kepler), my arm gcc is 4</em>8_2014q3, my hardware is an STM32F103RE processor based board.  I&#8217;m also using gnuarmeclipse plugins.
When first building, I received the following link error.  I&#8217;ve fixed it, but I suspect something else is wrong and I&#8217;m just masking my real problem with my &#8220;fix&#8221;.  Just putting this out there to see what folks think.  
Here is the link error (-flto is being used in the compile/link process): 
<hr />
<blockquote>
  &#8216;C:UsersmrichmonAppDataLocalTempccq0f0ed.ltrans0.ltrans.o&#8217;
  <code>vTaskSwitchContext' referenced in section</code>.text.PendSV<em>Handler.4125&#8242; of C:UsersmrichmonAppDataLocalTempccq0f0ed.ltrans0.ltrans.o: defined in discarded section <code>.text' of ./FreeRTOS_Source/source/tasks.o (symbol from plugin)</code>pxCurrentTCB&#8217; referenced in section <code>.text.PendSV_Handler.4125' of C:UsersmrichmonAppDataLocalTempccq0f0ed.ltrans0.ltrans.o: defined in discarded section</code>.text&#8217; of ./FreeRTOS</em>Source/source/tasks.o (symbol from plugin)
  <code>pxCurrentTCB' referenced in section</code>.text.SVC<em>Handler.4140&#8242; of C:UsersmrichmonAppDataLocalTempccq0f0ed.ltrans0.ltrans.o: defined in discarded section `.text&#8217; of ./FreeRTOS</em>Source/source/tasks.o (symbol from plugin)
  collect2.exe: error: ld returned 1 exit status
</blockquote>
<hr />
I tracked down the two resources being unceremoniously &#8220;discarded&#8221; during the the linking process:
<strong>vTaskSwitchContext()</strong>
<strong>pxCurrentTCBG</strong>
I fixed the problem by adding the attribute &#8220;used&#8221; to both resources (yes, I modified source code &#8212;icky right?).  
Defined in FreeRTOSConfig.h with a big juicy note:
<pre><code>    #define KEEP_ME     __attribute__((used))
</code></pre>
Modified in tasks.c
<pre><code>    void KEEP_ME vTaskSwitchContext( void )
    { . . . }
    PRIVILEGED_DATA TCB_t * volatile pxCurrentTCB KEEP_ME = NULL;
</code></pre>
So maybe -flto is the problem &#8212; but maybe I&#8217;ll want to use it for my app.  Are my only two options to avoid -flto or use the &#8220;used&#8221; attribute?  Does either choice represent a good practice?
Thanks!!
mjr

On the occasion I did have such a problem it was, if I recall correctly, because a symbol was only used in an assembly file.
