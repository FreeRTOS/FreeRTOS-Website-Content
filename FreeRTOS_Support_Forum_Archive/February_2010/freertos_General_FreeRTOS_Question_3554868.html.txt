  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">General FreeRTOS Question</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/ohm8">ohm8</a> on February 15, 2010</div><div class="thread-post-content">Hello,  
Hi. I&#8217;m new to FreeRTOS, and had some questions about the &#8220;Using the FreeRTOS Real Time Kernel &#8211; A Practical Guide.pdf&#8221; manual.  
1&#41; On page 28 there is a statement concerning the Idle Task Hook &#40;where you can put user defined code into the Idle Task: &#8220;Blocking the idle task in any way could therefore cause a scenario where no tasks are available to enter the Running state&#33;&#8221;. I know NOT to do this, but if the Idle task is the lowest priority, why would it block higher priority tasks? Does blocking the Idle task prevent the Kernal from transitioning task execution?  
2&#41; .On pages 26 and 27 it descusses how a periodic high-priority task preempts two lower priority tasks when a given time is reached. According to the output, the high priority task only prints its message after the time is reached. Should it not also print out its message as the first line of output, since it is the highest priority task?   
I would appreciate any insight. Thanks.  
Terry  
</div></div><div class="thread-post"><h3 class="thread-post-title">General FreeRTOS Question</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on February 15, 2010</div><div class="thread-post-content"><blockquote>
  1&#41; On page 28 there is a statement concerning the Idle Task Hook &#40;where you can put user defined code into the Idle Task: &#8220;Blocking the idle task in any way could therefore cause a scenario where no tasks are available to enter the Running state&#33;&#8221;. I know NOT to do this, but if the Idle task is the lowest priority, why would it block higher priority tasks? Does blocking the Idle task prevent the Kernal from transitioning task execution?
</blockquote>
As you rightly say, the idle task does run at the very lowest priority, so will not block a higher priority task from running.  
The passage you refer to says not to cause the idle task to block, not because it will block higher priority tasks, but because if the idle task does block then it is likely there will be NO tasks that are available to run and there must always be at least one task available to the kernel for scheduling.  
<blockquote>
  2&#41; .On pages 26 and 27 it descusses how a periodic high-priority task preempts two lower priority tasks when a given time is reached. According to the output, the high priority task only prints its message after the time is reached. Should it not also print out its message as the first line of output, since it is the highest priority task?
</blockquote>
The images only show a snapshot of the output, which does not start at time 0, so you cannot see the print out occurring.  
Hope this helps.  
Regards.
