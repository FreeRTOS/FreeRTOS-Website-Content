  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Problem with Freescale Tower Devkit MCF51CN</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/konek">konek</a> on February 15, 2010</div><div class="thread-post-content">Hi there,  
I just found this project on the web and downloaded and compiled the example for the Freescale MCF51CN128 tower kit.<br />
It compiles without errors and warnings on CW 6.2.2 and I can download &#40;flash&#41; it to the MCU.<br />
As given in the manual, the LEDs on the board start flashing at different intervals each.  
However I can not connect to the webserver. My local network is 192.168.178.0/24 and I gave a free address &#40;.222&#41; to the MCU as well as the MAC proposed in the Freescale manuals &#40; 00 CF 52 35 00 07&#41;. PC and devkit are hooked up to a switch &#40;I swapped cables and plugs to make sure it&#8217;s not a mechanical issue, the PC works on any line&#41; .  
What happenes is that the two LEDs that are built into the RJ45 connector on the Tower Serial Module start flashing &#40;both, the green and the yellow one&#41; at an interval of about two seconds. This stops after a while, then repeats. Seems to be something basic I guess, afaik you see this on network cards while the switch is trying to figure the connection speed &#40;10/100BaseT&#41;?  
Any help highly appreciated.  
Regards,<br />
Sven

</div></div><div class="thread-post"><h3 class="thread-post-title">Problem with Freescale Tower Devkit MCF51CN</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/konek">konek</a> on February 16, 2010</div><div class="thread-post-content">Fiddling around to get any hints, I commented out all the other demo tasks, just left the blinking LEDs and the webserver.<br />
Et voilà, all of a sudden the thing works&#33; 😀  
Just for anyone else encountering the same problem, if you look into main&#40;&#41; &#40;in main.c of course&#41;, there is this block that launches the individual tasks. As you can see I only left the LED flasher alive to see if anything is going on at all:  
/&#42; Start the standard demo tasks. &#42;/<br />
vStartLEDFlashTasks&#40; tskIDLE&#95;PRIORITY &#41;;<br />
// vStartGenericQueueTasks&#40; mainGEN&#95;QUEUE&#95;TASK&#95;PRIORITY &#41;;<br />
// vStartQueuePeekTasks&#40;&#41;;<br />
// vStartRecursiveMutexTasks&#40;&#41;;<br />
// vStartBlockingQueueTasks&#40; mainBLOCK&#95;Q&#95;PRIORITY &#41;;  
With these changes, the webserver works PLUS the whole thing consumes a mere 26k&#33; WOW&#33;  
So, some demo task keeps the thing from working, but since i dont need these anyways, I wont look any deeper into it.  
Regards,<br />
Sven
</div></div><div class="thread-post"><h3 class="thread-post-title">Problem with Freescale Tower Devkit MCF51CN</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/konek">konek</a> on February 16, 2010</div><div class="thread-post-content">One more observation for anyone interested in going further from here:<br />
I can now use breakpoints, plus, all the LEDs flash in a constant periodic on-off manner. Before that, it was rather like a pattern, like &#8220;beeeep &#8211; &#8211; &#8211; beeeep &#8211; &#8211; &#8211; bip&#8221; on the slowest.  
All in all I guess that this leads to the inevitable assumption that the MCU simply crashes and resets after like 2 seconds within the original code. Might just be a stacksize issue &#40;though I didnt change any of the original code and stack size definitions&#41;.  
Regards,<br />
Sven
</div></div><div class="thread-post"><h3 class="thread-post-title">Problem with Freescale Tower Devkit MCF51CN</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on February 16, 2010</div><div class="thread-post-content">Probably the demo is just running out of heap space. The idle task is created when you call vTaskStartScheduler&#40;&#41; and if there is not enough heap space for the idle task then vTaskStartScheduler&#40;&#41; will just return. You can put a for&#40;;;&#41;; loop after the call to catch it returning. The newest FreeRTOS versions have a malloc failed hook to catch that sort of error.  
I bet the compiler version has been updated since the demo was created and the new version is using more RAM.
