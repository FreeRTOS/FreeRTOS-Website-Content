  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">High frequency ISRs in FreeRTOS</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/peter_balazovic">peter_balazovic</a> on February 2, 2010</div><div class="thread-post-content">Hello all,  
I am a new to RTOS and starting to be familiarized with FreeRTOS.<br />
My intention is to investigate how to integrate motor control into FreeRTOS.<br />
Usually motor control system &#40;without RTOS&#41; runs Motor&#95;control&#95;ISR at 100 periodic rate and code is executed within this Motor&#95;control&#95;ISR which takes about 40.<br />
It is hard real time system where motor control must complete within a given time limit otherwise results in failure of the system.  
Are there any handling techniques of such high frequency ISR to comply with FreeRTOS?<br />
Do you have any suggestions how to handle high frequency ISRs within FreeRTOS?<br />
Should it be such a ISR executed outside of FreeRTOS?<br />
Thank you very much.  
regards,<br />
pepe
</div></div><div class="thread-post"><h3 class="thread-post-title">High frequency ISRs in FreeRTOS</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on February 2, 2010</div><div class="thread-post-content">Look at configKERNEL&#95;INTERRUPT&#95;PRIORITY and configMAX&#95;SYSCALL&#95;INTERRUPT&#95;PRIORITY at the bottom of <a href="http://www.freertos.org/a00110.html">this</a> page. These parameters are only on new ports though.  
The Cortex M3 demo apps run a 20KHz timer test that shows an interrupt entry jitter of about 100ns which is apparently equal to the effect of tail chaining in the core itself.
</div></div><div class="thread-post"><h3 class="thread-post-title">High frequency ISRs in FreeRTOS</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/peter_balazovic">peter_balazovic</a> on February 2, 2010</div><div class="thread-post-content">Is your suggestion to execute&nbsp; such ISRs outside FreRTOS? &#40;Interrupts running at these priorities will never be delayed from executing because of anything FreeRTOS.org is doing. &#41;<br />
If so, how to interact with FreeRTOS it means between high frequency ISR and FreeRTOS?
</div></div><div class="thread-post"><h3 class="thread-post-title">High frequency ISRs in FreeRTOS</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on February 2, 2010</div><div class="thread-post-content">Yes, if you want the interrupt to have a priority higher than any used by the kernel &#40;including critical sections&#41; then the handler cannot use any FreeRTOS functions.
</div></div><div class="thread-post"><h3 class="thread-post-title">High frequency ISRs in FreeRTOS</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/peter_balazovic">peter_balazovic</a> on February 2, 2010</div><div class="thread-post-content">Any idea how to interact between ISR &#40;priority higher than any used by the kernel&#41; and FreeRTOS kernel?
</div></div><div class="thread-post"><h3 class="thread-post-title">High frequency ISRs in FreeRTOS</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/petermeier">petermeier</a> on February 2, 2010</div><div class="thread-post-content">You can use anything you like. If you need a buffer just use it and make it globally available. Make sure you have a lock mechanism.  
UINT8 bufferLock = 0x00;<br />
UINT8 buffer;  
&#95;ISR&#95;&#40;…&#41;<br />
&#123;<br />
&nbsp; if &#40;&#33;bufferLock&#41;<br />
&nbsp; &#123;<br />
&nbsp;&nbsp;&nbsp; … check buffer data<br />
&nbsp;&nbsp;&nbsp; …update data<br />
&nbsp; &#125;<br />
&nbsp; …<br />
&#125;  
void pvTask&#40;…&#41; // Has a lower priority than the ISR, so pvTask can not interrupt the ISR<br />
&#123;<br />
&nbsp;&nbsp; // Try to access buffer, Method 1<br />
&nbsp; …disable interrupts<br />
&nbsp; if &#40;bufferLock&#41;<br />
&nbsp; &#123;<br />
&nbsp;&nbsp;&nbsp;&nbsp; // Buffer is in use…<br />
&nbsp; &#125; else<br />
&nbsp; &#123;<br />
&nbsp;&nbsp;&nbsp; // Update buffer here<br />
&nbsp; &#125;<br />
&nbsp; …enable interrupts  
&nbsp; &#35;Method 2<br />
&nbsp; ..disable interrupts<br />
&nbsp; if &#40;&#33;bufferLock&#41;<br />
&nbsp;&nbsp;&nbsp; bufferLock = 0x01;<br />
&nbsp; ..enable interrupts<br />
&nbsp; if &#40;bufferLock&#41;<br />
&nbsp; &#123;<br />
&nbsp;&nbsp;&nbsp; // Update your buffer…<br />
&nbsp;&nbsp; …<br />
&nbsp;&nbsp; // Unlock buffer<br />
&nbsp;&nbsp; bufferLock = 0x00;<br />
&nbsp; &#125;<br />
&#125;&nbsp;   
This is quick and dirty, but it works…
