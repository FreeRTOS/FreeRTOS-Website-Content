Thanks
</div></div><div class="thread-post"><h3 class="thread-post-title">LPC17xx Serial example</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/*anonymous">*anonymous</a> on February 27, 2010</div><div class="thread-post-content">Well I haven&#8217;t seen a follow up yet, so let me expand my issue.  
The main problem that I am having with the LPC1768 is that you cannot have a fully interrupt driven serial driver because the Transmit ISR only triggers on a FIFO transition to empty instead of generating interrupts while empty.&nbsp; So while IDEALLY I would like to do this:  
My code would call this function to place characters into the serial buffer:  
<pre><code>signed portBASE_TYPE serial_putChar(signed portCHAR ch, portTickType xBlockTime )){
    signed portBASE_TYPE xReturn = pdFAIL;
    xReturn = xQueueSend( TxQueue, &amp;ch, xBlockTime );
    UART1-&gt;IER |= UART_IER_THREINT_EN;
    return xReturn;
}
</code></pre>
And this would be the serial interrupt handler:  
<pre><code>void serialISR(){
    portBASE_TYPE xHigherPriorityTaskWoken = pdFALSE;
    portCHAR cChar;
    if(UART1-&gt;IIR &amp; UART_IIR_INTID_THRE){
        if( xQueueReceiveFromISR( TxQueue, &amp;cChar, &amp;xHigherPriorityTaskWoken ) == pdTRUE ){
            UART1-&gt;THR = cChar;
        }
        else{
            UART1-&gt;IER &amp;= ~UART_IER_THREINT_EN;
        }
    }
    portEND_SWITCHING_ISR( xHigherPriorityTaskWoken );
}
</code></pre>
This part doesn&#8217;t work like that.  
So I am working to have a task load the THR transmit register for me. This is what I have so far &#40;rough outline&#41;:  
My main function call would be  
<pre><code>signed portBASE_TYPE serial_putChar(signed portCHAR cOutChar, portTickType xBlockTime )
{
    signed portBASE_TYPE xReturn = pdFAIL;
    if( xQueueSend( xCharsForTx, &amp;cOutChar, xBlockTime ) == pdPASS ){
        xReturn = pdPASS;
    }
    return xReturn;
}
</code></pre>
The interrupt handler:  
<pre><code>void serialISR(void)
{
    portBASE_TYPE xHigherPriorityTaskWoken = pdFALSE;
    portCHAR cChar;
    if(UART1-&gt;IIR &amp; UART_IIR_INTID_THRE){
    {
        xSemaphoreGiveFromISR(xSendSemaphore, &amp;xHigherPriorityTaskWoken);
    }
    portEND_SWITCHING_ISR( xHigherPriorityTaskWoken );
}
</code></pre>
And my task to load characters into the THR register would be  
<pre><code>void xUARTsendTask(void *pvParameter)
{
    uint8_t sendChar;
    vSemaphoreCreateBinary(xSendSemaphore);
    xSemaphoreTake(xSendSemaphore, 0);
    for( ;; ){
        xQueueReceive(xCharsForTx, &amp;sendChar, portMAX_DELAY);
        UART1-&gt;THR = sendChar;
        xSemaphoreTake(xSendSemaphore, portMAX_DELAY);
    }
}
</code></pre>
The problem I have with this is that it halts have transmitting 2 characters.&nbsp; So what I am looking for is some ideas on making this work.
</div></div><div class="thread-post"><h3 class="thread-post-title">LPC17xx Serial example</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on February 27, 2010</div><div class="thread-post-content">While I am not familiar with this processor, here is what I tend to use a the pseudo code for the transmit character routine:  
Place character into software queue<br />
if that worked and serial transmit buffer is empty, force transmit buffer empty serial interrupt.  
The key here is finding a way to force the interrupt. On many processors you can write to the interrupt request flag to set it, or have some other way to trigger the interrupt.
</div></div><div class="thread-post"><h3 class="thread-post-title">LPC17xx Serial example</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/tgarner">tgarner</a> on February 27, 2010</div><div class="thread-post-content">What I usually do is use the Tx interrupt enable&nbsp; as a busy flag.  
Putchar(C)<br />
&#123;<br />
&nbsp;&nbsp;&nbsp; if&#40; Tx IE flag &#41;<br />
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; put c in Queue<br />
&nbsp;&nbsp;&nbsp; else<br />
&nbsp;&nbsp; &#123;<br />
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; Set Tx IE flag<br />
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; Write C directly to hardware<br />
&nbsp; &#125;<br />
&#125;  
ISR<br />
&nbsp; if char in Queue<br />
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; transmit it<br />
&nbsp; else<br />
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; turn off&nbsp; Tx IE flag  
</div></div><div class="thread-post"><h3 class="thread-post-title">LPC17xx Serial example</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on February 27, 2010</div><div class="thread-post-content">That has a race condition. If the interrupt for the last character going out occurs between the test of the IE flag and the insertion into the queue, then you end up with a character in the queue that will get output out of order, as the next character sent out will go directly to the transmit buffer, and then the queued character. One fix, if it is available, is to disable interrupts around the code.
