</div></div><div class="thread-post"><h3 class="thread-post-title">ARM7 failing on xQueueGenericReceive 5min+</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on February 25, 2010</div><div class="thread-post-content">The stack overflow checks only check the task stack.&nbsp; The line you are crashing on on calls SWI, which will cause a switch to using the Supervisor stack.&nbsp; Are you setting up a Supervisor stack?&nbsp; Are you setting up an IRQ stack?&nbsp; Both these are normally done from the startup code before main&#40;&#41; is called.  
Also, the SWI can cause a switch to another task, so you would need to step into the SWI handler to see where the real problem was, it might be that lots of code executes in other tasks before execution continued past the SWI instruction.  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">ARM7 failing on xQueueGenericReceive 5min+</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on February 25, 2010</div><div class="thread-post-content">In fact, the Yagarto main page itself has the following written:  
<pre><code>Information
In case you get some linker errors like:
error: no memory region specified for loadable section `.eh_frame'
you must add the following part to your linker script:
. = ALIGN(4);
.eh_frame :
{
     KEEP (*(.eh_frame))
} &gt; ram
The examples you can find at the howto pages was updated too.
</code></pre>
