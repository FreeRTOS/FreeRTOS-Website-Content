</div></div><div class="thread-post"><h3 class="thread-post-title">can&#8217;t create/run new task in demo</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on September 14, 2007</div><div class="thread-post-content">I presume you can successfully run the demo as it is in the download without any modification?
main&#40;&#41; creates a lot of standard demo tasks.&nbsp; In some of the demos these tasks use up all the available RTOS heap.&nbsp; The size of the heap being set by parameter configTOTAL&#95;HEAP&#95;SIZE within FreeRTOSConfig.h.&nbsp; If you run out of memory then try starting the scheduler the call to vTaskStartScheduler&#40;&#41; will simply return and you will run off the bottom of main&#40;&#41;.
Try preventing some of the standard demo tasks from being created so you have RAM left over to create your own task.&nbsp; Also try placing a null loop &#40;while&#40;1&#41;&#41; after vTaskStartScheduler&#40;&#41; within main&#40;&#41; so you can see if the function returns.
</div></div><div class="thread-post"><h3 class="thread-post-title">can&#8217;t create/run new task in demo</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/biker126">biker126</a> on September 15, 2007</div><div class="thread-post-content">i think you are probably right &#40;with the &quot;not enough memory&quot;&#41; as in some cases &#40;when i can debug the demo&#41; the program indeed ends up in and asm-endless-loop which is reached as far as i know by the &quot;return 0&quot; in main&#40;&#41; &#40;after the startscheduler&#40;&#41; &#41;.
could it also have something to do with a wrong memory map/linker script file?
