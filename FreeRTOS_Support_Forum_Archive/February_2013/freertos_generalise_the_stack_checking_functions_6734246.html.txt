  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">generalise the stack checking functions </h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/friedl">friedl</a> on February 9, 2013</div><div class="thread-post-content">Hi Richard&#33;  
I&#8217;ve just posted the patch  
<a href="https://sourceforge.net/tracker/?func=detail&amp;aid=3603970&amp;group_id=111543&amp;atid=659636">generalise the stack checking functions</a> on the Feature Requests tracker.   
This patch enables ports of FreeRTOS to architectures which use/need more than<br />
one stack.  
To support the stack overflow checking functionality on such a port for the<br />
additional stack&#40;s&#41;, we need to have general &#40;inline&#41; functions where the stack<br />
and such is not hard-coded.  
Tested on a real hw with configCHECK&#95;FOR&#95;STACK&#95;OVERFLOW == 2 and<br />
portSTACK&#95;GROWTH == -1.  
Just compile tested for portSTACK&#95;GROWTH == +1.  
Would be nice if you could mainline this.  
Regards<br />
Friedl
</div></div><div class="thread-post"><h3 class="thread-post-title">generalise the stack checking functions </h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on February 11, 2013</div><div class="thread-post-content">I have not done more than glance at this one yet.&nbsp; I understand the desire to generalise the stack checking, but the patch is not there yet because it uses inline functions &#40;remember FreeRTOS officially compiles with 18 different compilers so avoids using inline as different standards treat it differently &#41;.&nbsp; Also, the checking has to be very fast, hence the macros that are expanded inline rather than function calls.&nbsp; I&#8217;m not sure &#40;because I don&#8217;t use them often&#41; if the compiler will always perform a direct substitution for an inline function without any parameter overhead.&nbsp; I suspect most compilers will as soon as you turn any kind of optimisation on.  
I will look at what you are trying to achieve to see if there is an alternative that does not use the inlines.  
Regards.
