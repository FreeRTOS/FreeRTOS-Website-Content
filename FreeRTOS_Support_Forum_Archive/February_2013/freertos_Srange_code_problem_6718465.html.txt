</div></div><div class="thread-post"><h3 class="thread-post-title">Srange code problem!</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/travfrog">travfrog</a> on February 5, 2013</div><div class="thread-post-content">I believe the task stacks are allocated from the HEAP. Each stack is set for 1500 while your heap is set to 1500 &#8211; that won&#8217;t work. You also need RAM for the tasks themselves and any message Qs.   
You shouldn&#8217;t need stacks that big &#8211; try 400 bytes instead. Put your heap size up to 5K &#40;if you have the memory&#41;.  
In addition, you should always use the Stack overflow and memory allocation application hooks &#8211; they will tell you immediately if you haven&#8217;t allocated enough memory. Add the following to your FreeRTOSConfig.h file;&#8217;  
&#35;define configUSE&#95;MALLOC&#95;FAILED&#95;HOOK 1<br />
&#35;define configCHECK&#95;FOR&#95;STACK&#95;OVERFLOW&nbsp;&nbsp;&nbsp;&nbsp; 2  
The stack checking will slow the system slightly but start with it until you have a stable system. In main, you will need to implement:  
void vApplicationMallocFailedHook &#40;void&#41;  
and  
void vApplicationStackOverflowHook&#40; xTaskHandle &#42;pxTask, signed char &#42;pcTaskName &#41;

void vApplicationMallocFailedHook &#40;void&#41;<br />
&#123;<br />
&nbsp;&nbsp;&nbsp; const char &#42;stackStr = &#8220;RTOS out of Heap&#8221;;<br />

If you have a debugger with break point capability, put a break point in the function. All you want to know is when it fails. You could also simply turn a GPIO on or drive an LED. Keep increasing the heap size &#40;see below&#41; until it stops blowing up.  
4 stacks at 400 bytes each is 1600 bytes. If your heap is less than that it will blow up.   
Don&#8217;t confuse the linker generated heap with the RTOS heap. When using the RTOS, you can set the linker heap size to 0 &#40;or whatever minimum is allowed&#41; &#8211; I have mine set to 8. because it won&#8217;t accept 0 as valid.   
The FreeRTOS heap is where the stacks are allocated from &#8211;&nbsp; so in FreeRTOSConfig.h, you want:  
&#35;define configTOTAL&#95;HEAP&#95;SIZE&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; &#40; &#40; size&#95;t &#41; &#40; xx &#42; 1024 &#41; &#41;  
where xx is something large depending on the amount of RAM your processor has. You can always trim this back once you have got all your tasks up and running.  
Use the API uxTaskGetStackHighWaterMark &#40;taskHandle&#41; to get the maximum size each tasks Q reached. If it gets close to the size you defined then increase the stack size. &#40;You need to add &#35;define INCLUDE&#95;uxTaskGetStackHighWaterMark 1 to FreeRTOConfig.h to use this API.<br />
Once you&#8217;ve made the changes to FreeRTOSConfig.h, re-post it so I can check it.<br />
