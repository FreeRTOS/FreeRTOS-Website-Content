</div></div><div class="thread-post"><h3 class="thread-post-title">rtos viewer</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/edwards3">edwards3</a> on April 30, 2010</div><div class="thread-post-content">Is the priority of the interrupt set to portKERNEL&#95;INTERRUPT&#95;PRIORITY? If not try changing it to portKERNEL&#95;INTERRUPT&#95;PRIORITY to see if it fixes the problem. Also check the stack sizes of your tasks <a href="http://www.freertos.org/Stacks-and-stack-overflow-checking.html.">http://www.freertos.org/Stacks-and-stack-overflow-checking.html.</a>  
</div></div><div class="thread-post"><h3 class="thread-post-title">rtos viewer</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on April 30, 2010</div><div class="thread-post-content">One possible issue I see is that you have declared your interrupt handler no&#95;auto&#95;psv, which means that the handler can not access the PSV segment. You then call xQueueSendFromISR which I am not sure if it needs the auto&#95;psv segment. Most of the time the PSV segment will be setup right, and the interrupt will run fine. There may be a few small sections of your program in which the compiler needs to change the PSV segment, if the interrupt occurs there, and xQueueSendFromISR needs to access the PSV segment, then problems will occur.  
A side note, your interrupt routine is not checking the taskWoken flag, so if a character does arrive, the waiting task will not start up right away, but will need to wait for the next time a task switch happens &#40;like at the next timer tick&#41; before it has a chance to process that character. This may be acceptable for your program.

</div></div><div class="thread-post"><h3 class="thread-post-title">rtos viewer</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on April 30, 2010</div><div class="thread-post-content">If configKERNAL&#95;INTERRUPT&#95;PRIORIRY is set to 1, make sure you have changed the interrupt priority of the interrupt to be 1 also. &#40;Interrupts with a priority high than that are not allowed to call FreeRTOS APIs&#41;.  
As to the documentation of the View Plugin, I know it is in there, I just am not that familiar where. I believe you need to set the option to remove the static qualifications for FreeRTOS locals, enable some tracing options, and it is very helpful to make sure you give each queue a unique name.
