  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Cant get a simple SPI mutex to work.. </h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/jon_newcomb">jon_newcomb</a> on April 27, 2010</div><div class="thread-post-content">I&#8217;m having one of those days where I&#8217;m missing the blinding obvious..<br />
Using FreeRTOS V5.3.0, IAR 5.41.2,&nbsp; JLink, AT91SAM7S256  
We have lots of comms on a singe SPI port. I thought it sensible to convert my &#40;old and working I hope&#41; binary&nbsp;<br />
semaphore to a &#40;new and improved&#41; mutex.<br />
I have a global declaration..<br />
static xSemaphoreHandle semaphore&#95;spi&#95;guard;  
Simple.. change the line where it is initialised..<br />
from
<pre><code>vSemaphoreCreateBinary (semaphore_spi_guard
</code></pre>
&#41;;<br />
to
<pre><code>semaphore_spi_guard = xSemaphoreCreateMutex(
</code></pre>
&#41;;  
As described in<br />
<a href="http://null/">http://www.freertos.org/a00121.html<br />
http://www.freertos.org/CreateMutex.ht</a>ml  
It compiles..&nbsp;
<pre><code>#define configUSE_MUTEXES 1  in FreeRTOSConfig.h
</code></pre>
is all present and correct.  
The help says..<br />
&#8220;Mutexes created using this macro can be accessed using the xSemaphoreTake&#40;&#41; and xSemaphoreGive&#40;&#41; macros&#8221;<br />
Great.. I need not alter any of my code because this is the way I give and take my &#40;old&#41; binary SPI semaphore.  
Reality was different..<br />
I was disappointed to find every give or take of the mutex fails.. time to start investigating..<br />
I put breakpoints in a few different locations..<br />
This is when started to really scratch my head and get confused..  
in
<pre><code>xQueueHandle xQueueCreateMutex( void
</code></pre>
&#41;  
The following values are end up as follows:<br />
&nbsp;
<pre><code>pxNewQueue-&gt;pcWriteTo = NULL;
  pxNewQueue-&gt;pcReadFrom = NULL;
</code></pre>
.. OK, so unlike a queue, we don’t set these to the &#8216;head&#8217; of a queue.. So far so good.  
Then every time we come to give or take the mutex I arrive at xQueueGenericSend or xQueueGenericReceive.<br />
The very first few lines perform a check that always fails &#8211; and I cant work out why it does the check and how it can pass..  
This check is..
<pre><code>   if (!pxQueue || !pxQueue-&gt;pcHead) // extended check for valid Queue
   {
      return errQUEUE_UNDEF;
</code></pre>
&#125;  
Well of course it fails with 
<pre><code>errQUEUE_UNDEF
</code></pre>
.<br />
I get back to my give / take mutex having don’t nothing and returning a fail..<br />
Please help.. I’m very confused&#33;  
Thanks,<br />
Jon Newcomb
