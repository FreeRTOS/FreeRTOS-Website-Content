  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">How to know where my tasks are waiting</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/sergiosider">sergiosider</a> on April 23, 2010</div><div class="thread-post-content">Hi All,  
I did not find or was unable to find this info…  
I have an application using several tasks of the same priority using/waiting for Mutexes. I was debugging for hours and then, two or more tasks stopped wainting for something. I am sure it&#8217;s a deadlock of badly using those Mutexes.<br />
But that&#8217;s not the main problem.   
What is the way to know where in the task, the task is stopped ? and what resource is it waiting for ?<br />
My tasks are quite complex and could have stopped in several points and waiting for different resources &#40;mutexes&#41;.  
I am using Eclipse, codesourcery and Jlink debugger.. I can&#8217;t stop and run the program &#40;only one task is running&#41;, but I could not figure out by myself where the tasks are stopped.  
Thanks for any help&#33;&#33;<br />
Regards,<br />
Sergio Sider  
</div></div><div class="thread-post"><h3 class="thread-post-title">How to know where my tasks are waiting</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/edwards3">edwards3</a> on April 25, 2010</div><div class="thread-post-content">You can get this information from the Eclipse FreeRTOS plug in, which is a free download. Go to <a href="http://www.highintegritysystems.com/">http://www.highintegritysystems.com</a> and follow the links to the downloads.
</div></div><div class="thread-post"><h3 class="thread-post-title">How to know where my tasks are waiting</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/sergiosider">sergiosider</a> on April 25, 2010</div><div class="thread-post-content">Hi edwards,  
I have the plugin, and now I registered my Mutexes in the FreeRTOS registry so I can see them in the &#8220;Queue Table&#8221; tab.  
I found that the plugin shows the mutex name in the &#8220;Event Object&#8221; column of the task that appears to have gained the Mutex. It looks like a &#8220;dedly embrace&#8221;, but I still do not know where in the program the tasks are waiting.<br />
I suppose it&#8217;s possible to find this info in the stack of the task or in another place, but did not figured out.  
I could, and I probably will, put some debug routines to help me find it, but it would help a lot in the future to know how to go directly to the &#8220;offending line&#8221; of the task.   
Regards,<br />
Sergio.
</div></div><div class="thread-post"><h3 class="thread-post-title">How to know where my tasks are waiting</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/edwards3">edwards3</a> on April 25, 2010</div><div class="thread-post-content">Something else you can do is provide some trace macros. Take a look at <a href="http://www.freertos.org/rtos-trace-macros.html">http://www.freertos.org/rtos-trace-macros.html</a> then search through queue.c for the word &#8220;trace&#8221;. You can log when a task takes or gives a semaphore, so when your crash happens you know what the task did last.
</div></div><div class="thread-post"><h3 class="thread-post-title">How to know where my tasks are waiting</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/jkuusama">jkuusama</a> on April 26, 2010</div><div class="thread-post-content">The simple approach: Use global variables. There are not that many points where your tasks could be stuck, so looking the value of the global volatile variable of&nbsp; task1tracepoint in a debugger should be informative.
</div></div><div class="thread-post"><h3 class="thread-post-title">How to know where my tasks are waiting</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/sergiosider">sergiosider</a> on April 26, 2010</div><div class="thread-post-content">Hi guys,  
Thanks for the suggestions. Actually I found the bug that caused the deadly embrace &#40;and it was not a deadly embrace… was a deadly stupidity: the same task was trying to get a Mutex already taken by itself… :-&#40; &#41;  
I don&#8217;t want to sound whinny, but it would be great to have the knowledge to get the &#8220;Program Counter&#8221; of a blocked task.  
Thanks again,<br />
Sergio.  
</div></div><div class="thread-post"><h3 class="thread-post-title">How to know where my tasks are waiting</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on April 26, 2010</div><div class="thread-post-content">FreeRTOS also supports recursive semaphores, if that would help?
</div></div><div class="thread-post"><h3 class="thread-post-title">How to know where my tasks are waiting</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on April 26, 2010</div><div class="thread-post-content">sergioside, you will probably find that the &#8220;Program Counter&#8221; that the task last suspended at isn&#8217;t all that useful, as the main thing this will tell you is which api function suspended the task, but not information about where in the task that call was, or which object &#40;Semaphore, etc&#41; it was called on. That would require a much more complicate parsing of the stack, or saving additional information somewhere task specific.
</div></div><div class="thread-post"><h3 class="thread-post-title">How to know where my tasks are waiting</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/sergiosider">sergiosider</a> on April 28, 2010</div><div class="thread-post-content">Hi All,  
Thanks for your help&#33;  
Now, I am convinced that the &#8220;program counter&#8221; idea is problematic and debugging techniques are the way to go in that case ;-&#41;  
Regards,<br />
Sergio.
