  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">new task after vTaskStartScheduler</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/mcirsta">mcirsta</a> on April 28, 2010</div><div class="thread-post-content">I&#8217;m looking to dynamically create and delete tasks after vTaskStartScheduler was called &#40; a sort of thread pool &#41;.&nbsp;&nbsp;   
I&#8217;ve tried using a function pointer for a task defined before calling vTaskStartScheduler and then modifying the pointer at some point but that didn&#8217;t work , it still ran the old function defined when the task was created.  
I&#8217;ve also tried deleting a running task which worked but then creating a new one with xTaskCreate failed. I&#8217;m thinking that xTaskCreate won&#8217;t work after&nbsp; vTaskStartScheduler was called.   
Is there any way to add new tasks after&nbsp; vTaskStartScheduler was called ?  
Thank you.
</div></div><div class="thread-post"><h3 class="thread-post-title">new task after vTaskStartScheduler</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on April 28, 2010</div><div class="thread-post-content">There should be no reason why you cannot create and delete tasks after the scheduler has been started using the normal API functions.&nbsp; Creating a task will fail if there is insufficient heap space for the task stack.&nbsp; You can use xPortGetFreeHeapSize&#40;&#41; to check how much stack is free.  
To delete tasks you must ensure the memory the kernel allocated to the task can be freed.&nbsp; This means that the idle task must not be starved of processing time, and you cannot use heap&#95;1.c.  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">new task after vTaskStartScheduler</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/mcirsta">mcirsta</a> on April 29, 2010</div><div class="thread-post-content">Thanks for your answer , I&#8217;ll investigate this problem further.
</div></div><div class="thread-post"><h3 class="thread-post-title">new task after vTaskStartScheduler</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/mcirsta">mcirsta</a> on April 29, 2010</div><div class="thread-post-content">I&#8217;ve checked and it seems the problem was indeed that there was not enough memory available for starting another task.&nbsp; Also deleting the task didn&#8217;t free up any memory because as you said the memory allocation was implemented using heap&#95;1.c   
Isn&#8217;t it possible in any way to divert a task to do something else without deleting it and creating another one. I&#8217;m guessing using a function pointer instead of a function name when starting a task won&#8217;t work ?
</div></div><div class="thread-post"><h3 class="thread-post-title">new task after vTaskStartScheduler</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on April 29, 2010</div><div class="thread-post-content">Once a task has started, trying to do something outside that task to redirect it elsewhere is a very bad idea, as you have practically no idea where the task currently is.   
Note that when you give the create task call a function name, that name IS passed to the create function as a function pointer. Changing it afterward won&#8217;t change what the task is doing, as that value is just used as where to start.  
If you want a task to do different things, then what you need to do is have the task in part of its loop query what it is being asked to do and then go off and do that task, and when it checks again later maybe it does something else.  
The big question comes, why do do want to change on the fly what a task does? 
</div></div><div class="thread-post"><h3 class="thread-post-title">new task after vTaskStartScheduler</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/mcirsta">mcirsta</a> on April 30, 2010</div><div class="thread-post-content">Yes , you are right , the best way would be to check for something in the task loop.   
As to why I would want such a thing , it&#8217;s because I want to implement a sort of thread pool concept. There are 2 fixed tasks that do the same thing and 2 tasks that can be assigned to various other tasks and then when that task is finished be used for something else.  
Thank you all for your support , it helped .
