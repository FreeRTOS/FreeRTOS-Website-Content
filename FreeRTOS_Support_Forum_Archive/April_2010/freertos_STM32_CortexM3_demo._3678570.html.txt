  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">STM32 CortexM3 demo.</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/kolodko1">kolodko1</a> on April 16, 2010</div><div class="thread-post-content">Hi  
Seem to in demo config for STM32 CortexM3 arch is small bug &#40;rather non consistency&#41; but without side effects.  
In FreeRTOSConfig.h  
&#35;define configMAX&#95;SYSCALL&#95;INTERRUPT&#95;PRIORITY&nbsp; 191 /&#42; equivalent to 0xb0, or priority 11. &#42;/  
According <a href="http://www.st.com/stonline/products/literature/pm/15491.pdf">http://www.st.com/stonline/products/literature/pm/15491.pdf</a> page 20,<br />
in BASEPRI only bits 7:4 are valid. So I expect rather:  
&#35;define configMAX&#95;SYSCALL&#95;INTERRUPT&#95;PRIORITY&nbsp; &#40;11U&lt;&lt;4U&#41; /&#42; equivalent to 0xb0, or priority 11. &#42;/<br />
11U&lt;&lt;4U is 0xB0, what is also priority 11.  
It is equivalent of 191 &#40;0xBF&#41;, since from documentation bits 3:0 are reserved.  
Regards  
</div></div><div class="thread-post"><h3 class="thread-post-title">STM32 CortexM3 demo.</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on April 16, 2010</div><div class="thread-post-content">The Cortex M3 is designed with &#8216;forward compatibility&#8217; in mind &#40;sounds like their marketing dept. got involved in that&#41;.&nbsp; This is why the interrupt mechanism is so confusing.&nbsp; The Cortex M3 itself has 8 bits of priority, but different implementations use a different number of bits.&nbsp; In the interest of &#8216;forward compatibility&#8217; it is the most significant bits that are actually used, the idea being that code will be portable to future revisions of the cpu that might implement more bits.  
The way the code is written is deliberate, and fine as it is.&nbsp; A lot of this code was written before the CMSIS stuff existed, and before most of the documentation on the CM3 was publicly available.  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">STM32 CortexM3 demo.</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/kolodko1">kolodko1</a> on April 16, 2010</div><div class="thread-post-content">Catch point, thanks.

</div></div><div class="thread-post"><h3 class="thread-post-title">STM32 CortexM3 demo.</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on April 16, 2010</div><div class="thread-post-content"><blockquote>
