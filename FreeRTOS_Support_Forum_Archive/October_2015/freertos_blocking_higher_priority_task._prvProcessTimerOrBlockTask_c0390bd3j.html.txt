</div></div><div class="thread-post"><h3 class="thread-post-title">blocking higher priority task. prvProcessTimerOrBlockTask()</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on October 22, 2015</div><div class="thread-post-content">Your question is not completely clear, but I will try and answer it.
pxCallbackFunction() is the software timer callback function &#8211; but it is just a C function being called from an RTOS task (in this case the Timer task http://www.freertos.org/RTOS-software-timer.html) so it can do the same as any other C function being called from a task.  Generally, it can unblock a higher priority task, but it can&#8217;t really block a higher priority task.  It can <em>suspend</em> a higher priority task, but that is a different thing.
</div></div><div class="thread-post"><h3 class="thread-post-title">blocking higher priority task. prvProcessTimerOrBlockTask()</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on October 22, 2015</div><div class="thread-post-content">Timer call back functions are called in the contex of the Timer task, which is high priority (I think the highest allowed), not the task that setup the time. Thus timer call backs will have higher priority than your moderate to sort of high priority tasks.
Does this answer your question?
</div></div><div class="thread-post"><h3 class="thread-post-title">blocking higher priority task. prvProcessTimerOrBlockTask()</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/niksp">niksp</a> on October 22, 2015</div><div class="thread-post-content">Function call &#8220;pxTimer->pxCallbackFunction((TimerHandle t) pxTimer)&#8221; stands between vTaskSuspendAll() and xTaskResumeAll().
If inside ISR will be called xTaskResumeFromISR () for more priority than the &#8220;Timer task&#8221;,
a context switch is blocked (vTaskSuspendAll()) while there is a execution the callback function. additional delay of switching.
it turns out you can not make the task more priority than &#8220;Timer task&#8221;?
</div></div><div class="thread-post"><h3 class="thread-post-title">blocking higher priority task. prvProcessTimerOrBlockTask()</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on October 22, 2015</div><div class="thread-post-content">You can make a task have a higher priority by changing the definition of configTIMER<em>TASK</em>PRIORITY which lives in FreeRTOSConfig.h
What you can&#8217;t do is force a task switch during a vTaskSuspendAll() block.
TImer call backs should be fairly quick though.
