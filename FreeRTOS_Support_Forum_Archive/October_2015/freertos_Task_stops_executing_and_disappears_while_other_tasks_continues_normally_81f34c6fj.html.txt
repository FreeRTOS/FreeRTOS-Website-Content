  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Task stops executing and disappears while other tasks continues normally</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/inimicus8">inimicus8</a> on October 12, 2015</div><div class="thread-post-content">Hi
I have a task that I resume from an interrupt. After some time (10 minutes too several hours) the task that gets resumed from the interrupt stop executing. This while all other tasks continues to function normally. 
Interrupt code:
void CAN<em>RX</em>Interrupt( void )
{
………..
        xYieldRequired = xTaskResumeFromISR( canHandle );
          portYIELD<em>FROM</em>ISR( xYieldRequired );
}
OS Task code:
      while (1)
      {
<pre><code>        CAN_ReceiveRoutine();
        vTaskSuspend( NULL );
  }
</code></pre>
When I call vTaskList()  after the task have stopped working the effected task does not appear in the list anymore. 
vTaskList()  before CAN_T task stops executing:
Name    State     Priority        Stack      Num
<hr />
 Shell<em>T    R   5   300 4
CAN</em>T       R   1   428 3
IDLE        R   0   491 6
IR<em>T        B   3   482 2
Error</em>T     B   6   483 5
Main_T      B   2   460 1
Tmr Svc     B   2   993 7
>
vTaskList()  after CAN_T task stops executing:
 Name    State     Priority        Stack      Num
<hr />
 Error<em>T    R   6   483 5
IDLE        R   0   491 6
Shell</em>T     B   5   300 4
IR<em>T        B   3   477 2
Main</em>T      B   2   460 1
Tmr Svc     B   2   993 7
I don’t think its stack overflow because I don’t end up in the vApplicationStackOverflowHook() and  there seems to be plenty of memory still available when I call vTaskList()  before the task stops working. I also don’t get caught in the configASSERT .
Anyone having a clue what could be wrong here?
Why does the task disappear from the vTaskList()?
Info about platform: MCU: stm32f407: IDE: coocox 2.0.3. toolchain: gcc 4.8 2004. RTOS: FreeRTOS V8.2.2
</div></div><div class="thread-post"><h3 class="thread-post-title">Task stops executing and disappears while other tasks continues normally</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on October 12, 2015</div><div class="thread-post-content">If you are using the task suspend/resme mechanism to synchronise a task with an interrupt, then please don&#8217;t, it is a dangerous technique to use.  Please read the documentation page of the <a href="http://www.freertos.org/taskresumefromisr.html">xTaskResumeFromISR()</a>, and other posts in this forum where people have experienced the same issue.
The best and fasted way to do what you want is to use a direct to task notificiation.  See http://www.freertos.org/vTaskNotifyGiveFromISR.html
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">Task stops executing and disappears while other tasks continues normally</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/inimicus8">inimicus8</a> on October 12, 2015</div><div class="thread-post-content">Thank you for the reply! 🙂
I have tried using the vTaskNotifyGiveFromISR( canHandle, NULL ) but the program only runs for a couple of minutes before it ends up in the  HardFault_Handler().
If I don’t call the portYIELD<em>FROM</em>ISR( pdTRUE ) the program seems to work fine but the task is not started directly after the interrupt and that is not acceptable.
I don’t know why I get this problem but I guess it might have something with the interrupt priority settings. But as I understand it I think the settings are correct.
The interrupt priority for the interrupt calling vTaskNotifyGiveFromISR() and portYIELD<em>FROM</em>ISR()  is the following:
~~~~
  NVIC<em>PriorityGroupConfig(NVIC</em>PriorityGroup<em>4);
  NVIC</em>InitStructure.NVIC<em>IRQChannel = CAN1</em>RX0<em>IRQn;
  NVIC</em>InitStructure.NVIC<em>IRQChannelPreemptionPriority = 15;
  NVIC</em>InitStructure.NVIC<em>IRQChannelSubPriority = 15;
  NVIC</em>InitStructure.NVIC<em>IRQChannelCmd = ENABLE;
  NVIC</em>Init(&amp;NVIC_InitStructure);
~~~~
This should be the lowest interrupt priority.
The freeRTOS config settings are:
~~~~
<h1>define configLIBRARY<em>MAX</em>SYSCALL<em>INTERRUPT</em>PRIORITY    5</h1>
<h1>define configKERNEL<em>INTERRUPT</em>PRIORITY         255</h1>
<h1>define configMAX<em>SYSCALL</em>INTERRUPT_PRIORITY    191 /* equivalent to 0xb0, or priority 11.</h1>
<h1>define configLIBRARY<em>KERNEL</em>INTERRUPT_PRIORITY 15</h1>
~~~~
Task priority is:
<code>xTaskCreate( CAN_Control_Task, ( const char * ) "CAN_T", configMINIMAL_STACK_SIZE, NULL, 1, &amp;canHandle );</code>
Anyone having a clue of why I end up in hard fault when I use vTaskNotifyGiveFromISR and portYIELD<em>FROM</em>ISR from an interrupt? Or how I investigate further how to track down the fault?
</div></div><div class="thread-post"><h3 class="thread-post-title">Task stops executing and disappears while other tasks continues normally</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on October 12, 2015</div><div class="thread-post-content">Try setting the SubPriority to 0.  Are you also calling 
NVIC<em>PriorityGroupConfig( NVIC</em>PriorityGroup_4 );? 
(http://www.freertos.org/RTOS-Cortex-M3-M4.html).  Do you have <a 
href="http://www.freertos.org/a00110.html#configASSERT">configASSERT()</a> 
defined?  Do you have stack overflow checking turned on?
