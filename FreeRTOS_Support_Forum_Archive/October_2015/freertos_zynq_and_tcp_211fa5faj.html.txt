  running high performance tcp 600mbs or more
</blockquote>
Sounds like you have a 1000 mbit LAN?
Unfortunately we have only tested a Xilinx Zynq with a 100 mbs adapter.
<blockquote>
  Hopefully Hein will chip in with some throughput figures too.
</blockquote>
On a 100 mbs LAN we saw a nett throughput of up to 10 MByte, which is about the maximum you can get. This test was done with FTP, transferring big files to or from a RAM-disk.
If you have any questions about porting +TCP to your 1 Gbps MAC, please post them here.
Also I have developed a &#8216;iperf&#8217; server for FreeRTOS +TCP, in case you want to do performance testing.
I find that &#8216;iperf&#8217; isn&#8217;t very interesting, and like Richard wrote, it is important to see the performance in real life.
<blockquote>
  figure out how to implement in raw mode
</blockquote>
Within +TCP there is only one mode, which is the official BSD interface. But there are some back-doors, for those who prefer speed above compatibility:
<ul>
<li>The use of zero-copy for sending and receiving, both for UDP and TCP.</li>
<li>The use of call-backs from the IP-task such as OnReceive, OnSent, and OnError. These hooks are installable per socket.</li>
</ul>
An echo server which uses an OnReceive handler will have a higher performance because it uses less context switches and less copying.
Regards.

http://www.freertos.org/labs
You will find a directory:
<pre><code>FreeRTOS-Plus/Demo/FreeRTOS_Plus_TCP_and_FAT_Zynq_SDK
</code></pre>
Note that the SDK by Xilinx will provide/create the library (BSP) sources, they&#8217;re not included in this download.
Some of the sources have been adapted for +TCP or +FAT, they can be found under their original name in the &#8216;portable&#8217; directories:
~~~~~
    FreeRTOS-Plus/Source/FreeRTOS-Plus-TCP/portable/NetworkInterface/Zynq/
    FreeRTOS-Plus/Source/FreeRTOS-Plus-FAT/portable/Zynq/
~~~~~
About iperf sources: a couple of months ago I wrote an iperf server program for FreeRTOS+TCP. You can find it as an attachment to this post (<code>iperf_plus_tcp.zip</code>)
It uses a single task to handle all iperf clients, both UDP and TCP. This is possible by making all recv() and send() calls non-blocking and only block on a call to:
~~~~~
    xResult = FreeRTOS_select( xSocketSet, xBlockingTime );
~~~~~
The module can use zero-copy, if &#8216;ipconfigIPERF<em>USE</em>ZERO_COPY&#8217; is defined as non-zero.

Do you have the zynq+FAT+TCP demo running already ?
If so I will integrate it into that application and make it available to you.
On the Sourceforge email I saw your question about speed / performance. Here is an answer to that:
<blockquote>
  test out whats the max throughput for freeRTOS tcp?
</blockquote>
That is difficult to say.
lwIP has several layers of usage, and the so-called raw API&#8217;s are a bit faster than the BSD socket interface.
Like I wrote, +TCP has chosen to only offer a BSD socket interface and make several back-doors for users who need high-speed i/o. These back-doors allow direct call-backs and also zero-copy.
I won&#8217;t produce any (benchmark) numbers here because those numbers are not a fixed property of a stack. The speed of Ethernet / Internet depends on so many things, parameters, settings.
It is not very useful to measure the speed  of &#8216;data-pumping&#8217; like iperf does. It is much more interesting if the data goes to some application which works with it and sends replies.
Can you tell something about your application? What is it that needs so much speed? Is your LAN always quiet enough to guarantee so much bandwidth?
Regards.

Once the +TCP is up and running, you only have to call <code>vIPerfInstall()</code>, which will start-up the iperf-task.
I tested it with this compiler option:
<pre><code>#define ipconfigIPERF_DUAL_TCP    0

That means that the server will <strong>not</strong> make a return TCP connection to the client.
Please note that <code>iperf_task_v1_0.c</code> is not a FreeRTOS product. I wrote and tested it for one user on this forum, as an example of TCP + UDP servers.
