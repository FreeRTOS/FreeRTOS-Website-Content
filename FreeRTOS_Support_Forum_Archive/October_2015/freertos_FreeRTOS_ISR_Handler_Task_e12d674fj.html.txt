</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS ISR Handler Task</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on October 26, 2015</div><div class="thread-post-content"><blockquote>
  &#8211;>Create 6 Tasks (1ms, 5ms, 10ms, 20ms, 50ms, 100ms)
</blockquote>
Is that the cycle rates of the tasks?  What is the tick frequency?  If it is 1KHz then remember you only have a timing granularity of 1ms &#8211; and also the 1ms task will start running after every tick (assuming it is the highest priority).
<blockquote>
  &#8211;>Create a high priority Interrupt Handler Task. Initially this Task is suspended using vTaskSuspend(). This task is resumed only from ISR.
</blockquote>
Do NOT do this!  Please read the API documentation http://www.freertos.org/taskresumefromisr.html &#8211; it is an almost guaranteed way of loosing interrupts.  Consider what will happen if the interrupt tries to resume the task before it is suspended.  The best method is to use a direct to task notification.  http://www.freertos.org/RTOS<em>Task</em>Notification<em>As</em>Binary_Semaphore.html
<blockquote>
  Repeatedly it enters only ISR routine.
</blockquote>
Is the interrupt being cleared?
