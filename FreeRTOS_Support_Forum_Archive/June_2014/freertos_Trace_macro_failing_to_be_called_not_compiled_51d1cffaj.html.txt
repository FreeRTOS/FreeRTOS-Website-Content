  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Trace macro failing to be called (not compiled)</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/erupter">erupter</a> on June 4, 2014</div><div class="thread-post-content">I have a basic project running, but tasks are not doing what I want so I would like to use the traceTASK<em>SWITCHED</em>IN/OUT macros to output something to a logic analyzer.
So here is my code
<pre><code>
void setLogOutput (unsigned long c)
{
    int a;
    if (c == 0)
        a = 0;
}
#define traceTASK_SWITCHED_IN() setLogOutput(pxCurrentTCB->uxTaskNumber)
#define traceTASK_SWITCHED_OUT() setLogOutput(0)
#include "FreeRTOS.h"
</code></pre>
Obviously setLogOutput doesn&#8217;t do anything right now, and <b>I know it</b>.
But the point is that neighter SWITCHED<em>IN nor SWITCHED</em>OUT are ever called or compiled.
Breakpoints in tasks.c are broken.
I cannot understand what I am doing wrong, could anybody please help me?
</div></div><div class="thread-post"><h3 class="thread-post-title">Trace macro failing to be called (not compiled)</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on June 4, 2014</div><div class="thread-post-content">Where have you defined the macros?
The easiest place to put them, to get the correct include order, is at the bottom of FreeRTOSConfig.h.
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">Trace macro failing to be called (not compiled)</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on June 4, 2014</div><div class="thread-post-content">Hi,
You could try:
~~~~~~
volatile unsigned int dummy;
void setLogOutput (unsigned long c)
{
    dummy++;
}
~~~~~~
It is possible that optimiser ignores the code, because it does nothing.
GCC is very clever with this: it sees when a variable is only used in the left-hand size of expressions, and in that case it will never be implemented. &#8216;volatile&#8217; might help or better: print the variable somewhere.
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">Trace macro failing to be called (not compiled)</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/jdurand">jdurand</a> on June 4, 2014</div><div class="thread-post-content">I&#8217;ve been seeing GCC get more and more clever about working around my
ways to keep variables/code from being deleted.  There was a time when
global variables were safe, but not now.
I&#8217;ve tried debugging with no optimization, but that just blows the code
up where it doesn&#8217;t fit.  I now run with -Og which seems to be a
reasonable compromise most of the time.
