  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Linker Error using STM32F4 &#038; FreeRTOS</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/groufosse">groufosse</a> on June 2, 2014</div><div class="thread-post-content">Hi,
I believe I have followed the steps to integrate FreeRTOS into my STM32F4 project, but getting a link error. 
I modified the startup file for EWARM (IAR) and added the declarations there:
                EXTERN xPortPendSVHandler
                EXTERN xPortSysTickHandler
                EXTERN vPortSVCHandler
Also change further below in the __vector<em>table:
        DCD     vPortSVCHandler           ; SVCall Handler
        DCD     DebugMon</em>Handler          ; Debug Monitor Handler
        DCD     0                         ; Reserved
        DCD     xPortPendSVHandler        ; PendSV Handler
        DCD     xPortSysTickHandler       ; SysTick Handler
I have the file &#8220;FreeRTOSConfig.h&#8221; in my local include directory and it&#8217;s in the compiler&#8217;s preprocessor path. Still, I get this link error:
Error[Li005]: no definition for &#8220;vPortSVCHandler&#8221; [referenced from C:UsersrdsDocumentsIAR Embedded WorkbenchADC2ProjectsEWARMADC2 ConfigurationObjstartup_stm32f407xx.o] 
Can someone please provide some insight on this&#8230;?
Thank you.
</div></div><div class="thread-post"><h3 class="thread-post-title">Linker Error using STM32F4 &#038; FreeRTOS</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on June 3, 2014</div><div class="thread-post-content">I&#8217;m not sure why that would be as it looks ok.
The other option would be to keep the linker script exactly as delivered by IAR, then add the following lines into FreeRTOSConfig.h to effectively change the names of the FreeRTOS handlers:
<div style="background: #ffffff; overflow:auto;width:auto;border:solid gray;border-width:.1em .1em .1em .8em;padding:.2em .6em;"><pre style="margin: 0; line-height: 125%"><span style="color: #0000ff">#define vPortSVCHandler SVC_Handler</span>
<span style="color: #0000ff">#define xPortPendSVHandler PendSV_Handler</span>
<span style="color: #0000ff">#define xPortSysTickHandler SysTick_Handler</span>
</pre></div>
Regards,
Richard Barry.
</div></div><div class="thread-post"><h3 class="thread-post-title">Linker Error using STM32F4 &#038; FreeRTOS</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/markwrichardson">markwrichardson</a> on June 3, 2014</div><div class="thread-post-content">In my assembler, I have to use an assembly directive &#8216;XREF&#8217; to cast a variable as public.  They are private by default.  Also, my C/ASM environment use different variable names as seen by the linker.  All C variable have an underscore &#8216;_&#8217; before the name.  So, if I want to use an assembly variable or function from C I have to name it in assembly starting with an underscore and drop it in the C code.
</div></div><div class="thread-post"><h3 class="thread-post-title">Linker Error using STM32F4 &#038; FreeRTOS</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/groufosse">groufosse</a> on June 3, 2014</div><div class="thread-post-content">Hi,
Thanks for the help. Richard, your suggestion worked and it now compiles and links correctly.
Now a further question regarding systick. In my code, I had a basic ADC configuration in a loop reading an input, which was working OK.
Now, I&#8217;ve added in (under IAR) the FreeRTOS 8 folder and all required files, and it builds OK. I still have the same main.c file, of which I&#8217;ve included:
<h1>include &#8220;FreeRTOS.h&#8221;</h1>
<h1>include &#8220;task.h&#8221;</h1>
<h1>include &#8220;semphr.h&#8221;</h1>
But I have NOT actually added any FreeRTOS tasks, statements or variables. However, it appears the basic ADC operation is no longer working correctly. I had a simple for loop running the ADC 50 times in the call &#8220;HAL<em>ADC</em>PollForConversion&#8221;, which was previously working fine. Now, it now runs exactly 3 times and then freezes (I havea printf stament in the loop). I don&#8217;t want to yet add a task or start the scheduler until I understand what is now happening.
Any suggestions as to what has happened, and why the ADC is behaving this way, especially without any FreeRTOS operating code yet added?
Thanks again for any assistance.
</div></div><div class="thread-post"><h3 class="thread-post-title">Linker Error using STM32F4 &#038; FreeRTOS</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/groufosse">groufosse</a> on June 3, 2014</div><div class="thread-post-content">Hi all,
I&#8217;ve figured out where the problem is&#8230;there isn&#8217;t. It&#8217;s now working OK.
For whatever reason (maybe someone can explain why) that, until I placed the reading of the adc withing a task and launched the scheduler, it doesn&#8217;t operate correctly. I suspect this has something to do with systick?
Thanks&#8230;
</div></div><div class="thread-post"><h3 class="thread-post-title">Linker Error using STM32F4 &#038; FreeRTOS</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on June 3, 2014</div><div class="thread-post-content">Glad its working for you.
I don&#8217;t know why you would get the issue you described, but here are some possibilities:
<ul>
<li>Your printf function is using semi-hosting, which uses the SVC function, but now you have a FreeRTOS handler on that function.</li>
<li>You conversion routine was somehow using SysTick for delays between polling, but SysTick is now hooked into something else.</li>
</ul>
Regards.
