  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">xTimerResetFromISR do not restart the timer period properly</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/sminder">sminder</a> on June 25, 2014</div><div class="thread-post-content">I use the a periodical software timer that has period of 25 ms. Also I have an asynchronous interrupts which have to restart period of my timer (after the interrupt the next timer callback expected after 25 ms). But I have a problem: after the interrupt the next timer callback occur after random time, not my expected value (25 ms). What is wrong?
Code sample for restart timer (in the interrupt) follow:
void rtosStartDataPrdTimer()
{
    portBASE_TYPE xHigherPriorityTaskWoken = pdTRUE;
<pre><code>xTimerResetFromISR(rtos_timers[xDataPrdInterval], &amp;xHigherPriorityTaskWoken);
</code></pre>
}
</div></div><div class="thread-post"><h3 class="thread-post-title">xTimerResetFromISR do not restart the timer period properly</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on June 25, 2014</div><div class="thread-post-content">Have you tried using the xHigherPriorityTaskWoken parameter to ensure the timer task runs straight away if reseting the timer resulted in the timer task becoming the higher priority ready task?  You do that calling either portYIELD<em>FROM</em>ISR( xHigherPriorityTaskWoken ) or portEND<em>SWITCHING</em>ISR( xHigherPriorityTaskWoken ) (depending on the port you are using) before exiting the ISR.
Did you check the return value of xTimerResetFromISR() to ensure the call was successful?
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">xTimerResetFromISR do not restart the timer period properly</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/sminder">sminder</a> on June 27, 2014</div><div class="thread-post-content">Absolutely, I check the return value of the xTimerResetFromISR() and it looks good. Since I use an ARM port of the FreeRTOS should I use the portYIELD<em>WITHIN</em>API() function?
</div></div><div class="thread-post"><h3 class="thread-post-title">xTimerResetFromISR do not restart the timer period properly</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on June 27, 2014</div><div class="thread-post-content">Well FreeRTOS supports 8 different &#8216;ARM&#8217; architectures, but on all of them portYIELD<em>WITHIN</em>API() should not be used.  It is not part of the published API, and not intended for use by application writers.
You could use portYIELD<em>FROM</em>ISR().  That would ensure any task unblocked by the ISR would get a chance to run immediately that the ISR returns (the ISR would return to it, rather than the interrupted task) if the unblocked task has a priority higher than or equal to the currently running task.
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">xTimerResetFromISR do not restart the timer period properly</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/sminder">sminder</a> on June 27, 2014</div><div class="thread-post-content">Sorry for an inaccurate information. My chip is ATSAM4L (ARM Cortex-M4 core) but I didn&#8217;t find the portYIELD<em>FROM</em>ISR() macro in my RTOS sources (I&#8217;ve got a 7.4.2 version). Where can I get this macro for my chip?
P.S. IDE is IAR.
</div></div><div class="thread-post"><h3 class="thread-post-title">xTimerResetFromISR do not restart the timer period properly</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on June 27, 2014</div><div class="thread-post-content">In that version you will probably need to use portEND<em>SWITCHING</em>ISR().  Newer versions have both.
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">xTimerResetFromISR do not restart the timer period properly</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/sminder">sminder</a> on July 23, 2014</div><div class="thread-post-content">Thanks a lot!
