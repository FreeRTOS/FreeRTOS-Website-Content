  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Exception after adding global array</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/bnrtos">bnrtos</a> on April 20, 2011</div><div class="thread-post-content">Forgive the newbiancy, but I&#8217;ve just added a global array to my PIC32 project.&nbsp; e.g. buffer;&nbsp; I&#8217;ve already got several tasks and the project works great however when BUFFER&#95;SIZE is increased above a few hundred bytes or so, it seems a couple tasks no longer execute and I end up in the exception handler with a databus error.  
I&#8217;ve got the stack overflow set with a breakpoint in that hook and I&#8217;ve increased the heap size and all task sizes several times to no avail.  
Suggestions appreciated&#33;
</div></div><div class="thread-post"><h3 class="thread-post-title">Exception after adding global array</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on April 21, 2011</div><div class="thread-post-content">Have you checked that the tasks are actually created successfully? Look at the return value of xTaskCreate&#40;&#41;, and if you are using heap&#95;1.c or heap&#95;2.c &#40;not sure about heap&#95;3.c, but maybe that too&#41; then define a malloc failed hook to see if any allocations fail.  
Also check the linker script/map file to ensure you are using the right memory layout for the PIC32 chip you are using.
</div></div><div class="thread-post"><h3 class="thread-post-title">Exception after adding global array</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/bnrtos">bnrtos</a> on April 21, 2011</div><div class="thread-post-content">Hi Dave, thanks for the reply.  
&#45; Yes, I&#8217;ve got traps on all the xTaskCreate&#40;&#41; calls &#8211; no apparent problem there.&nbsp;<br />
&#45; I&#8217;m using heap&#95;2 and added the malloc failed hook/define but it doesn&#8217;t seem to be getting hooked.<br />
&#45; I&#8217;m not specifying a linker script so MPLAB is defaulting ot the standard script for my PIC32.  
Basically, I had a huge RTOS queue &#40;40960 bytes&#41; and found QueueSendToBack seemed a bit expensive so I was trying to replace it with my own circular buffer/array.&nbsp; I&#8217;ve made all the necessary changes, eliminated the queue, and defined my array buffer.&nbsp; Once I increase the size of my array past a couple hundred bytes, the tasks don&#8217;t seem to run properly.&nbsp; I know that&#8217;s a bit vague and it could be a multitude of things &#8211; the point is, I&#8217;m not &#42;using&#42; the array in my code yet… just allocating/defining it.&nbsp;   
If it&#8217;s under a certain size, everything works fine; if not, I don&#8217;t get any exceptions &#40;that I&#8217;m aware of&#41; but things are not fine.  
If I could create a Queue of size=40960, why can&#8217;t a define a native array of the same size?&nbsp; What&#8217;s different about the Queue creation?
</div></div><div class="thread-post"><h3 class="thread-post-title">Exception after adding global array</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/bnrtos">bnrtos</a> on April 21, 2011</div><div class="thread-post-content">Ok, wow, sorry for wasting everyone&#8217;s time.&nbsp; It turns out this wasn&#8217;t RTOS related at all.&nbsp; The initializer for said array was &#8220;0&#8221; instead of&nbsp; &#8220;&#123;0&#125;&#8221; which somehow caused all sorts of havoc without any warning&#40;s&#41;.  
Thanks for your time.
