  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Interrupt Enable/Disable &#8220;clobbers&#8230;</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/plinder13">plinder13</a> on April 29, 2011</div><div class="thread-post-content">I am using SafeRTOS on the Stellaris LM3S9B96.&nbsp;&nbsp; I know there is a forum for SafeRTOS and LM3S9B96, but I thought the FreeRTOS community would have some insight into my questions.  
The macros &#40;portSET&#95;INTERRUPT&#95;MASK&#40;&#41;, portCLEAR&#95;INTERRUPT&#95;MASK&#40;&#41;&#41; to disable and enable interrupts in portmacro.h &#8220;clobbers r0&#8221;, as the comments in the code indicate.&nbsp; I have noticed that recent versions of FreeRTOS push r0 on to the stack and pop it off afterwards, hence, r0 is not &#8220;clobbered&#8221;.&nbsp; Did older versions of FreeRTOS for Cortex-M3 &#8220;clobber&#8221; r0?&nbsp; Since the macro is a C macro with inline assembler, will &#8220;clobbering&#8221; r0 interfere with the compiler&#8217;s generation of code &#40;I know that the question is slightly dependant on the compiler&#41;.  
Basically, I am wondering if anyone has some insight to this and whether &#8220;clobbering&#8221; r0 is known to be an issue.&nbsp; Though I could rewrite the macro in portmacro.h to not &#8220;clobber&#8221; r0, I am sure the SafeRTOS version burned into ROM must be using the same code and hence &#8220;clobbering&#8221; r0 already.
</div></div><div class="thread-post"><h3 class="thread-post-title">Interrupt Enable/Disable &#8220;clobbers&#8230;</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on April 29, 2011</div><div class="thread-post-content">I have just had a quick glance at the code, and think the SafeRTOS version is doing exactly the right thing with regards to containing r0 in the clobber list.&nbsp; If it were a function it would not be necessary, but because it is a macro, it is.  
Now having just looked at the FreeRTOS version of the same macro, it looks to me to be identical to the SafeRTOS version with its use of the clobber list &#40;in the inline asm&#41;.&nbsp; Maybe you are looking at a different version of FreeRTOS?  
In any case, whether you add it to a clobber list and let the compiler sort it out, or whether you push and pop r0 manually, should not make any difference to the correctness of the code.&nbsp; Letting the compiler do it &#40;using the clobber list&#41; would be the better way though as it allows the compiler to perform better optimisation &#40;by, for example, not using r0 for anything else around the call to the macro&#41;.  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">Interrupt Enable/Disable &#8220;clobbers&#8230;</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/plinder13">plinder13</a> on April 29, 2011</div><div class="thread-post-content">I believe I am looking at the source code for the CCS4 port &#8211; which I realize is contributed and hence not officially supported.&nbsp; The port chooses to use the following in portasm.asm:  
;&#8212;&#8212;&#8212;&#8212;&#8212;&#8212;&#8212;&#8212;&#8212;&#8212;&#8212;&#8212;&#8211;  
vPortSetInterruptMask:  
push &#123; r0 &#125;<br />
mov r0, &#35;configMAX&#95;SYSCALL&#95;INTERRUPT&#95;PRIORITY&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;<br />
msr basepri, r0&nbsp;&nbsp;&nbsp;&nbsp;<br />
pop &#123; r0 &#125;<br />
bx r14  
;&#8212;&#8212;&#8212;&#8212;&#8212;&#8212;&#8212;&#8212;&#8212;&#8212;&#8212;&#8212;&#8211;  
vPortClearInterruptMask:  
push &#123; r0 &#125;<br />
mov r0, &#35;0<br />
msr basepri, r0<br />
pop &#123; r0 &#125;<br />
bx r14  
Based on what you are saying, it sounds like the compiler should handle it &#8211; but perhaps someone knows for sure whether the TI Compiler has any issues, hence the push and pop on the CCS port?
</div></div><div class="thread-post"><h3 class="thread-post-title">Interrupt Enable/Disable &#8220;clobbers&#8230;</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on April 29, 2011</div><div class="thread-post-content">The compiler will only handle it if you tell it it needs to handle it.&nbsp; i.e. you add the clobbered register to the clobber list.  
Clobber lists in that sense are a very sophisticated feature of the GCC inline assembler, and I doubt the code composer compiler has an equivalent.&nbsp; In which case, the push and pop will be necessary.  
Regards.
