Ive been messing around with an annoying problem in FreeRTOS and after few hours of testing, google searching i still cant resolve my problem. I am currently developing on a LM3S6965 Ethernet Eval Board.  
In my project its necessary to use float and double but i cant seem to get it right.  
<pre><code>INT8U buffer[50];
float value = 123.45;
sprintf(buffer, "%3.2f", value);
</code></pre>
When following code has been executed the buffer still remains 0x00 in all fields. Although normal integers does work with sprintf.   
The interesting part of my config looks like following:  
<pre><code>...
#define configUSE_PREEMPTION        1
#define configUSE_IDLE_HOOK         0
#define configUSE_TICK_HOOK         0

#define configMAX_TASK_NAME_LEN     ( 12 )

#define configUSE_16_BIT_TICKS      0
#define configIDLE_SHOULD_YIELD     0
#define configUSE_CO_ROUTINES       0
#define configUSE_MUTEXES           1
...
</code></pre>
And my portmacro.h  
<pre><code>/* Architecture specifics. */
#define portSTACK_GROWTH            ( -1 )
#define portTICK_RATE_MS            ( ( portTickType ) 1000 / configTICK_RATE_HZ )      
#define portBYTE_ALIGNMENT          8
</code></pre>
Basically it does not function in any way by using float or double.  
Is it a hardware restriction or have a simply overseen something?  
Thanks in advance.  
</div></div><div class="thread-post"><h3 class="thread-post-title">double/float problem with *printf</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on April 22, 2011</div><div class="thread-post-content">Many of the standard FreeRTOS demos include a tiny printf&#40;&#41;/sprintf&#40;&#41; implementation that is contained in a file called printf-stdarg.c.&nbsp; Are you including this file in your build, because it does not include floating point support.&nbsp; If you are including it, simply remove it to fall back to the default compiler provided library version, and then it should work &#40;but will also take a lot more stack space to execute&#41;.  
Regards.

</div></div><div class="thread-post"><h3 class="thread-post-title">double/float problem with *printf</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on April 13, 2012</div><div class="thread-post-content">Some of these problems were caused by stack alignment issues with 8 byte data types.&nbsp; The Cortex-M4F code is new, so could potentially have the same problem, but there are safeguards in the code now that should prevent it.&nbsp; Put a break point on entry to a task &#40;before the variable declarations&#41;, and look at the stack pointer value when the break point is hit &#8211; is it eight byte aligned?  
Regards.

</div></div><div class="thread-post"><h3 class="thread-post-title">double/float problem with *printf</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on April 13, 2012</div><div class="thread-post-content">Hmm.&nbsp; Which FreeRTOS version are you using, and are you using the official FreeRTOS CM4F code?&nbsp; If it is official code you should see something like this in the IAR CM4F port.c file:  
<pre><code>portSTACK_TYPE *pxPortInitialiseStack( portSTACK_TYPE *pxTopOfStack, pdTASK_CODE pxCode, void *pvParameters )
{
    /* Simulate the stack frame as it would be created by a context switch
    interrupt. */
    /* Offset added to account for the way the MCU uses the stack on entry/exit
    of interrupts, and to ensure alignment. */
    pxTopOfStack -= 2;
</code></pre>
That line of code should have taken care of your problem, but may need more or less subtracting from it.&nbsp; I can look at this when I have some CM4F hardware with me.  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">double/float problem with *printf</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/flash86">flash86</a> on April 13, 2012</div><div class="thread-post-content">Hi richardbarry&#33;<br />

</div></div><div class="thread-post"><h3 class="thread-post-title">double/float problem with *printf</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on April 13, 2012</div><div class="thread-post-content">Please try the following.  
In FreeRTOS/Source/Portable/RVDS/ARM&#95;CM3/portmarco.h, add the following line:  
<pre><code>#define portALIGNMENT_ASSERT_pxCurrentTCB ( void )
</code></pre>
then, in FreeRTOS/Source/Portable/RVDS/ARM&#95;CM3/port.c, change the first line in pxPortInitialiseStack&#40;&#41; from  
<pre><code>pxTopOfStack -= 2;
</code></pre>
to  
<pre><code>pxTopOfStack -= 1;
</code></pre>
and let me know if that fixes the problem of printing floating point numbers.&nbsp;   
Thanks and regards.
