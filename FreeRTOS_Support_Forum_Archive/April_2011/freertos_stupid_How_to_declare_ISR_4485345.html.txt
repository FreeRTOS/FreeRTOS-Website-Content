  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">*stupid* How to declare ISR?</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/sven-de">sven-de</a> on April 15, 2011</div><div class="thread-post-content">Hi, my setup is an ICSwift board with AT91SAM7X256 running the GCC/Eclipse-Demo. I managed to set up simple tasks on my own to blink the LEDs and to send out a simple countdown via CAN which I monitor with a CAN PC-card. Except for the uIP all of the demo tasks are disabled.  
Now I&#8217;m trying to set up an Interrupt to react on incoming CAN-messages, but whenever I sent a message &#40;ie. trigger the interrupt&#41; this totally resets the controller. This is visible by the LEDs, the CAN-Countdown restarts and even the network-connection is lost for an instant.  
I&#8217;m fairy certain this is because I don&#8217;t declare my ISR as such, but failed the whole morning to find out how to do this. So please, tell me the obviuous: how to declare an ISR?  
Am I missing something else, like clearing the Interrupt after being done?  
<pre><code>void CAN_IR_Handler(void)
{
    volatile unsigned int status;
    status = AT91C_BASE_CAN-&gt;CAN_SR &amp; AT91C_BASE_CAN-&gt;CAN_IMR;
    if(status &amp; AT91C_CAN_WAKEUP) {
        AT91C_BASE_CAN-&gt;CAN_IDR = AT91C_CAN_WAKEUP;
        flagCAN = 1;
    }
    if(status &amp; AT91C_CAN_MB0) {
        AT91C_BASE_CAN-&gt;CAN_MB0.CAN_MB_MCR = AT91C_CAN_MTCR;
    }
}
</code></pre>
</div></div><div class="thread-post"><h3 class="thread-post-title">*stupid* How to declare ISR?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/sven-de">sven-de</a> on April 15, 2011</div><div class="thread-post-content">After repeated reading of the demo documentation I tried this declaration  
<pre><code>void CAN_IR_Handler(void) __attribute__((interrupt("IRQ")));
</code></pre>
But got the Error, that &#8220;ISR cannot be coded in thumb mode&#8221;  
I figure it could also be, that the IR-vector points to the wrong location, so here&#8217;s the code for setting that up:  
<pre><code>AT91F_AIC_ConfigureIt( AT91C_ID_CAN, 1, AT91C_AIC_SRCTYPE_INT_HIGH_LEVEL, CAN_IR_Handler);
AT91C_BASE_AIC-&gt;AIC_IECR = 1 &lt;&lt; AT91C_ID_CAN;
</code></pre>
</div></div><div class="thread-post"><h3 class="thread-post-title">*stupid* How to declare ISR?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on April 15, 2011</div><div class="thread-post-content">On an ARM7 you have to use ARM mode for interrupts, or at least the interrupt entry point. Different versions of GCC have different bugs when it comes to trying to use the &#95;&#95;attribute&#95;&#95;&#40;&#40;interrupt&#41;&#41;, so it is best avoided. Instead, write your own interrupt entry code. There are lots of examples on the FreeRTOS web site, and in the download source code. For example look at the Interrupt Service Routines section on this page <a href="http://www.freertos.org/portat91fr40008.html">http://www.freertos.org/portat91fr40008.html</a>  
Even then it suggests using an attribute&#40;&#40;naked&#41;&#41; function for the entry point, but that too has issues with some GCC versions. I would say, write the wrapper in ARM assembly code, and write the handler that is called by the wrapper in C code. I&#8217;m sure there are examples of that in the download too.
</div></div><div class="thread-post"><h3 class="thread-post-title">*stupid* How to declare ISR?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/sven-de">sven-de</a> on April 18, 2011</div><div class="thread-post-content">Hi Dave, thanks for your quick reply. I&#8217;ve been following your advice without success, the CAN-Interrupt still resets the whole controller. What bugs me most is that the code in SAM7&#95;EMAC.c and EMAC&#95;ISR.c looks just like mine but is working &#40;incoming traffic doesn&#8217;t reset everything&#41;.  
One strange thing I observed: The order of Handler/Wrapper-definition makes a difference. When defining the handler first an the wrapper second &#40;as below&#41; I get the mentioned reset. But when switching the order to wrapper first, handler second &#40;as in EMAC&#95;ISR.c&#41; I get a total freeze. Also removing flagCAN = 1; in the Handler causes a freeze. This behaviour contradicts everything I believed to know about programming.  
Speaking of strange: When using portSAVE&#95;CONTEXT&#40;&#41; and portRESTORE&#95;CONTEXT&#40;&#41; as in EMAC&#95;ISR.c the compiler complains with a couple of these: &#8220;Error: selected processor does not support &#96;stmdb SP&#33;,&#123;R0&#125;'&#8221;. Meanwhile EMAC&#95;ISR.c compiles just fine.  
This is my current code:  
<pre><code>void CAN_IR_Wrapper(void) __attribute__ ((naked));
void CAN_IR_Handler(void) __attribute__ ((noinline));
void CAN_IR_Wrapper(void)
{
    //portSAVE_CONTEXT();
    __asm volatile ("bl CAN_IR_Handler");
    //portRESTORE_CONTEXT();
}
void CAN_IR_Handler(void)
{
    volatile unsigned int status;
    status = AT91C_BASE_CAN-&gt;CAN_SR &amp; AT91C_BASE_CAN-&gt;CAN_IMR;
    if(status &amp; AT91C_CAN_WAKEUP) {
        AT91C_BASE_CAN-&gt;CAN_IDR = AT91C_CAN_WAKEUP;
        flagCAN = 1;
    }
    if(status &amp; AT91C_CAN_MB0) {
        AT91C_BASE_CAN-&gt;CAN_MB0.CAN_MB_MCR = AT91C_CAN_MTCR;
    }
    /* Clear the interrupt. */
    AT91C_BASE_AIC-&gt;AIC_EOICR = 1;
}
// within main() before starting the scheduler or any tasks:
    portENTER_CRITICAL();
    // CAN Interrupt aktivieren
    AT91C_BASE_CAN-&gt;CAN_IER = AT91C_CAN_MB0;
    AT91F_AIC_ConfigureIt( AT91C_ID_CAN, 6, 0, ( void (*)( void ) ) CAN_IR_Wrapper);
    AT91C_BASE_AIC-&gt;AIC_IECR = 1 &lt;&lt; AT91C_ID_CAN;
    portEXIT_CRITICAL();
</code></pre>
</div></div><div class="thread-post"><h3 class="thread-post-title">*stupid* How to declare ISR?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/sven-de">sven-de</a> on April 18, 2011</div><div class="thread-post-content"><strong>PROBLEM SOLVED</strong>  
The ARM vs. THUMB mode aspect never really fired in my brain so I hat the ISR in my main.c. By coincidence I had a look into the makefile and only then realised my mistake. The ISR need to be in a dedicated file listed among those destined for compilation in ARM mode.  
Jesus, am I glad. Free hugs for everyone&#33;
