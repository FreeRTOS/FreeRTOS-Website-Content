<pre><code>/* Check the alignment of the initialised stack. */
        configASSERT( ( ( ( unsigned long ) pxNewTCB-&gt;pxTopOfStack &amp; ( unsigned long ) portBYTE_ALIGNMENT_MASK ) == 0UL ) );

<pre><code>/* Hardware specifics. */

</code></pre>
I read that the port alignment was changed in a previous version of FreeRTOS. Am I doing something wrong here or may the check/assert be wrong?   
Thanks a lot for your support.<br />
Nils

<pre><code>#define configASSERT( x )

</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS 7.0.0, PIC32, alignment of stack</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on April 12, 2011</div><div class="thread-post-content">Ok &#8211; here is a fix.  
In the file FreeRTOS/Source/Portable/MPLAB/PIC32MX/port.c, find the function pxPortInitialiseStack&#40;&#41;.&nbsp; At the very of of that function add the code:  
<pre><code>    /* Ensure byte alignment is maintained when leaving this function. */
    pxTopOfStack--;
</code></pre>
This should be the first line in the function, and no other lines should be changed.  
The port was originally written for 4 byte alignment &#8211; and later the check constant changed to 8 byte alignment, hence the source of this problem.  
I will add this to the list of known issues.&nbsp; Thanks for reporting it.  
Regards.
