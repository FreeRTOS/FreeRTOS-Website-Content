  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">returning at *beginning* of task after vTaskD</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/ivansb">ivansb</a> on April 19, 2011</div><div class="thread-post-content">I&#8217;ve 2 tasks one that parse input the other that execute actions:  
<pre><code>vTaskAction(void *pvParameters ) {
  for(;;) {
    // resume here
    switch (phase) {
      case a_state1:
        // do something
        vTaskDelay(N);
        // do something else
    }
  }  
}
vTaskInput(void *pvParameters ) {
  for(;;) {
    // change phase according to input
  }
}
</code></pre>
I&#8217;m using vTaskDelay because it frees CPU cycles inspite of using an internal counter to &#8220;delay&#8221;.  
Now suppose vTaskAction is waiting after it execude vTaskDelay, vTaskInput kicks in and change phase.  
I&#8217;d like vTaskInput to be able to make vTaskAction to conditionally resume from the beginning of vTaskAction and not from the end of vTaskDelay.  
Is there a way I can make a task wait &#40;and not consume cpu cycles&#41; and conditionally restart from where I stopped it OR &#8220;reset&#8221; the Task and start from the beginning eg. as if the Task was just created and resumed?  
</div></div><div class="thread-post"><h3 class="thread-post-title">returning at *beginning* of task after vTaskD</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on April 19, 2011</div><div class="thread-post-content">Instead of calling vTaskDelay&#40; delay&#95;time &#41;, call xQueueReceive&#40; …, …, delay&#95;time &#41; so delay&#95;time is the block time. Now if you want the task to restart, send a message to the queue telling the task to restart. If it does not receive a message on the queue it will time out and continue as before.  
Another way might be to simply delete then restart the task, but that is probably not a good way.
</div></div><div class="thread-post"><h3 class="thread-post-title">returning at *beginning* of task after vTaskD</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/ivansb">ivansb</a> on April 20, 2011</div><div class="thread-post-content">Perfect.  
If I push something in the queue from vTaskInput, vTaskAction will resume execution.  
Is there a way to know how much time passed?  
One way could be to use xTaskGetTickCount&#40;&#41; but I&#8217;m not really sure if it gets the work done as I expect &#40;eg. how overflow should be handled?&#41;.  
thanks
</div></div><div class="thread-post"><h3 class="thread-post-title">returning at *beginning* of task after vTaskD</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on April 21, 2011</div><div class="thread-post-content">The tick is an unsigned number so take the tick reading before waiting on the queue, and again after waiting on the queue, then take away the after time from the before time and overflows will not matter &#40;the unsigned number will wrap round&#41;. That assumes only one overflow can happen while you are waiting. If there could be more than one overflow then FreeRTOS keeps an overflow count and has some private utilities for working out time differences, but that would need digging around in the code internals.
