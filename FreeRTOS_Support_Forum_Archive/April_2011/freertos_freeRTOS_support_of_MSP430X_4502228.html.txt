  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">freeRTOS support of MSP430X</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/williamjsell">williamjsell</a> on April 24, 2011</div><div class="thread-post-content">I tried to port freeRTOS over to the msp430f5529 platform from the existing msp430f449 freeRTOS demo;&nbsp; I am using Crossworks V2.0 as the dev environment; it was pretty straightforward, or so it seemed; but when I called the asm line &#8220;call &#35;&#95;prvSetupTimerInterrupt&#8221;, the call never returns; at first I thought this was the stack getting manipulated to vector to the first task, but the call to portRESTORE&#95;CONTEXT is never reached, which means the stack should have the return address to the calling function. But this is not working and I cannot see the reason;&nbsp; Paul Curtis at Crossworks thinks this is something to do with the compilation being for the MSP430X series of processors which have a different idea of function pointers.&nbsp; To save myself some time figuring this issue, I thought I would check and see if anyone else has encountered a similiar problem; the new series of MSP&#8217;s from TI are getting very popular with the extended memory range and internal USB hardware, so it seems like a good thing to fix  
thanks  
-Bill
</div></div><div class="thread-post"><h3 class="thread-post-title">freeRTOS support of MSP430X</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on April 24, 2011</div><div class="thread-post-content">If you have the compiler set to use the extended memory, then you should be calling &#8220;calla&#8221;, not &#8220;call&#8221;.&nbsp; Check out the MSP430X instruction set.  
I would suggest using the provided IAR and CCS4 MSP430X ports &#40;in the FreeRTOS download&#41; as a reference.&nbsp; The Rowley compiler differs somewhat with regard to how function pointers are are used though, so when setting up the initial stack for the task you will have to de-reference to 16 bit pxCode parameter in the pxPortInitialiseStack&#40;&#41; function to find the true 20 bit value.&nbsp; &#40;the function pointer actually points to a look up table that contains the real addresses&#41;.  
Regards.
