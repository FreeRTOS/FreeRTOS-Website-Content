  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Is there a way I can use xQueueSelectFromSet in tandem with xQueueReceive?</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/kailashs">kailashs</a> on February 19, 2016</div><div class="thread-post-content">Hi,
I am using FreeRTOS v8.2.3 on a PIC32 micro controller. I have a case where I need to post the following 3 events to 3 corresponding queues from an ISR, in order to unblock a task awaiting one of these events at a time &#8211;
 a) SETUP packet arrival
 b) Transfer completed event 1
 c) Transfer completed event 2
 My exection sequence and requirement are as follows:
<strong>Case 1 (execution is blocked for an event at point_1):</strong>
 As SETUP arrives while waiting at point_1 of execution &#8211; 
 i) the waiting task should be unblocked
 ii)Setup received from queue and processed
 Some code is processed and reaches point_2
**Case 2  (execution is blocked for an event at point<em>2): **
 If any one of SETUP or transfer complete events occur at point</em>2 &#8211;
i) unblock the wait
ii) receive transfer<em>complete</em>1 or transfer<em>complete</em>2 event from queue to carry out some additional transfers and loop at point<em>2
iii)if it was a Setup queue event, do not receive, but go to point</em>1
The code does not seem to work when I try to use xQueueReceive and xQueueSelectFromSet on the Setup queue even when one of them is used at point<em>1 and the other used at point</em>2.
But seems to work fine if I use xQueueSelectFromSet at both the places and verify the queuset member handle that caused the event to proceed further.
 Given the requirement above, the problem with using xQueueSelectFromSet at both the places is that 
 &#8211; the xQueueSelectFromSet call will be placed back to back, first on a Setup event at point<em>2 and then immediately on point</em>1 which is not intentional
 &#8211; the xQueueSelectFromSet call at point_1 is also not desired
Hence can anyone please explain whether and how to use both a queueset and queuereceive on the same queue? If not possible how do we typically implement the above requirement in FreeRTOS?
Thank you very much for your precious time in advance. Have a good day!!!
<ul>
<li>Kailash &#8211; </li>
</ul>
</div></div><div class="thread-post"><h3 class="thread-post-title">Is there a way I can use xQueueSelectFromSet in tandem with xQueueReceive?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on February 19, 2016</div><div class="thread-post-content">I don&#8217;t fully understand your usage scenario, but some points which may help.
1) If a queue is a member of a queue set, then the queue can only be read after its handle has been returned from the queue set.  Further, if a queue&#8217;s handle is returned from a queue set then the item must be read from the queue.  If either of these requirements are not met then the state of the queue set will not match that of the queues in the set.
2) If the same task is reading from the multiple queues then it is probably not necessary to use a queue set at all.  See the &#8220;alternatives to using queue sets&#8221; section on the following page: http://www.freertos.org/Pend-on-multiple-rtos-objects.html
</div></div><div class="thread-post"><h3 class="thread-post-title">Is there a way I can use xQueueSelectFromSet in tandem with xQueueReceive?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/kailashs">kailashs</a> on February 20, 2016</div><div class="thread-post-content">Thanks, for the pointers. I guess may need a revisit on the queueset alternative with respect to my use cases. BTW, my usage scenario is an implementation of a USB device driver which receives / sends USB packets (through a SIE) over the bus from / to  a host computer, thus enabling the device enumeration along with implementing the business logic framework for application layers who are providers / consumers of data.
