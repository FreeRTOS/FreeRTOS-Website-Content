  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">STM32F10x tick rate 1/2 speed</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/ajcurtis84">ajcurtis84</a> on February 2, 2016</div><div class="thread-post-content">Hello,
I am having difficulties with timers and vTaskDelay() with the STM32F processor. It appears that delays are about 2X the programmed rate.
I created a very simple task that delays for 4 seconds and reports the actual number of elapsed ticks. The ticks are correct but the actually delay is around 8 seconds.
Sample code:
~~~~
    TickType<em>t start</em>tick;
    TickType<em>t end</em>tick;
    do {
        start<em>tick = xTaskGetTickCount();
        vTaskDelay(4000);
        end</em>tick = xTaskGetTickCount();
        trace<em>printf(&#8220;msec2ticks:%u ticksn&#8221;, (uint16</em>t)(end<em>tick-start</em>tick));
    }
    while (pdTRUE);
~~~~
Originally I thought this was a problem in 8.2.3, however I back ported to 8.2.0 and received the same results.
The only other change is the trace output configuration. Changed:
~~~~
<h1>undef OS<em>USE</em>TRACE_SEMIHOSTING</h1>
<h1>define OS<em>USE</em>TRACE_ITM</h1>
~~~~
Has anyone else had this issue?
TIA

</div></div><div class="thread-post"><h3 class="thread-post-title">STM32F10x tick rate 1/2 speed</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on February 2, 2016</div><div class="thread-post-content">When I read:
<blockquote>
  I created a very simple task that delays for 4 seconds and reports the actual number of elapsed ticks. The ticks are correct but the actually delay is around 8 seconds.
</blockquote>
When reading this my thought was, if the delay is correct in the number of ticks, but the time is different, then this is simply a case of the CPU clock running at a different frequency to that which you think it is.  Perhaps configCPU<em>CLOCK</em>HZ is wrong.  However, then you write:
<pre>
#undef OS_USE_TRACE_SEMIHOSTING
#define OS_USE_TRACE_ITM
</pre>
you mention semihosting.  Are you using semihosting?  If so, don&#8217;t, it will mess up your timing as it will stop the CPU while outputing to the host &#8211; and that might be the problem you are seeing.
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">STM32F10x tick rate 1/2 speed</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/ajcurtis84">ajcurtis84</a> on February 2, 2016</div><div class="thread-post-content">Hello, 
Thank you for the reply. No, I am not using SEMIHOSTING. Originally I was but it was causing all sorts of problems.
My BSP does not have the sysclk<em>get</em>clk_hz() function so I inserted the following code.
~~~~
  trace_printf(&#8220;System clock: %u Hzn&#8221;, SystemCoreClock);
<pre><code>RCC_ClocksTypeDef clock;
RCC_GetClocksFreq(&amp;clock);
trace_printf("SYSCLK=%ld,HCLK=%ld,PCLK1=%ld,PCLK2=%ld,ADCCLK=%ldn",
        clock.SYSCLK_Frequency,
        clock.HCLK_Frequency,
        clock.PCLK1_Frequency,
        clock.PCLK2_Frequency,
        clock.ADCCLK_Frequency);
</code></pre>
~~~~
This is the output
<blockquote>
  System clock: 8000000 Hz
  SYSCLK=8000000,HCLK=8000000,PCLK1=8000000,PCLK2=8000000,ADCCLK=4000000
</blockquote>
Based on this I debugged the SystemInit() function and determined that HSE never becomes ready. It looks like the oscillator isn&#8217;t working?
Thank you for pointing me in the right direction.
