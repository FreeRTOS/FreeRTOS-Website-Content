</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS+TCP: How can I switch DHCP on/off at runtime</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on February 10, 2016</div><div class="thread-post-content">hi Stefan,
<blockquote>
  Is this possible/planned for a future release?
</blockquote>
It should already be possible with the current 160112 release.
Please check http://www.freertos.org/labs for the latest download.
~~~~~
<h1>if( ipconfigDHCP<em>USES</em>USER_HOOK != 0 )</h1>
<pre><code>/* This is the config parameter: DHCP enabled or not. */
BaseType_t DHCPIsEnabled;
extern "C" BaseType_t xApplicationDHCPUserHook( eDHCPCallbackQuestion_t eQuestion,
    uint32_t ulIPAddress, uint32_t ulNetMask );
BaseType_t xApplicationDHCPUserHook( eDHCPCallbackQuestion_t eQuestion,
    uint32_t ulIPAddress, uint32_t ulNetMask )
{
BaseType_t xResult = ( BaseType_t ) eDHCPContinue;
    switch( eQuestion )
    {
    case eDHCPOffer:        /* Driver is about to ask for a DHCP offer. */
        /* Returning eDHCPContinue. */
        break;
    case eDHCPRequest:      /* Driver is about to request DHCP an IP address. */
        if( DHCPIsEnabled == pdFALSE )
        {
            xResult = ( BaseType_t ) eDHCPStopNoChanges;
        }
        break;
    }
    FreeRTOS_printf( ( "DHCP %s: use = %d: %sn",
        ( eQuestion == eDHCPOffer ) ? "offer" : "request",
        DHCPIsEnabled,
        xResult == ( BaseType_t ) eDHCPContinue ? "Cont" : "Stop" ) );
    return xResult;
}
</code></pre>
<h1>endif  /* ipconfigDHCP<em>USES</em>USER_HOOK */</h1>
~~~~~
In the above example the DHCP offer will always be asked for. The reason is that along with the offer other parameters are known: default gateway, network and netmask.
If <code>DHCPIsEnabled</code> is false, the fixed (configured) IP-address will be used. 
If <code>DHCPIsEnabled</code> is true, DHCP will be attemped (using the configured parameters for timing). If there is no valid response, the fixed pre-configured IP-address will also be used.
Please ask if I left anything unclear.
Regards.

</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS+TCP: How can I switch DHCP on/off at runtime</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on February 10, 2016</div><div class="thread-post-content"><blockquote>
  The first time this hook gets called it is with <code>eDHCPOffer</code>, which in the
  code you suggested did result in the DHCP discover packet to be send at
  least once. Does this make sense?
</blockquote>
That makes sense.
The library will do at most two call-backs:
~~~~
    eDHCPOffer:   Driver is about to ask for a DHCP offer
    eDHCPRequest: Driver is about to request DHCP an IP address
~~~~
If you do not reply <code>eDHCPContinue</code> in the state <code>eDHCPOffer</code>, you will never see the second question <code>eDHCPRequest</code>.
In my applications I&#8217;d always return <code>eDHCPContinue</code> to <code>eDHCPOffer</code> because I want to know the values of the other fields (GW, DNS).
Then if the user has indicated to use a fixed IP-address, I&#8217;d answer <code>eDHCPStopNoChanges</code> to the second question <code>eDHCPRequest</code>.
Within my <code>vApplicationIPNetworkEventHook()</code>, the code will set the final parameters to work with:
~~~~
if( ( DHCPIsEnabled == pdFALSE ) || ( DHCPFailed == pdTRUE ) )
{
    FreeRTOS_SetAddressConfiguration(
        &amp;ulIPAddress,
        &amp;ulNetMask,
        &amp;ulGateway,
        &amp;ulDNSAddress);
}
~~~~
Regards, Hein
