</div></div><div class="thread-post"><h3 class="thread-post-title">Malloc failed in with pic32MX port</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on February 22, 2016</div><div class="thread-post-content">One danger with using heap memory is that the heap space can become fragmented and hard to find large blocks. For instance, if you allocate a number of 1k blocks, then release every other one, the space left normally can&#8217;t be used to allocate a 2k block. This is one reason many coding standards restrict the use of heap memory to startup and &#8216;non-critical&#8217; operations that are allowed to &#8216;fail&#8217;.
</div></div><div class="thread-post"><h3 class="thread-post-title">Malloc failed in with pic32MX port</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/chaabanemalki">chaabanemalki</a> on February 22, 2016</div><div class="thread-post-content">I have allocated 36k for the kernel total heap, after few allocations of 38,32,512&#8230; bytes (doesn&#8217;t exceed 4k), the pvPortMalloc() systematically  failes to allocate 2K space yet it reported that it has more than 11,5K free space.
I reduced the total heap to 30K and everything is working just fine now !!!

</div></div><div class="thread-post"><h3 class="thread-post-title">Malloc failed in with pic32MX port</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on February 22, 2016</div><div class="thread-post-content"><blockquote>
  What do you mean by &#8220;Is anything else walking over the heap space?&#8221; I&#8217;m
  not sure how to check that !!
</blockquote>
The heap includes some meta data that describes its state (which blocks 
are free, which allocated, etc.).  If there is a good old fashioned data 
corruption by another part of the application writing over this data 
then the heap implementation will misbehave because the meta data will 
be corrupt.
It might be that a certain part of your RAM is getting used by something 
else, either intentionally or unintentionally, and once you set the heap 
size large enough so it hits that RAM region, you get into problems of 
corruption.
