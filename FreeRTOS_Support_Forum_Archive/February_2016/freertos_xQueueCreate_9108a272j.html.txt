</div></div><div class="thread-post"><h3 class="thread-post-title">xQueueCreate</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/xz8987f">xz8987f</a> on February 23, 2016</div><div class="thread-post-content">Hi Koorosh,
it means that xReturn is NULL. And this means that xQueueCreate() was not able to allocte the queue. Step with your debugger through xQueueCreate() and you should see what is failing.
I think your problem is
    /* Allocate the new queue structure and storage area. */
    pxNewQueue = ( Queue_t * ) pvPortMalloc( sizeof( Queue_t ) + xQueueSizeInBytes );
and that pvPortMalloc() returns NULL because you don&#8217;t have enough heap allocated.
I suggest you allocate more heap with increasing
configTOTAL<em>HEAP</em>SIZE
in FreeRTOSConfig.h
I hope this helps,
Erich

</div></div><div class="thread-post"><h3 class="thread-post-title">xQueueCreate</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on February 23, 2016</div><div class="thread-post-content">The FreeRTOS heap is separate to the heap allocated by the linker &#8211; and 
FreeRTOS doesn&#8217;t touch the heap allocated by the linker unless you are 
using heap_3 (see http://www.freertos.org/a00111.html for an explanation 
of the different heap options).  Unless you code is calling malloc() 
somewhere then you can set the size of the heap allocated by the linker 
to 0 (or 4 as 0 is not always a valid value) as it is not needed.  You 
application code can always call pvPortMalloc() instead of malloc() too 
&#8211; which will also allow you to set the linker allocated heap to 0.
If you are interested there is a V9 release candidate on SourceForge 
currently that allows you to allocate this memory statically too 
http://www.freertos.org/FreeRTOS-V9.html
Regards.
