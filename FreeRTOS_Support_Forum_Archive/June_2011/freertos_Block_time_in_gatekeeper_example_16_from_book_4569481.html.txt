  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Block time in gatekeeper example 16 from book</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/anguel78">anguel78</a> on June 11, 2011</div><div class="thread-post-content">Hi&#33;  
Looking at example 16 in the book there is the prvPrintTask&#40;&#41; function which is used to send strings to the gatekeeper task. This task uses xQueueSendToBack&#40;&#41; with a block time of 0. The comments say that this block time is used because there should always be space in the queue. But I am not sure that this is safe &#40;especially to use it in an example&#41;, because both prvPrintTask&#40;&#41; instances have priorities higher than the gatekeeper task and use random blocking delays. Additionally there is an ISR also writing to the queue. Maybe it is unlikely that all delays happen to be very short 5 consecutive times &#40;5 is the size of the queue&#41;, but on the other hand the gatekeeper uses printf which takes a lot of time so IMHO the queue may become full because the low priority gatekeeper may not get the chance to always empty the queue in time and if it was another type of application &#8211; queuing important items to the queue may fail. Or do I misunderstand something?  
Regards,<br />
Anguel
</div></div><div class="thread-post"><h3 class="thread-post-title">Block time in gatekeeper example 16 from book</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/anguel78">anguel78</a> on June 11, 2011</div><div class="thread-post-content">Sorry, in the post above of course I wanted to say that prvPrintTask&#40;&#41; uses xQueueSendToBack&#40;&#41; with a block time of 0.
</div></div><div class="thread-post"><h3 class="thread-post-title">Block time in gatekeeper example 16 from book</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on June 11, 2011</div><div class="thread-post-content">I think your analysis is in fact accurate.&nbsp; While it is unlikely that the queue would become full, it is definitely not impossible.&nbsp; Probably the comment should be edited.&nbsp; In the example, posts to the queue that are not successful may pas unnoticed as the return value of the queue send function is not checked.  
Thanks for pointing this out.
