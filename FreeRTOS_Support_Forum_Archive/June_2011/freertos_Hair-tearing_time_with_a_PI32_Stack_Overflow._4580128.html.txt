  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Hair-tearing time with a PI32 Stack Overflow.</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/malcolmsmc">malcolmsmc</a> on June 20, 2011</div><div class="thread-post-content">I am attempting to transfer code from another RTOS &#40;inhouse on a Renesas chip&#41; to Freertos in the PIC32. All appears to work except that I get a random Stack Overflow exception.  
When I examine the problem I find the following:<br />
The crash occurs in the vTaskSwitchContext&#40;&#41; called from the vPortYeildISR&#40;&#41;<br />
The current tcb is the IDLE task<br />
The Top of stack is pointing into the xISRStack instead of it own stack.  
Anybody with any ideas before I become bald?
</div></div><div class="thread-post"><h3 class="thread-post-title">Hair-tearing time with a PI32 Stack Overflow.</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on June 21, 2011</div><div class="thread-post-content">Sounds like something is corrupting your task info.  
A few things to look at:<br />
Interrupt that calls FromISR routine having too high of an interrupt priority<br />
Interrupt that calls a non FromISR API routine<br />
Improper nesting of interrrupts<br />
A non-interrupt calling a FromISR routine<br />
Idle Hook function blocks<br />
You have a stack overflow in some task &#40;try turning on overflow detection&#41;
</div></div><div class="thread-post"><h3 class="thread-post-title">Hair-tearing time with a PI32 Stack Overflow.</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/malcolmsmc">malcolmsmc</a> on June 21, 2011</div><div class="thread-post-content">My first assumption was stack corruption so I run all interrupts at the same priority to avoid nesting, carefully checked the FromISR calls and use the default idle loop and disabled the pre-emption.<br />
I run with the stack overflow&nbsp; turned on &#40;2&#41; which is how I found the problem.  
The locations round the stack pointer in the TCB are OK except for the stack pointer value itself. The appearance is of the idle task calling an interrupt routine which returns without resetting the stack pointer&#33;  
</div></div><div class="thread-post"><h3 class="thread-post-title">Hair-tearing time with a PI32 Stack Overflow.</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on June 21, 2011</div><div class="thread-post-content">From the two comments:  
<blockquote>
  All appears to work except that I get a random Stack Overflow exception.
</blockquote>
and   
<blockquote>
  I run with the stack overflow&nbsp; turned on &#40;2&#41; which is how I found the problem.
</blockquote>
Are you getting a stack overflow exception?&nbsp; If so, that is not coming from having the stack overflow protection turned on in FreeRTOS.&nbsp; The mechanism in FreeRTOS will cause vApplicationStackOverflow&#40;&#41; to be called, not an exception to occur.&nbsp; I know some PIC architectures have stack limit registers catch stack overflows, but I&#8217;m not sure that applies to the MIPS based parts, and FreeRTOS does not use them anyway so that functionality should be off in the hardware.  
<blockquote>
  The Top of stack is pointing into the xISRStack instead of it own stack.
</blockquote>
Do you mean the top of stack used by the idle task?&nbsp; If so, then I agree that is wrong.&nbsp; Otherwise, in an interrupt that called vTaskSwitchContext&#40;&#41; I would expect the stack pointer <strong>at the time the function was called</strong> to be in the ISR stack, as, after all, it is being called from an ISR.  
<blockquote>
  so I run all interrupts at the same priority
</blockquote>
Was that the lowest priority &#8211; so the same priority used by the kernel for its tick interrupt?<br />
Are you using the assembly wrappers for your interrupts?  
Regards.  
</div></div><div class="thread-post"><h3 class="thread-post-title">Hair-tearing time with a PI32 Stack Overflow.</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/malcolmsmc">malcolmsmc</a> on June 21, 2011</div><div class="thread-post-content">OK &#8211; I was a little imprecise.  
For Stack Overflow exception read vApplicationStackOverflow&#40;&#41; call.  
Th idle task pxTopOfStack points into the xISRStack area.  
All interrupts are run at the configKERNEL&#95;INTERRUPT&#95;PRIORITY.  
I am using the same interupt structure as used for the example :  
……..<br />
.section .FreeRTOS, &#8220;ax&#8221;, @progbits<br />
.set noreorder<br />
.set noat<br />
.ent uart4Wrapper  
uart4Wrapper:  
portSAVE&#95;CONTEXT<br />
jal uart4Handler<br />
nop<br />
portRESTORE&#95;CONTEXT  
.end uart4Wrapper  
……..  
As far as I am aware I do no context switching in the interrupt service routines unless they occur in xQueueSendFromISR or xSemaphoreGiveFromISR functions.
