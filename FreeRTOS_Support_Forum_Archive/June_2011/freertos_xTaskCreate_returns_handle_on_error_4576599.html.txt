  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">xTaskCreate returns handle on error</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/dgheyl">dgheyl</a> on June 17, 2011</div><div class="thread-post-content">ATMega644 &#8211; WinAVR &#8211; FreeRTOS7.0.1<br />
Initially I start only one task and put the micro to sleep.&nbsp; If the start button is pressed, the micro wakes up and then other tasks are started. If the system is then turned off, those other tasks are deleted by the main task and then it goes back to sleep.&nbsp; When I start two additional tasks from the main, I can turn it on and off five times &#8211; the sixth time doesn&#8217;t start properly. If I start only one task, I can turn on/off 10 times before failure.&nbsp; I found that xTaskCreate is returning errCOULD&#95;NOT&#95;ALLOCATE&#95;REQUIRED&#95;MEMORY &#8211; obviously I&#8217;m doing something wrong to use up memory. So that is my first issue &#8211; what am I doing wrong?&nbsp; I do not allocate any memory &#8211; only have declared variables. I thought maybe I was putting the micro to sleep before the OS had time to clean up, so I added this:<br />
while &#40;1&#41;<br />
&#123;<br />
num = uxTaskGetNumberOfTasks&#40;&#41;;<br />
if &#40;num == 2&#41;<br />
break;<br />
vTaskDelay&#40; &#40; portTickType &#41; 200 / portTICK&#95;RATE&#95;MS &#41;;<br />
&#125;<br />
It appears to drop to two tasks after one loop, which makes sense &#8211; I assume the 2nd task is the Idle task. So that doesn&#8217;t appear to be the problem.&nbsp; Any ideas about why I&#8217;m using up memory?&nbsp; Or is more time needed?  
The second issue is that I question whether xTaskCreate is working as expected when it returns errCOULD&#95;NOT&#95;ALLOCATE&#95;REQUIRED&#95;MEMORY. Again using uxTaskGetNumberOfTasks&#40;&#41; to look at the number of tasks, it appears that the task was not actually created when the error is returned.&nbsp; However, it returns a Handle, which I did not expect &#8211; assumed it would return 0 for Handle if not created.&nbsp; I was checking for a non-zero Handle before calling vTaskDelete.&nbsp; When I did this &#8211; tried to delete the tasks that weren&#8217;t really created, it ended up deleting all my tasks &#8211; uxTaskGetNumberOfTasks&#40;&#41; = 0.&nbsp; Is that how you would expect it to work?  
Best Regards,<br />
Dave
</div></div><div class="thread-post"><h3 class="thread-post-title">xTaskCreate returns handle on error</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on June 17, 2011</div><div class="thread-post-content">I don&#8217;t think what happens to the task handle when a task cannot be created is specified anywhere &#8211; but what actually happens is nothing happens.&nbsp; The task handle is not touched if an error code is returned, so you will get out whatever you put in.  
With regards to running out of memory.&nbsp; See the following link: <a href="http://www.freertos.org/a00111.html">http://www.freertos.org/a00111.html</a> &#45; you will see that the FreeRTOS heap is used when tasks are created to allocate the task stack and TCB, and that if you are using the very simplest memory manager &#40;heap&#95;1.c&#41; you cannot free memory once it is allocated.&nbsp; Also see <a href="http://www.freertos.org/a00126.html">http://www.freertos.org/a00126.html</a> to get an explanation of when the memory that was allocated for the stack and TCB is freed again once the task has been deleted.  
Regards.

Thanks so much for the quick reply.&nbsp; I changed to heap&#95;2 and it works fine, of course.&nbsp; I had built this project on a much simpler earlier project and didn&#8217;t think about the memory management.
