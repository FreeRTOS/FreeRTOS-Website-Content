</div></div><div class="thread-post"><h3 class="thread-post-title">xEventGroupSetBitsFromISR() return pdFAIL from the ISR sometimes</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on July 5, 2018</div><div class="thread-post-content">There is no sub-tick resolution &#8211; if there is a tick every 5ms and you

</div></div><div class="thread-post"><h3 class="thread-post-title">xEventGroupSetBitsFromISR() return pdFAIL from the ISR sometimes</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/tlafleur">tlafleur</a> on July 6, 2018</div><div class="thread-post-content">What Richard is trying to explain to you is that a tick is NOT deterministic, if a task yield in the middle of a tick caused by an interrupted or another mechanism, the scheduler will run and launch the next available tasks of the highest priority it does not wait 5 ms to launch the next task&#8230;. doing so would be very inefficient use of the CPUs resources&#8230;.most all Operating systems work like this. If you need more accurate timing use a hardware timer or change the tick to something faster like 1 ms&#8230;. but setting the tick faster, cause the OS to spend more time in the scheduler so, it become a system design trade off&#8230;.
</div></div><div class="thread-post"><h3 class="thread-post-title">xEventGroupSetBitsFromISR() return pdFAIL from the ISR sometimes</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on July 6, 2018</div><div class="thread-post-content">To elaborate further:  The tick interrupt occurs at a fixed frequency.  If you ask to block for 1 tick you are effectively saying unblock the task at the next tick interrupt.  If there is a tick interrupt every five milliseconds, and you block a task four milliseconds after the last tick interrupt, then the next tick interrupt will occur one milllisecond after that task entered the blocked state &#8211; and the task will therefore only block for one millisecond.  This is what I mean by there is only (in your case) five millisecond resolution &#8211; you cannot block with any more accuracy than five milliseconds.
