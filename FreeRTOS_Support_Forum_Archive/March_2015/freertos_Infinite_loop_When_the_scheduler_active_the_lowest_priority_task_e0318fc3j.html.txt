</div></div><div class="thread-post"><h3 class="thread-post-title">Infinite loop When the scheduler active the lowest priority task</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on March 17, 2015</div><div class="thread-post-content">I&#8217;m not sure I follow the description of the problem.  Your task is implemented as an infinite loop &#8211; as would be normal.  When it gets to the bottom of the for(;;) loop I would expect it to go back to the top of the for(;;) loop &#8211; are you saying instead of doing that it is going right back to the top of the function &#8211; so executing the call to xTaskGetTickCount() again?
By the way &#8211; you should not disable and enable interrupts directly, but use taskENTER<em>CRITICAL() and taskEXIT</em>CRITICAL() instead.
Regards.

If so, what happens?  Does the system crash, or does the higher priority 
task just continue running?
If the higher priority task continues running, does it ever enter the 
Blocked state?  If it does not enter the Blocked state then it will 
starve the lower priority tasks of processing time.
