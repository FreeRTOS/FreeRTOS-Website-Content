</div></div><div class="thread-post"><h3 class="thread-post-title">Problem with FromISR functions and TWI Interrupt using Atmel SAM3X</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on March 19, 2015</div><div class="thread-post-content">Here is the link to configASSERT() info:
http://www.freertos.org/a00110.html#configASSERT
You define it in FreeRTOSConfig.h &#8211; it can do what you want as long as 
you know it has been called.  The normal thing to do is disable 
interrupts and sit in a loop, as per your post, so when you break the 
debugger you can see it is sat on a configASSERT() statement.  There are 
more elaborate schemes you can implement &#8211; but the simpler the better I 
think.
Generally calling printf() in an interrupt is not recommended.
<blockquote>
  The crash happens at xSemaphoreGiveFromISR( testHandle, &amp;xTaskWoken ).
</blockquote>
I think the intention was for you to find out where inside the function 
the crash happens.  If you place a break point on the line, then step 
into the function in the debugger you should be able to see why the 
crash happens.
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">Problem with FromISR functions and TWI Interrupt using Atmel SAM3X</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/ajienikicio">ajienikicio</a> on March 23, 2015</div><div class="thread-post-content">Hi!
I had confirmed that there was no configASSERT() called and I just found out the problem :).
After looking at the FreeRTOS Demo Application again, I noticed that the Demo sets configTOTAL<em>HEAP</em>SIZE as 40960, while I had 8096. After setting it to 40960, the problem disappeared. But I don&#8217;t understand why the value was causing the problem.
</div></div><div class="thread-post"><h3 class="thread-post-title">Problem with FromISR functions and TWI Interrupt using Atmel SAM3X</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on March 23, 2015</div><div class="thread-post-content">If you run out of heap then queues, semaphores, event groups, tasks, 
etc. cannot be created &#8211; and the return value of the function used to 
create the object will return pdFAIL.  Are you checking the return 
values of such functions &#8211; or any direct call to pvPortMalloc().
You can also define a <a 
href="http://www.freertos.org/a00016.html">malloc failed hook</a> 
function to get notification that the heap was exhausted.
Regards.
