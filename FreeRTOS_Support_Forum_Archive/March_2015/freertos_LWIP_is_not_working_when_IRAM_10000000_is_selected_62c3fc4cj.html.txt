</div></div><div class="thread-post"><h3 class="thread-post-title">LWIP is not working when IRAM 10000000 is selected</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on March 19, 2015</div><div class="thread-post-content">I don&#8217;t think this is a FreeRTOS related question.  It is related to both lwIP and how to use the linker script and linker commands to use all the RAM on the device.
If you were using GCC then and the RAM on the chip was not in contiguous memory (which I don&#8217;t think it is) then you would most likely need to place the variables into the RAM manually as the linker will not be able to do it very intelligently for you.  If you are using IAR or Keil (I don&#8217;t think you say) then the linker may have a better attempt at it.
If all the RAM is in contiguous memory then the linker would be able to do it all for you in any case.
Have a look at the user manual to determine if the RAM is in contiguous memory or not, and if not, whether you have to explicitly enable separate blocks before you can use them.
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">LWIP is not working when IRAM 10000000 is selected</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/andymcc0">andymcc0</a> on March 20, 2015</div><div class="thread-post-content">The NXP LPC1788 Ethernet DMA engine requires the descriptors <strong>and</strong> the data buffers to be in the 32kB of Peripheral SRAM between 0x2000 0000 &#8211; 0x2000 7FFF.  I found it easiest to do this explicitly, rather than using the linker.
<pre><code>/* AWM - A comment in the original LPCOpen code example from which this was developed, stated:
 * "The Ethernet Block can only access Peripheral SRAM and External Memory. In this example,
 * Peripheral SRAM is selected for storing descriptors, status arrays and send/receive buffers." 
 * so I am going to use the statically allocated BufferAllocation_1 method.
 * See vNetworkInterfaceAllocateRAMToBuffers() below for more detail */
#define ENET_RX_STAT_BASE        (0x20000000UL)     /* Base of peripheral RAM */
#define ENET_RX_DESC_BASE   (ENET_RX_STAT_BASE + ENET_NUM_RX_DESC * sizeof(ENET_RXSTAT_T))
#define ENET_TX_STAT_BASE   (ENET_RX_DESC_BASE + ENET_NUM_RX_DESC * sizeof(ENET_RXDESC_T))
#define ENET_TX_DESC_BASE   (ENET_TX_STAT_BASE + ENET_NUM_TX_DESC * sizeof(ENET_TXSTAT_T))
#define ENET_BUFFER_BASE    (ENET_TX_DESC_BASE + ENET_NUM_TX_DESC * sizeof(ENET_TXDESC_T))
</code></pre>
The comment referred to is in <code>enet.c</code> in the periph_ethernet example.
Then you use these #defines when setting up the buffers and descriptors.  Note this was done for the FreeRTOS+TCP stack, not the lwip, but the principle should remain the same.
I don&#8217;t doubt that there are better ways to do this, but it worked for me.
Regards,
Andy McC
