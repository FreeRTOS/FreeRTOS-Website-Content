What do you think?

</div></div><div class="thread-post"><h3 class="thread-post-title">queue priority </h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on March 25, 2015</div><div class="thread-post-content">I&#8217;m afraid I don&#8217;t understand your requirements.  Are you talking about FreeRTOS queues?  So writing to the queue using xQueueSend()?  If so then any task can write to the queue, but only the highest priority task will be running, so the highest priority task will always write first.  Assuming you are writing to the back of the queue (xQueueSend() or xQueueSendToBack()) then the queue will act as a FIFO.  Data will come out in the same order it went in.  As far as ready from the queue &#8211; if more than one task is attempting to read from the queue it is always the highest priority task that will read first.
Does that answer the question?
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">queue priority </h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/ranco9">ranco9</a> on March 25, 2015</div><div class="thread-post-content">Hi
Thank you for your kind help
Yes i am talking about freeRTOS queue so using xQueueSend() but i would like to limit writing to it to only one task at a time at a first come first serve priority regardless of the task priority
To use an analogy, same as in a bank with one casheer, you can deposit only when its your turn and no cutting in line regardless your &#8220;priority&#8221; 🙂
Thanks again
Ran 
</div></div><div class="thread-post"><h3 class="thread-post-title">queue priority </h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on March 25, 2015</div><div class="thread-post-content">The queue handles all mutual exclusion issues for you &#8211; you do not need 
to worry about more than one task trying to access the queue at the same 
time.  As far as which task will actually write to the queue &#8211; that is 
handled by the priority of the task.  The scheduler will always run the 
highest priority task that is able to run &#8211; if that task is writing to a 
queue then the write will effectively be atomic &#8211; that is &#8211; it can&#8217;t be 
interrupted by another task writing to the same queue.
</div></div><div class="thread-post"><h3 class="thread-post-title">queue priority </h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/ranco9">ranco9</a> on March 26, 2015</div><div class="thread-post-content">Thanks again

Ran
