  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">error build ARM7_LPC2368_Eclipse</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/dsigit">dsigit</a> on October 7, 2009</div><div class="thread-post-content">Hi all,  
Recently, I try to build ARM7&#95;LPC2368&#95;Eclipse project using Eclipse+Yagarto and   
found this error message :  
error: no memory region specified for loadable section &#96;.eh&#95;frame&#8217;  
In Yagarto&#8217;s site, it&#8217;s said that I have to add following part to linker file   
lpc2368.ld :  
. = ALIGN&#40;4&#41;;<br />
.eh&#95;frame :<br />
&#123;<br />
&nbsp;&nbsp;&nbsp;&nbsp; KEEP &#40;&#42;&#40;.eh&#95;frame&#41;&#41;<br />
&#125; &amp;gt; ram  
but the problem is, I&#8217;m not really sure where exactly should I put it in my   
lpc2368.ld file. So, I take my chances by put it somewhere in SECTIONS &#123; &#125; part   
of the file and got this error messages :  
c:/program files/yagarto/bin/../lib/gcc/arm-elf/4.4.1/../../../../arm-  
elf/bin/ld.exe: RTOSDemo.elf section .eh&#95;frame will not fit in region ram<br />
c:/program files/yagarto/bin/../lib/gcc/arm-elf/4.4.1/../../../../arm-  
elf/bin/ld.exe: region ram overflowed by 7200 bytes<br />
collect2: ld returned 1 exit status<br />
make: &#42;&#42;&#42;&nbsp; Error 1  
Can anyone help me? Thank you.
</div></div><div class="thread-post"><h3 class="thread-post-title">error build ARM7_LPC2368_Eclipse</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on October 7, 2009</div><div class="thread-post-content">The problem is the new version of GCC that the latest version of Yagarto uses.&nbsp; Take the makefile and linker script out of the SVN repository &#40;FreeRTOS V6.0.0&#41; and you should find it compiles fine, although I have not tried actually running with the changes.  
Also be aware that the version of binutils used has problems with ARM/THUMB interworking.&nbsp; I would stick to ARM mode until it is fixed in GCC.  
Regards.
