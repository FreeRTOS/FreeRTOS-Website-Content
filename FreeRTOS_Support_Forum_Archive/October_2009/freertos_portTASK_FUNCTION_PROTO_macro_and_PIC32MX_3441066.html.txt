I have found that it works and included it in my demo branch &#40;for learning reasons only&#41;.

</div></div><div class="thread-post"><h3 class="thread-post-title">portTASK_FUNCTION_PROTO macro and PIC32MX</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on October 26, 2009</div><div class="thread-post-content">The macros can be used to add compiler key word extensions to task functions with the aim of reducing their stack usage &#40;basically because they never return&#41;.&nbsp; This is generally only useful on really small micros with very limited RAM.  
How have you implemented the macros?  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">portTASK_FUNCTION_PROTO macro and PIC32MX</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/*anonymous">*anonymous</a> on October 27, 2009</div><div class="thread-post-content">Hi Richard,  
I can send you the entire project &#40;although I doubt that&#8217;s what you want&#41;, here is a quick summary:  
First I modified the function prototypes for the two tasks, to validate the<br />
changes:  
//dmc static void prvTestTask1&#40; void &#42;pvParameters &#41;;<br />
static portTASK&#95;FUNCTION&#95;PROTO&#40;prvTestTask1, prvParameters&#41;;<br />
//dmc static void prvTestTask2&#40; void &#42;pvParameters &#41;;<br />
static portTASK&#95;FUNCTION&#95;PROTO&#40;prvTestTask2, prvParameters&#41;;  
And then the function definitions as:<br />
static portTASK&#95;FUNCTION&#40;prvTestTask1, pvParameters&#41;<br />
//static void prvTestTask1&#40; void &#42;pvParameters &#41;<br />
&#123;<br />
…<br />
&#125;  
and<br />
static portTASK&#95;FUNCTION&#40;prvTestTask2, pvParameters&#41;<br />
//static void prvTestTask2&#40; void &#42;pvParameters &#41;<br />
&#123;<br />
…<br />
&#125;  
To be comlete, I have not tested the parameters, but don&#8217;t see any issues…do you?  
I am using the demo on the PIC32MX/PIC32MX USB starter kits. I haven&#8217;t ported the USB driver &#40;in the spirit of the Microchip Application note you mention on your web site&#41; and probably won&#8217;t. My goal for now is to impliment a variation of the&nbsp; MRF24J40 Radio Utility Driver Program and develop a wireless application for the PIC32 under FreRTOS.  
Dave
</div></div><div class="thread-post"><h3 class="thread-post-title">portTASK_FUNCTION_PROTO macro and PIC32MX</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/*anonymous">*anonymous</a> on October 27, 2009</div><div class="thread-post-content">And I should probably mention that the macro definitions &#40;included with the port in the MPLAB PIC32MX portmacro.h file &#40;per the distribution&#41; are:<br />
/&#42; Task function macros as described on the FreeRTOS.org WEB site. &#42;/<br />
&#35;define portTASK&#95;FUNCTION&#95;PROTO&#40; vFunction, pvParameters &#41; void vFunction&#40; void &#42;pvParameters &#41; &#95;&#95;attribute&#95;&#95;&#40;&#40;noreturn&#41;&#35;define portTASK&#95;FUNCTION&#40; vFunction, pvParameters &#41; void vFunction&#40; void &#42;pvParameters &#41;  
i.e., no changes from the demo as unziped from FreeRTOS 6.0.0.
