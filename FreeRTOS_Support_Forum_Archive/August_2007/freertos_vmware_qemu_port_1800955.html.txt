</div></div><div class="thread-post"><h3 class="thread-post-title">vmware qemu port</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/sashiono">sashiono</a> on August 14, 2007</div><div class="thread-post-content">Originally I was thinking that it could be based off of one of the dos ports. but I think better would be to use QEMU. Perhaps the qemu-system-arm flag would be the best option. as it has a dual uart, Ethernet and a ARM926E core. 
The Main hurdle is getting FreeRTOS to compile into the proper form that QENU can recognize, boot, and execute.&nbsp; Or really any application for that matter. If I could find a &quot;hello world&quot; type makefile that builds a QEMU bootable image. that would be a great starting point.&nbsp; 
Once we can do that, then debugging via gdb would be simple and we really have unlimited ram to try out things with freertos. 
I don&#8217;t have much experience with QEMU, but it seems that it would be possible. 
It would also be a good way for people to try out FreeRTOS without hardware. Or before their hardware is ready. 
</div></div><div class="thread-post"><h3 class="thread-post-title">vmware qemu port</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/sashiono">sashiono</a> on August 14, 2007</div><div class="thread-post-content">just found this as well, working on getting it setup. http://wiki.openmoko.org/wiki/OpenMoko&#95;under&#95;QEMU
essentially an emulated S3C2410A and some peripherals. 
could make a decent Simulated FreeRTOS environment. 
</div></div><div class="thread-post"><h3 class="thread-post-title">vmware qemu port</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/sashiono">sashiono</a> on August 18, 2007</div><div class="thread-post-content">I finally got FreeRTOS running on a simulated arm7. 
I&#8217;m using Skyeye simulating the lpc2210 hardware. 
I&#8217;m using timer0 and uart0 simulated hardware
right now I have direct serial print functions working, When I try interrupt driven I can&#8217;t only get one character to print out. So I&#8217;m guessing that the interrupt driven uart is not properly simulated.&nbsp;&nbsp; 
so far I have been able to get tasks and coroutines&#40;in the idle hook&#41; 
right now I have three tasks and two coroutines all being scheduled properly. 
Both preemptive and not preemptive modes seem to work as well. &#40;to test out preemptive I have one task not blocking and other tasks still get swapped in to run&#41;
A couple of stuff I haven&#8217;t figured out yet is that the timers are not quite operating at the correct speed, so right now even though the tick should be every 1ms. its more like every 2 seconds. &#40;and I know that skyeye is not that slow&#41; I&#8217;m guessing that it is not properly simulating the pll. and I have no idea what the default clock is running at. 
I&#8217;ll post up an example when I get more stuff figured out. 
but everything is looking good so far.
