  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Undefined Handler &#8211; STR711</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/velososcooby">velososcooby</a> on August 26, 2007</div><div class="thread-post-content">Hello,
I&#8217;m getting an undefined handler on vPortStartFirstTask&#40;&#41;. It happens when &quot;SUBS PC, LR, &#35;4&quot; executes&#8230; I&#8217;ve checked and MCU is in supervisor mode. I&#8217;m using STR711FR0.
Can anyone help me?
Tks,
velososcooby
</div></div><div class="thread-post"><h3 class="thread-post-title">Undefined Handler &#8211; STR711</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on August 27, 2007</div><div class="thread-post-content">Can you be more specific?&nbsp; You are going into a default interrupt handler, or you are going into the undefined processor mode?
In the former case you will have to determine the source of the interrupt.&nbsp; Which interrupts do you configure prior to starting the first task.
I have no experience of the latter case other than to know the undefined processor mode is something to do with interfacing coprocessors so if you go into this state something very bad has happened.
</div></div><div class="thread-post"><h3 class="thread-post-title">Undefined Handler &#8211; STR711</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/velososcooby">velososcooby</a> on August 27, 2007</div><div class="thread-post-content">I&#8217;m going into the undefined processor mode. 
I&#8217;m using FreeRTOS example and I didn&#8217;t configure other interrupt source than wdg, configured by freertos.
The tasks are created correctly but when restoring context of first task the MCU going into undefined mode. 
SUBS PC, LR, &#35;4 must jump for the first task and copy SPSR to CPSR, ok? 
If I substitute that by SUB PC, LR, &#35;4 it jumps for the task but stay in supervisor mode, don&#8217;t enable interrupts and executes the first task forever.
Should I try recover task CPSR without enable interrupts? It doesn&#8217;t resolve the problem but can show us if the it is wdg interrupt.
Tks
</div></div><div class="thread-post"><h3 class="thread-post-title">Undefined Handler &#8211; STR711</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/velososcooby">velososcooby</a> on September 1, 2007</div><div class="thread-post-content">The CPSR created for my task was setting THUMB bit and causing the undefined processor mode.
So, I change it by setting thumb bit to 0.
Tks
</div></div><div class="thread-post"><h3 class="thread-post-title">Undefined Handler &#8211; STR711</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/sotd">sotd</a> on September 1, 2007</div><div class="thread-post-content">That something was probably having &quot;-D THUMB&#95;INTERWORK&quot; defined in your makefile.
