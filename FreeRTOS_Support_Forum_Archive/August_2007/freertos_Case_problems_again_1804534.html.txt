</div></div><div class="thread-post"><h3 class="thread-post-title">Case problems, again</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/jaymaynard">jaymaynard</a> on August 20, 2007</div><div class="thread-post-content">They build in the DOS box, but I can&#8217;t use their suggestion of a shortcut definition in the .gdbinit file to replace the long &#40;and, in the FreeRTOS doc, incorrect&#41; command to connect to the controller that way.
The CodeSourcery tools include a Unix command environment that isn&#8217;t Cygwin, and that environment is used under the covers even if you&#8217;re in a DOS box. You can also invoke that shell &#40;and that&#8217;s what they tell you to use&#41; by running the command C:binsh .
Here&#8217;s a test you can run: In a DOS box, run make to build the package. Run make &#42;again&#42;, as though you were rebuilding after changing one file &#40;you don&#8217;t need to actually change any files for this test&#41;. The second make will complain about missing dependencies. That&#8217;s because the case differences will be picked up by make from the automatically-generated gcc/&#42;.d files. Changing the case in the source, then doing make clean, then make, then make again will show the problem is fixed &#40;and reveal the next one to fix&#41;. I spent an hour or so last night doing that.
