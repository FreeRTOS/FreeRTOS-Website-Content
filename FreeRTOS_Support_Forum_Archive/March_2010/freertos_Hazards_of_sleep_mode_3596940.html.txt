  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Hazards of sleep mode</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/*anonymous">*anonymous</a> on March 12, 2010</div><div class="thread-post-content">Hi,<br />
I wrote an an idle hook shown here  
<pre><code>void vApplicationIdleHook( void )
{
    asm("nop");
    P1OUT &amp;= ~0x01;//go to sleep lights off!
    LPM3;// LPM Mode -  remove to make debug a little easier...
    asm("nop");
}
</code></pre>
That should cause the LED to turn off, and MSP430 to go to sleep when there is nothing to do. I turn the LED on during some tasks.  
I also made sure to modify the sleep mode bit in the SR upon exit of any interrupt that could possibly wake the MCU &#40;with the exception of the scheduler tick isr in port. The macro in iar is   
<pre><code>__bic_SR_register_on_exit(LPM3_bits);   // Exit Interrupt as active CPU 
</code></pre>
However, it seems as though putting the MCU to sleep causes some irregular behavior. The led stays on always, although when i scope it, it will turn off for a couple instructions cycles when ever i wake the mcu via one of the interrupts &#40;UART&#41;.<br />
If I comment out the LPM3 instruction, things go as planned. THe led stays off for most of the time and only comes on when a task is running.  
I am using a MSP4f305438  
Any ideas?
