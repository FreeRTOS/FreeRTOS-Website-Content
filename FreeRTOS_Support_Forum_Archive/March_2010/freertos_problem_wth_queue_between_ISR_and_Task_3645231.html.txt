  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">problem wth queue between ISR and Task</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/ale82t">ale82t</a> on March 27, 2010</div><div class="thread-post-content">Hi to all,<br />
i have a big problem: i&#8217;m using a queue system to synchronize a task with 2 ISR &#40;one from ethernet and one from timer&#41;.ISR unblock task with a binary semaphore. Inside ISR i&#8217;m using a queue to create events to insert into it&#40;with xQueueSendFromISR function&#41; and in the task i have a loop blocked with a xSemaphoreTake.Idon&#8217;t understand why i have a bus fault when i execute the instruction xSemaphoreTake. Thanks in advice for your answer,  
Alessio   
</div></div><div class="thread-post"><h3 class="thread-post-title">problem wth queue between ISR and Task</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on March 27, 2010</div><div class="thread-post-content">Which architecture are you using? Are you basing your project on a provided demo? Have you created the semaphore and the queue before you use them &#40;especially if the interrupt is executing before the scheduler is started&#41;? Is anything working?
</div></div><div class="thread-post"><h3 class="thread-post-title">problem wth queue between ISR and Task</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on March 27, 2010</div><div class="thread-post-content">If it was created as a semaphore, then the ISR should use xSemaphoreGiveFromISR not xQueueSendFromISR, while Semaphores are built on Queue code, I don&#8217;t think they are interchangeable &#40;for instance, Semaphores set up the queue for a zero byte object, and the QueueSend may not be set up to handle something like that.
</div></div><div class="thread-post"><h3 class="thread-post-title">problem wth queue between ISR and Task</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/ale82t">ale82t</a> on March 27, 2010</div><div class="thread-post-content">i&#8217;m using a STM32 architecture with Cortex M3 processor. I creathed both semaphore and queue before enable interrupts.I&#8217;m using a queue to simulate a producer-consumer model.Everytime i have an interrupt i insert an element in the queue,after i unblock task that consume elements in the queue. About ISR first i must insert an element on the queue &#40;and i do it with xQueueSendFromISR&#41; and after i do xSemaphoreGiveFromISR and finally before leave ISR i do portEND&#95;SWITCHING&#95;ISR.
</div></div><div class="thread-post"><h3 class="thread-post-title">problem wth queue between ISR and Task</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on March 27, 2010</div><div class="thread-post-content">Are you totally 100% sure that the priority of the interrupt is equal to or low than configMAX&#95;SYSCALL&#95;INTERRUPT&#95;PRIORITY? On the STM32 for the priority to be lower the value of the priority must be higher &#40;0 is the highest priority and 255 is the lowest priority, so if you don&#8217;t set the priority it will be 0 by default and therefore the highest possible and this will cause an issue&#41;. Also, how the priority is specified depends on the function used to set it. Some need the priority to be shifted to the top bits when others don&#8217;t. This is nearly always the problem with interrupts on Cortex M3 parts.
