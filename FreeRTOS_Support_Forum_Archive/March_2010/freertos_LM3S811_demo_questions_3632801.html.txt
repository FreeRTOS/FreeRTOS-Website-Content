I&#8217;m learning to use the FreeRTOS and I&#8217;m modifying the LM3S811 demo.<br />

Also this new task works ok, but… the vCheckTask fails, returning xErrorOccurred = pdTRUE.<br />
This strange behaviour appears when I add the dummy task to the existing ones and also when I leave it alone removing from the code the led flasher task.<br />
In other words, the problem seems to be related to the dummy task itself.  
I use the heap&#95;1.c and I set the following defines to:  
&#35;define configMINIMAL&#95;STACK&#95;SIZE &#40; &#40; unsigned short &#41; 70 &#41;<br />

static void vDummyTask&#40; void &#42;pvParameters &#41;;<br />
xTaskCreate&#40; vDummyTask, &#8220;Dummy&#8221;, configMINIMAL&#95;STACK&#95;SIZE, NULL, mainCHECK&#95;TASK&#95;PRIORITY &#8211; 1, NULL &#41;;<br />
static void vDummyTask&#40; void &#42;pvParameters &#41;<br />
&#123;<br />
unsigned portLONG ulSpy = 0;<br />
&nbsp; for&#40; ;; &#41;<br />
&nbsp; &#123;<br />
&nbsp;&nbsp;&nbsp; ulSpy++;<br />
&nbsp; &#125;<br />

</div></div><div class="thread-post"><h3 class="thread-post-title">LM3S811 demo questions</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/edwards3">edwards3</a> on March 23, 2010</div><div class="thread-post-content">Your task never enters the Blocked state so will starve tasks that use lower priorities. The check task looks at every task to ensure it is still running and will indicate an error if any are being starved of processing time.  
Try adding vTaskDelay&#40;10&#41; to the loop, or creating the task at the idle priority. Either will then allow lower priority tasks to continue executing.
</div></div><div class="thread-post"><h3 class="thread-post-title">LM3S811 demo questions</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/apessina">apessina</a> on March 24, 2010</div><div class="thread-post-content">Great&#33;&#33;&#33;<br />
You&#8217;re completely right.<br />
The little vTaskDelay &#40;10&#41; added to the loop is enough to fix the problem.<br />
I&#8217;m checking in this exact moment to what happens in the vCheckTask, setting some breakpoints to get the fail reason.<br />
I can see that the error flag is set because the following condition is met:<br />
if&#40; xAreIntegerMathsTaskStillRunning&#40;&#41; &#33;= pdTRUE &#41;<br />
