  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Tick time incorrect in CodeWarrior DEMO</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/shirleychen">shirleychen</a> on March 11, 2010</div><div class="thread-post-content">I found the tick time is incorrect in both CodeWarrior DEMO project.<br />
Compare value need to be added to TC0 before enable TFLG1 in file port.c,<br />
in function void interrupt vPortTickInterrupt&#40; void &#41;.<br />
The value that is added on TC0 is based on the system bus frequency.<br />
In my case is 2500 @ 20MHz bus clock.<br />
Anybody has the same experience?  
</div></div><div class="thread-post"><h3 class="thread-post-title">Tick time incorrect in CodeWarrior DEMO</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on March 12, 2010</div><div class="thread-post-content">I just looked at the code but don&#8217;t understand your comments because I cannot see anything being added to TC0. Can you explain further?
</div></div><div class="thread-post"><h3 class="thread-post-title">Tick time incorrect in CodeWarrior DEMO</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/shirleychen">shirleychen</a> on March 12, 2010</div><div class="thread-post-content">From the code generated by the Processor Expert TickTimer.c, interrupt service routine as below  
ISR&#40;TickTimer&#95;Interrupt&#41;<br />
&#123;<br />
&nbsp; TC0 += CmpVal;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; /&#42; Add value corresponding with periode &#42;/<br />
&nbsp; TFLG1 = 1;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; /&#42; Reset interrupt request flag &#42;/<br />
&nbsp; TickTimer&#95;OnInterrupt&#40;&#41;;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; /&#42; Invoke user event &#42;/<br />
&#125;  
CmpVal&#40;in this case = 2500&#41; is added on to TC0 to generate the 1kHz interrupt.<br />
When the vector for TC0 is redirected to vPortTickInterrupt&#40; void &#41; in port.c file as below,<br />
void interrupt vPortTickInterrupt&#40; void &#41;<br />
&#123;<br />
&#35;if configUSE&#95;PREEMPTION == 1<br />
&#123;<br />
/&#42; A context switch might happen so save the context. &#42;/<br />
portSAVE&#95;CONTEXT&#40;&#41;;  
/&#42; Increment the tick … &#42;/<br />
vTaskIncrementTick&#40;&#41;;  
/&#42; … then see if the new tick value has necessitated a<br />
context switch. &#42;/<br />
vTaskSwitchContext&#40;&#41;;<br />
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; TC0 += 2500;&nbsp;&nbsp; //&nbsp; I added the code here<br />
TFLG1 = 1; &nbsp;&nbsp;   
/&#42; Restore the context of a task &#8211; which may be a different task<br />
to that interrupted. &#42;/<br />
portRESTORE&#95;CONTEXT&#40;&#41;;<br />
&#125;<br />
&#35;else<br />
&#123;<br />
vTaskIncrementTick&#40;&#41;;<br />
TC0 += 2500;&nbsp; // I added code here<br />
TFLG1 = 1;<br />
&#125;<br />
&nbsp;&nbsp;&nbsp;&nbsp; &#125;<br />
&#35;endif<br />
Without the the code I added, the TC0 interrupt will be enabled with TC0 = 0, that is the next ISR will come in when the TC0 counts 0xFFFF cycle, which exceed 1ms period, that was why the tick time appeared longer than it suppose to be.
