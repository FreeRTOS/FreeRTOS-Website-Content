  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">AVR323_WinAVR demo compilation with AVR Studi</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/grosiles">grosiles</a> on March 28, 2010</div><div class="thread-post-content">I used to be able to compile the FreeRTOS demo for the Atmega32 &#40;using the Atmega323 demo&#41;&nbsp; with AVR Studio. I downloaded the newer version of FreeRTOS and get the following errors:<br />
C:WinAVRFreeRTOSDemoAVR&#95;ATMega323&#95;WinAVRrtosdemodefault/../../main.c:269: undefined reference to &#96;eeprom&#95;read&#95;block&#8217;  
C:WinAVRFreeRTOSDemoAVR&#95;ATMega323&#95;WinAVRrtosdemodefault/../../main.c:271: undefined reference to &#96;eeprom&#95;write&#95;byte&#8217;  
I know this looks more like an AVR studio or WinAVR question, but since it is related to the FreeRTOS demos I would like to see if someone has encountered this problem. It would seem that the compiler does not know were to locate the eeprom library, but&nbsp; if I make the program directly on a command window I don&#8217;t get this problem.   
Thanks.  
</div></div><div class="thread-post"><h3 class="thread-post-title">AVR323_WinAVR demo compilation with AVR Studi</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/grosiles">grosiles</a> on March 28, 2010</div><div class="thread-post-content">Ok, I found the culcript, which I do not know who to blame :&#41;. The main.c code for the demo has the following lines:  
&#35;ifdef GCC&#95;MEGA&#95;AVR<br />
/&#42; EEPROM routines used only with the WinAVR compiler. &#42;/<br />
&#35;include &lt;avr/eeprom.h&gt;<br />
&#35;endif  
It seems that GCC&#95;MEGA&#95;AVR is not defined. I assume FreeRTOS is expected this to be defined somewhere in the compiler, but it is not being detected at compilation time. As I said, if I &#8220;make&#8221; directly on a command line there is no problem. Hence, somehow AVR Studio is not providing this definition at compile time. I do not think I need to add the file into the project since this is suppose to be part of the compiler standard definitions &#40;?&#41;.  
In any case, this did not happen with the older versions on the WinAVR and AVRStudio tools.   
Regards.  
</div></div><div class="thread-post"><h3 class="thread-post-title">AVR323_WinAVR demo compilation with AVR Studi</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/grosiles">grosiles</a> on March 28, 2010</div><div class="thread-post-content">Forgot to mention, commenting out the pre-processor lines fixes the problem.
</div></div><div class="thread-post"><h3 class="thread-post-title">AVR323_WinAVR demo compilation with AVR Studi</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/grosiles">grosiles</a> on March 28, 2010</div><div class="thread-post-content">I meant to say:<br />
// &#35;ifdef GCC&#95;MEGA&#95;AVR<br />
/&#42; EEPROM routines used only with the WinAVR compiler. &#42;/<br />
&#35;include &lt;avr/eeprom.h&gt;<br />
// &#35;endif  
Sorry for so much blurb.
</div></div><div class="thread-post"><h3 class="thread-post-title">AVR323_WinAVR demo compilation with AVR Studi</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on March 28, 2010</div><div class="thread-post-content">Its been a while since I updated my WinAVR, but have just tried the very latest WinAVR against the very latest FreeRTOS and found it compiled without any problems &#40;I got the &#8220;../../Source/tasks.c:420: warning: cast from pointer to integer of different size&#8221; warning which has been discussed here before&#41;, although I have not tried actually running the code.  
The GCC&#95;MEGA&#95;AVR definition should be set on the GCC command line, using the -D option.&nbsp; Take a look at the makefile that comes in the FreeRTOS WinAVR example project.  
Regards
