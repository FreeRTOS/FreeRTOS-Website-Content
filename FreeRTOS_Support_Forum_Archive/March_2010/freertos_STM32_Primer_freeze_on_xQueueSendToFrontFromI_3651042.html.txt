</div></div><div class="thread-post"><h3 class="thread-post-title">STM32 Primer freeze on xQueueSendToFrontFromI</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on March 31, 2010</div><div class="thread-post-content">The normal reason for crashes in Cortex M3 interrupts is an invalid interrupt priority. The priority must be equal to or below configMAX&#95;SYSCALL&#95;INTERRUPT&#95;PRIORITY, which on the Cortex M3 means the priority value must be lower than configMAX&#95;SYSCALL&#95;INTERRUPT&#95;PRIORITY &#40;a priority of 255 being lower than a priority of 0&#41;. You must set the interrupt priority otherwise it will default to zero and most probably crash. Also, make sure you set it correctly as different functions use different methods, some need the priority shifted up to the most significant bits and other don&#8217;t.  
If it is memcpy that is crashing, can you stop on the debugger and see the addresses it is copying to and from?

</div></div><div class="thread-post"><h3 class="thread-post-title">STM32 Primer freeze on xQueueSendToFrontFromI</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on March 31, 2010</div><div class="thread-post-content">As suggested, I think this is where your bug lies. The interrupt priority is below 0, because it is numerically higher.  
What is configMAX&#95;SYSCALL&#95;INTERRUPT&#95;PRIORITY set to in FreeRTOSConfig.h.&nbsp; By default it will be 11, so your interrupt priorities need to be 11, 12, 13, or 14. Anything else will cause intermittent problems.
