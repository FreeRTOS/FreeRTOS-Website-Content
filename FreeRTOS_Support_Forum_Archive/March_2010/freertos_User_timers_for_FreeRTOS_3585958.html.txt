  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">User timers for FreeRTOS?</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/juku_59">juku_59</a> on March 9, 2010</div><div class="thread-post-content">Hi,  
In my application I need some timers. I will write those myself if I need to, but perhaps there is some code available already? I&#8217;m thinking of a system &#40;in a relatively high priority task, perhaps?&#41; that I can say something like &#8220;notify me every 500ms&#8221; or &#8220;do this after 12s&#8221;. In more technical terms, start/stop a periodic/single&#95;shot timer with somehow defining what to do at time out. Any pointers?  
Thank you,  
Juha
</div></div><div class="thread-post"><h3 class="thread-post-title">User timers for FreeRTOS?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on March 9, 2010</div><div class="thread-post-content">Look at the vTaskDelay and vTaskDelayUntil functions. As long as the period is a multiple of your tick rate, getting a task to wait up periodically isn&#8217;t a problem.
</div></div><div class="thread-post"><h3 class="thread-post-title">User timers for FreeRTOS?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/juku_59">juku_59</a> on March 9, 2010</div><div class="thread-post-content">Yes, and the tick count is also available. However, I need to do things like starting a process that should be ready in two seconds. When doing that, I want the starting task to continue; I&#8217;ll just set up a timer to send back a message after two seconds. If I get a message from the new process, I stop the timer and handle the new results. If I get a message from the timer, I&#8217;ll do error handling.   
I know FreeRTOS does not &#40;yet :-&#41; &#41; have this kind of services, but these can be readily created on top of it. As noted, I can write the timer code &#40;timer task?&#41; myself if I need to, but if there is something like this already, I rather not re-invent a wheel. 
</div></div><div class="thread-post"><h3 class="thread-post-title">User timers for FreeRTOS?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on March 9, 2010</div><div class="thread-post-content">I do have a &#40;very&#41; old timer module that allows timers to be generated dynamically, each of which with a callback function.&nbsp; However I have never included it in the main download, primarily because this sort of timer is very difficult to implement efficiently.&nbsp; Timer implementations normally do horrible things like walk linked lists inside critical sections, or even inside tick interrupts.&nbsp; That is something I have always tried to avoid in FreeRTOS because of the obvious adverse effect it has on&nbsp; system responsiveness.  
I would suggest also taking a look at using a tick hook function.&nbsp; Most timer functionality &#40;in the smaller systems that FreeRTOS targets at least&#41; can be implemented using a tick hook.  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">User timers for FreeRTOS?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on March 9, 2010</div><div class="thread-post-content">Sounds like one way to implement this is when task1 starts task2, it also starts up a watchdog task3 that does a wait for a signal from task2 with a timeout. When task2 is done, it sets the signal waking up the watchdog &#40;which could process the data if you wanted&#41;, but if task3 wakes up on timeout &#40;signal by a failure to get the signal&#41;, then it flags the error.
