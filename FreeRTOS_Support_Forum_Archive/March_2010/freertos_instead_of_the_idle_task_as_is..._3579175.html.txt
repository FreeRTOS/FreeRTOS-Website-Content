  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">instead of the idle task as is&#8230;</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/*anonymous">*anonymous</a> on March 4, 2010</div><div class="thread-post-content">I would like to have a set number of things happen when the idle task is called. I put my board to sleep when there is nothing to do &#40;loops in idle mode right now&#41;. The problem with just sticking all the power down steps in the idle task is that this task is jumped into and out of from any point within.&nbsp; I need to have a set number of steps occur before putting the micro into lpm3 &#40;MSP430&#41;.   
Whats a good way fo going about this?  
Oh ya, I am not just calling lpm3, but talking to external hardware to shut it down &#40;and other stuff&#41;. So there is an important order to the shutdown task.  
Thanks&#33;
</div></div><div class="thread-post"><h3 class="thread-post-title">instead of the idle task as is&#8230;</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on March 5, 2010</div><div class="thread-post-content">For something like this, I would use an idle hook function, and in that function enter a critical section, and inside that section quickly check that it really is time to go to sleep &#40;and not just that all the other tasks are just temporarily busy&#41;, if not time, quickly end the critical section, but if it is time, perform the shutdown. Depending on the condition that will be used to wake you up, you probably need to end the critical section just before actually going to sleep.
</div></div><div class="thread-post"><h3 class="thread-post-title">instead of the idle task as is&#8230;</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/*anonymous">*anonymous</a> on March 5, 2010</div><div class="thread-post-content">Hmmm, but what about when I come out of idle. I would need to do the powerup stuff.  
Essentially I need to somehow have a single exit and single entry point for idle power down/power up.  
When entering idle i want to power down and go into lpm3. Then if I wake up, enter a powerup phase and then exit idle.  
what about something like<br />
&#40;psuedo code&#41;  
<pre><code>idle func
enter critical---
power down code
exit critical----
lpm3
enter critical---
power up code
exit critical-----
end func
</code></pre>
or is there a&nbsp; better strategy?  
</div></div><div class="thread-post"><h3 class="thread-post-title">instead of the idle task as is&#8230;</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on March 5, 2010</div><div class="thread-post-content">close, I don&#8217;t know that processor, and the definition of &#8220;sleep&#8221; varies by processor and application.  
pseudo code:  
idle hook function &#40;will be called periodically by the idle task&#41; &#123;<br />
&nbsp; Enter Critical Section<br />
&nbsp; if&#40;ok to go to sleep&#41; &#123;<br />
&nbsp;&nbsp;&nbsp; prepare system to go to sleep<br />
&nbsp;&nbsp;&nbsp; enter sleep state<br />
&nbsp;&nbsp;&nbsp; wake system up from sleep state<br />
&nbsp;&nbsp;&nbsp; end critical section<br />
&nbsp; &#125; else &#123;<br />
&nbsp;&nbsp;&nbsp; end critical section<br />
&nbsp;&nbsp;&nbsp; maybe go to idle state if one is available<br />
&nbsp; &#125;<br />
&#125;  
Note that if you need an interrupt to wake you up from the sleep state, and the critical section disables that interrupt, the prepare to go to sleep may need to end with a exit critical section or at least re enabling that interrupt.  
I am assuming that the sleep being talked about here is a significant shutdown state that may take some time to recover from &#40;restarting clocks and the like&#41; and may disable some peripherals, so should only be entered when conditions are right for it. I have added an &#8220;Idle&#8221; routine, if the processor supports it, that saves a bit of power by stopping the processor until an interrupt occurs &#40;if we are in the idle task, nothing else is going to be able to execute until an interrupt occurs anyway, might as well let the processor take a break&#41;. If you have other tasks at the idle priority that can use the time productively, then you can skip the idle state.
</div></div><div class="thread-post"><h3 class="thread-post-title">instead of the idle task as is&#8230;</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/*anonymous">*anonymous</a> on March 5, 2010</div><div class="thread-post-content">Thanks,  
There is a lot to think about. Mostly because i need to keep a certain interrupt enabled when going to sleep, but when waking on that interrupt, service my powerup routine before i service that said interrupt.  
I am using a MSP430f5438 btw.  
I will post my solution when i have one.
</div></div><div class="thread-post"><h3 class="thread-post-title">instead of the idle task as is&#8230;</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on March 6, 2010</div><div class="thread-post-content">As I said, the prepare system to go to sleep will probably end with enabling some needed interrupts. If the interrupt processing function itself needs to fully wake up the processor, then you may need to have a flag that the enter sleep routine sets, so that the interrupt know that IT needs to do the wake up &#40;and it can clear the flag so the code in the idle hook know enough to not do the wake up it self too.&#41;  
It may be possible to make the interrupt to just a bit of minimal processing that could be done in the native &#8220;just woke up state&#8221; and do something to wake up a task to do most of the work,  
Thinking about this, part of the &#8220;preparing to go to sleep&#8221; routine will need to be disabling the scheduler, and re-enabling it AFTER you do all the wake up code, otherwise some other task might get started before you wake up everything.
