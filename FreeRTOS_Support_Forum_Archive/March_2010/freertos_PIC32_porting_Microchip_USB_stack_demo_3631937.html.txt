</div></div><div class="thread-post"><h3 class="thread-post-title">PIC32 porting, Microchip USB stack, demo?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/petermeier">petermeier</a> on March 26, 2010</div><div class="thread-post-content">Hi Piero,<br />
the USB Stack only uses one interrupt &#40;if you use host mode only &#8211; like for USB sticks&#41;. You need to wrap this ISR in the style FreeRTOS needs it &#40;there is a good example in the FreeRTOS package included&#41;. Next step is that you call once USBInitialize&#40;0&#41; when FreeRTOS is already running.&nbsp; After that you just need to call USBTasks&#40;&#41; periodicly every 1..10ms &#40;as you like&#41;. If you use a filesystem like FatFS from Chan there is a ready semaphore handling included &#8211; so you don&#8217;t need to worry about access rules from different tasks because FatFS will handle that.<br />
If you use the MSD&#95;SCSI functions for reading/writing&nbsp; a sector, think about this:<br />
These functions normally block the statemachine processing &#40;as the USB stack from Microchip is being designed&#41;. But these functions need a handling of the USBTasks&#40;&#41; &#8211; so Microchip decided, to make the handling quite easy &#8211; to include the calling of USBTasks&#40;&#41; in the blocking functions. And here you need to remove the call to USBTasks&#40;&#41; because in your main-task USBTasks&#40;&#41; will be already the called periodicly.  
Hope that helps a little.<br />
Regards,<br />
Peter
