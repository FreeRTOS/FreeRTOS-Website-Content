</div></div><div class="thread-post"><h3 class="thread-post-title">Task hangs on xQueueReceive</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on November 14, 2017</div><div class="thread-post-content"><blockquote>
  while( xQueueReceive(TaskAudioInputQueueHandle, &amp;msg, portMAX_DELAY) != pdTRUE ) ;
</blockquote>
The above is a bit illogical: when you call <code>xQueueReceive()</code> with <code>portMAX_DELAY</code> as a time-out, the function will block for ever, or until an item has been received.
and so it will always return <code>pdTRUE</code>.
<blockquote>
  while( xQueueReceive(TaskAudioInputQueueHandle, &amp;msg, 0) != pdTRUE ) vTaskDelay(10);
</blockquote>
The above loop makes more sense:  a time-out of 0 ( ticks ) means: polling. The call to <code>xQueueReceive()</code> will poll if there is a packet, and return immediately, either success, or fail  As long as there is no packet, every loop will sleep <strong>unconditionally</strong> for 10 clock-ticks.
Please also realise that when it calls <code>vTaskDelay(10)</code>, other ( lower-priority ) tasks get a chance to become active.  It will also be possible for other tasks to read from <code>TaskAudioInputQueueHandle</code>.
<blockquote>
  But it doesn&#8217;t help if I change it to:
</blockquote>
~~~
<blockquote>
  <h1>define configASSERT( x ) {}</h1>
  ~~~
</blockquote>
The introduction of <code>configASSERT()</code> will not directly prevent problems, at most it may reveal some bad behaviour.

    }
    else
    {

        xResult = xQueueSendToBackFromISR(CmdTxRxQueueHandle, &amp;msg, &amp;xHigherPriorityTaskWoken);
        portYIELD<em>FROM</em>ISR(xHigherPriorityTaskWoken);
    }
    return xResult;
}
~~~
