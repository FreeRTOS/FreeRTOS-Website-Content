  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">possible overflow check in xTaskCheckForTimeOut</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/chuan-jiang">chuan-jiang</a> on November 20, 2017</div><div class="thread-post-content">Hi,
I&#8217;ve noticed a possible overflow issue in xTaskCheckForTimeOut function. Could you please help to confirm it?
In the latest <em>RTOSv9.0.1, task.c, line3154</em>,
<strong>const TickType_t xElapsedTime = xConstTickCount &#8211; pxTimeOut->xTimeOnEntering;</strong>
Noticed that TickType_t might be defined as unsigned type, if xConstTickCount is less than pxTimeOut->xTimeOnEntering, the substraction will lead to an overflow.
and then in <em>line3187</em>, 
<strong>else if( xElapsedTime &lt; *pxTicksToWait )</strong>
I think this check condition should also take xNumOfOverflows into account.
(1) if xNumOfOverflows equals pxTimeOut->xOverflowCount+1, timeout might not be reached.
(2) but if xNumOfOverflows is larger than pxTimeOut->xOverflowCount+1, it might be the wrapped around, and the timeout has been passed away when this function is invoked. Then the return value should not be FALSE!
Also, xNumOfOverflows might also be wrapped around when come to xTaskCheckForTimeOut again.
Looking forwarding to your help and reply.
Thanks a lot

</div></div><div class="thread-post"><h3 class="thread-post-title">possible overflow check in xTaskCheckForTimeOut</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on November 21, 2017</div><div class="thread-post-content">A task can either block forever, in which case the code in your email 
doesn&#8217;t apply because it actually ends up on the suspended task list 
(even though it is in the blocked state), or it can block for a finite 
time, in which case the longest time it can block is the maximum block 
time that can be specified given the TickType_t data type.  That means, 
it can never block for more than one overflow because that is longer 
than the longest time it can possible ask for &#8211; so I don&#8217;t think it is 
actually possible for the scenario you describe to actually occur.
