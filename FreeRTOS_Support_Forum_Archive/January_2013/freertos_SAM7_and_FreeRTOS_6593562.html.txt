</div></div><div class="thread-post"><h3 class="thread-post-title">SAM7 and FreeRTOS</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on January 12, 2013</div><div class="thread-post-content">Operating at those speeds you really have to be doing the PWM and the ADC in the interrupt itself.  
With regards to the serial receive functions &#8211; the SAM7 USART has a Peripheral DMA Controllers that can handle the receiving for you with very little overhead on the CPU. I suggest in a high CPU load application like your you look to use that.&nbsp; You can find an <a href="http://www.atmel.com/images/doc42049.pdf">application note </a>and examples for the SAM3 &#40;the SAM7 replacement&#41;.  
I would suggest finding out why calculating the CRC is causing disruption to the interrupts.&nbsp; Only code that either disables the interrupts or places the CPU into a halt mode should do that.&nbsp; One of the things that can place the CPU into halt mode is printing out characters through a debug port &#40;semi-hosting&#41; so personally I would scrutinise your character input and output functions first.   
Regards.
