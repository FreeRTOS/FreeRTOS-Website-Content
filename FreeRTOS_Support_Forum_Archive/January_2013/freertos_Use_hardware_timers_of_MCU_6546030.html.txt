</div></div><div class="thread-post"><h3 class="thread-post-title">Use hardware timers of MCU</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on January 2, 2013</div><div class="thread-post-content">FreeRTOS does not make use of any of the peripheral timers.&nbsp; The only timer it uses is SysTick, which is part of the Cortex-M core.  
The demo applications make use of some software timers, but the demo tasks can &#40;should&#41; be removed.  
If you want to use the peripheral timers then I would suggest downloading the StellarisWare drivers from the TI website.&nbsp; There are API functions to manage the peripherals.

</div></div><div class="thread-post"><h3 class="thread-post-title">Use hardware timers of MCU</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on February 25, 2013</div><div class="thread-post-content"><blockquote>
  1&#46; So they are not related to FreeRTOS?&nbsp; On who&#8217;s context do they run?
</blockquote>
If you configure a hardware timer to generate an interrupt then the interrupt service routine runs as an interrupt, it is not in the context of any task.  
<pre><code>2. So do they have an impact on performance of FreeRTOS?
</code></pre>
Your application can use 100% of CPU time. The 100% is split between executing interrupts and executing non-interrupt code &#40;which may be a FreeRTOS application&#41;. If 5% of you time is spent executing interrupts then your non interrupt code only has 95% of the time left over, so yes interrupts always impact the performance of any code, not just FreeRTOS code.
</div></div><div class="thread-post"><h3 class="thread-post-title">Use hardware timers of MCU</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/khandharjay">khandharjay</a> on February 25, 2013</div><div class="thread-post-content">Thank you for the quick reply.  
So when I do a xSemaphoreGive in a Hardware Timer&#8217;s&nbsp; ISR, will that be semaphore be given immediately, and will release a task blocked on that semaphore?<br />
Or will it be given in the next tick, when the scheduler will run?
</div></div><div class="thread-post"><h3 class="thread-post-title">Use hardware timers of MCU</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on February 25, 2013</div><div class="thread-post-content">First, read the instructions for writing ISRs that interact with FreeRTOS. An ISR routine should NOT call xSemaphoreGive as that can cause data corruption. It needs to call xSemaphoreGiveFromISR &#40;ISR routines need to call the FromISR version of the API functions&#41;.  
As to resuming a now unblocked task, you need to look at the instructions for your port on how to activate the scheduler from your ISR to start the task up immediately. The xSemaphoreGiveFromISR has a parameter that you need to use to determine if you need to do this.
