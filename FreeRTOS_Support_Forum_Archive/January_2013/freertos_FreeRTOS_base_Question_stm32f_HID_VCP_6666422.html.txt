What is it you want to know about the test task, and when do you want to know it?  
If you want a snapshot view of the task then you could use a state viewer plug-in if you are using IAR or an Eclipse based IDE.&nbsp; That will tell you the stack usage at least.  
You can also code the task to monitor itself, if you want continuous monitoring.  
<blockquote>
  xTaskCreate&#40; , , , , , &amp;xHandle &#41;<br />

Is xHandle the same variable?&nbsp; A task handle can only reference one task at a time.&nbsp; It will reference the first task created after the first call to xTaskCreate&#40;&#41;, but then that reference will be lost and it will instead reference the second task created after the second call to xTaskCreate.  
Then, after the first call to vTaskDelete&#40;&#41; xHandle will not reference <strong>any</strong> valid task &#40;the task it did reference is not deleted&#41;, so the second call to vTaskDelete&#40;&#41; will be invalid.

</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS base Question (stm32f HID/VCP)</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on January 22, 2013</div><div class="thread-post-content">Most of the standard FreeRTOS demos use a set of common tasks that monitor themselves and update a counter if they are running correctly.&nbsp; A check task then monitors all the counters to ensure that all the tasks are running as expected.&nbsp; This is just one way of doing it though.  
The best way of doing it depends on what your task is doing.&nbsp; For example…if the task is supposed to run every second, then have the task read the time each time it executes so the task knows if it is running at the correct rate or not.&nbsp; If it detects that it is running at the correct rate it can communicate the error to whatever is monitoring the system.&nbsp; You can also use the hardware watchdog by having the task kick the watchdog if it is running and running correctly, and have it not kick the watchdog if it is not running or running incorrectly.  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS base Question (stm32f HID/VCP)</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/jdurand">jdurand</a> on January 22, 2013</div><div class="thread-post-content">One thing I do to check if tasks are running is I have each task I care about set a bit in my global FLAGS variable.&nbsp; Periodically &#40;slowly&#41; I run a Housekeeping task and one of the things it does is check the flags &#40;easy to do with a bit mask&#41;.&nbsp; If all is well it clears the flags and continues.&nbsp; Otherwise it skips touching the watchdog timer so the system will reset.  
Note that on setting and clearing flag bits in a global FLAGS variable I have two short functions that enter critical task while doing the change to prevent being swapped out in mid-change and messing up the global FLAGS.  
FlagSet&#40;bit&#95;mask&#41;;&nbsp; // OR in the bit<br />
FlagClear&#40;bit&#95;mask&#41;;&nbsp; // AND out the bit
