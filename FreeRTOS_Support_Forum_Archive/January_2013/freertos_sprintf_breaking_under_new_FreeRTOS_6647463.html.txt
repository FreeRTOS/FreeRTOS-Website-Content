Can anyone help out?

</div></div><div class="thread-post"><h3 class="thread-post-title">sprintf breaking under new FreeRTOS</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/jdurand">jdurand</a> on January 17, 2013</div><div class="thread-post-content">Check which print formatting library you have loaded.&nbsp; I had to enable semi-hosting in Code Red just to be able to get the full print library.
</div></div><div class="thread-post"><h3 class="thread-post-title">sprintf breaking under new FreeRTOS</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/groufosse">groufosse</a> on January 17, 2013</div><div class="thread-post-content">I&#8217;m using IAR EWARM 6.5, not code red. I&#8217;ve included the required libraries.   
If i build a test program without FreeRTOS, it formats OK, so it&#8217;s something in FreeRTOS causing it.  
</div></div><div class="thread-post"><h3 class="thread-post-title">sprintf breaking under new FreeRTOS</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on January 18, 2013</div><div class="thread-post-content">Your printf&#40;&#41; implementation will normally come from your compiler libraries, or sometimes from specialist third party libraries. FreeRTOS does not implement any standard library functions and it is highly improbable that anything in FreeRTOS could cause this.&nbsp; I think the issue you were referring to with the byte alignment was with regards to using 64 bit floating point numbers where the stack alignment needed adjusting &#8211; but the symptom was different.&nbsp; The symptom in that case was 0 being printed out instead of the floating point number, whereas in your case the symptom seems to be the printf formater does not understand the format string.  
<strong>However</strong> many FreeRTOS demos &#40;demos, not the kernel&#41; come with a third party file called printf-stdarg.c that provides a tiny cut down print/sprintf/printf implementation for use in cases where the libraries that come with the compiler are just too big for small embedded use &#40;notably when NewLib is used&#41;.&nbsp; I&#8217;m guessing that your project is including printf-starg.c in the build, and that is replacing the compilers implementation.  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">sprintf breaking under new FreeRTOS</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/groufosse">groufosse</a> on January 18, 2013</div><div class="thread-post-content">Richard,  
Thanks for elaborating your thoughts.<br />
To this point, I have half a dozen other projects that I have used the CMSIS included &#8220;debug&#95;frmwrk.h&#8221; file, and have had no issues using the calls from that &#40;&#95;DBG&#95;, &#95;DBG32&#95;, etc&#41;<br />
This formatting issue has just surfaced since I began developing with FreeRTOS a few weeks back. I can load any of those projects and don&#8217;t see this issue.  
Regartding the file you are referring to &#8211; &#8220;printf-stdarg.c&#8221;, it is in the RTOS source directory as I used one of your starting projects to get this going. It was the &#8220;Web dataserver&#8221; project.  
If i understand correctly, should I be using this instead of the CMSIS calls?  
Thank you.  
</div></div><div class="thread-post"><h3 class="thread-post-title">sprintf breaking under new FreeRTOS</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on January 18, 2013</div><div class="thread-post-content">One thing to note, not every file under the FreeRTOS directory is &#8220;part of FreeRTOS&#8221;, in particular, the contents of the demo directory is only sample programs provided as a guide. The file printf-stdarg.c that appears in many demos is such a file. If you want the functionality that the file provides, you can use it, but if it isn&#8217;t compatible with your requirements you shouldn&#8217;t.
</div></div><div class="thread-post"><h3 class="thread-post-title">sprintf breaking under new FreeRTOS</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/groufosse">groufosse</a> on January 18, 2013</div><div class="thread-post-content">Understood. </div></div><div class="thread-post"><h3 class="thread-post-title">sprintf breaking under new FreeRTOS</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on January 18, 2013</div><div class="thread-post-content">I suggest adding a simple printf&#40;&#8221;Hello world&#8221;&#41; line in your main&#40;&#41; function then step into the function in the debugger to see where it takes you.
</div></div><div class="thread-post"><h3 class="thread-post-title">sprintf breaking under new FreeRTOS</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on January 18, 2013</div><div class="thread-post-content">Could it be that your IAR project options are set to use a minimal printf&#40;&#41; implementation?  
If you bring up the project options, then go to the General Options category, then the Library Options tab, what is Printf Formatter set to?&nbsp; If it is set to anything other than &#8220;Full&#8221; can you try setting it to Full to see if that fixes your issue.
