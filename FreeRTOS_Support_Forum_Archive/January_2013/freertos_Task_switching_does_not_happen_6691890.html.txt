The target is a Tern 186 B engine board&gt;&nbsp; I am using Paradigm 7.00 as the developer IDE.  
I am using the demo project WizNET&#95;DEMO&#95;TERN&#95;186.. I have seen task / priority issues with this demo. Since I did not have all of the hardware used in this project I commented out the serial and http task creates in main.c. I also modified 186.cfg &#40;changed the amount of RAM from 128 to 512, the rdonly map from 0x0800 to 0x7ffff to 0x2c000 to 0x7ffff and the CODE&#95;START from 0x0800 to 0x2c000&#41; and freertosconfig.h &#40;config&#95;USE&#95;IDLE&#95;HOOK from 1 to 0 configCPU&#95;CLOCK&#95;HZ from 80000000 to 40000000&#41;. After downloading the application I set breakpoints inside the various forever loops that are in the created tasks. When I executed the code none of the breakpoints were hit. I did this because an earlier debug session with a breakpoint in the prvCheckTask function in main.c showed that no other task was running so I thought I could confirm this by breakpoints in the forever loops.   
What could be causing the lack of task execution other than prvCheckTask &#40;I even changed its priority from tskIDLE&#95;PRIORITY + 4 to tskIDLE&#95;PRIORITY + 2&#41;?   
Thanks
</div></div><div class="thread-post"><h3 class="thread-post-title">Task switching does not happen</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/edwards3">edwards3</a> on January 28, 2013</div><div class="thread-post-content">It sounds like the scheduler is not starting. Have you stepped through the vTaskStartScheduler&#40;&#41; function in the debugger? At the end it will call the portable layer start scheduler function. You should see the context of the first task being restored in that &#40;after the timer for the tick interrupt has been configured&#41;. What happens then?
</div></div><div class="thread-post"><h3 class="thread-post-title">Task switching does not happen</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/gary-e-a">gary-e-a</a> on January 31, 2013</div><div class="thread-post-content">I stepped through VTaskStartScheduler and found that when portFIRST&#95;CONTEXT&#40;&#41; is done is when things go bad.&nbsp; I stepped through the portFIRST&#95;CONTEXT assembler code and saw this: the registers AX, BX, CX, DX, SI, DI, BP, DS, and ES all got the value 0xA5A5.&nbsp; SP had 0x3DC.&nbsp; When the iret is done the CPU display shows A5A5:A5A5, at that and succeeding addresses is the value xFF &#8211; so the iRet went to memory that did not contain code.  
When I stepped this again I put a breakpoint in pxPortInitialiseStack&#40;&#41; and saw this code execute for each of the tasks created &#40;the last task created was prvIdleTask&#41;.&nbsp; Is it possible there is something wrong in the memory map definitions in 186,cfg?  
Thanks for your help.
</div></div><div class="thread-post"><h3 class="thread-post-title">Task switching does not happen</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on January 31, 2013</div><div class="thread-post-content">AX should be loaded with 0xaaaa, BX with 0xbbbb etc. so something is not good there.
