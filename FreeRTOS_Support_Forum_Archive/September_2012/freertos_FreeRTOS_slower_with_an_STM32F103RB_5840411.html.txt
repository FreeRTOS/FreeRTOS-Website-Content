  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">FreeRTOS slower with an STM32F103RB</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/blackswords">blackswords</a> on September 21, 2012</div><div class="thread-post-content">Hi everybody,  
I used FreeRTOS for a couple of projects based on an STM32F103VC and everything was working fine but now I switched to an STM32F103RB and for a reason that I ignore, the SysTick seems to run a about 100Hz instead of 1kHz… I measure this using the vApplicationTickHook&#40;&#41;.   
I used the exactly same files for the different projects, I just changed some definitions &#40;declare the MCU as a medium density for example&#41;.   
I checked, the oscillator is set up to runs at 72MHz, as usual.  
Do anyone has a lead on the origin of this behavior?   
Thanks
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS slower with an STM32F103RB</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on September 22, 2012</div><div class="thread-post-content">It must be a chip configuration problem.&nbsp;   
The kernel uses the SysTick to generate tick interrupts.&nbsp; SysTick is on the core itself and does not need clocking separately.&nbsp; The calculation used to set the tick frequency itself uses configCPU&#95;CLOCK&#95;HZ and configTICK&#95;RATE&#95;HZ &#40;both defined in FreeRTOSConfig.h&#41;.&nbsp; If these settings are correct, but the tick frequency is wrong, it would indicate that the CPU is not running at the frequency you think it is.  
<blockquote>
  I used the exactly same files for the different projects,
</blockquote>
Does that include the same system files provided by ST?&nbsp; If there is a setting in those files that is specific to the chip, then that might be the cause of the problem.&nbsp; Nothing in the FreeRTOS files themselves will change between the chips.  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS slower with an STM32F103RB</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/blackswords">blackswords</a> on September 22, 2012</div><div class="thread-post-content">Thanks for your answer.<br />
No, not the same ST files. I changed the linker script and the startup file. The chip is declared as a medium density one.<br />
In FreeRTOSConfig.h I have these lines :<br />
&#35;define configCPU&#95;CLOCK&#95;HZ &#40; 72000000UL &#41;<br />
&#35;define configTICK&#95;RATE&#95;HZ &#40; &#40; portTickType &#41; 1000 &#41;  
Is there any way to check the chip frequency?
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS slower with an STM32F103RB</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/blackswords">blackswords</a> on September 22, 2012</div><div class="thread-post-content">I used a PWM output to check the frequency of the CPU and I have an output frequency of 11.11Hz instead of 100Hz.<br />
So apparently the chip is running at 8MHz…<br />
It&#8217;s not a FreeRTOS problem so we can close this thread but if someone has an idea to solve that…
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS slower with an STM32F103RB</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on September 22, 2012</div><div class="thread-post-content">You could try finding the function that configures the CPU frequency, and then step into that using the debugger to see if there is a clue there &#40;either in the comments, or a variable&#41;.&nbsp; Be aware however that often a debugger will loose contact with the hardware if you try stepping over the instructions that change the CPU frequency &#40;presumably because the JTAG frequency changes too&#41;.&nbsp; The function that configures the clock might be called before main&#40;&#41;.  
Alternatively, if you are using CMSIS libraries, you can try inspecting the SystemCoreClock variable.  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS slower with an STM32F103RB</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/blackswords">blackswords</a> on September 22, 2012</div><div class="thread-post-content">Problem solved, I forgot that on this board I don&#8217;t have any external oscillator so I modified the clock configuration function to enable the PLL on the internal oscillator. I can reach 64MHz in this configuration.   
Thanks for your help
