  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Hard Fault after Interupt processing</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/sirdogged">sirdogged</a> on September 25, 2012</div><div class="thread-post-content">Hello.<br />
I installed and configured freeRTOS 7.2.0. After that i wrote a test program just to play with semaphores. If i push button on the board, led flashing mode should change. So i implemented all tasks, and, the strange fact is ISR process only one interrupt from the buttion, after second it executes portEND&#95;SWITCHING&#95;ISR function and hardfaults immidiatly.<br />
Could someone help me?<br />
Here is my code:<br />
<a href="http://pastebin.com/JLHmR8j7">http://pastebin.com/JLHmR8j7</a><br />
Here is problem part:  
<pre><code>void EXTI0_IRQHandler(void)
{
      if(EXTI_GetITStatus(EXTI_Line0) != RESET)
      {
          static portBASE_TYPE xHigherPriorityTaskWoken = pdFALSE;
          EXTI_ClearITPendingBit(EXTI_Line0);
          xHigherPriorityTaskWoken = pdFALSE;
          xSemaphoreGiveFromISR( xBinarySemaphore, &amp;xHigherPriorityTaskWoken );
          portEND_SWITCHING_ISR(xHigherPriorityTaskWoken);
      }
}
</code></pre>
After 2 press hardfault exception occurs.
</div></div><div class="thread-post"><h3 class="thread-post-title">Hard Fault after Interupt processing</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on September 26, 2012</div><div class="thread-post-content">Some ideas.  
&#45; The code you post does not show the interrupt priority being set, or the number of preemption priority bits being set.&nbsp; Please see <a href="http://www.freertos.org/RTOS-Cortex-M3-M4.html.">http://www.freertos.org/RTOS-Cortex-M3-M4.html.</a>  
&#45; When cr is 1, you create vBlinkLed before deleting vBlinkLed1.&nbsp; Are they trying to access the same hardware pins simultaneously?  
&#45; What is being executed when the hard fault occurs?&nbsp;<br />
<a href="http://www.freertos.org/Debugging-Hard-Faults-On-Cortex-M-Microcontrollers.html">http://www.freertos.org/Debugging-Hard-Faults-On-Cortex-M-Microcontrollers.html</a>
