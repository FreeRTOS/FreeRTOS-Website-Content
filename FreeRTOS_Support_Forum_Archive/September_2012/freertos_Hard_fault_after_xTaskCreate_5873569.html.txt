</div></div><div class="thread-post"><h3 class="thread-post-title">Hard fault after xTaskCreate</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on September 26, 2012</div><div class="thread-post-content">Is cmd&#95;newinterpreter&#40;&#41; called when when the kernel is already running?&nbsp; I presume so if you are calling vTaskDelay&#40;1&#41;.  
The effect calling vTaskDelay&#40; 1 &#41; has will depend on the priority of the task you are calling cmd&#95;newinterpreter&#40;&#41;&nbsp; from.&nbsp; The task you are creating is priority 2, so if you are calling cmd&#95;newinterpreter&#40;&#41; from a task of priority 3 or higher, then the vTaskDelay&#40;&#41; will allow cmd&#95;commandtask&#40;&#41; to run before cmd&#95;newinterpreter&#40;&#41; returns.&nbsp; If you are calling cmd&#95;newinterpreter&#40;&#41; from a task of priority 2 or lower, then cmd&#95;commandtask&#40;&#41; will run before cmd&#95;newinterpreter&#40;&#41; returned with or without the vTaskDelay&#40; 1 &#41;.  
Does it crash inside xTaskCreate&#40;&#41;, or inside cmd&#95;commandtask&#40;&#41;?&nbsp; What is it doing &#40;or trying to do&#41; to make it crash?  
Do you create a new queue for every command?&nbsp; Do you check the queue was created before trying to use it &#40;that is not shown in the code you have posted&#41;.
