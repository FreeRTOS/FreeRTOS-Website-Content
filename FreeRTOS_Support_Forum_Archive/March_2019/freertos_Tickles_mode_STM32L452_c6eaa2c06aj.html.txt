</div></div><div class="thread-post"><h3 class="thread-post-title">Tickles mode STM32L452</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on March 28, 2019</div><div class="thread-post-content">From your post I think you may be misinterpreting what the value does.
It does not say, &#8220;if you have been idle for
configEXPECTED<em>IDLE</em>TIME<em>BEFORE</em>SLEEP ticks then enter tickless mode&#8221;,
but &#8220;if there is nothing predictable to do for the next
configEXPECTED<em>IDLE</em>TIME<em>BEFORE</em>SLEEP ticks, then enter tickless mode&#8221;.
As a simple example, let&#8217;s say you have one task that runs every 1000
ticks, something like:
~~~
void mytask( void *pvParameters )
{
    for( ;; )
    {
        vTaskDelay( 1000 );
        DoSomething();
    }
}
~~~
Then every time the program enters vTaskDelay() the scheduler will know
the system has nothing to do for 1000 ticks (there are no other tasks
with shorter block times) so if configEXPECTED<em>IDLE</em>TIME<em>BEFORE</em>SLEEP is
set to 999 it will enter tickless mode to wait for 1000 ticks.  On the
other hand, if configEXPECTED<em>IDLE</em>TIME<em>BEFORE</em>SLEEP is set to 1001 then
it knows it will have something to do before 1001 ticks have passed as
mytask() needs to run in 1000 ticks, so it will not enter sleep mode.
The reasons I said &#8216;anything predictable to do&#8217; is because you can
receive an interrupt that brings the system out of sleep mode at any
time, the RTOS scheduler cannot know when that will happen in advance.
