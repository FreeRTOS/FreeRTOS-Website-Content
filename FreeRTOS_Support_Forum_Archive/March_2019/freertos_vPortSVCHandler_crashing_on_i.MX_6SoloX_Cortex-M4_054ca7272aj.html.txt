I&#8217;m not sure what ARMGCC with Mingw32 is exactly, but it sounds like you

toolchain.  You can look up &#8220;ARM GCC Launchpad&#8221; on Google to find a
native toolchain, then try compiling with the simplest of command line
options to start with.

1) Connect the debugger and step through the program normally
2) Stop the session
3) Connect the debugger and step through the program normally
However, step 3 fails and causes an impassible sigtrap on &#8220;svc 0&#8221; during the second debug session. I suspect that because this is a RAM application some things aren&#8217;t reset properly between sessions. But I&#8217;m not sure how I can sove this and where I should be looking. I&#8217;m currently using &#8216;reset 0&#8217; during programming and I&#8217;m passing the board to the gdb server. So this reset should already be the most optimal for my board.

</div></div><div class="thread-post"><h3 class="thread-post-title">vPortSVCHandler crashing on i.MX 6SoloX Cortex-M4 </h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on March 21, 2019</div><div class="thread-post-content">No, sorry, don&#8217;t know, but normally debug probes enable various
