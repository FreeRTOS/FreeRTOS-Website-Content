  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">UART Receive Non-Functioning with HAL Firmware</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/groger57">groger57</a> on March 17, 2019</div><div class="thread-post-content">Hello:
This issue is using and STM32L4, and FreeRTOS v9.
HAL is being a problem with interrupts on the UART. My FreeRTOSConfig.h has this:
~~#define configPRIO<em>BITS                               4
~~#define configLIBRARY</em>LOWEST<em>INTERRUPT</em>PRIORITY       3
~~#define configLIBRARY<em>MAX</em>SYSCALL<em>INTERRUPT</em>PRIORITY  3
~~#define configKERNEL<em>INTERRUPT</em>PRIORITY      ( configLIBRARY<em>LOWEST</em>INTERRUPT<em>PRIORITY &lt;&lt; (8 &#8211; configPRIO</em>BITS) )
~~#define configMAX<em>SYSCALL</em>INTERRUPT<em>PRIORITY ( configLIBRARY</em>MAX<em>SYSCALL</em>INTERRUPT<em>PRIORITY &lt;&lt; (8 &#8211; configPRIO</em>BITS) )
I know the scheduler is working OK because the systick is generated by TIM17, at  the end of SystemClock<em>Config() this code: 
 HAL</em>NVIC<em>SetPriorityGrouping(NVIC</em>PRIORITYGROUP<em>4);
HAL</em>NVIC<em>SetPriority(SysTick</em>IRQn, 15, 0);
And a task has no problem executing after scheduler launch. The UART is configured for interrupt callback and at the end of the configuration file:
 HAL<em>NVIC</em>SetPriority(USART3<em>IRQn, 3, 0);
 HAL</em>NVIC<em>EnableIRQ(USART3</em>IRQn);
 The callback (toggle a LED when active rx)
 void HAL<em>UART</em>RxCpltCallback(UART<em>HandleTypeDef* uartHandle)
{
     HAL</em>GPIO<em>TogglePin(GPIOB, GPIO</em>PIN<em>8); 
     HAL</em>UART<em>Receive</em>IT(&amp;huart3, rxBuff, 4);
}
 In main():
    MX<em>USART3</em>UART<em>Init();
    HAL</em>UART<em>Receive</em>IT(&amp;huart3, rxBuff, 4); 
<pre><code>At the start of the program the LED is on momentarily, then off, and does not come back on. I have this same interrupt functioning in a non-FreeRTOS application so I know the interrupt and callback appears to be working.
</code></pre>
I have read the section on M4 implementation, as mentioned, I have used FreeRTOS in quite a few CMSIS based firmware projects without problems, and in fact I am using the same FreeRTOSConfig file.
What can the issue be?

Didn&#8217;t have one of the priorities set in HAL correctly.
