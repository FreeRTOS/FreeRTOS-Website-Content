</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS on PIC32MX795 &#8211; Heap Stack issues</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on March 16, 2016</div><div class="thread-post-content">Prior to FreeRTOS V9, FreeRTOS would allocate all objects from the heap.  These are in the most part very small allocations, but the stacks used by tasks are also allocated from the heap, and those can be quite large.  The first thing to do will be to determine if any tasks are being allocated a stack size that is much larger than necessary.
There is a FreeRTOS plug-in for MPLAB but I&#8217;m not sure if it shows the stack sizes.  If not, you can use the <a href="http://www.freertos.org/uxTaskGetSystemState.html">uxTaskGetSystemState()</a> API function.
It is also advisable to ensure you have <a href="http://www.freertos.org/a00016.html">stack overflow and malloc failed hooks</a> defined in case you set the stack too small, or set the heap too small, respectively.
In Harmony the size of the stacks used by tasks created by the framework are set in the graphical configuration interface &#8211; it may be that the defaults are larger than necessary.

</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS on PIC32MX795 &#8211; Heap Stack issues</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on March 17, 2016</div><div class="thread-post-content">When you create a task, calling xTaskCreate(), the stack sizes are specified in words &#8211; so on a PIC32 a stack size of 100 words is 400 bytes.  The screen shot is showing the sizes in bytes I think.  Some of the tasks (the FS task in particular) do seem to be using a lot of stack space &#8211; but presumably necessarily so.
FreeRTOS+Trace will trace memory allocations, perhaps that will be useful?  I think there is a PIC32 version.
