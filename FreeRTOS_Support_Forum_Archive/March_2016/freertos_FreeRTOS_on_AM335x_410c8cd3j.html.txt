I know there&#8217;s been few discussions about that, but they&#8217;re from 2 years back.<br />
Is there eny port of FreeRTOS to AM335x processors? I&#8217;m developing software on custom board with AM3352, but port for BeagleBone will be ok.<br />
If not, is there port for any Cortex-A8 processor? If so is it reliable?
<p>Best regards,<br />
Konrad</p>

<h3 class="thread-post-title">FreeRTOS on AM335x</h3>
<div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on March 2, 2016</div>
<div class="thread-post-content">
<p>There are several Cortex-A9 ports, which will do what you want. Look at Renesas RZ/A, Xilinx Zynq and Altera SoC for examples. There are also Cortex-A5 ports for the Atmel SAMA5 parts &#8211; although these use a propriatory interrupt controller.</p>
<p>http://www.freertos.org/Using-FreeRTOS-on-Cortex-A-Embedded-Processors.html<br />
http://www.freertos.org/Using-FreeRTOS-on-Cortex-A-proprietary-interrupt-controller.html</p>
</div>
</div>
<div class="thread-post">
<h3 class="thread-post-title">FreeRTOS on AM335x</h3>
<div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/konradfoit">konradfoit</a> on March 4, 2016</div>
<div class="thread-post-content">OK.<br />
I&#8217;ve managed to do this. Wasn&#8217;t that hard, but the better start-point for this is the A5 port, since AM335x doesn&#8217;t have ARM GIC.<br />
The only tricky part was modifying IRQHandler form TIs StarterWare to perform Context switching.<br />
Although it seems that in the A5 port implementation of IRQHandler, FreeRTOS is checking if it should switch context on every interrupt, not only from SysTick. is that correct behaviour?</div>
</div>
<div class="thread-post">
<h3 class="thread-post-title">FreeRTOS on AM335x</h3>
<div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on March 4, 2016</div>
<div class="thread-post-content">
<p>Yes that is correct &#8211; any interrupt can unblock a task, and if a task that has a priority above the currently running task (the task that the interrupt interrupted) is unblocked then the ISR should return directly to the unblocked task.</p>
<p>I would be grateful if you could post your project to the FreeRTOS Interactive site (http://interactive.freertos.org).</p>
</div>
</div>

<h3 class="thread-post-title">FreeRTOS on AM335x</h3>
<div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on March 25, 2017</div>

use the ports as a reference for the required syntax.</div>
