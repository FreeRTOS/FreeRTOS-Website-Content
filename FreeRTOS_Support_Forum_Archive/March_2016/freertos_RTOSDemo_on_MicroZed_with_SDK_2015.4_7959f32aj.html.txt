</div></div><div class="thread-post"><h3 class="thread-post-title">RTOSDemo on MicroZed with SDK 2015.4</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on March 25, 2016</div><div class="thread-post-content">Hi Sting,
Try the following steps:
Unpack the entire ZIP in e.g. c:tempxilinx
Start 2015.4
File -> Switch -> Other -> enter e.g. &#8220;c:tempxilinxworkspace&#8221;
File -> Import -> General -> Existing project into workspace
Root directory enter:
<pre><code>C:tempxilinxFreeRTOS-PlusDemoFreeRTOS_Plus_TCP_and_FAT_Zynq_SDK
</code></pre>
and press TAB
The box will fill with three projects. Select them all and press OK.
When I press &#8220;Project -> Build All&#8221;, indeed I get mentioned error, a missing <code>xparameters.h</code>
Solution:
Press File -> New -> Board support package (BSP)
Do not use the default but this location for the BSP :
<pre><code>C:tempxilinxFreeRTOS-PlusDemoFreeRTOS_Plus_TCP_and_FAT_Zynq_SDK
</code></pre>
<ul>
<li>Hardware platform: MicroZed<em>hw</em>platform</li>
<li>CPU: ps7<em>cortexa9</em>0</li>
<li>standalone (because the project already contains FreeRTOS kernel)</li>
</ul>
Press Finish
Choose libraries (none are needed) and press OK
Now right-click in &#8220;Project Explorer&#8221; on <code>RTOSDemo</code>, select Project references and make sure that these are selected:
<pre><code>MicroZed_hw_platform
standalone_bsp_0
</code></pre>
It makes the main project (<code>RTOSDemo</code>) dependent on these 2 sub-projects, they will be included when building.
Now try &#8220;Project->Build All&#8221; again. <code>RTOSDemo.elf</code> will be created.
And also this file will be present:
<pre><code>..standalone_bsp_0ps7_cortexa9_0includexparameters.h
</code></pre>
Have a look at the attachment of this post: &#8216;MicroZed_debug.png&#8217;, it might answer your next questions 🙂
Regards.

</div></div><div class="thread-post"><h3 class="thread-post-title">RTOSDemo on MicroZed with SDK 2015.4</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on March 29, 2016</div><div class="thread-post-content">This is Xilinx tools specific stuff, rather than FreeRTOS specific stuff.
The demos ship with a hardware description in the form of a hardware project, from which the Xilinx tools auto-generate a BSP project, which in turn is used by the application project.  The instructions on the documentation page give detailed information on how this is down &#8211; but the demo does not use anything outside of the hard wired ARM processor, the FPGA is not programmed so no bitstream is required [by the demo].
</div></div><div class="thread-post"><h3 class="thread-post-title">RTOSDemo on MicroZed with SDK 2015.4</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on March 29, 2016</div><div class="thread-post-content">Sting, about the UDP logging.
Here are all config parameters that influence the UDP logging:
~~~~
/* Make this non-zero if your terminal needs CR+LF in stead of LF. */
<h1>define configUDP<em>LOGGING</em>NEEDS<em>CR</em>LF  ( 0 )</h1>
/* The UDP port to which the UDP logging facility sends messages.
Open a UDP socket on this port number on your laptop: */
<h1>define configUDP<em>LOGGING</em>PORT_REMOTE       2403</h1>
/* The local UDP port to which messages can be sent.
If you want to send messages to the UDP logging socket,
send them to the following port number: */
<h1>define configUDP<em>LOGGING</em>PORT_LOCAL        2402</h1>
/* You can define configUDP<em>LOGGING</em>ADDR[0-3] which will be
used as a fixed target IP address.
As defined here, all UDP logging will be sent to
192.168.1.115 on port &#8216;configUDP<em>LOGGING</em>PORT_REMOTE&#8217; */
<h1>define configUDP<em>LOGGING</em>ADDR0  192</h1>
<h1>define configUDP<em>LOGGING</em>ADDR1  168</h1>
<h1>define configUDP<em>LOGGING</em>ADDR2  1</h1>
<h1>define configUDP<em>LOGGING</em>ADDR3  115</h1>
/* If you do not define configUDP<em>LOGGING</em>ADDR[0-3], the program
will look at your network address and netmask, and (in your case)
all logging will be sent to 192.168.1.255 port &#8216;configUDP<em>LOGGING</em>PORT_REMOTE&#8217; */
~~~~
If you are able to PING, I don&#8217;t think you have a hardware problem and ALL UDP and TCP communication should be possible.
About the hardware initialisation: in the examples that I sent, another platform ZC02 was used, sorry about that.
I attached a new PGN file that shows the settings for MicroZed<em>hw</em>platform.
Regards.

is something like freertos.html.  Unless you have changed the files on

processors are hard processors that can be used just like any processor
