  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Getting Started with Tiva C series</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/frankthetank34">frankthetank34</a> on March 23, 2016</div><div class="thread-post-content">Hello,
I am starting development of a project with the Tiva C series TM4c1294 launchpad. I see there is an example RTOS project for the board under the &#8220;sensor<em>iot&#8221; project. There is also a &#8220;free</em>rtos&#8221; demo on the tm4c123 launchpad. From what I can tell, the two projects link to the same freertos source files within the tivaware install directory. When reading the &#8220;porting a freertos demo&#8221; page, it makes me believe there should be minute differences between the two projects, as they run on the same family of processors but slightly different processors. How are the projects differentiating the two? I am trying to understand what parameters are actually different. I would like to use the free_rtos demo to start, as it is significantly less complicated, but I want to run it on the TM4C1294 launchpad.
Thanks
</div></div><div class="thread-post"><h3 class="thread-post-title">Getting Started with Tiva C series</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on March 24, 2016</div><div class="thread-post-content">These are Cortex-M based devices, so will use exactly the same FreeRTOS 
port.  The FreeRTOS download has lots of Cortex-M demo applications, 
which target lots of different Cortex-M parts, from lots of different 
MCU vendors, and all reference and all these demos reference and build 
the same Cortex-M port layer in the FreeRTOS/Source/portable/[compiler] 
directory.
The only differences will be found in the application, not the RTOS 
source code, where:
<ul>
<li>the linker scripts will be difference</li>
<li>the start up code will be difference (different interrupt vector table 
in particular)</li>
<li>FreeRTOSConfig.h will be different, this just tailors the RTOS to the 
application</li>
</ul>
