</div></div><div class="thread-post"><h3 class="thread-post-title">portEND_SWITCHING_ISR</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on March 3, 2016</div><div class="thread-post-content"><blockquote>
  I don&#8217;t understand your answer, can you elaborate more.
</blockquote>
I said &#8220;Depends on which port you are using.&#8221; because, the answer to your question depends on which port you are using, and as you didn&#8217;t say, I couldn&#8217;t answer the question.
If you are using a Cortex-M4 port then you can call portEND<em>SWITCHING</em>ISR or portYIELD<em>FROM</em>ISR at any time &#8211; it does not have to be at the end of the ISR.
</div></div><div class="thread-post"><h3 class="thread-post-title">portEND_SWITCHING_ISR</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on March 4, 2016</div><div class="thread-post-content">If I remember right, on the M4 the portYIELD<em>FROM</em>ISR triggers a lowest priority interrupt to cause the task switch, which will be blocked by the current ISR running, so exactly when that interrupt is triggered doesn&#8217;t matter. 
On the other hand, in the PIC24 port, the portYIELD<em>FROM</em>ISR actually does the task switch, and continues execution at that task, and the code that follows isn&#8217;t executed until the original task gets switched back to, so it really does need to be the very last code in the ISR.
If you wanted to write you ISR so it can work on system like the latter, then any function that the ISR calls which might set the HigherPriorityTaskWasWoken flag, needs to be passed the flag so it can pass that to the API, and the ISR tests it as its last step.
