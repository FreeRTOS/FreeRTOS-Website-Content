for this board? 
   The Advantech in question is a current production industrial ruggedized
PC clone, and runs Linux Mint 17.2 with no problem.  Any BSP which supports
IA32 mode on a standard PC-type computer should work.
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS on Advantech PCM-3356 (IA32 mode i686 processor)</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on March 2, 2016</div><div class="thread-post-content">I presume this is the port you are using: http://www.freertos.org/RTOS<em>Intel</em>Quark<em>Galileo</em>GCC.html &#8211; that should set up the timer interrupt and integrate the scheduler with the tick for you.
What are you looking for in the BSP?  (what needs to be supported?)
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS on Advantech PCM-3356 (IA32 mode i686 processor)</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/dave-the-rave">dave-the-rave</a> on March 2, 2016</div><div class="thread-post-content">I am using that port, or at least parts of it.  Specifically:
BaseType<em>t xPortInstallInterruptHandler( ISR</em>Handler<em>t pxHandler,
                                         uint32</em>t ulVectorNumber );
The problem is that I can get swi to work just fine, but cannot get an IRQ 5 to fire.
The IRQ 5 is connected to an old-fashioned PC/104 bus and appears on the
8259 input pins (or their virtual equlvalent).
Three questions:
Is this thing using the PIC, the APIC, or something else?
I am using grub as the bootloader, which puts the cpu into flat IA32-bit mode, but which requires that I call the routine which does asm(&#8220;lidt&#8221;) before any interrupt service routine will run.  Is this going to cause some kind of problem?
Do I have to change the interrupt vector location?  If so, how do I do that?
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS on Advantech PCM-3356 (IA32 mode i686 processor)</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on March 2, 2016</div><div class="thread-post-content">That demo is using the APIC (predominantly  at least, I think there are some interrupts routed via the legacy PIC used in the demo app).
The demo also uses grub &#8211; I think there is a pdf linked from the documentation page that gives more detail.  With regards to setting up the APIC and IDT, see https://sourceforge.net/p/freertos/code/HEAD/tree/trunk/FreeRTOS/Source/portable/GCC/IA32_flat/port.c &#8211; the tables are set up before the scheduler is started, you can search for the lidt instruction being used.
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS on Advantech PCM-3356 (IA32 mode i686 processor)</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/dave-the-rave">dave-the-rave</a> on March 2, 2016</div><div class="thread-post-content">I have read most of this, including the port.c.  My question is, where does it put the vectors for the legacy interrupts (com1, com2, lpt1, etc?)  I suspect that if I was to be sure about where exactly to put the vector, that would be half the problem solved.
I notice that, after grub has finished and after calling the port.c init stuff, the PIC registers contain non-zero mask bits, which implies that the PIC is being used.  True?
