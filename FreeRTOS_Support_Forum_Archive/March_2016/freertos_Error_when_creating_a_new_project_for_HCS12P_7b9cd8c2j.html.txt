</div></div><div class="thread-post"><h3 class="thread-post-title">Error when creating a new project for HCS12P</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on March 15, 2016</div><div class="thread-post-content"><blockquote>
  **Link Error : L1822: Symbol vAssertCalled in file
  C:UsersToshibaDesktopProject<em>4</em>newProject<em>4</em>new<em>DataStandardObjectCodeheap</em>1.c.o
  is undefined
</blockquote>
I suspect you have configASSERT() defined to call vAssertCalled() &#8211; if 
you do that then your application must implement vAssertCalled().
http://www.freertos.org/a00110.html#configASSERT
<blockquote>
  <em>Link Error : L1822: Symbol portRESET_READY_PRIORITY in file
  C:UsersToshibaDesktopProject_4_newProject_4_new_DataStandardObjectCodetasks.c.o
  is undefined</em>
</blockquote>
Searching for portRESET<em>READY</em>PRIORITY in tasks.c will show that, if 
configUSE<em>PORT</em>OPTIMISED<em>TASK</em>SELECTION is set to 0 or undefined in 
FreeRTOSConfig.h, then portRESET<em>READY</em>PRIORITY is not needed.
If that is not clear &#8211; set configUSE<em>PORT</em>OPTIMISED<em>TASK</em>SELECTION to 0.
<blockquote>
  *
  Link Error : L1822: Symbol taskRECORD<em>READY</em>PRIORITY in file
  C:UsersToshibaDesktopProject<em>4</em>newProject<em>4</em>new_DataStandardObjectCodetasks.c.o
  is undefined*
</blockquote>
Same as portRESET<em>READY</em>PRIORITY comment.
<blockquote>
  <em>Link Error : L1822: Symbol TERMIO_PutChar in file C:Program Files
  (x86)FreescaleCWS12v5.1libHC12clibansibi.lib is undefined</em>
</blockquote>
This is a tools issue.  Perhaps the library has been changed since the 
demo was created (which was many years ago).
<blockquote>
  <em>Link Error : L1822: Symbol vApplicationMallocFailedHook in file
  C:UsersToshibaDesktopProject_4_newProject_4_new_DataStandardObjectCodeheap_1.c.o
  is undefined</em>
</blockquote>
Google vApplicationMallocFailedHook to find the documentation page for 
this on the FreeRTOS.org website. [either set 
configUSE<em>MALLOC</em>FAILED_HOOK to 0 or define the 
vApplicationMallocFailedHook callback function]
>
<blockquote>
  <em>Link Error : L1822: Symbol vConfigureTimerForRunTimeStats in file
  C:UsersToshibaDesktopProject_4_newProject_4_new_DataStandardObjectCodetasks.c.o
  is undefined</em>
</blockquote>
Again, Google finds the answer right away 
http://www.freertos.org/rtos-run-time-stats.html
>
<blockquote>
  <em>Link Error : L1822: Symbol TickTimer_SetFreqHz in file
  C:UsersToshibaDesktopProject_4_newProject_4_new_DataStandardObjectCodeport.c.o
  is undefined</em>
</blockquote>
This looks like a library function being called from the RTOS port layer 
&#8211; if it cannot be found then either the libraries have been changed 
since the port was written (it is an OLD port!) or it is related to the 
fact that the library could not be found (a few comments above).
<blockquote>
  <em>Link Error : L1822: Symbol TickTimer_Enable in file
  C:UsersToshibaDesktopProject_4_newProject_4_new_DataStandardObjectCodeport.c.o
  is undefined</em>
</blockquote>
Same comment as for TickTimer_SetFreqHz.

</div></div><div class="thread-post"><h3 class="thread-post-title">Error when creating a new project for HCS12P</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on March 20, 2016</div><div class="thread-post-content">On 20/03/2016 00:10, Karima AISSAOUI wrote:
<blockquote>
  Hello,
  I tried to integrate TickTimer.C file that you recommended, but that
  creates other errors, so I tried the alternative solution, of modifying
  the file port.c with another one.
  finally I got the following error:
  <em>Link Error : L1102: Out of allocation space in segment RAM at address
  0x3105
  *
  *Link Error : Link failed</em>
</blockquote>
I suspect you have just declared a heap that is too big for the part you 
are trying to use.  See 
http://www.freertos.org/a00110.html#configTOTAL<em>HEAP</em>SIZE
<blockquote>
  Another question if it is possible : Can we port the kernel of FreeRTOS
  on the HCS12P64 microcontroller which has 64KB cache memory and 4KB of RAM?
</blockquote>
64KB cache memory?  I presume you mean 64KB for flash memory &#8211; and if 
that is the case, then yes, definitely.  http://www.freertos.org/FAQMem.html
As for 4K of RAM, then yes also, but it will restrict the number of 
tasks you can create as each task requires its own stack, and each stack 
needs RAM.  It looks like the [very old] demo in the download is using 
less than 2K.
Regards.
