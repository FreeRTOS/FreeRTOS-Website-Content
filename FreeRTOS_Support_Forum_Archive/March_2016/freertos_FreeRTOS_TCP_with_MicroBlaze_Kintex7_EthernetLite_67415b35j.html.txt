</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS+TCP with MicroBlaze_Kintex7_EthernetLite</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on March 25, 2016</div><div class="thread-post-content">Hi John,
Have you had a look at the <a href="http://www.freertos.org/FreeRTOS-Plus/FreeRTOS_Plus_TCP/FreeRTOS_TCP_Porting.html">porting guide</a> already?
Your function <code>xNetworkInterfaceInitialise()</code> will be called at regular intervals until it returns <code>pdPASS</code>. So as long as the interface is not ready (e.g. PHY Link Status low), you return <code>pdFAIL</code>.
Once it has returned pdPASS, two things will happen:
<ul>
<li>The <code>xNetworkInterfaceOutput()</code> function will be called by the IP-task to have packets sent.</li>
<li>Your driver will poll RX messages and add them to a queue to the IP-task. It should also test the PHY status.</li>
</ul>
You could start with e.g. one of these drivers:
<pre><code>FreeRTOS-Plus-TCP/portable/NetworkInterface/Zynq/NetworkInterface.c
FreeRTOS-Plus-TCP/portable/NetworkInterface/ATSAM4E/NetworkInterface.c
</code></pre>
Make a choice between one of these <a href="http://www.freertos.org/FreeRTOS-Plus/FreeRTOS_Plus_TCP/Embedded_Ethernet_Buffer_Management.html">source files</a>:
<pre><code>    FreeRTOS-Plus-TCP/portable/BufferManagement/BufferAllocation_1.c
    FreeRTOS-Plus-TCP/portable/BufferManagement/BufferAllocation_2.c
</code></pre>
Once it works, you can look at optimisations, such as:
<pre><code>#define ipconfigDRIVER_INCLUDED_TX_IP_CHECKSUM  ( 1 )
#define ipconfigDRIVER_INCLUDED_RX_IP_CHECKSUM  ( 1 )
#define ipconfigETHERNET_DRIVER_FILTERS_PACKETS ( 1 )
#define ipconfigUSE_LINKED_RX_MESSAGES          ( 1 )
#define ipconfigZERO_COPY_RX_DRIVER             ( 1 )
#define ipconfigZERO_COPY_TX_DRIVER             ( 1 )
</code></pre>
If you have specific questions about porting you can also write to us <a href="http://www.freertos.org/RTOS-contact-and-support.html">directly</a>
Regards.

</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS+TCP with MicroBlaze_Kintex7_EthernetLite</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/logicanalyzer">logicanalyzer</a> on March 25, 2016</div><div class="thread-post-content">Thanks for the reply. Let me restate my question.
The FreeRTOSV8.2.3 release has a demo for the Xinlix MicroBlaze processor on a Xilinx KC705 FPGA development board. The MicroBlazeKintex7_EthernetLite demo uses the light weight IP stack (&#8220;lwIP&#8221;) and the Xilinx &#8220;emaclite&#8221; driver.
I want to use FreeRTOS+TCP instead of lwIP. Is there any chance of using the lwIP &#8220;emaclite&#8221; driver with FreeRTOS+TCP? Or is the FreeRTOS+TCP driver model so different that the lwIP driver can&#8217;t be used, and a new, FreeRTOS+TCP compatible driver must be developed?
Alternately, is there a Xilinx emaclite driver for FreeRTOS+TCP?
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS+TCP with MicroBlaze_Kintex7_EthernetLite</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on March 26, 2016</div><div class="thread-post-content">In any TCP/IP stack the drivers can be viewed at two levels:
1) The low level network input and output functions
2) The functions that interface the low level network input and output 
functions with the TCP/IP stack.
The hardest part is getting (1) to work.  In this case Xilinx provide 
this for you, and it is the Xilinx low level drivers that are used in 
the lwIP example.
(2) is just wrapping the low level drivers in a function that has the 
prototype and behaviour expected by the TCP/IP stack &#8211; which is a lot 
simpler than writing and debugging the drivers in the first place.  The 
prototype of these interface functions is not compatible between lwIP 
and FreeRTOS+TCP, but as you don&#8217;t need to create the low level input 
and output functions, it should not be difficult porting to 
FreeRTOS+TCP.  Hein has already linked to the porting documentation, and 
there are several examples in the FreeRTOS+TCP download.
As always, start with the easiest thing first &#8211; don&#8217;t try and do 
anything cleaver like have a 100% zero copy driver.  Just get the code 
working in the simplest way possible and only after it is working assess 
whether it meets your performance acquirements, and only if it does not 
meet your performance requirements adapt the simple working driver into 
something more complex.
