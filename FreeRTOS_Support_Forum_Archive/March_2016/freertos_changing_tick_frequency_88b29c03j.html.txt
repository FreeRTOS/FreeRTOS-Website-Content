I&#8217;m using an atmega328p with FreeRTOS 8.3.2. with 16MHz and 1000 ticks per second.
All my delays are like (x / portTICK<em>PERIOD</em>MS) where x is the delay in ms.

I&#8217;ve read some topics about tick timing but I&#8217;m still not sure what&#8217;s wrong here.
Can you help me?
Thanks a lot 🙂
</div></div><div class="thread-post"><h3 class="thread-post-title">changing tick frequency</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on March 30, 2016</div><div class="thread-post-content"><blockquote>
  8.3.2
</blockquote>
guess you mean 8.2.3
<blockquote>
  (x / portTICK<em>PERIOD</em>MS)
</blockquote>
Use pdMS<em>TO</em>TICKS(x) instead.
The tick frequency can only be changed at compile time. If you use the pdMS<em>TO</em>TICKS or portTICK<em>PERIOD</em>MS macros for all timing then you should be good for tick speeds up to 1KHz.

void blinkThread(void* arg) {

</div></div><div class="thread-post"><h3 class="thread-post-title">changing tick frequency</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/kyromaster">kyromaster</a> on March 30, 2016</div><div class="thread-post-content">the ARDUINO<em>START() and ARDUINO</em>END() macros disable and enable the scheduler. that&#8217;s what I found as recommendation.
strange thing is that when I change to:
~~~~
void blinkThread(void* arg) {
<pre><code>while (true) {
    ARDUINO_START();
    digitalFlip(LED_PIN);
    ARDUINO_END();
    vTaskDelay(1000);
}
</code></pre>
}
~~~~
everything works fine. so I guess there&#8217;s something wrong with the pdMS<em>TO</em>TICKS macro.
I configured freertos with:
~~~~
<h1>define configCPU<em>CLOCK</em>HZ          ( ( unsigned long ) F_CPU )</h1>
<h1>define configTICK<em>RATE</em>HZ          ( ( TickType_t ) 1000 )</h1>
~~~~
</div></div><div class="thread-post"><h3 class="thread-post-title">changing tick frequency</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on March 30, 2016</div><div class="thread-post-content">Its possible you are simply getting a numeric overflow as it is likely 
your tick count value is only 16-bits.  You could set 
configUSE<em>16</em>BIT_TICKS to 0 in FreeRTOSConfig.h, which will then make 
the ticks 32-bit, at some processing overhead expense as you only have 
an 8-bit device.
Also, try declaring a const variable that has the delay you need, then 
you will see what the value actually is.  Also it will be more efficient 
as the pdMS<em>TO</em>TICKS() macro will only evaluate once, rather than each 
time you call vTaskDelay().
</div></div><div class="thread-post"><h3 class="thread-post-title">changing tick frequency</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/kyromaster">kyromaster</a> on March 30, 2016</div><div class="thread-post-content">I changed configUSE<em>16</em>BIT_TICKS to 0.
