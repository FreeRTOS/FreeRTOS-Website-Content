  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Detect TCP client disconnect</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/focusmaarten">focusmaarten</a> on February 12, 2019</div><div class="thread-post-content">Hey all,
I&#8217;m using FreeRTOS+TCP to start up a small server through which I serve a CLI to a connecting user. I only want a single user connected at a time, so it is important for me to detect a client disconnecting as soon as possible. For now, the only way I&#8217;ve found to figure out the client has disconnected, is to try to send or receive something and check the return value from the function.
But, if a client disconnects nicely (i.e. sends a nice TCP FIN message with all the necessary acks going back and forth), the TCP/IP stack knows that the client has disconnected, right? Is there a way I can know right away that the socket has been closed remotely?
</div></div><div class="thread-post"><h3 class="thread-post-title">Detect TCP client disconnect</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on February 12, 2019</div><div class="thread-post-content">For your application, <code>ipconfigTCP_KEEP_ALIVE</code> will be helpful. It sends mini-packets to the peer, just to test if it is still alive. After 3 times &#8220;no answer&#8221;, the connection will be broken.
If your TCP server will only have 1 client at the time, consider using <code>FREERTOS_SO_REUSE_LISTEN_SOCKET</code>.
Normally, <code>FreeRTOS_accept()</code> returns a new socket. The server socket itself will never connect and it will only be used to call accept().
With the <code>FREERTOS_SO_REUSE_LISTEN_SOCKET</code> option, a successful <code>FreeRTOS_accept()</code> will return the server socket itself. After the connection has gone, please call <code>FreeRTOS_closesocket()</code> for that server socket.
After that, create a new server socket and call accept() again.
I wrote some code that causes a graceful disconnect <a href="https://sourceforge.net/p/freertos/discussion/382005/thread/fe2c5dd342/?limit=250#cfad">here</a>
But normally when the peer takes the initialive to disconnect ( like a telnet server ), you can use this type of code:
~~~
    for( ;; )
    {
    BaseType_t xResult;
<pre><code>    xResult = FreeRTOS_recv( xSocket, pcBuffer, sizeof( pcBuffer ), 0 );
    if( ( xResult &lt; 0 ) &amp;&amp; ( xResult != -pdFREERTOS_ERRNO_EAGAIN ) )
    {
        break;
    }
    if( xResult &gt; 0 )
    {
        /* Do something with the data received. */
    }
}
</code></pre>
~~~
Now when the peer sends a shutdown, <code>FreeRTOS_recv()</code> will return immediately with <code>-pdFREERTOS_ERRNO_ENOTCONN</code> or so.
You can also poll the current status: <code>FreeRTOS_issocketconnected()</code>.
Personally I like to use the option <code>ipconfigSOCKET_HAS_USER_SEMAPHORE</code>. That allows you to attach semaphore to all sockets. If any socket has an important event ( RX, TX, error, disconnect ), the semaphore will be given to. When using this technique, the sockets are used in a non-blocking way ( e.g. with <code>FREERTOS_MSG_DONTWAIT</code> ).
The main loop will look like this:
~~~
    for( ;; )
    {
        xSemaphoreTake (xMySemaphore, pdMS<em>TO</em>TICKS( 10000 ));
        /* Check all sockets in a non-blocking way. */
    }
~~~
