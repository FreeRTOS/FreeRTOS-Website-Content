</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS 10.1.1 HTTP server on SAM4E Xplained stops after sending one file</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on February 20, 2019</div><div class="thread-post-content">About <code>tx_release_count</code> :
&#8211; [0] must be equal to [2]
&#8211; Both [1] and [3] must remain zero.
tx<em>release</em>count[2] :
After a packet was delivered, there is an interrupt from the EMAC.
The TX DMA descriptors are returned via a queue &#8216;xTxBufferQueue&#8217;
tx<em>release</em>count 0 and 1:
The task <code>prvEMACHandlerTask()</code> will free the Network Buffer.
If the buffer was OK, it will call <code>vReleaseNetworkBufferAndDescriptor()</code> and increase tx<em>release</em>count[0].
Otherwise, it will increase tx<em>release</em>count[1]
The above is only true for zero-copy drivers (<code>ipconfigZERO_COPY_TX_DRIVER</code>).
Other drivers will only increase tx<em>release</em>count[0].
<code>xTXDescriptorSemaphore</code> is a &#8220;counting semaphore&#8221;, it keeps track of the number of available DMA descriptors for transmission. It is incremented after a DMA descriptor is returned to the driver.
Have you seen this warning ?
~~~
    FreeRTOS_printf( ( &#8220;TX DMA buffers: lowest %lun&#8221;, uxLowestSemCount ) );
~~~
When tx<em>release</em>count[3] is increased, all DMA descriptors were occupied. That is unexpected.
<code>GMAC_TX_BUFFERS</code> defines the number of DMA/TX descriptors. How is it defined in your project?
But even if you only have 1 TX descriptor, there should not be a time-out: <code>xNetworkInterfaceOutput</code> waits for 50 ms for a TX descriptor. That is more than enough to deliver the largest packet.
I think that your <code>GMAC_TX_BUFFERS</code> equals 8 and that <code>xTxCallback()</code> is never called by the driver <code>gmac_SAM.c</code>.
<a href="https://sourceforge.net/p/freertos/discussion/382005/thread/3ffa4ba7/f365/attachment/DriverSAM_20_apr_2018.7z">Here</a> you find the latest SAM driver, I attached it to <a href="https://sourceforge.net/p/freertos/discussion/382005/thread/3ffa4ba7/?limit=250#f365">this post</a>
I left in two lines that <strong>must</strong> be taken away:
~~~
-NVIC<em>DisableIRQ( GMAC</em>IRQn );
-NVIC<em>EnableIRQ( GMAC</em>IRQn );
~~~
I temporarily disabled the IRQ in order debug the code. That might cause the problem that you are describing.
