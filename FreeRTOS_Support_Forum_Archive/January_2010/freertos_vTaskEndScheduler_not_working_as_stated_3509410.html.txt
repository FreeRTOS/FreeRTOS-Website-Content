I&#8217;m using FreeRTOS on a project of my own with a custom board and an AT90USB647 uController. At some point I need to jump to the USB boot loader code and before I do it I stop the scheduler with <em>vTaskEndScheduler</em> function.<br />
Problem is:<br />
&#45; in the documentation it is stated that execution will return to the instruction after the call to <em>vTaskStartScheduler</em> just as if it had returned &#40;see <a href="http://www.freertos.org/a00133.html%29.">http://www.freertos.org/a00133.html&#41;.</a><br />

<pre><code>void vTaskEndScheduler( void )
{
    /* Stop the scheduler interrupts and call the portable scheduler end
    routine so the original ISRs can be restored if necessary.  The port
    layer must ensure interrupts enable bit is left in the correct state. */
    portDISABLE_INTERRUPTS();
    xSchedulerRunning = pdFALSE;
    vPortEndScheduler();
}
</code></pre>
this means that unless somehow i make code on <em>vPortEndScheduler</em> to return to the instruction after <em>vTaskStartScheduler</em> the return will be to the instruction after <em>vTaskEndScheduler</em>.

Bernardo Marques.

 portBASE_TYPE xPortStartScheduler( void )
 {
+   if (!sh_stop_request) {
    /* Make PendSV and SysTick the same priroity as the kernel. */

+           "   push {r0-r12,lr}            n"
+           "   mrs %[basepri_val], basepri n"
+           "   mrs %[control_val], control n"
+           "   mrs %[psp_val], psp         n"
+           "   mrs %[msp_val], msp         n"
+           : [basepri_val]"=r" (sh_context[0]), [psp_val]"=r" (sh_context[1]), [msp_val]"=r" (sh_context[2]), [control_val]"=r" (sh_context[3])
