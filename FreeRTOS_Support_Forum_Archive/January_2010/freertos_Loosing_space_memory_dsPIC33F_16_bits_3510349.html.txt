Has some setup to do on MPLab or have no way? In both examples, I have one byte and one int, but in the first I loss one byte of memory, adding one byte on the final result, and always I make this exact structure, it adds one byte after int.

</div></div><div class="thread-post"><h3 class="thread-post-title">Loosing space memory dsPIC33F 16 bits</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/edwards3">edwards3</a> on January 7, 2010</div><div class="thread-post-content">I think their compilers are GCC based so you can use &#95;&#95;attribute&#95;&#95;&#40;&#40;packed&#41;&#41; on individual structure variables or -fpack-struct compiler switch to pack all structures.  
Not a FreeRTOS question, by the way.
</div></div><div class="thread-post"><h3 class="thread-post-title">Loosing space memory dsPIC33F 16 bits</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on January 7, 2010</div><div class="thread-post-content">One comment, on the dsPic Processor, like many processors today, multi-byte numbers may not be placed at arbitrary memory locations, but must be aligned to some power of 2 for addresses. 16 bit numbers on the dsPic must be stored on even addresses or the processor will not fetch them correctly. If you try to access a 16 bit word at an odd address, the processor will raise an address error execption.
</div></div><div class="thread-post"><h3 class="thread-post-title">Loosing space memory dsPIC33F 16 bits</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/edwards3">edwards3</a> on January 7, 2010</div><div class="thread-post-content"><blockquote>
  One comment, on the dsPic Processor, like many processors today, multi-byte numbers may not be placed at arbitrary memory locations, but must be aligned to some power of 2 for addresses. 16 bit numbers on the dsPic must be stored on even addresses or the processor will not fetch them correctly. If you try to access a 16 bit word at an odd address, the processor will raise an address error execption.
</blockquote>
So the order in which you list the members inside the structure will also make a difference.&nbsp; Dont have a char followed by an int followed by a char, but instead a char followed by a char followed by an int.
</div></div><div class="thread-post"><h3 class="thread-post-title">Loosing space memory dsPIC33F 16 bits</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on January 7, 2010</div><div class="thread-post-content">Int followed by char followed by another char won&#8217;t lose space. A structure of an int followed by a char, and that is all, will still take 4 bytes as is required to make array work.
</div></div><div class="thread-post"><h3 class="thread-post-title">Loosing space memory dsPIC33F 16 bits</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/vscastro">vscastro</a> on January 8, 2010</div><div class="thread-post-content">Hi edwards3, the tip you said worked very well &#8220;&#95;&#95;attribute&#95;&#95;&#40;&#40;packed&#41;&#41;&#8221;.  
My structures are in this syntax:<br />
typedef struct<br />
&#123;<br />
&nbsp; char a;<br />
&nbsp; int b;<br />
&nbsp; char c;<br />
&#125; Tes1;  
How I put the attribute in this structure above?  
Because I got it in this syntax below:<br />
struct Test2<br />
&#123;<br />
&nbsp; char a;<br />
&nbsp; int b;<br />
&nbsp; char c;<br />
&#125; &#95;&#95;attribute&#95;&#95;&#40;&#40;&#95;&#95;packed&#95;&#95;&#41;&#41;;  
typedef struct Test2 Test&#95;2;  
Result:<br />
sizeof&#40;Tes1&#41; = 6<br />
sizeof&#40;Test&#95;2&#41; = 4
