On an MP3 application, I have the following task:  
void vFADERTask &#40;void&#42; pvParameters&#41;<br />
&#123;<br />
char STEP;<br />
for &#40;STEP=0; &#40;STEP&lt;32&#41; &amp;&amp; &#40;SYSFLAGS&#40;SS&#95;FLAG&#95;PLAYING&#41;&#41;; STEP++&#41; &#123;<br />
wrsta&#40;0x46,STEP&#41;;<br />
wrsta&#40;0x48,STEP&#41;;<br />
vTaskDelay&#40;60 / portTICK&#95;RATE&#95;MS&#41;;<br />
&#125;  
if &#40;SYSFLAGS&#40;SS&#95;FLAG&#95;PLAYING&#41;&#41; SYSFLAGS&#40;SS&#95;FLAG&#95;ABORTPLAY&#41;=1;<br />
FADERTaskHandle = NULL;<br />
vTaskDelete&#40;NULL&#41;;  
&#125;  
and, in another part of the program:  
//create the Fader Task<br />
if &#40;FaderTaskHandle==NULL&#41; &#123;<br />
if &#40;xTaskCreate&#40; vFADERTask, &#40;signed portCHAR&#42;&#41; &#8220;Fader&#8221;, 64, NULL, 2, &amp;FaderTaskHandle&#41; &#33;= pdTRUE&#41; DEBUG&#95;PRINT&#40;&#8221;CANT CREATE TASK&#33;&#33;&#33;&#8221;&#41;;<br />
&#125; else &#123;<br />
DEBUG&#95;PRINT&#40;&#8221;Fader task running&#33;&#8221;&#41;;<br />
&#125;  
Here&#8217;s what happens:  
It&#8217;s working fine, until I call it for aproximately 10 times…&#40;plenty of time before each call, so no overlaps&#41;<br />
Then the code to create the task returns &#33;= pdTRUE… as there are no resources available  
Do I have to clean up anything beyond calling vTaskDelete ?  
another &#8216;parallel&#8217; thing I noticed is that the Task Handle does not get NULLed by TaskDelete, so I had do it manually &#40;is this a potential problem? so the task could be created before actually deleted ?&#41;  
Thank you very much&#33;<br />
Sergio P. Sider
</div></div><div class="thread-post"><h3 class="thread-post-title">resource wasted on task delete and create</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/edwards3">edwards3</a> on January 15, 2010</div><div class="thread-post-content">Is the idle task getting any time to execute? The idle task frees up some of the resources after a task delete.
</div></div><div class="thread-post"><h3 class="thread-post-title">resource wasted on task delete and create</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/sergiosider">sergiosider</a> on January 15, 2010</div><div class="thread-post-content">Yes… in my case, it&#8217;s fading out a music that is playing… I was commanding with the keyboard to fade out a music at a time.. so there is plenty of time in theory…
</div></div><div class="thread-post"><h3 class="thread-post-title">resource wasted on task delete and create</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/sergiosider">sergiosider</a> on January 15, 2010</div><div class="thread-post-content">Well, I think I may have found the problem, although did not test it:  
I am not letting the Idle task run…. because all of my other task are higher priority and not all uses a taskdelay, only taskYIELD or not at all… so if I understood it, if I not call a vTaskDelay inside a higher priority task or something like that, the idle task never gets a chance to run… is that correct ?  
</div></div><div class="thread-post"><h3 class="thread-post-title">resource wasted on task delete and create</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on January 15, 2010</div><div class="thread-post-content">Just calling taskYIELD will not let any lower priority tasks run &#40;so depending on your task setup, more than the Idle task might get starved&#41;. You don&#8217;t need to use just vTaskDelay, a wait on a Queue &#40;including semaphores and Mutexs&#41; with a non-zero max delay parameter can also give time to lower priority tasks &#40;assuming the task at least sometime gets to the Queue when it isn&#8217;t ready&#41;. A task that is designed to use &#8220;All remaining available CPU bandwidth&#8221; needs to be at the lowest priority that needs to be run.
</div></div><div class="thread-post"><h3 class="thread-post-title">resource wasted on task delete and create</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on January 15, 2010</div><div class="thread-post-content">A second comment, If you are going to be creating and deleting this task multiple times, and each creation will be doing the same thing, and you don&#8217;t need a variable number of them at once &#40;which looks like it fits this case&#41;, it may be better to create the task once, and have it wait for a semaphore to tell it to start, it does its stuff, and then goes back, reinitialize itself and waits on the semaphore again.
</div></div><div class="thread-post"><h3 class="thread-post-title">resource wasted on task delete and create</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/sergiosider">sergiosider</a> on January 16, 2010</div><div class="thread-post-content">Thanks Richard…<br />
I wasn&#8217;t letting the idle task run at all… one of my tasks was using taskYIELD only, and other was nothing at all… &#40;the remaining tasks were ok, either using mutexes/semaphores and delays&#41;.  
I actually implemented the &#8220;problematic&#8221; task in a run once task with semaphore &#40;as you suggested&#41;.  
Thanks again&#33;<br />
Sergio.
