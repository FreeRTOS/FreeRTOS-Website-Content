</div></div><div class="thread-post"><h3 class="thread-post-title">compiler warning in tasks.c</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/kevinroland">kevinroland</a> on September 21, 2010</div><div class="thread-post-content">I made the following change to tasks.c.&nbsp; It preserves the &#8220;unsigned long&#8221; type used by the code.&nbsp; &#40;Alternatively, I think &#8220;unsigned long&#8221; could be replace by uintptr&#95;t if you rely on the C99 standard.&#41;  
<pre><code>&lt;somewhere near top of file&gt;
/*
 * Union to allow application of alignment mask to "top of stack"
 * pointer without compiler warnings.
 */
typedef union topOfStackConversion
{
    portSTACK_TYPE *pxTopOfStack;
    unsigned long ulTopOfStack;
} topOfStackConv;
&lt;inside of xTaskGenericCreate&gt;
topOfStackConv xTopOfStack;
...
#if( portSTACK_GROWTH &lt; 0 )
{
    xTopOfStack.pxTopOfStack = pxNewTCB-&gt;pxStack + ( usStackDepth - 1 );
    xTopOfStack.ulTopOfStack &amp;= ( unsigned long ) ~portBYTE_ALIGNMENT_MASK;
    pxTopOfStack = xTopOfStack.pxTopOfStack;
}
#else
</code></pre>
Reference:<a href="https://www.securecoding.cert.org/confluence/display/cplusplus/INT11-A.%2BTake%2Bcare%2Bwhen%2Bconverting%2Bfrom%2Bpointer%2Bto%2Binteger%2Bor%2Binteger%2Bto%2Bpointer">https://www.securecoding.cert.org/confluence/display/cplusplus/INT11-A.+Take+care+when+converting+from+pointer+to+integer+or+integer+to+pointer</a>
</div></div><div class="thread-post"><h3 class="thread-post-title">compiler warning in tasks.c</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/kevinroland">kevinroland</a> on September 21, 2010</div><div class="thread-post-content">I should add that I only tested this with the AVR GCC tools for an ATxmega128A1.&nbsp; I did a brief search, but other than my original reference, I did not find any guarantees about the alignment of the different types in the union.&nbsp; I don&#8217;t suggest you blindly use this without testing it on your specific platform.
