I need to get UDP running on a Zynq processor with the FreeRTOS. I have been working on trying to get the +TCP Zynq port up and running. I appreciate you sending us the Zynq port before it is actually
posted, the network stack is something we need to get tested and running.
The code has been integrated in 3 steps: 
1) Update the OS from 8.0.0 to 8.2.1
2) Pull in the +TCP/IP files, source and includes, but not the low level
<em>emac</em> files
3) Pull in the <em>emac</em> files
Step one seems to have gone OK, for the most part our application is still
running as expected. The version was upgraded by copying over the FreeRTOS files you emailed to replace the version 8.0.0 that was running here. Step two took a little more work due to the amount of files and some naming conventions. I think this is working, and with stubbed out network interface functions that the stack will initialize. The third step is where it comes apart. It seems that at the lowest level there has been a lot of good work done to enhance the functions themselves, as well as renaming of
variables/functions. There is also some dependency on other projects such as
the FAT etc. It quickly became difficult to get it working.
Another approach was to upgrade the version to 8.2.1, use the +UDP
stack that comes with 8.2.1, and take the network interface and low level
<em>emac</em> files from the drop you emailed. That had its own set of issues,
especially in the buffer_management.c files. Again it was a lot of reworked
functions etc.
Note that the heap_4.c was used when required.
Unfortunately for us the demo you provided can&#8217;t be opened here. There is
some tooling (SDK) problem. The SDK actually crashes when trying to build
the demo. So it seemed a good path to integrate the + code into an existing
project that is running.
The UDP functionally is actually all that is needed, I&#8217;m wondering if you
see an easier way to achieve this? Perhaps the approach being taken is not
the best one, can you provide input? I know the +TCP/IP Zynq port is still
in the lab, do you have some estimate of when it might be released? Do you
see a more clean way to proceed on getting the FreeRTOS with a UDP stack
running? 
Thank you
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS with UDP stack</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on August 14, 2015</div><div class="thread-post-content"><blockquote>
  The version was upgraded by copying over the FreeRTOS files you emailed to replace the version 8.0.0 that was running here
</blockquote>
That should be fine.
<blockquote>
  Step two took a little more work due to the amount of files and some naming conventions. 
</blockquote>
The easiest way of doing this is to simply open the project that was sent, as that is already correctly configured and contains the correct files, include paths etc. . . . but:
<blockquote>
  Unfortunately for us the demo you provided can&#8217;t be opened here. 
</blockquote>
Which version of the SDK are you using?  2015.2 is required, and is freely available from the Xilinx website.
<blockquote>
  It seems that at the lowest level there has been a lot of good work done to enhance the functions themselves, as well as renaming of variables/functions
</blockquote>
The project uses (references) a BSP project that is generated by the SDK.  None of the files in the BSP project have been edited.  Some of the files have however been copied into the driver layer, and edited there.  The versions in the driver layer are then used by the compiler, instead of the versions in the BSP project, as C will only bring functions out of a library if they are not used anywhere else.  There should not be any dependencies on the FAT code in the TCP driver code.
<blockquote>
  Another approach was to upgrade the version to 8.2.1, use the +UDP
  stack that comes with 8.2.1, and take the network interface and low level
  emac files from the drop you emailed
</blockquote>
I think that would be harder, as the interface will not be the same.
Regards.

</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS with UDP stack</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on August 19, 2015</div><div class="thread-post-content">How are you running the application?  Standalone, or through the 
debugger.  As delivered it expects to be executed through the debugger &#8211; 
so downloaded and started using a launch configuration in the SDK.
The debugger launch configuration should be set to run the ps7<em>init &#8211; 
you will see a check box for this on the &#8220;Target Setup&#8221; tab of the 
launch configuration.  It is also best to ensure the Reset Entire System 
check box is also checked.  If you run it standalone it will be 
necessary to call ps7</em>init() manually from the compiled code.
The documentation for this will be online soon &#8211; it was written some 
time back.
