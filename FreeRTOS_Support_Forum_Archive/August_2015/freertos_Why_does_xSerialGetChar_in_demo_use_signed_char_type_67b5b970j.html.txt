  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Why does xSerialGetChar() in demo use &#8216;signed char&#8217; type?</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/dbuntin">dbuntin</a> on August 30, 2015</div><div class="thread-post-content">I&#8217;ve extended the serial.c and serial.h files from the demo application to facilitate writing strings and debug information to the serial console in my application. I&#8217;m using snprintf() and similar library functions defined in stdio.h. These functions use parameters of type &#8221; char * &#8220;. When passing strings created by these functions to xSerialPutChar() and xSerialPutString() a must cast to a &#8221; signed char * &#8221; to avoid compiler warnings. Before I make any changes, I&#8217;d like to fully understand the types used and the reasons behind them.
Why does xSerialPutChar() use a signed char in it&#8217;s prototype?
signed portBASE<em>TYPE xSerialPutChar( xComPortHandle pxPort, <strong>signed char</strong> cOutChar, TickType</em>t xBlockTime );
I&#8217;m also not sure I understand the full meaning of the parameter type &#8220;const signed char * const pcString&#8221; used in xSerialPutString. Could someone help me interpret this type and the use of const twice?
void vSerialPutString( xComPortHandle pxPort, **const signed char * const **pcString, unsigned short usStringLength );
Background: I&#8217;ve created my application based on the AVR<em>ATMege323</em>WinAVR demo applicaiton. I&#8217;m using AVR Studio and it&#8217;s native GCC complier.
Thanks,
David
</div></div><div class="thread-post"><h3 class="thread-post-title">Why does xSerialGetChar() in demo use &#8216;signed char&#8217; type?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on August 30, 2015</div><div class="thread-post-content">You are looking at quite an old file.  For portability, the original coding standard did not allow unqualified char types (without the signed or unsigned qualifier) because some compilers default char types to signed and some to unsigned.  That has since been relaxed to allow unqualified char types <strong>if</strong> the char is an ascii character or pointing to a string of ascii characters.
<blockquote>
  I&#8217;m also not sure I understand the full meaning of the parameter type &#8220;const signed char * const pcString&#8221;
</blockquote>
That is a C question, easy to look up in any C reference book or on the web &#8211; we like to keep questions on the forum specific to FreeRTOS as it is more valuable to FreeRTOS users that way &#8211; there are plenty of general embedded programming forums [the answer in this case is that the type is a const pointer to a const string &#8211; neither the pointer, nor the string in points to, can be modified.]
