</div></div><div class="thread-post"><h3 class="thread-post-title">Arduino FreeRTOS code flip</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on January 1, 2019</div><div class="thread-post-content">I have no idea about Arduino, but from what I can see from your original post&#8230;.
The code that is is setup() can be code that appears in main() before the scheduler is started.
The code that is in loop can be added to a task that uses vTaskDelayUntil() (https://www.freertos.org/vtaskdelayuntil.html ) to control the period of its execution &#8211; unless delay(1) is very short, in which just run the task at the idle priority so it doesn&#8217;t starve out higher priority tasks and call vTaskDelay( 1 ) instead of vTaskDelayUntil().
In your second post you added a couple of extra delays around the call to map() &#8211; not sure why, but if you are waiting for the map() operation to complete, then it would be better to block on an event primitive, such as a direct to task notification, so the delay is exactly as long as the operation takes rather than choosing an arbitrary block time (https://www.freertos.org/RTOS-task-notifications.html ).
