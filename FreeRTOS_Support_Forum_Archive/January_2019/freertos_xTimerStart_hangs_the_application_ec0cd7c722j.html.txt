  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">xTimerStart hangs the application</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/freertos99">freertos99</a> on January 22, 2019</div><div class="thread-post-content">Hi Experts,
I have an application run on freertosv10.1 which creates five timers using xTimerCreate() with different timeout periods. After expiry of each timer the callbacks print a message and again start the timer. Four timers are working perfectly but 5th timer calls the callback once after expiry and hangs after the start of the timer. I&#8217;ve run out of ideas on how to debug this issue. Can anyone please help ?
~~~
<h1>define PERIOD<em>MS ( 1000UL / portTICK</em>RATE_MS)</h1>
static TimerHandle<em>t xApp[10] = {NULL};
void timer</em>start(int p)
{
    switch(p)
    {
    case 1:
    xTimerStart(xApp[1], 0);
    break;
    case 2:
    xTimerStart(xApp[2], 0);
    break;
    case 3:
    xTimerStart(xApp[3], 0);
    break;
    case 4:
    xTimerStart(xApp[4], 0);
    break;
    case 5:
    xTimerStart(xApp[5], 0);
    break;
    default:
    break;
    }
}
static void TimerCallback( TimerHandle<em>t xTimer )
{
    int i=0;
    i = ( int ) pvTimerGetTimerID( xTimer );
    printf(&#8220;Inside timer callbackrn&#8221;);
    timer</em>start(i);
}
void init<em>timer(void)
{
int i;
//create timers
for(i=1;i&lt;6;i++)
{
xApp[i] = xTimerCreate(&#8220;AppTimer&#8221;, (PERIOD</em>MS+ (100<em>i)), pdFALSE, (void</em>) i, TimerCallback);
}
//start timers
for(i=1;i&lt;6;i++)
timer_start(i);
}
FreeRTOSConfig.h
<h1>define configUSE_TIMERS                                                1</h1>
<h1>define configTIMER<em>TASK</em>PRIORITY                               ( 3 )</h1>
<h1>define configTIMER<em>QUEUE</em>LENGTH                                10</h1>
<h1>define configTIMER<em>TASK</em>STACK<em>DEPTH                    ( configMINIMAL</em>STACK_SIZE  )</h1>
~~~
</div></div><div class="thread-post"><h3 class="thread-post-title">xTimerStart hangs the application</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on January 22, 2019</div><div class="thread-post-content">One possible issue is that timer callbacks aren&#8217;t supposed to block, and depending on how printf is implemented, it might not be suitable for use in a timer callback.
If you use a debugger to stop the system, (and have configASSERT defined) does it show you caught on an assert, and if so which one?
</div></div><div class="thread-post"><h3 class="thread-post-title">xTimerStart hangs the application</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/freertos99">freertos99</a> on January 23, 2019</div><div class="thread-post-content">Thanks for pointer.
You are right.. the problem was due to printf&#8217;s in callback routine. Now I can see the timer getting started. Maybe we can document that timer callbacks should not be blocked (as a NOTE) or maybe this is basic thing which I&#8217;m not aware of 🙁 
Thank you.
</div></div><div class="thread-post"><h3 class="thread-post-title">xTimerStart hangs the application</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/xz8987f">xz8987f</a> on January 23, 2019</div><div class="thread-post-content">See https://www.freertos.org/RTOS-software-timer.html:
&#8220;Important information on writing timer callback functions
Timer callback functions execute in the context of the timer service task. It is therefore essential that timer callback functions never attempt to block. For example, a timer callback function must not call vTaskDelay(), vTaskDelayUntil(), or specify a non zero block time when accessing a queue or a semaphore. &#8221;
