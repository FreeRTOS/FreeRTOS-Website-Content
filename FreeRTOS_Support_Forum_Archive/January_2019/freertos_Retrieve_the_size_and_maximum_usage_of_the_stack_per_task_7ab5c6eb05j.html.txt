  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Retrieve the size and maximum usage of the stack per task</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/mastupristi">mastupristi</a> on January 30, 2019</div><div class="thread-post-content">For reasons related to debugging our application we use the function <code>uxTaskGetSystemState()</code>. It populates a vector of structures <code>TaskStatus_t</code>. In this structure is also present the field <code>usStackHighWaterMark</code>, whose comment says:
<blockquote>
  / * The minimum amount of stack space that has remained for the task since the task was created.  The closer this value is to zero the closer the task has come to overflowing its stack. * /
</blockquote>
For the same reasons of debugging, we also need to know the size of the stack, and the maximum usage percentage of it. 
How can I get this information with the functions and structures available?
best regards
Max
</div></div><div class="thread-post"><h3 class="thread-post-title">Retrieve the size and maximum usage of the stack per task</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on January 30, 2019</div><div class="thread-post-content">If you set configRECORD<em>STACK</em>HIGH_ADDRESS to 1 in FreeRTOSConfig.h then 
the other end of the stack is also recorded in the task&#8217;s TCB &#8211; 
depending on which version of FreeRTOS you are using (its quite a new 
feature), but I don&#8217;t think there is a function to retrieve it so you 
would have to look in the TCB manually.
However, as the size of a task&#8217;s stack is defined by the application 
writer when the task is created I would suggest you already know the 
total size of the stack.
</div></div><div class="thread-post"><h3 class="thread-post-title">Retrieve the size and maximum usage of the stack per task</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/mastupristi">mastupristi</a> on January 30, 2019</div><div class="thread-post-content">It would be better if we could get the information from the process structures, because it&#8217;s true that I know the information when I create tasks, but it&#8217;s also true that in the moment in which the vector of <code>TaskStatus_t</code> is populated it&#8217;s difficult, if not impossible, to access such information.
However, I use version 10.0.1
</div></div><div class="thread-post"><h3 class="thread-post-title">Retrieve the size and maximum usage of the stack per task</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on January 30, 2019</div><div class="thread-post-content">If you look at the bottom of tasks.c you will see that, with the correct 
<h1>defines, you can insert your own code into tasks.c by providing header</h1>
files that are included into the c file directly.  That enables any 
extensions you want for your project without the need to edit the 
kernel&#8217;s source files.
</div></div><div class="thread-post"><h3 class="thread-post-title">Retrieve the size and maximum usage of the stack per task</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/mastupristi">mastupristi</a> on January 30, 2019</div><div class="thread-post-content">I did as you say, and I was successful, thank you.

</div></div><div class="thread-post"><h3 class="thread-post-title">Retrieve the size and maximum usage of the stack per task</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on January 30, 2019</div><div class="thread-post-content">It&#8217;s always nice when people share code, but you don&#8217;t have to.
</div></div><div class="thread-post"><h3 class="thread-post-title">Retrieve the size and maximum usage of the stack per task</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/mastupristi">mastupristi</a> on January 31, 2019</div><div class="thread-post-content">Here&#8217;s the patch. I tried to follow the FreeRTOS coding rules, but I&#8217;m not sure I did it all.
~~~
diff &#8211;git a/FW/amazon-freertos/lib/FreeRTOS/tasks.c b/FW/amazon-freertos/lib/FreeRTOS/tasks.c
index 20c3962..6393e8f 100644
&#8212; a/FW/amazon-freertos/lib/FreeRTOS/tasks.c
+++ b/FW/amazon-freertos/lib/FreeRTOS/tasks.c
@@ -5042,4 +5042,27 @@ when performing module tests). */
 #endif
+#if( ( FREERTOS<em>ADDITIONAL</em>FEATURE<em>TOTAL</em>STACK<em>API == 1 ) &amp;&amp; ( configRECORD</em>STACK<em>HIGH</em>ADDRESS == 1 ) )
+
+uint32<em>t uxTaskGetStackSize( TaskHandle</em>t xTask )
+{
+   uint32<em>t uxReturn;
+   TCB</em>t *pxTCB;
+
+   if( xTask != NULL )
+   {
+       pxTCB = ( TCB_t * ) xTask;
+       uxReturn = (pxTCB->pxEndOfStack &#8211; pxTCB->pxStack) * sizeof(StackType_t);
+   }
+   else
+   {
+       uxReturn = 0;
+   }
+
+   return uxReturn;
+}
+
+#endif
diff &#8211;git a/FW/amazon-freertos/lib/include/task.h b/FW/amazon-freertos/lib/include/task.h
index d53b4dd..2a36eef 100644
&#8212; a/FW/amazon-freertos/lib/include/task.h
+++ b/FW/amazon-freertos/lib/include/task.h
@@ -2359,6 +2359,12 @@ void *pvTaskIncrementMutexHeldCount( void ) PRIVILEGED_FUNCTION;
 void vTaskInternalSetTimeOutState( TimeOut_t * const pxTimeOut ) PRIVILEGED_FUNCTION;
+#if( ( FREERTOS<em>ADDITIONAL</em>FEATURE<em>TOTAL</em>STACK<em>API == 1 ) &amp;&amp; ( configRECORD</em>STACK<em>HIGH</em>ADDRESS == 1 ) )
+
+uint32<em>t uxTaskGetStackSize( TaskHandle</em>t xTask );
+
+#endif
+
 #ifdef __cplusplus
 }
 #endif
~~~
To enable this function is necessary that also the symbol <code>FREERTOS_ADDITIONAL_FEATURE_TOTAL_STACK_API</code> is defined to 1. I do it on the command line when I launch make.

Max
