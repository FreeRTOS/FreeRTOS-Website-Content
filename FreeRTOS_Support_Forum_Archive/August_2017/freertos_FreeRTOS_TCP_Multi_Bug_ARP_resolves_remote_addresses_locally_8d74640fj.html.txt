  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">FreeRTOS+TCP_Multi Bug: ARP resolves remote addresses locally</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/miclam">miclam</a> on August 11, 2017</div><div class="thread-post-content">Hello,
I&#8217;m currently testing the DNS client of +TCP<em>multi. When using 8.8.8.8 as DNS server I noticed, that eARPGetCacheEntry does not resolve unmatched remote ip addresses to the default gateway.
This is because FreeRTOS</em>FindEndPointOnNetMask returns either the correct EndPoint, or the default EndPoint, and only in case no default is set NULL.
eARPGetCacheEntry then checks by <code>if( pxEndPoint == NULL )</code> (Line 456 in FreeRTOS_ARP.c) if the default gateway should be used, which is never reached.
My idea was to let FreeRTOS<em>FindEndPointOnNetMask return NULL instead of the default EndPoint, and to explicitly call FreeRTOS</em>FindDefaultEndPoint wherever the default EndPoint is required. But FreeRTOS_FindEndPointOnNetMask is used in quiet a lot locations, I&#8217;m afraid of breaking something without knowing.
What do you think?
Many thanks,
Michael
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS+TCP_Multi Bug: ARP resolves remote addresses locally</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/miclam">miclam</a> on August 11, 2017</div><div class="thread-post-content">Hello,
as far as I can see commenting out <code>pxEndPoint = pxDefault;</code> in Line 375 in FreeRTOS<em>Routing.c and changing Line 2655 in FreeRTOS</em>IP.c and Line 195 in FreeRTOS<em>UDP</em>IP.c to
<pre><code>        pxNetworkBuffer-&gt;pxEndPoint = FreeRTOS_FindEndPointOnNetMask( pxIPPacket-&gt;xIPHeader.ulDestinationIPAddress, 7 );
        /* _ML_ Removed default EndPoint from FreeRTOS_FindEndPointOnNetMask, so get it here if needed. */
        if( pxNetworkBuffer-&gt;pxEndPoint == NULL )
        {
            pxNetworkBuffer-&gt;pxEndPoint = FreeRTOS_FindDefaultEndPoint();
        }
</code></pre>
works. The other occurences of FreeRTOS_FindEndPointOnNetMask seem to actually expect it not to return the default gateway.
Regards,
Michael
