When I switch from Thumb mode to ARM mode, there are other errors:

Both modes don&#8217;t work! Do I need a different port? Or is FreeRTOS not working with this controller?

Sebastian
</div></div><div class="thread-post"><h3 class="thread-post-title">Port for Atmel SAM4SD32C</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on August 22, 2017</div><div class="thread-post-content"><blockquote>
  Hi
  I&#8217;m working for the first time with FreeRTOS using a testboard from 
  Atmel (ATSAM4S-XPRO) with the ARM processor SAM4SD32C (Atmel Studio 7.0, 
  FreeRTOS 9.0)
  http://www.microchip.com/DevelopmentTools/ProductDetails.aspx?PartNO=ATSAM4S-XPRO
</blockquote>
If that part has a floating point unit then use the port layer in 
FreeRTOS/Source/portable/GCC/ARM<em>CM4F, otherwise use the port layer in 
FreeRTOS/Source/portable/GCC/ARM</em>CM3 (even though it is an M4 part).
<blockquote>
  When I switch from Thumb mode to ARM mode, there are other errors:
  http://imgur.com/hroRLnN
</blockquote>
That part does not have an ARM mode, just THUMB2.
</div></div><div class="thread-post"><h3 class="thread-post-title">Port for Atmel SAM4SD32C</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/sircorono">sircorono</a> on August 23, 2017</div><div class="thread-post-content">Hi
According to this page, the controller has a FPU:
http://www.microchip.com/wwwproducts/en/ATSAM4SD32C
However, the ARM_CM4F port does not work:
http://imgur.com/iPWuD3T
But the ARM_CM3 works, thanks for the help. I didn&#8217;t try this because I have a Cortex M4.
Sebastian
</div></div><div class="thread-post"><h3 class="thread-post-title">Port for Atmel SAM4SD32C</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on August 23, 2017</div><div class="thread-post-content"> From the screenshot you provided I can see that you are not using the 
correct compiler settings.  If you tell the compiler you don&#8217;t have a 
floating point unit then it will not allow floating point instructions. 
Double check the compiler settings to ensure you both specify that 
hardware floating point is present, and which hardware floating point 
unit the device has &#8211; these must be on the command line sent to the 
compiler.
</div></div><div class="thread-post"><h3 class="thread-post-title">Port for Atmel SAM4SD32C</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/sircorono">sircorono</a> on August 24, 2017</div><div class="thread-post-content">Hi
Found it here:
http://www.atmel.com/Images/Atmel-42144-SAM4E-FPU-and-CMSIS-DSP-Library<em>AP-Note</em>AT03157.pdf
 -mfpu=fpv4-sp-d16 -mfloat-abi=softfp was missing.
 Thanks for the help.
