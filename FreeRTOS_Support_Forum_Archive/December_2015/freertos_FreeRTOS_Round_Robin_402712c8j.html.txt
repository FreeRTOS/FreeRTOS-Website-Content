  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">FreeRTOS Round Robin</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/cdb1702">cdb1702</a> on December 7, 2015</div><div class="thread-post-content">What are ,in the source code of FreeRTOS.the functions that make the round robin in the case of tasks with the same priority?
The following example is taken from  USING THE FREERTOS REAL TIME KERNEL A Practical Guide
Richard Barry
void vTaskFunction( void <em>pvParameters )
{
char *pcTaskName;
volatile unsigned long ul;
/</em> The string to print out is passed in via the parameter. Cast this to a
character pointer. <em>/
pcTaskName = ( char * ) pvParameters;
/</em> As per most tasks, this task is implemented in an infinite loop. <em>/
for( ;; )
{
/</em> Print out the name of this task. <em>/
vPrintString( pcTaskName );
/</em> Delay for a period. <em>/
for( ul = 0; ul &lt; mainDELAY_LOOP_COUNT; ul++ )
{
/</em> This loop is just a very crude delay implementation. There is
nothing to do in here. Later exercises will replace this crude
loop with a proper delay/sleep function. <em>/
}
}
}
/</em> Define the strings that will be passed in as the task parameters. These are
defined const and not on the stack to ensure they remain valid when the tasks are
executing. <em>/
static const char *pcTextForTask1 = “Task 1 is runningrn”;
static const char *pcTextForTask2 = “Task 2 is runningtn”;
int main( void )
{
/</em> Create one of the two tasks. <em>/
xTaskCreate( vTaskFunction, /</em> Pointer to the function that implements
the task. <em>/
&#8220;Task 1&#8221;, /</em> Text name for the task. This is to
facilitate debugging only. <em>/
1000, /</em> Stack depth &#8211; most small microcontrollers
will use much less stack than this. <em>/
(void</em>)pcTextForTask1, /* Pass the text to be printed into the task
using the task parameter. <em>/
1, /</em> This task will run at priority 1. <em>/
NULL ); /</em> We are not using the task handle. <em>/
/</em> Create the other task in exactly the same way. Note this time that multiple
tasks are being created from the SAME task implementation (vTaskFunction). Only
the value passed in the parameter is different. Two instances of the same
task are being created. <em>/
xTaskCreate( vTaskFunction, &#8220;Task 2&#8221;, 1000, (void</em>)pcTextForTask2, 1, NULL );
/* Start the scheduler so our tasks start executing. <em>/
vTaskStartScheduler();
/</em> If all is well then main() will never reach here as the scheduler will
now be running the tasks. If main() does reach here then it is likely that
there was insufficient heap memory available for the idle task to be created.
CHAPTER 5 provides more information on memory management. */
for( ;; );
}
