  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">osDelay() when the Tickless Idle Mode of FreeRTOS</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/masahoshi">masahoshi</a> on December 9, 2015</div><div class="thread-post-content">I am trying to use the tickless idle mode using FreeRTOS 8.2.1 on STM32L476G-Discovery.
I am using a task which is blinking the LED for eacxNextTaskUnblockTime of prvGetExpectedIdleTime() was portMAX<em>DELAY, when pass a value to portSUPPRESS</em>TICKS<em>AND</em>SLEEP( xExpectedIdleTime ).
h 50ms, and want to confirm that if the action could be maintained in 50ms interval even in the tickless idle mode or not.
The action is confirmed good when release LowPower by Systick interrupt.
But when release LowPower by external interrupt, sometimes the action was not expected (means the action could not be maintained in 50ms interval) .
※ External interrupt is assigned the EXIT Line1 Interrupt to Left Botton of Joystick, press many times at irregular intervals.
I checked the output log via UART.
xNextTaskUnblockTime of prvGetExpectedIdleTime() was portMAX<em>DELAY, when pass a value to portSUPPRESS</em>TICKS<em>AND</em>SLEEP( xExpectedIdleTime ).
How can I keep the action in a 50ms interval when release LowPower by external interrupt?
</div></div><div class="thread-post"><h3 class="thread-post-title">osDelay() when the Tickless Idle Mode of FreeRTOS</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on December 9, 2015</div><div class="thread-post-content">If I understand you correctly, then when you use the default Cortex-M tickless idle mode then it is working as expected, but when you use the STM32L specific one you are getting the problem.  If my understanding is correct, are you using the STM32L specific implementation found in the FreeRTOS zip file download?
<blockquote>
  xNextTaskUnblockTime of prvGetExpectedIdleTime() was portMAX<em>DELAY, when pass a value to portSUPPRESS</em>TICKS<em>AND</em>SLEEP( xExpectedIdleTime ).
</blockquote>
The portMAX<em>DELAY value should be capped to the maximum possible sleep time (basically the time it takes for the timer to overflow) inside the suppress ticks and sleep function itself.  Is the problem that this should be less than or equal to 50ms, rather than portMAX</em>DELAY, before it is passed into the suppress ticks and sleep function?  Could you try V8.2.3 version, as some work was done there recently, although as I recall it was only to allow tickless idle when configUSE_PREEMPTION was 0 (which could not be done before).

void StartDefaultTask(void const * argument)
{

uint32_t  startTime, endTime;
/</em> Infinite loop <em>/
for(;;)
{
HAL_GPIO_TogglePin(GPIOB, GPIO_PIN_2);
startTime = osKernelSysTick();
osDelay(50);
endTime = osKernelSysTick();
printf(&#8220;intvl=%dnr&#8221;, endTime &#8211; startTime);
}
/</em> USER CODE END 5 */
}
・Add the following code to mxconstants.h.
*****#define PUTCHAR_PROTOTYPE int fputc(int ch, FILE *f)
