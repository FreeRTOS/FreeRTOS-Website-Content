  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">BUG found in FreeRTOS Kernel</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/kristofmulier">kristofmulier</a> on December 21, 2015</div><div class="thread-post-content">I have found a bug in the following function (from the &#8220;list.c&#8221; file in the Kernel):
~~~~
void vListInsertEnd(List<em>t * const pxList, ListItem</em>t * const pxNewListItem)
{
    ListItem_t * const pxIndex = pxList->pxIndex;
<pre><code>/*-----------------------------------------------*/
/* Integrity checks not used, code removed.      */
/*-----------------------------------------------*/
/* Insert a new list item into pxList, but rather than sort the list,
make the new list item the last item to be removed by a call to
listGET_OWNER_OF_NEXT_ENTRY(). */
pxNewListItem-&gt;pxNext = pxIndex;
pxNewListItem-&gt;pxPrevious = pxIndex-&gt;pxPrevious;
/* Only used during decision coverage testing. */
mtCOVERAGE_TEST_DELAY();
pxIndex-&gt;pxPrevious-&gt;pxNext = pxNewListItem;
pxIndex-&gt;pxPrevious = pxNewListItem;
/* Remember which list the item is in. */
pxNewListItem-&gt;pvContainer = (void *) pxList;
(pxList-&gt;uxNumberOfItems)++;
/* BUG FOUND                                                     */
/* The documentation for this function mentions: "Placing        */
/* an item in a list using vListInsertEnd(..) effectively        */
/* places the item in the list position pointed to by pvIndex."  */
/* I believe there are two bugs here:                            */
/* (1) The correct field name is not "pvIndex" but "pxIndex"     */
/*     (that's a documentation bug, so not really a big deal)    */
/* (2) The pxList-&gt;pxIndex does not point to the NewListItem!    */
/*     The following code line was forgotten:                    */
pxList-&gt;pxIndex = pxNewListItem;
</code></pre>
}
~~~~
Did anyone experience this bug?

</div></div><div class="thread-post"><h3 class="thread-post-title">BUG found in FreeRTOS Kernel</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/kristofmulier">kristofmulier</a> on December 21, 2015</div><div class="thread-post-content">Thank you very much for your quick reply 🙂
No, I did not see a misbehaviour. But I just figured out that the documentation mentions:
~~~~
/* The &#8220;pxIndex&#8221; from the List<em>t will point to the newly inserted ListItem</em>t , such that every other item within the list will be returned by listGET<em>OWNER</em>OF<em>NEXT</em>ENTRY(..) before the pxIndex parameter again points to the item being inserted. */
~~~~
Indeed, when you call the macro &#8220;listGET<em>OWNER</em>OF<em>NEXT</em>ENTRY(..)&#8221;, the pxIndex parameter from the list gets incremented first, such that it points to the &#8220;next entry&#8221; from which the owner is returned. So the documentation above makes perfectly sense.
Unfortunately, the documentation doesn&#8217;t correspond with the actual behaviour of the &#8220;vListInsertEnd(..)&#8221; function. This is because the following code line is forgotten (or at least, it looks to me like the developer forgot this line of code to update the pxIndex):
~~~~
pxList->pxIndex = pxNewListItem;
~~~~
That&#8217;s all 🙂
One more question: I noticed that some parts of the documentation mention the List_t to be in descending order, whereas other parts of the documentation state that it&#8217;s ascending order. So I&#8217;m a bit confused.
From the function:
~~~~
vListInsert( List<em>t * const pxList, ListItem</em>t * const pxNewListItem )
~~~~
I conclude that it is ascending order (from small to large). Is my conclusion correct?
Kind greetings 🙂
