  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">heap_4 uses more memory that heap_3</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/trob76">trob76</a> on December 18, 2015</div><div class="thread-post-content">I am integrating FreRTOS 8.2.2 into a legacy project. In addition, I am trying to incorporate TCP+ example code. The old coding used heap<em>3 for the heap model and the TCP+ requires heap</em>4. When I use heap<em>4 the build fails saying that the heap memory has overrun it size. I can only use half the size for heap that I need.
I am using arm</em>xilinx_eabi and an ARM9 in a ZYNQ. 
Why are the heap requirements so much more in the heap_4? Is there a way to use the same heap size?
</div></div><div class="thread-post"><h3 class="thread-post-title">heap_4 uses more memory that heap_3</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on December 18, 2015</div><div class="thread-post-content">There are no differences in the amount of heap required or used when switching from heap<em>3 to heap</em>4, the only difference is how the heap is allocated.  
When you use heap_3 the heap is allocated by the development tools, and does not form part of the data that is located by the linker, and so the linker does not take its size into account.  
When you use heap<em>4 the heap is basically a statically allocated array, which is located by the linker &#8211; and the linker has to fit it into its memory map.  The size of the array that is used as the heap is defined by the configTOTAL</em>HEAP_SIZE setting.
Remember that, when using heap_4, provided no other code is calling malloc directly, you can set the size of the heap allocated by the tools to as close to 0 as the tools will allow (normally 4 bytes).
See http://www.freertos.org/a00111.html for more details.
