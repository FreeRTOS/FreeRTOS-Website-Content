</div></div><div class="thread-post"><h3 class="thread-post-title">How can I porting lpc2129 demo to lpc2468 </h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on April 30, 2008</div><div class="thread-post-content">Hi Steve,
I just replied to your post on the LPC2000 group.&nbsp; For completeness I have posted the same reply below:
&gt; Here is my story. Download lpc2129 porting&#40;IAR IDE&#41; from freertos
&gt; websit. 
So you are starting with a working project.&nbsp; This is good as it means you will have the correct setup and things should compile straight off.&nbsp; However, it might be that you need to change the configuration of the timer that generates the RTOS tick, as it is likely to be a bit different on the 2468 compared to the 2129.
The timer configuration is contained in a function called prvSetupTimerInterrupt&#40;&#41; which can be found in port.c.&nbsp; For GCC there are two different versions, one can be found in SourceportableGCCARM7&#95;LPC2000port.c, and the other in SourceportableGCCARM7&#95;LPC23xxport.c.&nbsp; I have not checked the data sheet but it is likely that you will require the latter version.&nbsp; You can copy the changes from the referenced GCC version into your IAR files.
&gt; and demo board &#40;lpc2468&#41; from IAR too. Made a few changing:
&gt; 1. changed processor to lpc2468 option in IAR IDE setting.
&gt; 2. changed processor header file from lpc2129 to lpc2468
&gt; 3. notice there are some differenc in PLL area, made some 
&gt; changed there.
&gt; 
&gt; what I can run now:
&gt; 1. can turn LED on and off without OS start creat tasks.
That is encouraging, so there is a good chance that the linker script and processor configuration are good.
&gt; 2. afer running into OS code, has data or undefine abort.
&gt; 3. the abort happen after schedulor start.
Do you ever hit the first task?&nbsp; Put a break point at the beginning of the highest priority task to see if you ever reach it.&nbsp; If not then it is likely that the MCU is in the wrong mode when you start the scheduler.
Also check that the call to xTaskStartScheduler&#40;&#41; never returns, to do so would be indicative of having too smaller heap to allow the idle task to be created.
&gt; I am thinking that I am facing a configuraton problem. Have tried 
&gt; to modify code in startup.s and freertosconfig.h and others which
&gt; freertos suggest to take a look. Well, I am still no lucky to let
&gt; it running.
What did you change in startup.s?&nbsp; Can you check that the MCU is in Supervisor mode when main&#40;&#41; is called?&nbsp; This is the most likely cause of the problem.
Startup.s should also allocate stacks for IRQ mode, FIQ only if used, and Supervisor modes.&nbsp; If using the 2129 project as a base you should also setup the VIC to vector directly to an ISR handlers as well as making sure that the vPortYieldProcessor is installed as the SWI handler.&nbsp; If you are using the demo project startup file then this should all be done already.
Regards
