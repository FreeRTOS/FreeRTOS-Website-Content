  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">death test failure</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/yen2008">yen2008</a> on April 9, 2008</div><div class="thread-post-content">Hi, I have successfully ported FreeRTOS 4.7.1 on a microprocessor and all the demo are working.&nbsp; Recently, I have ported the same version of FreeRTOS to a different toolchain.&nbsp; The death test failed.&nbsp; It runs for a while &#40;vCreateTasks are created a few times&#41; and then crashes.&nbsp; I have increased substantially the stack size for the vCreateTasks &#40;3Kbytes&#41; and vSuicidalTask&#40;1Kbytes&#41; to determine if this could be stack overflow problem &#40;I have 23Kbytes of heap memory and this is the only test running&#41;.&nbsp; However, this does not seem to solve the problem.&nbsp; What are the other possible causes for the test to fail please?
</div></div><div class="thread-post"><h3 class="thread-post-title">death test failure</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on April 9, 2008</div><div class="thread-post-content">Which compiler are you using, and which heap file are you including in your project &#40;heap&#95;1.c, heap&#95;2.c or heap&#95;3.c&#41;?
</div></div><div class="thread-post"><h3 class="thread-post-title">death test failure</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/yen2008">yen2008</a> on April 9, 2008</div><div class="thread-post-content">I am using heap&#95;3.c. The compiler is GCC
</div></div><div class="thread-post"><h3 class="thread-post-title">death test failure</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on April 9, 2008</div><div class="thread-post-content">GCC libraries are huge so stack issues could be an issue &#8211; although you say you have increased it already.
configTOTAL&#95;HEAP&#95;SIZE has no effect when using heap&#95;3 so it could be that your linker script is not setting up a heap at all, or that the one it is setting up is very small.
Try switching to heap&#95;2.c, in which case configTOTAL&#95;HEAP&#95;SIZE does dimension the heap.
</div></div><div class="thread-post"><h3 class="thread-post-title">death test failure</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/yen2008">yen2008</a> on April 9, 2008</div><div class="thread-post-content">Hi, I have verified that the linker script is correctly setting up the amount of heap memory requested. This is done by doing a loop malloc&#8217;ing 1K of memory, and the counter returned did reflect the heap memory specified in the linker script.&nbsp; Anyway, I manage to run ALL the other demo tasks concurrently &#40;except &quot;death&quot; demo&#41;.&nbsp; Presumably this is sufficient to show the linker script is working.
I have looked further into this problem.&nbsp; It looks like the vSuicidalTask did not manage to kill and free the tasks stacks.&nbsp; Looking at the memory addresses allocated for the &quot;pxNewTCB&quot; and &quot;pxNewTCB-&gt;pxStack&quot; of each of the vSuicidalTask.&nbsp; The &quot;pxNewTCB-&gt;pxStack&quot; of &quot;SUICID1&quot; and the &quot;pxNewTCB&quot; &amp; &quot;pxNewTCB-&gt;pxStack&quot; of &quot;SUICID2&quot; are different each time these two tasks are created.&nbsp; The program crashes when the &quot;pxNewTCB-&gt;pxStack&quot; of &quot;SUICID1&quot; overlaps with the &quot;pxNewTCB&quot; of &quot;SUICID2&quot;.&nbsp; I am not sure what are the causes the task was not deleted?
</div></div><div class="thread-post"><h3 class="thread-post-title">death test failure</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/woops_">woops_</a> on April 9, 2008</div><div class="thread-post-content">Does the idle task ever run. It must run to free up the memory. Do you have any tasks running about the idle task that do not ever block.
