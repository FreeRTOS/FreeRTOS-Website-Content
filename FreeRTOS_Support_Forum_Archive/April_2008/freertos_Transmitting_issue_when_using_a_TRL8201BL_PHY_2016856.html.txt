irrelevant for your case.
1&#41; How did you understand that you can receive but unable to send? I mean do you use
UDP connection in the code? Do you check all with logic analyzer or do you use wireshark/ethereal?
2&#41; Have you checked is PHY id is correct in prvProbePHY function in SAM7&#95;EMAC.c?
3&#41; I don&#8217;t know how is your PHY is connected to the MAC but it may help to double check
PHY power down pin status. It is cleared in xEMACInit function. Some PHYs don&#8217;t have power down,
and hardware designers use it for other purposes but code assumes it to be used. This hit me once,
so I just wanted to warn on.
4&#41; Transformator pins of connector&#8217;s are different from vendor-to-vendor, sometimes. Not all PHYs work
with all&#40;As far as I remember&#41;. This may explain receive working but not transmitting&#40;this is also
related to the answer to 5&#41;
5&#41; Do you have any status leds on your board? Is negotiation correct?&#40;duplex, speed, link&#41;
I&#8217;m justing thinking loud, I hope they can help.

</div></div><div class="thread-post"><h3 class="thread-post-title">Transmitting issue when using a TRL8201BL PHY</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/maczor">maczor</a> on April 25, 2008</div><div class="thread-post-content">The easiest way to make sure things are working on the raw ethernet side of things, is to send a broadcast MAC packet..
You PC will see this in Wireshark/Ethereal if it is sent out onto the network because the router/switch/hub has to forward it to all devices on the local network.
A broadcast Ethernet packet has a destination address of FF:FF:FF:FF:FF:FF.&nbsp; So just make up a source mac address and specify a length for the packet, stick in some dummy data up to that length and send the packet.
You could try sending it repeatedly in case it doesn&#8217;t send properly the first time and you should see it at the PC&#8230;
If you&#8217;re using a hub/switch you should also see the activity light changing if you are repeatedly sending data..
One thing worth checking is that your bias circuit is correct on the transmit side &#40;the 50 ohm resistor network&#41;.&nbsp; Just double check this again with the reference circuit to make sure that you&#8217;re connecting it exactly as in the reference.
