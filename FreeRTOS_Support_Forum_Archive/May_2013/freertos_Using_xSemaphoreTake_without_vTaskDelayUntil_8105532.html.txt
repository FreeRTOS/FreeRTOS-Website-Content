  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Using xSemaphoreTake without vTaskDelayUntil</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/dilirious">dilirious</a> on May 8, 2013</div><div class="thread-post-content">I am using FreeRTOS Ver 7.1.0.<br />
Does xSemaphoreTake&#40;&#41; allow other tasks to run if the task its being called from does not use vTaskDelayUntil&#40;&#41;?<br />
It doesnt appear to.&nbsp; No other tasks will run.&nbsp; I have a high priority task that needs to run and handle I2C traffic, this tasks needs to delay little as possible, &lt; 2 msec.&nbsp; There are other, lower priority threads that need to run as well.&nbsp; I was hoping that these other threads would get a chance to run during xSemaphoreTake&#40;&#41; but they dont unless I use vTaskDelayUntil&#40;&#41;.&nbsp;&nbsp;<br />
Thanks  
</div></div><div class="thread-post"><h3 class="thread-post-title">Using xSemaphoreTake without vTaskDelayUntil</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on May 8, 2013</div><div class="thread-post-content">If you specify a block time in your call to xSemaphoreTake&#40;&#41; and the semaphore is not available then the calling task will block and let lower priority tasks run just as if you had called vTaskDelayUntil&#40;&#41;. If the semaphore is always there when you call xSemaphoreTake&#40;&#41; then the the call to xSemaphoreTake&#40;&#41; will always return immediately and the calling task will not block and starve lower priority tasks of CPU time.
</div></div><div class="thread-post"><h3 class="thread-post-title">Using xSemaphoreTake without vTaskDelayUntil</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/dilirious">dilirious</a> on May 8, 2013</div><div class="thread-post-content">There must be something I am missing then.&nbsp; I block indefinitely when I call xSemaphoreTake&#40;&#41; with portMAX&#95;DELAY.<br />
I know there are 4 msec periods of time where other low priority tasks should run but they never get called unless I am using vTaskDelayUntil&#40;&#41; in my high priority thread that calls xSemaphoreTake&#40;&#41;.&nbsp;<br />
Right now I just have one other task that blinks an LED every 75 msec.&nbsp; It is easy to see this thread never gets called.<br />
Is there anything else I should be doing?<br />
Thanks.
</div></div><div class="thread-post"><h3 class="thread-post-title">Using xSemaphoreTake without vTaskDelayUntil</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/dilirious">dilirious</a> on May 8, 2013</div><div class="thread-post-content">Let me clarify.&nbsp; There are times where xSemaphoreTake&#40;&#41;&nbsp; is called and there will not be an interrupt giving the semaphore back for 4 msec.&nbsp; This is when I expect my LED blink task to run.
</div></div><div class="thread-post"><h3 class="thread-post-title">Using xSemaphoreTake without vTaskDelayUntil</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on May 8, 2013</div><div class="thread-post-content">If you are absolutely sure that the task taking the semaphore does block for up to 4ms at a time, then other tasks should run during those 4ms. You can verify that what you think is happening is actually happening by using the FreeRTOS+Trace tool. As a quick and dirty you can call xTaskGetTickCount&#40;&#41; before calling xSemaphoreTake&#40;&#41;, and then again after calling xSemaphoreTake&#40;&#41;, and check that the difference between the two readings is sometimes greater than 1 &#40;indicating that it was blocked for at least one tick period&#41;.  
What is configTICK&#95;RATE&#95;HZ set to?<br />
Are you sure your other tasks are running as you expect when the task that calls xSemaphoreTake&#40;&#41; is not created?<br />
Is the timing of your system about what would be expected for your configuration &#8211; so if you only create the LED blink task does the LED blink at the rate you specify?
</div></div><div class="thread-post"><h3 class="thread-post-title">Using xSemaphoreTake without vTaskDelayUntil</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/dilirious">dilirious</a> on May 8, 2013</div><div class="thread-post-content">You are correct, xSemaphoreTake&#40;&#41; would get the semaphore right away due the fact I was enabling the I2C interrupt right before this call and never clearing the interrupt so it would fire right away.&nbsp;<br />
Thanks for the help.
