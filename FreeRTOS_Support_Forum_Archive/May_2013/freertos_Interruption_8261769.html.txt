</div></div><div class="thread-post"><h3 class="thread-post-title">Interruption</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on May 23, 2013</div><div class="thread-post-content">How an interrupt is generated is completely dependent on the hardware, not the RTOS.&nbsp; You don&#8217;t say as much but it looks from your code that you are using the STM32 libraries.  
Test your interrupt generation code without the RTOS first.&nbsp; You can use the libraries to configure the interrupt, then sit in a while&#40;1&#41; loop with a break point in the interrupt handler to ensure the interrupt triggers when you expect.&nbsp; Once you know the interrupt is working you can add the code to a working FreeRTOS project.  
As you are using FreeRTOS I assume you want the task to handle the LED, rather than doing it directly in the interrupt.&nbsp; If that is the case then you need to ensure the priority of the interrupt is less then configMAX&#95;LIBRARY&#95;SYSCALL&#95;INTERRUPT&#95;PRIORITY, and that all the STM32 priority bits are assigned as preemption priority bits, not sub-priority bits.&nbsp; This is explained on this page:<br />
<a href="http://www.freertos.org/RTOS-Cortex-M3-M4.html">http://www.freertos.org/RTOS-Cortex-M3-M4.html</a>  
You then need to signal the task from the interrupt.&nbsp; The most common way of doing that is using a semaphore.&nbsp; See the function vTaskApplicationTickHook&#40;&#41; on <a href="http://www.freertos.org/Hardware-independent-RTOS-example.html">http://www.freertos.org/Hardware-independent-RTOS-example.html</a> to see how a semaphore is given from an interrupt &#40;the tick hook function in the example is called from an interrupt&#41; and prvEventSemaphoreTask&#40;&#41; on the same page to see how a semaphore is used to synchronise with the interrupt.&nbsp; The API documentation on the website and demos in the FreeRTOS download will show you how to context switch from the ISR.  
Regards.
