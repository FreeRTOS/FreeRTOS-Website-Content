  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Non Blocking Task wont Give CPU To a Periodic</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/krnl386">krnl386</a> on May 10, 2013</div><div class="thread-post-content">I am Currently Evaluating The FreeRTOS Kernel on an LPCXpresso LPC1114 EVB , Created two tasks ,<br />
a non blocking one using the small printf lib to print out some string and the other is a periodic Task using the vTaskDelayUntil&#40;&amp;xTimeUpdate, &#40;500/portTICK&#95;RATE&#95;MS&#41;&#41; API to have a sharp 500ms Delay , with a priority higher than the non-Blocking one , the Result is having the Periodic Task Executing Once and Leaving THE CPU for the non-Blocking Task forever ,this problem also occurs when using the vTaskDelay&#40;&#41; API , I know that this problem may seem silly but im really stuck Please Help &#33;&#33;
</div></div><div class="thread-post"><h3 class="thread-post-title">Non Blocking Task wont Give CPU To a Periodic</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on May 11, 2013</div><div class="thread-post-content">The two most likely causes are<br />
1&#41; You have preemption turned off, thus the &#8220;non-blocking&#8221; task will never give up the processor unless you add a yield to the loop.  
2&#41; Your timer tick interrupt isn&#8217;t working for some reason.  
You can check the first by adding the yield.<br />
The second by seeing if the tick counter is increasing.
</div></div><div class="thread-post"><h3 class="thread-post-title">Non Blocking Task wont Give CPU To a Periodic</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/krnl386">krnl386</a> on May 11, 2013</div><div class="thread-post-content">&#45; Preemtion is turned on , and working with Blocking Tasks Normally<br />
&#45; xTickCount does increment during Runtime , but increments slowly , it Should Reach 1000 Tick within 1 Second But That Does Not Happen   
Any Advice?
</div></div><div class="thread-post"><h3 class="thread-post-title">Non Blocking Task wont Give CPU To a Periodic</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on May 11, 2013</div><div class="thread-post-content"><blockquote>
  Any Advice?
</blockquote>
Start by ensuring the tick interrupt is executing at the expected frequency before adding in any additional functionality.&nbsp; You could leave your code as it is, and add in a <a href="http://www.freertos.org/a00016.html">tick hook function</a> function that just toggles an IO port.&nbsp; Check the frequency at which the IO port toggles matches that expected according to your configTICK&#95;RATE&#95;HZ and configCPU&#95;CLOCK&#95;HZ settings in FreeRTOSConfig.h.&nbsp; Once you have the frequency correct you can then return to look at what your application is actually doing.  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">Non Blocking Task wont Give CPU To a Periodic</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/krnl386">krnl386</a> on May 11, 2013</div><div class="thread-post-content">&#45; Downloaded NXPs FreeRTOS Example ,<br />
&#45; Experimented the xTickCount Found it incrementing by 1000 Persecond with a CLK Frequency 48000000<br />
&#45; Changed the Tick Frequency found Everything Going fine With Port 0 Pin 7 Led Toggling Frequency<br />
&#45; Switched Off Tick Hook Function&nbsp; , usedThe HeartBeating Task&nbsp; WITH NO BLOCKING And Made Another&nbsp; Led Toggling Task With A Higher Priority and a &#40;configTICK&#95;RATE&#95;HZ / 2 &#41; Delay   
Result is : xTickCount Increments 1 every Second , Higher Priority Task Runs Once and the HeartBeat Task Running Forever Not Giving UP CPU 
</div></div><div class="thread-post"><h3 class="thread-post-title">Non Blocking Task wont Give CPU To a Periodic</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/krnl386">krnl386</a> on May 11, 2013</div><div class="thread-post-content">using the NXP Example removed all tasks and left the HeartBeat Task and removed the vTaskDelay Blocking function to see the Task Behavior when being continuous ,&nbsp; Found That the xTickCount Drops down its rate per second without touching the configuration file&nbsp; .
</div></div><div class="thread-post"><h3 class="thread-post-title">Non Blocking Task wont Give CPU To a Periodic</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on May 11, 2013</div><div class="thread-post-content">Is the peripheral used to generate the tick &#40;or the configuration of the timer used to feed the peripheral that generates the tick&#41; configured before the scheduler is started or by one of the tasks? If it is configured by one of the tasks then removing the task will stop the hardware being configured.  
Can you remove the tasks one at a time to determine when the tick configuration changes.
</div></div><div class="thread-post"><h3 class="thread-post-title">Non Blocking Task wont Give CPU To a Periodic</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/krnl386">krnl386</a> on May 11, 2013</div><div class="thread-post-content">The Peripheral Generating the Tick is a core peripheral &#40;SysTick&#41; common in Cortex-M Microcontrollers , and its configuration is standardized through CMSIS wich is used by FreeRTOS , the configuration API SysTick&#95;Config&#40; &#41; could be found in the xPortStartSchedular&#40; &#41; API in the M0 Port , and its Arguments are configCPU&#95;CLOCK&#95;HZ&nbsp; and configTICK&#95;RATE&#95;HZ , not configured in one of the Tasks
