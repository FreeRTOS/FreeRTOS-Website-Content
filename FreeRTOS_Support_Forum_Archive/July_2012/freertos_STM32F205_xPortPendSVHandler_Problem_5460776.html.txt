  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">STM32F205 xPortPendSVHandler Problem</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/pandivijayaraj">pandivijayaraj</a> on July 21, 2012</div><div class="thread-post-content">Hi,  
I&#8217;m facing a problem while writing an UART application in STM32F205 using FreeRTOS.<br />
I have two tasks one will send data out through UART and other will read data coming in through the same UART and process it.<br />
I have assigned the Receiving task with priority &#40;tskIDLE&#95;PRIORITY+2&#41; and writing task with the priority &#40;tskIDLE&#95;PRIORITY+1&#41;.<br />
UART IRQ uses TXE interrupt to send data out and it receives a data for every occurance of the RXNE interrupt and places the data into a buffer, from which my receiving task will read.  
I have used the NVIC Configurations as instructed in FreeRTOS manual  
<pre><code>#define configKERNEL_INTERRUPT_PRIORITY     255
#define configMAX_SYSCALL_INTERRUPT_PRIORITY    191 
#define configLIBRARY_KERNEL_INTERRUPT_PRIORITY 15
 NVIC_PriorityGroupConfig(NVIC_PriorityGroup_4); 
  NVIC_InitStructure.NVIC_IRQChannel = USART2_IRQn;
  NVIC_InitStructure.NVIC_IRQChannelPreemptionPriority = configLIBRARY_KERNEL_INTERRUPT_PRIORITY; 
  NVIC_InitStructure.NVIC_IRQChannelSubPriority = 0;
  NVIC_InitStructure.NVIC_IRQChannelCmd = ENABLE; 
 NVIC_Init(&amp;NVIC_InitStructure);
</code></pre>
My Receive Task is blocked on a Binary semaphore which is actually released by IRQ handelr for every byte reception.<br />
IRQ handler uses these calls to release the Semaphore  
<pre><code>xSemaphoreGiveFromISR(ParseSem, &amp;xHigherPriorityTaskWoken);
portEND_SWITCHING_ISR(xHigherPriorityTaskWoken);
</code></pre>
My application works as i expected.<br />
I dont face any problem&nbsp; when I send minimal amount of data out. If i periodically send data lessthan 50 bytes for a long time no problem.<br />
If i try to send 300 bytes continuously,&nbsp; i&#8217;m receiving some of the data what i&#8217;m sending out and HardFault ocuurs.<br />
I suspect a corruption in NVIC, it handles TXE as RXNE and my IRQ reads in the same data that is sent out.  
Call Stack indicates the hardFault occurance in &#8221; xPortPendSVHandler+29 &#8220;.<br />
If I trace this leads to xPortPendSVHandler  
<pre><code>ldr r0, [r1]        /* The first item in pxCurrentTCB is the task top of stack. */
</code></pre>
I can&#8217;t make much out of this hint. Also I tried to debug in many ways, like using Queue instead of Semaphore as shown in FreeRTOS example. But HardFault can&#8217;t be prevented.  
Thanks,<br />
Vijayaraj
</div></div><div class="thread-post"><h3 class="thread-post-title">STM32F205 xPortPendSVHandler Problem</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on July 23, 2012</div><div class="thread-post-content">If the fault is occurring on that line, then it looks like you have a RAM corruption somewhere that has corrupted the value loaded into R1 prior to that line of code.  
Do you have stack overflow detection switched on?<br />
Is your UART in an error state &#40;overrun error, for example&#41; that is not being handled?<br />
How is your UART processing received bytes &#40;placing them in a circular buffer, for example&#41;?  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">STM32F205 xPortPendSVHandler Problem</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/pandivijayaraj">pandivijayaraj</a> on July 23, 2012</div><div class="thread-post-content">Yes I have enabled stack overflow checking in my code.&nbsp; I have used the &#8220;vApplicationStackOverflowHook&#8221;&nbsp; to just print the name of the task having corrupted stack.&nbsp; But this vApplicationStackOverflowHook is never executed. Aiso i checked the size of stacks for all the tasks in FreeRTOS plugin for IAR. It is showing all the tasks having size &gt;256.  
My UART&nbsp; IRQ handler will receive a byte for every RXNE interrupt and copies it to a circular buffer. Then it will signal to a task using a semaphore.<br />
For debugging purpose i tweaked this logic and implemented similar to a FreeRTOS demo program given for Cortex-M3. IRQ reads a byte for every RXNE interrupt and palces it in a queue. The corresponding task is blocked on the queue.<br />
in this way i&#8217;m making sure data is read immediately after the occurrence of interrupt. But then also hardfault occurs.  
Actually i should not receive the same data what i&#8217;m sending out. But i&#8217;m receiving some unwanted RXNE interrupts and reading the same data i&#8217;m sending out.  
if i check UART overrun error flag after hardfault, it is set.
