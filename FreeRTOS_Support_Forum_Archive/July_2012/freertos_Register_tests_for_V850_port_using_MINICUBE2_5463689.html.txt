  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Register tests for V850 port using MINICUBE2</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/cmao">cmao</a> on July 23, 2012</div><div class="thread-post-content">I try to make freeRTOS v7.1.1 work on V850ES/Jx3-L low-power demonstrator &#40;<a href="http://am.renesas.com/products/tools/introductory_evaluation_tools/renesas_demo_kits/v850es_jx3l_lpd/index.jsp">http://am.renesas.com/products/tools/introductory_evaluation_tools/renesas_demo_kits/v850es_jx3l_lpd/index.jsp</a>&#41;. I debugged the following code snippet&nbsp; excerpted from the register test code &#40;RegTest.s85&#41; using MINICUBE2 and found that R31&#8217;s content is always 0x0. My question is anybody has verified freeRTOS&#8217;s V850 port on any hardware?<br />
MOV 0xa101010b, R31<br />
CMP R31, R1<br />
BZ $+6<br />
JARL vRegTestFailed, lp  
</div></div><div class="thread-post"><h3 class="thread-post-title">Register tests for V850 port using MINICUBE2</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on July 23, 2012</div><div class="thread-post-content">In the code snippet you have posted, you are setting the value of R31, then testing the value of R31, all done in assembly code so the compiler cannot be interfering.&nbsp; If, after setting the value of R31 it does not hold the value you just wrote to it, then there is something strange going on indeed.&nbsp; Please not however, that this code is not part of the FreeRTOS code, it is just assembly code in the application.&nbsp; It could be feasible that an interrupt is occurring between setting R31 and testing R31, and that that interrupt is corrupting R31.&nbsp; To discount that try disabling interrupts in the asm code before the MOV instruction.&nbsp; It could also be feasible that the trap instruction before the MOV instruction &#40;not shown in your code snippet&#41; is causing the MOV to get skipped somehow &#8211; try adding a couple of NOP instructions between the TRAP and the MOV instructions.  
That said…  
The code in the FreeRTOS download is different to the code you posted in that the value written to R31 has changed.&nbsp; This is the code in the download:  
<pre><code>    MOV     0x01010101, R31
    CMP     R31, R1
    BZ      $+6
    JARL    vRegTestFailed, lp
</code></pre>
What else did you change?&nbsp; Did you also change the value in R1 to match?  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">Register tests for V850 port using MINICUBE2</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/cmao">cmao</a> on July 24, 2012</div><div class="thread-post-content">Richard,  
Thank you very much for your reply. Actually, the code I quoted is from the second register test routine and yours is from the first one. They stored different values in R1 register.  
I commented out TRAP instruction because it stopped the debugger from functioning.  
I think the reason causing the problem is because the on-chip monitor program downloaded by debugger uses interrupt and function calls. In order to using the debug function, I didn&#8217;t disable the general interrupt mask using DI instruction. Instead, I just masked the tick timer interrupt.  
Charles
