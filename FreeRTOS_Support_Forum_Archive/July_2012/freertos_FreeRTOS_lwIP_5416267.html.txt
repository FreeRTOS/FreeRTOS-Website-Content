  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">FreeRTOS lwIP</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/alpha86">alpha86</a> on July 9, 2012</div><div class="thread-post-content">I am having a hard time debugging my lwIP application. I have a modified copy of the<a href="http://www.freertos.org/FreeRTOS-Plus/FreeRTOS_Plus_IO/Demo_Applications/LPCXpresso_LPC1769/NXP_LPC1769_Demo_Description.shtml"> freeRTOS+ demo</a> and it has been working good so far. My lwIP application runs well but when I use SPI together with lwIP task running I always end up at hardfault.  
I have narrow down to the function, and it seems to occur at lwip&#95;recv&#40;&#41; function. I am not sure how the FreeRTOS port of lwIP is implemented, will definitely appreciate any info about it.  
I will also like to know:<br />
1&#41; if the freeRTOS port of lwIP is thread/ISR safe?<br />
2&#41; I try to dig into the code, and I found this xInsideISR at sys&#95;arch.c. I will like to know if this variable is an internal variable or should I use it in my code? I did a search on this variable and I dont seem to see any changes on this variable &#40;only logic test&#41;. The variable definition is copied here for reference:  
/&#42; Very crude mechanism used to determine if the critical section handling<br />
functions are being called from an interrupt context or not.&nbsp; This relies on<br />
the interrupt handler setting this variable manually. &#42;/<br />
volatile portBASE&#95;TYPE xInsideISR = pdFALSE;  
3&#41; I understand the lwIP requires a tcp timer. is freeRTOS using the hardware timer or software?  
hope to get some info about it, thanks 
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS lwIP</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on July 15, 2012</div><div class="thread-post-content"><blockquote>
  1&#41; if the freeRTOS port of lwIP is thread/ISR safe?
</blockquote>
lwIP itself is not thread safe, but the way FreeRTOS uses lwIP in the example is fine and can be copied.&nbsp; For example, the sockets API uses message queues to send data to the TCP thread so the TCP processing only occurs in one thread.  
<blockquote>
  I try to dig into the code, and I found this xInsideISR at sys&#95;arch.c. I will like to know if this variable is an internal variable or should I use it in my code?
</blockquote>
xInsideISR is used because some of the lwIP port functions are called from both the task level and the ISR level &#8211; and the API function to call needs to be different in each case.&nbsp; Therefore, the variable is only used in the Ethernet interrupts that might call the lwIP port layer.&nbsp; It is not normally needed.  
<blockquote>
  3&#41; I understand the lwIP requires a tcp timer. is freeRTOS using the hardware timer or software?
</blockquote>
lwIP manages the timing itself, FreeRTOS does not provide anything explicitly for this purpose.  
Regards.
