  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">help with freertos Interrupt Handlers in  IAR</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on December 5, 2005</div><div class="thread-post-content">im using IAR dev environment with the str711 controller and im fairly new to the freeRtos environment.&nbsp; Im trying to port my application to be used with freeRtos.&nbsp; Everything is compiling ok, but whats left to do is the interrupt handling. so far i have the uart handlers figured out &#40;that was included with the demo&#41; but more importantly im trying to get my USB along with a couple of timers working.&nbsp; Anybody have any tips on how or what interrupt handling is required for the usb, or any pointers on how to write the handlers properly with the rtos ?&nbsp; at the moment all the interrupt handlers except the uarts are handled by a DefaultISR which does nothing.
thanks for any help.
</div></div><div class="thread-post"><h3 class="thread-post-title">help with freertos Interrupt Handlers in  IAR</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on December 5, 2005</div><div class="thread-post-content">The peripheral details of the chip you are using are somewhat out of scope of this thread &#8211; but here are some general tips.
&#43; Make sure that you are using the startup and interrupt vectoring code supplied with the FreeRTOS ST ports.&nbsp; This will ensure that the interrupts are entered correctly and that the required stacks are setup.&nbsp; By default only the IRQ and Supervisor stacks are allocated any memory.&nbsp; You can allocate some to others if required.
&#43; The USB handlers can follow the same model as per the UART.&nbsp; The same rules apply, as detailed on the ST port documentation page.&nbsp; You can take a look at the SAM7 sample USB drivers for guidance also.&nbsp; Sample USB drivers for both HID and CDC classes are included in the download for the SAM7.
&#43; Remember that the sample drivers all use a queue mechanism to pass data out of the ISR.&nbsp; When this is done it allows you to prioritise your ISR&#8217;s by waking a task within the ISR that executes immediately that the ISR completes.&nbsp; However if you have no requirement to do this then a simple circular buffer may be more efficient.
&#43; Remember to keep the ISR very short &#8211; simply collect the data, then process the data within a task.
Regards.
