</div></div><div class="thread-post"><h3 class="thread-post-title">AT91SAM7X-EK Problem with uIP Demo example</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on December 15, 2005</div><div class="thread-post-content">Hi Javier,
I also had one of the original boards.&nbsp; ZE-03 94 V-0 2305&#8230;maybe even older than yours if the last number means anything.
Anyway &#8211; there is a timing issue with using the early boards if using RMII mode.&nbsp; The latest FreeRTOS version defaults to using MII mode as Atmel changed the hardware for production units.&nbsp; Some hardware mods are required to the original boards to use MII mode.&nbsp; This hardware issue will not cause the problem you are having however so can be ignored for now.
Are you using the latest V3.2.4 FreeRTOS code?&nbsp; If so then you need to change the default back to RMII mode.
Another thing V3.2.4 did was change very slightly the init sequence for the EMAC to allow it more time to auto initialise.&nbsp; I think this change is only required when using MII mode &#40;?&#41;, and again will not cause the problem you are having.
I&#8217;m a little unsure what you mean by &#8216;gets stuck&#8217;.&nbsp; Are you saying that the step instruction stops working in the debugger?&nbsp; Or that there is an exception at that point and you jump to a data abort or invalid instruction exception?&nbsp; A little more detail would be good.
If you power down the board, power it back up again, then download the code and run it in the debugger so it is the first execution after power up &#8211; does the problem still happen?&nbsp; If the first run works but subsequent runs do not then there is likely to be a macro initialisation issue.&nbsp; 
Does it run when you are not using the debugger but just programming it into flash?&nbsp; This could be a sign of the same thing.
The code really should run exactly as downloaded with just the IP address, MAC address and gateway addresses set.&nbsp; I know several people who have used it successfully.&nbsp; One person did report problems when powering the board through a USB hub.
Regards.
