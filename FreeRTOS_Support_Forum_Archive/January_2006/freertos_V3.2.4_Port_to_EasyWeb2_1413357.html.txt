  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">V3.2.4 Port to EasyWeb2</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/alunz">alunz</a> on January 3, 2006</div><div class="thread-post-content">Just an announcement that ports of both FreeRTOS demo applications &#40;the &#8216;standard&#8217; demo and the uIP demo&#41; to the MSP430F149 based EasyWeb2 board are in progress and are coming along nicely.&nbsp; The current state of play is:
&#45; The standard demo application is pretty much there except that the queue demo behaves in strange ways &#40;for values of &#8216;strange&#8217; that includes killing the entire app&#41;.
&#45; uIP has been successfully ported to V2.5.5.&nbsp; The port borrows heavily from the EW2 port developed by Paul Curtis of Rowley Associates Limited &#40;see: http://www.rowley.co.uk/msp430/uip.htm&#41;.
In no particular order a few comments and queries:
1&#46; When using msp430-gcc, rather than &quot;&#35;include &lt;msp430x44x.h&gt;&quot; it is cleaner to use &quot;&#35;include &lt;io.h&gt;&quot; in files &#40;for e.g. in FreeRTOSConfig.h&#41;.
2&#46; When building a .zip file to distribute a FreeRTOS port, what is the preferred approach between:
2.1 &#8211; Build a &quot;stand alone&quot; project directory with required FreeRTOS source files copied into the same directory as all other source files. With this approach the project does not require the FreeRTOS distribution to be installed separately, or
2.2 &#8211; Attempt to build a .zip file with the same directory structure as the FreeRTOS distribution, so the port .zip file can be unzipped on top of a FreeRTOS distribution. Or
2.3 &#8211; Something else &#40;please provide details&#41;.
3&#46; Does Version 3.x.x introduce some optimizations over v2.x.x?&nbsp; There is a task that reports the time taken to complete a lengthy process; under v2.x.x the reported time is ~200ms, for the same app under v3.x.x the reported time is ~130ms.&nbsp; The difference could be due to differences between the apps, but a quick scan indicates they should be identical.
4&#46; Does version 3.x.x attempt to reclaim / reuse memory used by the main task stack?
Cheers,
aLUNZ
</div></div><div class="thread-post"><h3 class="thread-post-title">V3.2.4 Port to EasyWeb2</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on January 3, 2006</div><div class="thread-post-content">I look forward to seeing your demo.
In response to &#40;2&#41;:
The preferred method is to stick to the distribution pattern of having &#8211;
FreeRTOS/Demo/abc for the demo app, and
FreeRTOS/Source/portable/XYZ for the port code.
This means you need ../../&#8217;s in the project file, but makes it much easier to drop your demo into updated versions of FreeRTOS at a later date.
With reference to &#40;3&#41;
There have been some optimisations.&nbsp; More will follow&#33;
With reference to &#40;4&#41;
No.&nbsp; This was once a plan but not implemented as it was very port specific and difficult to keep portable.
Regards.
