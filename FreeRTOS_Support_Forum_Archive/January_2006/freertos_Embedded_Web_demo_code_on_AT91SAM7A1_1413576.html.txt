  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Embedded Web demo code on AT91SAM7A1</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on January 3, 2006</div><div class="thread-post-content">Hi,
Your demo code using AT91SAM7X evaluation board is wonderful. Unfortunately, I&#8217;m using AT91SAM7A1 chip and SMSC&#8217;s Lan9115 MAC chip. I would like to try out your demo program on our board to see how freeRTOS works out. However, apparently, the EMAC driver code needs to be replaced. &#40;Of course, the startup assembly code also need to be replaced.&#41; What does it take to adapt the AT91SAM7X EMAC code so that it will work with SMSC&#8217;s Lan9115 chip? &#40;SMSC only provides code for Win CE and Linux. So, there is no code available for CrossStudio.&#41;
Thanks for your help.
</div></div><div class="thread-post"><h3 class="thread-post-title">Embedded Web demo code on AT91SAM7A1</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on January 3, 2006</div><div class="thread-post-content">The EMAC driver code is tightly coupled to the EMAC peripheral within the AT91SAM7X chip.&nbsp; The driver configures the EMAC peripheral, then processes events to pass data into and out from the peripheral &#8211; presenting the data to the demo source code.&nbsp; If you are wanting to use a different NIC then you will require an equivalent driver for your LAN9115 chip.&nbsp; The driver source code is &#40;hopefully&#41; well commented so you can see what it is doing.&nbsp; If everything were ideal you would be able to keep the same function prototypes and just change the function implementation to access your LAN9115 registers as necessary rather than the EMAC registers.
I have had a quick look on the SMSC WEB site and the following links may provide some useful information:
http://www.smsc.com/main/catalog/lan9115.html&#35;Additional%20Information&nbsp;&nbsp; Right down the bottom of this page is a &#8216;generic driver&#8217; source code link.&nbsp; I have not looked at it as I don&#8217;t have an SMSC login, but normally this type of driver will do everything you require with a &#8216;portable&#8217; interface that you have to complete for your particular hardware configuration.
Again I have not looked at it but from the title http://ftp.smsc.com/main/anpdf/an1212.pdf appears to give the register information you would require.
Also the Linux driver might provide a useful reference but would presumable require a lot of stripping.
Which board are you using?
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">Embedded Web demo code on AT91SAM7A1</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on January 3, 2006</div><div class="thread-post-content">Richard,
Thanks for your detailed help. I appreciate it very much.
It seems that I don&#8217;t have an easy way out but follow your recommendations, which is also what I would do if I have to adapt it myself.
The generic code on SMSC web site is pseudo code, I can only use it as a reference. 
So, I think I just have to create an animal from several different animals, i.e., SMSC pseudo code, SMSC linux code, Atmel EMAC code and SMSC documentations.
I&#8217;m using a custom board.
Thanks again for your help.
