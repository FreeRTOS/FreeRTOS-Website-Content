  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Can usTaskCheckFreeStackSpace() be right?</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/johnnybosc">johnnybosc</a> on October 21, 2008</div><div class="thread-post-content">I&#8217;m a tad confused abt. the usTaskCheckFreeStackSpace&#40;&#41; function in task.c.&nbsp; Allow me to quote it in full&nbsp; &#40;sry &#8217;bout that&#41; from the provided source code:
unsigned portSHORT usTaskCheckFreeStackSpace&#40; const unsigned portCHAR &#42; pucStackByte &#41;
&#123;
&nbsp; register unsigned portSHORT usCount = 0;
&nbsp; while&#40; &#42;pucStackByte == tskSTACK&#95;FILL&#95;BYTE &#41;
&nbsp; &#123;
&nbsp;&nbsp;&nbsp; pucStackByte -= portSTACK&#95;GROWTH;
&nbsp;&nbsp;&nbsp; usCount++;
&nbsp; &#125;
&nbsp; usCount /= sizeof&#40; portSTACK&#95;TYPE &#41;;
&nbsp; return usCount;
&#125;
Now, on a PIC32 MCU portSTACK&#95;GROWTH is = -4, i.e. every iteration in the while&#40;&#41; loop will increase the tested address by 4 &#8212; looks very much like we&#8217;re counting 32-bit integers, doesn&#8217;t it?
However, on exiting the while&#40;&#41; loop the count of 32-bit integers in usCount is divided by sizeof&#40;portSTACK&#95;TYPE&#41;&#33;
In the PIC32 port, sizeof&#40;portSTACK&#95;TYPE&#41; is = 4.&nbsp; In other words, I end up with a stack high water mark that is 4 TIMES TOO SMALL.&nbsp; This is borne out by setting a breakpoint in usTaskCheckFreeStackSpace&#40;&#41; and just doing a memory dump of the memory being scanned.
Am I missing something really silly here, or is this a bona fide bug?
</div></div><div class="thread-post"><h3 class="thread-post-title">Can usTaskCheckFreeStackSpace() be right?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on October 21, 2008</div><div class="thread-post-content">Yes it &#8216;was&#8217; a bug.&nbsp; It got fixed in the SVN copy a few days ago but is not yet in the download.
Apologies for any inconvenience caused.
Regards.
