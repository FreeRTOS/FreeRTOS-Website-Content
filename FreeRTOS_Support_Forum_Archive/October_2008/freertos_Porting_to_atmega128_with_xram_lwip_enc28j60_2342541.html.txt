  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Porting to atmega128 with xram+lwip+enc28j60</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/shameless1">shameless1</a> on October 9, 2008</div><div class="thread-post-content">Hi all,
I am working on create a port using freeRTOS 5.0.4, lwip 1.30 on the atmega128 with 32Kb of external sram, using a mcrochip enc28j60 module for the ethernet.
The hardware works fine as I have had uip running on it, but unfortunately the delayed acks just made that not feasible solution for my project.
I am using winavr 20080610 for the toolset.&nbsp; I have started with the atmega323 port and have got the demo apps working correctly for the atmega128 &#40;nothing special here&#41;.
Since I have the extra 32Kb of external sram I moved the global vars and heap to utilise this, leaving the 4Kb of internal sram available for the stack.&nbsp; This brought up an interesting point.&nbsp; There are various posts in various forums stating that the stack should always be located in internal sram &#40;performance and reliability&#41;.&nbsp; But using the heap&#95;2.c from freeRTOS will moved the stack into the external sram as it is alloacted using a global variable.&nbsp; I therefore created heap&#95;4.c that simply starts allocating ram from the start of the internal sram memory space at 0x0100.&nbsp; Since nothing other than the original stack was ever going to touch this ram I figure it safe to use for this purpose.&nbsp; I simply used heap&#95;1.c as a starting point and changed pvPortMalloc to the following:
void &#42;pvPortMalloc&#40; size&#95;t xWantedSize &#41;
&#123;
void &#42;pvReturn = NULL; 
&nbsp;&nbsp;&nbsp; /&#42; Ensure that blocks are always aligned to the required number of bytes. &#42;/
&nbsp;&nbsp;&nbsp; &#35;if portBYTE&#95;ALIGNMENT &#33;= 1
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; if&#40; xWantedSize &amp; heapBYTE&#95;ALIGNMENT&#95;MASK &#41;
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; &#123;
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; /&#42; Byte alignment required. &#42;/
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; xWantedSize += &#40; portBYTE&#95;ALIGNMENT &#8211; &#40; xWantedSize &amp; heapBYTE&#95;ALIGNMENT&#95;MASK &#41; &#41;;
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; &#125;
&nbsp;&nbsp;&nbsp; &#35;endif
&nbsp;&nbsp;&nbsp; vTaskSuspendAll&#40;&#41;;
&nbsp;&nbsp;&nbsp; &#123;
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; /&#42; Check there is enough room left for the allocation. &#42;/
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; if&#40; &#40; &#40; xNextFreeByte + xWantedSize &#41; &lt; configTOTAL&#95;HEAP&#95;SIZE &#41; &amp;&amp;
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; &#40; &#40; xNextFreeByte + xWantedSize &#41; &gt; xNextFreeByte &#41;&nbsp;&nbsp;&nbsp; &#41;/&#42; Check for overflow. &#42;/
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; &#123;
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; /&#42; Return the next free byte then increment the index past this
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; block. &#42;/
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; pvReturn = &#40;void&#42;&#41;&#40;0x0100+xNextFreeByte&#41;;
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; xNextFreeByte += xWantedSize;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; 
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; &#125;&nbsp;&nbsp;&nbsp; 
&nbsp;&nbsp;&nbsp; &#125;
&nbsp;&nbsp;&nbsp; xTaskResumeAll&#40;&#41;;
&nbsp;&nbsp;&nbsp; return pvReturn;
&#125;
This allows configTOTAL&#95;HEAP&#95;SIZE to be set to something quite close to 4096 as long as you don&#8217;t have too many stack requirements before the schedular is started.
I have also changed to use a makefile generated using mfile from winavr as I was having problems with the one from the atmega323 port.
All of the above changes were tested on the demo apps and worked fine.
I am however having major problems with getting the lwip code to work. I am using the code from the contrib port ARM9&#95;STR91X&#95;IAR to pinch the lwip/webserver code.&nbsp; It compiles fine and appears to run correctly until to create the tasks.&nbsp; But as soon as the schedular is started the atmega128 resets.&nbsp; As I am new to both freeRTOS and lwip I am unsure as to were to start looking.&nbsp; Does anyone have any ideas?&nbsp; I suspect it is probably some sort of memory issue, but I am struggling.&nbsp; If anyone has any idea of where to start looking it would be appreciated. I believe it to be within the lwip code that things go wrong.&nbsp; The initialisation function for the enc28j60 never gets called.
I have a jtagmk2 to assist in debugging although I am new to it and still learning how to use it to debug.
Sorry about the long post, but any assistance would be much appreciated.&nbsp; When I get this working I intend to make it available to the community.
Cheers
Simon
