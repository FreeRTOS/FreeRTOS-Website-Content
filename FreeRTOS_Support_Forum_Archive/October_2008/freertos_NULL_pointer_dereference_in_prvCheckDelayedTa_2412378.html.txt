  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">NULL pointer dereference in prvCheckDelayedTa</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/em1ssnuke">em1ssnuke</a> on October 21, 2008</div><div class="thread-post-content">I keep getting a &#95;&#95;dapt&#40;&#41; on execution of the Demo for ARM7&#95;AT91SAM7X256&#95;Eclipse. On the first call to vTaskIncrementTick&#40;&#41; it attempts to find if a timeout has expired using prvCheckDelayedTasks&#40;&#41;.&nbsp; Unfortunately, it appears prvInitialiseTaskLists&#40;&#41; has not executed prior to this point and pxDelayedTaskList has a NULL pointer for it.&nbsp; This causes all kinds of problems.
Any idea why initializations are not preformed prior to allowing ticks to generate?&nbsp; Has this already been found out? &#40;I did browse/search this list and did not find any thing.&#41;&nbsp; Is there a patch for this potential issue?
thnx &#8211;&nbsp; bob
</div></div><div class="thread-post"><h3 class="thread-post-title">NULL pointer dereference in prvCheckDelayedTa</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on October 22, 2008</div><div class="thread-post-content">The tick interrupt is configured as the scheduler is started and after interrupts have been disabled. Interrupts will not be enabled again until the first task is running. This means provided you have created some tasks to run you should not get any tick interrupts until everything has been initialized. The lists get initialized when the first task is created.
</div></div><div class="thread-post"><h3 class="thread-post-title">NULL pointer dereference in prvCheckDelayedTa</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/em1ssnuke">em1ssnuke</a> on October 22, 2008</div><div class="thread-post-content">The problem is on restart after a system reset.&nbsp; The PIT timer does not appear to be disabled upon reinitialization.
code snippet:
static void prvSetupHardware&#40; void &#41;
&#123;
&nbsp;&nbsp;&nbsp; portDISABLE&#95;INTERRUPTS&#40;&#41;;
&#8230;
and portDISABLE&#95;INTERRUPTS&#40;&#41; does not appear to disable all interrupts, only IRQ and FIQ
code snippet 
&#8230;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; &quot;MRS&nbsp;&nbsp;&nbsp; R0, CPSR&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; nt&quot;&nbsp;&nbsp;&nbsp; /&#42; Get CPSR.&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; &#42;/&nbsp;&nbsp;&nbsp; 
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; &quot;ORR&nbsp;&nbsp;&nbsp; R0, R0, &#35;0xC0&nbsp;&nbsp;&nbsp; nt&quot;&nbsp;&nbsp;&nbsp; /&#42; Disable IRQ, FIQ.&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; &#42;/&nbsp;&nbsp;&nbsp; 
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; &quot;MSR&nbsp;&nbsp;&nbsp; CPSR, R0&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; nt&quot;&nbsp;&nbsp;&nbsp; /&#42; Write back modified value.&nbsp;&nbsp;&nbsp; &#42;/&nbsp;&nbsp;&nbsp; 
&#8230;
So &#8230; i added the following and it now works as expected.
code snippet:
static void prvSetupHardware&#40; void&#41;
&#123;
&nbsp;&nbsp;&nbsp; AT91F&#95;PITDisableInt&#40; AT91C&#95;BASE&#95;PITC&#41;;
&nbsp;&nbsp;&nbsp; portDISABLE&#95;INTERRUPTS&#40;&#41;;
&#8230;
</div></div><div class="thread-post"><h3 class="thread-post-title">NULL pointer dereference in prvCheckDelayedTa</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on October 22, 2008</div><div class="thread-post-content">Are you using IAR tools?&nbsp; If so the most likely cause is that the debugger macro file &#40;which contains scripts that are run on debug events, such as reset&#41; is not correctly clearing the interrupt peripherals.&nbsp; Look for a file in the debugger settings that has a .mac extension.
