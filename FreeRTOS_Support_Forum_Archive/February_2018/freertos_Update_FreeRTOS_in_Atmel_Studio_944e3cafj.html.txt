  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Update FreeRTOS in Atmel Studio</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/anb80">anb80</a> on February 1, 2018</div><div class="thread-post-content">I have an Arduino Due board which is available in Atmel Studio and it has a SAM3X chip. The FreeRTOS edition that comes with it is 7.3.0. 
After downloading the FreeRTOS 10.0 I updated all the files in the OS sources of my Atmel Studio project.
However, now the compilation does not succeed and ends with an error:
implicit declaration of function &#8216;sysclk<em>get</em>cpu_hz&#8217; [-Werror=implicit-function-declaration] in &#8230;srcconfigFreeRTOSConfig.h 74
However, this function is declared in sysclk.h as: 
static inline uint32<em>t sysclk</em>get<em>cpu</em>hz(void)
{
    /* CONFIG<em>SYSCLK</em>PRES is the register value for setting the expected <em>/
    /</em> prescaler, not an immediate value. */
    return sysclk_get_main_hz() /
        ((CONFIG_SYSCLK_PRES == SYSCLK_PRES_3) ? 3 :
            (1 &lt;&lt; (CONFIG_SYSCLK_PRES >> PMC_MCKR_PRES_Pos)));
}
During the compilation I get various other warnings such as: 
Warning     nested extern declaration of &#8216;sysclk<em>get</em>cpu<em>hz&#8217;
Warning     nested extern declaration of &#8216;<strong>FLASH_segment_end</strong>&#8216; 
Warning     nested extern declaration of &#8216;<strong>SRAM_segment_start</strong>&#8216; 
Warning     pointer targets in passing argument 1 of &#8216;MPU</em>vTaskGetRunTimeStats&#8217; differ in signedness 
Warning     pointer targets in passing argument 2 of &#8216;MPU_xTaskCreate&#8217; differ in signedness
Is there any recommended way how to be updating the FreeRTOS to latest version under Atmel Studio? I always struggle with this and drop-in replacement is usually not possible. 
Thank you.
</div></div><div class="thread-post"><h3 class="thread-post-title">Update FreeRTOS in Atmel Studio</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on February 1, 2018</div><div class="thread-post-content">What was it you replaced?  Did you keep the FreeRTOSConfig.h the same 
(which would be the right thing to do)?  Other than the one starting 
MPU_ the variables mentioned in your post are not used by FreeRTOS 
itself so I&#8217;m not sure why updating the FreeRTOS .c and .h files would 
effect the build unless Atmel had changed something in the core kernel 
files.
The references to variables starting MPU_ are suspicious though.  Are 
you using the MPU version of FreeRTOS?  I doubt you are intentionally, 
in which case either you have included the wrong FreeRTOS port layer, or 
you have configUSE<em>MPU</em>WRAPPERS set to 1 in FreeRTOSConfig.h.
The SAM3X has a Cortex-M3 core, and Atmel Studio uses GCC, so you should 
have picked the port layer files from FreeRTOS/Source/portable/GCC/ARM_CM3.
