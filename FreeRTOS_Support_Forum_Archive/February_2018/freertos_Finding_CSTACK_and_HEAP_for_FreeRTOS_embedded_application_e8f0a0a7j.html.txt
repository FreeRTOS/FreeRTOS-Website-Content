  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Finding CSTACK and HEAP for FreeRTOS embedded application ? </h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davinderpro">davinderpro</a> on February 5, 2018</div><div class="thread-post-content">Our embedded application keep crashing <strong>VListinsertend</strong> after some time of operations. 
Is this due to CSTACK and HEAP size ? 
**FreeRTOS details
**
FreeRTOS  8.2  with heap 4 , Systick timer
osThreadDef(Task1, StartTask1, osPriorityRealtime, 0, 256);
osThreadDef(Task2, StartTask2, osPriorityHigh, 0, 196);
osThreadDef(Task3,StartTask3, osPriorityRealtime, 0, 256);
osThreadDef(Task4, StartTask4, osPriorityAboveNormal, 0, 196);
**MicroController is STM32F303CC 
**
256 Kbytes of Flash memory
40 Kbytes of SRAM, 
Routine booster: 8 Kbytes of SRAM on instruction and data bus, with HW parity check (CCM)
** Custom  CSTACK and HEAP settings
**
CSTACK : 0X600 
HEAP       : 0X300 
What should be the ideal CSTACK and HEAP size for the this kind of appilcations  ? 
</div></div><div class="thread-post"><h3 class="thread-post-title">Finding CSTACK and HEAP for FreeRTOS embedded application ? </h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on February 5, 2018</div><div class="thread-post-content"><blockquote>
  Is this due to CSTACK and HEAP size ?
</blockquote>
Could be, or it could be one of a number of different things, the level 
of detail in your post only allows us to guess.
<blockquote>
  FreeRTOS 8.2 with heap 4 , Systick timer
</blockquote>
I would recommend upgrading to a much newer version of FreeRTOS because 
the later the version there more <a 
href="https://www.freertos.org/a00110.html#configASSERT">configASSERT()</a> 
calls there are to check you are configuring the system correctly.  You 
may find with a later version of FreeRTOS and configASSERT() defined to 
something that halts execution you find the cause of your problem 
immediately.
<blockquote>
  osThreadDef(Task1, StartTask1, osPriorityRealtime, 0, 256);
  osThreadDef(Task2, StartTask2, osPriorityHigh, 0, 196);
  osThreadDef(Task3,StartTask3, osPriorityRealtime, 0, 256);
  osThreadDef(Task4, StartTask4, osPriorityAboveNormal, 0, 196);
</blockquote>
This is not the native FreeRTOS API.
<blockquote>
  *MicroController is STM32F303CC
</blockquote>
As this is an STM32 did you note the &#8216;special note for STM32 users&#8217; on 
this page: https://www.freertos.org/RTOS-Cortex-M3-M4.html that says you 
must call NVIC<em>PriorityGroupConfig( NVIC</em>PriorityGroup_4 ); before 
starting the scheduler?
<blockquote>
  *
  256 Kbytes of Flash memory
  40 Kbytes of SRAM,
  Routine booster: 8 Kbytes of SRAM on instruction and data bus, with HW 
  parity check (CCM)
  *Custom CSTACK and HEAP settings
  *
  CSTACK : 0X600
  HEAP : 0X300
</blockquote>
The cause won&#8217;t be one of these as the CStack is only used by interrupts 
after the scheduler has started and if you are using heap_4 then the 
heap set up by the compiler/linker will only be used if you call 
malloc() directly yourself &#8211; FreeRTOS won&#8217;t call it.
Some links you might find helpful:
https://www.freertos.org/a00111.html
https://www.freertos.org/FAQHelp.html
https://www.freertos.org/Documentation/RTOS_book.html
