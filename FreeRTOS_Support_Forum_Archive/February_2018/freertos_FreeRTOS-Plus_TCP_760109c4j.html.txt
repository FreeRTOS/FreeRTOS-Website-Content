</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS-Plus_TCP</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on March 1, 2018</div><div class="thread-post-content">I added a &#8220;loop-back interface&#8221; to the normal ( non-multi ) FreeRTOS+TCP library, and it works nicely.
With this change, you can ping to the device&#8217;s IP-address, connect to your own TCP-services, and exchange UDP messages.
A small change is needed to the <code>NetworkInterface.c</code> that you are using, e.g. :
~~~

 {
 /* Do not wait too long for a free TX DMA buffer. */
 const TickType</em>t xBlockTimeTicks = pdMS<em>TO</em>TICKS( 50u );
<pre><code> do {
</code></pre>
+        if( xCheckLoopback( pxDescriptor, bReleaseAfterSend ) != 0 )
+        {
+            /* The packet has been sent back to the IP-task.
+            The IP-task will further handle it.
+            Do not release the descriptor. <em>/
+            bReleaseAfterSend = pdFALSE;
+            break;
+        }
         if( ( ulPHYLinkStatus &amp; BMSR_LINK_STATUS ) == 0 )
         {
             /</em> Do not attempt to send packets as long as the Link Status is low. */
             break;
         }
~~~
The new function <code>xCheckLoopback()</code> will compare the target MAC-address of the IP-message ( ICMP, UDP, or TCP ) with the MAC-address of the device.  If they are the same, the packet is forwarded to, and answered by the IP-stack.
It is literally a <strong>loop-back</strong> interface!
I put the new function <code>xCheckLoopback()</code> in <code>FreeRTOS_ARP.c</code> and declared it in <code>FreeRTOS_ARP.h</code>, so it can be used by any NetworkInterface.c.
<code>FreeRTOS_ARP.c</code> has a change in <code>eARPGetCacheEntry()</code>: In case the devices&#8217;s IP-address is looked-up, the proper MAC-address will be returned as a <code>eARPCacheHit</code>.
~~~

         eReturn = eARPCacheHit;
     }

I tested the changes on a SAME70 with ping and TCP.
Please find <strong>attached</strong> the code in the form of a patch.

In case you don&#8217;t like patches, there is also the raw code in <code>xCheckLoopback.c</code>.
