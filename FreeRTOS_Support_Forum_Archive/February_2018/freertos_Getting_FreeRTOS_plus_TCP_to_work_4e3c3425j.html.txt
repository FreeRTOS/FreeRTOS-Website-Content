</div></div><div class="thread-post"><h3 class="thread-post-title">Getting FreeRTOS plus TCP to work</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/fest">fest</a> on February 10, 2018</div><div class="thread-post-content">I solved the problem finally &#8211; it was incorrect PHY configuration (obviously, since I&#8217;m using different chip) + I had a short code for opening a TCP socket and binding it inside vApplicationIPNetworkEventHook function when event is eNetworkUp. For some reason, creating TCP socket worked but bind call caused IP task to freeze so recieved frames weren&#8217;t processed. That&#8217;s why I was getting messages about network buffers getting used up.
When I moved socket related code to a separate task and just signaled it from vApplicationIPNetworkEventHook (in addition to using modified physpeed.c file), it started working.
I&#8217;m not sure why would this happen &#8211; it would be ok if bind function returned some error but it just froze. In any case, I hope my experiences here will be helpful for someone in future.
</div></div><div class="thread-post"><h3 class="thread-post-title">Getting FreeRTOS plus TCP to work</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on February 10, 2018</div><div class="thread-post-content">Thank you for reporting this.
Application hooks like <code>vApplicationIPNetworkEventHook()</code> often have a risk: they are called from a different task.  The same for <code>vApplicationIdleHook()</code> (called form the idle task), and <code>vApplicationTickHook()</code> (called from an ISR, the FreeRTOS clock-tick interrupt).
In this case you were calling a +TCP API from the IP-task.  I also made this mistake some day. What I did is just set a variable from within <code>vApplicationIPNetworkEventHook()</code>.
<blockquote>
   it would be ok if bind function returned some error but it just froze
</blockquote>
I will see if the API can just fail and return some appropriate error.
<blockquote>
  I hope my experiences here will be helpful for someone in futur
</blockquote>
You helped me remind about this trap, thanks.
