Even running the demo project contained in the FreeRTOS distribution shows the same problem.  It will run for an hour or two and then the debugger halts showing &#8220;No user code at 0x0&#8221;
I&#8217;m using MPLAB X IDE v2.15, xc16-gcc v1.21 and ICD 3  with a dsPIC33FJ256GP710A on the Microchip Explorer 16 board.  FreeRTOS version is 8.1.2.
I picked up the documentation package and ported the very simple two task example from the &#8220;Using the FreeRTOS Real Time Kernel &#8211; A Practical Guide&#8221; PIC32 edition and it shows the same reset problem after running for a while.
I&#8217;ve identified that it isn&#8217;t my hardware or MPLAB environment as the Microchip Explorer 16 demo ran for close to a day without a reset.
I added the interrupt trap file from the Explorer 16 demo which has system interrupt traps with infinite while loops for the things that cause a processor reset (E.g. address, stack, math errors) but none of the interrupts are entered when the FreeRTOS application halts.
I&#8217;ve ensured the project has the MPLAB<em>DSPIC</em>PORT definition defined in the pre processing and messages &#8220;Define C macrons&#8221; option as I saw a post that indicated the author&#8217;s resets were due to the lack of this definition.
The problem can be replicated by simply running the FreeRTOS dsPIC demo application for a while with the debugger on.  You&#8217;ll find eventually the session halts.

</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS with dsPIC has periodic resets</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/c_welch">c_welch</a> on September 30, 2014</div><div class="thread-post-content">The problem here relates to importing projects into MPLAB X.  It has been a while since I&#8217;ve used MPLAB, but I recall the older version of MPLAB used to allow you to setup the chip configuration as part of the project setup.
That is no longer the case and the chip configuration settings are not brought in with the project when you do the import.
That leaves the watch dog active (on by default) causing the resets.
You now have to use the configuration generator and put the setup into a header file or manually code the settings.
Heads up if you are using the new tools with these materials.
