  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Configure RTOS tick under 1ms versus portTICK_PERIOD_MS</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/simointe">simointe</a> on June 13, 2016</div><div class="thread-post-content">(TMS570LC4, nested interrupt, C++, FreeRTOS V9.0.0rc2, compiler TI v5.2.7, rtos running ok).
Considering
~~~
<h1>define portTICK<em>PERIOD</em>MS    ((TickType<em>t) 1000 / configTICK</em>RATE_HZ)</h1>
~~~
where tickType<em>t is unsigned long, it means that 1KHz is the maximum frequency I can setup the tick ?
portTICK</em>PERIOD_MS seems to be used in many places.
</div></div><div class="thread-post"><h3 class="thread-post-title">Configure RTOS tick under 1ms versus portTICK_PERIOD_MS</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on June 13, 2016</div><div class="thread-post-content">portTICK<em>PERIOD</em>MS is not used ANYWHERE in the FreeRTOS source code, it 
is only provided as a convenience, and in fact, its use is not 
recommended now as the pdTICKS<em>TO</em>MS() macro should be used in its place.
FreeRTOS V9.0.0 (not the release candidate) allows pdMS<em>TO</em>TICKS() to be 
overridden, should the default implementation not give the accuracy 
required (it considers speed more).
portTICK<em>PERIOD</em>MS and pdMS<em>TO</em>TICKS() is used in a lot of places in 
example code and external components, but again for convenience, and 
FreeRTOS has no dependency on it.
That all said &#8211; it is rarely a good idea to set the tick rate greater 
than 1KHz &#8211; 100Hz being typical.
