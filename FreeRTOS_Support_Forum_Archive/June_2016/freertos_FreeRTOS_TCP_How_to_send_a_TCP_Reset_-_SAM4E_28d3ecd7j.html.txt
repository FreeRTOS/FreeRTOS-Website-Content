  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">FreeRTOS+TCP How to send a TCP Reset &#8211; SAM4E</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/bodone">bodone</a> on June 7, 2016</div><div class="thread-post-content">Hi guys,
I&#8217;m currently working with FreeRTOS+TCP from FreeRTOS<em>Labs</em>160112 on a SAM4E Xplained Pro Evaluation Kit (microcontroller : ATSAM4E16E), jointly with FreeRTOS V8.2.3, working with Atmel Studio 7.
My board is communicating with another &#8220;non-FreeRTOS running&#8221; board, through MODBUS/TCP protocol. My board is configured in client mode, and attempt to connect with the other one who is listening for entering connection requests. The connection and communication work fine but when we lost this connection for any reason, the other board don&#8217;t see it and I have to reboot it, or forging a reset to make it listen again to my connection requests. I can&#8217;t find out how I can send a TCP frame (with the RST flag on) through the freeRTOS+TCP API and is not experienced enough to find an other way&#8230;
I would be very grateful if someone have an idea about how to perform this reset, thank you very much for your concern.
Best regards,
Alexandre Beaudonnet
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS+TCP How to send a TCP Reset &#8211; SAM4E</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on June 10, 2016</div><div class="thread-post-content">Hi Alexandre,
Sorry to leave your post unanswered for so long.
<blockquote>
  when we lost this connection for any reason, the other board don&#8217;t see it and I have to reboot it
</blockquote>
That sounds a bit contradictional: the SAM4E, a TCP client, looses a connection and the server is not aware of it?
Or have you rebooted the client without shutting down the connection, maybe?
How do you notice that you loose the connection in the first instance?
Does <code>FreeRTSO_recv()</code> return an error, what is the error number?
There is no method of just sending a RST flag, except by closing the socket (<code>FreeRTOS_closesocket</code>). But if the peer is just keeping silent, he will never see a RST flag.
As long as the connection is still alive, and you want to force a disconnection, you can call <code>FreeRTOS_shutdown()</code>. After calling it, keep on calling <code>FreeRTOS_recv()</code>, until it returns an error.
If the connection gets lost because your client has rebooted, and the server doesn&#8217;t allow you to make a connection, I&#8217;m afraid you&#8217;ll have to look at the software running on the server. Did you write that also? What OS is it using?
Please give more info
Regards.
