  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Wanted to introduce WDT on free RTOS running atmel SAMD20</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/hellomanas1991">hellomanas1991</a> on June 2, 2016</div><div class="thread-post-content">Hi All,
I wanted to introduce WDT on atmel(RTOS running). I have tried with the <strong>WDT driver</strong> provided on <strong>Atmel IDE</strong>. It is working on basic project(Mean without RTOS).  But when I am using the same driver on a project where RTOS is running just keep on resetting the system again and again.                                                                                                                                                                                                                                                                                                                                                                                      
</div></div><div class="thread-post"><h3 class="thread-post-title">Wanted to introduce WDT on free RTOS running atmel SAMD20</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on June 2, 2016</div><div class="thread-post-content">You don&#8217;t say why.  I&#8217;m guessing, as this is a watchdog, that it is supposed to reset the system if it is not &#8216;kicked&#8217;.  Are you kicking the watchdog in an attempt to prevent the watchdog resetting the system.  If so, where from and under what circumstance?
</div></div><div class="thread-post"><h3 class="thread-post-title">Wanted to introduce WDT on free RTOS running atmel SAMD20</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/hellomanas1991">hellomanas1991</a> on June 3, 2016</div><div class="thread-post-content">Thanks for the reply !
I have a WDT which I configured for 15 sec reset time if it is not being kicked with in that time period.But the problem is that in case of RTOS after initializing all the tasks and just before the <strong>schedular</strong> starts when I am initializing the WDT. It is not waiting till the expiry time. Immediately it is resetting the system.So I am thinking it is doing something with the free RTOS Ticks count/timer tick.
</div></div><div class="thread-post"><h3 class="thread-post-title">Wanted to introduce WDT on free RTOS running atmel SAMD20</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on June 3, 2016</div><div class="thread-post-content">Do you mean the system resets before the scheduler has even started?  If 
so, are you sure it is the WDT that is resetting the system &#8211; seems 
unlikely if it is set for 15 seconds.
Is the driver for the watchdog timer enabling interrupts using the 
basepri register?  If so, that could cause a problem just before the 
scheduler starts.
Have you tried enabling the watchdog after the scheduler has started? 
Perhaps in the Daemon Task Startup Hook, if you are using timers 
(http://www.freertos.org/a00016.html) &#8211; or maybe even in a one shot timer.
</div></div><div class="thread-post"><h3 class="thread-post-title">Wanted to introduce WDT on free RTOS running atmel SAMD20</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/hs2sf">hs2sf</a> on June 4, 2016</div><div class="thread-post-content">I&#8217;m using the SAM1B WDT w/o any problems. Except a periodic refresh task (as 1 possibility) it&#8217;s completely unrelated to the RTOS. Although I&#8217;m not uing a &#8216;driver&#8217; for the rather simple WDT setup I guess, the Atmel driver only touches WDT resoures.
You should double check you WDT setup.
</div></div><div class="thread-post"><h3 class="thread-post-title">Wanted to introduce WDT on free RTOS running atmel SAMD20</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/hellomanas1991">hellomanas1991</a> on June 12, 2016</div><div class="thread-post-content">Thank you so much for your support ! I have resolved this issue by implementing the above solution you provided.
