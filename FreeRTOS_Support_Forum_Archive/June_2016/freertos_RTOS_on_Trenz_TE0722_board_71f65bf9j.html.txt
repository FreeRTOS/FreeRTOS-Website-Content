  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">RTOS on Trenz TE0722 board</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/peteallwright">peteallwright</a> on June 22, 2016</div><div class="thread-post-content">Am failing to get a basic RTOS build up on the Trenz Zynq board.  Have constructed a build as per the guide in &#8220;Mastering the FreeRTOS&#8221; (pre-release version).  This in on Xilinx Vivado 2014.4 (for historic reasons) and under Windows 10.
The construction of the project succeeds and can be downloaded to the target.
However when executing, the processor crashes in vPortInstallFreeRTOSVectorTable() within prvSetupHardware();
I have noted the following:
In debug when tracing, the address of <em>freertos</em>vector_table that is loaded is 0 &#8211; so does the code not simply copy the vector table over itself?
That stepping through the routine vPortInstallFreeRTOSVectorTable, when the instruction dsb is executed the link register lr is clobbered. Hence when the bx lr instruction is executed we effect a re-boot (without a reset).
Any ideas?
Pete A
</div></div><div class="thread-post"><h3 class="thread-post-title">RTOS on Trenz TE0722 board</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on June 22, 2016</div><div class="thread-post-content">There are three options for creating a project:
1) Taking the existing Zynq demo from the FreeRTOS download, and 
re-targeting it for your hardware (replacing the hardware definition 
project to be correct for your hardware, then re-generating the BSP 
project from the updated hardware definition).
2) Manually creating the project from scratch by allowing the SDK to 
create a bare metal project that uses a standalone BSP, and then 
manually adding in the FreeRTOS source files.
3) Using the SDK to create a FreeRTOS BSP instead of a standalone BSP, 
and in so doing, having the SDK add the FreeRTOS source files into the 
project for you.
Which method did you use?
</div></div><div class="thread-post"><h3 class="thread-post-title">RTOS on Trenz TE0722 board</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/peteallwright">peteallwright</a> on June 22, 2016</div><div class="thread-post-content">Option 2 &#8211; following the guidelines in the manual.  (Did not get option 3 that I have seen.)
Have tried option 1 but cannot get to download &#8211; the debugger simply connects to the hardware and does not give a download option.
Pete
</div></div><div class="thread-post"><h3 class="thread-post-title">RTOS on Trenz TE0722 board</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on June 22, 2016</div><div class="thread-post-content">Did you take the files you added to your project from the FreeRTOS V9.0.0 release?  The SDK project in the V9.0.0 release uses the 2016.1 SDK, which may explain your download issue, as you are using 2014.4.
In the Zync 7000 demo found in FreeRTOS V9.0.0 <tt><em>freertos</em>vector<em>table</tt> is implemented in FreeRTOS</em>asm<em>vectors.S, where it is placed in the freertos</em>vectors section.  Looking at the linker file I see freertos<em>vectors is then placed at the very start of the .text region, which means it should appear at 0x00100000.  Looking at the map file I see freertos</em>vectors does indeed appear at 0x00100000, but you are reporting that in your built <tt><em>freertos</em>vector_table</tt> appears at address 0 &#8211; so could this be a linker script problem?
</div></div><div class="thread-post"><h3 class="thread-post-title">RTOS on Trenz TE0722 board</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/peteallwright">peteallwright</a> on June 22, 2016</div><div class="thread-post-content">when tracing the code in vPortInstallFreeRTOSVectorTable() the address loaded to
r0 is 0x00000000.
So could be a linker problem.
Am faily new to the Vivado suite.  Have a long background in real time systems and
using Keil microvision etc.
Pete
</div></div><div class="thread-post"><h3 class="thread-post-title">RTOS on Trenz TE0722 board</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on June 22, 2016</div><div class="thread-post-content">Have a look at 
FreeRTOSDemoCORTEX<em>A9</em>Zynq<em>ZC702RTOSDemosrclscript.ld &#8211; I think 
the addition of *(.freertos</em>vectors) was the only edit over the linker 
script that was automatically generated for the hardware I was using.
