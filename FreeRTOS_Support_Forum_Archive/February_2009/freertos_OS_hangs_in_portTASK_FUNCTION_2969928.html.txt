</div></div><div class="thread-post"><h3 class="thread-post-title">OS hangs in portTASK_FUNCTION</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/edwards3">edwards3</a> on February 4, 2009</div><div class="thread-post-content">You don&#8217;t say which port you are using. Not all the ports allow interrupt nesting, so that might be what the problem is.
The idle task is meant to sit in a loop if there are no other tasks that can run so the problem seems to be that none of your other tasks are wanting to do anything.
</div></div><div class="thread-post"><h3 class="thread-post-title">OS hangs in portTASK_FUNCTION</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on February 4, 2009</div><div class="thread-post-content">Interrupts above kernel priority are not allowed to call freeRTOS routines, so I suspect you are corrupting some system data.
When freeRTOS is manipulating critical data, is enters a critical section which disables interrupts of kernel level and below so nothing else will try and adjust the data area while it is being updated. If an interrupt above kernel level calls an RTOS routine, it may manipulate that area that is in the middle of being manipulated and mess it up.
</div></div><div class="thread-post"><h3 class="thread-post-title">OS hangs in portTASK_FUNCTION</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/alainm3">alainm3</a> on February 4, 2009</div><div class="thread-post-content">Please Richard Barry, can you comment on this, because from what I understand:
1&#41; IRQ are suposed to be above kernel piority
2&#41; it is safe to call from ISR functions named fromISR
</div></div><div class="thread-post"><h3 class="thread-post-title">OS hangs in portTASK_FUNCTION</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on February 4, 2009</div><div class="thread-post-content">It if fine to call any API function that ends in &quot;FromISR&quot; from within an ISR &#8211; but no others.
I cannot answer point 1&#41; because I don&#8217;t know which port you are using.
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">OS hangs in portTASK_FUNCTION</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on February 4, 2009</div><div class="thread-post-content">Richard,
Your documentation says that for ports that support configMAX&#95;SYSCALL&#95;INTERRUPT&#95;PRIORITY, then that is the highest level interrupt that can call the FromISR routines, and that those ports support not disabling all interrupts when in a critical section.
</div></div><div class="thread-post"><h3 class="thread-post-title">OS hangs in portTASK_FUNCTION</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on February 4, 2009</div><div class="thread-post-content">That is correct.&nbsp; Interrupts at priority level configMAX&#95;SYSCALL&#95;INTERRUPT&#95;PRIORITY and below can call API functions that end in &quot;FromISR&quot;.&nbsp; Interrupts that are above that priority cannot call any API functions.&nbsp; API functions that do not end if &quot;FromISR&quot; must not be called from any interrupts.
Sorry if I&#8217;m not being clear &#8211; its been a long day.
Its difficult to answer definitively without knowing the port being used.
Regards.
