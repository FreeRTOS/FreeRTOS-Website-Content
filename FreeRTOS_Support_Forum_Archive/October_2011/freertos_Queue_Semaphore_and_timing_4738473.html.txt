  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Queue, Semaphore and timing</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/gerhardkreuzer">gerhardkreuzer</a> on October 4, 2011</div><div class="thread-post-content">Hi,<br />
my problem:<br />
I want to transmit some messages, which takes time &#40;USART …&#41;. I post one message after the other using a queue and after the first post I tell the hardware to start transmitting. After the hardware has sent the first message, the next message is taken and so on, in the meantime more messages will be created and put in the queue.<br />
After creating all messages, I know the number, I have to wait for the end of transmission of the last message. Not the end of any message or the beginning of the transmission of the last message or whatever.<br />
So, waiting until the queue runs dry isn&#8217;t the correct way.<br />
Has anybody some idea to manage this situation in some elegant way with FreeRTOS?  
Thanks.  
With best regards  
Gerhard
</div></div><div class="thread-post"><h3 class="thread-post-title">Queue, Semaphore and timing</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on October 4, 2011</div><div class="thread-post-content">You would have to implement something in the UART interrupt handler.&nbsp; For example, presumably the UART will continue transmitting for as long as there is data to transmit.&nbsp; When the queue is empty, and the last message received from the queue has been sent completely, the UART interrupt will know, and can set a semaphore to indicate such.&nbsp; The task can then take the semaphore before it starts sending messages to the Tx queue, then block on the semaphore again once it has posted all the messages to the queue.&nbsp; When the task unblocks, it knows the UART Tx interrupt has finished.  
Regards.
