  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Task Critical blocks USB</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/roystondsouza">roystondsouza</a> on October 10, 2011</div><div class="thread-post-content">I am using free RTOS on STM32 hardware which I have designed. There is an STM32F103RG MCU connected to an accelerometer &#40;MMA8415Q&#41;, gyroscope&#40;L3G2400D&#41; and USB. The accelerometer is ineterfaced on I2C and Gyroscope on SPI. For the accelerometer and gyroscope routines I use taskENTER&#95;CRITICAL and taskEXIT&#95;CRITICAL during the I2C and SPI access. At the beginning of the program I just read the accelerometer and Gyroscope device ID registers. After this I go ahead and init the USB section for using VCOM.  
If I read the accelerometer and Gyrocope registers, the USB is not enumerated by Windows and says Windows cannot recognise device.<br />
If i comment out the taskENTER&#95;CRITICAL and taskEXIT&#95;CRITICAL from the accelerometer and Gyroscope routines then the Windows enumerated USB properly.  
Can anyone advise on the above problem.  
Thanks..  
Royston
</div></div><div class="thread-post"><h3 class="thread-post-title">Task Critical blocks USB</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on October 10, 2011</div><div class="thread-post-content">You are asking about application design, not really FreeRTOS, but if the critical section is preventing interrupts that are needed to enumerate the USB then the critical section must be very very long, which is never good. If there is only one device on I2C and one device on SPI, then I doubt a critical section is needed around the whole access, and suspect it will only be needed around the access of any registers that are shared by the two serial buses. You might have better luck using scheduler locking, which will leave interrupts enabled, or making the USB interrupt above configMAX&#95;SYSCALL&#95;INTERRUPT&#95;PRIORITY if it does not make any FreeRTOS API calls.
</div></div><div class="thread-post"><h3 class="thread-post-title">Task Critical blocks USB</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/roystondsouza">roystondsouza</a> on October 10, 2011</div><div class="thread-post-content">Thank you davedoors for your reply.

&nbsp; NVIC&#95;InitStructure.NVIC&#95;IRQChannelPreemptionPriority = 14;<br />
&nbsp; NVIC&#95;InitStructure.NVIC&#95;IRQChannelSubPriority = 0;<br />

And my FreeRTOS SYSCALL priority is as follows:  
/&#42; This is the raw value as per the Cortex-M3 NVIC.&nbsp; Values can be 255 &#40;lowest&#41; to 0 &#40;1?&#41; &#40;highest&#41;. &#42;/  
&#35;define configKERNEL&#95;INTERRUPT&#95;PRIORITY 255<br />
&#35;define configMAX&#95;SYSCALL&#95;INTERRUPT&#95;PRIORITY 191 /&#42; equivalent to 0xa0, or priority 5. &#42;/
