</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS &#038; IAR Debug on the IAR Simulator</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on October 27, 2011</div><div class="thread-post-content">I don&#8217;t know about the IAR simulator specifically, but the only simulator &#40;for any architecture&#41; I have ever successfully run FreeRTOS in without having to change anything is the Keil one.&nbsp; That is because most simulators only simulate the core.&nbsp; If the code does something like configure a PLL and wait for it to lock, the code will just hang, as there is no PLL simulation.&nbsp; You can normally spot that because if you stop the simulator and look at which code it is executing you will find it is sat in a tight loop waiting for a register to change &#8211; when the register does not even exist in the simulation &#40;that often happens even before main&#40;&#41; has been called&#41;.&nbsp; You can work around this by selectively commenting out bits of code, but I don&#8217;t think you will get the Ethernet working in the simulator whatever.  
If you have V6.21 of the IAR tools then I don&#8217;t think you need to change or install anything to use the plug-in &#8211; it is shipped with IAR pre-installed.&nbsp; As you say, under the debug options, on the plug-ins tab &#40;from memory&#41; you just check the box next to FreeRTOS &#40;some versions may call it OpenRTOS&#41;, then start a debug session.  
Regards.
