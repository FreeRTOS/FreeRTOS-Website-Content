I&#8217;m new to the FreeRTOS and I&#8217;ve being working on using it with a m52259evb from Freescale.<br />
Since on my company we won&#8217;t use ColdWarrior, I did some modifications so I could use the Demo files from the 52233 with the 52259 under eclipse. It took me a little time to get the hang of it but now I can turn the evb LEDS on and off &#40;I know it might not sound much but I&#8217;m getting used to the board and FreeRTOS&#41;.<br />
However, for a short period I used MQX and when I did a printf, I could see the output on a minicom terminal connected to the board serial port. I belive the same should happen with FreeRTOS, but I can&#8217;t get the printf to work &#40;it compiles and all but nothing shows up&#41;.<br />
I did copy the printf-stdargs.c from the 52259 demo project but still nothing.<br />
Am I missing some sort of configuration? I&#8217;m kinda lost here.  
Thanks a lot<br />
Ariel
</div></div><div class="thread-post"><h3 class="thread-post-title">Printf on m52259evb</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/erupter">erupter</a> on October 5, 2011</div><div class="thread-post-content">I don&#8217;t know the specific platform, but usually onboard hardware modules &#40;like the UART/USART you plan to use&#41; need be configured for operation.<br />
In the USART case things most probably needed are:<br />
-sync/async<br />
-parity<br />
-stop bits<br />
-baudrate<br />
-module enabled/disabled  
Maybe check the mcu manual?
</div></div><div class="thread-post"><h3 class="thread-post-title">Printf on m52259evb</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/erupter">erupter</a> on October 5, 2011</div><div class="thread-post-content">Also there &#42;might&#42; already be a configuration lingering from the original demo, but it might be wrong for the selected micro.
</div></div><div class="thread-post"><h3 class="thread-post-title">Printf on m52259evb</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on October 6, 2011</div><div class="thread-post-content">printf-stadarg.c is provided as a very light weight &#40;in both code and RAM&#41; alternative to standard library printf&#40;&#41;/sprintf&#40;&#41; functions. If you include it in your project it will replace the printf&#40;&#41;/sprintf&#40;&#41; that comes with your compiler. It is likely that the printf&#40;&#41;/sprintf&#40;&#41; that comes with your compiler has an option to direct its output to the UART already, if you look for it. If you use printf-stdarg.c then you have to do that yourself. They way to do it is set up a UART with the baud rate and other parameters as already suggested in this thread, then in printf-stdarg.c implement a putchar&#40;&#41; to write the char to the UART. You will also have to remove the line &#8220;&#35;define putchar(C) c&#8221; from the top of printf-stdarg.c, else your putchar&#40;&#41; implementation will get &#35;defined to nothing.
