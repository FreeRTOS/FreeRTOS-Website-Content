  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Precious time delay for all tasks</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/gridsense">gridsense</a> on October 29, 2011</div><div class="thread-post-content">I have some function require precious time delay, it maybe at any task with different priority. I am not sure how to do it properly in RTOS.  
For example I need a 100mS pulse, the code as below:  
PintA&#95;Output&#95;High;<br />
vTaskDelay&#40; 10&#95;Ticks&#41;;&nbsp; // 100 mS delay.<br />
PintA&#95;Outpou&#95;Low;  
If those code in low priority task, the pulse will be longer than 100mS, because after &#8220;vTaskDelay&#40; 10&#95;Ticks&#41;&#8221; the CPU may execute other higher priority tasks.  
</div></div><div class="thread-post"><h3 class="thread-post-title">Precious time delay for all tasks</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on October 29, 2011</div><div class="thread-post-content">If it is very important that it be not delayed, then it needs to be a top priority task.  
Note that there is already some variation built into the program, as a 10 tick delay &#40;unless just after another delay&#41; can be as short as just above 9 ticks, as the remainder of the current tick is the first tick of delay, no matter how much or little of it left.  
If you really need an accurate pulse, and the software methods aren&#8217;t doing well enough, you may need to switch to a dedicated timer, which you can start at just the right point in time, and tells you when to stop and just the right point in time.
