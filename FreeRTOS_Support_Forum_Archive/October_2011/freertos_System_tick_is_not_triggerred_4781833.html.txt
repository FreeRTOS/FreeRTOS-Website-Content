</div></div><div class="thread-post"><h3 class="thread-post-title">System tick is not triggerred</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/brakova">brakova</a> on October 31, 2011</div><div class="thread-post-content">Hi,  
I finally got it and I think that it&#8217;s a good thing to share it with you so that if anyone else happen to have the same problem it would be easier to find a solution.  
If you want to run the FreeRTOS examples with the IAR Simulator you have to first choose the Simulator as your Debugger Driver in the Project options and secondly &#8211; you need to set up the Simulator Interrupts you want to have.<br />
You go to Simulator &gt; Interrupts Setup. As you already know &#8211; The FreeRTOS needs SVC, SysTick and PendSV interrupts. However you need to set up the SysTick only and it will consiquently trigger the other two interrupts.<br />
You need to add the SysTick interrupt. You have to set the required parameters. My example works fine with the following settings:  
• First activation &#8211; 5000000 &#8211; Specify the value of the cycle counter after which the specified type of interrupt will be generated.<br />
• Repeat Interval &#8211; 100000 &#8211; Specify the periodicity of the interrupt in cycles.<br />
• Hold time &#8211; 100000 &#8211; Specify how long, in cycles, the interrupt remains pending until removed if it has not been processed. If you select Infinite, the corresponding pending bit will be set until the interrupt is acknowledged or removed.<br />
• Variance &#8211; 0 &#8211; Selects a timing variation range, as a percentage of the repeat interval, in which the interrupt might occur for a period. For example, if the repeat interval is 100 and the variance 5%, the interrupt might occur anywhere between T=95 and T=105, to simulate a variation in the timing.<br />
• Probability &#8211; 100 &#8211; Selects the probability, in percent, that the interrupt will actually occur within the specified period.
