  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Random hangs with STM32</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/*anonymous">*anonymous</a> on October 12, 2011</div><div class="thread-post-content">I&#8217;m running FreeRTOS V6.0.3 on an STM32 &#40;STM32F107RCT&#41;. I am randomly getting three different types of problems when I run the project:  
1&#41; Hard fault   
2&#41; Code hangs in the 
<pre><code>for( pxIterator = ( xListItem * ) &amp;( pxList-&gt;xListEnd ); pxIterator-&gt;pxNext-&gt;xItemValue &lt;= xValueOfInsertion; pxIterator = pxIterator-&gt;pxNext )
</code></pre>
loop of list.c  
3&#41; Code hangs in 
<pre><code>while( uxMissedTicks &gt; ( unsigned portBASE_TYPE ) 0 )
</code></pre>
loop of tasks.c &#40;due to uxMissedTicks being a very large number i.e. &gt;0xFF000000&#41;  
I have searched this forum and found several posts that seem to be for this issue revolving around the setup of interrupts. I have the following settings:  
&#35;define configKERNEL&#95;INTERRUPT&#95;PRIORITY 0xFF&nbsp;&nbsp;&nbsp; // Equivalent to priority 15 &#40;lowest&#41;<br />
&#35;define configMAX&#95;SYSCALL&#95;INTERRUPT&#95;PRIORITY 0x00&nbsp;&nbsp;&nbsp; // Equivalent to priority 0 &#40;highest&#41;  
Which should allow me to use interrupts with priorities between 1 and 15 I think. I am setting the interrupts I use to priority 13 with the following code:  
<pre><code>    NVIC_PriorityGroupConfig(NVIC_PriorityGroup_4);                         
    NVIC_InitStructure.NVIC_IRQChannel                      = SPI1_IRQChannel;
    NVIC_InitStructure.NVIC_IRQChannelPreemptionPriority    = 13;          
    NVIC_InitStructure.NVIC_IRQChannelSubPriority           = 0;
    NVIC_InitStructure.NVIC_IRQChannelCmd                   = ENABLE;
    NVIC_Init(&amp;NVIC_InitStructure);
</code></pre>
To check this I look in the Peripherals-&gt;Core Peripherals-&gt;NVIC window and I can see that the interrupts that I&#8217;m using are all set to priority 13. There seems to be five interrupts enabled &#40;other than the ones I define&#41;:  
&#45; Non-maskable interrupt NMI &#40;priority = -2&#41;<br />
&#45; Hard fault HARDFAULT &#40;priority = -1&#41;<br />
&#45; System service call SVCALL &#40;priority = 0&#41;<br />
&#45; Pend system service PENDSV &#40;priority = 15&#41;<br />
&#45; System tick timer SYSTICK &#40;priority = 15&#41;  
Does this look correct for these?  
Another cause from the forum posts is a stack overflow. I have switched on the FreeRTOS stack checking with 
<pre><code>#define configCHECK_FOR_STACK_OVERFLOW  2
</code></pre>
and provided a vApplicationStackOverflowHook&#40;&#41; function to catch a stack overflow. This never gets reached so my assumption is that the problem is not a stack issue.  
Does anyone have any thoughts on what I might be doing wrong?   
Thanks.
</div></div><div class="thread-post"><h3 class="thread-post-title">Random hangs with STM32</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on October 12, 2011</div><div class="thread-post-content">As you are using an STM32, I would also say make sure that all the priority bits are set as being preemption priority bits.&nbsp; Most systems do that by default, but not the STM32 libraries.&nbsp; To set them call NVIC&#95;PriorityGroupConfig&#40; NVIC&#95;PriorityGroup&#95;4 &#41;;  
<blockquote>
  &#35;define configKERNEL&#95;INTERRUPT&#95;PRIORITY 0xFF&nbsp;&nbsp;&nbsp; // Equivalent to priority 15 &#40;lowest&#41;<br />
  &#35;define configMAX&#95;SYSCALL&#95;INTERRUPT&#95;PRIORITY 0x00&nbsp;&nbsp;&nbsp; // Equivalent to priority 0 &#40;highest&#41;
</blockquote>
You always have to take care on Cortex-M3 devices that priorities are set in accordance with the semantics of the library being used to set them.&nbsp; Some want the priority set with the bits already shifted to the correct positions, some with the bits in the lowest significant places in the priority byte to allow the library function to do the shift itself.&nbsp; The way you have intended to set these two parameters should, logically, effectively remove the any possibility of getting that wrong though, as it should prevent any interrupt nesting at all.&nbsp; <strong>However</strong>, unfortunately 0 is not a valid interrupt priority, and has a special meaning on the Cortex-M3.&nbsp; You cannot set a mask value of 0, and setting it to zero actually means you are not masking any interrupts at all, and those settings will definitely cause problems.  
If you want a really simple test to see if interrupt nesting is causing a problem, then set both these parameters to 0xFF, then set all interrupt priorities in your code to 15.&nbsp; That way, everything will use the lowest interrupt priority, and nothing will nest.&nbsp; That would mean making the change from  
<pre><code>NVIC_InitStructure.NVIC_IRQChannelPreemptionPriority = 13
</code></pre>
to 
<pre><code>NVIC_InitStructure.NVIC_IRQChannelPreemptionPriority = 15
</code></pre>
for all interrupts.&nbsp; Also make sure the sub priority is set to 0.&nbsp; Once you have established if that fixes your problem, then you can work on having the priorities set how you actually want them, to get the benefit from interrupt nesting too.  
Regards.

Thanks for your quick response. I actually seem to have solved the problem by changing configMAX&#95;SYSCALL&#95;INTERRUPT&#95;PRIORITY to 0x10. This sets it at a lower priority than the system service call SVCALL. Perhaps someone could explain why this might have made a difference? I was just trying to ensure that no user defined interrupts could be a higher priority by setting it to 0x00 but I&#8217;ve not seen any evidence that anyone else has used such a high &#40;in priority terms&#41; value. Most people seem to use 191 &#40;priority 11&#41;.
