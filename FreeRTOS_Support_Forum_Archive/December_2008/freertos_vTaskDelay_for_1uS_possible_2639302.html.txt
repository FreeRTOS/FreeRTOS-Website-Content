  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">vTaskDelay for 1uS, possible?</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/willywortel">willywortel</a> on December 3, 2008</div><div class="thread-post-content">First of all, thanks everyone for the response so far. You really helped me out&#33;
But again, i have another question. I managed to get USB HID working under FreeRtos. However, during enumeration some USB hosts require a &#40;small&#41; response every 100uS.
I tried to increase the tick rate, but when set the value to 10.000, the whole OS stopped working. Apparently the OS is consuming too much CPU now.
What is the best way to solve this problem? I&#96;m thinking about using an external timer interrupt every 100uS. But i was wondering if there are more/better ways to do.
</div></div><div class="thread-post"><h3 class="thread-post-title">vTaskDelay for 1uS, possible?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/edwards3">edwards3</a> on December 3, 2008</div><div class="thread-post-content">I don&#8217;t know anything in USB that requires this resolution. But if you really need to do that use a hardware timer.
</div></div><div class="thread-post"><h3 class="thread-post-title">vTaskDelay for 1uS, possible?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/willywortel">willywortel</a> on December 4, 2008</div><div class="thread-post-content">Well, actually at 1mS refresh rate &#40;using the delayUntil&#41; gives me a message in windows that the USB device cannot be started &#40;code 10&#41;.
When i put the function in a continuous loop, without delay calls, then it works correctly. But then off course the OS gets stalled because the USB task consumes all of the processing power.
The strange thing is that with the 1mS delayUntil, the USB does work correctly on my notebook. But not on my PC. 
Anyway, I&#96;m thinking to use the USB on board interrupts instead of a polling loop. I think that should work.
Thanks for the reply.
</div></div><div class="thread-post"><h3 class="thread-post-title">vTaskDelay for 1uS, possible?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/spacewrench">spacewrench</a> on December 10, 2008</div><div class="thread-post-content">Delays on the order of microseconds almost certainly have to be done with either a hardware timer &#40;and you just monitor the count value&#41; or with a timed sequence of instructions &#40;like NOPs&#41;.&nbsp; But for USB work &#40;and I&#8217;m just getting to the &quot;oh, I see&quot; stage with that&#41; you really have to use interrupts.&nbsp; As you&#8217;ve discovered, it&#8217;s very timing-sensitive, but if you&#8217;re on the device side, the timing is pretty much not up to you.&nbsp; The reason to use an RTOS is so you can do something else while you&#8217;re waiting for the host to demand that you do the next thing, within the next X microseconds.&nbsp; You can poll, but you&#8217;re wasting a lot of time.
For very initial development, I had fair results by calling the ISR in a tight loop from an ordinary task.&nbsp; However, this risks having things work &#40;or not&#41; because of random lucky &#40;or unlucky&#41; timing coincidences.&nbsp; For example, I was able to get enumeration to work this way, but only if I had certain debugging messages turned on.&nbsp; The problem was, with the messages, I was pausing long enough for a STATUS phase to complete, but without, I was doing the next thing too soon.&nbsp; The correct solution is to key off the STATUS-PHASE-COMPLETE interrupt.
