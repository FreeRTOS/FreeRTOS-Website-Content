  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">passing strings between tasks</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/daverm">daverm</a> on December 10, 2008</div><div class="thread-post-content">What&#8217;s the best way to pass strings between tasks?
1&#46; xQueueCreate&#40; maxstringlength, sizeof&#40; char &#41; &#41;;
2&#46; xQueueCreate&#40; 1, maxstringlength &#41;; //inefficient because it copies MAX string length instead of actual string length
3&#46; xQueueCreate&#40; 1, sizeof&#40; char&#42; &#41; &#41;; //also requires semaphores
4&#46; semaphores around a global string?
Thx,
Dave
</div></div><div class="thread-post"><h3 class="thread-post-title">passing strings between tasks</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/spacewrench">spacewrench</a> on December 10, 2008</div><div class="thread-post-content">Depends whether the receiving task needs to modify the string, and whether the sending task needs its own copy, or needs to release the memory or whatever.&nbsp; For strings that are const after sending &#40;no task needs to modify or delete them&#41;, I&#8217;d go with 3.&nbsp; If you&#8217;re really trying to pass a buffer of data from a producer to a consumer &#40;for example&#41;, and have the producer generate more data after the consumer is finished, then I&#8217;d go with 4: semaphores around a global buffer.
</div></div><div class="thread-post"><h3 class="thread-post-title">passing strings between tasks</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/daverm">daverm</a> on December 10, 2008</div><div class="thread-post-content">Thx Dave.
4 it is.
The producer is generating variable sized non-const &#8216;debug&#8217; strings that are output to a port by the consumer.
</div></div><div class="thread-post"><h3 class="thread-post-title">passing strings between tasks</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/spacewrench">spacewrench</a> on December 10, 2008</div><div class="thread-post-content">Oh yeah, totally.&nbsp; That&#8217;s a great way to handle debugging output &#40;everything spews into a common circular buffer, and some low-priority task prints it out when it has a chance&#41;.&nbsp; It can get pretty complex if you&#8217;re doing timestamping and making sure messages interleave on a line-by-line basis, plus the buffer has to be pretty big if you have a lot of high-priority output, but a robust debug/error reporting scheme makes development MUCH easier.
