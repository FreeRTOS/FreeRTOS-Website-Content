when I add the interrupt initialization code, the task won&#8217;t start.<br />
Here&#8217;s the code:  
<pre><code>void initInterr()
{
    AT91F_AIC_ConfigureIt(AT91C_BASE_AIC, AT91C_ID_PIOA, 5, AT91C_AIC_SRCTYPE_INT_HIGH_LEVEL,ChangeFlashRate);
    AT91F_AIC_EnableIt(AT91C_BASE_AIC, AT91C_ID_PIOA);
    AT91C_BASE_PIOA-&gt;PIO_IER = AT91C_PIO_PA19; // B1
}
void vStartLEDFlashTasks()
{
    initInterr();
    xTaskCreate( vLEDBlink, ( signed char * ) "LEDtaskC", configMINIMAL_STACK_SIZE, NULL, tskIDLE_PRIORITY + 2, NULL );
}
void ChangeFlashRate()
{
    int status;
    status = AT91C_BASE_PIOA-&gt;PIO_ISR;
    vParTestToggleLED( 0 );
}
</code></pre>
As you can see it&#8217;s very simple. I&#8217;m using SAM7-P64 dev board. Am i doing it wrong?

</div></div><div class="thread-post"><h3 class="thread-post-title">Interrupt handling in FreeRTOS</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/barbart1">barbart1</a> on June 8, 2010</div><div class="thread-post-content">Hi, I bought the manual and changed my code, but interrupts still don&#8217;t work. Everything seems to be ok. Is the ISR written correctly?  
<pre><code>void ToggleLedISR()
{
    int status;
    static portBASE_TYPE xHigherPriorityTaskWoken = pdFALSE;
    status = AT91C_BASE_PIOA-&gt;PIO_ISR;
    xSemaphoreGiveFromISR(xSemafor, &amp;xHigherPriorityTaskWoken);
    if(xHigherPriorityTaskWoken == pdTRUE) {
        AT91C_BASE_AIC-&gt;AIC_EOICR = 0xFA;
        portYIELD_FROM_ISR();
    }
}
</code></pre>
Here&#8217;s the task that takes the semaphore:  
<pre><code>void ToggleLedTask(void *pvParameters) {
    while(1) {
        xSemaphoreTake(xSemafor, portMAX_DELAY);
        vParTestToggleLED( 0 );
    }
}
</code></pre>
</div></div><div class="thread-post"><h3 class="thread-post-title">Interrupt handling in FreeRTOS</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on June 8, 2010</div><div class="thread-post-content">Not familiar with this processor, but the line<br />
AT91C&#95;BASE&#95;AIC-&gt;AIC&#95;EOICR = 0xFA;<br />
would be my guess at the error. I presume this is an end of interrupt control, and probably doesn&#8217;t want to be conditioned on xHigherPriorityTaskWoken. I would suggest placing it before the if statement.
</div></div><div class="thread-post"><h3 class="thread-post-title">Interrupt handling in FreeRTOS</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/barbart1">barbart1</a> on June 8, 2010</div><div class="thread-post-content">I got it working. It seems that an interrupt handler that gives a token to a semaphore needs to be called from a wrapper that copies the context. I got it working with:  
<pre><code>void vLed_ISR_Wrapper( void )
{
    /* Save the context of the interrupted task. */
    portSAVE_CONTEXT();
    /* Call the handler itself.  This must be a separate function as it uses
    the stack. */
    __asm volatile ("bl vLed_ISR_Handler");
    /* Restore the context of the task that is going to
    execute next. This might not be the same as the originally
    interrupted task.*/
    portRESTORE_CONTEXT();
}
</code></pre>
Now, correct me if I&#8217;m wrong, but that is the only way I managed to get it done. Without the wrapper the processor &#8220;hangs&#8221; itself. And of course both the wrapper and the handler must be compiled in ARM mode. Or is there a way without using a wrapper?
</div></div><div class="thread-post"><h3 class="thread-post-title">Interrupt handling in FreeRTOS</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on June 8, 2010</div><div class="thread-post-content">If your interrupt is wanting to cause a context switch, or wanting to call a FreeRTOS API function, then the wrapper is required &#8211; as per the documentation and examples.
