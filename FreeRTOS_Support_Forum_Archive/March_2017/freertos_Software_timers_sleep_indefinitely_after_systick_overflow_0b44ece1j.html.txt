  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Software timers sleep indefinitely after systick overflow</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/kelvinelton">kelvinelton</a> on March 10, 2017</div><div class="thread-post-content">I am currently developing a project with FreeRTOS (v8.2.1) on ARM Cortex-M3 (STM32F103xE) and IAR Compiler and all the software timers callbacks stopped being called after a systick overflow.
I also created a minimal example and the result was the same. The timer worked just fine until the overflow on xTickCount.  Am I missing something here or is there really a bug?
I also tried to create the timer within a task, or starting it after osKernelStart(), but it&#8217;s always the same result.
FreeRTOSConfig.h:
~~~
&#8230;
<h1>define configUSE<em>16</em>BIT_TICKS                   1</h1>
<h1>define configTICK<em>RATE</em>HZ                       ((TickType_t)1000)</h1>
<h1>define configUSE_TIMERS                         1</h1>
<h1>define configTIMER<em>TASK</em>PRIORITY                3</h1>
<h1>define configTIMER<em>QUEUE</em>LENGTH                 6</h1>
<h1>define configMINIMAL<em>STACK</em>SIZE                 ((uint16_t)128)</h1>
<h1>define configTIMER<em>TASK</em>STACK<em>DEPTH             configMINIMAL</em>STACK_SIZE</h1>
&#8230;
~~~
main.c:
~~~
static volatile uint32<em>t testtick = 0;
TimerHandle</em>t test_timer = NULL;
void testticktimer(void * n) {
    testtick += 10;
}
int main() {
    // Hardware configuration (clock, systick, &#8230;)
    test<em>timer = xTimerCreate(&#8220;test</em>timer&#8221;, pdMS<em>TO</em>TICKS(10), pdTRUE, (void *) 2, testticktimer);
    xTimerStart(test_timer, 0);
    osKernelStart();
    while(1){}
}
~~~
</div></div><div class="thread-post"><h3 class="thread-post-title">Software timers sleep indefinitely after systick overflow</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on March 10, 2017</div><div class="thread-post-content">The behaviour of software timers when the tick overflows is very well tested. In addition soak tests that use a 16-bit counter, which results in frequent overflows, run for months with no failures. That doesn&#8217;t mean there are not bugs though, just that if there are our tests don&#8217;t find them.
It looks like you are using an abstraction layer on top of the FreeRTOS API. My first suggestion would be to try using the native API directly. If you still have a demostatable issue after that please create the smallest project possible that exhibits the behaviour along with instructions on how to observe the error and we can investigate.
</div></div><div class="thread-post"><h3 class="thread-post-title">Software timers sleep indefinitely after systick overflow</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/kelvinelton">kelvinelton</a> on March 13, 2017</div><div class="thread-post-content">Actually I was using the version 8.2.2 and the problem occurs only in this version.
I tried 8.2.1 or 8.2.3 and it worked as excepted. It&#8217;s probably the same bug fix related to tickless low power applications.
</div></div><div class="thread-post"><h3 class="thread-post-title">Software timers sleep indefinitely after systick overflow</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on March 13, 2017</div><div class="thread-post-content">Didn&#8217;t realise you were using tickless &#8211; tickless and software timers 
didn&#8217;t used to work together but that was changed some versions ago.
