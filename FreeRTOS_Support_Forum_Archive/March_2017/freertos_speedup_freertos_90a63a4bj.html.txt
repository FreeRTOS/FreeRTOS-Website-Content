  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">speedup freertos</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/mastupristi">mastupristi</a> on March 1, 2017</div><div class="thread-post-content">Hi,
I have an STM32F410 cortex M4 clocked @100MHz. I notify an high priority task from another, with lower priority, using <em>xTaskNotifyGive()/ulTaskNotifyTake()</em>.
The firmware is  compiled with arm-gcc:
~~~
~$ arm-none-eabi-gcc &#8211;version
arm-none-eabi-gcc (GNU Tools for ARM Embedded Processors) 5.4.1 20160609 (release) [ARM/embedded-5-branch revision 237715]
~~~
and I already use <em>-O3</em> optimization.
Moving a pin I can measure time between notification and task wakeup. It is about <strong>4us</strong>.
Is it possible to speed up notification (I think also context switch)?
best regards
Max
</div></div><div class="thread-post"><h3 class="thread-post-title">speedup freertos</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on March 1, 2017</div><div class="thread-post-content">Hi Max
There are many factors influencing this delay between <code>vTaskNotifyGiveFromISR()</code> and <code>ulTaskNotifyTake()</code>.
Compiler optimisation, for GCC, use -Os or -O3. I tend to like -Os ( optimise for size )
Once you&#8217;re ready debugging, stop using <code>configASSERT()</code> and stop checking the for stack overflows.
Make sure that the task that you are waking-up has the highest priority of all tasks that are runnable at that moment.
Please let us hear
</div></div><div class="thread-post"><h3 class="thread-post-title">speedup freertos</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/hs2sf">hs2sf</a> on March 1, 2017</div><div class="thread-post-content">I also tend to use -Os instead of -O3 with GCC. In addition I get pretty good results using link time optimization (LTO) ie. using -flto. At least it saves even more code space which usually also improves runtime performance.
</div></div><div class="thread-post"><h3 class="thread-post-title">speedup freertos</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on March 1, 2017</div><div class="thread-post-content">Stack overflow detection is the feature that takes the most time to execute.
As has already been said, turning off run time stats, asserts, tick 
hooks, etc. all help.  The context switch itself is not the limiting factor.
