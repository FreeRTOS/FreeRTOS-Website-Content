  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">FreeRTOS won&#8217;t build on GCC if Linker Time Optimization is set (issue for STM32 ARM CM-7 &#8211; port.c:427: undefined reference to `vTaskSwitchContext)</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/daveharr">daveharr</a> on March 10, 2017</div><div class="thread-post-content">Hello, FreeRTOS won&#8217;t build on GCC if Link-Time Optimization (-flto) is set. (issue for STM32 ARM CM-7)
I consistently get this error in port.c:427: undefined reference to vTaskSwitchContext). 
The vTaskSwitchContext() function is clearly defined in tasks.c. This problem can be fixed in tasks.h if vTaskSwitchContext is declared thus at line 2172: void vTaskSwitchContext( void ) PRIVILEGED_FUNCTION <strong>attribute</strong>((used)); For some reason the double underscores  before and after the word attribute do not appear in the post.
Can you fix this so that this is include in the next release? I realize this is GCC dependent so you&#8217;d have to make it apply only for a GCC build.
Thanks.
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS won&#8217;t build on GCC if Linker Time Optimization is set (issue for STM32 ARM CM-7 &#8211; port.c:427: undefined reference to `vTaskSwitchContext)</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on March 10, 2017</div><div class="thread-post-content">We can&#8217;t put GCC specific code in a non-GCC specific file.  What happens 
if you add this prototype to the port.c file specific to the Cortex-M 
port you are using?  Then there will be two prototypes for the same 
function visible to the file, so it might puke.
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS won&#8217;t build on GCC if Linker Time Optimization is set (issue for STM32 ARM CM-7 &#8211; port.c:427: undefined reference to `vTaskSwitchContext)</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/daveharr">daveharr</a> on March 10, 2017</div><div class="thread-post-content">I tried that &#8211;  i.e. putting the prototype
void vTaskSwitchContext( void ) PRIVILEGED_FUNCTION <strong>attribute</strong>((used));
in port.c. The GCC compiler doesn&#8217;t object but it doesn&#8217;t get rid of the undefined reference to vTaskSwitchContext either.  That is because the link time optimizer is optimizing away the actual vTaskSwitchContext function defined in tasks.c because it doesn&#8217;t see it referenced anywhere.
It is the tasks.c source code file that needs to have that prototype, or the equivalent of it somewhere.
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS won&#8217;t build on GCC if Linker Time Optimization is set (issue for STM32 ARM CM-7 &#8211; port.c:427: undefined reference to `vTaskSwitchContext)</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/xz8987f">xz8987f</a> on March 10, 2017</div><div class="thread-post-content">This is what I have done in all my FreeRTOS ports:
Using this in task.h:
~~~
<h1>ifdef <strong>GNUC</strong> /* &lt;&lt; EST: &#8216;used&#8217; attribute need for LTO (Link Time Optimization) */</h1>
  void vTaskSwitchContext( void ) PRIVILEGED_FUNCTION <strong>attribute</strong>((used));
<h1>else</h1>
  void vTaskSwitchContext( void ) PRIVILEGED_FUNCTION;
<h1>endif</h1>
~~~
Using this in task.c:
~~~
<h1>ifdef <strong>GNUC</strong> /* &lt;&lt; EST */</h1>
<strong>attribute</strong>((used)) /* using C++ compiler, vTaskSwitchContext() might be removed even with -O0? */
<h1>endif</h1>
void vTaskSwitchContext( void )
~~~
I have seen that problem both with -Lto and compiling the RTOS in C++ mode.
I agree that using compiler specifc things like above is not ideal, but worked for me.
Another option would be to use some defines in the GCC portmacro.h
Erich

</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS won&#8217;t build on GCC if Linker Time Optimization is set (issue for STM32 ARM CM-7 &#8211; port.c:427: undefined reference to `vTaskSwitchContext)</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on March 11, 2017</div><div class="thread-post-content">Ok &#8211; I had already made that change, but not checked it in, so its easy 
to undo.  Another solution is required.
Presumable if vTaskSwitchContext() was called by C code, rather than 
just asm code, then the compiler/linker would know to keep the function. 
  Can you try calling the function, or at least referencing the 
function, after the scheduler has been started?  The compiler will not 
know that in the GCC port prvPortStartFirstTask() will not return, so 
you can call vTaskSwitchContext() after prvPortStartFirstTask() within 
the xPortStartScheduler() function, which is itself in the 
FreeRTOS/Source/portable/GCC/ARM_CMx/port.c file.  You will notice that 
prvTaskExitError() is already called there for a simliar (but not 
identical) reason.

</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS won&#8217;t build on GCC if Linker Time Optimization is set (issue for STM32 ARM CM-7 &#8211; port.c:427: undefined reference to `vTaskSwitchContext)</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/hs2sf">hs2sf</a> on March 12, 2017</div><div class="thread-post-content">I&#8217;ve added this to compiler/platform specific portmacro.h:
~~~
<h1>ifndef portFORCE_USED</h1>
<pre><code>#define portFORCE_USED  __attribute__(( used ))
</code></pre>
<h1>endif</h1>
~~~
and appended portFORCE_USED to vTaskSwitchContext decl. in task.h:
<code>void vTaskSwitchContext( void ) PRIVILEGED_FUNCTION portFORCE_USED;</code>
This should solve the GCC specfic issue in a generic way.
(see feature req. ticket <strong>#90 LTO Support in FreeRTOS</strong>)
Just my 2ct, HS2
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS won&#8217;t build on GCC if Linker Time Optimization is set (issue for STM32 ARM CM-7 &#8211; port.c:427: undefined reference to `vTaskSwitchContext)</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on March 12, 2017</div><div class="thread-post-content">My guess, is that LTO is looking at the call context of the function to see if it can be profitably inlined, or perhaps some optimiazations for the code are possible, and not seeing any context is omitting the function, but the ASM reference SHOULD raise a flag that there is a (possible) call that is from an unknown context, so the compiler needs to be conservative in optimization. Perhaps the ((used)) attribute is a way of signalling it, but to me it really shouldn&#8217;t be needed.
As Real Time Engineers commented, a simpler fix might just be to put a call to it in C code so it knows it will be needed.
