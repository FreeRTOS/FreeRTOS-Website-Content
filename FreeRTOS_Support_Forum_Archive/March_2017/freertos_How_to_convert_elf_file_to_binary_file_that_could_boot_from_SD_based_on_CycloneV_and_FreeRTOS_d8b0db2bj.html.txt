  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">How to convert elf file to binary file that could boot from SD based on CycloneV and FreeRTOS</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/yycolin">yycolin</a> on March 31, 2017</div><div class="thread-post-content">Hello Everyone.
I am developing a project based on Altera Cyclone V SoC RTOS Demo(http://www.freertos.org/RTOS<em>Altera</em>SoC<em>ARM</em>Cortex-A9.html). That Demo has been ported successfully and debug normally.  Then I try to convert elf file (RTOSDemo.elf) to binary image file which could be stored in a SD card and boot from it, but failed. Two steps I have tried. 
Firstly, use tool &#8220;arm-altera-eabi-objcopy&#8221; as following.
arm-altera-eabi-objcopy -O binary RTOSDemo.elf RTOSDemo.bin
 The size of file named RTOSDemo.elf is 1.85 MB, after converting,the size of RTOSDemo.bin is 3.99 GB.
Secondly, Try use tool &#8220;mkimage&#8221; as following.
mkimage -A arm -T standalone -C none -a 0x100040 -e 0 -n &#8220;Baremetal Image&#8221; -d RTOSDemo.bin main-mkimage.bin
But the shell return as follow.
D:altera15.0embeddedhost_toolsalteramkimagemkimage.exe: Can&#8217;t read RTOSDemo.bin: No error
Could you please give me some suggestion? Thank you very much.
</div></div><div class="thread-post"><h3 class="thread-post-title">How to convert elf file to binary file that could boot from SD based on CycloneV and FreeRTOS</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on March 31, 2017</div><div class="thread-post-content">Not really a FreeRTOS question as such (how do the docs for the Altera 
tools tell you to do this?), but:
<blockquote>
  Firstly, use tool &#8220;arm-altera-eabi-objcopy&#8221; as following.
  arm-altera-eabi-objcopy -O binary RTOSDemo.elf RTOSDemo.bin
  The size of file named RTOSDemo.elf is 1.85 MB, after converting,the
  size of RTOSDemo.bin is 3.99 GB.
</blockquote>
I presume this is because you have a non-contiguous memory map (for 
example, executable code far away from some RAM block), and the gaps 
between the memory regions are just being filled with zeros.
