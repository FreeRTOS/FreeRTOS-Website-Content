  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Strategy to implement a periodic task.</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/simointe">simointe</a> on March 6, 2017</div><div class="thread-post-content">Setup: FreeRTOS version is V9.0.0 (comes from here, download link at file menu), port TMS570.
My current implementation uses wait on notification and timeout value on this notification to be able to react on different events along have a periodic execution in case of no event.
   BaseType<em>t xResult = xTaskNotifyWait( pdFALSE,          // Don&#8217;t clear bits on entry.
                                         ULONG</em>MAX,        // Clear all bits on exit.
                                         &amp;ulNotifiedValue, // Stores the notified value.
                                         nbTick );
The problem is that this design don&#8217;t take into accompt the time to execute the thread itself. For instance, if it takes 200us to run my periodic thread of 1Khz, the resulting frequency will be around 800Hz instead of 1Khz.
A solution could be to use auto-reload timer to notify the task to run, which is in fact to use default timer task to notify my thread.
Is there another solution to make the thread more stand alone than using timer ?
</div></div><div class="thread-post"><h3 class="thread-post-title">Strategy to implement a periodic task.</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on March 6, 2017</div><div class="thread-post-content">Am I right in interpreting this to mean you want to perform periodic 
processing, and handle events in between each processing cycle?
There are two things that might work:
1) Use <a 
href="http://www.freertos.org/vtaskdelayuntil.html">vTaskDelayUntil()</a> 
to get a fixed period, then use <a 
href="http://www.freertos.org/xTaskAbortDelay.html">xTaskAbortDelay()</a> 
to unblock the task when an event needs processing.
2) Continue with a scheme similar to the one you are already using, and 
use <a 
href="http://www.freertos.org/vTaskSetTimeOutState.html">vTaskSetTimeOutState()</a> 
and <a 
href="http://www.freertos.org/xTaskCheckForTimeOut.html">xTaskCheckForTimeOut()</a> 
to adjust the time the task blocks to wait for the event so that the 
task always unblocks when it is time to perform the periodic processing 
again.
</div></div><div class="thread-post"><h3 class="thread-post-title">Strategy to implement a periodic task.</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/simointe">simointe</a> on March 7, 2017</div><div class="thread-post-content">That&#8217;s right I want to perform periodic processing, and handle events in between each processing cycle. But that&#8217;s not my problem here. My problem is that I &#8220;restart&#8221; my waiting (on timeout) AFTER I&#8217;ve done the execution of my task, so this execution time is added to the overall period.
Is there some API functions to soustract this execution time to the next timeout value ?
</div></div><div class="thread-post"><h3 class="thread-post-title">Strategy to implement a periodic task.</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/edwards3">edwards3</a> on March 8, 2017</div><div class="thread-post-content">thats what vTaskDelayUntil() does. When it unblocks is relative to the last time it unblocked so the time between calls doesnt matter.
</div></div><div class="thread-post"><h3 class="thread-post-title">Strategy to implement a periodic task.</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/simointe">simointe</a> on March 9, 2017</div><div class="thread-post-content">Ok, I see.
It&#8217;s look like there is not the same built-in feature within Notification API. I guess I should to it by hand.
</div></div><div class="thread-post"><h3 class="thread-post-title">Strategy to implement a periodic task.</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richarddamon">richarddamon</a> on March 9, 2017</div><div class="thread-post-content">Yes, the timeout parameters for the various API doesn&#8217;t have the same &#8216;until&#8217; feature as DelayUntil.
If you want a timeout for a given period from the point you last got an event, you would need to read the tick couter yourself and adjust.  For me, most of the time the timeout period isn&#8217;t that crutial, but is mostly to detect that something has gone wrong or away, so the variation isn&#8217;t that important, if it is, you will need to correct for it.
