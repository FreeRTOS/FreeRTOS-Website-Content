  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">FreeRTOS Sharing Memory between cores</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/iamshut">iamshut</a> on March 16, 2017</div><div class="thread-post-content">I have some probles with memory reads operations in multiple core platforms. I have a dual-core with a Cortex-A9 with U-Boot and a Cortex-M4with FreeRTOS. From the FreeRTOS I read data pointing to the physical address of the memory:
<pre><code>volatile char readAddressData;
volatile char *writeAddressData = (char *) 0x91F000;
readAddressData = *writeAddressData;
</code></pre>
The data read is checked with U-Boot doing:
    md 91f000
However, if the data of the memory is modified (mw 91f000 aaaaaaaa), the changes are not read in the FreeRTOS. Do somebody know why?
Thank you
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS Sharing Memory between cores</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on March 16, 2017</div><div class="thread-post-content">If the memory is written by one core and read by another you will 
probably need to perform a cache flush after the write before it becomes 
visible to the reader.
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS Sharing Memory between cores</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/iamshut">iamshut</a> on March 17, 2017</div><div class="thread-post-content">I do a &#8220;dchache flush&#8221; after writing in U-Boot. HOwever, the core reading does not detect the changes.
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS Sharing Memory between cores</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on March 17, 2017</div><div class="thread-post-content">As a hardware question this really falls outside of FreeRTOS support.  I 
would recommend describing the issue to the hardware manufacturer and 
see what they recommend.
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS Sharing Memory between cores</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on March 17, 2017</div><div class="thread-post-content">Although this subject is a bit off-topic for FreeRTOS, I&#8217;ll give my two cents:
● Are you sure that there is no memory-address translation within uboot? If you write to address 0x91F000, is that really the first byte of the shared memory?
● Are you sure that the mapping for that physical memory within the Cortex-M4 is the same? Also at address 0x91F000?
● is memory access from within the Cortex-M4 without caching? If not a refresh would be necessary
● and last of all: wouldn&#8217;t it be possible to reserve a block of uncached shared memory for this purpose?
