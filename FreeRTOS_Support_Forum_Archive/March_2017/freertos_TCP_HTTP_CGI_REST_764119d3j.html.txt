  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">+TCP HTTP CGI / REST</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/miclam">miclam</a> on March 23, 2017</div><div class="thread-post-content">Like Michael here https://sourceforge.net/p/freertos/discussion/382005/thread/72bd7781/ I also need a way to deliver data as dynamically created JSON objects and to embed placeholders in HTML files. uIP had CGI routines for that.
Basically what happend there was, that if a requested file had a specific ending (.shtml), instead of just serving the file as-is, it was scanned for placeholders like <code>%! foo</code>. Content up to the placeholder was send, then the script associated with the placeholder was executed and the return was send, then the rest of the file was processed.
I am planning to implement a similar logic, since it should be easy to call FreeRTOS_send() multiple times.
I am aware of the ipconfigHTTP<em>HAS</em>HANDLE<em>REQUEST</em>HOOK, which will be usefull to analyse GET parameters to answer requests like <code>/user.json?id=12</code>.
As soon as I have some code I will append it here, but I&#8217;m already up for comments and feedback.
</div></div><div class="thread-post"><h3 class="thread-post-title">+TCP HTTP CGI / REST</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on April 22, 2017</div><div class="thread-post-content">Hi Michael, sorry for thinking so long about a proper answer to your post.
When I hear &#8220;CGI&#8221;, I&#8217;ve always thought that you need an OS which can at least run a script or a program. It doesn&#8217;t sound like FreeRTOS, which is running tasks, not programs. And &#8216;scripts&#8217;, yes, you can interpret scripts.
I understand the need for flexible HTML code. What we decided, well not &#8220;we&#8221; but the JS (<code>JQuery</code>) programmers that I work with, is to make extensive use of the statement:
~~~
    $(&#8216;#id&#8217;).html( <html code> );
~~~
That is a different way of creating flexible HTML code.
The actual <code>&lt;html code&gt;</code> is often the result of a JSON request to an HTML server. And this request is indeed handled by the application hook ( with <code>ipconfigHTTP_HAS_HANDLE_REQUEST_HOOK</code> enabled ).
Only requests with a certain characters (usually a <code>'?'</code>) will be forwarded to the application. All other requests are about retrieving files.
In some project I&#8217;m showing the properties of a sound-limiter, gain, bass, treble, and also the actual (measured) sound pressure. There is a constant polling of these properties and they&#8217;re shown in a browser with e.g.:
~~~
    $(&#8216;#id<em>volume&#8217;).html(settings.volume);
    $(&#8216;#id</em>bass&#8217;).html(settings.bass);
    $(&#8216;#id<em>sound</em>pressure&#8217;).html(settings.spl);
~~~
The advantage of this approach is more simplicity at the embedded side. It just has to answer simple questions about settings and measurements. And also it gets commands of course, to change the settings.
Browsers are normally running on powerful CPU&#8217;s with lots of memory. Let them do more work to unload our small cheap MCU&#8217;s 🙂
