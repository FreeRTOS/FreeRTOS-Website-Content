</div></div><div class="thread-post"><h3 class="thread-post-title">I want to implement FAT32 on FreeRTOS for USB OTG USB Memory.</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on March 21, 2017</div><div class="thread-post-content">Just as TCP code is generic, but must be ported to an Ethernet 
controller, the FAT code is generic, but must be ported to the media 
that is going to store the file file system.  Information on how to do 
this is provided on the following link:
http://www.freertos.org/FreeRTOS-Plus/FreeRTOS<em>Plus</em>FAT/Creating<em>a</em>file<em>system</em>media_driver.html

Can i use below for USB Stick like &#8220;FF_USBDiskDetect() with just porting for reading, writing, IOMan Initializing and DISK IO &#8220;?
BaseType<em>t FF</em>SDDiskDetect( FF<em>Disk</em>t *pxDisk );

</div></div><div class="thread-post"><h3 class="thread-post-title">I want to implement FAT32 on FreeRTOS for USB OTG USB Memory.</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on July 5, 2017</div><div class="thread-post-content">I&#8217;m not sure I fully understand your question, but yes, you should be 
able to port to USB storage.  It may be a little trickier than most port 
as you will need to start with a working USB stack with appropriate drivers.
</div></div><div class="thread-post"><h3 class="thread-post-title">I want to implement FAT32 on FreeRTOS for USB OTG USB Memory.</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on July 5, 2017</div><div class="thread-post-content">I think that the documentation pointed-out by Richard is quite complete.
But the most important functions to be implemented are:
~~~
    static int32<em>t prvFFRead( uint8</em>t *pucBuffer, uint32_t ulSectorNumber, uint32_t ulSectorCount, FF_Disk_t *pxDisk );
    static int32_t prvFFWrite( uint8_t *pucBuffer, uint32_t ulSectorNumber, uint32_t ulSectorCount, FF_Disk_t *pxDisk );
~~~
You&#8217;ll bind the address of these functions to the so-called io-handler.
Note that these functions use sector numbers, not a byte offset.
For the other <code>FF_SDDisk</code> functions you can use the existing implementation in most cases.
