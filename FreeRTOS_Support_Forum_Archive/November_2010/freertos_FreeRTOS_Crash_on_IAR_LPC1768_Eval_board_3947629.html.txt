&gt; With some modifications I used the uipWebserver example in the<br />
&gt; project to read out the task&#8217;s run time stats for the application.  
Note that the run time and task stat tables are good for debugging purposes, but generating the tables leaves interrupts disabled for a long time so they are not so good for production code.  
&gt; And&nbsp; slowly I started adding my other BMS application related tasks.<br />
&gt; This started increasing my SRAM consumption, which is understandable.  
Did you also remove the other &#8216;standard demo&#8217; tasks that you don&#8217;t need?&nbsp; That in turn will free up RAM.  
&gt; So I accordingly started adjusting my FreeRTOSConfig.h and eventually<br />
&gt; when I go over 32K of SRAM bank, my application crashes immediately<br />
&gt; before even it runs. I know the LPC1768 has two separate banks of 32K<br />
&gt; SRAM, I have changed my IAR compiler to treat the two separate SRAM<br />
&gt; banks as one and it did it. But for some reason when I set<br />
&gt; configTOTAL&#95;HEAP&#95;SIZE to put the SRAM over 32KB after compilation,<br />
&gt; the whole application crashes with Hardfault exception error shown in<br />
&gt; the debugger.   
Check where the Ethernet buffers are being placed.&nbsp; I think it will be in one of the AHB RAM sections, but it might not necessarily show up in the map file &#8211; depending on how they are defined.&nbsp; They might befined as arrays or just as hard coded addresses.&nbsp; In the latter case you might be getting some memory usage overlap.  
I&#8217;m not sure what the LPC17xx requirements are for accessing the AHB RAM directly, rather than from the Ethernet or USB DMA.  
&gt; I use IAR workbench compiler and debugger. I am using<br />
&gt; IAR 1768-SK evaluation board as my development board.<br />
&gt;<br />
&gt; 2&#46; Second problem, I have added few task to the BMS application and<br />
&gt; in the process I wanted bumped the priority of uipTask to<br />
&gt; &#40;tskIDLE&#95;PRIORITY + 6&#41; and in the webserver&#8217;s webpage in the runtime<br />
&gt; stats or in one of those tabs where it shows the each task&#8217;s details<br />
&gt; shows the priority as 4. If I put the task priority as 5 or higher it<br />
&gt; shows up as 4 on the webpage. But other tasks whose priority is 4 or<br />
&gt; less shows up correctly. Why?   
What is configMAX&#95;PRIORITIES set to in FreeRTOSConfig.h?  
&gt; I remember reading in the freertos<br />
&gt; manual that you can setup up priority numbers pretty high and can run<br />
&gt; any number of tasks.  
That is correct, but configMAX&#95;PRIORITIES should be as low as your application allows, to save RAM, so it might be set to 5 &#40;priorities 0 to 4 then being valid&#41;.  
&gt; 3&#46; Third problem, when I add a new task or change priorities around,<br />
&gt; the whole application becomes very unstable. Any info or pointers<br />
&gt; would definitely help me get going.  
Are you using interrupts?&nbsp; By far the most common cause of support requests on CM3 devices is people getting their interrupt proprieties inverted &#40;0 is the highest priority, which is counter intuitive&#41;, or not setting the priority at all &#40;which will mean it has a priority above configMAX&#95;SYSCALL&#95;INTERRUPT&#95;PRIORITY&#41; or using a function to set the priority and passing in the function parameter incorrectly &#40;some functions require the priority to be shifted to the most significant bits, some want it unshifted and do the shifting internally&#41;.  
Regards.
