  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">taskYIELD() causes hang inPIC24f interupt</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/s-obrien">s-obrien</a> on November 16, 2010</div><div class="thread-post-content">Per the FreeRTOS documentation to handle API calls inside of an interrupt I need to taskYIELD if necessary, I have the following ISR:  
void &#95;&#95;attribute&#95;&#95; &#40;&#40;&#95;&#95;interrupt&#95;&#95;, no&#95;auto&#95;psv&#41;&#41; &#95;T4Interrupt&#40;void&#41;<br />
&#123;<br />
&nbsp;&nbsp; portBASE&#95;TYPE xHigherPriorityTaskWoken = pdFALSE;<br />
&nbsp;&nbsp; IFS1bits.T4IF = 0;<br />
&nbsp;&nbsp;<br />
&nbsp;&nbsp; xQueueSendToBackFromISR&#40;queue&#95;name, &amp;queue&#95;data, &amp;xHigherPriorityTaskWoken&#41;;  
&nbsp;&nbsp; if&#40;xHigherPriorityTaskWoken == pdTRUE&#41;<br />
&nbsp;&nbsp; &#123;<br />
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; taskYIELD&#40;&#41;; // Force context switch<br />
&nbsp;&nbsp; &#125;  
Everytime xHigherPriorityTaskWoken is true and the taskYIELD&#40;&#41; executes, my processor resets.&nbsp; I&#8217;ve debugged to determine this is correct.&nbsp; If I comment out the taskYIELD, everything works smoothly.  
The only thing I can think is that the priority of this interrupt is 7 and the tick timer has priority 1, but I&#8217;m not disabling any interrupts and per the RTOS docs this should be the correct method to use.
</div></div><div class="thread-post"><h3 class="thread-post-title">taskYIELD() causes hang inPIC24f interupt</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/jorick23">jorick23</a> on November 16, 2010</div><div class="thread-post-content">The correct function to use to switch tasks inside an interrupt is vTaskSwitchContext, not taskYield.&nbsp; So your code should look like this:  
&nbsp;&nbsp; if&#40;xHigherPriorityTaskWoken == pdTRUE&#41;<br />
&nbsp;&nbsp; &#123;<br />
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; vTaskSwitchContext&#40;&#41;; // Force context switch<br />
&nbsp;&nbsp; &#125;  
</div></div><div class="thread-post"><h3 class="thread-post-title">taskYIELD() causes hang inPIC24f interupt</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on November 16, 2010</div><div class="thread-post-content">I think in this case calling taskYIELD&#40;&#41; is the correct thing to do &#8211; but this must be done as the very last thing in the ISR routine.&nbsp; Is it the last line of executable code?  
FreeRTOSDemoPIC24&#95;MPLABserialserial.c has an example ISR.  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">taskYIELD() causes hang inPIC24f interupt</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/s-obrien">s-obrien</a> on November 16, 2010</div><div class="thread-post-content">I&#8217;ve solved the problem.&nbsp; It turns out I was getting a stack overflow on my IDLE task.&nbsp; I had been assuming that the stack used for interrupts was from the task executing when the interrupt occurred which wouldn&#8217;t have caused any stack issues.  
Could someone shed some light on what consumes the IDLE task&#8217;s stack during operation?&nbsp; &#40;I have no user defined IDLE hook or anything that should be used during idle time&#41;.
