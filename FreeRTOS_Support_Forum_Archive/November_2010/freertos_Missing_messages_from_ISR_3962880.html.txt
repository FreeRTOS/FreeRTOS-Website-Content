</div></div><div class="thread-post"><h3 class="thread-post-title">Missing messages from ISR</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on November 26, 2010</div><div class="thread-post-content">There is not&nbsp; an official Actel port, which means I don&#8217;t really know which code you are using.&nbsp; However, all the Cortex M3 ports that are in the official release all use the same port layer code &#8211; the only difference being the compiler used.&nbsp; There is a port for GCC &#40;including Rowley, Code Red, Atollic, etc&#41;, Keil, and IAR.&nbsp; Which are you using?

</div></div><div class="thread-post"><h3 class="thread-post-title">Missing messages from ISR</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on November 26, 2010</div><div class="thread-post-content">The macro to use then is portEND&#95;SWITCHING&#95;ISR&#40;&#41;, not taskYIELD&#95;FROM&#95;ISR&#40;&#41;.  
If you are sending a lot of messages character by character consider using a ring buffer instead, and just send a single message to the task that processes the data once a complete message has been received.  
Also, what have you set the priority of the interrupt to?&nbsp; It must be equal to or below configMAX&#95;SYSCALL&#95;INTERRUPT&#95;PRIORITY, remembering that high numeric values denote &#42;&#42;&#42;low&#42;&#42;&#42; interrupt priorities, and that different functions provided by different vendors want the interrupt priority specified in different ways &#40;some wanted shifted into the most significant bits, while others want it in the least significant bits and do the shifting internally within the driver&#41;.&nbsp; Definitely &#42;&#42;&#42;do not&#42;&#42;&#42; leave the interrupt at its default priority as this will be 0 and therefore the highest priority in the system.  
Regards.
