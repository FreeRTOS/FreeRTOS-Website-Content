</div></div><div class="thread-post"><h3 class="thread-post-title">Memory usage</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/aggarg-aws">aggarg-aws</a> on August 14, 2019</div><div class="thread-post-content">Thanks Dave. I verified this using STM32Cube IDE and the same bug exists there. 
Jan, TOTAL<em>HEAP</em>SIZE and the stack sizes for statically allocated tasks are not related. You should modify the generated code. 
TOTAL<em>HEAP</em>SIZE is defined in FreeRTOSConfig.h:
~~~
<h1>define configTOTAL<em>HEAP</em>SIZE                    ((size_t)2000)</h1>
~~~
Task sizes of the statically allocated tasks are defined at the time of task creation:
~~~
osThreadId myTask02Handle;
uint32<em>t myTask02Buffer[ 128 ]; /* Update the stack size here. */
osStaticThreadDef</em>t myTask02ControlBlock;
/* Pass the updated stack size to osThreadStaticDef instead of 128. */
osThreadStaticDef(myTask02, StartTask02, osPriorityIdle, 0, 128, myTask02Buffer, &amp;myTask02ControlBlock);
 myTask02Handle = osThreadCreate(osThread(myTask02), NULL);
~~~
Just FYI, you can directly use xTaskCreateStatic instead of going via osThreadCreate wrapper.
Thanks.
