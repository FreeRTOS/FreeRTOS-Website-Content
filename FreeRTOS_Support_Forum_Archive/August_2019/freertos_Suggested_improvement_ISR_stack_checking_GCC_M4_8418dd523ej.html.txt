  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Suggested improvement: ISR stack checking (GCC M4)</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/dnadler">dnadler</a> on August 21, 2019</div><div class="thread-post-content">For Cortex M4 (and  other MCUs) ISR&#8217;s run on a separate stack from FreeRTOS tasks (MSP).
To ensure bulletproof operation, its a good idea to verify all stacks have adequate space 😉
I suggest the following additions:
<ol>
<li>In configuration, new #defines:
~~~
// DRN ISR (MSP) stack initialization and checking</li>
</ol>
<h1>define configISR<em>STACK</em>SIZE_WORDS (0x100) // DRN in WORDS, must be valid constant for assembler</h1>
<h1>define configSUPPORT<em>ISR</em>STACK_CHECK  1   // DRN initialize and check ISR stack</h1>
~~~
2.  Additional code in port.c  (this is for the M4 GCC port).  I&#8217;ve tried to keep this tight but my ARM-GCC-assembler isn&#8217;t super-strong&#8230;
~~~
<h1>define QUOTE(str) #str</h1>
<h1>define EXPAND<em>AND</em>QUOTE(str) QUOTE(str)</h1>
<h1>if defined(configSUPPORT<em>ISR</em>STACK<em>CHECK) &amp;&amp; configSUPPORT</em>ISR<em>STACK</em>CHECK &amp;&amp; !defined(configISR<em>STACK</em>SIZE_WORDS)</h1>
  #error &#8220;configISR<em>STACK</em>SIZE_WORDS must be defined for ISR stack checking (WORDS to reserve for MSP stack)&#8221;
<h1>endif</h1>
static void prvPortStartFirstTask( void )
{
    /* Start the first task.  This also clears the bit that indicates the FPU is
    in use in case the FPU was used before the scheduler was started &#8211; which
    would otherwise result in the unnecessary leaving of space in the SVC stack
    for lazy saving of FPU registers. */
    __asm volatile(
      &#8221; ldr r0, =0xE000ED08  n&#8221; /* Use the NVIC offset register to locate the initial stack. */
      &#8221; ldr r0, [r0]         n&#8221;
      &#8221; ldr r0, [r0]         n&#8221; /* r0 now has top of stack (actually, word above beginning of stack) */
      &#8221; msr msp, r0          n&#8221; /* Set the MSP (*ISR* stack register) back to the start of the stack (top of RAM). */
<pre><code>#if defined(configSUPPORT_ISR_STACK_CHECK) &amp;&amp; configSUPPORT_ISR_STACK_CHECK
  // DRN code: Zero the MSP stack before use, to facilitate stack use check
  " mov r1, #0           n" /* value to store into stack */
  " ldr r2, pxMSRstackLenn" /* remaining words to clear in stack */
  "FillZeroMSPstack:     n"
  " sub r0, r0, #4       n" /* next word to zero */
  " str r1, [r0]         n" /* store a zero */
  " sub r2, r2, #1       n" /* decrement word count */
  " cmp r2, #0           n" /* finished clearing stack? */
  " bne FillZeroMSPstack n"
#endif // #if defined(configSUPPORT_ISR_STACK_CHECK) &amp;&amp; configSUPPORT_ISR_STACK_CHECK
  " mov r0, #0         n" /* Clear the bit that indicates the FPU is in use, see comment above. */
  " msr control, r0    n"
  " cpsie i            n" /* Globally enable interrupts. */
  " cpsie f            n"
  " dsb                n"
  " isb                n"
  " svc 0              n" /* System call to start first task. */
  " nop                n"
</code></pre>
   );
  #if defined(configSUPPORT<em>ISR</em>STACK<em>CHECK) &amp;&amp; configSUPPORT</em>ISR<em>STACK</em>CHECK
    __asm volatile (
      &#8221;    .align 4        n&#8221;
      &#8220;pxMSRstackLen: .word &#8221; EXPAND<em>AND</em>QUOTE(configISR<em>STACK</em>SIZE<em>WORDS) &#8220;n&#8221;
    );
  #endif // #if defined(configUSE</em>ISR<em>STACK</em>CHECK) &amp;&amp; configUSE<em>ISR</em>STACK_CHECK
}
/*&#8212;&#8212;&#8212;&#8212;&#8212;&#8212;&#8212;&#8212;&#8212;&#8212;&#8212;&#8212;&#8212;&#8212;&#8212;&#8212;&#8212;&#8212;&#8212;&#8211;*/
<h1>if defined(configSUPPORT<em>ISR</em>STACK<em>CHECK) &amp;&amp; configSUPPORT</em>ISR<em>STACK</em>CHECK</h1>
  BaseType<em>t xUnusedISRstackWords( void ) {
    register uint32</em>t *pStackOrigin;
    int unusedStackWords = 0;
    __asm volatile(
      &#8221; ldr r0, =0xE000ED08  n&#8221; /* Use the NVIC offset register to locate the initial stack. */
      &#8221; ldr r0, [r0]         n&#8221;
      &#8221; ldr r0, [r0]         n&#8221; /* r0 now has top of stack (actually, word above beginning of stack) */
      &#8221; mov %[result], r0    n&#8221; : [result] &#8220;=r&#8221; (pStackOrigin) :: &#8220;r0&#8221;
     );
    uint32_t *pStackUseEnd = pStackOrigin &#8211; configISR_STACK_SIZE_WORDS; // start testing at stack limit
    for(int lim=configISR_STACK_SIZE_WORDS; lim; lim&#8211;) {
      if(*pStackUseEnd++) break; // break at first used word
      unusedStackWords++;
    }
    return unusedStackWords;
  }
<h1>endif // #if defined(configUSE<em>ISR</em>STACK<em>CHECK) &amp;&amp; configUSE</em>ISR<em>STACK</em>CHECK</h1>
/<em>&#8212;&#8212;&#8212;&#8212;&#8212;&#8212;&#8212;&#8212;&#8212;&#8212;&#8212;&#8212;&#8212;&#8212;&#8212;&#8212;&#8212;&#8212;&#8212;&#8211;</em>/
~~~
With this I&#8217;m able to verify ISR stack use in our application.
Thanks as always for your excellent work,
Best Regards, Dave

</div></div><div class="thread-post"><h3 class="thread-post-title">Suggested improvement: ISR stack checking (GCC M4)</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on August 23, 2019</div><div class="thread-post-content">Hi Dave &#8211; thanks for your valuable input as always.
The PIC32 (MIPS core) port does actually check for overflows in the ISR
stack as the stack is allocated by the kernel itself, although I was
thinking of changing that so it works like the Cortex-M ports whereby
the stack is not allocated by the kernel, but instead the stack that is
allocated by the linker configuration is re-used as the ISR stack &#8211; and
there is the issue with doing this in a generic way as the linker
scripts are all different and some don&#8217;t even define a stack size at all
(preferring to just let the stack and heap grow toward each other in
scary and complex to predict way).
So in nearly all Cortex-M cases, where the linker script is created or
provided by the tools, or set up in the IDE (IAR and the like) the ISR
stack size is not actually know.
</div></div><div class="thread-post"><h3 class="thread-post-title">Suggested improvement: ISR stack checking (GCC M4)</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/dnadler">dnadler</a> on August 23, 2019</div><div class="thread-post-content">We&#8217;re agreed about avoiding the scary and unpredictable bit 😉
Because linker scripts and symbols are wildly different across toolchains, 
and there is often no symbol for stacksize that&#8217;s relevant (as in STM case), 
I took the unpleasant approach of defining the ISR stack size in FreeRTOSconfig.
If the default is no ISR stack checking, the user will have to fill in the value
on enabling the check, and hopefully will match their LD values.
Can&#8217;t easily modify the LD as the vendor &#8220;wizards&#8221; overwrite changes&#8230;
One thing at a time, but I&#8217;m happy to help with the other Cortex M parts.
I think I have eval test boards for the assorted Cortex parts.
I only have GCC toolchain at present.
Let me know how I can help,
Best Regards, Dave
</div></div><div class="thread-post"><h3 class="thread-post-title">Suggested improvement: ISR stack checking (GCC M4)</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on August 23, 2019</div><div class="thread-post-content">&#8230;because of the wide variation of compilers that have different linker script formats, and the variation in ways in which linker scripts are written, I think the only clean solution that would not impact backward compatibility would be to copy what was done for the RISC-V port whereby if you define a constant in FreeRTOSConfig.h that sets the size of the interrupt stack then the stack is defined by the kernel (just a static array) and it is possible to monitor the stack for overflows, otherwise a linker variable is used to re-use the stack that was used by main() which saves RAM but prevents the stack being monitored:  https://www.freertos.org/Using-FreeRTOS-on-RISC-V.html#RISC-V-INTERRUPT_STACK   &#8211;   except in the Cortex-M case you don&#8217;t need the linker variable because the  start of stack is obtained from the vector table (as it is in the Cortex-M ports today).
