  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Shared memory between two processes</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/plattens">plattens</a> on August 23, 2019</div><div class="thread-post-content">I&#8217;m new to FreeRTOS, I&#8217;m working on a project that was developed using XiLinx.  There are two parts to this project, an FPGA and an Application.  The FPGA and Application use share memory to communicate.  I have the original source code but its very unclear how this works and why it works at all.  The application declares a pointer to an address that as far as I can see is not allocated or protected in any way, this pointer is at 0x43c00000.
In the application this address is use as follows:
<pre><code>    volatile AxiAddressMapping* currentAxiMapping = (AxiAddressMapping*)AXI_ADDRESS_MAPPING;
</code></pre>
The application then reads and writes to this structure.  There isn&#8217;t any protection or API calls I can see in place to determine how this memory is accessed or protects either side.  When this memory is access the application crashes.  Is there an example on the correct way to do this?

</div></div><div class="thread-post"><h3 class="thread-post-title">Shared memory between two processes</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/hs2sf">hs2sf</a> on August 23, 2019</div><div class="thread-post-content">In fact the FPGA design contains an AXI lite port mapped to a physical address range starting at this fixed address. The FPGA code in turn handles read/write accesses to this address range by the CPU. That&#8217;s low level and is completely up to your application code.
I&#8217;m not familiar with the FreeRTOS Zynq port, but there should be some PS (processing system) init code called early setting up the PS including memory/address regions etc. generated by the Xilinx FPGA toolchain (ps7init.c ?).
I assume the FPGA is already loaded when running your application. Otherwise the AXI bus access will fail probably causing a HW exception.
</div></div><div class="thread-post"><h3 class="thread-post-title">Shared memory between two processes</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/hs2sf">hs2sf</a> on August 23, 2019</div><div class="thread-post-content">And someone also ported the FPGA design to the new board 😉
Perhaps there are some debug LEDs showing that the FPGA was successfully initialized&#8230;
</div></div><div class="thread-post"><h3 class="thread-post-title">Shared memory between two processes</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on August 23, 2019</div><div class="thread-post-content">That address is in the address space of the I/O bus of the FPGA. When you code accesses that, it will do an AXI access to talk to the FPGA. If the FPGA isn&#8217;t initialized, still in reset, or isn&#8217;t getting a clock, you will get a bus error. On the Zynq, as I remember the processor comes up first and is responsible for configuring the FPGA, and if it tries to access the FPGA before it has finished initializing you will get this sort of error.
If you altered the FPGA design, it is also possible that your port changed to a different address, as the address is based on bus position, and if you change that the address will be different.

The odd thing is that Xilinx 2019.1 when used results in a crash as soon as this memory location is accessed.  Xilinx 2016.2 works fine, its exactly the same source just  compiled using different versions of Xilinx.
