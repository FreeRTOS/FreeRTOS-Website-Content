  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Failing configASSERT in xQueueGiveFromISR and vPortEnterCritical on migration to 10.0.0 from 7.3.0</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/adityas">adityas</a> on August 6, 2019</div><div class="thread-post-content">Hi,
I have been tasked with migrating to FreeRTOS 10.0.0 on my Atmel SAM4E8C(A) chip which was originally running the 7.3.0 kernel. It has not been as out-of-box replacement as my initial research impressed on me, but bear with me, as I am new to RTOS. I have updated the Atmel Software Framework (ASF) to 3.40 (from 3.34) to upgrade to FreeRTOS 10.0.0 (it does not seem like the ASF supports 10.2.1 yet, otherwise I would have gone for that, though the release notes do not indicate I am missing out for my MCU core). Atmel Studio 7 is my IDE, and I am using the standard Atmel ICE for debugging.
<ol>
<li>Issue: The local<em>uart</em>handler() has a xSemaphoreGiveFromISR macro that used to be defined as xQueueGenericSendFromISR (7.3.0) and is now xQueueGiveFromISR. While I think this makes sense, the following ASSERT condition is failing.
~~~
configASSERT( !( ( pxQueue->uxQueueType == queueQUEUE<em>IS</em>MUTEX ) &amp;&amp; ( pxQueue->pxMutexHolder != NULL ) ) );
~~~</li>
</ol>
Both the checks evaluate to TRUE, and hence the ASSERT fails. What am I supposed to do here, as these are 3rd party files that I really don&#8217;t want to hack around?
<ol>
<li>Issue: I am also failing the Assert condition in the use of vPortEnterCritical(). </li>
</ol>
~~~
configASSERT( ( portNVIC<em>INT</em>CTRL<em>REG &amp; portVECTACTIVE</em>MASK ) == 0 );
~~~
What extra items need to be in place for this to pass in 10.0 that were not required in 7.3.0?
Side note:
I don&#8217;t feel this is relevant, but recognising gaps in my understanding: I found the ASF update did not acquire the correct type folder in  &#8230;envatmelsrcASFthirdpartyfreertosfreertos-10.0.0SourceportableGCC&#46; The original import was for &#8216;ARM<em>CM3&#8242;, while this should have been &#8216;ARM</em>CM4F&#8217; (my verification being that the #ifndef <strong>VFP_FP</strong> check triggered a fail when switched to #ifdef). I directly copied this folder in at the relevant location and pointed the library search path to this.
Any help or suggestions would be much appreciated. Thanks.
Regards,
Aditya
</div></div><div class="thread-post"><h3 class="thread-post-title">Failing configASSERT in xQueueGiveFromISR and vPortEnterCritical on migration to 10.0.0 from 7.3.0</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on August 7, 2019</div><div class="thread-post-content">A Mutex inherently should be taken and then given back by the same task, its owner.  I beleive earlier versions of FreeRTOS did not enforce this restriction, but some changes in how priority inhertance worked required it, It really makes no sense for an ISR to give a Mutex, is it doesn&#8217;t make sense for it to take it in the first place. 
The second assert looks to be using a non-ISR API function inside an ISR.
</div></div><div class="thread-post"><h3 class="thread-post-title">Failing configASSERT in xQueueGiveFromISR and vPortEnterCritical on migration to 10.0.0 from 7.3.0</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/adityas">adityas</a> on August 13, 2019</div><div class="thread-post-content">Thank you Richard, especially for the quick response. You are correct. It was actually some interface files provided by Atmel ASF for FreeRTOS that were incorrect in their previous version. In fact, most issues seem to be related to ASF files rather than FreeRTOS. I&#8217;ve had to spend a few days sourcing and refactoring these files, and understanding the code structure to a point I can (somewhat) follow what is going on.
For the second issue, the code was using vPortEnterCritical()/vPortExitCritical() in an ISR, so swapped that out for portSET<em>INTERRUPT</em>MASK<em>FROM</em>ISR() / portCLEAR<em>INTERRUPT</em>MASK<em>FROM</em>ISR().
</div></div><div class="thread-post"><h3 class="thread-post-title">Failing configASSERT in xQueueGiveFromISR and vPortEnterCritical on migration to 10.0.0 from 7.3.0</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on August 13, 2019</div><div class="thread-post-content">The simplest change would be to use a binary semaphore instead of a
mutex &#8211; that just requires the function used to create the semaphore to
be changed.
