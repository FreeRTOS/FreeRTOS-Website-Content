I have questions about the vApplicationTickHook(). How could this be used to
measure the execution time of e.g. taska and taskb? Also how could I change the priority of
e.g. taskb after having meausured the execution time?
The vApplicationTickHook is always run but how to measure the execution time for e.g taska and taskb so
I can have the specific execution time for each of them?
Also how to use e.g. vTaskPrioritySet(handle, 2) to change the priority of a task?
Grateful for examples
</div></div><div class="thread-post"><h3 class="thread-post-title">measure execution by vApplicationTickHook, change priority?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on May 23, 2017</div><div class="thread-post-content">Hi, I would introduce a third lightweight task to do that job. Let it sleep (block) for 5 seconds, check the system load, and sleep again.
<code>vApplicationTickHook()</code> is being called from an ISR and that gives many limitations. You can not do much from within an ISR. <code>vApplicationTickHook()</code> is handy if you want to have a blinking LED or so.
There are several ways to get an estimate of CPU-time per task, for instance <a href="http://www.freertos.org/rtos-run-time-stats.html">configGENERATE<em>RUN</em>TIME_STATS</a>
I never had the need to do what you want to do, and I wonder if you can take a different approach? Have a look at the following :
~~~
    #define configUSE<em>PREEMPTION       1
    #define configUSE</em>TIME_SLICING     1
~~~
It is commented in <a href="https://sourceforge.net/p/freertos/discussion/382005/thread/30fbd897">this post</a>
With these settings, the OS makes sure that runnable tasks of equal priority will get an equal amount of CPU-time!
It will not depend on the task&#8217;s willingness to yield. I would consider using that option and not play with the tasks&#8217; priorities.
</div></div><div class="thread-post"><h3 class="thread-post-title">measure execution by vApplicationTickHook, change priority?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on May 23, 2017</div><div class="thread-post-content">As Hein says, seems wrong to need to change priorities based on CPU usage. Priorities should reflect the needs of the system, and generally don&#8217;t change. The one exception that I can think of is if something changes &#8216;mode&#8217; and some operation changes significantly in need (something changes so what used to be not important exactly when it occured, to being very important).  
</div></div><div class="thread-post"><h3 class="thread-post-title">measure execution by vApplicationTickHook, change priority?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/electronicdev">electronicdev</a> on May 24, 2017</div><div class="thread-post-content">Is it possible by vApplicationTickHook to check which task that is running and then increment a counter as long as that task is executed? What function could I call inside vApplicationTickHook to check if e.g. taskb is executing and then increase my counter for every tick my taskb is executing, if not executed no count is performed. How to do this and what arguments are returned etc if checking taskb is executed?
Thank you
</div></div><div class="thread-post"><h3 class="thread-post-title">measure execution by vApplicationTickHook, change priority?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on May 24, 2017</div><div class="thread-post-content">You could ask for the current task handle ( <code>xTaskGetCurrentTaskHandle()</code> ), and use that pointer to increment some counter belonging to a task.
The API <code>xTaskGetCurrentTaskHandle()</code> does not have a critical section, so it should be safe to call it from <code>vApplicationTickHook()</code>.
I still think it would be much cleaner and more exact to use <code>configGENERATE_RUN_TIME_STATS</code>. You can use a spare TC timer to get an exact time in uS, and provide this function in your <code>FreeRTOSConfig.h</code>:
~~~
    extern uint32<em>t ulGetRunTimeCounterValue(void);
    #define portGET</em>RUN<em>TIME</em>COUNTER_VALUE()    ulGetRunTimeCounterValue()
~~~
What it misses is the possibility to clear the <code>ulRunTimeCounter</code>. <a href="https://sourceforge.net/p/freertos/discussion/382005/thread/cdea0f6f/?limit=25#5ca0">Here</a> is a description of how you can add that.

</div></div><div class="thread-post"><h3 class="thread-post-title">measure execution by vApplicationTickHook, change priority?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on May 25, 2017</div><div class="thread-post-content">Oops
Your implementation of <code>printf()</code> is probably not fit to be called from within an ISR. Many standard implementations of <code>printf()</code> use the heap.
Beside that, you&#8217;re making a C-style error :
~~~
    if (taska_handle = xTaskGetCurrentTaskHandle())
    {
    }
~~~
I suppose you mean to write a comparison ( <code>==</code> ) and not an assignment ( <code>=</code> ) :
So simply write:
~~~
    if (taska<em>handle == xTaskGetCurrentTaskHandle())
    {
        iCount++;
        printf(&#8220;exeqution</em>time_taska %drn&#8221;, iCount);
    }
    else
    {
        iCount = 0;
    }
}
~~~
Regards.
