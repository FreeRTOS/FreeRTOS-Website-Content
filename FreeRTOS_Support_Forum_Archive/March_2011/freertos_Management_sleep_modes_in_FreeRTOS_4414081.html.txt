  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Management sleep modes in FreeRTOS</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/spl12">spl12</a> on March 16, 2011</div><div class="thread-post-content">Currently I’m working about a possible way to manage the sleep modes in FreeRTOS. Since even other companies use sleep modes to manage the power management, I thought to adopt a strategy common to all. Below, it is a sum up about my idea.  
<strong>Sleep Mode for tasks</strong><br />
Basically, inside in each&nbsp; task’s body the user can define the sleep mode to go in for the next idle tasks &#40; using&nbsp; PMSetSleepMode&#41; and the Power Framework will choose only that sleep mode in common among tasks.  
<strong>Sleep mode for ISRs</strong>  
An example: If two tasks request to stay in sleep mode 2 and just before to go in idle task, an interrupt occurs, then can be the case that the sleep mode chosen is not longer valid after ISR’s execution. For this reason, we need to define an API to choose the sleep mode also for ISR.<br />
But in this case we have the necessity to know for how long we have to keep the sleep mode chosen by ISR. This is an important case, in fact if many ISRs occur &#40;each ISR defines a different sleep mode&#41; the system before to choose a sleep modes must be sure that it doesn’t go in a wrong one.<br />
For instance: ISR1 wants to stay in Sleep Mode 1 &#40;because the ISR2 is triggered by a peripheral of Sleep mode 1&#41;, then when&nbsp; ISR2 occurs, the system can go in sleep mode 2. Thus, the system can’t understand for how long a sleep mode can be kept valid. To cope this issue, a function “PMLockSleepMode” defines a starter point of a sleep mode and another function “PMUnlockSleepMode” defines the end of that sleep mode. The idea is to freeze the sleep mode for a while. The user can unlock the&nbsp; mode in another ISR or in a Task.<br />
If we don’t want to freeze the sleep mode, we can use the function “PMSetSleepModeISR”. After invocation of this function, the system keeps valid the sleep mode only until the end of first idle task. For the following idle tasks the sleep mode is discarded.  
<strong>Power Management Framework</strong>  
&#43; <em>PMSetSleepMode &#40;unsigned char mode&#41;</em> ==&gt; Set a sleep mode for that task &#40;sleep mode is used in next idle tasks&#41;;<br />
&#43; <em>PMSetSleepModeISR &#40;unsigned char mode&#41;</em> ==&gt; Set a sleep mode for that ISR &#40;sleep mode is used only for next idle task&#41;;<br />
&#43; <em>PMGetSleepMode &#40;&#41;</em> ==&gt;Returns the current sleep mode where the system can go to. The sleep mode depends from the requests done by other tasks or ISRs. This function is used only inside tasks body;<br />
&#43; <em>PMGetSleepModeISR&#40;&#41;</em> ==&gt;Returns the current sleep mode where the system can go to. The sleep mode depends from the requests done by other tasks or ISRs. This function is used only inside ISRs body;<br />
&#43; <em>PMLockSleepModeISR &#40;unsigned char mode&#41;</em> ==&gt; Lock a sleep mode inside an ISR. The lock can be done only inside an ISR. A sleep mode can be locked for many times &#40;max 256&#41;. A further version of this function might be to lock a sleep mode for a duration of time given in input;<br />
&#43; <em>PMUnlockSleepModeISR &#40;unsigned char mode&#41;</em> ¬==&gt; Unlock a sleep mode from an ISR.<br />
&#43; <em>PMUnlockSleepMode &#40;unsigned char mode&#41;</em> ==&gt; Unlock a sleep mode from a task.<br />
&#43; <em>PMIdleSleepMode&#40;&#41;</em> ==&gt; Returns the suitable sleep mode for idle task. This function is invoked inside idle task, it is used before to go in sleep mode.<br />
&#43; <em>PMGoToSleep &#40;unsigned char mode&#41;</em> ==&gt; This function pushes the MCU in sleep mode taken in input.   
Actually, I’ve developed an implementation about this power framework for Energy Micro. For me it is really important to get feedback and suggestions to improve my work.
