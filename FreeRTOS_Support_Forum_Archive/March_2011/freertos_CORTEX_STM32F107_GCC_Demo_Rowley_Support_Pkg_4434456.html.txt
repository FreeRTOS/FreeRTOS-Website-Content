</div></div><div class="thread-post"><h3 class="thread-post-title">CORTEX_STM32F107_GCC Demo, Rowley Support Pkg</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/northgeer">northgeer</a> on March 31, 2011</div><div class="thread-post-content">My friend JM has found the solution.  
The STM32 &#40;V2&#41; support package has the required CPU support for the STM32F107VC.<br />
However, the STM32.hzq file can only be installed in the V2.0 Rowley compilers.<br />
It can not be directly loaded into Crossworks V1.7.  
If you download the Rowley V2.0 compiler 30 day evaluation, you can install this support package.<br />
It unpacks the STM32.hzq file and puts the installed package files in the directory<br />
E:Documents and SettingsusernameLocal SettingsApplication DataRowley Associates LimitedCrossWorks for ARMpackagestargetsSTM32<br />
&#40;not the C:Program FilesRowley Associates LimitedCrossWorks for ARM 2.0targets directory as I expected&#41;.  
The STM32F107VC&#95;MemoryMap.xml file can then be copied to the C:Program FilesRowley Associates Limited&#92;CrossWorks for ARM 1.7targetsST&#95;STM32F10x directory.<br />
This presumes that the STM32F10x CPU support has already been installed for v1.7 .  
Other changes required to build…  
1.&nbsp; One small change needs to be made to the STM32F107VC&#95;MemoryMap.xml file.<br />
One letter needs to be added.<br />
A few lines from the end, change &#8220;RAM&#8221; to &#8220;SRAM&#8221; in the following line<br />
&lt;MemorySegment size=&#8221;0x10000&#8243; name=&#8221;RAM&#8221; start=&#8221;0x20000000&#8243;/&gt;  
2&#46; Edit propertyGroups.xml in the targets directory to add a section for the STM32F107VC&#95;MemoryMap.xml file, copying the format of the previous sections.  
3&#46; In the project settings under project-&gt;RTOSDemo-&gt;Property Groups File setting, point to your V1.7 propertyGroups.xml file.  
4&#46; In the project settings under project-&gt;RTOSDemo-&gt;Memory Map File setting, point to your STM32F107VC&#95;MemoryMap.xml file.  
I was able to compile the FreeRTOS demo with Rowley V1.7 with the above changes.&nbsp;<br />
I still have the old V1.7 ST32F10x startup file, so I will probably have to change to the newer V2.0 ST32&#95;Startup.s file to get it to load and run correctly since the F107 has additional interrupt vectors and other things that need to be defined.
