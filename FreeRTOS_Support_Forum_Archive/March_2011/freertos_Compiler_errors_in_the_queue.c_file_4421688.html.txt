  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Compiler errors in the queue.c file</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/ksoldavin">ksoldavin</a> on March 21, 2011</div><div class="thread-post-content">I am attempting to compile FreeRTOS 6.1.1 with IAR ARM compiler version 6.05 but I keep running into an error with a specific compiler option. I want to compile the code with the &#8220;Multi-file Compilation&#8221; option enabled but I always get errors in the queue.c file. An example of the errors I get is &#8220;declaration of function &#8220;xQueueTakeMutexRecursive&#8221; is incompatible with a declaration in another translation&#8221;. I get roughly 15 errors in this file. If I remove the compiler option the code compiles perfectly and runs fine. Does anyone have any idea why these errors are coming up and how to avoid them?  
Thank you<br />
Keith  
</div></div><div class="thread-post"><h3 class="thread-post-title">Compiler errors in the queue.c file</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on March 21, 2011</div><div class="thread-post-content">I have never tried using that compiler options, so the following is just a guess:  
The &#40;deliberate&#41; data hiding in the FreeRTOS kernel means that something like an xQueueHandle is a pointer to a structure inside the queue.c source file, but a pointer to a void &#42; in all other files.&nbsp; It sounds like the compiler cannot cope with that when that particular option is used.  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">Compiler errors in the queue.c file</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on March 21, 2011</div><div class="thread-post-content">The problem is that the &#8220;Multi-file Compilation&#8221; option does not work with a mixed language project.&nbsp; The FreeRTOS kernel files must be compiled truly as C code, not C++ due to the way the data hiding is done &#40;and a few other Cisms in the code, not surprising since it is C code&#41;.  
You will either need to convert the code to be valid C++ code, which to start means changing the definition of handles from void &#42; to being struct xxxx&#42; &#40;xxx depending on the given handle&#41;, which may kick up a few other errors, or you need to turn off the &#8220;Multi-file Compilation&#8221; option &#40;this is what I did&#41;. You may also be able to change your project to compile FreeRTOS into a library module, and include that in your main project if you really need to use the Multi-file option.
</div></div><div class="thread-post"><h3 class="thread-post-title">Compiler errors in the queue.c file</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/ksoldavin">ksoldavin</a> on March 21, 2011</div><div class="thread-post-content">Thank you for the input. The reason I wanted to try the multiple file option was to help the optimizer remove more unused code. I will try to compile the RTOS as a library without that option and then include it in my project.  
Thanks<br />
Keith
