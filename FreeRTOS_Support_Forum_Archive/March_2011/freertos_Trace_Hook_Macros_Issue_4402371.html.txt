  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Trace Hook Macros Issue</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/tekkkon">tekkkon</a> on March 8, 2011</div><div class="thread-post-content">Hi all,  
I read the tutorial for Trace Hook Macros and got a couple of questions.  
In the example 2, how does the &#8220;reasonBLOCKING&#95;ON&#95;QUEUE&#95;READ&#8221; defined? And how does the &#8220;log&#95;event&#40;&#41;&#8221; function logging the task execution? Is there any specific example in the Demo that logging task execution sequences, task timing, kernel events?&nbsp;   
I ported it to CORTEX&#95;LM3Sxxxx Rowley, and suspect one of my task stopped working and the RTOS is locking up for some reason. So I&#8217;m trying to figure it out by API call logging. Thank you in advance&#33;  
/&#42; traceBLOCKING&#95;ON&#95;QUEUE&#95;RECEIVE&#40;&#41; is just one of the macros that can be used to record why<br />
a context switch is about to occur. &#42;/<br />
&#35;define traceBLOCKING&#95;ON&#95;QUEUE&#95;RECEIVE&#40;pxQueue&#41;&nbsp;&nbsp;&nbsp;&nbsp; <br />
&nbsp;&nbsp;&nbsp; ulSwitchReason = reasonBLOCKING&#95;ON&#95;QUEUE&#95;READ;  
/&#42; log&#95;event&#40;&#41; is an application defined function that logs which tasks ran when, and why. &#42;/<br />
&#35;define traceTASK&#95;SWITCHED&#95;OUT&#40;&#41;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; <br />
&nbsp;&nbsp;&nbsp; log&#95;event&#40; pxCurrentTCB, ulSwitchReason &#41;;  
</div></div><div class="thread-post"><h3 class="thread-post-title">Trace Hook Macros Issue</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on March 8, 2011</div><div class="thread-post-content">I think you are referring to the page about trace hook macros on the web site?&nbsp; Three of the five FreeRTOS tutorial books have already been updated to include a section on using the trace macros, with quite a comprehensive example included too &#40;another book has also been updated, but the example not yet ported&#41;.  
<blockquote>
  how does the &#8220;reasonBLOCKING&#95;ON&#95;QUEUE&#95;READ&#8221; defined
</blockquote>
reasonBLOCKING&#95;ON&#95;QUEUE&#95;READ is supposed to be just a unique constant that indicates that the context switch that is about to occur is occurring because the current task blocked on a queue read.&nbsp; In a real application, it would just be a number, nothing else.&nbsp; It is a hypothetical example so the definition of reasonBLOCKING&#95;ON&#95;QUEUE&#95;READ is not given.  
<blockquote>
  And how does the &#8220;log&#95;event&#40;&#41;&#8221; function logging the task execution?
</blockquote>
Again, its a hypothetical example, so log&#95;event&#40;&#41; is not doing anything.&nbsp; It is up to the application to decide how you want to log an event.&nbsp; It could be write to a RAM disk for example, but ideally it would be to communicate with a kernel aware debugger.&nbsp; The Cortex-M3 can output trace information in real time in a non intrusive manner, so if that was how the trace was output, log&#95;event&#40;&#41; would simply be a macro that wrote to the trace port.  
Regards.
