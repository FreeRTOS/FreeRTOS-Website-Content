  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">configASSERT fail on xQueueSendFromISR</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/joe_her">joe_her</a> on November 1, 2014</div><div class="thread-post-content">Trying to figure out why this happens, according to the comments in the code,:
/* The following assertion will fail if a service routine (ISR) for
            an interrupt that has been assigned a priority above
            configMAX<em>SYSCALL</em>INTERRUPT<em>PRIORITY calls an ISR safe FreeRTOS API
            function.  ISR safe FreeRTOS API functions must *only* be called
            from interrupts that have been assigned a priority at or below
            configMAX</em>SYSCALL<em>INTERRUPT</em>PRIORITY.<br />
&#8230; */
so I changed this HAL<em>NVIC</em>SetPriority to  configMAX<em>SYSCALL</em>INTERRUPT<em>PRIORITY, but it still fail.
This code is part of USB host, for STM32F4, code is the library by ST.
//&#8212;&#8212;&#8212;&#8212;&#8212;
 HAL</em>NVIC<em>SetPriorityGrouping(NVIC</em>PRIORITYGROUP<em>4);
 HAL</em>NVIC<em>SetPriority(OTG</em>FS<em>IRQn, configMAX</em>SYSCALL<em>INTERRUPT</em>PRIORITY, 0);
 HAL<em>NVIC</em>EnableIRQ(OTG<em>FS</em>IRQn);
//&#8212;&#8212;&#8212;&#8212;&#8212;-
Any ideas and tips how to debug this will help.
Thanks.
</div></div><div class="thread-post"><h3 class="thread-post-title">configASSERT fail on xQueueSendFromISR</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on November 1, 2014</div><div class="thread-post-content">configMAX<em>SYSCALL</em>INTERRUPT<em>PRIORITY is probably a full 8 bit value, whereas NVIC</em>SetPriority() requires a shifted priority.  I know this is complex but it is how the Cortex-M works.  I tried explaining it on this page: http://www.freertos.org/RTOS-Cortex-M3-M4.html
Most newer projects have a conversion in the FreeRTOSConfig.h file, something like the following:
<div style="background: #ffffff; overflow:auto;width:auto;border:solid gray;border-width:.1em .1em .1em .8em;padding:.2em .6em;"><pre style="margin: 0; line-height: 125%"><span style="color: #888888">/* Cortex-M specific definitions. */</span>
<span style="color: #557799">#ifdef __NVIC_PRIO_BITS</span>
    <span style="color: #888888">/* __BVIC_PRIO_BITS will be specified when CMSIS is being used. */</span>
    <span style="color: #FF0000; background-color: #FFAAAA">#</span>define configPRIO_BITS              __NVIC_PRIO_BITS
<span style="color: #557799">#else</span>
    <span style="color: #FF0000; background-color: #FFAAAA">#</span>define configPRIO_BITS              <span style="color: #0000DD; font-weight: bold">4</span>        <span style="color: #888888">/* 15 priority levels */</span>
<span style="color: #557799">#endif</span>
<span style="color: #888888">/* The lowest interrupt priority that can be used in a call to a &quot;set priority&quot;</span>
<span style="color: #888888">function. */</span>
<span style="color: #557799">#define configLIBRARY_LOWEST_INTERRUPT_PRIORITY            0xf</span>
<span style="color: #888888">/* The highest interrupt priority that can be used by any interrupt service</span>
<span style="color: #888888">routine that makes calls to interrupt safe FreeRTOS API functions.  DO NOT CALL</span>
<span style="color: #888888">INTERRUPT SAFE FREERTOS API FUNCTIONS FROM ANY INTERRUPT THAT HAS A HIGHER</span>
<span style="color: #888888">PRIORITY THAN THIS! (higher priorities are lower numeric values. */</span>
<span style="color: #557799">#define configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY   5</span>
<span style="color: #888888">/* Interrupt priorities used by the kernel port layer itself.  These are generic</span>
<span style="color: #888888">to all Cortex-M ports, and do not rely on any particular library functions. */</span>
<span style="color: #557799">#define configKERNEL_INTERRUPT_PRIORITY        ( configLIBRARY_LOWEST_INTERRUPT_PRIORITY &lt;&lt; (8 - configPRIO_BITS) )</span>
<span style="color: #888888">/* !!!! configMAX_SYSCALL_INTERRUPT_PRIORITY must not be set to zero !!!!</span>
<span style="color: #888888">See http://www.FreeRTOS.org/RTOS-Cortex-M3-M4.html. */</span>
<span style="color: #557799">#define configMAX_SYSCALL_INTERRUPT_PRIORITY   ( configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY &lt;&lt; (8 - configPRIO_BITS) )</span>
</pre></div>
So in that case configLIBRARY<em>LOWEST</em>INTERRUPT<em>PRIORITY is set by hand as a shifted value (and therefore easier to understand for a human) and configKERNEL</em>INTERRUPT<em>PRIORITY is then generated automatically.  Likewise configLIBRARY</em>MAX<em>SYSCALL</em>INTERRUPT<em>PRIORITY and configMAX</em>SYSCALL<em>INTERRUPT</em>PRIORITY.
The &#8216;LIBRARY&#8217; prefix denoting that it is the version to be used in library function calls.  So in your code you want to use configLIBRARY<em>MAX</em>SYSCALL<em>INTERRUPT</em>PRIORITY to prevent the assert triggering.
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">configASSERT fail on xQueueSendFromISR</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/joe_her">joe_her</a> on November 2, 2014</div><div class="thread-post-content">I read the page at http://www.freertos.org/RTOS-Cortex-M3-M4.html as it is in the comment above the assert line, but did not understand that I need to use configLIBRARY<em>LOWEST</em>INTERRUPT_PRIORITY.
This solved the problem.
Thank you.
