  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">PIC32MZ Assert/exception in vListInsertEnd()</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/jmmag">jmmag</a> on November 4, 2014</div><div class="thread-post-content">As a preface, I had typed up a lengthy post describing my methods for diagnosing this problem, but lost it without warning when the page navigated to the &#8216;CodeHilite&#8217; documentation.  So I apologize in advance if this initial post does not seem as detailed (or marked-up) as what it would have been.
Anyway, I have been encountering issues when sending messages from a DMA ISR to a task queue via xQueueSendFromISR().  The address error exception occurs at this line:
pxIndex->pxPrevious->pxNext = pxNewListItem;
and when debugging I see that the stack is indeed overflowing, but have tried a number of things to address the issue (increasing stack, configMAX<em>SYSCALL</em>INTERRUPT_PRIORITY, etc.) without much success.  Any help would be appreciated.
Thanks,
Jon
</div></div><div class="thread-post"><h3 class="thread-post-title">PIC32MZ Assert/exception in vListInsertEnd()</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/edwards3">edwards3</a> on November 4, 2014</div><div class="thread-post-content">The PIC32 port uses configISR<em>STACK</em>SIZE in FreeRTOSConfig.h to size the stack used by interrupts. Have you tried increasing that?
</div></div><div class="thread-post"><h3 class="thread-post-title">PIC32MZ Assert/exception in vListInsertEnd()</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/jmmag">jmmag</a> on November 4, 2014</div><div class="thread-post-content">Yes, I stopped at 8k; furthermore all of my ISR variables are either global or static and the queue element is only 4 ints in size.  I have <a href="https://sourceforge.net/p/freertos/discussion/382005/thread/a55c744b/">found</a> a few <a href="https://sourceforge.net/p/freertos/discussion/382005/thread/f1151277/">different threads</a> that deal with <a href="https://sourceforge.net/p/freertos/discussion/382005/thread/20cf7379/">similar</a> issues, but none seem to match mine exactly.  Although, <a href="https://sourceforge.net/p/freertos/discussion/382005/thread/9da2e384/#5226">this post</a> seems to describe my situation of the exponential stack usage, but the ISR flags aren&#8217;t reset until after xQueueSendFromISR() finishes.  So there should be no chance for recursion, at least above the hood.
Jon
</div></div><div class="thread-post"><h3 class="thread-post-title">PIC32MZ Assert/exception in vListInsertEnd()</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on November 4, 2014</div><div class="thread-post-content">There are two  ways  of  defining  interrupts  on the  PIC32. One uses the compiler syntax  to get the compiler  to generate  the interrupt entry code, the other uses an assembly file wrapper to switch  stacks on interrupt  entry  in order to save a lot of RAM. Which method  are you  using?
Regards .
</div></div><div class="thread-post"><h3 class="thread-post-title">PIC32MZ Assert/exception in vListInsertEnd()</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/jmmag">jmmag</a> on November 4, 2014</div><div class="thread-post-content">I am using the latter method of wrapping the InterruptHandler into the assembly InterruptWrapper just like all of the demos supplied by FreeRTOS &amp; Microchip.
Another point worth mentioning is that the issue goes away when I decrease the interrupt frequency.  Is it possible for an ISR to yield to its own interrupt if one happens before portEND<em>SWITCHING</em>ISR() exits?  Perhaps I shouldn&#8217;t be clearing the interrupt flag until I know <em>for sure</em> that the ISR has exited.
</div></div><div class="thread-post"><h3 class="thread-post-title">PIC32MZ Assert/exception in vListInsertEnd()</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on November 5, 2014</div><div class="thread-post-content">On a lot of architectures it would not be possible for an ISR to yield 
to its own interrupt, but I&#8217;m not sure on the MIPs.  It depends on the 
interrupt controller implementation.
