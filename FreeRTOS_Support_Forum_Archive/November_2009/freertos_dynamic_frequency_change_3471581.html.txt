  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">dynamic frequency change</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/allanon74">allanon74</a> on November 27, 2009</div><div class="thread-post-content">Hi all,<br />
in a cortexM3 &#40;stm32&#41; project i am using FreeRTOS and i need to change dynamically core frequency &#40;min being 8Mhz and max 72Mhz, default 16Mhz&#41;.  
in an old post Richard Barry suggested the following:<br />
&#42;In SourceportableMPLABPIC32MXport.c you will see the function vPortIncrementTick&#40;&#41;. This calls vTaskIncrementTick&#40;&#41; just once. If you have the frequency, change this so vTaskIncrementTick is called twice. If you quarter the frequency, change this so it is called 4 times. Etc.&#42;  
i was wondering if i can instead change the systick interrupt config when i change core freq.  
Thanks<br />
Beppe
</div></div><div class="thread-post"><h3 class="thread-post-title">dynamic frequency change</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on November 27, 2009</div><div class="thread-post-content">Not sure exactly what you are asking &#8211; but you have to ensure that time moves at the same speed for the kernel.&nbsp; If you slow down the core speed by 2, then assuming this causes the tick interrupt occurs at half the frequency, you will have to call vTaskIncrementTick&#40;&#41; twice in each tick interrupt.  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">dynamic frequency change</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on November 27, 2009</div><div class="thread-post-content">Richard, I believe that he is asking if you cut the clock speed in half, and also cut the clock cycles per tic interrupt in half &#40;so the tics still happen at the same rate&#41; with that work, and I think it should. It will increase the overhead by the tic interrupt, but that is sort of to be expected.
</div></div><div class="thread-post"><h3 class="thread-post-title">dynamic frequency change</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on November 27, 2009</div><div class="thread-post-content">Richard&#95;damon, I agree with you.  
Regards.
