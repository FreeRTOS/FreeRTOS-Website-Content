</div></div><div class="thread-post"><h3 class="thread-post-title">round-robin (time-slicing algo)</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/*anonymous">*anonymous</a> on November 25, 2009</div><div class="thread-post-content">A real-time system usually does not deal with time-sharing. A highest priority task runs until it either voluntarily relinguishes the processor &#40;to sleep for example&#41; or gets preempted by a higher priority task &#40;which gets created or unblocked&#41;.  
This way, you make the best usage of the CPU since while your task is running you use 100% of it &#40;minus the IRQ handlers&#41; and do not spend any time switching context.

</div></div><div class="thread-post"><h3 class="thread-post-title">round-robin (time-slicing algo)</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on November 25, 2009</div><div class="thread-post-content">First off &#8211; all this is explained &#40;hopefully&#41; very clearly in the e-book, if you don&#8217;t mind me giving it a plug.&nbsp; Also, the execution model is very traditional, and the behaviour similar to other systems.  
The following only applies if you have configUSE&#95;PREEMPTION set to 1:  
FreeRTOS is a priorities pre-emptive system and will always run the highest priority task that is able to run.&nbsp; By able to run I mean, not blocked waiting for a time &#40;vTaskDelay&#40;&#41;, etc.&#41; or blocked waiting for a queue or semaphore event.&nbsp; If a task become able to run and it has a priority above the currently running task it will pre-empt the currently running task and so run immediately.  
Where you have two tasks of the same priority that are both able to run &#40;neither are blocked&#41; then the scheduler will share processing time between them &#8211; but only if there are no higher priority tasks.&nbsp; It does this by switching between them on each tick interrupt.  
Regards.
