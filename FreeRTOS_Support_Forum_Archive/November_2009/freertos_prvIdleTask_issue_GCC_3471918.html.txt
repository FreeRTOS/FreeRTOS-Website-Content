  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">prvIdleTask issue (GCC)</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/iammrt">iammrt</a> on November 27, 2009</div><div class="thread-post-content">Hey there,  
i want to compile FreeRTOS &#40;v6.0.1&#41; with gcc 4.2.3. I get the Error &#8220;prvIdleTask undeclared &#40;first use in function&#41;&#8221; in tasks.c line 1027. As i can see there is the implementation of the function as macro in line 1781 where i get the Warning &#40;&#8221;return type default to int&#8221;&#41; and there is the Prototype declaration in line 325 where i get the warning &#8220;parameter names without types in function declaration&#8221;.<br />
Is this a compiler specific problem? I havent touched the Kernel code, so this can only be a problem with the port, an problem with the compiler or a general issue in the OS &#40;what i dont think can be&#41;.  
Is there someone getting the same error with GCC?
</div></div><div class="thread-post"><h3 class="thread-post-title">prvIdleTask issue (GCC)</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on November 27, 2009</div><div class="thread-post-content">tasks.c is part of the core code, not the port code, so this is not a port issue as such.&nbsp; Although portTASK&#95;FUNCTION&#95;PROTO and portTASK&#95;FUNCTION, which are used in the prototype and definition of prvIdleTask&#40;&#41;, should be defined in portmacro.h which is part of the port layer.  
&#43; Which port are you using?&nbsp; Are these macros in the portmacro.h file you are including?<br />
&#43; Where did you get your GCC version from, I didn&#8217;t realise there was a 4.2.3 version.&nbsp;<br />
&#43; Did you build your GCC exe yourself?  
In nearly all ports the macros don&#8217;t actually do anything and expand to  
void prvIdleTask&#40; void &#42;pvParameters &#41;;  
You could manually change the offending lines to that to get running, but I would be interested to know what the problem is.  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">prvIdleTask issue (GCC)</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/iammrt">iammrt</a> on November 27, 2009</div><div class="thread-post-content">&#8211;&nbsp; I&#8217;am using this Port: &#8220;FreeRTOSSourceportableGCCARM&#95;CM3&#8221; I think the macros are included in the file, and the header file is included to the build.<br />
&#45; You can find GCC 4.2.3 here <a href="http://gcc.gnu.org/gcc-4.2">http://gcc.gnu.org/gcc-4.2</a>&nbsp; I know there is 4.4.x allready avaible but the 4.2.x is still working fine for me, and why change it when there is everything working fine.<br />
&#45; Since i&#8217;m using openSuse I compiled GCC bymyself, yes.
</div></div><div class="thread-post"><h3 class="thread-post-title">prvIdleTask issue (GCC)</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on November 27, 2009</div><div class="thread-post-content">Are you sure that version of GCC supports THUMB2 instructions.&nbsp; It might do, but if it does I would guess it was one of the first versions that does.&nbsp; See <a href="http://www.codesourcery.com/sgpp/lite/arm/download.html">http://www.codesourcery.com/sgpp/lite/arm/download.html</a> &#45; EABI is the build you want.  
I would suggest getting a pre-built version of GCC.&nbsp; You can get the CodeSourcery Lite version for free with a convenient installer.&nbsp; That should compile the code with no problem.&nbsp;   
Also, start with a pre-configured makefile, that is what they are there for.&nbsp; You should be able to build the makefile found in the directory FreeRTOSDemoCORTEX&#95;LM3Sxxxx&#95;EclipseRTOSDemo using the CodeSourcery build without any problems &#40;unless you are using Linux, in which case you may find the occasional case sensitivity problem in file names or include file names&#41;.&nbsp; The makefile uses files from the directory you say you are trying to use.  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">prvIdleTask issue (GCC)</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/iammrt">iammrt</a> on November 30, 2009</div><div class="thread-post-content">Thanks for advice. I installed latest version of GCC and it worked. So the problem was probably the Thumb-2 Support of the 4.2.x Version of GCC. It supports Thumb code for sure, but Thumb-2 not.
