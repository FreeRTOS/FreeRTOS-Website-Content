</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS-Plus-TCP-multi with Zynq</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on May 21, 2018</div><div class="thread-post-content">If I had the time, I should compile the library with all combinations of flags.  In my case, I both have <code>ipconfigUSE_DNS</code> and <code>ipconfigUSE_NBNS</code> enabled, so I didn&#8217;t notice the problem.
In <code>FreeRTOS_UDP_IP.c</code>, you should make this little change around line 67:
~~~
 #include &#8220;FreeRTOS_Routing.h&#8221;
-#if( ipconfigUSE<em>DNS == 1 )
+#if( ipconfigUSE</em>DNS == 1 ) || ( ipconfigUSE<em>NBNS == 1 )
    #include &#8220;FreeRTOS</em>DNS.h&#8221;
 #endif
 /* The expected IP version and header length coded into the IP header itself. */
~~~
I attached the <code>FreeRTOSIPConfig.h</code> that I used for a Xilinx/Zynq project.
Note that <code>ipconfigUSE_NETWORK_EVENT_HOOK</code>, the application Network Event hook, is very useful. When it is called for the first time with <code>eNetworkEvent == eNetworkUp</code>, you can start the necessary TCP- and UDP-servers.
Note that in FreeRTOS+TCP/multi, the application hook will be called for every defined end-point.
~~~
<h1>if( ipconfigMULTI_INTERFACE != 0 )</h1>
<pre><code>void vApplicationIPNetworkEventHook( eIPCallbackEvent_t eNetworkEvent, NetworkEndPoint_t *pxEndPoint )
</code></pre>
<h1>else</h1>
<pre><code>void vApplicationIPNetworkEventHook( eIPCallbackEvent_t eNetworkEvent )
</code></pre>
<h1>endif</h1>
<pre><code>{
}
</code></pre>
~~~
Something about address binding: within FreeRTOS+TCP /multi, a port number can only be bound once. When binding a socket, the IP-address provided is ignored.  So if you bind a socket to e.g. port number 5001, that server socket will receive connection requests from all interfaces.  The function <code>FreeRTOS_accept()</code> will tell you which client is connecting to your server.
An equivalent in Berkeley sockets is to bind a socket to the IP-address <code>0.0.0.0</code>.
~~~
    xBindAddress.sin<em>len = sizeof( xBindAddress );
    xBindAddress.sin</em>family = FREERTOS<em>AF</em>INET;
    xBindAddress.sin<em>addr = 0ul;
    xBindAddress.sin</em>port = FreeRTOS_htons( 5001 ); /* Bind to server port number. */
~~~

<blockquote>
  function lUDPLoggingPrintf() is needed when ipconfigHAS_PRINTF is being (1)
</blockquote>
This is a function from a module called <code>CommonUtilitiesUDPLoggingPrintf.c</code>, which was added to the FreeRTOS+TCP demo&#8217;s. As I made some changes to the module for <code>ipconfigMULTI_INTERFACE</code>, so I will attach the latest versions to this post.
<blockquote>
  uxRand(), i found there is one such function defined in main.c under demo for Window_Simulator. Can it be use?
</blockquote>
Yes, as long as it generates ( pseudo ) random numbers, it is OK.
It would be good, if you can set it&#8217;s seed just after the device has started up.  That saves lots of problems later on, while testing TCP.  If <code>uxRand()</code> always returns the same series of numbers, the IP-stack won&#8217;t issue truly random port numbers, and the TCP sequence numbers will always start with the same values, which is not secure.
<blockquote>
  I am wondering, if DHCP is enabled, will the stack auto switch to static IP
  after sometime if it cannot locate any IP address (i think lwIP demo example
  is doing it this way).
</blockquote>
Yes sure, when DHCP fails, you can choose to use either a fixed configured IP-address, or you start using &#8220;auto-IP&#8221; if <code>ipconfigDHCP_FALL_BACK_AUTO_IP</code> is defined. &#8220;auto-IP&#8221; assigns a Link Layer IP address in the range 169.254.x.x.
DHCP has an application hook ( see <code>ipconfigUSE_DHCP_HOOK</code> ), which let&#8217;s you decide what action to take:
~~~
            #if( ipconfigUSE<em>DHCP</em>HOOK != 0 )
                /* Ask the user if a DHCP request is required. <em>/
                eAnswer = xApplicationDHCPHook( eDHCPPhasePreRequest, pxEndPoint->xDHCPData.ulOfferedIPAddress );
                if( eAnswer == eDHCPContinue )
            #endif  /</em> ipconfigUSE<em>DHCP</em>HOOK */
~~~
where <code>eDHCPContinue</code> means: accept the offer.
