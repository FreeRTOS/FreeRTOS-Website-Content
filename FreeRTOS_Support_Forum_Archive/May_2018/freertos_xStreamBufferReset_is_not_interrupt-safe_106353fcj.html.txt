  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">xStreamBufferReset is not interrupt-safe</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/lpmay">lpmay</a> on May 18, 2018</div><div class="thread-post-content">Hi,
I think I may have stumbled into a bug with <code>xStreamBufferReset</code>, and how it interacts with <code>xStreamBufferSendFromISR</code>.  Perhaps it&#8217;s just a misunderstanding on my, part and if so I think the documentation could probably be a little more clear.
Basically, I thought it was always safe to call <code>xStreamBufferReset</code>, but in fact if <code>FromISR</code> functions are used it is not safe, unless interrupts are disabled.  Since <code>xStreamBufferReset</code> ultimately clears the underlying stream structure and then re-populates it with interrupts enabled, it is possible for an interrupt to fire while the structure is not in a valid state.  If that interrupt tries to access the StreamBuffer, even with one of the <code>fromISR</code> functions that access will fail (and <code>configASSERT</code>).  
In pseudo-code, my setup is something like this:
&#8220;`
:::c
void ISR(void)
{
    &#8230;
    xStreamBufferSendFromISR(/* new byte */);
    &#8230;
 }
void process_bytes(void)
{
while(1){
/* start with a fresh stream */
xStreamBufferReset();
/*
&#8230; receive from stream multiple times, continue if error encountered
*/
return;
}
&#8220;`
In my opinion, there should be a specific note in the documenation that <code>xStreamBufferReset</code> is not safe to use with the <code>FromISR</code> functions, or better yet the implementation should be changed such that <code>xStreamBufferReset</code> is safe to use with the <code>FromISR</code> functions.
Am I missing something more fundamental?  Should I open a support ticket?  Thanks for any help!
</div></div><div class="thread-post"><h3 class="thread-post-title">xStreamBufferReset is not interrupt-safe</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on May 18, 2018</div><div class="thread-post-content">Thanks for pointing this out &#8211; I have added a crticial section within the xStreamBufferReset() function to make it safe from interrupt access while it is being reset.  The code will be checked into the public SVN repo once it has been tested.

My current work-around is that my code wraps it&#8217;s call to <code>xStreamBufferReset()</code> with an interrupt enable/disable, but it would be nice to delegate this responsibility back to the updated <code>xStreamBufferReset()</code>.
