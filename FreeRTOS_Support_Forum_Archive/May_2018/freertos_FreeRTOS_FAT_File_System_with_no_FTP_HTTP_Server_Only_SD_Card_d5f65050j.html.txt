</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS+FAT File System with no FTP/HTTP Server, Only SD Card</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on May 8, 2018</div><div class="thread-post-content">Hola Oscar,
<blockquote>
  Is it possible to create a FAT System with the FreeRTOS+FAT
  that runs entirely on the microcontroller (NO FTP/HTTP SERVERS!)
</blockquote>
Sure that is possible. You will only have to include the +FAT sources, along with the appropriate +FAT driver. And then you can access an SD-card by using the pseudo stdio functions, as defined in &#8220;ff_stdio.h&#8221;.
If you like, it is also possible to create a RAM disk.
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS+FAT File System with no FTP/HTTP Server, Only SD Card</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on May 8, 2018</div><div class="thread-post-content">Sorry, I didn&#8217;t answer all of your questions:
<blockquote>
  I would like to know which libraries would be necessary to include
</blockquote>
Depending on the platform: 
~~~
FreeRTOS-Plus-FATportableSTM32F4xxff<em>sddisk.c
FreeRTOS-Plus-FATportableSTM32F4xxstm32f4xx</em>hal_sd.c
FreeRTOS-Plus-FATportableSTM32F7xxff<em>sddisk.c
FreeRTOS-Plus-FATportableSTM32F7xxstm32f7xx</em>hal_sd.c
FreeRTOS-Plus-FATportablelpc18xxff_sddisk.c
FreeRTOS-Plus-FATportableATSAM4Eff_sddisk.c
~~~
Remember, if you have to store loads of data, try to cache the data in buffers and write them to the SD-card in multiples of at least 512 bytes. The bigger the write blocks, the faster data will be written.
If you&#8217;re only writing a few bytes, you can as well use a formatting <code>ff_printf()</code>.

</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS+FAT File System with no FTP/HTTP Server, Only SD Card</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on May 9, 2018</div><div class="thread-post-content">Hi Oscar,
The source file <code>ATSAM4Eff_sddisk.c</code> should be a good basis for any other Atmel controller. But you will have to merge it with the low-level driver that is available for your ATSAM3X8C.
The most important functions of any ff_sddisk.c are these :
~~~
static int32<em>t prvFFRead( uint8</em>t *pucBuffer, uint32_t ulSectorNumber, uint32_t ulSectorCount, FF_Disk_t *pxDisk )
static int32_t prvFFWrite( uint8_t *pucBuffer, uint32_t ulSectorNumber, uint32_t ulSectorCount, FF_Disk_t *pxDisk )
~~~
And the initialisation is also pretty generic:
~~~
FF<em>Disk</em>t *FF_SDDiskInit( const char *pcName )
~~~
It creates a <code>FF_Disk_t</code> with an I/O manager ( <code>pxDisk-&gt;pxIOManager</code> ).
If you find it complicated, you can write me directly to: hein [at] htibosch [point] net
That will be quicker rather than writing many posts about boring details.
