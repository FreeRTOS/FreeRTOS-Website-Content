  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">FreeRtos problems in ADC task and Streaming Task</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/andreahmed">andreahmed</a> on May 25, 2018</div><div class="thread-post-content">I have an ADC task that uses 4 channels and uses the DMA for transfer I also have a streaming client which streams the ADC data thur the TCP socket I made the ADS Task lower priority than the streaming client.
I&#8217;m sending an integer that selects which ADC channel is selected as a message queue to the streaming client.
The problem is I get queue overflow when sending that adc channel integer.
ADC TASK
~~~
if(bufferSelect != BUFFERS<em>NOT</em>READY)
        {
            if(xQueueSend(g<em>adcQueue, &amp;bufferSelect,  0) != pdPASS)
            {
                throwError(ERROR</em>MESSAGE<em>QUEUE</em>FULL);
                PRINTF(&#8220;%srn&#8221;, getErrorMessage(ERROR<em>MESSAGE</em>QUEUE<em>FULL));
            }
            bufferSelect = BUFFERS</em>NOT_READY;
        }
~~~
Streaming client task
~~~
/* obtain next buffer ready event */
        if(xQueueReceive(g_adcQueue, &amp;bufferSelect, 0) == pdFALSE)
        {
            g_stopStreaming = true;
            continue;
        }
~~~
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRtos problems in ADC task and Streaming Task</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on May 25, 2018</div><div class="thread-post-content">In both the queue read and queue write case you have a block time of 0. 
If you add a block time you will get a natural flow control as the queue 
becomes full (or empty as the case may be).  Also if you only have one 
reader and one writer consider a stream or message buffer as a more 
efficient means of sending the data.
