Could there be an exception, that ends in an eternal loop <code>for(;;)</code>?
Does your function <code>digitalRead()</code> always succeed? Or does it wait for a condition that sometimes does not occur?
<blockquote>
   esp if that function happens to be in a different cpp file e.g.
</blockquote>
It should not make any difference in which source file a function is located.
Are you using C++ ? That should work OK with FreeRTOS, as long as the compiler knows the linkage type of every function ( C versus C++ ).
C-only headers will often include these statements:
~~~
    #ifdef __cplusplus
    extern &#8220;C&#8221; {
    #endif
<pre><code>/* Put your C declarations here */
#ifdef __cplusplus
}
#endif
</code></pre>
~~~
Mind you that constructors of global and static C++ objects, are being called before <code>main()</code> is active. If you use the option <code>nostartfiles</code>, you will have to call the constructors your self. Also make sure that in these constructors, you can not use many resources: for instance the heap has not been set-up yet before <code>main()</code> is running.
The code that you&#8217;re showing is simple and looks good to me.

Good pointers! I&#8217;ve come across such cases before and to avoid them, I&#8217;ve added a good amount of precautionary measures as follows:
<ul>
<li>all tasks have while(true) or for( ; ; ) loops</li>
<li>all tasks defined as static</li>
<li>no while(true) or for( ; ; ) loop exists without vTaskDelay()</li>
<li>software doesn&#8217;t try to access invalid memory e.g. task handles, and semaphores</li>
<li>no unsupported blocking function is called e.g. Arduino&#8217;s delay()</li>
<li>semaphores are accessed only when available</li>
<li>after deleting tasks, assign their task handles to NULL and call vTaskDelay()</li>
</ul>
I&#8217;ll look into the C-only headers and double check the library if the expressions need to be added.

  Do you mind elaborating on this part please?

Well, here is an example to make it clear:
~~~
class CMyClass {
    uint8_t *pcBuffer;
public:
    CMyClass();
    ~CMyClass();
};
CMyClass::CMyClass()
{
    // main() might not be running yet
    pcBuffer = pvPortMalloc( BUFFER_SIZE );
}
CMyClass::~CMyClass()
{
    // This might never get called
    vPortFree( pcBuffer );
}
// Constructor will be called <em>before</em> main is active.
// Destructor  will be called <em>after</em> main has exit,
// which never happens
CMyClass globalObject;
int main()
{
    // Initialise hardware.
    // Initialise heap.
<pre><code>// Here OK : heap has been initialised
// The destructor is never called because
// vTaskStartScheduler() never returns
CMyClass autoObject;
// Start scheduler.
vTaskStartScheduler();
</code></pre>
}
~~~
