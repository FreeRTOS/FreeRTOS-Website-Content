  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">10 byte offset when fetching a structure from a queue with
 xQueueReceiveFromISR()</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/ajellisuk">ajellisuk</a> on May 23, 2018</div><div class="thread-post-content">Hello
I have a project where I am collecting packets of data using an STM32F745 and then sending them via an SPI port to a master device (the mcu is an spi slave). When I receive the packets of data I place them into a buffer held within a structure, and place the structure in a queue. My SPI ISR retrieves the structures from the queue and copies them into a dma buffer ready for sending to the master device. The problem I have is that when I retrive the structure from the queue, the data appears to be offset by 8 bytes. I have looked at this page https://www.freertos.org/a00118.html for an example of how to queue a structure, but am still having problems.
My structure is:
~~~
<h1>define INTERNAL<em>BUFF</em>SIZE 248</h1>
typedef struct tSPIPacket
{
 uint8<em>t flags;
 uint8</em>t checksum;
 uint8<em>t framecount;
 uint8</em>t frametime;
 uint64_t timestamp;
 uint8<em>t size;    //size of structure, not amount of data
 uint8</em>t packetid;   //an id for the entire packet (large data split across transfers have same id)
 uint8<em>t xferid;   //id for transfer in packet (0=first transfer for packet, 1=second etc)
 uint8</em>t xfersize;  //number of data bytes in this transfer
 uint32<em>t totaldatasize;   //total amount of data in the packet
 uint32</em>t datatype;   //fourcc, 
 uint8<em>t data[INTERNAL</em>BUFF<em>SIZE];
} SPI</em>Packet;
extern SPI<em>Packet Spi</em>Buffer;
extern SPI<em>Packet *Spi</em>Buffer2;
~~~
Then the code for creating the queue, and placing data onto the queue is:
~~~
spi<em>queue = xQueueCreate( 100, sizeof( SPI</em>Packet  *) );
memcpy(Spi<em>Buffer.data[0], <incoming data>, INTERNAL</em>BUFF<em>SIZE);
      // Fill out the packet header
      Spi</em>Buffer.flags = 0;
      Spi<em>Buffer.checksum = 0;
      Spi</em>Buffer.framecount = 1;
      Spi<em>Buffer.frametime = 1;
      Spi</em>Buffer.timestamp = 1;
      Spi<em>Buffer.size = sizeof(SPI</em>Packet);
      Spi<em>Buffer.packetid = 0;
      Spi</em>Buffer.xferid = 0;
      Spi<em>Buffer.xfersize = INTERNAL</em>BUFF<em>SIZE;
      Spi</em>Buffer.totaldatasize = INTERNAL<em>BUFF</em>SIZE + sizeof(SPI<em>Packet);
      Spi</em>Buffer.datatype =  FOURCC;
&amp;Spi<em>Buffer, ( TickType</em>t ) 0 );
      SPI<em>Packet *spitmp=&amp;Spi</em>Buffer;
      xQueueSend( spi<em>queue, ( void * ) spitmp, ( TickType</em>t ) 0 );
And the code for retriving the structures and placing them into the dma buffer is:
// Arm the SPI and DMA to Tx bytes from aSPITxBuffer
            if ( xQueueReceiveFromISR( spi<em>queue, ( void * ) &amp;(Spi</em>Buffer2), &amp; xTaskWokenByReceive) )
            {
                memset ( aSPITxBuffer, 0, 256 ); // ensure tx buffer is clear
                memcpy(&amp;aSPITxBuffer[1], &amp;Spi<em>Buffer2, 256);
                HAL</em>SPI<em>TransmitReceive</em>DMA(&amp;hspi5, (uint8<em>t*)&amp;aSPITxBuffer[0], (uint8</em>t *)&amp;aSPIRxBuffer[0], 256);
                return; // Return from he as we don&#8217;t want to be re armed for receive only
            }
            if ( xTaskWokenByReceive != pdFALSE )
            {
                /* We should switch context so the ISR returns to a different task.
                   NOTE:  How this is done depends on the port you are using.  Check
                   the documentation and examples for your port. */
                HAL_SPI_Receive_DMA(&amp;hspi5, (uint8_t *)aSPIRxBuffer, 7);
                taskYIELD ();
            } 
~~~
I am using the intermediate buffer aSPITxBuffer to make this issue easier to debug.
Can someone please suggest why I&#8217;m getting the 8 byte offset when I retrieve Spi_Buffer2 from the queue please?
Thanks in advance
Andrew
</div></div><div class="thread-post"><h3 class="thread-post-title">10 byte offset when fetching a structure from a queue with
 xQueueReceiveFromISR()</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on May 24, 2018</div><div class="thread-post-content">Your memcpy call places the data at &amp;aSPITxBUFFER[1], and then you send &amp;aSPITxBuffer[0]. I don&#8217;t see a definition of the buffer, but that seems to be a possible source of an offset.
</div></div><div class="thread-post"><h3 class="thread-post-title">10 byte offset when fetching a structure from a queue with
 xQueueReceiveFromISR()</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/ajellisuk">ajellisuk</a> on May 24, 2018</div><div class="thread-post-content">Hi Richard
Thank you for your reply.
The definition of the buffer is:
~~~
uint8_t aSPITxBuffer[282] = {0};
~~~
The reson for the 1 byte offset with memcopy is because when the spi transfer is started, the first by of the buffer is droped by the master as it is clocked out with the write cycle. If I create a dummby buffer like the one below:
~~~
uint8_t aSPITestTxBuffer[21] = {0x00,0xDE,0xAD,0xBE,0xEF,0x60,0x0D,0xF0,0x0D,0x00,0x01,0x02,0x03,0x04,0x05,0x06,0x07,0x08,0x09,0x0A,0x00};
~~~
I can perform the same memcopy witht he 1 byte offset and the spi transfer works correctly. I.E:
~~~
memcpy(&amp;aSPITxBuffer[1], &amp;aSPITestTxBuffer, 21);
                HAL<em>SPI</em>TransmitReceive<em>DMA(&amp;hspi5, (uint8</em>t*)&amp;aSPITxBuffer[0], (uint8_t *)&amp;aSPIRxBuffer[0], 256); // 272 is the max no bytes the cavium can hadnle in 1 go
~~~
The problem is when I&#8217;m trying to retrive the data from the queue. Previosuly I have placed the output of the queue straight into the dma buffer, and I saw the same issue at the master.
Andrew
