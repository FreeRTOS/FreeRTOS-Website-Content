</div></div><div class="thread-post"><h3 class="thread-post-title">LOW POWER MODE | INTERUPT MSP432</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on June 23, 2019</div><div class="thread-post-content">I don&#8217;t know anything about the code you are linking to so my answer is
generic.
How the system will behave will depend on what the low power mode is
doing and the clock used to generate the tick interrupt.  If you just
leave the clock that generates the tick interrupt running, and the low
power mode also keeps the clock running, then you will most likely leave
low power mode whenever the next tick interrupt occurs.  I&#8217;m afraid I
don&#8217;t know which clock you are using to generate the tick or what
PCM<em>LPM0</em>LDO_VCORE0 does so suggest having a look at the following for
more info: https://www.freertos.org/low-power-tickless-rtos.html

I was putting the MCU in low power mode using the <strong>PCM_setPowerState()</strong>.  Now I understand the situation better :D. The <strong>xMaximumPossibleSuppressedTicks</strong> is very low, 349 ticks.  Instead of put MCU in low power mode I used <strong>vPortSuppressTicksAndSleep()</strong>  in a wrapper  function [CODE1]. It is working, but I&#8217;d like to put the microcontroller in a non-working state.
I saw the link that you sent and the <a href="https://www.freertos.org/low-power-ARM-cortex-rtos.html"> Low Power RTOS For ARM Cortex-M MCUs</a> material, but I&#8217;m bit confused whether I can configure two SysTick sources. Is it possible to use two SysTick sources? One used when the MCU needs more power and another when the hibernate mode is required.
I appreciate your help.
CODE1:
~~~
void hibernate(uint8<em>t time</em>ms)
{
<pre><code>int clockFrequency = 48000000;  //48MHz
int tickRateHZ = 1000;           //1KHz
int timerCountsForOneTick = (clockFrequency / tickRateHZ); // 48000 - timer for one tick 20,8ms
int maximumPossibleSuppressedTicks = portMAX_24_BIT_NUMBER
        / timerCountsForOneTick 349 ticks;
int iterations = time_ms / maximumPossibleSuppressedTicks;
int i = 0;
for (i = 0; i &lt; iterations; i++)
{
    vPortSuppressTicksAndSleep(maximumPossibleSuppressedTicks); // loop to complete the time
}
</code></pre>
~~~
</div></div><div class="thread-post"><h3 class="thread-post-title">LOW POWER MODE | INTERUPT MSP432</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on June 23, 2019</div><div class="thread-post-content">The default tickless idle operation does not use tick sources, but if
you provide your own &#8216;suspend and sleep&#8217; function as per the link I
posted then you can just stop SysTick all together and configure
whichever clock you want to bring the MCU out of low power mode at the
appropriate time.
I&#8217;m still not clear <em>where</em> you are placing the MCU into low power mode
as if you are using the &#8216;suspend and sleep&#8217; function it should be called
by the kernel, not you, and it won&#8217;t call PCM_setPowerState() unless you
have already customised the sleep functions for your particular MCU.
