  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">How to share a variable change throughout the main.c an the ISR </h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/valentinopapan">valentinopapan</a> on June 24, 2019</div><div class="thread-post-content">I am working with a periodic Interrup in which i have inizialized a counter, every time i get an interrupt the counter is increased by one unit through a notification function.  This notification function is executed in the ISR ( Interupt Service Rountine). Is there anyway that i can show that variation of this counter outside the ISR, say in my main.c file so that i can use it for a conditional trigger ( ex: &#8221; if ( counter == 50)&#8221;)
thanks to all that might be able to help
</div></div><div class="thread-post"><h3 class="thread-post-title">How to share a variable change throughout the main.c an the ISR </h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on June 24, 2019</div><div class="thread-post-content">A variable defined outside any function, is at file scope and is directly accessable by any function in that file, and by functions in other files in they have an &#8216;extern&#8217; decleration for the variable, unless the definition was declared static.
You do need to make sure that the reading/changes are atomic (done without possible interruption) or you might get mixed results. You may need to also add a volatile to let the compiler know that this variable might change behind its back in the ISR, so it doesn&#8217;t &#8216;optimize&#8217; the test to use a value it read previously, which might now be wrong.
</div></div><div class="thread-post"><h3 class="thread-post-title">How to share a variable change throughout the main.c an the ISR </h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/valentinopapan">valentinopapan</a> on June 26, 2019</div><div class="thread-post-content">Can you explain better what you mean by atomic ? my changes on this
variable happen in the ISR routine by it is a global variable and not
defined as static. But my main.c doesn&#8217;t seem to recognise the changes at
all. I know that my variable is increasing in the ISR because the reaching
of a certain value on that variable triggers an hardware action that I can
see. but I cannot use the variable change outside my function that runs in
the ISR.
</div></div><div class="thread-post"><h3 class="thread-post-title">How to share a variable change throughout the main.c an the ISR </h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richarddamon">richarddamon</a> on June 26, 2019</div><div class="thread-post-content">Perhaps if you show the code you use. The only way that main.c won&#8217;t see the change in the variable is if main.c is seeing a dfferent variable (perhaps with the same name).
The atomic comment is that if the varable in question isn&#8217;t accessed in a single unbreakable instruction, then it is possible that the read gets part of an old value and part of a new value, giving a value that doesn&#8217;t match either of them.
</div></div><div class="thread-post"><h3 class="thread-post-title">How to share a variable change throughout the main.c an the ISR </h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/pfav63">pfav63</a> on June 26, 2019</div><div class="thread-post-content">Hi
Did you declare the variable as volatile?
</div></div><div class="thread-post"><h3 class="thread-post-title">How to share a variable change throughout the main.c an the ISR </h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/valentinopapan">valentinopapan</a> on June 28, 2019</div><div class="thread-post-content">Thank you all for your help, indeed declaring the variable as volatile was
necessary and also the fact that I initialised my counter variable as equal
to 0 from the beginning so that was all that was readable outside the
function. I used a support variable in order to check how my main counter
was changing and everything works fine. Thank you all again.
