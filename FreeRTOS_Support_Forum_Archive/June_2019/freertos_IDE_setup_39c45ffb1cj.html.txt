So I&#8217;ve given up an integrated environment and uses Visual Studio Code as editor, use Gnu make and gcc/clang to build things and then either use gdb or Segger Ozone depending on what JTAG I&#8217;m using. Ozone is definitely my favorite debugger, but it only works with Seggers JTAGs.
I&#8217;d definitely steer clear of vi and emacs today. A good IDE makes things so much easier to code with the built in support for auto completion, syntax checks etc.

</div></div><div class="thread-post"><h3 class="thread-post-title">IDE setup</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/martin-etla">martin-etla</a> on June 20, 2019</div><div class="thread-post-content">AWS FreeRTOS is a superset of the ordinary FreeRTOS. If you don&#8217;t need the Amazon extensions you can use either.
https://www.freertos.org/FAQ_Amazon.html
Make isn&#8217;t that hard to understand, it&#8217;s more rather tedious to write all the rules and manually set all the flags to the compiler in a slightly obnoxious syntax that will bite you every now and then. On the other hand it makes it possible to integrate for example tools like splint, valgrind, gtest or similar in the build process so they are always run instead of when you remember it.
The manual is reasonably useful and I bet you won&#8217;t have to read all of it to get a grip of the basic concepts. And yes, it&#8217;s much easier to back out of an IDE-environment to make (since you have full control over your makefile) than go the other way.
The gnu make manual can be downloaded here:
https://www.gnu.org/software/make/manual/make.pdf
200 pages of condensed insanity. 😉
Slight warning; make and Windows don&#8217;t play entirely well together. It works, but there&#8217;s tons of fun pitfalls because make was created in a UNIX environment which matches badly with how Windows works. A recommendation is to run make in CygWin if you want to go that path.
On the other hand, IIRC Code Ccomposer Studio is a reasonable IDE that will do it&#8217;s job well at least in smaller projects.
