  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Problems with Building a Demo for TriCore</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/train">train</a> on June 25, 2019</div><div class="thread-post-content">Following the  Tricore guide,
http://www.freertos.org/FreeRTOS-for-Infineon-TriCore-TC1782-using-HighTec-GCC.html
I get the following error on HighTec IDE:
~~~
../RTOSDemo/FreeRTOS<em>Source/portable/GCC/TriCore</em>1782/port.c: In function
&#8216;pxPortInitialiseStack&#8217;:
../RTOSDemo/FreeRTOS<em>Source/portable/GCC/TriCore</em>1782/port.c:141:4: error:
stray &#8216;$&#8217; in program
    _mtcr( $FCX, pulUpperCSA[ 0 ] );
    ^
~~~
This error appears on every instance of &#8216;$&#8217; in the code.
Any ideas on how to fix the issue?
</div></div><div class="thread-post"><h3 class="thread-post-title">Problems with Building a Demo for TriCore</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on June 25, 2019</div><div class="thread-post-content">I suspect this will be due to a change in the tools since the example was created.  Can you reference any assembly code that comes with the tools, or the assembler&#8217;s manual, to see what the new syntax is?  Also, is this just when the mtcr macro is used?  If so, maybe the semantics of the macro changed?
</div></div><div class="thread-post"><h3 class="thread-post-title">Problems with Building a Demo for TriCore</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/train">train</a> on June 26, 2019</div><div class="thread-post-content">I believe that not the macro itself is the problem, but the use of $ in regaddr. 
The macro is:
~~~
static <strong>inline</strong> <strong>attribute</strong>((<strong>always_inline</strong>))
void _mtcr (const unsigned <strong>regaddr, const unsigned __val)
{
  __asm</strong> volatile (&#8220;mtcr LO:%0, %1&#8221;
                    :: &#8220;i&#8221; (<strong>regaddr), &#8220;d&#8221; (</strong>val) : &#8220;memory&#8221;);
}
~~~
and the problematic call for example is:
<code>_mtcr( $PSW, ulMFCR );</code>
It seems that $PSW is not recognizable.. 
</div></div><div class="thread-post"><h3 class="thread-post-title">Problems with Building a Demo for TriCore</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on June 26, 2019</div><div class="thread-post-content">What does the assembly manual say about this?  It looks like PSW is also
a macro (guessing as it is capitalised) so perhaps that has changed.
You can also check the assembly code that comes with the compiler and
the assembly code generated by the compiler to see how it accesses these
registers.  Please report back your findings for others with the same issue.
</div></div><div class="thread-post"><h3 class="thread-post-title">Problems with Building a Demo for TriCore</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/train">train</a> on June 26, 2019</div><div class="thread-post-content">I was trying to find the definition of the $ (like $PSW) symbols, but couldn&#8217;t find anything in the compiler code.
I have a feeling that it something that used to be when the example was written, but currently doesn&#8217;t exist.
