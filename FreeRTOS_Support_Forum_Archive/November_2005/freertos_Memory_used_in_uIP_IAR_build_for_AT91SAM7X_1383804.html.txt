  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Memory used in uIP IAR build for AT91SAM7X</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/baxsie">baxsie</a> on November 13, 2005</div><div class="thread-post-content">The summary of the map file for the uIP&#95;Demo&#95;IAR&#95;ARM7 shows:
 21 480 bytes of CODE&nbsp; memory
 34 534 bytes of DATA&nbsp; memory
&nbsp; 9 981 bytes of CONST memory
30K for code on a 256K flash part seems very reasonable. But the 34K of data for a 64K RAM part seems steep. Is there a reasonable way to reduce this requiement? How much is used by the kernal and how much is used by uIP?
Full map file here for reference:
http://www.baxsie.com/scratch/FreeRTOS&#95;uIP&#95;IAR&#95;Map&#95;AT91SAM7X-EK.txt
I also built uIP&#95;Demo&#95;Rowley&#95;ARM7, which seems to say 45K flash and 15K RAM, but I&#8217;m not sure I&#8217;m reading it right.
http://www.baxsie.com/scratch/FreeRTOS&#95;uIP&#95;Rowley&#95;AT91SAM7X-EK.txt
</div></div><div class="thread-post"><h3 class="thread-post-title">Memory used in uIP IAR build for AT91SAM7X</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on November 13, 2005</div><div class="thread-post-content">The kernel requires RAM for the task stacks, as described in the Memory Management section of the API documentation.&nbsp; The amount of RAM reserved for the kernel to use is defined by configTOTAL&#95;HEAP&#95;SIZE in FreeRTOSConfig.h.&nbsp; This can be sized to whatever is appropriate for your application &#40;how many tasks/queues/semaphores do you want to create?&#41;.&nbsp; The default heap size is defined to provide enough heap to run all the demo tasks.&nbsp; If you reduce the heap size then also remove some of the demo tasks.&nbsp; Most true applications will not require so many tasks.&nbsp; From the map file in your link you can see that the majority of RAM is going here.
The uIP memory usage is also configurable.&nbsp; In particular the buffer it uses to receive and create IP packets can be set as low as 200 bytes &#40;I think?&#41;, but the demo sizes this to be around 2K &#40;again this is from memory so can be double checked&#41;.&nbsp; This can be optimised for your system also.&nbsp; From the map file in your link the uIP buffer is using much less RAM than the heap, but still, but total uIP RAM usage is still 3K &#40;very small for a stack&#33;&#41;.
Finally, again from the map file, there is 7.5K allocated to SAM7&#95;EMAC.h.&nbsp; This memory is used by the peripheral buffers &#8211; the RAM that the emac itself uses to pass data to and from the application.&nbsp; The size and number of the Tx buffers is also configurable, but the Rx buffers are fixed.
regards.
