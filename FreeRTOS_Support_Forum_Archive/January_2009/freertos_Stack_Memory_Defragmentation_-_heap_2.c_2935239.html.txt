  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Stack Memory Defragmentation &#8211; heap_2.c</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/fkln">fkln</a> on January 28, 2009</div><div class="thread-post-content">Are there any workarounds concering the problem of the Memory Defragmentation of the heap&nbsp; ?
My idea is, during vPortFree&#40;&#41; look at the following block and the previous block in the list of free blocks.
If any or both blocks are free, it should be possible to combine the free blocks to one common free block.
With this solution, the defragmentation should be avoided ?
Any comments ?
Klaus
</div></div><div class="thread-post"><h3 class="thread-post-title">Stack Memory Defragmentation &#8211; heap_2.c</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on January 28, 2009</div><div class="thread-post-content">It is common for heap managers to combine adjacent free blocks. This reduces but does not remove fragmentation problems. It generally also makes the functions slower and less deterministic.
</div></div><div class="thread-post"><h3 class="thread-post-title">Stack Memory Defragmentation &#8211; heap_2.c</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/fkln">fkln</a> on January 28, 2009</div><div class="thread-post-content">Are there any add-ons for FreeRTOS for such a heap manager ?
Klaus
</div></div><div class="thread-post"><h3 class="thread-post-title">Stack Memory Defragmentation &#8211; heap_2.c</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/raphaelpereira">raphaelpereira</a> on January 28, 2009</div><div class="thread-post-content">It mainly depend on your development environment. For example, if you use GCC and newlib, you could use its malloc&#40;&#41; and free&#40;&#41; implementation, that already take care of that.
</div></div><div class="thread-post"><h3 class="thread-post-title">Stack Memory Defragmentation &#8211; heap_2.c</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/incrediball">incrediball</a> on January 28, 2009</div><div class="thread-post-content">If the defragmenting would be done by something optional in the idle task, the speed of the operation shouldn&#8217;t be a concern, unless a significant amount of time is spent inside critical sections.
To the person who suggested malloc/free: how useful is that really for embedded systems? malloc just seems a bit too general purpose for me with no way of configuring it, i.e. total heap size, minimum/maximum block size, where is any housekeeping done, what are worst and best case conditions, etc. I actually wound up writing my own heap manager because I wanted something handle based that would allow blocks to be relocated and reference counted.
</div></div><div class="thread-post"><h3 class="thread-post-title">Stack Memory Defragmentation &#8211; heap_2.c</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/fkln">fkln</a> on January 29, 2009</div><div class="thread-post-content">Thanks for the replies.&nbsp; I think, the solution with the defragmentation in the idle task is the best solution. Is a source code for this solution available ?
