  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">FreeRTOS takes up all ROM and Program memory</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/*anonymous">*anonymous</a> on January 21, 2009</div><div class="thread-post-content">Hello all,
I&#8217;ve been messing around with FreeRTOS for the PIC32MX460512L and have successfully managed to create a project from scratch and create two tasks which blink some LEDs. However, checking the Memory Usage Gauge in MPLAB shows that my very simple system is taking up 131471 out of 134140 words of ROM and 31404 out of 32768 words of RAM&#33;&#33;
I only found out about this when I tried to incorporate FreeRTOS into an existing PIC32 project. Without FreeRTOS, this project consumes 35160 words of ROM and 8460 words of RAM. However, once I add the FreeRTOS files in, the linker brings up these error messages:
Executing: &quot;C:Program FilesMicrochipMPLAB C32 Suitebinpic32-gcc.exe&quot; -mprocessor=32MX360F512L &quot;Main.o&quot; &quot;list.o&quot; &quot;queue.o&quot; &quot;tasks.o&quot; &quot;port.o&quot; &quot;port&#95;asm.o&quot; &quot;heap&#95;2.o&quot; -o&quot;BD176-01.elf&quot; -Wl,-L&quot;C:Program FilesMicrochipMPLAB C32lib&quot;,-L&quot;C:Program FilesMicrochipMPLAB C32pic32mxlib&quot;,&#8211;defsym=&#95;&#95;MPLAB&#95;BUILD=1,-Map=&quot;BD176-01.map&quot;
C:Program FilesMicrochipMPLAB C32 Suitepic32mxbinld.exe: region kseg1&#95;data&#95;mem is full &#40;BD176-01.elf section .bss&#41;
C:Program FilesMicrochipMPLAB C32 Suitepic32mxbinld.exe: address 0xa00091b0 of BD176-01.elf section .heap is not within region kseg1&#95;data&#95;mem
C:Program FilesMicrochipMPLAB C32 Suitepic32mxbinld.exe: address 0xa00095b0 of BD176-01.elf section .stack is not within region kseg1&#95;data&#95;mem
C:Program FilesMicrochipMPLAB C32 Suitepic32mxbinld.exe: address 0xa0009800 of BD176-01.elf section .ramfunc is not within region kseg1&#95;data&#95;mem
Link step failed.
Any ideas?
&#45;-Amr
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS takes up all ROM and Program memory</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on January 21, 2009</div><div class="thread-post-content">I have seem FreeRTOS run with file system, TCP/IP stack and other software all at once so ROM should not be an issue. I suggest you look at the map file to see where it is going. Probably to the GCC libraries. Are you using sprintf&#40;&#41; or something similar? There are lower cost versions in the download.
Regarding RAM. What you are seeing is the heap RAM, nearly all of which will be free. This is just a big array set by configTOTAL&#95;HEAP&#95;SIZE.
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS takes up all ROM and Program memory</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/*anonymous">*anonymous</a> on January 21, 2009</div><div class="thread-post-content">Thanks for your reply Dave,
The heap was causing the problem &#8211; the default heap size was set to 28000 but my program was already using 8460 words of ram in variables and the two couldn&#8217;t fit into the 32768 words of on chip ram. Changing the heap to 20000 fixed the problem and the project now compiles just fine.
Thanks for your help&#33;
&#45;-Amr
