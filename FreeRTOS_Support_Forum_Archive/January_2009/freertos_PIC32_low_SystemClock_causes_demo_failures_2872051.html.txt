  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">PIC32 low SystemClock causes demo failures</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/randers">randers</a> on January 17, 2009</div><div class="thread-post-content">Hi,
I have recognized the following certain behavior in the PIC32-demo-project:
The original project works with 80Mhz-SysCLK &amp; 40MHz-PBCLK.
This is realized by the following lines in main.c:
&#35;pragma config FPLLMUL = MUL&#95;20, FPLLIDIV = DIV&#95;2, FPLLODIV = DIV&#95;1, FWDTEN = OFF
&#35;pragma config POSCMOD = HS, FNOSC = PRIPLL, FPBDIV = DIV&#95;2
// SysCLK = 8 / FPLLIDIV &#42; FPLLMUL / FPLLODIV
The compiler itself gets this information by the following lines in FreeRTOSConfig.h:
&#35;define configCPU&#95;CLOCK&#95;HZ&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; &#40; &#40; unsigned portLONG &#41; 80000000UL &#41;&nbsp; 
&#35;define configPERIPHERAL&#95;CLOCK&#95;HZ&nbsp;&nbsp;&nbsp; &#40; &#40; unsigned portLONG &#41; 40000000UL &#41;
I lowered the CPU-Clock by setting FPLLODIV = DIV&#95;2 // DIV4, DIV8, &#8230;
&#40;and customizing FreeRTOSConfig.h&#41;
The PB-Clock is in each case half of the CPU-Clock.
The demo works with 80/40MHz &#40;original settings&#41;. It works with 40/20MHz too.
But with 20/10MHz and 10/5MHz failures are reported via LCD-display:
&quot;Error: Gen Q&quot; ,&nbsp; &quot;Error: Blck time&quot; &#8230;
Is there anything known?
ralf
</div></div><div class="thread-post"><h3 class="thread-post-title">PIC32 low SystemClock causes demo failures</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on January 17, 2009</div><div class="thread-post-content">The demos do all sorts of the self checks &#8211; some more detailed than others.&nbsp; Some will check that an event occurred within the expected time.&nbsp; If you slow the clock right down then the resolution of time measurement will decrease and some tasks will start to think they have missed deadlines.&nbsp; It is not something to worry about, you have just changed the execution environment from that the tasks were expected to find the selves operating under.
Regards.
