  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">FreeRTOS V5 for AVR32 Timer Tick Rate</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/bmenkveld">bmenkveld</a> on January 6, 2009</div><div class="thread-post-content">We are working on a project using FreeRTOS on an Atmel AVR32 UC3A0512 CPU.&nbsp; 
The sample FreeRTOS code supplied by Atmel is built on V4 of FreeRTOS.&nbsp;&nbsp; I decided that we should upgrade to FreeRTOS V5, since it would be beneficial to get access to its stack and heap check features.
I downloaded the latest V5 FreeRTOS, and have replaced all the FreeRTOS files with their V5 counterparts.&nbsp; I also fixed all the FromISR&#40;&#41; calls, as directed.&nbsp; The project now builds, and even runs.&nbsp; 
However, the FreeRTOS timer tick rate is incorrect.&nbsp; I have configTICK&#95;RATE&#95;HZ set to 1000, and with V4 I got 1ms ticks very nicely.&nbsp; With V5, I don&#8217;t.&nbsp; With configTICK&#95;USE&#95;TC set to 0, I get a tick period of about 800ms&#33;&nbsp; With configTICK&#95;USE&#95;TC set to 1, I get a tick period of 0.5ms &#40;better, but not quite&#41;.
I also found that the new port.c references a symbol called &quot;INT0&quot;, which does not appear to exist in any of Atmel&#8217;s header files.&nbsp; I replaced it with AVR32&#95;INTC&#95;INT0, because that seemed a reasonable replacement &#40;and it&#8217;s defined as 0&#41;.&nbsp; There were more problems with exception.S, so I decided to keep my V4 version of exception.S.
Any idea whether I&#8217;m doing something wrong, or whether maybe the V5 AVR32 port has not been fully tested?
My thanks in advance for any suggestions.
&#45;-
Bert Menkveld
P.Eng.

In the mean time I can supply you with old versions of the header files, which fixed the problem for somebody else.&nbsp; I would also be interested in receiving the files you are using from the Atmel distribution &#8211; Source/Portable/&#91;compiler&#93;/&#91;chip&#93;.&nbsp; Email address is r &#42;dot&#42; barry &#91;at&#93; freertos.org.

</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS V5 for AVR32 Timer Tick Rate</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on September 14, 2009</div><div class="thread-post-content">The explanation is that there are two variables, and therefore 4 combinations.&nbsp; The original demo was done with original silicon and early compiler versions.&nbsp; Since then the libraries for both GCC and IAR have been updated in a way that introduces incompatibilities, and the silicon has been revised which also introduces incompatibilities.  
Its on my list to provide an alternative demo using the other set of variables.&nbsp; For now you can take all the header files from the original compiler versions and patch them into the new compiler versions &#8211; but make sure you backup the new headers before you overwrite them.
