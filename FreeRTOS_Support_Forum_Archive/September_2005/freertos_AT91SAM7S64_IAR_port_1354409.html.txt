  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">AT91SAM7S64 IAR port</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/jra01">jra01</a> on September 20, 2005</div><div class="thread-post-content">I discovered a problem with crashing system. The cause showed up to be that IAR expects stack to be initiated to 0, but freeRTOS initates to 01010101, 02020202 &#8230;
Therefore I have made a change to port.c, in &quot;pxPortInitialiseStack&quot;:
&#45;&#8211;
&nbsp;&nbsp;&nbsp; &#42;pxTopOfStack = &#40; portSTACK&#95;TYPE &#41; 0xaaaaaaaa;&nbsp;&nbsp;&nbsp; /&#42; R14 &#42;/
&nbsp;&nbsp;&nbsp; pxTopOfStack&#8211;;&nbsp;&nbsp;&nbsp; 
&nbsp;&nbsp;&nbsp; &#42;pxTopOfStack = &#40; portSTACK&#95;TYPE &#41; pxOriginalTOS; /&#42; Stack used when task starts goes in R13. &#42;/
&nbsp;&nbsp;&nbsp; pxTopOfStack&#8211;;
&nbsp;&nbsp;&nbsp; for &#40;i = 0; i &lt; 12; ++i&#41; &#123;
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; &#42;pxTopOfStack = &#40; portSTACK&#95;TYPE &#41; 0x0;&nbsp;&nbsp;&nbsp; /&#42; R12&#8230;R1 &#42;/
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; pxTopOfStack&#8211;;&nbsp;&nbsp;&nbsp; 
&nbsp;&nbsp;&nbsp; &#125;
&#45;&#8211;
After that it works.
Regards
Jokke
</div></div><div class="thread-post"><h3 class="thread-post-title">AT91SAM7S64 IAR port</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on September 20, 2005</div><div class="thread-post-content">This is definitely not the case.&nbsp; When a task starts it does not make any assumptions as to the stack or register states.
I suspect you are calling main&#40;&#41; in the wrong processor mode.&nbsp; main&#40;&#41; must be called in supervisor mode.&nbsp; Are you using the startup code that came with the demo project?
</div></div><div class="thread-post"><h3 class="thread-post-title">AT91SAM7S64 IAR port</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/jra01">jra01</a> on September 20, 2005</div><div class="thread-post-content">This has nothing to do with main. In a normal task I discovered &#40;looking at the assembler listing&#41; that the compiler places a read in a vector, using an index that is in some cases still not initialized. This works fine as long as the index is 0 until it is used, but I got problems with reads out of defined memory, since, in this case, R5 was 0x05050505, as is initialised in port.c.
Maybe this is a compiler error, but my guess was that they made this assumption. 
The code is a state machine, and it might not be obvious enough for the compiler that it starts in a state where the index is set, before moving to the state where it is used. On the other hand I do not get any warning of &quot;used before set&quot;&#40;maybe IAR does not give such warnings?&#41;.
I am using the startup from the demo project, and I made a lot of versions of the software before this came up.
I guess I will have to send you the code and the assembler listing before we reach consensus on this&#8230;
Regards
Jokke
