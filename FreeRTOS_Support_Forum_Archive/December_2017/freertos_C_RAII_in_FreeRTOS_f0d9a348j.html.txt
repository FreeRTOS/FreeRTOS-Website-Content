What I&#8217;ve done in cases like this is not directly delete the task, but wake the task up with a message / event that says &#8220;kill yourself&#8221;, then the task can exit a local scope (and trigger RAII / DTOR) and then commit suicide.

</div></div><div class="thread-post"><h3 class="thread-post-title">C++ RAII in FreeRTOS</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on December 7, 2017</div><div class="thread-post-content">Please realise that <code>vTaskDelete()</code> is a kind of abortion, an <code>exit()</code>. The destructors of objects created in a task will not be called.  This behaviour is not a mistake, neither it is &#8220;erroneous&#8221;.
If I ever call <code>vTaskDelete()</code>, it is the task who kills itself, using the parameter <code>NULL</code>. The task knows best what to do to finish its work in a graceful way.  <code>vTaskDelete()</code> is not nice, the OS will just eliminate the task from the task-list.
If you want a task to stop running, I would recommend sending a messages: &#8220;Please stop&#8221;.  Let the task delete explicitly the objects that it has created. You could define use a sub-scope, that closes before calling <code>vTaskDelete()</code>, like in this example:
~~~
void dataProcessing<em>Task(void * argument)
{
    {
        DataRAII raii</em>guard(daq);
        daq.Start();
        for(;;)
        {
            if (xTaskNotifyWait(0x00, 0xFFFFFFFF,&#8230;&#8230;
            if( has<em>to</em>stop )
            {
             break;
            }
        }
        /* at this point the destructor ~DataRAII() will be called. <em>/
    }
    /</em> Kill my self. <em>/
    vTaskDelete( NULL );
    /</em> This line won&#8217;t be reached. */
 }
~~~
