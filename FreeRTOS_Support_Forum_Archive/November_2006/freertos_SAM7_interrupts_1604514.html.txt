  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">SAM7 interrupts</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on November 3, 2006</div><div class="thread-post-content">I am working with FreeRTOS on the At91sam7x-ek development board.&nbsp; I am trying to write some serial code to poll an external device, and I am trying to use the PDC to buffer the values before having a thread running in FreeRTOS copy over the buffer, then reset the PDC.&nbsp; However, the PDC buffer isn&#8217;t getting all of the characters when it is attached to the external device &#40;works fine in hyper terminal though&#8230;&#41;.&nbsp; So, I decided to write an interrupt to just print out all of the received characters over a TCP connection.&nbsp; I write a simple little interrupt that will just echo the character back over the serial port for starters, and then compiled it all using the arm-gcc.&nbsp; I also ended up putting the interrupt function in a separate file so that I could compile it in ARM mode, rather than THUMB mode. However, when I run the program on the uC, whenever the interrupt is generated, the entire kernel locks up.&nbsp; My best guess is that when it is not returning to &quot;Thumb&quot; mode after the conclusion of the interrupt, but I&#8217;m not completely sure.&nbsp; However, I was looking at some of the FreeRTOS code, parcitularly the EMAC interrupt, and it is able to use interrupts without much trouble, however, on the comments for the prototypes they all have something about an asm wrapper.&nbsp; I don&#8217;t know if that is talking about the &#95;&#95;attribute&#95;&#95; or if that means that somewhere in some assembler file, i need to write some code that tells the uC to switch back to &quot;thumb&quot; mode.&nbsp; I was hoping that since you &#40;or someone in your group&#41; was the one who wrote the EMAC interrupt, that you might know how to fix this problem.&nbsp; Any help would be greatly appreciated, or even a point in the right direction. Thanks :&#41;
</div></div><div class="thread-post"><h3 class="thread-post-title">SAM7 interrupts</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nobody">nobody</a> on November 3, 2006</div><div class="thread-post-content">&gt; I am working with FreeRTOS on the At91sam7x-ek development board.&nbsp; I am trying
&gt; to write some serial code to poll an external device, and I am trying to use
&gt; the PDC to buffer the values before having a thread running in FreeRTOS copy
&gt; over the buffer, then reset the PDC.&nbsp; However, the PDC buffer isn&#8217;t getting
&gt; all of the characters when it is attached to the external device &#40;works fine
&gt; in hyper terminal though&#8230;&#41;.&nbsp; 
Have you tried writing a very simply program that just does nothing else but receive the data?&nbsp; Without any other functionality, FreeRTOS related or otherwise?&nbsp; Once you have this running you can start to add in other things to see where it starts to go wrong.
&gt;So, I decided to write an interrupt to just print
&gt; out all of the received characters over a TCP connection.&nbsp; I write a simple
&gt; little interrupt that will just echo the character back over the serial port
&gt; for starters, and then compiled it all using the arm-gcc.&nbsp; I also ended up putting
&gt; the interrupt function in a separate file so that I could compile it in ARM
&gt; mode, rather than THUMB mode. However, when I run the program on the uC, whenever
&gt; the interrupt is generated, the entire kernel locks up.&nbsp; 
Which version of GCC are you using?&nbsp; There we a bug reported recently that can be fixed using a particular command line option.&nbsp; See this thread: http://sourceforge.net/forum/forum.php?thread&#95;id=1597532&amp;forum&#95;id=382005
&gt;My best guess is that
&gt; when it is not returning to &quot;Thumb&quot; mode after the conclusion of the interrupt,
&gt; but I&#8217;m not completely sure.&nbsp; 
&gt;However, I was looking at some of the FreeRTOS
&gt; code, parcitularly the EMAC interrupt, and it is able to use interrupts without
&gt; much trouble, however, on the comments for the prototypes they all have something
&gt; about an asm wrapper.&nbsp; I don&#8217;t know if that is talking about the &#95;&#95;attribute&#95;&#95;
&gt; or if that means that somewhere in some assembler file, i need to write some
&gt; code that tells the uC to switch back to &quot;thumb&quot; mode.&nbsp;&nbsp; Any help would be greatly appreciated,
&gt; or even a point in the right direction. Thanks :&#41;
If your interrupt does not cause a context switch then it can be written as a normal interrupt without having to worry about anything.&nbsp; If you are wanting to cause a context switch in the interrupt then make sure you copy the examples given for the GCC compiler &#8211; not the IAR compiler.&nbsp; The GCC compiler does not need the asm wrappers.
