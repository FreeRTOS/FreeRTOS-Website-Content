If I am not mistaken, <code>xZeroCopyBufferDescriptor_t</code> should be:
~~~
    typedef NetworkBufferDescriptor<em>t *xZeroCopyBufferDescriptor</em>t;

Note that nowadays, the initial &#8216;x&#8217; would not be used for a typedef anymore, so it would become <code>ZeroCopyBufferDescriptor_t</code>.
<code>ipconfigMAX_UDP_DATA_LENGTH</code> indicates the length of the UDP packets that are transmitted.
The function <code>FreeRTOS_GetZeroCopyBuffer()</code> was a wrapper, it would call the function <code>pxGetNetworkBufferWithDescriptor()</code> .
I think it looked lke this:
~~~

{
BaseType</em>t xResult;

if( *pBuffer != NULL )

    xResult = pdPASS;

}

</code></pre>
}
~~~
<strong>Zero-copy</strong> for UDP:
For UDP sockets, zero-copy means that the user doesn&#8217;t pass character buffers, but Network Buffers, which travel from the Network Interface all the way to the application ( <code>FreeRTOS_recvfrom()</code> ), without ever getting ( mem- ) copied.
The same for <code>FreeRTOS_sendto()</code> : the user fills and sends a Network Bufferm which won&#8217;t get copied neither.  If you have a zero-copy driver, the memory of the Network Buffer will be passed directly to DMA.
The actual library sources files of FreeRTOS+TCP are these nine:
~~~
FreeRTOS<em>ARP.c
FreeRTOS</em>DHCP.c
FreeRTOS<em>DNS.c
FreeRTOS</em>IP.c
FreeRTOS<em>Sockets.c
FreeRTOS</em>Stream<em>Buffer.c
FreeRTOS</em>TCP<em>IP.c
FreeRTOS</em>TCP<em>WIN.c
FreeRTOS</em>UDP_IP.c
~~~
I hope that they compile without too many problems. Yes we also tested it with the GCC Arm toolchain.
Max, are you sure you need the /multi version of FreeRTOS+TCP? For which platform, if I may ask?
The /multi version has support for multiple Network Interfaces, and also multiple IP-addresses. it also implements IPv6, but that part is still under construction.
