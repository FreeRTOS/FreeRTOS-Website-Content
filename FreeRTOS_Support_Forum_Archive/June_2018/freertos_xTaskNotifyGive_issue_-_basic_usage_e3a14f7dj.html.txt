</div></div><div class="thread-post"><h3 class="thread-post-title">xTaskNotifyGive issue &#8211; basic usage</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on June 7, 2018</div><div class="thread-post-content">I think this recent thread: 
https://sourceforge.net/p/freertos/discussion/382005/thread/543fb83e/ 
showed xil<em>printf() may not be thread safe and may cause problems (which 
is why we normally serialse logging by only calling printf() form a 
single task) so in this case it might be that xil</em>printf() is taking 
longer to execute than you are allowing with the allowable margin you 
have set using pdMS<em>TO</em>TICKS( 10 ).  Try increasing to pdMS<em>TO</em>TICKS( 
1000 ) as a sanity check.

</div></div><div class="thread-post"><h3 class="thread-post-title">xTaskNotifyGive issue &#8211; basic usage</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on June 7, 2018</div><div class="thread-post-content">Ah &#8211; I see the problem.
The parameter to xTaskNotifyGive() is supposed to be the handle of the 
task the notification is sent to.  The parameter you are passing is a 
pointer to the function that implements the task, not the task&#8217;s handle.
The last parameter in your call to:
xTaskCreate( vPlaybackTask, &#8220;Playback&#8221;, 1024, NULL, configMAX_PRIORITIES 
&#8211; 4, NULL );
is null so you never save the task&#8217;s handle.  Do something like this:
// File scope
static TaskHandle_t PlaybackHandle;
// Update call to xTaskCreate to save the handle.
xTaskCreate( vPlaybackTask, &#8220;Playback&#8221;, 1024, NULL, configMAX_PRIORITIES 
&#8211; 4, &amp;PlaybackHandle );
// Update call to xTaskNotifyGive() to use the handle.
xTaskNotifyGive( PlaybackHandle );
</div></div><div class="thread-post"><h3 class="thread-post-title">xTaskNotifyGive issue &#8211; basic usage</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/nndpkz">nndpkz</a> on June 8, 2018</div><div class="thread-post-content">Yes, that was a problem. I knew I was missing something obvious.  But, I also thought some assert would fail if something like this happens.
