</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS_debug_printf double quotes</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/heinbali01">heinbali01</a> on June 6, 2018</div><div class="thread-post-content"><blockquote>
  FreeRTOS<em>debug</em>printf double quotes 
</blockquote>
Not double quotes but double parentheses. This way of logging is not uncommon in public libraries.
In every <code>FreeRTOSIPConfig.h</code> you will see this code that should explain it:
~~~
extern int lUDPLoggingPrintf( const char *pcFormatString, &#8230; );
/* Set to 1 to print out debug messages.  If ipconfigHAS<em>DEBUG</em>PRINTF
is set to 1 then FreeRTOS<em>debug</em>printf should be defined to the
function used to print out the debugging messages. */
<h1>ifndef ipconfigHAS<em>DEBUG</em>PRINTF</h1>
<pre><code>#define ipconfigHAS_DEBUG_PRINTF    1
</code></pre>
<h1>endif</h1>
<h1>if( ipconfigHAS<em>DEBUG</em>PRINTF == 1 )</h1>
<pre><code>#define FreeRTOS_debug_printf(X)    lUDPLoggingPrintf X
</code></pre>
<h1>else</h1>
<pre><code>/* Define it as an empty statement so that a semicolon can be placed safely after it. */
#define FreeRTOS_debug_printf(X)    do {} while( 0 )
</code></pre>
<h1>endif</h1>
/* Set to 1 to print out non debugging messages, for example the
output of the FreeRTOS<em>netstat() command, and ping replies.  If ipconfigHAS</em>PRINTF is set to 1 then FreeRTOS_printf should be
set to the function used to print out the messages. */
<h1>ifndef ipconfigHAS_PRINTF</h1>
<pre><code>#define ipconfigHAS_PRINTF            1
</code></pre>
<h1>endif</h1>
<h1>if( ipconfigHAS_PRINTF == 1 )</h1>
<pre><code>#define FreeRTOS_printf(X)            lUDPLoggingPrintf X
</code></pre>
<h1>else</h1>
<pre><code>#define FreeRTOS_printf(X)            do {} while( 0 )
</code></pre>
<h1>endif</h1>
~~~
The <code>FreeRTOS_debug_printf()</code> is quite detailed, whereas <code>FreeRTOS_printf()</code> will only log essential events and problems.   Once you release your device, you may want to disable all logging.
The GNU compiler has ellipses in its macro syntax, so we could wwrite:
<pre><code>#define FreeRTOS_printf( format, ... )
</code></pre>
but many other compilers get stuck on the three dots.
We could also demand that a user defines a function:
<pre><code>void FreeRTOS_printf( const char *pcFormat, ... )
</code></pre>
and use single parenthesis.
You will get used to the double parentheses:
<pre><code>FreeRTOS_printf( ( "Hello worldn" ) );
</code></pre>
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS_debug_printf double quotes</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davidbrown">davidbrown</a> on June 6, 2018</div><div class="thread-post-content">Hi,
Note that it is not gcc that has the variadic macro support &#8211; it is C99.
 Any C99 compiler will support it (though gcc has a couple of neat
extensions to make it better).  But FreeRTOS, AFAIU, is C90 compatible
and thus does not use any C99 features.
(Personally, I&#8217;d like to see C90 support dropped in future versions of
FreeRTOS &#8211; compilers and C programmers have had about 20 years to catch
up, and have no excuse for not supporting C99.  C99 would bring a lot of
benefits to FreeRTOS, such as in this case.  Of course, changing to a
better syntax here would mean backwards incompatible changes &#8211; these
things are never pain-free.)
An alternative way to handle this sort of thing would have been to write:
<h1>if( ipconfigHAS<em>DEBUG</em>PRINTF == 1 )</h1>
<pre><code>#define FreeRTOS_debug_printf    lUDPLoggingPrintf
</code></pre>
<h1>else</h1>
<pre><code>/* Define it as an empty statement so that a semicolon can be placed
</code></pre>
safely after it. */
    #define FreeRTOS_debug_printf(X)    do {} while( 0 )
<h1>endif</h1>
Then the FreeRTOS<em>debug</em>printf macro would have taken exactly the same
arguments as lUDPLoggingPrintf.
mvh.,
David

</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS_debug_printf double quotes</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davidbrown">davidbrown</a> on June 7, 2018</div><div class="thread-post-content">Hi,
The way you are defining it is the C99 way.  It will then look like a 
normal function or function-like macro &#8211; you don&#8217;t need double 
parenthesis.  But it also means that you /can&#8217;t/ have double 
parenthesis, and it is thus inconsistent with the current FreeRTOS way 
(which is designed to work with C90).
It would be nice if FreeRTOS could take advantage of the improvements in 
modern C, but consistency and backwards compatibility are vital &#8211; so my 
advice is to use Hein&#8217;s recommendation.
Don&#8217;t forget that your version added a &#8220;r&#8221;, while Hein&#8217;s does not.
Incidentally, if your code is going to be compiled with gcc, then I 
strongly recommend a gcc extension here:
extern void PrintUart(const char* format, &#8230;)
    <strong>attribute</strong>((format(printf, 1, 2)));
This well let gcc check that your format string and the parameters match up.
mvh.,
David
