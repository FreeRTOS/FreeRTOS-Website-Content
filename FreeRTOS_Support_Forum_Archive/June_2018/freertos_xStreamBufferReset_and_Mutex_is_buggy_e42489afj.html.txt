  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">xStreamBufferReset and Mutex is buggy</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/seagull_kamome">seagull_kamome</a> on June 15, 2018</div><div class="thread-post-content">I guess that my previous post got filtered. So, this is second post.
Hi FreeRTOS developer team.
I’m currently testing FreeRTOS  kernel for our project. And, found
something weird.
   1.
   xStreamBufferReset doesn’t save a STATICALLY_ALLOCATED flag in ucFlags. So,
   it will crashes our system at vStreamBufferDelete by calling free().
   2.
   xSemaphoreGet with Mutex doesn’t give priority back to that mutex holder
   when timed out
Sorry. I can’t explain well in english so I’ll show the unit test code.
<h2>Task1</h2>
static SemaphoreHandle_t mx1;
static unsigned int volatile test_counter;
static TaskHandle<em>t test</em>task;
static void test<em>task</em>main_1(void* args __unused) {
xSemaphoreTake(mx1, 10); // will be fail.
++test_counter;
ulTaskNotifyTake(0, portMAX_DELAY);
++test_counter;
xSemaphoreTake(mx1, portMAX_DELAY);
++test_counter;
ulTaskNotifyTake(0, portMAX_DELAY);
++test_counter;
xSemaphoreGive(mx1);
vTaskDelete(NULL);
}
<h2>and test  task. This task has priority (tskIDLE_PRIORITY + 2).</h2>
should_eq(xTaskGetCurrentTaskHandle(), xSemaphoreGetMutexHolder(mx1)); //
precondition check
should<em>eq(tskIDLE</em>PRIORITY + 2, uxTaskPriorityGet(NULL));  // precondition
check
test_counter = 0;
should<em>eq(pdTRUE, xTaskCreate(test</em>task<em>main</em>1, &#8220;TSK&#8221;,
configMINIMAL<em>STACK</em>SIZE, NULL, tskIDLE<em>PRIORITY + 3, &amp;test</em>task));
should<em>eq(tskIDLE</em>PRIORITY + 3, uxTaskPriorityGet(NULL));  // OK. the
priority is inherited.
should<em>eq(0, test</em>counter); // OK. the task still waiting.
vTaskDelay(11);
should<em>eq(1, test</em>counter); // OK. the task already timed out
// All tests is OK until here.
//   BUG? FreeRTOS never descent priority into base when the waiting task
got timeout.
should<em>eq(tskIDLE</em>PRIORITY + 2, uxTaskPriorityGet(NULL));  // Fail: actual
is tskIDLE_PRIORITY + 3
xTaskNotifyGive(test_task); // elevate again. the task will preempt control.
taskYIELD(); // but actually not.
should<em>eq(2, test</em>counter); // OK. the task waiting again.
should<em>eq(tskIDLE</em>PRIORITY + 3, uxTaskPriorityGet(NULL)); // OK
should_eq(pdTRUE, xSemaphoreGive(mx1)); // OK
should<em>eq(3, test</em>counter); // OK
should<em>eq(test</em>task, xSemaphoreGetMutexHolder(mx1)); // OK
should<em>eq(tskIDLE</em>PRIORITY + 2, uxTaskPriorityGet(NULL)); // Fail:! I&#8217;m
still in tskIDLE_PRIORITY + 3!!!
Thanks
</div></div><div class="thread-post"><h3 class="thread-post-title">xStreamBufferReset and Mutex is buggy</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/seagull_kamome">seagull_kamome</a> on June 18, 2018</div><div class="thread-post-content">Finally. I found  this comment .
<pre><code>            /* Only disinherit if no other mutexes are held.  This is a
            simplification in the priority inheritance implementation.  If
            the task that holds the mutex is also holding other mutexes then
            the other mutexes may have caused the priority inheritance. */
</code></pre>
