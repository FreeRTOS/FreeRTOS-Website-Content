  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">MPU demo LPC1768 link script problem</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/docsis">docsis</a> on July 8, 2015</div><div class="thread-post-content">In file rtosdemo<em>rdb1768</em>Debug.ld, The privileged_data section simply set as bss:
<pre><code>privileged_data :
{
    _bss = .;
    *(privileged_data)
    /* Non kernel data is kept out of the first 256 bytes of SRAM. */
} &gt; SRAM    
</code></pre>
But in task.c, not all variable is zero initial value:
<pre><code>PRIVILEGED_DATA static volatile TickType_t xNextTaskUnblockTime     = portMAX_DELAY;
</code></pre>
Not sure if this is an issue.
</div></div><div class="thread-post"><h3 class="thread-post-title">MPU demo LPC1768 link script problem</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on July 9, 2015</div><div class="thread-post-content">Thanks for pointing this out &#8211; it is an interesting one and I&#8217;m afraid I don&#8217;t have an answer for how it worked <em>however</em> the head revision code no longer initialises this variable where it is declared, and instead initialises it immediately before the scheduler is started.  The change was made explicitly to ensure the kernel itself had nothing outside the bss section.
You can see the head revision version here:
https://sourceforge.net/p/freertos/code/HEAD/tree/trunk/FreeRTOS/Source/tasks.c#l250
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">MPU demo LPC1768 link script problem</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/docsis">docsis</a> on July 10, 2015</div><div class="thread-post-content">Thank you for your reply. Yes, this is the only privileged variable with no-zero initial value.
There are some other minor issues in link script, maybe also not issues:
1. If enable timer, <em>Privileged</em>Data<em>Region</em>Size exceed 256.
2. If change flash start address to other value than zero, link fail. Have to change:
<pre><code>.text :
    {
        /* Non privileged code kept out of the first 16K or flash. */
        . = __privileged_functions_start__ + _Privileged_Functions_Region_Size;
</code></pre>
to
<pre><code>.text :
    {
        /* Non privileged code kept out of the first 16K or flash. */
        . =  ORIGIN( FLASH ) + _Privileged_Functions_Region_Size;
</code></pre>
In my environment, need change these to get right link result.
3. Also have to change this to put .bss after <em>Privileged</em>Data<em>Region</em>Size.
<pre><code>. = ORIGIN( SRAM ) + _Privileged_Data_Region_Size;
.bss :
{
*(.bss*)
*(COMMON)
_ebss = .;
} &gt; SRAM
</code></pre>
to
<pre><code>.bss :
{
. = ORIGIN( SRAM ) + _Privileged_Data_Region_Size;
*(.bss*)
*(COMMON)
_ebss = .;
} &gt; SRAM 
</code></pre>
