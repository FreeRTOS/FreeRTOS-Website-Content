</div></div><div class="thread-post"><h3 class="thread-post-title">  vTaskDelayUntil()  </h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on November 1, 2013</div><div class="thread-post-content">It depends on the priorities you assign to the tasks.
If the task that takes 3 seconds to complete has a priority above the other tasks then the other tasks will not run until it completes.
If the task that takes 3 seconds to complete has a priority below the other tasks then it will get preempted as soon as the other tasks need to run.
If all the tasks have the same priority then they will time slice and it will probably appear that all the tasks run just when they want to.

</div></div><div class="thread-post"><h3 class="thread-post-title">  vTaskDelayUntil()  </h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on November 2, 2013</div><div class="thread-post-content">No. Using VTaskDelayUntil in the task loop will make that task run as close to that rate as possible. It will only be late if:
1) Some higher or equal priority task is running at the point, in which case the task will be delayed until the higher priority task blocks, or the same priority task blocks or continues for a tick.
2) It takes longer to finish than the repeat period, at which point the vTaskDelay Until doesn&#8217;t block, but just updates the next execution time an returns.
You mentioned one task taking a long period to execute, If that is compute bound time, then you probably don&#8217;t want that task higher priority than the others, as it would affect their timing. Long executing tasks (if CPU bound) tend to be lower in priority to avoid them impacting more important quick operations.

</div></div><div class="thread-post"><h3 class="thread-post-title">  vTaskDelayUntil()  </h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on November 12, 2013</div><div class="thread-post-content">I have no idea what xTimeIncrement is, so the answer to your question is probably &#8220;no&#8221;.
Block times are specified in ticks, so the maximum time you can block for depends on your tick frequency (configTICK<em>RATE</em>HZ in FreeRTOSConfig.h) <b>and</b> the type used for portTickType.  If configUSE<em>16</em>BIT<em>TICKS is 1 then the maximum block time is 0xffff ticks.  If configUSE</em>16<em>BIT</em>TICKS is 0 then the maximum block time is 0xffffffff ticks.  
If you want to convert milliseconds into ticks then divide it by portTICK<em>RATE</em>MS.  For example, of you want to delay for 1000 milliseconds then call vTaskDelay( 1000 / portTICK<em>RATE</em>MS );
When you are blocking on an object such as a queue, semaphore or mutex then you can block indefinitely (without a timeout) if INCLUDE<em>vTaskSuspend is set to 1 in FreeRTOSConfig.h and you set portMAX</em>DELAY as the block time.
Regards.

Timer ticks faster than 1 ms are really impractical, and some of the coding techniques in the examples don&#8217;t work (as MS<em>PER</em>TICK is 0). In most application you can actually use a slower tick rate. A 10ms tick would allow a delay of 655 seconds, nearly 11 minutes. If you want real long delays, you need to turn off 16 bits as mentioned, then you get VERY long delays (Over a month with 1 ms ticks).

</div></div><div class="thread-post"><h3 class="thread-post-title">  vTaskDelayUntil()  </h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/dragonflight1">dragonflight1</a> on December 2, 2013</div><div class="thread-post-content">Rather than incur the 32 bit penalty all the time (though it really isn&#8217;t that much), if you only want to delay a task some long time then you can use
~~~~~~~~~~~~~~~
void sleep( unsigned int sec ) {
    long ticks = sec * 1000 * portTICK<em>RATE</em>MS;
    while(ticks >= portMAX<em>DELAY ) {
        vTaskDelay( portMAX</em>DELAY-1 );
        ticks -= portMAX_DELAY-1;
    }
    vTaskDelay( ticks );
}
~~~~~~~~~~~~~~~
or
~~~~~~~~~~~~~~~
void sleepUntil( portTickType *prevWakeTime,  unsigned int sec ) {
    long ticks = sec * 1000 * portTICK_RATE_MS;
    while(ticks >= portMAX_DELAY ) {
        vTaskDelayUntil( prevWakeTime, portMAX_DELAY-1 );
        ticks -= portMAX_DELAY-1;
    }
    vTaskDelayUntil( prevWakeTime, ticks );
}
~~~~~~~~
if you really want to wake up exactly every sec seconds.
NOTE: if you use sleepUntil then you must call it before the base timer overflows &#8211; 65 secs with 1000Hz or 655 secs with 100Hz which I assume is not an issue.
