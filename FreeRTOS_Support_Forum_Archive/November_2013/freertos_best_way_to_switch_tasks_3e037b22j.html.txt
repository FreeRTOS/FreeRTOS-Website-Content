  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">best way to &#8220;switch&#8221; tasks</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/matejm">matejm</a> on November 6, 2013</div><div class="thread-post-content">Hi,
i have some problems how to &#8220;control&#8221; tasks&#8230; i have one main task which control others &#8220;reporting&#8221; tasks, which read data from sensors, sending data to server etc&#8230; but they&#8217;ll run occasionally some of them will run once per day others few times on month
now i&#8217;m wondering how should i do that and why is one way better than other? 
a) suspending/resuming tasks
b) changing their priorities
i didn&#8217;t find any specific info at http://www.freertos.org/a00112.html when should i use one of them&#8230; if i choose b) and raise priority to one task, scheduler won&#8217;t run other task until i don&#8217;t set low priority to it&#8230; what is diffrent if i choose way a) &#8211; i run task with highest priority and when is finished i suspend it&#8230;
best regards,
Matej
</div></div><div class="thread-post"><h3 class="thread-post-title">best way to &#8220;switch&#8221; tasks</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on November 6, 2013</div><div class="thread-post-content">If you need tasks to do these periodic actions then my answer assumes the functionality is unsuitable to be done in a software timer.
The other tasks must be tightly synchronized with the controlling task then you could have the other tasks suspend themselves when they have finished their action. The controlling task can then unsuspend them when it is time for them to perform their action again.
</div></div><div class="thread-post"><h3 class="thread-post-title">best way to &#8220;switch&#8221; tasks</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/matejm">matejm</a> on November 6, 2013</div><div class="thread-post-content">Dave, thanks for reply, tasks &#8211; actions are not peridoic&#8230; i think that suspending tasks is best choose because task is in suspended state and scheduler doesn&#8217;t have to mess with it (until i resume it )&#8230; if i changing a priority &#8211; task is in a Ready mode and scheduler will looking between more tasks (for each task at least one or more comparation)
</div></div><div class="thread-post"><h3 class="thread-post-title">best way to &#8220;switch&#8221; tasks</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on November 7, 2013</div><div class="thread-post-content">Generally i have tasks switch by having them wait on something (like a semaphore or queue) which tells them they have something to do. Trying to starts/stop tasks with resumes or priorities generally indicates that not enough effort has gone into figuring out when they are supposed to run and what they are supposed to do.
Tasks in the Blocked state don&#8217;t take attention of the scheduler.
