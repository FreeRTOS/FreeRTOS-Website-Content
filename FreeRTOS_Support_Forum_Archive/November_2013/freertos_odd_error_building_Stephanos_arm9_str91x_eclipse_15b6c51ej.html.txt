Anyway, I found out what&#8217;s <em>really</em> wrong&#8230; The makefile in Stephano&#8217;s package had a bug:
        -D STR91X<em>GCC 
        -D STACK</em>LWIP<em>130 
        -D $(THUMB</em>D)
        -mcpu=arm966e-s 
Notice the absence of a backslash after the THUMB<em>D line &#8211; the THUMB</em>D macro doesn&#8217;t contain a backslash either&#8230; so the build lines were being truncated at that point!!
Now that I&#8217;ve fixed that bug, I&#8217;m getting a different error, that -mcpu is deprecated, replaced by -mtune or -march, so I need to find what the equivalent arguments are&#8230;
</div></div><div class="thread-post"><h3 class="thread-post-title">odd error building Stephano&#8217;s arm9_str91x_eclipse</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/gorlash3">gorlash3</a> on November 7, 2013</div><div class="thread-post-content">Dammit &#8230; now I&#8217;m trying to use -march= (as recommended by gnu.gcc.org), but I can&#8217;t find any valid argument that this compiler will accept!!  The arm966e-s core is an armv5te architecture&#8230;  gnu.gcc.org says that -march will accept:
‘armv5’, ‘armv5t’, ‘armv5e’, ‘armv5te’, 
But I&#8217;ve tried all of these, and my (Yagarto) compiler rejects them all!!
How do I proceed from here??  Is there some way to ask gcc which arguments it <em>will</em> accept for -march ??
Later note:
Okay, I figured this one out as well&#8230; Even though I was explicitly defining CC to point to my ARM compiler chain, make was actually calling some other compiler; I don&#8217;t even know where it&#8217;s finding a compiler that is version &#8220;cc (GCC) 4.7.3&#8221; !!
My three ARM cross compilers are V4.2.2, V4.5.0, and V4.7.4 20130913.
This is very bizarre!!  What is clear, however, is that at this point, my problem is with a very complex Makefile, not FreeRTOS.
