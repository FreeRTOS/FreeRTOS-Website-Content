  <body bgcolor="#C0C0C0" text="#000000">
    <font size="+1"><font face="Times New Roman">We&#8217;ve been working on a
        project for several years now, which using the STR912 CPU.<br>
        We&#8217;ve been using the Yagarto toolchain, which is a GCC package.<br>
        The linker command using an argument <b><font face="Courier            New, Courier, monospace">-mcpu=arm966e-s</font></b> which is
        correct for this chip.<br>
        Our project currently comprises about 70,000 lines of code,
        coded directly on the CPU (no OS), and works well.<br>
        <br>
        Now I&#8217;m trying to study FreeRTOS, with an eye toward eventually
        porting the whole software package to this RTOS.<br>
        There are no examples with the package to support STR9 with GCC,
        so I&#8217;ve been looking at the STR9/IAR demo (which has no
        makefile) and the WizNET<em>DEMO</em>GCC<em>ARM7 demo, trying to carefully
        convert them over to STR9, but had some problems.<br>
        <br>
        So I looked online, and found an example that purported to be
        for STR9 + GCC, and I tried it out on my machine.<br>
        However, I noted that the (anonymous) author used <b><font
            face="Courier New, Courier, monospace">-mcpu=arm7tdmi</font></b>
        instead of </font></font><br>
    <font size="+1"><font face="Times New Roman"><b><font face="Courier            New, Courier, monospace">-mcpu=arm966e-s</font></b>.&nbsp; I was
        confused by this, and tried changing -mcpu to the correct value,
        but when I try to build with that setting, I get numerous linker
        errors, like this:<br>
        <br>
        <font face="Courier New, Courier, monospace">c:/yagarto/bin/../lib/gcc/arm-elf/4.2.2/../../../../arm-elf/bin/ld.exe:
          ERROR:
          c:/yagarto/bin/../lib/gcc/arm-elf/4.2.2/../../../../arm-elf/lib/thumb/interworklibg.a(lib</em>a-memset.o)
          uses FPA instructions, whereas RTOSDemo.elf does not<br>
        </font><br>
        If I change the -mcpu back to ARM7, these linker errors all go
        away.&nbsp; BTW, I had the same experience with the GCC_ARM7 demo
        package; it builds with the ARM7 type but gets these linker
        errors with the ARM9 CPU type.<br>
        What does this mean?&nbsp; Is this because they are mixing THUMB and
        ARM modules?<br>
        <br>
        I could test this by switching the entire project to ARM mode
        and abandoning THUMB mode, and I&#8217;m thinking of trying that just
        to see if it will build, but for now I&#8217;m more concerned with
        understanding what is going on&#8230;<br>
        <br>
        I would appreciate any insights that other STR9 users out there
        might have about this issue.<br>
        <br>
        Dan Miller<br>
        <br>
        <br>
        <br>
        <br>
      </font></font>
