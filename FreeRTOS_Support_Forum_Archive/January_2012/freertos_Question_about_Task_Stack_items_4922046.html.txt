  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Question about Task Stack items</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/gastaronum">gastaronum</a> on January 3, 2012</div><div class="thread-post-content">Hi,  
MCU: EFM32 &#40;EnergyMicro Cortex M3&#41;<br />
FreeRTOS 7.0.1  
I check stack allocation in function xTaskGenericCreate&#40;&#41; and pxPortInitialiseStack&#40;&#41;, for example:  
TOP of stack = 0x200008CC, aligned TOP of stack = 0x200008C8  
Aligned TOP of Stack value – 4 bytes &#40;0x200008C4&#41;&nbsp; portINITIAL&#95;XPSR<br />
Aligned TOP of Stack value – 8 bytes &#40;0x200008C0&#41; pointer to task function<br />
Aligned TOP of Stack value – 12 bytes LR<br />
Aligned TOP of Stack value – 16 bytes R12 &#40;reserved for use in future&#41;<br />
Aligned TOP of Stack value – 20 bytes R3 &#40;reserved for use in future&#41;<br />
Aligned TOP of Stack value – 24 bytes R2 &#40;reserved for use in future&#41;<br />
Aligned TOP of Stack value – 28 bytes R1 &#40;reserved for use in future&#41;<br />
Aligned TOP of Stack value – 32 bytes pointer to parameters, passed to the Task Function<br />
Aligned TOP of Stack value – 36 bytes R11 &#40;reserved for use in future&#41;<br />
Aligned TOP of Stack value – 40 bytes R10 &#40;reserved for use in future&#41;<br />
Aligned TOP of Stack value – 44 bytes R9 &#40;reserved for use in future&#41;<br />
Aligned TOP of Stack value – 48 bytes R8 &#40;reserved for use in future&#41;<br />
Aligned TOP of Stack value – 52 bytes R7 &#40;reserved for use in future&#41;<br />
Aligned TOP of Stack value – 56 bytes R6 &#40;reserved for use in future&#41;<br />
Aligned TOP of Stack value – 60 bytes R5 &#40;reserved for use in future&#41;<br />
Aligned TOP of Stack value – 64 bytes &#40;0x20000888&#41; R4 &#40;reserved for use in future&#41;  
When the Task Function is called by system, firstly a values of R4 and LR is pushed to stack:  
void TaskFunction&#40;void &#42;pvParameters&#41;<br />
&#123;<br />
TaskFunction:<br />
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; 0x14c22: 0xb510&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; PUSH&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; &#123;R4, LR&#125;<br />
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; …..  
Them pushed at address 0x200008C4 &#40;LR&#41; and 0x200008C0 &#40;R4&#41; and completely overwrite the portINITIAL&#95;XPSR and pointer to the task function values.  
Does it correct behavior?<br />
Can I analyze the stack area &#40;R1 .. R12 values stored in the stack as reserved in pxPortInitialiseStack&#40;&#41; function&#41; after context switch or this area is &#8220;not for use&#8221;?  
Best Regards and thanks for support.  
</div></div><div class="thread-post"><h3 class="thread-post-title">Question about Task Stack items</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on January 3, 2012</div><div class="thread-post-content">The items are pushed onto the stack before the stack is started to allow the stack to be started.&nbsp; That is, the items are popped from the stack during the processor starting the task.&nbsp; Once they have been popped from the stack, and the task is running, the stack frame as initially configured is no longer required and a new stack frame is created by the task function entry code &#40;the compiler generated prologue&#41;.&nbsp; The tasks stack frame will overwrite the original stack frame, so this behaviour is correct.  
Regards.
