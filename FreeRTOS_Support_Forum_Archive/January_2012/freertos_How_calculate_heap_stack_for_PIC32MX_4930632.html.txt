</div></div><div class="thread-post"><h3 class="thread-post-title">How calculate heap, stack for PIC32MX</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on January 7, 2012</div><div class="thread-post-content">While it is possible to calculate worst case stack usage, likewise heap usage, I take a more pragmatic approach and use experimentation.&nbsp; It is made easier by the fact that, on the PIC32 &#40;and other CPUs&#41;, the FreeRTOS port uses a separate stack for interrupts &#8211; so interrupt nesting does not need to be taken into consideration on the task stack.  
If a stack is too small, then the stack overflow hook will catch it, and you know to increase it.<br />
<a href="http://www.freertos.org/Stacks-and-stack-overflow-checking.html">http://www.freertos.org/Stacks-and-stack-overflow-checking.html</a>  
If a stack is larger than necessary, then you can resize it using the information obtained from its high water mark.<br />
<a href="http://www.freertos.org/uxTaskGetStackHighWaterMark.html">http://www.freertos.org/uxTaskGetStackHighWaterMark.html</a>  
With regards to the FreeRTOS heap, if you are allocating everything up front then just inspect the FreeRTOS heap to see how much is left, and you can reduce its size accordingly.&nbsp; If you are using heap&#95;1.c or heap&#95;2.c there is even a function provided to query how much is left &#40;xPortGetFreeHeapSize&#40;&#41;&#41;.  
Regards.
