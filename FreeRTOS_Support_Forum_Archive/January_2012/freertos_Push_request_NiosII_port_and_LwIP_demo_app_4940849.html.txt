  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Push request: NiosII port and LwIP demo app</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/dipswitch">dipswitch</a> on January 11, 2012</div><div class="thread-post-content">Good morning,  
I&#8217;m almost done integrating LwIP v1.4.0 in FreeRTOS v7.1.0 in the Nios II IDE. I would like to share the demo app and port update. Would it be possible that this source is included in the repository so it will be released with feature releases?  
Updated in the Nios II port:<br />
Fixed bug report:<br />
&#45; Nios II port bug when using -O3 or -Os &#8211; ID: 3037968<br />
Changed:<br />
&#45; It&#8217;s now possible to keep interrupts enabled while the scheduler has not been started yet. &#40;So now it&#8217;s possible to print output via USART before the OS is started for example…&#41;<br />
&#45; The FreeRTOS tick handler is called via the timer hook provided by the Nios II HAL library.  
Further more I made an install script which installs the FreeRTOS and LwIP packages into the Altera Nios II IDE &#40;tested for version 11.0 and up, although v9.0 and v10.0 are probably also supported&#41; So FreeRTOS&nbsp; can be chosen as Board Support Package &#40;BSP&#41; and LwIP can be chosen as software package when an FreeRTOS BSP is chosen.<br />
There will also be installed a FreeRTOS + LwIP demo package. This demo consists of a default FreeRTOS demo and the LwIP stack running a TCP echo server and an HTTP server which displays the currently running FreeRTOS tasks.

</div></div><div class="thread-post"><h3 class="thread-post-title">Push request: NiosII port and LwIP demo app</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/helarsen">helarsen</a> on March 7, 2012</div><div class="thread-post-content">Great work&#33; In order to get the installer to work on one of two win7/64 machines however I had to modify the file <em>alt-freertos-lwip-do-install.sh</em>. The problem is related to POSIX file access rights in. When using <em>cp</em>, POSIX rights are copied. They are apparently not set to u+rw in the distribution.   
I did two changes. Changed all distribution code to u+rw like this  
echo &#8221;&nbsp;&nbsp;&nbsp; &#45; Silently setting rw POSIX access on the distribution files to avoid access troubles..&#8221;;  
<pre><code>chmod -Rf u+rw FreeRTOS_src
chmod -Rf u+rw freertos_demo
chmod -Rf u+rw nios2_freertos_port
chmod -Rf u+rw altera_nios2
chmod -Rf u+rw freertos
chmod -Rf u+rw lwip
</code></pre>
and where the code is copied to the altera directory I added the -f option &#40;force&#41; to the cp command &#40;4 locations&#41;:  
<pre><code># now lets copy our stuff to the altera directory
echo -n "    - FreeRTOS..: ";
if cp -rf "${INST_PATH}/freertos" "${COMPONENTS}"; then
    echo "Success";
else
    echo "Failed with error code: $?";
fi;
</code></pre>
I dont know how to attach the suggested file. Teach me if you would like a copy. But again great job on this NIOS port.
