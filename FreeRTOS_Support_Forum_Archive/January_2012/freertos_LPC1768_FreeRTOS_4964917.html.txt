</div></div><div class="thread-post"><h3 class="thread-post-title">LPC1768 + FreeRTOS</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on January 22, 2012</div><div class="thread-post-content">Leaving FreeRTOS to on side for the moment, do you have a simple hello world demo running on the hardware &#40;without the FreeRTOS source files included&#41;?&nbsp; If you are unsure as the the linker script and start up files to use, then get that sorted before you add in any additional source files and functionality.  
I don&#8217;t know what comes with the CodeSourcery tools, but with the CodeRed tools you can just use their project creation wizard to generate a project that has the correct start up code and linker script for you.&nbsp; The tool will manage the linker script by default, but at least you can see the linker script.&nbsp; I&#8217;m sure there are lots of other places you can get linker scripts for that chip too.  
If CodeSourcery have a similar project wizard, or any examples that run on your particular chip, then use the start up files and linker script from those.&nbsp; I would not recommend mixing and matching linker scripts or startup files from different environments.  
Once you have a simple project, with a linker script, startup file and hardware configuration &#40;PLL, etc.&#41; that you are confident with you can add in the FreeRTOS files.&nbsp; Best to copy an existing LPC1768 project.&nbsp; You just need the FreeRTOS/Source files and the FreeRTOS/source/portable/GCC/ARM&#95;CM3 files, with FreeRTOS/Source/include and FreeRTOS/Source/portable/GCC/ARM&#95;CM3 in your include path.  
You can then install the interrupt handlers directly in the vector table, or better still, if you are using CMSIS files, just &#35;define the names of the FreeRTOS handlers to the CMSIS handler.&nbsp; Something like:  
<pre><code>#define vPortSVCHandler SVC_Handler
#define xPortPendSVHandler PendSV_Handler
#define xPortSysTickHandler SysTick_Handler
</code></pre>
in FreeRTOSConfig.h.&nbsp; &#40;check the names are the same as those in the vector table, as there is a little variation on the CMSIS side&#41;.  
Once the code is compiling, just create a simple task that does nothing but toggle an LED, and start the scheduler.  
Regards.
