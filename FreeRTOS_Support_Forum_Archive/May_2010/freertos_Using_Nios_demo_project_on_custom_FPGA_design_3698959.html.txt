  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Using Nios demo project on custom FPGA design</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/dsmhmm">dsmhmm</a> on May 5, 2010</div><div class="thread-post-content">I am trying to get the demo for the Nios ii running on my own board design.&nbsp; I am using a cyclone III similar to the one on the reference board used for the demo project.&nbsp; Having said that, it is a different card and the FPGA design is unique along with the Nios I have other custom logic blocks.&nbsp; In theory if I can setup the Nios &#40;sopc design&#41; with the same resources as the demo boards FPGA design things should work fine or if I knew how to specify the hardware resources the FreeRTOS code uses I could make my sopc design work as well.  
The .ptf file is the only included hardware file for the FPGA design rather than the .sopc file which you could open up and view to see what hardware resources are required to run the demo or exactly what the demo fpga design has.  
I have been able to create the Nios IDE project and point to my sopc design and when I compile I am getting an error with some of the code associated with the timer Interrupt which I am sure is because the code is trying to use a timer block inside sopc design that does not exists in my design that was there in the demo fpga design.  
Does anyone know how or where the code and hardware peripherals get &#8220;tied&#8221; together ?&nbsp;&nbsp;
</div></div><div class="thread-post"><h3 class="thread-post-title">Using Nios demo project on custom FPGA design</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on May 10, 2010</div><div class="thread-post-content">I asked William about this &#40;William is the NIOS man&#41;, and this is his response:  
<blockquote>
  I think that the root of the problem is that the latest Altera tools have changed the way the system library is created. The &#8216;syslib&#8217; project is now called &#8216;BSP&#8217; and requires a different file to generate the necessary hardware description for the software. Therefore, I think that the &#8216;ptf&#8217; has been deprecated, or at the very least, it cannot be used by the Nios environment.  
</blockquote>
When I tried to use the latest Altera software, I came across this problem but rolled back the Altera software because I didn&#8217;t have the FPGA project to generate the necessary files. In theory, you could use the latest Quartus to create the files because you have the FPGA design for the EBV DBC3C40 board.  
More appropriately for &#8216;dsmhmm&#8217;, he just needs to do a find and replace of &#8216;SYS&#95;CLK&#95;&#8217; to the name of his Timer peripheral in port.c. Replacing &#8216;SYS&#95;CLK&#95;&#8217; will catch &#8216;SYS&#95;CLK&#95;BASE&#8217;, which is the memory mapped address of the peripheral, and &#8216;SYS&#95;CLK&#95;IRQ&#8217;, which is the IRQ number.  
I am not 100% sure about the new format mainly because I haven&#8217;t tried it but at the very least &#8216;dsmhmm&#8217; will know which lines need to be changed in the port layer code.  
Regards.
