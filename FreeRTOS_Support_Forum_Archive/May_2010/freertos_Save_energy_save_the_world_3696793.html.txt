  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Save energy, save the world</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/cesarverdes">cesarverdes</a> on May 4, 2010</div><div class="thread-post-content">I&#8217;ve noted that when the system uses co-routines it&#8217;s dificult to know when send the CPU to sleep.  
As I could understand, the documentation suggests to include the vCoRoutineSchedule&#40;&#41; call into the vApplicationIdleHook&#40;&#41; function, setting configUSE&#95;IDLE&#95;HOOK to 1. I reference the &#8220;Scheduling the co-routine&#8221; topic at the <a href="http://www.freertos.org/croutine.html">documentation</a>.  
The<a href="http://www.freertos.org/tutorial/solution2.html"> Solution &#35;2</a> of the FreeRTOS Tutorial evaluates that for a fully preemptive system the power consumption can be reduced if the idle task places the processor into power save &#40;sleep&#41; mode.  
With the present co-routine implementation I find hard to detect when all the co-rutines are blocked &#40;delayed&#41; in order to place the processor into a power save mode until the next tick.  
In this <a href="https://sourceforge.net/projects/freertos/forums/forum/382005/topic/3579175">post</a> Richard Damon sugest this pseudo-code for the idle hook funcion:  
<pre><code>idle hook function (will be called periodically by the idle task) 
{
  Enter Critical Section
  if(ok to go to sleep) 
  {
    prepare system to go to sleep
    enter sleep state
    wake system up from sleep state
    end critical section
  }
  else 
  {
    end critical section
    maybe go to idle state if one is available
  }
}
</code></pre>
The question is, how to know when is ok to go to sleep when co-ruoutines are used?  
As a possile solution I suggest to change the return value of vCoRoutineSchedule&#40;&#41; from void to portBASE&#95;TYPE, and modify this function in order to return pdTRUE when there is at least one ready co-rutine, and return pdFALSE if there is not.  
As the <a href="http://www.freertos.org/taskandcr.html">documentation</a> declares, Co-routines are really only intended for use on very small processors that have severe RAM constraints. This kind of constraints can be common in small battery operated appliances.  
Please, does anyone see the same dificulty that I do? Does anyone found a good way to solve it?  
I know myself as a newbie, in case than more experienced FreeRTOS developers find my suggestion a good one, I would like to work on it and propose some code to discuss.  
I&#8217;m studing FreeRTOS only for pleasure, as a hobby in my free time. I&#8217;m trying to understand line by line, function by function. That&#8217;s why I could even think about situations that perhaps they are not real life ones.  
Regards,  
César
</div></div><div class="thread-post"><h3 class="thread-post-title">Save energy, save the world</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on May 4, 2010</div><div class="thread-post-content">I don&#8217;t use co-routines, but it seems to me that what could be done is use the priority feature of co-routines to do this. Set up a Priority 0 co-routine that does the sleep, and put all other co-routines at a higher priority. The Priority 0 co-routine will only get time if no task or other co-routine &#40;unless they also are at priority 0&#41; are able to run.
</div></div><div class="thread-post"><h3 class="thread-post-title">Save energy, save the world</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on May 4, 2010</div><div class="thread-post-content">Both suggestions sound good. The first one could be added under the sourceforge feature request tracker for FreeRTOS, although maybe richard&#95;damons suggestion makes it obsolete?

But I think your suggestion is really good enough without any kernel modification. It&#8217;s a pleasure to be studing an OS with this level of community support.
</div></div><div class="thread-post"><h3 class="thread-post-title">Save energy, save the world</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on May 6, 2010</div><div class="thread-post-content">The code actually uses a fairly efficient method to scan for the highest priority co-routine &#40;or task in similar code&#41; that is ready to run. I suspect that by making the sleep routine just the lowest priority may be a very efficient way to check for this, as it uses the existing code without special cases.
