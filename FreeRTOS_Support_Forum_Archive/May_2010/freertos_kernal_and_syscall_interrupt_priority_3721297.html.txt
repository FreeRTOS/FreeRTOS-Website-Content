  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">kernal and syscall interrupt priority</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/sloren">sloren</a> on May 26, 2010</div><div class="thread-post-content">Hi,  
I have a problem with configKERNEL&#95;INTERRUPT&#95;PRIORITY and configMAX. I&#8217;m using port for Cortex-M3 architecture. I&#8217;m using following set of configuration parameters:  
&#35;define configKERNEL&#95;INTERRUPT&#95;PRIORITY 255<br />
&#35;define configMAX&#95;SYSCALL&#95;INTERRUPT&#95;PRIORITY 191 /&#42; equivalent to 0xb0, or priority 11. &#42;/  
which is the standard configuration of the kernel. I have an interrupt that uses &#8220;fromISR&#8221; API calls and I have configured this interrupt to have priority of 12 &#40;0x0c&#41;. I found the kernel stucked in &#8216;list.c&#8217; where there is following comment note &#40;line: 134&#41;:  
/&#42; &#42;&#42;&#42; NOTE &#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;<br />
If you find your application is crashing here then likely causes are:<br />
1&#41; Stack overflow &#8211;<br />
&nbsp;&nbsp; see <a href="http://www.freertos.org/Stacks-and-stack-overflow-checking.html">http://www.freertos.org/Stacks-and-stack-overflow-checking.html</a><br />
2&#41; Incorrect interrupt priority assignment, especially on Cortex M3<br />
&nbsp;&nbsp; parts where numerically high priority values denote low actual<br />
&nbsp;&nbsp; interrupt priories, which can seem counter intuitive.&nbsp; See<br />
&nbsp;&nbsp; configMAX&#95;SYSCALL&#95;INTERRUPT&#95;PRIORITY on <a href="http://www.freertos.org/a00110.html">http://www.freertos.org/a00110.html</a><br />
3&#41; Calling an API function from within a critical section or when<br />
&nbsp;&nbsp; the scheduler is suspended.<br />
4&#41; Using a queue or semaphore before it has been initialised or<br />
&nbsp;&nbsp; before the scheduler has been started &#40;are interrupts firing<br />
&nbsp;&nbsp; before vTaskStartScheduler&#40;&#41; has been called?&#41;.<br />
See <a href="http://www.freertos.org/FAQHelp.html">http://www.freertos.org/FAQHelp.html</a> for more tips.<br />
&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;&#42;/  
I have no kernel problems if I use that interrupt priority of 15 which is acutally equal to configKERNEL&#95;INTERRUPT&#95;PRIORITY in my case. As far as documentation concerned &#40;More Advanced -&gt; Customization&#41; it is possible to use interrupts that can interrupt kernel-related interrupts as long as priority of those preemptive interrupts are kept lower &#40;in Cortex-M3 arch higher&#41; than configMAX&#95;SYSCALL&#95;INTERRUPT&#95;PRIORITY. I did so in the first case but my application tends to crash anyway.<br />
Has anybody had similar problem?  
</div></div><div class="thread-post"><h3 class="thread-post-title">kernal and syscall interrupt priority</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on May 28, 2010</div><div class="thread-post-content">Also be very careful with the function that you use to set the interrupt priority.&nbsp; Some require the priority to be shifted up into the most significant bits, while others don&#8217;t.&nbsp; For example, if you are using a Stellaris Cortex-M3 then there will be three bits implemented, but these are to most significant three bits.&nbsp; To set a priority to 5 using the StellarisWare functions you would have to actually pass in &#40;5&lt;&lt;5&#41;, whereas using a CMSIS function you would just pass in &#40;5&#41;.  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">kernal and syscall interrupt priority</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/sloren">sloren</a> on May 31, 2010</div><div class="thread-post-content">I&#8217;m using STM32 uC with ST drivers. I have checked if I set the interrupt priority ok in my application and everything seems to be OK. My question is: Is it possible to use interrupts priorities between configMAX&#95;SYSCALL&#95;INTERRUPT&#95;PRIORITY and configKERNEL&#95;INTERRUPT&#95;PRIORITY for interrupts calling FreeRTOS API &#40;as stated in documentation&#41; or it is just not safe? My application doesn&#8217;t crash immediately but after some time which is totally random. I know that it could be caused by some other &#8216;mistakes&#8217; but I have tripple checked and simplified my code just to be sure I don&#8217;t cross any of hints mentioned among those 4 points. When I look into the serial example of FreeRTOS distribution I find serial interrupt priority set at configKERNEL&#95;INTERRUPT&#95;PRIORITY level.
</div></div><div class="thread-post"><h3 class="thread-post-title">kernal and syscall interrupt priority</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on May 31, 2010</div><div class="thread-post-content">Only API functions that have FromISR in their name can be called in an ISR, but these can be called in all interrupts that have a priority equal to or between the KERNEL&#95;INTERRUPT&#95;PRIORITY and MAX&#95;SYSCALL&#95;INTERRUPT&#95;PRIORITY constants.
