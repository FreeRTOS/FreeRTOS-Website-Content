  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Retrieving task names from TCB</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/ajlennon">ajlennon</a> on May 28, 2010</div><div class="thread-post-content">Hi there,  
I&#8217;m using FreeRTOS with an ATMega1280 based project. I&#8217;m trying to optimise heap and stack usage as the device is fairly memory constrained.  
So I&#8217;m making use of&nbsp; uxTaskGetStackHighWaterMark&#40;xTaskHandle&#41;. I don&#8217;t really want to use more RAM to store the task names, but it would be helpful to log the names rather than the handle IDs. The names are in the TCB of course but I can&#8217;t see a function to retrieve them.  
Could somebody point me to a function, if it exists, or is there an architectural reason that one couldn&#8217;t/shouldn&#8217;t be added?  
Thanks,  
Alex
</div></div><div class="thread-post"><h3 class="thread-post-title">Retrieving task names from TCB</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on May 28, 2010</div><div class="thread-post-content">The handle ID is a pointer to the task control block, in which the name is stored. You could add a function to tasks.c like  
<pre><code>char *pcGetTaskName(void *handle)
{
    return ((tskTCB*)handle)-&gt;pcTaskName;
}
</code></pre>
I have not actually tested this code, but you see the idea.
</div></div><div class="thread-post"><h3 class="thread-post-title">Retrieving task names from TCB</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/ajlennon">ajlennon</a> on May 28, 2010</div><div class="thread-post-content">Hi Dave,  
Thanks for the response.   
I had put something similar in place, but using &#40;const char &#42;&#41; for the return.  
My question was more to do with why the there are no accessor functions in place already in FreeRTOS as this seems a sensible idea. I wondered if there is an architectural reason not to expose fields of the TCBs in this way…  
Alex
</div></div><div class="thread-post"><h3 class="thread-post-title">Retrieving task names from TCB</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on May 28, 2010</div><div class="thread-post-content">All the kernel data structures use data hiding in this way.&nbsp; Inside the files that define the structures the structure members are fully visible.&nbsp; Outside the files the structures are defined as void&#42; to keep their members hidden &#8211; and access can only be obtained through access functions.  
There is no particular reason why a function to return the name has never been included.&nbsp; I have added it to the todo list so it will be there in the next release.  
Regards.
