</div></div><div class="thread-post"><h3 class="thread-post-title">about using interrupts ..</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/davedoors">davedoors</a> on May 13, 2010</div><div class="thread-post-content">Its not obvious from your code what is main&#40;&#41; and what is the interrupt, it seems mixed up, but a few quick points.

Thanks for your reply …
</div></div><div class="thread-post"><h3 class="thread-post-title">about using interrupts ..</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on May 13, 2010</div><div class="thread-post-content">the question comes, what does the function need from the interrupt? If it needs just a bit of data, then perhaps a queue would work to store the data &#40;insert data in ISR, retrieve data in task&#41;, if it needs a bigger chunk of data, then sending a pointer to a buffer may work better &#40;and have some code to figure out which buffers are free for the interrupt to use&#41;. If the task just needs to be notified that something changed &#40;but isn&#8217;t being sent any specific data&#41; then the task can wait on a semaphore which is set by the ISR. In each of these cases, the task is calling a routine to get something that the interrupt is sending for the task to get.  
Since the interrupt is a timer, it probably isn&#8217;t sending data, but just indicating a time period, you are most apt to want to use the semaphore.  
A couple of thought as a look at things. One issue is that FreeRTOS may be already using T1 for its timebase, and this will interfere with you doing something special with it. The second is that if you are just looking for the task to run periodically, you may want to look at vTaskDelay and vTaskDelayUntil as these may be all that you really need.  
Have you read the documentation on FreeRTOS.org? It really is quite good and does provide simple examples for how things work.
