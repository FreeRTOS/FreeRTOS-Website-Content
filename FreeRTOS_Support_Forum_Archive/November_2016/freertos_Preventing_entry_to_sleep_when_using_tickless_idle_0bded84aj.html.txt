  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Preventing entry to sleep when using tickless idle</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/bryce78">bryce78</a> on November 15, 2016</div><div class="thread-post-content">Hello Community,
I have a question about preventing (&#8220;turning off&#8221;) entry to sleep during specific idle periods.  For example, suppose I am performing a network provisioning task which involves a lot of waiting during which the MCU could go to sleep.  But, for simplicity and to prevent continuous sleep-wake cycles, I wish to have the idle task run (skipping entry to sleep mode) until the network provisioning completes or timesout.  Essentially I would like to control (select) either entry to low-power sleep, or simply remain idling.
Here is a little background on my project: I am using Keil uVision v5.20 for development with FreeRTOS v9.0.0 on STM32L471 ARM Cortex M4 MCU.  My RTOS project defines 5 tasks, 4 of which use a Queue and wait for events to process, and the fifth uses Task Notifications to block until something happens.  Some relevant configuration:
~~~
<h1>define configOVERRIDE<em>DEFAULT</em>TICK_CONFIGURTION 1</h1>
<h1>define configUSE<em>TICKLESS</em>IDLE                  2</h1>
<h1>define configUSE<em>IDLE</em>HOOK                      0</h1>
~~~
I use 32.768kHz oscillator to drive low-power timer and generate the RTOS tick.  I have the RTOS tick independent of the MCU SYSCLK so I can achieve longer sleep periods, and also I need to keep SYSCLK running at a low frequency while in SLEEP.  To do all this I had to implemented my own portSUPPRESS<em>TICKS</em>AND_SLEEP() for tickless idle.
Back to the question of selecting either idle or sleep: I am thinking of introducing a simple global variable into the idle task which will determine whether the tickless idle code is skipped or run.
I think it&#8217;s pretty simple but wouldn&#8217;t mind a little feedback about this approach or more generally how to control entry to sleep mode.  (For example, if portSUPPRESS<em>TICKS</em>AND_SLEEP() is to be skipped, perhaps I should call vApplicationIdleHook() to increment an idle time counter that could be cleared when any task wakes.  It could be used to ensure a &#8220;minimum idle time&#8221; before allowing entry to sleep in general circumstances.)
Thanks for any suggestions!
Bryce

</div></div><div class="thread-post"><h3 class="thread-post-title">Preventing entry to sleep when using tickless idle</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/xz8987f">xz8987f</a> on November 18, 2016</div><div class="thread-post-content">Hi Bryce,
I had the problem that I need to prevent entering low power or tickless idle mode in case there is some communication pending (e.g. UART). For this I have extended FreeRTOS with two defines:
~~~
<h1>define configUSE<em>TICKLESS</em>IDLE<em>DECISION</em>HOOK     1 /* set to 1 to enable application hook, zero otherwise */</h1>
<h1>define configUSE<em>TICKLESS</em>IDLE<em>DECISION</em>HOOK_NAME xEnterTicklessIdle /* function name of decision hook */</h1>
~~~
The first one turns on an extra hook, and the second one provides the name.
You can find an implementation on GitHub here: https://github.com/ErichStyger/Hexiwear<em>v2/tree/master/KDS/Hexiwear</em>SDKv2/freertos/Source
The extension is in task.c
https://github.com/ErichStyger/Hexiwear<em>v2/blob/master/KDS/Hexiwear</em>SDKv2/freertos/Source/tasks.c
around line 3336:
~~~
        /* This conditional compilation should use inequality to 0, not equality
        to 1.  This is to ensure portSUPPRESS<em>TICKS</em>AND<em>SLEEP() is called when
        user defined low power mode implementations require
        configUSE</em>TICKLESS<em>IDLE to be set to a value other than 1. */
        #if ( configUSE</em>TICKLESS<em>IDLE != 0 )
        #if configUSE</em>TICKLESS<em>IDLE</em>DECISION<em>HOOK /* &lt;&lt; EST */
        if (configUSE</em>TICKLESS<em>IDLE</em>DECISION<em>HOOK</em>NAME()) /* ask application if it shall enter tickless idle mode */
        #endif
        {
        TickType_t xExpectedIdleTime;
<pre><code>        /* It is not desirable to suspend then resume the scheduler on
        each iteration of the idle task.  Therefore, a preliminary
        test of the expected idle time is performed without the
        scheduler suspended.  The result here is not necessarily
        valid. */
</code></pre>
xExpectedIdleTime = prvGetExpectedIdleTime();
~~~
Basically this extra hook allows the application to decide if the idle (and low power) mode really shall be entered. That approach worked really well for me. See as well https://mcuoneclipse.com/2014/02/09/iot-freertos-down-to-the-micro-amps/ and https://mcuoneclipse.com/2013/07/06/low-power-with-freertos-tickless-idle-mode/
I hope this helps,
Erich
</div></div><div class="thread-post"><h3 class="thread-post-title">Preventing entry to sleep when using tickless idle</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on November 18, 2016</div><div class="thread-post-content">I think there might be an easier way because 
portSUPPRESS<em>TICKS</em>AND_SLEEP() is declared in a way that allows the user 
to override its default implementation by providing their own.
The default definition is as follows:
<pre>
#ifndef portSUPPRESS_TICKS_AND_SLEEP
     extern void vPortSuppressTicksAndSleep( TickType_t xExpectedIdleTime );
     #define portSUPPRESS_TICKS_AND_SLEEP( xExpectedIdleTime ) 
vPortSuppressTicksAndSleep( xExpectedIdleTime )
#endif
</pre>
To override the definition you can add your own implementation of 
portSUPPRESS<em>TICKS</em>AND_SLEEP into FreeRTOSConfig.h, and can use that 
definition to decide if you want to go into sleep mode or not. 
Something like the following to be added to FreeRTOSConfig.h:
<pre>
extern void vPortSuppressTicksAndSleep( TickType_t xExpectedIdleTime );
#define portSUPPRESS_TICKS_AND_SLEEP( xExpectedIdleTime ) 
     if( AppWantsToEnterSleepMode() == pdTRUE )            
     {                                                     
         vPortSuppressTicksAndSleep( xExpectedIdleTime );  
     }
</pre>
