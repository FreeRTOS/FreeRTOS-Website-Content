  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">FreeRtos+UDP and FreeRtos+TCP with LPC1769</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/hardware-dev">hardware-dev</a> on November 17, 2016</div><div class="thread-post-content">Hello,
We have tested the example code <strong>FreeRTOSPlusUDPandCLILPC1830GCC</strong>. It seems to work well.
Now we would like to port this example to our microcontroller <strong>LPC1769</strong>.
In the zip-package from FreeRtos there is a folder with drivers for LPC1769:
FreeRTOSv9.0.0FreeRTOS-PlusSourceFreeRTOS-Plus-UDPportableNetworkInterfaceLPC17xx
So I took the file &#8220;NetworkInterface.c&#8221; from this folder and put it into my project in place of original file for LPC1830.
<strong>I also added the driver files for emac:</strong>
* lpc17xx<em>emac.c
* lpc17xx</em>emac.h
* and all other files which were needed.
<strong>Now the compiler can&#8217;t find the following functions:</strong>
* EMAC<em>NextPacketToRead();
* EMAC</em>SetNextPacketToSend();
* EMAC_StartTransmitNextBuffer();
I <strong>can</strong> find that functions in the driver for LPC1830 but they don&#8217;t work with LPC1769.
<strong>The questions are as follows:</strong>
* Is this driver &#8220;NetworkInterface.c&#8221; for 1769 incomplete?
* What do I have to do to get it work?
Our target is to use the FreeRtos+TCP (we need webserver and UDP), but there is no example code for our LPC microcontrollers. That is why we would like to port the example <strong>FreeRTOSPlusUDPandCLILPC1830GCC</strong>. If it works correctly, then we will try to port the FreeRtos+TCP.

</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRtos+UDP and FreeRtos+TCP with LPC1769</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on November 17, 2016</div><div class="thread-post-content">In the LPC18xx example EMAC<em>NextPacketToRead() is implemented in the 
lpc18xx</em>emac.c souce file &#8211; which is a driver file provided by NXP, and 
it seems the LPC17xx version of NetworkInterface.c expects the 
equivalent LPC17xx driver from NXP to provide the same function.  It 
sounds like the version of lpc17xx<em>emac.c that you are using (is that 
from NXP too?) is different to the one used when the networkinterface.c 
file for that chip was written.  Look in your lpc17xx</em>emac c and h 
source files to see what it calls the functions that you are missing &#8211; 
I&#8217;m sure they will be there but it sounds like they are named differently.

There are following functions <strong>lpc18xx_emac.c</strong>:
BaseType<em>t EMAC</em>Init(EMAC<em>CFG</em>Type *EMAC_ConfigStruct);
int32_t EMAC_UpdatePHYStatus(void);
<strong>uint32_t EMAC_GetReceiveDataSize(void);

void EMAC_NextPacketToRead( xNetworkBufferDescriptor_t *pxNetworkBuffer );
void EMAC_UpdateRxConsumeIndex(void);

Whereas in <strong>lpc17xx_emac.c</strong> I can find:
Status EMAC<em>Init(EMAC</em>CFG<em>Type *EMAC</em>ConfigStruct);
void EMAC<em>DeInit(void);
int32</em>t EMAC<em>CheckPHYStatus(uint32</em>t ulPHYState);

int32</em>t EMAC<em>UpdatePHYStatus(void);
void EMAC</em>SetHashFilter(uint8<em>t dstMAC</em>addr[], FunctionalState NewState);
void EMAC<em>SetFilterMode(uint32</em>t ulFilterMode, FunctionalState NewState);
void EMAC<em>WritePacketBuffer(EMAC</em>PACKETBUF<em>Type *pDataStruct);

IntStatus EMAC_IntGetStatus(uint32_t ulIntType);
Bool EMAC_CheckReceiveIndex(void);
