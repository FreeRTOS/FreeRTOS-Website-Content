  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">MPU port BSS segment initialization for FreeRTOS</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/jgreen">jgreen</a> on November 29, 2016</div><div class="thread-post-content">I&#8217;m working on creating a Cortex-M4 project using the MPU version of FreeRTOS.  The target processor is the STM32F303RE.
To summarize the issue I&#8217;m having: global BSS data in FreeRTOS privileged areas is not being cleared to 0 on init.
I&#8217;m using a linker script based on FreeRTOS/Demo/CORTEX<em>MPU</em>Simulator<em>Keil</em>GCC/GCC_Specific/sections.ld but with the proper ROM and RAM areas for this MPU:
  ROM (rx)  : ORIGIN = 0x08000000, LENGTH = 128K
  RAM (xrw) : ORIGIN = 0x20000000, LENGTH = 32K
The startup assembler file is the ST CMSIS startup file which comes with their standard peripheral library.  Stepping through the Reset_Handler code, I see that it does a BSS init to zero for my application data.  But this does not include variables in FreeRTOS privileged areas.  This results in crashes when I start creating tasks, since structures like pxReadyTasksLists are essentially uninitialized.
My guess is that the startup assembler code needs to initialize a second BSS area and possibly also copy initialized data from ROM to RAM for another area for FreeRTOS.  Or maybe there is something wrong with the linker map, where these areas should somehow be combined but still marked as privileged?  Is there a startup assembler file I can look at for an MPU port?  Any other ideas?
Best regards,
Element
</div></div><div class="thread-post"><h3 class="thread-post-title">MPU port BSS segment initialization for FreeRTOS</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/jgreen">jgreen</a> on November 29, 2016</div><div class="thread-post-content">I have implemented a hack to get things to work for now, until I can fix this properly.  In main() I have the following code:
~~~
extern uint32<em>t <strong>privileged_data_start</strong>[];
extern uint32</em>t <strong>privileged<em>data</em>end</strong>[];
int
main(void)
{
  // Hack to initialize privileged data areas to 0
  // FIXME &#8211; How does this usually happen with the FreeRTOS MPU port?
  memset (&amp;<strong>privileged<em>data</em>start</strong>, 0, ((uint8<em>t *)(&amp;<strong>privileged_data_end</strong>)) &#8211; ((uint8</em>t *)(&amp;<strong>privileged_data_start</strong>)));
~~~
Would like to know how this SHOULD work.
Best regards,

</div></div><div class="thread-post"><h3 class="thread-post-title">MPU port BSS segment initialization for FreeRTOS</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/rtel">rtel</a> on November 29, 2016</div><div class="thread-post-content">This is not really a FreeRTOS question.
The start up routine (the function that the reset handler calls) is 
dependent on the linker script.  It uses information from the linker 
script, normally linker variables, to know the start and end address of 
the RAM that needs to be cleared to 0, and the start and end address of 
the data to copy and where to copy it to to initialise variables.  If 
you edit the linker script to add in new sections that need 
initialisation then you also need to update the start up routine 
accordingly.
</div></div><div class="thread-post"><h3 class="thread-post-title">MPU port BSS segment initialization for FreeRTOS</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/jgreen">jgreen</a> on November 29, 2016</div><div class="thread-post-content">Seems pretty related to me.  FreeRTOS MPU sets up specific regions of memory for different purposes.  Knowing that it&#8217;s own BSS section is not initialized by run of the mill default startup code, is critical to getting the MPU port working on any platform.  I did not see anything in the Keil simulator demo project showing this (perhaps it starts with a zeroed memory space by default), which seems to warrant at least some mention of this somewhere (which I could not find).  The names of these sections and their purpose is defined by FreeRTOS.  Regardless, as outlined in my other post, I&#8217;m just using memset() in main().
