Tick Handler for RL78 version of FreeRTOS ?</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/gerlad0">gerlad0</a> on November 17, 2016</div><div class="thread-post-content">The Tick Handler for the RL78 Demo version of FreeRTOS doesn&#8217;t appear to be correct i..e  why would it be calling the vTaskSwitchContext()  function for each tick (see the first call below)??   Secondly since vTaskSwitch function is declared as type &#8216;void&#8217; it won&#8217;t be returning a function value however the code below is testing for a zero value return (cmpw ax, #0x00).
<strong>Or am I misssing something rather fundamental??</strong>  I appreciate all the insight that you can provide!!!!
This is installed as the interval timer interrupt handler.
     RSEG CODE:CODE
vPortTickISR:
    portSAVE<em>CONTEXT               ; Save the context of the current task.<br />
    call    _vTaskSwitchContext     ; Call the timer tick function.
    cmpw    ax, #0x00
    skz
    call    _vTaskSwitchContext     ; Call the scheduler to select the next task.
    portRESTORE</em>CONTEXT            ; Restore the context of the next task to run.
    reti
<pre><code>void vTaskSwitchContext( void )
</code></pre>
<strong>My environment is as follows</strong>:
IAR EW for RL78 Version 2.21.2
IAR EW Version 7.4.1.4269
FreeRTOS Version 8.2.3
RTSDemo &#8211; YRPBRL78G13 (YRPBRL78G13 is #defined).

When I look in the FreeRTOS 
distribution for the IAR RL78 port I find the following code:
<pre>
; FreeRTOS tick handler.  This is installed as the interval timer interrupt
; handler.
     RSEG CODE:CODE
vPortTickISR:
  portSAVE_CONTEX ; Save the context of the current task.
  call xTaskIncrementTick ; Call the timer tick function.
  cmpw ax, #0x00
  skz
  call vTaskSwitchContext ; Call the scheduler to select the next task.
  portRESTORE_CONTEXT ; Restore the context of the next task to run.
  reti
</pre>
