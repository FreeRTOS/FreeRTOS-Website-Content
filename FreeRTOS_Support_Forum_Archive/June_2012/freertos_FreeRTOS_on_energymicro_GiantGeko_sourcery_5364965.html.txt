  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">FreeRTOS on energymicro GiantGeko (sourcery)</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/valeriobardelli">valeriobardelli</a> on June 19, 2012</div><div class="thread-post-content">Hi,<br />
I&#8217;m trying to port FreeRTOS on energymicro GiantGeko &#40;CortexM3&#41; with codesourcery cross-compiler. I&#8217;m able to compile and run a demo application, but the task that I create it seems that doesn&#8217;t start.<br />
When I try to debug it seems that vPortStartFirstTask in port.c &#40;an assembler routine&#41; hangs forever, but the task routine is never reached.<br />
My starting point was <a href="http://www.freertos.org/Interactive_Frames/Open_Frames.html?http://interactive.freertos.org/entries/20291196-energy-optimized-port-of-freertos-6-for-efm32%2C">http://www.freertos.org/Interactive&#95;Frames/Open&#95;Frames.html?http://interactive.freertos.org/entries/20291196-energy-optimized-port-of-freertos-6-for-efm32,</a> but I tryed also with the last version of FreeRTOS and I have a similar problem &#40;in prvPortStartFirstTask routine in port.c&#41;.  
Any idea about this problem?  
Any help is greatly appreciated&#33;  
Regards, Valerio
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS on energymicro GiantGeko (sourcery)</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on June 19, 2012</div><div class="thread-post-content"><blockquote>
  it seems that vPortStartFirstTask in port.c &#40;an assembler routine&#41; hangs forever
</blockquote>
This function calls SVC, which generates an interrupt/exception.&nbsp; Have you populated the vector table with the FreeRTOS interrupt handlers?&nbsp; Or alternatively if you are using CMSIS files, mapped the FreeRTOS interrupt handlers to the CMSIS handler names in FreeRTOSConifg.h as per post 2 here:<br />
<a href="http://www.freertos.org/FreeRTOS_Support_Forum_Archive/September_2011/freertos_FreeRTOS_on_Atmel_SAM3U_in_CrossStudio_4694403.html">http://www.freertos.org/FreeRTOS_Support_Forum_Archive/September_2011/freertos_FreeRTOS_on_Atmel_SAM3U_in_CrossStudio_4694403.html</a>  
Did you also try the official demo &#40;without the tickless modification?&#41;<br />
<a href="http://www.freertos.org/EFM32.html">http://www.freertos.org/EFM32.html</a>  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">FreeRTOS on energymicro GiantGeko (sourcery)</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/valeriobardelli">valeriobardelli</a> on June 20, 2012</div><div class="thread-post-content">Hi Richard,  
many thanks for your response&#33; ;&#41;  
Yes, I tried with official demo &#40;as I explain in my first post&#41;, but I port it from IAR &#40;I think the only compiler supported, at the moment for energymicro&#41; to codesourcery because our OEM customer don&#8217;t want to buy a licence. If there is a FreeRTOS port for codesourcery &#40;for energymicro&#41; could be very usefull&#33; ;&#41;  
The problem it seems to be soved&#33;&#33;&#33;&#33;  
I have to change the code in startup&#95;efm32gg.s &#40;I compile this file instead of the modified startup&#95;efm32&#95;cs3.s in the project because I have GiantGeko and not Geko, this is my orrible mistake&#33; -.- &#41;.  
But, I think the best and elegant solution, is to add in my FreeRTOSConfig.h this few lines:  
<pre><code>#define vPortSVCHandler SVC_Handler
#define xPortPendSVHandler PendSV_Handler
#define vPortSVCHandler SVC_Handler
#define xPortSysTickHandler SysTick_Handler
[code]
Now it works! I can also debug with eclipse and JLink! Great! I can investigate now about EM2 energy mode...
Thanks a lot for your precious, professional and very quick support!
Regards, Valerio
</code></pre>
