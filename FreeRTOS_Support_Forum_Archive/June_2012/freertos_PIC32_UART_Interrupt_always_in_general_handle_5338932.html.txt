</div></div><div class="thread-post"><h3 class="thread-post-title">PIC32 UART Interrupt always in general handle</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on June 12, 2012</div><div class="thread-post-content">Which version of FreeRTOS are you using?&nbsp; The last function in main.c is indeed the general exception handler, but using the Microchip function name as follows:  
<pre><code>void _general_exception_handler( unsigned long ulCause, unsigned long ulStatus )
{
    /* This overrides the definition provided by the kernel.  Other exceptions 
    should be handled here. */
    for( ;; );
}
</code></pre>
See the MPLAB CX32 users guide for information on the handler, and the MIPS M4K documentation for information on what the exception is.  
<blockquote>
  10.5.2 General Exception<br />
  A general exception is any non-interrupt exception which occurs during program<br />
  execution outside of bootstrap code &#40;StatusBEV=0&#41;. General exceptions are vectored<br />
  to offset 0x180 from EBase.<br />
  At this location, the 32-bit toolchain places a branch instruction targeting a function<br />
  named &#95;general&#95;exception&#95;context&#40;&#41;. The provided implementation of this<br />
  function saves context, calls an application handler function, restores context and<br />
  performs a return from the exception instruction. The context saved is the hi and lo<br />
  registers and all General Purpose Registers except s0-s8, which are defined to be<br />
  preserved by all called functions and so are not necessary to actively save here again.<br />
  The values of the Cause and Status registers are passed to the application handler<br />
  function &#40;&#95;general&#95;exception&#95;handler&#40;&#41;&#41;. If the user application provides an<br />
  implementation of &#95;general&#95;exception&#95;context&#40;&#41;, that implementation will be<br />
  used instead.<br />
  void &#95;general&#95;exception&#95;handler &#40;unsigned cause, unsigned status&#41;;<br />
  A weak default implementation of &#95;general&#95;exception&#95;handler&#40;&#41; is provided in<br />
  the standard library which merely goes into an infinite loop. If the user application<br />
  provides an implementation of &#95;general&#95;exception&#95;handler&#40;&#41;, that<br />
  implementation will be used instead.
</blockquote>
