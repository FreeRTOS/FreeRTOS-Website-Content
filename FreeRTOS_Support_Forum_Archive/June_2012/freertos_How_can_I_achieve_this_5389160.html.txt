  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">How can I achieve this?</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/kuku2010">kuku2010</a> on June 28, 2012</div><div class="thread-post-content">Two threads, one needs to run at the highest possible frequency, but 90% of the time it has nothing to do, taking only a fraction of the tick. If it has nothing to do, I would like to suspend it until next tick, and let the second thread to use up the remaining time of the current tick.  
When the next tick comes in, the first thread gets back to work…. repeating the cycles  
This way,&nbsp; the higher priority task can run at the highest frequency  
Thanks for any pointer&#33;
</div></div><div class="thread-post"><h3 class="thread-post-title">How can I achieve this?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on June 28, 2012</div><div class="thread-post-content">First, it sounds like the first task needs to be set to the highest priority in your system. Then, the task just needs to call vTaskDelay&#40;1&#41; to delay until the next tick.  
A better question comes, is there a way you can set a semaphore when more work is available &#40;can you get an interrupt when it happens and have an ISR give the semaphore&#41;, if so, then have the first task wait on a get for that semaphore, then you don&#8217;t need to wait for the next tick, but it will run immediately.
</div></div><div class="thread-post"><h3 class="thread-post-title">How can I achieve this?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/kuku2010">kuku2010</a> on June 29, 2012</div><div class="thread-post-content">I was taking the first approach before posting the question, but I didn&#8217;t like the idea of vTaskDelay&#40;1&#41;, meaning the highest frequency for task 1 is only 1/2 of the tick frequency.  
semaphore is not easy since i haven&#8217;t found a good sport in ISR to put it in   
Any other option?
</div></div><div class="thread-post"><h3 class="thread-post-title">How can I achieve this?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/*anonymous">*anonymous</a> on June 29, 2012</div><div class="thread-post-content">Why do you assume it would only run at 1/2 the tick frequency?&nbsp; From what I see, it would run at exactly the tick frequency.
</div></div><div class="thread-post"><h3 class="thread-post-title">How can I achieve this?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richard_damon">richard_damon</a> on June 30, 2012</div><div class="thread-post-content">vTaskDelay&#40;1&#41; delays till the next tick. In general a call to vTaskDelay&#40;n&#41; waits for n ticks to happen before the task is rescheduled, since you might be part way through the current tick, it cause a delay of between n-1 and n ticks in duration &#40;and thus a vTaskDelay&#40;1&#41; could delay for almost 0 time, if the tick interrupt occurs just after the call is processed&#41;. The task needs to be the highest priority, or their could be additional delay imposed due to higher tasks running.  
I would really suggest looking again at the semaphore. Note that it is ok for the interrupt to give the semaphore multiple times if that makes the code significantly easier. 
</div></div><div class="thread-post"><h3 class="thread-post-title">How can I achieve this?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/kuku2010">kuku2010</a> on July 2, 2012</div><div class="thread-post-content">Considering the nature of my project, I&#8217;d rather see task 1 to be paced in a timely fashion, thus semaphore may not work even I can issue it from ISR.  
As for the vTaskDelay &#40;1&#41;, my understanding was at tick 1, task1 ran for 1/f ticks, then it calls for vTaskDelay &#40;1&#41;, so it will not come back to the ready state until 1+1/f, meaning it will miss the second tick. Am I right?
</div></div><div class="thread-post"><h3 class="thread-post-title">How can I achieve this?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/*anonymous">*anonymous</a> on July 2, 2012</div><div class="thread-post-content">So maybe the following will solve your problem:<br />
Make your Task 1 being the highest priority task in the system. Task 1 should block on waiting for a semaphore with for example xSemaphoreTake function. Once the semaphore is given, Task 1 wakes, does its job and blocks again waiting for the semaphore.  
If you want your task to be run in timely manner and you think that waking Task 1 with system tick frequency is suitable, use Tick Hook Function and give the semaphore from void vApplicationTickHook&#40; void &#41; function. Please note that this function needs some configs to be set and runs in interrupt context. More details can be found in <a href="http://www.freertos.org/a00016.html">http://www.freertos.org/a00016.html</a>  
Hope that helps,<br />
Adam

</div></div><div class="thread-post"><h3 class="thread-post-title">How can I achieve this?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/kuku2010">kuku2010</a> on July 2, 2012</div><div class="thread-post-content">thank you, richard&#95;damon, adam and <a href="https://www.google.com/accounts">https://www.google.com/accounts</a>   
If &#8220;vTaskDelay&#40;1&#41; could potentially delay almost 0 time. &#8220;, shouldn&#8217;t it be renamed vTaskDelay&#40;0&#41;?  
If vTaskDelay&#40;1&#41; indeed guarantee task 1 to be called every tick, I would avoid semaphore
</div></div><div class="thread-post"><h3 class="thread-post-title">How can I achieve this?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on July 2, 2012</div><div class="thread-post-content">You have the resolution of one tick.&nbsp; Calling vTaskDelay&#40; 1 &#41; will delay for nearly an entire tick period if it is called immediately after the last tick interrupt, or practically no time at all if it is called immediately before the next tick interrupt.&nbsp; You cannot have fractions of a tick.  
vTaskDelay&#40; 0 &#41; is equivalent to taskYIELD&#40;&#41;.  
Generally, I don&#8217;t think it is a good idea to have a task run every tick, unless you have a slow tick rate.&nbsp; It sounds like a candidate for code that would do better in a timer interrupt routine.  
Regards.
