  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Saving CRC Register on context switch</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/harikk09">harikk09</a> on June 20, 2012</div><div class="thread-post-content">I am using MSP430F5418 with FreeRTOS 7 in medium data model.  
I want to save the MSP CRC registers on FreeRTOS context switch. I edited the portext.s43 like this.  
In save context macro, after pushing 15 registers to stack, I push the CRC registers. &#40;CRCDI is the MSP register to save&#41;  
mov.w CRCD1, r15<br />
pushx.a r15<br />
In restore context macro, I poped the CRC just before poping the 15 registers.  
popx.a r15<br />
mov.w r15, CRCDI<br />
It is supposed to be working , but it is not. The program control is going to unknow location.  
Anybody have any Idea?
</div></div><div class="thread-post"><h3 class="thread-post-title">Saving CRC Register on context switch</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on June 20, 2012</div><div class="thread-post-content">You will also have to set up the initial stack given to the task when it is created to include the additional register &#8211; otherwise, when the task first starts, the restore context macro will try and pop a register that does not exist resulting in junk in the register and a stack underflow.  
Look at the function pxPortInitialiseStack&#40;&#41; in whichever port.c file you are using.  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">Saving CRC Register on context switch</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/harikk09">harikk09</a> on June 20, 2012</div><div class="thread-post-content">Thank you Richard for your reply.<br />
In that function what should I change?
</div></div><div class="thread-post"><h3 class="thread-post-title">Saving CRC Register on context switch</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on June 20, 2012</div><div class="thread-post-content">I don&#8217;t know which port you are looking at, but if you look at FreeRTOS/Source/Portable/IAR/MSP430X/port.c, then assume PRELOAD&#95;REGISTER&#95;VALUES is set, you will see that the function writes a value for each register that is to be popped from the stack when the context is loaded.&nbsp; If your new register is the last thing popped from the stack, add it to the start of the list, if it is the first thing popped from the stack, add it to the end of the list.  
Regards.
</div></div><div class="thread-post"><h3 class="thread-post-title">Saving CRC Register on context switch</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/harikk09">harikk09</a> on June 21, 2012</div><div class="thread-post-content">But PRELOAD&#95;REGISTER&#95;VALUES is not set in my port.c, what should I do?
