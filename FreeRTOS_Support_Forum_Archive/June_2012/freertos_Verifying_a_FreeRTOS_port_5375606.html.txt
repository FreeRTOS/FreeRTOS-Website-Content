</div></div><div class="thread-post"><h3 class="thread-post-title">Verifying a FreeRTOS port?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/richardbarry">richardbarry</a> on June 23, 2012</div><div class="thread-post-content">Older features are tested &#42;extremely&#42; thoroughly by the SafeRTOS test harnesses, whereas newer features have their own tests &#40;although not published&#41; &#8211; but these are primarily for the generic behviour of the common code rather than a port.  
When testing a port the first thing I do it check the tick frequency is correct with an oscilloscope.  
Next create a set of tasks that fill the CPU registers with known values &#8211; each register has a different values &#8211; and each task uses its own unique values.&nbsp; Make sure the some tasks also perform yields.&nbsp; Once the registers are filled, loop around continuously checking that none of the values ever change as the tasks are swapped in and out, and as interrupts execute.&nbsp; If a value ever changes, then something is wrong in the context switching mechanism.&nbsp; .  
Next do a soak test by running the standard demo tasks.&nbsp; Some of there are very sophisticated in testing interrupt nesting, block times, timers, etc. and they actually give you very good kernel coverage as well as port layer coverage.&nbsp; Leave these running with the tasks that check the CPU registers too.&nbsp; You will need a task that checks all the demo and test tasks are running without error &#8211; again there are lots of demos in the download that do this.  
Hope this helps.&nbsp; Which port do you have?  
Regards.
