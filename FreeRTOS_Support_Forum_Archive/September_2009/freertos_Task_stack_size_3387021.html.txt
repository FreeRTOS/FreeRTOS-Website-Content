  <main class="main-content"><div class="thread-post"><h2 class="thread-post-title">Task stack size?</h2><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/yyang2000">yyang2000</a> on September 2, 2009</div><div class="thread-post-content">Hi,
Does any one know how to determine a stack size when I create a task? Or tell me what factors need to be consider for calculating a task stack size? I have read it from FreeRTOS web stie, but I am still not clear how. I used the demo of Cortex&#95;LM3Sxxxxx&#95;Keil. I tried to figure out how the demo does to determine a stack size. For example, the default configMINIMAL&#95;STACK&#95;SIZE is 70, but I modified it to 250.&nbsp; I wonder if it is a proper setting.&nbsp; 
Also the mainBASIC&#95;WEB&#95;STACK&#95;SIZE for uIP web server was set to configMINIMAL&#95;STACK&#95;SIZE &#42; 3 which the original was 70&#42;3=210. However, since I modified to 250, now it is 250&#42;3=750. Is it waste memory space?
Any help will be appreciated.
</div></div><div class="thread-post"><h3 class="thread-post-title">Task stack size?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/wdeninger">wdeninger</a> on September 2, 2009</div><div class="thread-post-content">As you know, the stack size is determined during the creation of the task.&nbsp; Determining stack size has never been an automated process. For instance, FreeBSD has a default of 64MB stack for each application thread, and RedHat has 10MB user, and 8kB kernel, etc&#8230;&nbsp; Generally, you should estimate the required stack space for each thread.&nbsp; If you do have any recursive calling code within your task, you will need to program them for a maximum recursion depth.&nbsp; 
FreeRTOS does have a compile mode supporting stack overflow detection, and I plan on having it compiled in automatically with the DEBUG build.
-W
</div></div><div class="thread-post"><h3 class="thread-post-title">Task stack size?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/incrediball">incrediball</a> on September 2, 2009</div><div class="thread-post-content">You can also use the uxTaskGetStackHighWaterMark function to determine how much stack has actually been used and fine tune it. Important is that interrupts also use the stack of the task that is interrupted &#40;although I&#8217;m not sure if all ports do this&#41; so their usage needs to be added to the task&#8217;s own usage.
</div></div><div class="thread-post"><h3 class="thread-post-title">Task stack size?</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/wdeninger">wdeninger</a> on September 2, 2009</div><div class="thread-post-content">Just remember that in FreeRTOS, the stack size is specified as an unsigned portSHORT, which generally means 65535 words max.&nbsp; -W
