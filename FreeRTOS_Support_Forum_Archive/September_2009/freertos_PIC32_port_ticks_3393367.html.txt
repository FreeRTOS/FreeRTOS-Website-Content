</div></div><div class="thread-post"><h3 class="thread-post-title">PIC32 port ticks</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/edwards3">edwards3</a> on September 8, 2009</div><div class="thread-post-content">Having just looked at the code I would say xMinDisplayTime is a hard coded value that is never changed.
</div></div><div class="thread-post"><h3 class="thread-post-title">PIC32 port ticks</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/wne1">wne1</a> on September 8, 2009</div><div class="thread-post-content">what is hard coded value? The main.c defines:
xLCDMessage xMessage = &#123; &#40; 200 / portTICK&#95;RATE&#95;MS &#41;, cStringBuffer &#125;;
Cause portTICK&#95;TATE&#95;MS is 1, it make sense that xMinDisplayTime is 200.
why the break point stop every 500 ticks?
</div></div><div class="thread-post"><h3 class="thread-post-title">PIC32 port ticks</h3><div class="thread-post-author">Posted by <a href="http://sourceforge.net/users/edwards3">edwards3</a> on September 8, 2009</div><div class="thread-post-content">Ok now I understand your question.
I would say it was because there are two delays in the task. You are just looking at vTaskDelay&#40;&#41; which blocks for the 200 ticks, but there is also a call to xQueueReceive&#40;&#41; which blocks for ever. What ever posts to the queue probably does so every 500 ticks. This would be normal for a &#8216;check&#8217; task which inspects system status every 300 or 500ms &#40;depending on the demo&#41; then shows a status message or toggles and led.
